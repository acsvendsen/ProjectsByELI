# Reality Check

## Subtitle Placement: Feasible Now
- **Subtitle Clarity**: The current implementation in `TranscriptLab` should aim for a clear, fast, and stable subtitle display to ensure the wearer can trust them during live conversations. Given that the project is V1 focused on frame-touch interactions, subtitles need to be placed in an area that minimizes distraction but ensures they are easily readable.
- **Usability vs Distraction**: Placing subtitles near the bottom of the field of vision where they do not obstruct sightlines or cause visual clutter can be feasible now. This approach balances usability with social acceptability.

## Confidence Display: Feasible Later
- **Confidence Score vs Label**: The current focus on `TranscriptLab` suggests that confidence display should evolve based on real-world testing and feedback. A simple label-based system might be sufficient initially, but as the project matures, adding a short reason or score can improve trust.
- **Implementation Grounding**: Based on the current setup in `TranscriptLab`, implementing a confidence display with labels is feasible now. Adding more sophisticated options (like scores) will require further testing and real-world validation.

## Memory/Cache Policy: Feasible Now
- **Face/Name Recall**: The core deepening mode emphasizes improving memory support, making this area a priority for immediate attention.
- **Local vs Cloud Storage**: Given the V1 focus on phone-first processing, caching face/name information locally is feasible now. This approach reduces latency and battery usage while ensuring that critical memory data remains accessible.

## Phone/Cloud Boundary: Feasible Now
- **Phone-First Processing**: The current architecture direction strongly favors phone-first processing for heavy tasks like context lookup and memory storage.
- **Optional Cloud Integration**: While the project allows for optional cloud integration, this should be used judiciously to ensure that V1 remains practical and reliable.

## Visual Hierarchy: Feasible Now
- **Subtitles vs Prompts**: The visual hierarchy between subtitles and one-line prompts should prioritize clarity and ease of use. Subtitles can take precedence due to their real-time nature, but the design must also allow for clear differentiation.
- **Frame-Touch Interaction**: Since V1 interaction is frame-touch only, the visual hierarchy should be designed with this in mind, ensuring that the most critical information (like subtitles) are easily accessible.

## Likely Waste of Time
- **Automatic Memory Support vs Confidence and Correction Safety**: While improving memory support is a core attractor, immediately adding complex confidence mechanisms without real-world testing might be premature. Focus on basic functionality first before introducing more advanced features.
- **Rich AR Visuals**: The current focus on phone-first processing does not justify the implementation of fancy AR visuals in V1.

## Assumptions Needing Evidence
- **Subtitle Clarity**: While the project acknowledges subtitle clarity as a core attractor, concrete evidence from real-world testing is needed to fine-tune placement and readability.
- **Memory Trust**: The current implementation of face/name recall should be validated through user feedback and iterative improvements. 

## Summary

- **Subtitle Placement**: Feasible now; focus on clear and unobtrusive placement.
- **Confidence Display**: Feasible later; start with simple labels and refine based on testing.
- **Memory/Cache Policy**: Feasible now; cache critical information locally to ensure reliability.
- **Phone/Cloud Boundary**: Feasible now; prioritize phone-first processing.
- **Visual Hierarchy**: Feasible now; design for frame-touch interaction.

By maintaining a focus on core functionality and iterative improvement, the project can ensure that V1 remains robust and useful while preparing for future enhancements.
