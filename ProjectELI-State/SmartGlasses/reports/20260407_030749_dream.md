### Idea 1: Subtitle Placement

1. **Why it benefits the core**

Stable subtitle placement rules ensure that subtitles remain consistent, readable, and not distracting during live conversations. This stability helps maintain trust in the system's real-time functionality and reduces cognitive load on the wearer.

2. **What small change unlocks it**

Define two subtitle placement modes: one for high-confidence speech (always visible) and another for low-confidence speech (only appear when needed). This allows the system to prioritize clarity during critical moments while maintaining a clean UI in less important segments of conversation.

3. **Likely payoff**

By implementing these two placement modes, the system can provide more reliable subtitles during key parts of conversations, such as introductions or important details, without overwhelming the wearer with constant text. This enhances the overall user experience and trust in the system’s real-time capabilities.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format, we can enhance the trustworthiness of our system. A well-crafted confidence label and short reason will help users understand when they should rely on the displayed information or seek clarification.

2. **What small change unlocks it**

   Introduce a new confidence format that combines a numeric score with a label and a short reason. For example, "score 0.85 + 'High' + 'Seen recently'".

3. **Likely payoff**

   This change will provide users with clear feedback on the reliability of the displayed information, which can significantly improve their trust in the system. Users will be more likely to rely on subtitles and memory support when they understand the basis for the confidence level.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - By setting a clear local memory threshold, the system can ensure that only relevant and frequently encountered names and faces are stored locally on the phone, reducing storage pressure while maintaining essential context for fast recall.

2. **What small change unlocks it**
   - Define a local cache size limit of 50 entities (names or faces) that automatically evicts the least recently used items when new ones are added.

3. **Likely payoff**
   - This change will help manage memory usage efficiently, ensuring that critical context is retained while avoiding unnecessary data storage, which can reduce battery consumption and improve overall system performance.

4. **Immediate next probe**
   - Define one local cache size limit of 50 entities for name and face recall to optimize memory use and fast lookup.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining what runs phone-local versus what falls back to cloud for live subtitle processing, we ensure that subtitles remain real-time and stable enough to be trusted in live conversations. This helps maintain the core mission of providing clear, fast subtitles that enhance understanding without introducing latency or distraction.

2. **What small change unlocks it**

   Define a specific set of face/name recognition tasks that will run locally on the phone for real-time processing, such as initial face detection and basic name recall. This local processing can then trigger cloud-based memory lookups if needed, but with minimal delay to maintain subtitle clarity.

3. **Likely payoff**

   By keeping critical live subtitle processing local, we ensure that subtitles remain clear and stable enough for the wearer to trust them in real-time interactions. This reduces the risk of latency-induced errors and enhances the overall reliability of the system, which is crucial for maintaining user trust.

4. **Immediate next probe**
   - Define the cloud fallback boundary for initial face detection to run locally on the phone with real-time subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line prompts helps maintain the wearer's focus on critical information, reducing cognitive load and social awkwardness. This balance is crucial for the core mission of helping the wearer understand and respond better in real-world interactions without overwhelming them with too much information.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prioritizes subtitles over one-line prompts when both are present on-screen, ensuring subtitles remain prominently visible while one-line prompts take secondary display precedence.

3. **Likely payoff**

   By prioritizing subtitles, the system enhances trust and usability. Subtitles will be more readable and stable, while one-line prompts provide just enough additional context without detracting from the primary information. This improves overall user experience and aligns with the core attractors of real-time subtitle clarity and low-friction assistance.

4. **Immediate next probe**
   - Define a visual priority rule that prioritizes subtitles over one-line prompts when both are present on-screen.
