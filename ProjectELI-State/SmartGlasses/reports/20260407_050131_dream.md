### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Improving subtitle placement rules can significantly enhance the wearer's trust in the system by ensuring subtitles remain readable and unobtrusive, even during fast-paced conversations.

2. **What small change unlocks it**
   - Define two subtitle placement modes: one for normal conversation (fixed position) and another for high-confidence states where subtitles can be slightly higher or lower to avoid overlap but remain clear.

3. **Likely payoff**
   - By providing a fixed position mode, the system ensures consistency and reduces the risk of missed information during natural speech patterns. The additional modes for high-confidence states will help in drawing attention when needed without overwhelming the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Enhancing the confidence display format will ensure that the wearer can easily understand the level of certainty in the subtitles and memory support, thereby increasing trust and reliability. A well-designed confidence label with a short reason will help the wearer quickly assess the quality of the information provided.

2. **What small change unlocks it**

   Define one confidence format candidate for V1 that uses a numeric score plus a label followed by a short reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format will provide clear and concise confidence information.

3. **Likely payoff**

   By implementing a simple but effective confidence display, the system will increase user trust in its outputs. This will lead to more accurate subtitle placement, better memory recall, and overall improved wearer satisfaction. The straightforward nature of the confidence labels will also reduce cognitive load on the wearer, making the product easier to use.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a precise local cache threshold for name recall, we ensure that frequently encountered people and names are readily available to the wearer without compromising privacy or memory accuracy. This improves the trustworthiness of memory support by reducing false positives and ensuring that only relevant evidence is cached locally.

2. **What small change unlocks it**

   Define a recency-based eviction policy where name memories older than 30 days are evicted from local cache unless they have been seen recently (e.g., within the last 7 days).

3. **Likely payoff**

   This change will enhance the wearer's trust in memory recall by ensuring that names and faces remain fresh in their memory, reducing the risk of outdated or irrelevant information being recalled incorrectly. It also helps manage local storage efficiently while maintaining a high level of accuracy.

4. **Immediate next probe**

   Define one recency-based eviction rule for name memories where entries older than 30 days are evicted unless seen within the last 7 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By optimizing which tasks run on the phone versus falling back to the cloud, we can balance real-time responsiveness with privacy and battery efficiency. This ensures that critical subtitle processing happens locally while less time-sensitive memory lookups or transcript cleanup can leverage cloud resources.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing as running on the phone only, and set a clear rule for when face/name recall lookup should fall back to the cloud if not found locally within a certain time frame.

3. **Likely payoff**

   This balance will enhance real-time performance by keeping critical processes local, while still allowing for robust memory support through periodic cloud checks, thus maintaining privacy and battery efficiency without compromising core functionality.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for face/name recall lookup such that if a name is not found within the first 5 seconds of search on the phone, it falls back to the cloud for further processing.
