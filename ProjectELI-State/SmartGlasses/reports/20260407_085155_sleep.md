# Recent Consolidation for SmartGlasses Project

## Strengthening Signals

### Core Mission Reinforcement
- **Subtitle Quality:** Ensuring subtitles remain clear, fast, and stable enough to maintain trust during live conversations (subtitle_clarity).
- **Memory Support:** Enhancing memory recall of names and faces with confidence objects to build reliable support for the wearer.

### Interaction Focus
- **Frame-Touch Only V1:** Emphasizing frame touches as primary interaction method in V1 without introducing voice commands.
- **Low-Friction UX:** Prioritizing one-line prompts and visible support that do not create command overhead or social awkwardness.

## Weakening Signals

### Broad Feature Expansion
- **Avoiding Speculative Features:** Focusing on core deepening rather than broad feature expansion to avoid distracting from the mission.

### Interaction Sprawl
- **No Voice Activation in V1:** Not assuming voice-command control for subtitle management, mode switching, or confirmations.
- **No New Command Surfaces:** Avoiding new command surfaces that do not match current interaction constraints until further iteration.

## Contradictions That Must Stay Alive

### Privacy vs. Usefulness
- Ensuring assistive behavior does not quietly slide into invasive capture or retention while providing helpful support.

### Latency vs. Richness
- Balancing the need for timely help with avoiding overloading the runtime to ensure fast and reliable responses.
- Avoiding complex multimodal UIs that could introduce significant latency without clear value added.

## Dormant Ideas Worth Reactivating

### Subtitle Placement and Visual Clarity
- Revisiting subtitle placement strategies to find a balance between readability and non-distracting UX, especially in noisy environments.
- Considering the visual hierarchy for subtitles and one-line prompts to ensure they do not overload the wearer.

## Concrete Tensions Around Core Aspects

### Real-Time Subtitle Assistance vs. Privacy
- Ensuring real-time subtitle clarity (subtitle_clarity) while maintaining privacy by not over-relying on invasive features or data retention practices.
- Balancing useful memory support with privacy concerns to avoid creating a system that feels too intrusive.

### Memory Support vs. Low-Friction Interaction
- Managing the trade-off between providing rich, reliable memory support and keeping interactions simple enough to remain socially acceptable (discreet_ux_vs_visual_clarity).

## Real Implementation Constraints

### Battery and Thermal Limits
- Continuing to keep glasses hardware lightweight in V1 to avoid thermal and battery pressure.
- Biasing towards phone-first processing where heavy on-glasses compute is impractical.

### Cloud vs. On-Glasses Processing
- Limiting cloud use to where it clearly adds value, ensuring that early versions remain heavily reliant on the phone for practicality (phone_first_runtime).

## Current Open Questions

- **Subtitle Placement:** What placement ensures readability without becoming distracting?
- **Confidence Display:** How should confidence be represented to build trust: label only, label + short reason, or score + label?
- **Memory/Caching Policy:** How much face/name memory should be cached locally on the phone for fast lookup and reinforcement?
- **Phone/Cloud Boundary:** Which interactions work offline versus requiring cloud support?
