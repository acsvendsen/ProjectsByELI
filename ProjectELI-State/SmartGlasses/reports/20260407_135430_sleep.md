# Recent Signals Consolidation

## Strengthening Signals
- **Subtitle Clarity**: The importance of clear, fast, and stable subtitles in live conversations is becoming more pronounced. This ensures the wearer can trust the system during interactions.
- **Memory Trust**: The reliability of name and face memory support is crucial for building a trustworthy assistant. Users need to feel that their memories are accurately represented without any false certainty or errors.

## Weakening Signals
- **Low-Friction Assistance**: The current implementation has begun to lean more towards providing detailed one-line assistance rather than keeping the interface minimal. This could increase social awkwardness and distract from the core subtitle functionality.

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: There is a continuous tension between providing useful assistive features without infringing on user privacy. The system must maintain a balance that respects users' privacy while offering valuable support.
- **Latency vs Richness**: The need to provide timely help without overloading the runtime with richer but slower processing remains a critical balance.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement and Visual Hierarchy**: These are currently inactive but could become important as the project evolves. Ensuring subtitles are placed in a way that minimizes distraction while maintaining readability is essential.
- **Confidence Display**: How to best represent confidence levels to users without causing confusion or overreliance on the system.

## Concrete Tensions Around Core Areas
- **Subtitle Quality vs Memory Trust**: Improving subtitle clarity and speed might come at the cost of less emphasis on memory support. This tension must be managed carefully.
- **Automatic Memory Behavior vs Explicit Remember-Touch Behavior**: The balance between automatically remembering new faces and names versus requiring explicit user interaction (touch) to reinforce these memories is crucial for maintaining trust.
- **Battery Constraints vs Always-On Sensing**: The project must continuously manage the trade-off between always-on functionality and battery usage, ensuring that heavy sensing does not drain the device.

## Open Questions
1. **Subtitle Placement**: What is the best placement for subtitles to ensure they are readable without becoming distracting?
2. **Confidence Display**: How should confidence be represented to users: as a numeric score, label, or short reason?
3. **Memory Policy**: How much face/name memory should be cached locally on the phone to balance local processing and cloud usage?

## Key Project Inputs
- **Core Deepening Over Sprawl**: The project should focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion.
- **Frame-Touch-Only V1 Interaction**: Early interactions must remain frame touches only, with no assumption of voice commands or spoken user control.
- **Phone-First Processing**: Heavy processing should primarily occur on the phone, with cloud support optional where justified by clear value.

## Recent Xcode Build Summary
The `TranscriptLab` app build was successful, indicating that the live transcription and confidence display functionalities are working as intended. This success provides a solid foundation for further development and testing of subtitle clarity and memory trust features.

### Next Steps
1. **Subtitle Clarity**: Focus on optimizing subtitle rendering to ensure readability and stability.
2. **Memory Trust**: Implement robust mechanisms for name and face recognition while maintaining user privacy.
3. **Low-Friction Interaction**: Ensure that one-line assistance does not overwhelm the interface, focusing instead on enhancing core functionalities.

By addressing these areas, the project can continue to strengthen its core mission of providing real-time support without compromising on privacy or usability.
