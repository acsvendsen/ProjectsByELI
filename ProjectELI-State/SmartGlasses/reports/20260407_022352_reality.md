# Reality Check

## Subtitle Placement: feasible now
- **Current State**: The glasses should display subtitles in a way that is readable but not distracting.
- **Constraints**: Given the current focus on frame-touch V1, subtitle placement must be simple and effective. The existing `TranscriptLab` test app provides a framework for testing different placements without adding unnecessary complexity.
- **Feasibility**: With the current project inputs, it's feasible to experiment with subtitle placement using the `TranscriptLab` app. This will help in determining an optimal position that maximizes readability while minimizing distraction.

## Confidence Display: feasible now
- **Current State**: The system needs a confidence display mechanism to inform users of the reliability of the subtitles.
- **Constraints**: The initial focus is on frame-touch V1, and confidence should be represented clearly without overwhelming the user. The `TranscriptLab` app can be used to prototype different confidence indicators (label only, label + short reason, or score + label).
- **Feasibility**: It’s feasible to implement a basic confidence display in `TranscriptLab`. This could include simple visual cues like color changes or icons that indicate the reliability of subtitles. More complex mechanisms can be explored later.

## Memory/Cache Policy: likely waste of time
- **Current State**: The glasses should remember names and faces but must do so without creating a false sense of certainty.
- **Constraints**: V1 interaction is frame-touch only, and memory policy should be simple to avoid overwhelming the user. The project focuses on core deepening rather than broad feature expansion.
- **Feasibility**: At this stage, it's likely premature to deeply implement face/name memory policies. Instead, focus should be on ensuring that any memory support provided is clear about its limitations.

## Phone/Cloud Boundary: feasible later
- **Current State**: The phone will handle most of the heavy processing initially.
- **Constraints**: V1 interaction is frame-touch only, and cloud dependency should be minimized to reduce latency. However, as the project evolves, more complex interactions may require cloud support.
- **Feasibility**: For now, it’s feasible to continue developing with a strong phone-first approach. The `TranscriptLab` app can help in testing various behaviors without relying on cloud services.

## Visual Hierarchy: feasible now
- **Current State**: The glasses need to display subtitles and confidence indicators clearly.
- **Constraints**: V1 interaction is frame-touch only, and visual clarity should be a priority. The `TranscriptLab` app provides a platform for prototyping different visual hierarchies.
- **Feasibility**: It’s feasible to experiment with visual hierarchy in `TranscriptLab`. This could involve testing various font sizes, colors, and placement of subtitles and confidence indicators.

## Summary
- **Subtitle Placement**: Feasible now using the `TranscriptLab` app.
- **Confidence Display**: Feasible now by prototyping basic mechanisms in `TranscriptLab`.
- **Memory/Cache Policy**: Likely a waste of time at this stage; focus on core deepening.
- **Phone/Cloud Boundary**: Feasible later as complexity increases.
- **Visual Hierarchy**: Feasible now using the `TranscriptLab` app.

This reality check aligns with the current project inputs and guides the team toward feasible actions that will deepen the core mission of the SmartGlasses.
