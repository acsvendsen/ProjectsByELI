### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states helps ensure that subtitles remain readable and stable enough to maintain trust in live conversations. By defining clear, fixed position rules for high-confidence versus low-confidence subtitles, we can reduce visual distraction while ensuring critical information is always visible.

2. **What small change unlocks it**

   Define a simple rule where high-confidence subtitles are placed at the bottom of the frame with a slight inset to avoid overlapping with text or objects in the foreground, and low-confidence subtitles are shown above the high-confidence ones but slightly faded to indicate lower certainty.

3. **Likely payoff**

   This approach will help maintain visual clarity and reduce cognitive load by ensuring that high-certainty information is always easily readable while still providing context for uncertain information without overwhelming the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a numeric score with a label and short reason, we can enhance trust in the system's certainty without overwhelming the wearer. This approach aligns with the core attractors of real-time subtitle clarity and memory support, as it ensures that the wearer understands the reliability of both subtitles and remembered information.

2. **What small change unlocks it**

   Define a confidence object format that combines a numeric score (e.g., 0.84), a label indicating certainty level (e.g., "High"), and a short reason (e.g., "Seen recently").

3. **Likely payoff**

   This refined confidence display will help the wearer trust the system more, leading to better engagement with subtitles and memory support. It also provides a clear indication of reliability, which is crucial for maintaining the core attractors of real-time clarity and trustworthy memory.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local memory threshold for face/name recall, we ensure that the system retains relevant memories without overwhelming the wearer or draining the device's resources. This balance helps in maintaining trust by not overloading the user with unnecessary information while ensuring key interactions are always accessible.

2. **What small change unlocks it**

   Define a specific number of recent interactions (e.g., 5-10) that should be retained locally on the phone for face/name recall, with a policy to purge older entries after a certain period (e.g., one week).

3. **Likely payoff**

   This approach ensures that the system can quickly and accurately provide support during conversations without requiring frequent cloud lookups or local memory refreshes. It enhances both privacy and usability by managing memory size effectively.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays phone-local versus falling back to cloud for live subtitle processing, we ensure that subtitles are always available in near-real-time without overloading the glasses hardware. This improves the core attractor of real-time subtitle clarity and reduces battery drain, maintaining trust and utility.

2. **What small change unlocks it**

   Define a specific task boundary: live subtitle processing. For this task, all audio input and initial transcription work should be done on the phone to ensure minimal latency and high quality. Only when the initial transcript is complete and needs refinement or background processing will the fallback to cloud occur.

3. **Likely payoff**

   This change will significantly enhance the core attractor of real-time subtitle clarity by ensuring that subtitles are always available in near-real-time, reducing battery drain from heavy processing on glasses hardware, and maintaining trust through fast, reliable assistance.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving subtitle vs one-line support coexistence ensures that the wearer can trust both types of information without visual overload or distraction. This balance enhances overall user experience by providing necessary context while maintaining clarity and focus.

2. **What small change unlocks it**

   Define a clear priority rule where subtitles are always visible but one-line prompts are suppressed unless confidence is high, ensuring that critical information remains prominent while auxiliary support does not overwhelm the wearer.

3. **Likely payoff**

   By clearly defining subtitle vs one-line priority, the system can avoid visual clutter and ensure that essential information (subtitles) remains prioritized over less critical assistance (one-line prompts). This results in a cleaner UI that enhances user trust and usability.

4. **Immediate next probe**
