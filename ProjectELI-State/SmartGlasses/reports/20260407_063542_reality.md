# Reality-Check Assessment

## Subtitle Placement: Feasible Now

**Description:** Ensure subtitles are placed in a way that minimizes distraction while remaining readable.

**Constraints:**
- Must fit within the glasses' display limits.
- Should not block the wearer's view or be too small.

**Evaluation:**
- The glasses should prioritize placement strategies tested and proven effective on similar devices (e.g., smartwatches, AR glasses). 
- Initial testing with different subtitle sizes and positions can quickly determine what works best without overcomplicating V1.
- Given the current focus on core-deepening work, implementing a few high-confidence designs early will provide immediate feedback.

**Conclusion:** Feasible now. Begin testing various placements in `TranscriptLab` to get initial data for subtitle placement.

## Confidence Display: Feasible Now

**Description:** Design confidence indicators that enhance user trust without overwhelming the display space.

**Constraints:**
- Must be readable and non-intrusive.
- Should not create visual clutter.

**Evaluation:**
- Use a simple label-based system initially, such as "Confident" or "Uncertain," to gauge user reaction.
- Introduce optional additional information (e.g., short reason) only if it does not significantly impact usability or display space.
- Leverage the `TranscriptLab` app for rapid iteration and testing.

**Conclusion:** Feasible now. Implement a basic confidence label system in `TranscriptLab` to test initial designs.

## Memory/Cache Policy: Feasible Now

**Description:** Develop policies for caching face and name data on the phone to balance memory use with lookup speed.

**Constraints:**
- Must respect battery and thermal limits.
- Should minimize privacy risks while maintaining useful recall.

**Evaluation:**
- Start by caching minimal information (e.g., names and basic contextual data) locally.
- Implement a reinforcement learning mechanism for prioritizing frequently encountered faces/names.
- Use the `TranscriptLab` app to simulate memory updates and lookups, ensuring they do not significantly impact performance or user trust.

**Conclusion:** Feasible now. Develop initial caching policies in `TranscriptLab` based on minimal data retention and frequent update patterns.

**Conclusion:** Feasible now. Refine the phone/cloud boundary definitions in `TranscriptLab` based on current architecture direction.
