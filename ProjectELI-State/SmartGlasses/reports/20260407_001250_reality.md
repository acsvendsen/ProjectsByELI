## Subtitle Placement: Feasible Now

**Rationale:** The current project emphasizes real-time subtitle clarity and low-friction assistance. Given the constraints of frame-touch interaction in V1, subtitle placement should remain unobtrusive but clear enough for fast reading.

- **Subtitle Placement:** Place subtitles slightly above the center of the wearer's gaze to ensure they are visible without obstructing the field of view significantly. This position can be tested using the `TranscriptLab` app to find an optimal balance between visibility and distraction.
  - **Feasibility:** Feasible now. The `TranscriptLab` app provides a platform for testing different subtitle placements.

## Confidence Display: Likely Waste of Time

**Rationale:** Early V1 interactions are frame-touch only, meaning confidence display should be minimal to avoid adding unnecessary complexity. Initial focus should be on ensuring the subtitles themselves are clear and reliable.

- **Confidence Display:** For now, use a simple "high" or "low" label without additional reasons. This approach minimizes visual clutter and aligns with the current interaction constraints.
  - **Feasibility:** Likely waste of time in V1. More detailed confidence displays can be explored later as part of core deepening.

## Memory/Cache Policy: Feasible Now

**Rationale:** Face/name recall must expose uncertainty clearly, which implies a simple cache policy where memory is refreshed and reinforced over time.

- **Memory Cache Policy:** Implement a caching strategy that stores recent face and name interactions in the phone's local storage. Ensure this data is refreshed periodically to maintain accuracy without overwhelming the system.
  - **Feasibility:** Feasible now. The `TranscriptLab` app can be used to test memory recall functionality.

## Phone/Cloud Boundary: Feasible Now

**Rationale:** V1 should rely heavily on phone processing, with cloud optional where clearly justified by latency and complexity constraints.

- **Phone/Cloud Boundary:** Design the system so that heavy processing (e.g., voice recognition, context understanding) happens on the phone. Only use cloud services for tasks like model updates or background analysis.
  - **Feasibility:** Feasible now. The `TranscriptLab` app provides a test bed to ensure local processing is robust before considering cloud integration.

## Visual Hierarchy: Feasible Now

**Rationale:** The visual hierarchy should support the core mission of providing clear, unobtrusive assistance.

- **Visual Hierarchy:** Ensure subtitles are prioritized over other UI elements. Use a simple, clean design that minimizes distraction while providing essential information.
  - **Feasibility:** Feasible now. The `TranscriptLab` app can be used to prototype and test different visual hierarchy designs.
