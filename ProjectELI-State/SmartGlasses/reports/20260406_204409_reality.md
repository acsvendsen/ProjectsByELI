# Reality Check for SmartGlasses V1

## Subtitle Clarity
- **Feasible Now:**  
  The current hardware setup allows for real-time subtitles that are clear, fast, and stable enough to be trusted in live conversation. Given the focus on frame-touch interaction and low-friction support, achieving this level of subtitle quality is feasible now.

## Memory Trust
- **Feasible Later:**  
  Implementing memory trust through automatic new-person recall and reinforcement over time requires a more advanced context-aware system. While it's a key attractor, the initial V1 can rely on contextual cues and explicit remember-touch behavior to build trust. More sophisticated memory management will be necessary for later versions.

## Low-Friction Assistance
- **Feasible Now:**  
  Delivering one-line contextual prompts that are clear and unobtrusive is feasible now. This aligns with the low-friction interaction requirement of V1, ensuring the system remains discreet and user-friendly.

## Privacy vs Usefulness
- **Assumptions Needing Evidence:**  
  The balance between privacy and usefulness needs more concrete evidence to determine how much memory support can be automatically inferred versus explicitly remembered by the user. This will inform decisions on how much information is stored locally and when it's appropriate to reinforce recall.

## Latency vs Richness
- **Feasible Now:**  
  Ensuring timely help without overloading the runtime with richer but slower processing is feasible now. The current V1 interaction through frame touches allows for simple, fast responses that don't require complex processing on the glasses themselves.

## Discreet UX vs Visual Clarity
- **Feasible Now:**  
  Display behavior can remain socially acceptable while still being readable in motion and noise. The initial design should focus on clear, unobtrusive subtitles placed optimally to enhance understanding without becoming distracting.

## Frame-Touch-Only V1 Interaction
- **Feasible Now:**  
  Implementing interaction through frame touches only is feasible now given the current hardware constraints. This respects the early hardware limits and ensures a low-friction user experience.

## Phone-First Runtime
- **Feasible Now:**  
  Heavy processing on the phone, with cloud optional where clearly justified, is feasible now. The initial V1 should leverage this approach to keep the glasses lightweight and socially acceptable.

## Core Deepening Over Sprawl
- **Core Deeper Changes:**  
  Focus on improving subtitle quality, memory trust, confidence display, and visual UX rather than broad feature expansion is essential for V1. This will help maintain a clear focus on the core mission without adding unnecessary complexity.

## Constraint Pressure
- **Feasible Now:**  
  Surface battery, latency, privacy, and usability limits early so weak directions are killed quickly. The current project setup allows for early identification of constraints to guide development effectively.

## Implementation Grounding
- **Concrete Design Over Generic Suggestions:**  
  Reason from actual repo files, app docs, and build truth instead of generic ideation is feasible now. Using concrete signals like the `TranscriptLab` test app will provide a solid foundation for making informed decisions.

## Action Inbox

### Subtitle Placement
- **Action Required:**
  Define an optimal subtitle placement strategy that balances readability with minimal distraction. Use the `TranscriptLab` app to test different placements and refine the design based on user feedback.

### Confidence Display
- **Action Required:**
  Determine a clear and unobtrusive confidence display mechanism that maintains trust without overwhelming the wearer. Consider options like labels, scores, or short reasons for clarity.

### Memory/Cache Policy
- **Action Required:**
  Decide how much face/name memory should be cached locally on the phone and when explicit remember-touch behavior is necessary to reinforce recall. This will impact privacy and usability.

### Phone/Cloud Boundary
- **Action Required:**
  Establish clear guidelines for when cloud processing is beneficial versus unnecessary for V1. Ensure that local processing remains lightweight and socially acceptable.

### Visual Hierarchy
- **Action Required:**
  Design the visual hierarchy to ensure subtitles and prompts are distinct yet easily readable. Use the `TranscriptLab` app to prototype different layouts and refine the design based on usability testing.

## Summary

The current V1 direction is feasible now with concrete steps to address subtitle clarity, memory trust, low-friction assistance, and core-deepening changes. Early constraint pressure and implementation grounding will help ensure that weak directions are identified and addressed quickly. The focus should remain on improving core functionality without broad feature sprawl or unnecessary complexity.
