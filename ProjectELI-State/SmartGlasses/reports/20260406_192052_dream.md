### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Stable subtitle placement rules ensure that subtitles remain readable, unobtrusive, and trust-preserving in noisy environments, enhancing the wearer's ability to understand live conversations.

2. **What small change unlocks it**
   - Define three fixed subtitle placement rules: one for high confidence states (e.g., when a speaker is clearly visible), one for medium confidence states (e.g., when context provides reasonable certainty), and one default rule for low confidence states (e.g., always at the bottom of the field of view).

3. **Likely payoff**
   - By establishing clear placement rules, users will have more consistent and reliable subtitles, reducing visual distraction and improving overall understanding in various interaction contexts.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring clear, stable, and timely confidence display helps build trust in the system's abilities. By providing a consistent and understandable format for confidence levels, the wearer can better understand when to rely on the system’s judgments and when to seek clarification.

2. **What small change unlocks it**

   Define a simple, standardized confidence object that includes a numeric score, label, and short reason. For example: `score 0.84 + "High" + "Seen recently"` for recent and reliable memory entries; `score 0.42 + "Low" + "Weak match"` for less certain names or faces.

3. **Likely payoff**

   A clear confidence display will reduce uncertainty for the wearer, enhancing trust in the system’s judgments. This clarity can prevent misunderstandings and ensure that the user is better informed about the reliability of the information provided by the glasses.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory, we ensure that the system retains only the most relevant and frequently encountered entities, reducing memory bloat while maintaining necessary contextual support.

2. **What small change unlocks it**

   Define a policy where new faces are added to the local cache after three encounters but removed if not seen again within one week.

3. **Likely payoff**

   This policy will maintain a lean yet effective memory system that balances resource usage with the need for reliable face/name recall, enhancing both trust and performance without overwhelming the device's limited storage.

4. **Immediate next probe**

   Define a local cache size limit of 50 entities for face/name memory to balance contextual support and resource efficiency.
