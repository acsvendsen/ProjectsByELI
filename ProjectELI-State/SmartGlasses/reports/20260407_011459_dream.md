### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules to ensure subtitles remain stable yet unobtrusive, we can enhance the wearer's trust in the system without overwhelming their visual attention during live conversations. This stability is crucial for maintaining confidence in real-time assistance.

2. **What small change unlocks it**

   Define a simple subtitle placement rule that keeps subtitles near the center of the field of view but slightly below and to one side, ensuring they are visible yet not distracting.

3. **Likely payoff**

   A well-defined subtitle placement will reduce visual fatigue during prolonged use and ensure that subtitles remain readable and understandable without causing distractions. This can significantly improve user trust in the system’s real-time assistance capabilities.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer understands the reliability of the subtitles and memory support. A clear, concise, and trustworthy confidence indicator can prevent misunderstandings and build stronger trust in the system.

2. **What small change unlocks it**

   Define a consistent confidence label format for different levels of certainty: "High", "Medium", and "Low". For example:
   - Score 0.85+ : High
   - Score 0.65-0.84 : Medium
   - Score <0.65 : Low

3. **Likely payoff**

   By clearly indicating the confidence level, users will have a better understanding of how much they can trust the subtitles and memory support. This can reduce cognitive load and enhance overall trust in the system.

4. **Immediate next probe**

   Define one confidence label format for different levels of certainty: "High", "Medium", and "Low".

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a specific local memory threshold for face/name recall, we can ensure that only the most relevant and frequently encountered individuals are cached on the phone. This reduces the risk of privacy concerns while still providing the wearer with useful and timely memory support.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects that is both efficient and effective. For example, allow up to 50 most frequently encountered faces/names to be cached locally on the phone, with a recency threshold of one week.

3. **Likely payoff**

   This small change will significantly reduce the memory footprint on the phone while maintaining high trust and utility for frequent contacts. It ensures that only relevant memories are stored, aligning with privacy constraints and user experience goals.

4. **Immediate next probe**
   - Define a local cache size limit of 50 most frequently encountered faces/names.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus cloud, we can ensure that critical subtitle processing happens on the device where latency and battery constraints are most stringent. This decision will help maintain real-time clarity and stability of subtitles, which is essential to keeping the wearer's trust in the system.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing as phone-local, with no fallbacks allowed until V1 confirms this approach works well. For example, explicitly state that all subtitle text rendering and initial confidence display must occur on the phone device.

3. **Likely payoff**

   By keeping subtitle processing local, we can ensure that subtitles are displayed in near real-time without the latency introduced by cloud communication. This will significantly enhance the wearer's trust in the system’s ability to provide accurate and timely information during live conversations.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task: live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are clearly prioritized over one-line prompts can enhance the wearer's ability to follow conversations in real-time without being overwhelmed by additional text, thereby maintaining trust and focus.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles always appear first, with one-line support appearing only when there is no available space or if the confidence of the spoken content is low enough to warrant an assistive prompt.

3. **Likely payoff**

   By prioritizing subtitles over one-line prompts, the system will maintain high clarity and reduce visual clutter, leading to a more focused user experience that can help the wearer stay better engaged in conversations.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
