## Subtitle Placement

**Feasible Now:** 
- **Subtitle Clarity**: The current focus on keeping subtitles clear, fast, and stable is critical to real-time interaction. Given the current project emphasis on ensuring that subtitles are readable in noisy environments, subtitle placement should remain unobtrusive but visible enough for quick reference. Placements like top-center or side-center (e.g., along the temple) could be tested early without adding significant hardware complexity.

**Assumptions Needing Evidence:**
- **User Testing**: Concrete evidence on preferred placements can come from user testing with prototypes placed in various positions. This should include both physical placement and visual clarity tests to ensure subtitles are not distracting but still easily readable during fast conversations.
  
## Confidence Display

**Feasible Now:** 
- **Label Only vs Label + Short Reason vs Score + Label**: Given the current emphasis on avoiding command overhead, a label-only system could be implemented initially. This approach balances ease of use with clarity in uncertain situations. If users find this sufficient and do not perceive it as lacking, no further complexity is needed. 

**Assumptions Needing Evidence:**
- **User Feedback Loop**: Implementing a simple confidence display (e.g., "low," "medium," "high") could be tested early. Gathering user feedback through the TranscriptLab app to see if this level of detail is sufficient or if more nuanced information is necessary.
  
## Memory/Cache Policy

**Feasible Now:** 
- **Memory Storage and Reinforcement**: The initial implementation should focus on remembering names, faces, and prior context using a basic reinforcement learning approach. This can start with a simple cache policy that stores recent interactions (e.g., last 5 conversations) and gradually builds up over time.

**Assumptions Needing Evidence:**
- **User Interaction Patterns**: Understanding the frequency and nature of user interactions will help determine how much memory to store locally versus remotely. Early testing in the TranscriptLab app can provide insights into what kind of information users find most useful.
  
## Phone/Cloud Boundary

**Feasible Now:** 
- **Phone First**: The initial architecture should remain phone-first, with cloud services used only where clearly justified by latency and performance needs.

**Assumptions Needing Evidence:**
- **Latency Testing**: Early testing in the TranscriptLab app can help determine if certain tasks (e.g., face recognition, voice transcription) need to be offloaded to the cloud. If the local processing is sufficient for initial tests, this can guide future decisions on when and how to introduce cloud services.
  
## Visual Hierarchy

**Feasible Now:** 
- **Subtitle vs Prompt Display**: Subtitles should remain prominently displayed while one-line prompts should appear in a less dominant but still visible way. This could be achieved through different colors or font sizes, ensuring that subtitles are the primary focus.

**Assumptions Needing Evidence:**
- **User Feedback on Readability**: Testing with different visual hierarchy setups (e.g., subtitle color vs prompt color) can provide insights into what is most readable and least distracting during fast interactions.
