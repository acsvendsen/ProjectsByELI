# Consolidation of Recent Project Signals

## Strengthening Signals
- **Subtitle Clarity**: The need for clear, stable subtitles that remain trustworthy during live conversations is becoming more critical as we refine our subtitle rendering algorithms.
- **Memory Trustworthiness**: There's growing emphasis on ensuring memory support is reliable and does not introduce false certainty. This includes better confidence displays and handling of uncertainty.

## Weakening Signals
- **Rich Context vs Low-Latency Response**: The urgency to provide rich, context-aware assistance is starting to subside in favor of more immediate, actionable support.
- **Discreet UX vs Visual Clarity**: As we move towards V1, the focus on achieving a balance between discreet and clear UI is shifting slightly towards ensuring the UI remains readable.

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: The tension between providing useful assistive features without compromising privacy must be continuously managed. This includes careful handling of user data and transparent communication about how data is used.
- **Always-On Sensing vs Battery and Thermals**: The constraints on always-on sensing to preserve battery life are persistent, and any new features must consider this tradeoff.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement and Visual Hierarchy**: These ideas should be revisited to ensure the placement of subtitles is both unobtrusive and effective. The visual hierarchy needs optimization for readability in noisy environments.
- **Face/Name Memory Reinforcement**: There’s a need to revisit how face/name memory is reinforced over time, ensuring it remains reliable and doesn’t degrade with repeated use.

## Concrete Tensions Around Subtitle Quality, Confidence Trust, Automatic New-Person Memory, Memory Reinforcement, Fast Lookup, Privacy, Latency, Battery, Visual UX
- **Subtitle Quality**: Ensure subtitles are clear, stable, and easily readable in various environments.
- **Confidence Trust**: Develop a robust confidence display that builds trust without being intrusive.
- **Automatic New-Person Memory**: Implement memory reinforcement for new faces and names to ensure reliable recall over time.
- **Memory Reinforcement**: Improve how context is reinforced through interactions to maintain strong memory support.
- **Fast Lookup**: Balance the need for fast lookup with the risk of storing low-value information, ensuring only relevant data is retained.
- **Privacy**: Ensure privacy constraints are strictly followed and communicated transparently to users.
- **Latency**: Minimize latency in subtitle delivery while maintaining a balance between rich context and immediate response.
- **Battery**: Optimize power usage for always-on features without sacrificing functionality.
- **Visual UX**: Design the UI to be both discreet and effective, ensuring subtitles are readable without being distracting.

## Open Questions
- **Subtitle Placement and Visual Hierarchy**: What is the best placement of subtitles to minimize distraction while ensuring readability?
- **Confidence Display**: How should confidence be represented: as a numeric score, label, or short reason?
- **Memory/Cache Policy**: How much face/name memory should be cached locally on the phone versus relying on cloud storage?
- **Phone/Cloud Boundary**: What interactions should work offline and which require cloud support?

## Core Deepening vs Feature Sprawl
The project should continue to focus on core deepening, particularly in subtitle quality, memory trustworthiness, and visual UX improvements. Broad feature expansion without strong justification is not encouraged.

## Reality-Check Rule
Surface real-world constraints early to prevent optimizing for impossible directions. This includes hardware limitations, battery management, latency considerations, privacy concerns, and usability issues.
