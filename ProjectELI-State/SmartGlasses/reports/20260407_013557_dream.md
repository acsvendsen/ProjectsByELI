### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - By refining subtitle placement rules based on confidence levels, V1 can ensure that subtitles are always in a clear, non-distracting position, thereby improving the wearer's trust and understanding during live conversations.

2. **What small change unlocks it**
   - Define three distinct subtitle placement modes: one for high-confidence situations where subtitled names and faces are highly reliable, another for medium-confidence situations with some uncertainty, and a third for low-confidence scenarios where subtitled information is less certain but still valuable.

3. **Likely payoff**
   - This approach will result in more consistent and trustworthy subtitles during live interactions, reducing the risk of distractions or misunderstandings. It also aligns with the core attractor of real-time subtitle clarity by ensuring that the most critical information appears where it can be seen and understood most easily.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances the wearer's trust in the system by clearly indicating the reliability of the displayed information. This is crucial for maintaining a balance between real-time assistance and avoiding false certainty, which could lead to misunderstandings or social awkwardness.

2. **What small change unlocks it**

   Define two specific confidence label formats: one that uses a simple numeric score with a label (e.g., "90% High") and another that includes both the label and a short reason for the confidence level (e.g., "85% High, seen in last 10 minutes").

3. **Likely payoff**

   By clearly indicating the certainty of name or face recognition through specific labels and short reasons, the system can maintain high trust levels without overloading the wearer with too much information. This clarity will help users better understand when they should rely on the system's suggestions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we can ensure that critical information like names and faces are reliably remembered without overloading the phone's memory or causing privacy concerns. This helps in maintaining trust and ensuring that the glasses can quickly provide relevant support to the wearer.

2. **What small change unlocks it**

   Define a local cache size limit of 10 entries for face/name recall, with each entry having a recency threshold of 7 days.

3. **Likely payoff**

   This small change will help in maintaining a balance between useful memory and privacy. It ensures that names and faces are remembered reliably for a week, providing consistent support without overwhelming the phone's storage or raising privacy concerns.

4. **Immediate next probe**
   - Set the recency threshold for face/name recall to 7 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud, we can ensure that critical real-time subtitle processing and memory recall happen on the device, reducing latency and improving trust. This focus will help maintain the low-friction, always-on nature of the system, which is essential for the core attractors of real-time subtitle clarity (subtitle_clarity) and trustworthy memory support (memory_trust).

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that stays phone-local to ensure near-real-time performance. For example, set the rule that all face/name recall and memory lookup tasks should fallback to cloud only if there is no local cache available or if the context requires richer analysis.

3. **Likely payoff**

   By keeping critical real-time functions like face/name recall on the phone, we can significantly reduce latency and ensure that the system remains highly responsive. This will enhance the wearer's trust in the product by providing timely and accurate support without the delays associated with cloud processing.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

1. **Why it benefits the core**

2. **What small change unlocks it**

3. **Likely payoff**
