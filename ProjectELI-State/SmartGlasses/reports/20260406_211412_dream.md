### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Ensuring consistent subtitle placement enhances the wearer's trust in real-time subtitles, which is crucial for understanding and interaction in noisy environments.

2. **What small change unlocks it**
   - Define a fixed subtitle placement rule that prioritizes stability over reactivity: place subtitles at the bottom center of the screen regardless of confidence levels.

3. **Likely payoff**
   - By setting a stable subtitle position, the wearer can rely on consistent and unobtrusive subtitle visibility, reducing cognitive load and increasing focus during conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format directly addresses the tension between privacy vs usefulness by ensuring that the wearer can trust the system's memory support while respecting their privacy. A clear and honest confidence display helps build user trust in the memory capabilities, allowing for more reliable recall of names and faces without overwhelming the wearer with uncertain information.

2. **What small change unlocks it**

   Define a simple confidence format that combines a numeric score, label, and short reason. For example:
   - `0.95 + "High" + "Seen multiple times recently"`

3. **Likely payoff**

   By implementing a clear and concise confidence display, the system will better convey its certainty to the wearer, reducing uncertainty and improving overall trust in memory support. This clarity can lead to more effective use of the memory features without creating privacy concerns.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a local cache threshold for name recall, we can ensure that frequently encountered names are stored and readily accessible on the phone, reducing latency and improving memory trust while staying within battery constraints.

2. **What small change unlocks it**

   Implement a simple cache eviction policy where names seen more than 10 times in the last hour are retained locally, with older or less frequent names evicted to keep the cache size manageable.

3. **Likely payoff**

   This policy will enhance memory recall speed and accuracy for frequently encountered people without significantly increasing battery usage, thus maintaining trust and usability.

4. **Immediate next probe**

   Define one local-cache size limit for name recall retention of 20 entries per hour.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   By defining a clear boundary for phone-local processing versus cloud fallback, we ensure that critical real-time subtitle and memory support functions are handled on the phone, maintaining low latency and preserving the wearer's trust in the system.

2. **What small change unlocks it**
   Define one task-specific cloud fallback boundary, such as face/name recall lookup, where the glasses can request a name or face from the cloud if the local memory does not have enough confidence to provide a reliable response.

3. **Likely payoff**
   This approach ensures that critical real-time interactions remain smooth and responsive on the phone, enhancing trust by keeping sensitive operations closer to the user while still leveraging cloud capabilities for less time-critical tasks like background updates or complex memory lookups.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
