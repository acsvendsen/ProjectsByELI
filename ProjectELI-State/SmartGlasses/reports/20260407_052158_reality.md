# Reality Check

## Subtitle Placement: Feasible Now
- **Subtitle placement** should focus on making subtitles readable without being overly distracting. Given the current implementation constraints (V1 frame-touch interaction, early phone-first processing), placing subtitles at the bottom of the glasses' field of view would be feasible. This position ensures that subtitles are visible but do not obstruct the wearer's primary viewing area. However, further testing and iteration will be needed to find the optimal balance.

## Confidence Display: Feasible Now
- **Confidence display** can use a simple label format initially (e.g., "High", "Medium", "Low") along with a brief reason when necessary. The current implementation in `TranscriptLab` provides a foundation for experimenting with different confidence formats, such as labels only or including a short reason. This approach aligns with the core-deepening mode and respects the constraint of avoiding speculative hardware complexity.

## Memory/Cache Policy: Feasible Now
- **Memory policy** should initially cache face/name memory on the phone to support quick lookups. Given that early versions rely heavily on phone processing, caching relevant memories can help in providing useful context quickly. However, this needs further refinement and testing to ensure it does not overwhelm the user or violate privacy concerns.

## Phone/Cloud Boundary: Feasible Now
- **Phone/cloud boundary** should remain focused on keeping the initial interaction simple (frame touches) and processing heavy tasks off-glasses until justified by performance bottlenecks. The current implementation in `TranscriptLab` tests phone-side transcript behavior effectively, indicating that early versions can operate primarily on the phone.

## Visual Hierarchy: Feasible Now
- **Visual hierarchy** should prioritize readability and minimal distraction. Given the frame-touch interaction constraint, subtitles should be displayed prominently but not overly obtrusively. Testing different visual hierarchies in `TranscriptLab` will help refine this aspect without adding unnecessary complexity initially.

## Core Deepening Over Sprawl: Feasible Now
- **Core-deepening over sprawl** is a guiding principle and remains feasible now. The current focus on improving subtitle quality, memory support, and confidence behavior aligns well with the project's core mission of providing real-time assistance without overwhelming the user.

## Privacy vs Usefulness: Feasible Now
- **Privacy vs usefulness** is an active tension that requires careful balance. The current implementation avoids invasive capture or retention by focusing on helping the wearer understand better rather than pretending certainty. However, ongoing testing and refinement will be necessary to ensure this balance is maintained as features evolve.

## Latency vs Richness: Feasible Now
- **Latency vs richness** can be managed by ensuring that subtitles remain clear and stable even when processing demands increase. The current implementation in `TranscriptLab` provides a foundation for experimenting with different levels of richness, but initial focus should remain on maintaining low latency.

## Discreet UX vs Visual Clarity: Feasible Now
- **Discreet UX vs visual clarity** can be addressed by placing subtitles at the bottom and ensuring they are readable without being overly intrusive. The current implementation in `TranscriptLab` allows for iterative testing to find the best balance between these two considerations.

## Real-time Subtitle Clarity: Feasible Now
- **Real-time subtitle clarity** is critical for maintaining trust during live conversations. The initial implementation in `TranscriptLab` provides a good starting point, and further testing will help refine this aspect without overcomplicating the system.

## Memory Support Trustworthiness: Feasible Now
- **Memory support trustworthiness** can be improved by initially caching relevant memories on the phone for quick lookups. This approach aligns with the early V1 constraints and allows for iterative refinement based on real-world use cases.

## Low-friction Assistance: Feasible Now
- **Low-friction assistance** is an active attractor that can be achieved through one-line prompts that do not create command overhead or social awkwardness. The current implementation in `TranscriptLab` provides a foundation for experimenting with different low-friction interaction patterns.

### Summary of Recommendations

- **Subtitle Placement**: Bottom of the glasses' field of view, testing to ensure readability without distraction.
- **Confidence Display**: Simple label format initially (e.g., "High", "Medium", "Low"), with brief reasons as needed.
- **Memory Policy**: Cache face/name memory on the phone for quick lookups but test extensively.
- **Phone/Cloud Boundary**: Focus on phone processing, with cloud support optional where clearly justified.
- **Visual Hierarchy**: Prominent but not obtrusive placement of subtitles, testing different visual hierarchies in `TranscriptLab`.
- **Core Deepening Over Sprawl**: Prioritize subtitle quality, memory trust, and visual UX improvements.

These recommendations align with the current project inputs and constraints while allowing for iterative refinement as the system evolves.
