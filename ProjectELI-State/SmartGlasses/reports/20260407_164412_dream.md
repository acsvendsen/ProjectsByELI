### Idea 2: Confidence Display

1. **Why it benefits the core**

   Enhancing the confidence display format will improve the trustworthiness of subtitle and memory assistance, ensuring that the wearer understands when to rely on the system's suggestions. A clear and consistent confidence label combined with a short reason will help reduce cognitive load and increase the wearer's confidence in the system’s reliability.

2. **What small change unlocks it**

   Define a new confidence format that includes a numeric score, a confidence label (e.g., "High," "Medium," or "Low"), and a short reason for the level of certainty. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

   By providing clear and understandable confidence levels, users will be better able to trust the system's real-time subtitle assistance and memory support. This clarity can lead to a more natural and effective use of the glasses without causing unnecessary cognitive strain or skepticism.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we ensure that frequently encountered faces and names are stored on the phone with higher priority. This improves memory trust and support for daily-use scenarios where frequent interactions occur with known people.

2. **What small change unlocks it**

   Define a local cache eviction rule that prioritizes recently seen or often recalled entities over less relevant data, ensuring the memory system retains high-confidence face/name information while managing storage efficiently.

3. **Likely payoff**

   This change will enhance the reliability of name recall for common interactions, reducing the need to query the cloud and improving the overall user experience by providing faster and more accurate support in everyday conversations.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that critical subtitle processing and memory recall are handled efficiently on-device, maintaining low latency and privacy while offloading less time-sensitive tasks to the cloud. This balance helps preserve the real-time nature of subtitles and the trustworthiness of memory support.

2. **What small change unlocks it**

   Define one specific task boundary for exactly what runs phone-local versus what falls back to the cloud. For instance, choose a task like live subtitle processing and commit to handling all real-time subtitle generation on-device while offloading transcript cleanup or memory archive sync to the cloud when needed.

3. **Likely payoff**

   By keeping critical tasks local, we reduce latency, preserve privacy, and ensure that subtitles remain clear and stable in real-time interactions. This will enhance trust and usability, aligning with our core attractors of subtitle clarity and memory trust.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
