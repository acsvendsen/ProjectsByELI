# Reality Check Summary

## Subtitle Placement: Feasible Now
- **Subtitle Placement**: The current focus on subtitle clarity (high strength) and real-time delivery is feasible now, given the existing `TranscriptLab` test app. The app provides a framework to ensure subtitles are clear, fast, and stable enough for live conversation.
- **Reasoning**: The project has already implemented basic transcript functionality in `TranscriptLab`. Ensuring that subtitles can be placed effectively without becoming distracting will involve minor adjustments to the visual hierarchy, which is within the current scope.

## Confidence Display: Feasible Now
- **Confidence Display**: Implementing a confidence format (e.g., label + short reason) that builds trust while remaining simple and readable is feasible now. The project can use the `TranscriptLab` app to test different display methods.
- **Reasoning**: Current implementation in `TranscriptLab` includes basic confidence displays, allowing for testing and refinement of these formats.

## Memory/Cache Policy: Feasible Later
- **Memory/Cache Policy**: Deciding how much face/name memory should be cached locally on the phone is a more complex decision that can be addressed later. The current implementation focuses on core functionalities.
- **Reasoning**: While `TranscriptLab` allows for basic memory support, a detailed cache policy will require deeper integration and testing with actual glasses hardware, which is beyond V1 constraints.

## Phone/Cloud Boundary: Feasible Later
- **Phone/Cloud Boundary**: Determining the exact roles of the phone and cloud in real-time processing can be addressed later. The current focus on phone-first processing aligns with early V1 goals.
- **Reasoning**: Early development focuses on local processing to minimize battery drain and thermal issues, making this a future consideration.

## Visual Hierarchy: Feasible Later
- **Visual Hierarchy**: Defining the best subtitle placement and visual hierarchy for fast reading is a more complex task that can be addressed after core functionalities are in place.
- **Reasoning**: Current implementation in `TranscriptLab` allows for basic display testing, but refining the visual hierarchy will require more detailed user testing with actual glasses.

## Assumptions Needing Evidence
- **Subtitle Placement**: The specific placement of subtitles needs evidence through user testing. While `TranscriptLab` can provide initial insights, more refined tests are necessary.
- **Confidence Display**: The format and effectiveness of confidence displays need empirical evidence from user interactions.
- **Memory/Cache Policy**: Determining the optimal memory caching strategy requires further experimentation with actual glasses hardware.
- **Phone/Cloud Boundary**: Defining precise roles for phone and cloud processing will require more detailed design and testing.

## Core Deepening Over Sprawl
- The project should focus on core deepening rather than broad feature expansion. This aligns well with the current goals of improving subtitle quality, memory trust, and visual UX.
- **Reasoning**: Given the `core_deepening` mode in the current scorecard, efforts should be directed towards refining these core functionalities.

## Constraint Pressure
- Early identification of constraints such as battery, latency, privacy, and usability is crucial to avoid wasting time on infeasible directions.
- **Reasoning**: The project has already identified key constraints like real-time delivery (latency) and social acceptability. Continuous monitoring of these constraints will ensure that the product remains feasible.

## Likely Waste of Time
- **Automatic Memory Support vs Confidence and Correction Safety**: While this is an important tension, implementing a fully automatic memory support system now might be premature without empirical evidence from user testing.
- **Reasoning**: The project should focus on core functionalities before addressing more complex behaviors like automatic memory support.

By focusing on these core areas and continuously monitoring constraints, the project can ensure that its development efforts are aligned with real-world limitations and user needs.
