### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states ensures that subtitles are always visible and readable, reducing cognitive load and enhancing the wearer's understanding during live conversations. This helps in maintaining trust by ensuring that important information is not missed.

2. **What small change unlocks it**

   Define two to three subtitle placement rules for different confidence levels: one for high confidence (where the system is certain of the speaker), another for medium confidence (where there is some uncertainty), and a third for low confidence (where the system is unsure). This will create a clear hierarchy that guides where subtitles should appear based on their reliability.

3. **Likely payoff**

   By establishing distinct subtitle placement rules, V1 can ensure that high-confidence subtitles are prominently visible, while lower-confidence ones are less intrusive but still clearly visible. This improves overall subtitle clarity and trustworthiness without overwhelming the wearer with too much text.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display ensures that the wearer has a clear understanding of the certainty behind each memory or subtitle. This enhances trust in the system, making interactions more natural and less prone to social awkwardness. By providing a reliable confidence format, we can support the wearer's ability to navigate conversations with greater ease.

2. **What small change unlocks it**

   Define a simple numeric score + label + short reason format for confidence objects. This format provides a clear and concise way to convey certainty without overwhelming the user with too much detail.

3. **Likely payoff**

   A well-defined confidence format will help in building trust with the wearer, as they can easily understand when the system is certain about something versus when it has lower confidence. This clarity will reduce uncertainty and enhance the overall user experience.

4. **Immediate next probe**
   - Define the confidence score presentation as "0.84" for V1.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory cache size and eviction policy will enhance the trustworthiness and utility of name recall in live interactions. By ensuring that frequently encountered faces and names are cached locally, the system can provide faster and more reliable recall without overwhelming the wearer with too many entities.

2. **What small change unlocks it**

   Define a simple local cache policy that evicts less-recently used entries when the cache size exceeds a threshold. This involves setting a specific number of items to keep in memory locally, based on their recency and confidence levels.

3. **Likely payoff**

   The payoff is improved real-time name recall performance, reducing the latency and improving the overall trustworthiness of the system. Frequent encounters with names can be quickly recalled without needing cloud assistance, enhancing the wearer's confidence in the product’s reliability.

4. **Immediate next probe**

   Define one local-cache size limit for face/name memory objects, set at 10 items to balance between utility and memory conservation.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains phone-local can significantly reduce latency and improve the overall responsiveness of the system. This approach aligns with the core mission of delivering clear, real-time subtitles without breaking the wearer's concentration.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing to run entirely on the phone rather than falling back to cloud support under any circumstances. This can be achieved by setting up a local cache and processing pipeline that handles all necessary transcript data, confidence scoring, and subtitle generation within the phone's runtime.

3. **Likely payoff**

   By keeping live subtitle processing phone-local, we reduce latency, enhance reliability, and ensure that subtitles are delivered with minimal delay. This improves trust in the system’s ability to provide clear and timely assistance during conversations, which is critical for the core mission of helping wearers understand real-time interactions.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can easily read critical information without being overwhelmed by additional text, thereby enhancing the overall assistive value and reducing cognitive load.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles always have higher precedence and are displayed first in any given frame, with one-line prompts shown only when there is no subtitle or when the confidence of the subtitle falls below a certain threshold.

3. **Likely payoff**

   By ensuring that subtitles take precedence over one-line prompts, we can maintain the wearer's focus on critical information while still providing useful context through shorter, less intrusive prompts. This will help in maintaining clarity and reducing cognitive overload during real-time interactions.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
