### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain a consistent user experience, reducing visual distractions and enhancing trust in the system's ability to provide accurate and timely information. Stable placement also aligns with the project's mission of low-friction assistance by minimizing unnecessary visual changes that could disrupt the wearer's flow during conversations.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence situations (e.g., well-known speakers or familiar contexts) and another for lower-confidence scenarios (e.g., new faces or noisy environments). This differentiated approach allows the system to adapt its visual priority without overwhelming the wearer, thereby maintaining a balance between information provision and user comfort.

3. **Likely payoff**

   By implementing distinct subtitle placement rules based on confidence levels, the system can provide more relevant and timely information in real-time conversations, enhancing the overall usability and trustworthiness of the smart glasses. This refinement will help reduce visual clutter during high-confidence situations while ensuring critical information is always easily accessible.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display by using a clear, label-based format with a short reason will enhance trust and clarity in memory support. This ensures that the wearer understands the reliability of the information provided without overloading them with too much detail.

2. **What small change unlocks it**

   Define a simple, label-based confidence format for face/name memories. The format should include a certainty label (e.g., "High," "Medium," "Low") and a short reason (e.g., "Seen recently," "Weak match," "Name heard once").

3. **Likely payoff**

   By using this simplified confidence display, the system will provide more reliable memory support that is easy to interpret. This will reinforce trust in the wearer's memory recall process, making them more likely to rely on the glasses for accurate name and face recognition.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new names and faces are remembered with a robust, reinforcement-based memory system helps build trust in the assistant's reliability. By automatically linking new evidence to existing person-memory objects, the system can provide more accurate and contextually relevant support over time.

2. **What small change unlocks it**

   Introduce a simple entity-linking rule that attaches new face or name evidence to an existing memory object based on similarity scores, with a threshold for initial reinforcement. This rule will ensure that when a new person is encountered, their memory object is created and linked confidently.

3. **Likely payoff**

   By implementing this small change, the system can automatically and reliably remember new people without requiring explicit user interaction, thus reducing friction and increasing trust in the assistant's ability to support the wearer over time.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we ensure that critical processing such as live subtitle generation and face/name recall remain stable and responsive. This helps maintain trust and real-time usability, which are key to the SmartGlasses' core mission of enhancing understanding in noisy environments.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing runs entirely on the phone. For example, use the "live subtitle processing" task as the clear decision point for what stays phone-local and does not fallback to the cloud.

3. **Likely payoff**

   By ensuring real-time subtitles are handled locally, we can avoid latency issues that could degrade the wearer's experience. This leads to a more reliable and trustworthy system that remains responsive even under poor network conditions.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line prompts, we ensure that the most critical information is prioritized and presented in a way that minimizes distraction while maximizing clarity. This improves the wearer's focus during conversations by ensuring they can quickly read and understand key phrases without feeling overwhelmed.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prefers subtitles to one-line prompts when both are active, but allows one-line prompts to override subtitles if necessary for urgent or time-sensitive information. This ensures that subtitles remain the primary source of continuous context while one-line prompts can interject with critical real-time support.

3. **Likely payoff**

   By maintaining a clear visual hierarchy, we reduce cognitive load and distractions, enhancing overall understanding and response times during conversations. This improves the wearer's experience by making it easier to follow along without being overwhelmed, thus deepening trust in the system’s assistive capabilities.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
