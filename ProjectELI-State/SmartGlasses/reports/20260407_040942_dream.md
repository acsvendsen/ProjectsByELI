### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules based on confidence levels, we ensure that subtitles remain clear and unobtrusive while providing critical information when needed most. This helps maintain real-time clarity and trust in noisy or challenging environments.

2. **What small change unlocks it**

   Define three subtitle placement modes: fixed position at the bottom of the frame for high-confidence matches, fading-in from the top-right corner for medium-confidence matches, and dynamic adjustment to avoid overlapping with text that the wearer is currently reading for low-confidence matches.

3. **Likely payoff**

   This refined placement strategy will enhance the user's trust in the system by ensuring that subtitles are always visible when needed but do not interfere with reading or conversation flow. It balances the need for clarity and distraction minimization effectively.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to be more explicit about certainty and source, we can enhance trust in both subtitle accuracy and memory recall. This clarity will help the wearer better understand when information is highly certain versus when there's a lower level of confidence.

2. **What small change unlocks it**

   Define a consistent confidence object format that includes a numeric score, label, and short reason for each piece of information displayed to the user. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   This change will provide the wearer with a clear and honest indication of confidence levels, which can significantly enhance trust in both subtitle accuracy and memory recall. Clear and consistent confidence indicators will make it easier for the user to distinguish between highly certain information and uncertain data.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a strict local cache threshold for face/name memory on the phone, we can ensure that only the most relevant and recent memories are stored and reinforced locally. This approach balances the need for fast lookup with the practical limitations of battery and thermal management.

2. **What small change unlocks it**

   Define a local cache size limit for person-memory objects, specifically setting it to retain only the top 5 most recently encountered faces/names within a session.

3. **Likely payoff**

   This change will reduce memory storage overhead on the phone while ensuring that key individuals are remembered with high confidence and quick recall. It helps maintain trust by not overwhelming the local cache with irrelevant information, thus preserving battery life and reducing thermal strain.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs phone-local versus falling back to cloud, the system can balance real-time responsiveness with efficient use of resources, ensuring that critical processing stays on-device while less time-sensitive tasks offload to the cloud.

2. **What small change unlocks it**

   Define a single task-specific boundary rule, such as live subtitle processing, for which all confidence and memory operations must remain phone-local to ensure timely and accurate real-time support.

3. **Likely payoff**

   This approach will significantly enhance the glasses' ability to provide real-time subtitles without undue battery drain or latency issues, ensuring that the wearer receives immediate and reliable assistance in noisy environments.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
