# Reality Check for SmartGlasses

Based on the provided core field, scorecard, and linked documents, here is an assessment of proposed directions against real-world limits:

### Subtitle Placement: Feasible Now
- **Current State**: The system should keep subtitles clear, fast, and stable enough that the wearer can trust them in live conversation. Given the current `TranscriptLab` test app and its focus on real-time transcript behavior, subtitle placement can be optimized through iterative testing.
- **Reasoning**: With the existing setup in `TranscriptLab`, we can experiment with different placements to ensure subtitles do not distract but remain readable. This is feasible now as it does not require new hardware or significant changes beyond UI adjustments.

### Confidence Display: Feasible Now
- **Current State**: The system should deliver one-line help and visible support without creating command overhead or social awkwardness.
- **Reasoning**: Using the `TranscriptLab` app, we can test different confidence display formats (label only, label + short reason) to determine which format builds trust best. This is a feasible now task as it involves UI/UX tweaks within an existing framework.

### Memory/Cache Policy: Feasible Later
- **Current State**: The system should remember names and faces without creating corrupted recall.
- **Reasoning**: Implementing face/name memory requires significant backend processing, which is currently offloaded to the phone and cloud. Optimizing this policy will depend on the stability of `TranscriptLab` and future enhancements in confidence behavior. This task can be deferred until we have more concrete data from early testing.

### Phone/Cloud Boundary: Feasible Now
- **Current State**: The system should primarily rely on phone processing, with cloud optional where clearly justified.
- **Reasoning**: Given the current setup, we can fine-tune the phone-side transcript plumbing and confidence display within `TranscriptLab`. This ensures that V1 interactions remain simple and do not depend heavily on cloud resources.

### Visual Hierarchy: Feasible Now
- **Current State**: The system should favor clarity over feature density.
- **Reasoning**: With the current focus on subtitle placement and confidence display, optimizing visual hierarchy involves ensuring subtitles are readable while minimizing distractions. This can be done within `TranscriptLab` by iteratively refining UI design.

### Summary of Feasibility
- **Subtitle Placement & Confidence Display**: Feasible Now - Can be tested and optimized with existing tools.
- **Memory/Cache Policy**: Feasible Later - Dependent on early testing results.
- **Phone/Cloud Boundary & Visual Hierarchy**: Feasible Now - Can be refined within current setup.

### Assumptions Needing Evidence
- **Subtitle Quality Improvement**: While the core field emphasizes subtitle clarity, we need evidence from `TranscriptLab` to ensure real-time subtitles are usable in noisy environments.
- **Face/Name Memory Trustworthiness**: Further testing is needed to ensure that memory support does not create corrupted recall or invade privacy.

### Next Steps
1. **Subtitle Placement & Confidence Display**: Continue optimizing these within `TranscriptLab`.
2. **Memory/Cache Policy**: Plan future iterations based on initial testing.
3. **Phone/Cloud Boundary & Visual Hierarchy**: Refine and test the current setup to ensure it meets V1 requirements.

By focusing on core-deepening changes and respecting the existing constraints, we can iteratively improve the system's daily-use value without straying into speculative feature sprawl.
