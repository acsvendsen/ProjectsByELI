### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules to ensure subtitles remain stable, clear, and unobtrusive in various confidence states, we enhance the wearer's trust in real-time understanding. Stable and predictable subtitle placement reduces distraction and cognitive load, allowing the wearer to focus more on the conversation.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence speech (e.g., clear speakers) where subtitles can be placed closer to the center of the field of view, and another for low-confidence speech (e.g., noisy environments or less clear speakers) where subtitles are placed lower in the peripheral vision.

3. **Likely payoff**

   Implementing these placement rules will make subtitles more reliable and unobtrusive across a variety of speaking conditions, reducing user frustration and increasing trust in the system's ability to provide accurate real-time support.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance trust in both subtitle clarity and memory recall, ensuring that the wearer can better understand and respond to real-world interactions without over-relying on uncertain information.

2. **What small change unlocks it**

   Introduce a new confidence label "Uncertain" for situations where the system is less certain but still providing support. This label will be accompanied by a short reason such as "Weak match" or "Seen once".

3. **Likely payoff**

   By clearly indicating when the system is uncertain, the wearer can take appropriate actions, such as paying more attention to context clues or seeking clarification from others. This improves overall trust and reliability in both subtitle clarity and memory support.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Memory caching and local storage rules for names and faces directly benefit the core by ensuring that the wearer can rely on quick, accurate recall of people's names and relevant context without overloading the phone or cloud with heavy processing requests. This improves trust in memory support, which is a primary attractor for the project.

2. **What small change unlocks it**

   Define a simple local cache eviction policy where old entries are replaced by new ones based on recent encounters but keep a minimum threshold of 5-10 key person memories to ensure quick recall and reinforcement over time.

3. **Likely payoff**

   By implementing this cache rule, the system will maintain a balance between memory richness and low-friction usability. The wearer can expect quick retrieval of names and context without frequent cloud queries, reducing latency and battery use while maintaining high confidence in memory support.

4. **Immediate next probe**

   Define one local-cache size limit for key person memories set at 10 entries to balance memory recall speed with system resource usage.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

By defining clear phone-local vs cloud boundaries, we can ensure that V1 focuses on delivering real-time subtitle clarity and memory trust without overloading the device or compromising privacy. This helps maintain a balance between utility and usability, ensuring that the system remains reliable and discreet.

2. **What small change unlocks it**

Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing. For example, decide when to hand off real-time subtitle generation from the phone to the cloud, based on network conditions or resource availability.

3. **Likely payoff**

This decision will help in maintaining low latency and high accuracy for subtitles during critical moments, ensuring that the wearer can trust the system even in poor network conditions. It also allows us to scale up processing power when needed without impacting the device's local resources, thereby preserving battery life and thermal management.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear, fast, and stable subtitle display in real-time helps maintain trust during conversations. A well-designed visual hierarchy ensures that subtitles are readable without distraction, allowing the wearer to stay present and engaged.

2. **What small change unlocks it**

   Define one subtitle placement rule for different confidence states. For example, use higher priority (and less intrusive) placement for high-confidence matches, and lower priority (but still visible) placement for low-confidence matches.

3. **Likely payoff**

   By optimizing subtitle placement based on confidence levels, the system can reduce visual distractions while ensuring critical information is always visible, thereby enhancing trust and real-time utility without overwhelming the wearer.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
