# Consolidation of Core Signals for SmartGlasses V1

## Strengthening Signals
- **Subtitle Quality**: The system should prioritize real-time subtitle assistance, ensuring subtitles are clear, accurate, and unobtrusive. This includes optimizing placement and visual hierarchy to minimize distraction while maximizing comprehension.
- **Face/Name Memory Reinforcement**: Automatic memory behavior for new faces and names should be enhanced through confidence objects and frequent reinforcement over time. Explicit remember-touch behavior will also play a crucial role in reinforcing these memories.

## Weakening Signals
- **Voice Activation**: The system should not incorporate voice activation or spoken commands in V1, as the current design assumes frame touches only.
- **Complex AR Visuals**: Early versions should focus on text display and minimal sensors. Heavy AR visuals are not a priority for V1.

## Contradictions that Must Stay Alive
- **Battery and Thermal Constraints**: The glasses must remain lightweight and socially acceptable. Early versions should avoid heavy on-glasses compute to manage battery and thermal risks.
- **Privacy vs Usefulness**: The system must balance providing useful assistance with respecting privacy constraints, ensuring the wearer feels comfortable using it.

## Dormant Ideas Worth Reactivating
- **Phone/Cloud Boundary**: Explore how phone-cloud interactions can be optimized without overloading the glasses. This includes evaluating when cloud processing adds clear value and when local processing is sufficient.
- **Interaction Complexity**: Keep V1 interaction simple with frame touches only, avoiding unnecessary complexity that could distract from core functionalities.

## Concrete Tensions Around Key Areas
### Subtitle Quality vs Latency
- The system must balance real-time subtitle quality with minimal latency to avoid breaking trust. This tension will be managed by optimizing local processing and ensuring efficient communication between glasses and phone.

### Confidence Display vs Memory Policy
- **Confidence Display**: How should confidence be represented? Numeric scores, labels, or short reasons may need to be evaluated for their impact on trust.
- **Memory Policy**: Should face/name memory be cached locally or rely entirely on cloud processing? This tension will be addressed by determining the optimal balance between local caching and cloud reliance.

### Memory Reinforcement vs Privacy Perception
- The system should reinforce new faces/names through confidence objects while managing privacy concerns. This includes deciding how much personal data is stored and how it is handled.
  
### Fast Lookup vs Rich Context
- **Fast Lookup**: One-line prompts should be quick and helpful, without overwhelming the wearer with too much information.
- **Rich Context**: The system must provide enough context to support effective conversation memory while maintaining a low-friction user experience.
