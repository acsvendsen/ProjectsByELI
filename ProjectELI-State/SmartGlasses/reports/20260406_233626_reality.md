## Reality Check for SmartGlasses V1 Direction

### Subtitle Placement: Feasible Now

- **Subtitle Placement:** The current implementation should focus on placing subtitles in a location that is visible and readable but not distracting. Given the constraint of lightweight glasses, the subtitle placement can start with a simple top-center display, which balances visibility with minimal distraction.
  - **Reasoning:** This approach aligns with the core-deepening mode and respects the current hardware constraints. It allows for initial testing and validation without adding unnecessary complexity.

### Confidence Display: Feasible Now

- **Confidence Display:** Implement a simple confidence display using a label only, such as "High" or "Low," to indicate the reliability of subtitles. This can be integrated into the subtitle UI.
  - **Reasoning:** The current implementation in `TranscriptLab` can include basic confidence indicators, which will provide initial feedback and help users trust the system more easily.

### Memory/Cache Policy: Feasible Now

- **Memory/Caching Policy:** Start with a simple caching policy that stores minimal information locally on the phone. This can be expanded later if necessary.
  - **Reasoning:** Given the constraint of early hardware simplicity, initial memory policies should focus on storing only essential data to reduce battery and thermal strain.

### Phone/Cloud Boundary: Feasible Now

- **Phone/Cloud Boundary:** Early V1 interaction should rely heavily on the phone for processing. Use cloud services only where they add clear value, such as model upgrades or background processing.
  - **Reasoning:** The current `TranscriptLab` implementation already demonstrates a phone-first approach, which aligns well with the core-deepening mode.

### Visual Hierarchy: Feasible Now

- **Visual Hierarchy:** Design subtitles and one-line prompts to coexist without overloading the wearer. Use clear separation between subtitles and prompts.
  - **Reasoning:** This can be tested in `TranscriptLab` by implementing a simple visual hierarchy, ensuring that subtitles and prompts are distinct yet easily readable.

### V1 Interaction: Frame Touches Only

- **Interaction Constraint:** Ensure all interactions with the glasses happen through frame touches. Do not assume voice commands or spoken user commands for subtitle management.
  - **Reasoning:** This aligns with the hard constraint of `frame_touch_only_v1`. The current implementation in `TranscriptLab` should respect this by focusing on touch-based controls.

### Real-Time Subtitle Clarity

- **Subtitle Clarity:** Implement real-time subtitles that are clear, fast, and stable enough for live conversation. Initial tests can focus on improving readability and stability.
  - **Reasoning:** This is a core attractor and should be prioritized to ensure initial user trust in the system.

### Trustworthy Memory Support

- **Memory Support:** Implement name and face recall with clear uncertainty signals. Avoid creating false certainty or corrupted recall.
  - **Reasoning:** This aligns with the high-strength attractor of memory trust, ensuring that the system remains useful without compromising privacy or user trust.

### Low-Friction Assistance

- **Assistance:** Provide low-friction one-line prompts to help the wearer understand and respond. Ensure these are unobtrusive and provide clear value.
  - **Reasoning:** This aligns with the medium-strength attractor of low-friction assistance, ensuring that the system remains helpful without overwhelming the user.

### Constraint Pressure

- **Battery and Latency:** Surface real-world constraints early to ensure weak directions are identified quickly. Focus on real-time subtitle clarity and memory support.
  - **Reasoning:** This ensures that initial implementations focus on critical aspects of the core mission, such as subtitle quality and memory trust, without overwhelming other less critical areas.

### Core Deepening

- **Core Deepening Mode:** Prioritize improvements in subtitle quality, memory trust, and visual UX over broad feature expansion.
  - **Reasoning:** This aligns with the current mode `core_deepening`, ensuring that initial work focuses on strengthening core capabilities before expanding features.

### Summary of Feasibility

- **Subtitle Placement, Confidence Display, Memory/Caching Policy, Phone/Cloud Boundary, Visual Hierarchy:** These are all feasible now given the current constraints and implementation.
- **Interaction Constraint (Frame Touches Only):** This is a hard constraint that must be respected in V1.
- **Real-Time Subtitle Clarity, Trustworthy Memory Support, Low-Friction Assistance:** These align with core attractors and should be prioritized.

### Likely Waste of Time

- **Voice Activation:** Given the current interaction constraint of frame touches only, voice activation is likely a waste of time for V1.
  - **Reasoning:** Voice commands are not currently supported by the hardware constraints and would add unnecessary complexity.

By focusing on these areas, the project can ensure that initial implementations are grounded in real-world constraints while aligning with core attractors.
