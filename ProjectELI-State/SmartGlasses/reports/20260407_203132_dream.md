### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules that remain readable and unobtrusive will enhance the wearer's trust in the system during live conversations, aligning with the primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define a set of fixed subtitle placement rules based on confidence levels: high-confidence subtitles always visible at a consistent position; medium-confidence subtitles may fade out after 3 seconds if no action is taken; low-confidence subtitles show for 1 second and then disappear unless reinforced by user interaction.

3. **Likely payoff**

   By providing stable, predictable subtitle behavior, the system will maintain the wearer's trust in the subtitles' reliability during conversations. This reduces cognitive load and enhances focus on the conversation itself.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide clear and concise certainty information, we can enhance the wearer's trust in both subtitles and memory support. A well-designed confidence indicator will help users understand when they are more or less certain about a piece of information, reducing cognitive load and increasing overall system reliability.

2. **What small change unlocks it**

   Define a simple numeric score format that ranges from 0 to 1, with corresponding labels like "Low", "Medium", and "High". For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   This change will make the system more transparent and trustworthy, allowing wearers to better judge the reliability of displayed information. It will also provide a clear signal for when the system is less confident, prompting users to seek additional context or clarification.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a strict local cache threshold for face/name memory on the phone, we ensure that only relevant and frequently accessed information is stored locally, reducing the risk of privacy concerns while maintaining useful memory support. This helps in balancing the need for rich contextual memory with the constraint of limited on-device storage.

2. **What small change unlocks it**

   Define a local cache threshold where face/name memories older than 30 days are automatically removed from the phone's cache, unless explicitly reinforced by frequent interactions or explicit user touches.

3. **Likely payoff**

   This change will help in maintaining a balance between rich memory support and privacy concerns. By limiting cached data to recent encounters, we reduce storage needs while ensuring that relevant memories are still available when needed. This approach also prevents the system from becoming too complex for users to manage, thus maintaining low social friction.

4. **Immediate next probe**

   Define one local-cache size limit of 50 face/name entries with a retention period of 30 days before automatic removal, unless reinforced by frequent interactions or explicit user touches.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Sticking to a phone-first architecture for live subtitle processing ensures that critical real-time functionalities are not bottlenecked by battery or thermal constraints on the glasses themselves. This allows the system to provide clear, stable subtitles without compromising on performance or user trust.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary as "transcript cleanup". For live subtitle processing, keep all real-time data and logic local on the phone, only sending transcribed text for post-processing tasks like cleaning up transcript errors to the cloud when needed.

3. **Likely payoff**

   By focusing live subtitles strictly on phone-first processing, we can ensure that subtitles remain reliable in noisy environments, maintaining high trust with the user. This also allows for faster and more consistent subtitle delivery, which is critical for real-time understanding.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain low-friction assistance while preventing overload. This balance is crucial for enhancing the wearer's understanding without causing distraction, thus supporting the core mission of providing helpful, unobtrusive real-time aid.

2. **What small change unlocks it**

   Define two priority rules: one where subtitles have higher precedence during quieter moments and lower precedence during louder or more dynamic interactions, and another where a single-line prompt is shown only when necessary and not overlapping with subtitles to avoid redundancy.

3. **Likely payoff**

   This refined visual hierarchy will enhance the overall user experience by making critical information more prominent while reducing clutter, thereby maintaining trust and utility without overwhelming the wearer.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
