# Consolidation of Core Signals for SmartGlasses V1

## Strengthening Signals
- **Subtitle Clarity**: Subtitle clarity remains the top priority, ensuring subtitles are clear, fast, and stable enough to maintain wearer trust in live conversations.
- **Memory Trust**: The system must continue to support reliable face and name recall while maintaining transparency about the level of certainty.

## Weakening Signals
- **Low-Friction Assistance**: While it is important, its importance is somewhat lower compared to subtitle clarity and memory trust. Efforts should focus more on ensuring the core functionality before expanding this area.
  
## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: The system must balance providing useful assistance with maintaining privacy and avoiding overreach.

## Dormant Ideas Worth Reactivating
- **Face/Name Memory Reinforcement**: This is a key area that should be re-examined to ensure names and faces are remembered accurately and quickly.
  
## Concrete Tensions Around Core Areas

### Subtitle Quality, Confidence Trust, Automatic New-Person Memory, Memory Reinforcement, Fast Lookup, Privacy, Latency, Battery, Visual UX
- **Subtitle Quality**: Ensuring subtitles remain clear and readable is crucial. Any trade-offs in speed or complexity must maintain readability.
- **Confidence Trust**: Displaying confidence levels in a way that builds trust without overloading the wearer with too much information.
- **Automatic New-Person Memory**: The system should automatically remember new faces and names but do so transparently and accurately.
- **Memory Reinforcement**: Regularly reinforcing memory of important people or contexts to ensure quick recall when needed.
- **Fast Lookup Requirements**: Balancing the need for fast, reliable lookups with real-time processing constraints.
- **Privacy**: Ensuring that user data is handled in a way that protects privacy while providing useful assistance.
- **Latency**: Minimizing latency without sacrificing the quality of subtitles or memory support.
- **Battery**: Managing power consumption to ensure the system remains usable over extended periods without draining the battery too quickly.
- **Visual UX**: Maintaining a clean, unobtrusive visual interface that does not distract from the wearer’s experience.

### Specific Tensions
- **Privacy vs Usefulness**: The system must provide useful assistance while respecting user privacy.
- **Latency vs Richness**: The system should aim for timely responses without sacrificing the richness of memory and confidence displays.
- **Discreet UX vs Visual Clarity**: Balancing the need for a discreet interface with the requirement to remain visually clear.

## Open Questions
- **Subtitle Placement**: How can subtitles be placed to maximize readability while minimizing distraction?
- **Confidence Display**: What is the best way to display confidence levels: label only, label + short reason, or score + label?
- **Memory/Cache Policy**: How much face/name memory should be cached locally on the phone versus relying on cloud storage?
- **Phone/Cloud Boundary**: Where and when should processing occur on the phone versus the cloud?

## Core Deepening vs Sprawl
- The project should focus on deepening core features such as subtitle quality, memory trust, confidence display, and visual UX rather than broad feature expansion.

## Real-World Constraints
- Surface battery, latency, privacy, and usability limits early to avoid wasted effort on impossible directions.
- Ensure the system remains socially acceptable and does not create excessive friction or distraction for the wearer.

## Concrete Tensions

### Subtitle Quality
- **Strengthen**: Focus on real-time clarity and stability.
- **Weaken**: Consider reducing text density if it impacts readability.

### Memory Trust
- **Strengthen**: Enhance automatic memory behavior while maintaining explicit remember-touch behaviors to build trust.
- **Weaken**: Simplify confidence displays to avoid overwhelming the wearer.

### Automatic New-Person Memory
- **Strengthen**: Implement and refine mechanisms for remembering new faces and names transparently.
- **Weaken**: Avoid overloading the system with too many new-person entries at once, ensuring a manageable load.

### Memory Reinforcement
- **Strengthen**: Regularly reinforce memory of important people or contexts to ensure quick recall.
- **Weaken**: Limit the frequency of reinforcement prompts to avoid annoying the wearer.

### Fast Lookup Requirements
- **Strengthen**: Ensure fast and reliable lookups for names, faces, and prior context.
- **Weaken**: Avoid introducing delays that could impact user trust.

### Privacy
- **Strengthen**: Maintain strong privacy protections while still providing useful assistance.
- **Weaken**: Avoid collecting unnecessary data or exposing too much information to the system.

### Latency
- **Strengthen**: Minimize latency in both subtitle delivery and memory lookups.
- **Weaken**: Consider reducing the complexity of certain features if it causes noticeable delays.

### Battery
- **Strengthen**: Optimize power consumption for extended use.
- **Weaken**: Allow some trade-offs in feature richness to ensure battery remains manageable.

### Visual UX
- **Strengthen**: Design a clean, unobtrusive interface that enhances the wearer’s experience without becoming distracting.
- **Weaken**: Avoid adding unnecessary visual elements that could cause clutter or distraction.
