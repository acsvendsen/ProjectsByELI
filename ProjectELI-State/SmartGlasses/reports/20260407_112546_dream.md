### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain readable, stable, and trustworthy in live conversations. This enhances the wearer's ability to follow the conversation without distraction or confusion, thereby strengthening the core attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define 3 specific subtitle placement rules for different confidence states: low (60%), medium (80%), and high (95%) confidence levels. For each rule, specify a fixed position on the screen to ensure subtitles are always in a clear, unobtrusive area.

3. **Likely payoff**

   By defining these rules, we can ensure that subtitles remain stable and not overly distracting, which will enhance user trust and satisfaction. This also aligns with the core attractor of real-time subtitle clarity and ensures that the subtitles do not become a source of distraction in conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache policy ensures that the system can efficiently recall names and faces with high confidence over time. This is crucial for maintaining trust in the wearer's memory support, which is a key attractor of the project.

2. **What small change unlocks it**

   Define a local cache eviction rule that retains recent encounters but removes older ones to balance memory usage and lookup speed. For example, keep memories of people seen within the last week but remove those not seen for over a month.

3. **Likely payoff**

   By setting a clear cache eviction policy, the system can maintain a robust memory database while keeping memory size manageable. This ensures fast recall during conversations without overwhelming the local storage or slowing down lookups.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we can ensure that V1 focuses on delivering the most critical and usable features with minimal complexity. This will help maintain battery efficiency and privacy while ensuring that subtitle processing remains real-time and reliable.

2. **What small change unlocks it**

   Define explicit rules for when live subtitle processing should fallback to the cloud versus being handled locally by the phone. For example, create a policy where face/name recall lookup falls back to the cloud only if there is no recent match in local memory.

3. **Likely payoff**

   By clearly defining which tasks run on the phone and which fall back to the cloud, we can ensure that V1 has the lowest friction interaction while maintaining critical functionality. This will help in preserving battery life and ensuring that the core subtitle processing remains real-time, thus enhancing the wearer's trust and usability.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
