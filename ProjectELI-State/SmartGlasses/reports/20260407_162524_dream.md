### Idea 1: Subtitle Placement

1. **Why it benefits the core**

Improving subtitle placement rules under different confidence states helps ensure that subtitles remain clear, stable, and readable in live conversation. This enhances real-time subtitle clarity (attractor: `subtitle_clarity`), making them a reliable tool for understanding during interactions.

2. **What small change unlocks it**

Define three subtitle placement rules:
- Fixed position at the bottom of the frame.
- Adjusted position slightly above the fixed to avoid overlapping other UI elements.
- Dynamic adjustment based on current confidence level, moving subtitles higher when confidence is low and lower when confidence is high.

3. **Likely payoff**

Implementing these rules will result in more consistent and readable subtitle placement, reducing distractions and maintaining trust in the assistive nature of the system. This improvement directly supports real-time subtitle clarity and enhances the wearer's ability to follow conversations effectively.

4. **Immediate next probe**
   - Define the fixed position rule for subtitle placement at the bottom of the frame.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer can trust the system's assistance by clearly conveying certainty levels. A well-defined confidence label and short reason will reduce uncertainty, enhance user trust, and align with the project's mission of discreetly assisting without deception.

2. **What small change unlocks it**

   Define a new confidence object format using a numeric score, label, and a short reason that succinctly explains why the system is certain about the displayed information. For example, "score 0.85 + 'High' + 'Seen recently'".

3. **Likely payoff**

   By clearly communicating certainty levels through concise labels and reasons, users will feel more confident in the system's accuracy, leading to better overall trust and adoption. This improvement directly supports the core attractor of memory support (memory_trust) by ensuring that any assistance provided is credible.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   
   Improving the local cache size for face/name memory ensures that frequently encountered names and faces are readily available in a low-latency manner, enhancing subtitle clarity and trustworthiness by providing quick and accurate recognition during live conversations.

2. **What small change unlocks it**

   Define a local cache threshold for storing recently seen people and their associated confidence objects on the phone. This threshold should be set to keep frequently encountered names and faces in memory while maintaining low memory usage.

3. **Likely payoff**

   By setting an optimal local cache size, we can significantly reduce the latency of name recall during live conversations. This improves the overall trustworthiness of the system, as people are recognized quickly without needing cloud access or additional queries. The payoff is a more seamless and reliable experience for the wearer.

4. **Immediate next probe**
   - Set the local cache size threshold for storing frequently encountered faces and names on the phone to balance memory usage with quick recall speed.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for live subtitle processing, we can ensure that subtitles remain fast and reliable in real-time interactions. This balance enhances trust by keeping critical functions local while still leveraging the phone's computational power for necessary tasks.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing remains phone-local. For instance, keep basic subtitle rendering, confidence formatting, and initial placement rules on the glasses. Only pass fully processed subtitles to the cloud for any additional refinement or fallback logic.

3. **Likely payoff**

   By keeping subtitle processing local, we reduce latency, ensure faster response times, and maintain trust through consistent, reliable performance. This local-first approach will enhance the wearer's experience by providing clear, readable subtitles in real-time without the risk of dropped frames or delays due to cloud processing.

4. **Immediate next probe**

   Define one task-specific phone-local vs cloud fallback boundary for live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy rule between subtitles and one-line support, we ensure that the most critical information (subtitles) remains easily readable while minimizing distractions from less important but useful prompts (one-line support). This rule strengthens the core attractor of real-time subtitle clarity by ensuring that subtitles remain the primary focus during live conversations.

2. **What small change unlocks it**

   Define a visual hierarchy rule where subtitles are always displayed prominently and clearly, taking precedence over one-line support in terms of visibility and placement on the display. This can be achieved by setting a priority order for text elements, ensuring that subtitles are positioned at the top or center of the frame, with one-line prompts appearing below them.

3. **Likely payoff**

   By enforcing this rule, we reduce visual clutter during live conversations, making it easier for the wearer to focus on understanding spoken words while still benefiting from contextual support provided by one-line prompts. This improves overall user experience and aligns better with the core attractor of low-friction assistance.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
