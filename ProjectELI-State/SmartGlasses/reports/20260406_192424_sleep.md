# Consolidation of Key Signals for SmartGlasses V1

## Strengthening Signals
- **Subtitle Clarity**: Subtitles must remain clear, fast, and stable to ensure trust in live conversations.
- **Memory Trust**: Names, faces, and prior context should be remembered accurately without creating false certainty.
- **Low-Friction Assistance**: Provide one-line help through subtitles or prompts without adding unnecessary complexity.

## Weakening Signals
- **Discreet UX vs Visual Clarity**: The system must balance social acceptability with the need for clear display behavior. Discreetness should not compromise readability in noisy environments.
- **Always-On Sensing vs Battery and Thermals**: The glasses should minimize always-on sensing to preserve battery life, avoiding unnecessary thermal strain.

## Contradictions that Must Stay Alive
- **Privacy vs Usefulness**: Balancing the need for useful assistive behavior without infringing on privacy. This contradiction must be managed carefully.
- **Latency vs Richness**: Ensuring timely responses while maintaining a balance between rich context and low-latency real-time processing.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement**: Evaluate different subtitle placements to find the optimal balance between readability and non-distracting behavior.
- **Confidence Display**: Revisit confidence display options, such as numeric scores or labels with short reasons, to ensure users trust the system.

## Concrete Tensions Around Specific Areas
### Subtitle Quality, Confidence Trust, Automatic New-Person Memory, Memory Reinforcement, Fast Lookup, Privacy, Latency, Battery, and Visual UX
- **Subtitle Quality**: Ensure subtitles are clear and stable.
- **Confidence Trust**: Display confidence in a way that builds user trust without overconfidence.
- **Automatic New-Person Memory**: Enhance automatic memory for new faces and names with reinforcement over time.
- **Memory Reinforcement**: Improve the system's ability to remember and recall prior contexts effectively.
- **Fast Lookup**: Prioritize fast, accurate lookup of stored information without compromising battery life or privacy.
- **Privacy**: Ensure that memory storage and retrieval do not infringe on user privacy.
- **Latency**: Maintain real-time processing with minimal delay.
- **Battery**: Reduce always-on sensing to preserve battery life.
- **Visual UX**: Balance discreetness with the need for clear, readable subtitles.

## Core Field
The project should focus on enhancing subtitle clarity, memory trust, and low-friction assistance while maintaining a balance between privacy and usefulness. V1 interaction should remain frame-touch only, and heavy processing should be offloaded to the phone or cloud as needed.

### Core Tensions
- **Privacy vs Usefulness**: Ensure that the system provides useful information without compromising user privacy.
- **Latency vs Richness**: Balance real-time performance with rich context for better understanding.
- **Discreet UX vs Visual Clarity**: Maintain social acceptability while ensuring subtitles are clear and readable.

### Core Attractors
- Real-time subtitle clarity: Keep subtitles clear, fast, and stable enough that the wearer can trust them in live conversation.
- Trustworthy memory support: Remember names, faces, and prior context without pretending certainty or creating corrupted recall.
- Low-friction assistance: Deliver one-line help and visible support without creating command overhead or social awkwardness.

### Core Constraints
- **Frame-Touch-Only V1**: Interaction should remain frame-touch only to keep the system simple and user-friendly.
- **Phone-First Runtime**: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.
- **Core Deepening Over Sprawl**: Focus improvements that deepen subtitle quality, memory trust, confidence display, and visual UX rather than broad feature expansion.

### Core Modes
- **Current Mode: Core Deepening**: Bias toward subtitle, memory, confidence, and architecture improvements that increase daily-use value.

### Reality Check
Early surface real-world limitations such as battery, latency, privacy, and usability constraints to ensure the project does not optimize impossible or low-value directions.
