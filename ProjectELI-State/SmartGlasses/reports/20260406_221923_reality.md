## Reality Check Assessment

### Subtitle Placement: Feasible Now
- **Subtitle placement** should remain within the field of vision but not become too distracting. For V1, a simple center display with minimal visual clutter is feasible now given the constraints on battery draw and thermal pressure.

### Confidence Display: Feasible Later
- Given current constraints, using a simple label-only confidence indicator might be more feasible later once the core subtitle functionality is well established. A label + short reason could introduce complexity early that isn't yet justified by user testing or real-world use cases.
  
### Memory/Cache Policy: Likely Waste of Time
- The initial focus should remain on getting subtitle clarity and memory support functioning reliably. Adding significant local cache policy before better understanding the core loop behavior is likely premature.

### Phone/Cloud Boundary: Feasible Now
- Given the current architecture direction, focusing on keeping the phone as the primary runtime for heavy processing aligns well with early V1 constraints. This should be feasible now to ensure a stable foundation.

### Visual Hierarchy: Feasible Later
- Defining an initial visual hierarchy is feasible later once the core subtitle and confidence display behaviors are more fleshed out. For now, a minimal design that doesn't overwhelm the wearer is sufficient.

## Reality Rules Compliance

- **Subtitles**: The current implementation should prioritize clear, readable, and stable subtitles in live conversation.
- **Memory Support**: Face/name recall must expose uncertainty clearly to maintain user trust.
- **Low-Friction UX**: Initial interactions through frame touches are preferred over voice commands for V1.

### Core Deepening Over Sprawl
- Current focus on subtitle quality, memory trust, and visual UX is appropriate. Broad feature expansion should be avoided unless it directly enhances the core mission.

## Constraints Early Surfacing

- **Battery and Thermals**: Given current constraints, keeping glasses hardware simple in V1 remains a priority.
- **Always-On Sensing**: Avoid always-on sensing features until battery and thermal limitations are better understood or mitigated.
- **Latency vs Richness**: The system should provide timely help without overloading the runtime with richer but slower processing. Initial focus on real-time subtitles is feasible now.

### Interaction Constraints

- **Frame Touches Only**: V1 interaction through frame touches only aligns well with current constraints and user experience goals. Voice commands are not part of V1, so any design should respect this constraint.

## Next Steps

- Continue focusing on subtitle clarity and memory support in the initial V1.
- Develop a minimal visual hierarchy for future iterations once core behaviors are established.
- Use the `TranscriptLab` app to test real-time transcript behavior before expanding into more complex interactions or features.
