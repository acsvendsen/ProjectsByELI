## Reality Check for SmartGlasses V1 Direction

### Subtitle Placement: feasible now
- **Constraints**: The glasses should remain lightweight and socially acceptable.
- **Current Implementation**: Current testing is focused on clear, stable subtitles that can be read in motion without becoming distracting. 
- **Feasibility Analysis**: The current TranscriptLab test app already validates subtitle placement. It’s straightforward to implement different placements (e.g., top-center vs side) and observe user feedback via the phone-first interaction mode.

### Confidence Display: feasible now
- **Constraints**: Confidence display should be clear, but not overly complex.
- **Current Implementation**: The current design includes a simple confidence label with minimal additional text. This is aligned with the goal of keeping interactions low-friction.
- **Feasibility Analysis**: Implementing and testing different confidence formats (label only vs label + short reason) in TranscriptLab will provide clear insights into what works best without complex UI changes.

### Memory/Cache Policy: feasible now
- **Constraints**: Face/name memory should be stored with clear uncertainty indications, and caching on the phone must balance between utility and privacy.
- **Current Implementation**: The current implementation uses simple caching strategies that respect user trust by showing appropriate uncertainty. 
- **Feasibility Analysis**: Test different caching policies in TranscriptLab to determine how much local storage is needed without overwhelming the wearer.

### Phone/Cloud Boundary: feasible now
- **Constraints**: V1 should rely heavily on phone processing, with cloud optional.
- **Current Implementation**: The current architecture relies primarily on the phone for speech and context handling. 
- **Feasibility Analysis**: TranscriptLab already tests this boundary by keeping most of the heavy lifting on the phone.

### Visual Hierarchy: feasible now
- **Constraints**: Display behavior should favor clarity over feature density.
- **Current Implementation**: The current design in TranscriptLab keeps the UI minimal, focusing on clear and readable subtitles.
- **Feasibility Analysis**: Conduct usability tests with different visual hierarchies to determine what best supports subtitle reading without distraction.

### Summary

- **Subtitle Placement** and **Confidence Display** are feasible now based on current implementation and testing through TranscriptLab. 
- **Memory/Cache Policy** is also feasible now, as we can test caching strategies within the existing framework.
- **Phone/Cloud Boundary** is well-aligned with current constraints and can be tested effectively in the phone-first setup.
- **Visual Hierarchy** is a practical next step to ensure that subtitle readability remains primary.

### Next Steps
1. Implement and test different subtitle placements, confidence formats, memory policies, and visual hierarchies in TranscriptLab.
2. Use the feedback from these tests to refine the design and ensure it aligns with user needs and constraints.
3. Continue to surface real-world limitations through ongoing testing and validation.

By focusing on these core areas now, we can ensure that early implementation is grounded in actual use cases and technical realities.
