### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain a consistent visual flow, reducing cognitive load for the wearer and enhancing their trust in the system. A well-placed subtitle streamlines understanding during live conversations, making real-time subtitles more useful and less distracting.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence states (e.g., when the speaker is clearly audible or there's a high certainty of text accuracy) and another for lower-confidence states (e.g., when ambient noise might interfere with clarity).

3. **Likely payoff**

   By providing stable, predictable subtitle placement based on confidence levels, the system can enhance the wearer’s trust in the subtitles, making them more reliable during critical moments like introductions or important details.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring clear, stable, and accurate confidence display helps build trust in the system's reliability. By making confidence objects more explicit, we can guide users to recognize when the system is certain about a name or face, which enhances the overall user experience.

2. **What small change unlocks it**

   Introduce a simple numeric score plus label format for confidence objects, such as "score 0.84 + 'High' + 'Seen recently';" this provides both quantitative and qualitative feedback to the wearer.

3. **Likely payoff**

   This approach helps users quickly understand the system's certainty level without overwhelming them with too much information. It also reinforces trust by clearly showing when the system is less certain, preventing misinterpretation of names or faces during critical conversations.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that face/name memory is cached locally with a carefully defined threshold can significantly improve the wearer's trust in the system by making name recall faster and more reliable, even when internet connectivity is poor or absent.

2. **What small change unlocks it**

   Define a local cache size limit for face and name memories based on recent encounters. For example, only store up to 10 names with high confidence levels (confidence score > 0.8) in the local cache.

3. **Likely payoff**

   By limiting the local cache to a manageable size, the system can provide faster and more accurate name recall, reducing lag during conversations and improving the overall trust in the memory support feature without overwhelming the phone's storage or processing capabilities.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs on the phone versus the cloud, we ensure that the system remains lightweight and battery-efficient while still providing essential real-time support. This helps maintain trust and social acceptability by minimizing latency and processing overhead.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing to run entirely on the phone, with no fallback to the cloud unless absolutely necessary for critical features like confidence updates or memory lookup.

3. **Likely payoff**

   By keeping live subtitle processing local, we ensure that subtitles remain highly responsive and low-latency, enhancing trust and usability in noisy environments where real-time accuracy is crucial. This also reduces battery drain on the glasses hardware.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
