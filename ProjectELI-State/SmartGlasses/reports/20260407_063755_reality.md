# Reality Check for SmartGlasses

## Subtitle Clarity (subtitle_clarity)
- **Feasible Now:** 
  - The `TranscriptLab` test app is already providing real-time transcript behavior, which can be further refined to ensure clarity and stability. This aligns with the core-deepening mode, focusing on improving subtitle quality.
  
## Memory Trust (memory_trust)
- **Feasible Later:**
  - Implementing a system for face/name memory and reinforcement is feasible but requires more groundwork. The current focus should be on getting the subtitle functionality robust before adding complex memory systems.

## Low-Friction Assistance (low_friction_assistance)
- **Feasible Now:**
  - One-line prompts can be implemented through simple text overlays that do not require additional command overhead or social awkwardness. This aligns with the frame-touch-only V1 interaction constraint.
  
## Constraint Pressure
- **Feasible Now:**
  - Early testing in `TranscriptLab` can help surface real-world limitations such as battery drain, latency, and thermal pressure. These constraints should be surfaced early to inform design decisions.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Feasible Now:**
  - The subtitle placement in `TranscriptLab` can already provide a starting point for determining the best visual hierarchy and placement. This needs refinement but is feasible with current constraints.
  
## Privacy vs Usefulness (privacy_vs_usefulness)
- **Assumptions Needing Evidence:**
  - The system should avoid creating corrupted recall or pretending certainty, which are critical concerns. Further evidence through testing and user feedback is needed to ensure privacy and usefulness balance.

## Latency vs Richness (latency_vs_richness)
- **Feasible Now:**
  - Early prototypes in `TranscriptLab` can help test real-time response times. Optimizing for near-real-time behavior should be a priority to maintain trust.
  
## Core Deepening Over Sprawl (core_deepening_over_sprawl)
- **Feasible Now:**
  - Focus on improving subtitle quality, memory trust, and visual UX through the `TranscriptLab` test bed is feasible. Broad feature expansion that does not align with these core attractors should be avoided.

## Interaction Constraints
- **Feasible Now:**
  - Frame-touch interaction in V1 is a hard constraint and can be tested effectively using the `TranscriptLab` app, which supports this interaction pattern without voice commands.
  
## Phone/Cloud Boundary (phone/cloud boundary)
- **Feasible Now:**
  - The current focus on phone-first processing aligns with the project's constraints. Early testing in the `TranscriptLab` app can help validate the phone-side implementation before considering cloud integration.

### Summary
- Focus on improving subtitle clarity, memory trust, and low-friction assistance while surfacing early real-world limitations.
- Use the `TranscriptLab` test app to drive concrete decisions and validate core features without adding unnecessary complexity.
- Continuously surface constraints like battery, latency, and privacy to ensure sustainable design choices.
