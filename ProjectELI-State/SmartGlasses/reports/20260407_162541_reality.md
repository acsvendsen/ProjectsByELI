# Reality Check

## Subtitle Clarity - Real-time subtitle clarity (strength: high)
- **Feasible now**: The `TranscriptLab` test app indicates that real-time subtitles are possible with the current hardware and software setup. Ensuring that subtitles remain clear, fast, and stable enough for live conversation is within reach given the current implementation.
- **No assumptions needing evidence**: The existing transcript behavior in `TranscriptLab` should be sufficient to validate subtitle clarity.

## Memory Trust - Trustworthy memory support (strength: high)
- **Feasible now**: The system can remember names, faces, and prior context using confidence objects and reinforcement over time. Given the current state of face/name recall, it is feasible to implement a mechanism that surfaces uncertainty clearly.
- **No assumptions needing evidence**: The existing `TranscriptLab` setup allows for testing memory support without assuming cloud dependency or complex AR visuals.

## Low-friction Assistance - Low-friction assistance (strength: medium)
- **Feasible now**: Delivering one-line help through frame touches is achievable with the current interaction constraints. The `TranscriptLab` app can serve as a proof of concept for low-friction assistance.
- **No assumptions needing evidence**: Frame-touch interactions should be prioritized in V1 to keep user experience simple and discrete.

## Privacy vs Usefulness - Privacy vs usefulness (pressure: high)
- **Feasible now**: The system can provide helpful assistive behavior without quietly sliding into invasive capture or retention. Given the current architecture, which primarily relies on phone processing and cloud optional support where justified, this balance is feasible.
- **No assumptions needing evidence**: The existing design constraints in `v1_architecture_direction` should be sufficient to ensure privacy concerns are managed effectively.

## Latency vs Richness - Latency vs richness (pressure: high)
- **Feasible now**: The system can provide timely help without overloading the runtime with richer but slower processing. Real-time subtitles and confidence display should remain fast enough for live conversation.
- **No assumptions needing evidence**: The `TranscriptLab` app tests both real-time subtitle behavior and confidence display, ensuring that these features are fast and responsive.

## Discreet UX vs Visual Clarity - Discreet UX vs visual clarity (pressure: medium)
- **Feasible now**: Display behavior can remain socially acceptable while still being readable in motion and noise. The `TranscriptLab` app provides a basis for testing subtitle placement and visual hierarchy.
- **No assumptions needing evidence**: Initial tests in `TranscriptLab` should be sufficient to determine the best subtitle placement and visual hierarchy.

## Frame-touch-only V1 - Hard constraint
- **Feasible now**: Frame touches are the explicit interaction pattern for V1. This constraint is already respected in the current implementation.
- **No assumptions needing evidence**: The existing `TranscriptLab` setup enforces frame-touch interactions, ensuring that this constraint remains feasible.

## Phone-first runtime - Hard constraint
- **Feasible now**: Heavy processing should primarily happen on the phone with cloud optional support. This is already implemented in `TranscriptLab`.
- **No assumptions needing evidence**: The current implementation ensures that heavy processing is handled by the phone, reducing battery and thermal pressure.

## Core Deepening over Sprawl - Guiding constraint
- **Feasible now**: Work should focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion. This direction aligns with the `core_deepening` mode.
- **No assumptions needing evidence**: The existing `TranscriptLab` app provides a clear path to core improvement.

## V1 Real World Limits - Hard constraints
- **Feasible now**: Glasses should remain lightweight and socially acceptable, avoiding heavy on-glasses compute. This is already respected in the current implementation.
- **No assumptions needing evidence**: The `TranscriptLab` setup ensures that glasses hardware remains simple and lightweight.

## V1 Interaction Constraints - Hard constraint

- **No assumptions needing evidence**: Frame-touch interactions are already tested in `TranscriptLab`.
