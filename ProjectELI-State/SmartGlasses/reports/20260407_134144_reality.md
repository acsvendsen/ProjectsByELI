# Reality Check for SmartGlasses Project

## Subtitle Clarity (Subtitle Placement)

- **Subtitles should be clear, fast, and stable in live conversations.**
  - **Feasible Now**: The current implementation of `TranscriptLab` on the phone shows good initial progress with real-time subtitles. However, further optimization is needed to ensure stability and readability, especially in noisy environments.
  - **Assumptions Needing Evidence**: Ensure that the subtitle placement does not become distracting over time. Consider conducting user testing to find a balance between visibility and non-intrusiveness.

## Memory Trust (Face/Name Recall)

- **Memory support should remember names, faces, and prior context without pretending certainty or creating corrupted recall.**
  - **Feasible Now**: The current implementation uses confidence objects and reinforcement learning for face/name memory. This is a good start but requires further refinement.
  - **Assumptions Needing Evidence**: Determine the optimal level of confidence to display. Testing with real users will help determine how they perceive the accuracy of remembered information.

## Low-Friction Assistance

- **One-line support should be delivered without creating command overhead or social awkwardness.**
  - **Feasible Now**: The current V1 interaction through frame touches is a good starting point. One-line prompts can be integrated seamlessly.
  - **Assumptions Needing Evidence**: Ensure that the one-line prompts are concise and helpful without overwhelming the user.

## Core Deepening Over Sprawl

- **Focus on improving subtitle quality, memory trust, and visual UX over broad feature expansion.**
  - **Feasible Now**: The current mode of operation is focused on core deepening, which is appropriate given the constraints.
  - **Assumptions Needing Evidence**: Continue to refine these core areas based on user feedback.

## Battery Constraints

- **Battery and thermals are major risks for always-on features.**
  - **Feasible Now**: The current implementation uses phone-first processing, which helps manage battery consumption. However, further optimization of the speech transcriber could reduce power draw.
  - **Assumptions Needing Evidence**: Monitor battery usage in different scenarios and adjust algorithms to minimize impact.

## Latency Constraints

- **Latency vs richness: The system should provide timely help without overloading the runtime with richer but slower processing.**
  - **Feasible Now**: The current implementation shows that real-time subtitles are feasible, though there is room for improvement.
  - **Assumptions Needing Evidence**: Test different levels of latency and ensure that it does not affect user trust.

## Privacy Constraints

- **Privacy vs usefulness: Helpful assistive behavior should not quietly slide into invasive capture or retention.**
  - **Feasible Now**: The current implementation handles privacy by relying on the phone for processing. However, ongoing testing is needed to ensure that the system does not collect more data than necessary.
  - **Assumptions Needing Evidence**: Develop and test a privacy policy that clearly communicates what data is collected and how it is used.

## Discreet UX

- **Display behavior should remain socially acceptable while still being readable in motion and noise.**
  - **Feasible Now**: The current implementation of `TranscriptLab` shows good progress with discreet UI elements.
  - **Assumptions Needing Evidence**: Conduct user testing to ensure that the UI is both functional and unobtrusive.

## Interaction Constraints

- **V1 should not depend on voice activation or spoken user commands for controlling the glasses.**
  - **Feasible Now**: The current implementation relies on frame touches, which aligns with V1 constraints.
  - **Assumptions Needing Evidence**: Continue to refine the interaction model based on feedback.

## Phone/Cloud Boundary

- **Phone-first runtime: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.**
  - **Feasible Now**: The current implementation is aligned with this constraint.
  - **Assumptions Needing Evidence**: Ensure that any cloud usage adds clear value and does not compromise battery or latency.

## Visual Hierarchy

- **Subtitle placement and visual hierarchy should support fast reading with low distraction.**
  - **Feasible Now**: The current implementation of `TranscriptLab` provides a good starting point for visual hierarchy.
  - **Assumptions Needing Evidence**: Test different subtitle placements to find the best balance between readability and non-intrusiveness.
