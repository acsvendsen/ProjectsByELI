### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules that prioritize readability over distraction, we can ensure the subtitles remain clear and stable enough for the wearer to trust them in live conversations. This focus on usability directly supports the "Real-time subtitle clarity" attractor.

2. **What small change unlocks it**

   Define a set of fixed subtitle placement rules based on confidence levels: 
   - Place subtitles at the bottom center for high-confidence matches.
   - Place subtitles near the top right corner for medium-confidence matches.
   - Hide subtitles or place them in a less intrusive location (e.g., edge) for low-confidence matches.

3. **Likely payoff**

   This small change will likely result in more reliable and trusted subtitles during live conversations, reducing cognitive load and enhancing overall user experience. It aligns with the core goal of delivering clear, stable, and useful real-time subtitles.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a score label combination with a short reason, the system can provide more nuanced and trustworthy information to the wearer without overwhelming them. This approach ensures that the confidence levels are clear and actionable, which is crucial for the wearer's trust in the assistant's responses.

2. **What small change unlocks it**

   Introduce a simple confidence format that combines a numeric score with a label and a short reason. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'. This format provides a clear, concise, and actionable way to convey the reliability of the information.

3. **Likely payoff**

   The refined confidence display will enhance the wearer's trust in the assistant by providing more transparent and understandable feedback on the reliability of each piece of information. This increased trust can lead to better overall user satisfaction and more reliable interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new faces and names are automatically remembered with confidence objects and reinforced over time strengthens the core attractors related to memory trust and low-friction assistance. By default, likely new people should be remembered without explicit user intervention, which aligns with the project's goal of providing reliable personal support.

2. **What small change unlocks it**

   Define a simple entity-linking rule that attaches new evidence to an existing person-memory object by default. This can be achieved by setting up a local cache threshold where any new face or name encounter is automatically linked to an existing memory if the confidence score exceeds a certain threshold (e.g., 0.6).

3. **Likely payoff**

   Implementing this rule will reduce the friction of manual memory capture, ensuring that the glasses remain low-impact while still providing robust support for names and faces. This pays off by reinforcing the core attractors related to trust in memory support and low-friction assistance.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   - By defining a clear boundary for what runs phone-local versus what falls back to cloud, we ensure that the system maintains low latency and high privacy while still providing useful functionality.

2. **What small change unlocks it**
   - Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing. This means explicitly deciding which critical real-time tasks should be handled locally on the phone rather than sent to the cloud, ensuring that subtitles are displayed with minimal delay and privacy is maintained.

3. **Likely payoff**
   - By optimizing real-time subtitle processing to run entirely on the phone, we can ensure high-quality, low-latency subtitle delivery that remains stable and trust-preserving during live conversations. This will directly support the primary attractor of real-time subtitle clarity while also respecting battery and privacy constraints.

4. **Immediate next probe**
   - Define the cloud fallback boundary for live subtitle processing to run entirely on the phone, ensuring minimal latency and high privacy.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear precedence rule between subtitles and one-line support, we ensure that the most critical information is always prominently displayed while minimizing visual clutter. This will enhance the wearer's ability to follow the conversation without being overwhelmed by additional prompts.

2. **What small change unlocks it**

   Introduce a single decision statement in V1 that prioritizes subtitle display over one-line support when both are present, ensuring subtitles remain readable and clear.

3. **Likely payoff**

   This simple precedence rule will significantly improve the wearer's ability to focus on the core conversation by reducing visual distractions. It will also enhance the trustworthiness of subtitles, as they will always take priority in the display hierarchy.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
