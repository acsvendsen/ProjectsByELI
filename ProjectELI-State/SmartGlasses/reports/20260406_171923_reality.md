# Reality Check for SmartGlasses V1 Direction

## Subtitle Clarity
- **Feasible Now**: The project is currently focused on real-time subtitle clarity, which is a critical feature for the core mission. Given that the `TranscriptLab` app has been set up to test live transcript behavior and stability, it's feasible to work on ensuring subtitles are clear, fast, and stable in V1.
- **Assumptions Needing Evidence**: Ensure that the subtitle display technology can handle real-world conditions (e.g., noise, rapid changes) without lag or distortion. This will likely require ongoing testing with a variety of input sources.

## Memory Trust
- **Feasible Later**: The memory trust aspect is currently being prioritized as part of the core deepening process. While it's not feasible to implement complex memory storage and retrieval in V1, the project can start laying down the foundational architecture that will support this feature later.
- **Assumptions Needing Evidence**: Determine the initial implementation for face/name recall without overloading the system with unnecessary complexity. This might involve simple caching mechanisms on the phone first.

## Low-Friction Assistance
- **Feasible Now**: The one-line support aspect can be implemented in a low-friction manner using frame touches as interactions. The project should focus on creating clear, unobtrusive prompts that help the wearer without causing social awkwardness.
- **Assumptions Needing Evidence**: Define the format and content of these one-line prompts to ensure they provide helpful information while remaining unobtrusive.

## Privacy vs Usefulness
- **Feasible Later**: Balancing privacy and usefulness will be an ongoing tension. For V1, the focus should be on ensuring that any memory or recall features are transparent and do not create a privacy concern.
- **Assumptions Needing Evidence**: Define clear privacy policies and ensure that all interactions with face/name recognition are handled in a way that respects user control and consent.

## Latency vs Richness
- **Feasible Now**: The system should provide timely help, which means the latency between input and output must be minimized. This can be achieved by offloading heavy processing to the phone/cloud.
- **Assumptions Needing Evidence**: Test the performance of the `TranscriptLab` app to ensure that real-time subtitles are stable and responsive enough.

## Discreet UX vs Visual Clarity
- **Feasible Now**: The V1 should prioritize a discreet user experience. This can be achieved through careful placement of subtitles and one-line prompts.
- **Assumptions Needing Evidence**: Use the `TranscriptLab` app to test different subtitle placements and visual hierarchies to find the optimal balance between clarity and discretion.

## Frame-Touch Only V1 Interaction
- **Feasible Now**: The frame-touch interaction model is firmly established as part of V1. This constraint must be respected in all design decisions.
- **Assumptions Needing Evidence**: Ensure that all interactions are intuitive and do not require complex user gestures or commands.

## Phone-First Runtime
- **Feasible Now**: The phone-first architecture is a key principle, which means the project should leverage cloud services only when absolutely necessary. This will help manage battery and thermal constraints.
- **Assumptions Needing Evidence**: Define clear boundaries for what tasks can be handled on-device versus offloading to the phone or cloud.

## Core Deepening Over Sprawl
- **Feasible Now**: The current focus is on deepening core features like subtitle quality, memory trust, and confidence display. Broad feature expansion should be avoided.
- **Assumptions Needing Evidence**: Continue refining the design of these core components to ensure they meet user needs.

## Persistent SmartGlasses ELI Inputs
- **Feasible Now**: The ongoing inputs from the `TranscriptLab` app provide a solid foundation for testing and iterating on V1 features. These tests should be integrated into the development process.
- **Assumptions Needing Evidence**: Ensure that all tests are comprehensive enough to cover edge cases and real-world usage scenarios.

## Reality Rules
- **Feasible Now**: The reality rules are designed to guide the project based on current constraints and user needs. They ensure that the project stays focused on delivering core value while respecting technical limitations.
- **Assumptions Needing Evidence**: Continuously review these rules as the project evolves to ensure they remain relevant.

## Open Questions
- **Feasible Now**: The open questions related to subtitle placement, confidence display, memory policy, and visual hierarchy should be addressed through iterative testing with the `TranscriptLab` app.
- **Assumptions Needing Evidence**: Ensure that all experimental changes are thoroughly tested before being implemented in V1.

By focusing on these areas, the project can ensure that it remains grounded in real-world constraints while continuously improving its core functionality.
