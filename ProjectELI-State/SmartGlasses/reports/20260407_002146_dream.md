### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states ensures that subtitles are always readable and stable enough to be trusted in real-time conversations, thereby enhancing the wearer's understanding and trust in the system.

2. **What small change unlocks it**

   Define 3 to 5 fixed subtitle placement rules for different confidence levels: high-confidence (high certainty of correct name or face), medium-confidence (some doubt but still likely correct), and low-confidence (uncertain, may require confirmation).

3. **Likely payoff**

   By implementing stable and predictable subtitle placement rules, the system can ensure that subtitles are always in a clear, visible location regardless of the confidence level. This improves the overall user experience by reducing cognitive load and increasing trust in the assistive behavior.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to be more precise and understandable, we can enhance trust in both subtitles and memory support. A clear and concise confidence indicator will help the wearer judge the reliability of the information presented, ensuring they are not misled by uncertain data.

2. **What small change unlocks it**

   Define a new confidence object that uses a numeric score along with a label and short reason. For example: `score 0.84 + "High" + "Seen recently"` for well-established names or topics, vs `score 0.42 + "Low" + "Weak match"` for less certain data.

3. **Likely payoff**

   This change will make the confidence display more trustworthy and transparent. It will allow the wearer to quickly assess the reliability of subtitles and memory support, reducing uncertainty and improving overall trust in the system's outputs.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that frequently encountered names and faces are cached more reliably on the phone, reducing the need for cloud lookups and enhancing real-time response speed. This directly supports the core attractor of "Trustworthy memory support" by ensuring that key information is available quickly without disrupting the wearer's flow.

2. **What small change unlocks it**

   Define a local cache threshold where names and faces encountered more than 5 times are cached on the phone with a high confidence level, while those less frequent are looked up from the cloud or only remembered temporarily.

3. **Likely payoff**

   By caching frequently encountered entities locally, the system can provide quicker responses in real-time interactions, reducing latency and ensuring that critical information is always accessible without waiting for cloud processing. This improves overall memory trust and enhances the daily-use value of the device by making it more responsive and reliable.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what stays phone-local versus what falls back to cloud, we can optimize V1's performance and privacy while ensuring real-time subtitle clarity and memory support are handled efficiently.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that prioritizes low-latency responses over rich context analysis, ensuring the glasses remain socially acceptable without overheating or draining the battery.

3. **Likely payoff**

   This decision will help maintain high subtitle clarity and trust by keeping subtitle rendering local to the glasses, while also preserving privacy by limiting cloud interactions for less critical tasks like memory lookups and transcript cleanup.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support helps ensure that the most critical information is always easily readable and not overwhelming the wearer's attention. This ensures that the system remains low-friction and discreet, while still providing essential assistance.

2. **What small change unlocks it**

   Define a clear precedence rule where subtitles are prioritized over one-line prompts when both are present on screen simultaneously. This can be achieved by routing subtitle content to a higher layer of the display stack or ensuring that subtitles are always displayed first and fade out if the display space is limited.

3. **Likely payoff**

   By clearly prioritizing subtitles, we ensure that the wearer can focus on understanding spoken conversation without being distracted by less critical one-line prompts. This improves overall trust in the system's ability to provide real-time assistance, which is crucial for the core attractor of low-friction assistance.

4. **Immediate next probe**
   - Define the display precedence rule where subtitles have a higher priority than one-line prompts when both are present on screen simultaneously.
