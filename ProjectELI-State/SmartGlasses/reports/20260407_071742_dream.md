### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules enhances the wearer's trust in real-time subtitles, making them more reliable and understandable during live conversations. This stability is crucial for maintaining the quality of assistive behavior without adding distracting visual elements that could break concentration.

2. **What small change unlocks it**

   Define fixed subtitle placement rules based on confidence levels: high-confidence subtitles always visible at the top center, medium-confidence subtitles slightly below or to the side with a lower priority, and low-confidence subtitles shown only upon explicit user interaction.

3. **Likely payoff**

   By implementing these fixed rules, the system will provide a clearer visual hierarchy for subtitles, reducing distractions while ensuring that critical information is always visible. This improvement will enhance the wearer's confidence in the assistive behavior without overwhelming them with too much text on screen.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format in V1 will enhance trust by making the system's certainty more transparent and understandable to the wearer, without creating unnecessary complexity or distraction.

2. **What small change unlocks it**

   Define a simple numeric score + label + short reason format for confidence objects that can be directly displayed alongside subtitles and memory entries.

3. **Likely payoff**

   By clearly showing the system's certainty level with each piece of information, the wearer will trust the assistant more, knowing exactly how much to rely on different pieces of data. This clarity can lead to fewer misunderstandings and better overall understanding during interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - By defining a clear local memory threshold, we ensure that new names and faces are remembered with confidence objects, reinforcing trust in the system's ability to recall past interactions without overwhelming the wearer.

2. **What small change unlocks it**
   - Define a local memory cache size limit of 10-15 entries for likely new people and names, with periodic reinforcement checks based on recency and confidence scores.

3. **Likely payoff**
   - This approach balances the need for remembering new people and faces while avoiding clutter in the wearer's interface. It ensures that critical memories are retained and can be quickly recalled, enhancing the system’s trustworthiness and usefulness.

4. **Immediate next probe**
   - Define a local memory cache size limit of 10 entries for likely new people and names.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for phone-local versus cloud processing, we ensure that critical real-time operations like live subtitle processing remain fast and reliable. This directly supports the core attractor of real-time subtitle clarity while also respecting privacy constraints.

2. **What small change unlocks it**

   Define a single task boundary where face/name recall lookup should always be local on the phone before falling back to cloud, with clear criteria for when cloud fallback is justified.

3. **Likely payoff**

   This will reduce latency and ensure that critical memory lookups are fast and reliable, enhancing trust in the system’s ability to support names and faces in real-time interactions. It also respects privacy by minimizing data sent to the cloud.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as face/name recall lookup.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain the wearer's focus on essential information, enhancing overall understanding and reducing cognitive load. By prioritizing the most critical content visually, the system ensures that key subtitled dialogue is not overshadowed by less important prompts.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles are given higher visual prominence than one-line support cues when both appear simultaneously in the field of view. This can be achieved by using different display precedence rules or adjusting font size, color contrast, and spacing to ensure subtitles remain clearly visible.

3. **Likely payoff**

   By maintaining a clear distinction between critical subtitle information and less urgent one-line prompts, the wearer's attention remains focused on essential interactions. This reduces cognitive overload and ensures that important dialogue is not missed, thereby enhancing the overall user experience and trust in the system.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
