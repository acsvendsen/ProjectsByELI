# Reality Check

## Subtitle Clarity (feasible now)
- **Current Situation**: The `TranscriptLab` test bed is being used to validate real-time subtitle clarity.
- **Constraints**: Must remain readable, stable, and trust-preserving in live conversation.
- **Assessments**:
  - The current implementation should focus on ensuring subtitles are clear, fast, and stable enough for live use. This aligns with the `TranscriptLab`'s core mission of validating real-time transcript behavior.
  - Ensuring this within the existing constraints (e.g., minimal local logic) is a feasible task given the simplicity in V1.

## Memory Trust (feasible later)
- **Current Situation**: Face and name memory support should be reliable without overcommitting to certainty or creating false recall.
- **Constraints**: Must respect privacy vs. usefulness tension, ensure context-rich but not overwhelming memory support.
- **Assessments**:
  - The current `TranscriptLab` test bed focuses on live transcripts rather than memory support. Implementing this feature will require more complex backend processing and confidence mechanisms.
  - Given the current focus on core deepening and the need to surface constraints early, working on memory trust can be deferred until after initial subtitle clarity is solidified.

## Low-Friction Assistance (feasible now)
- **Current Situation**: One-line prompts should provide low-friction assistance without creating command overhead or social awkwardness.
- **Constraints**: Must ensure this through frame touches only in V1.
- **Assessments**:
  - The current `TranscriptLab` already includes basic transcript and confidence display, which can be adapted to include one-line prompts. This is a low-complexity addition that aligns with the V1 constraints.

## Privacy vs Usefulness (likely waste of time)
- **Current Situation**: Balancing privacy and usefulness in memory support.
- **Constraints**: Heavy on glasses hardware remains simple; battery and thermals are major risks.
- **Assessments**:
  - Given the current focus on subtitle clarity, low-friction assistance, and core deepening, spending significant effort on early privacy vs. usefulness tradeoffs might be premature.
  - Addressing this can come later once subtitle quality is established.

## Latency vs Richness (feasible now)
- **Current Situation**: Ensuring timely help without overloading the runtime with richer but slower processing.
- **Constraints**: Phone-first runtime; heavy processing on phone, cloud optional.
- **Assessments**:
  - The `TranscriptLab` setup can be used to test and balance latency vs. richness effectively by iterating on the real-time transcript behavior.
  - This is a practical approach that aligns with the current mode of core deepening.

## Discreet UX vs Visual Clarity (feasible now)
- **Current Situation**: Ensuring display remains socially acceptable while still being readable in motion and noise.
- **Constraints**: Glasses should remain lightweight; early versions not heavy on glasses compute.
- **Assessments**:
  - The current `TranscriptLab` setup can help refine subtitle placement and visual hierarchy to ensure they are both clear and discreet.
  - This is a feasible task that fits within the V1 constraints.
