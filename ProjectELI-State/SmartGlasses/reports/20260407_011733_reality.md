# Reality Check for SmartGlasses Project

## Subtitle Clarity: Feasible Now
- **Subtitle Placement**: The glasses should place subtitles where they are easily readable but not overly distracting. Given the current transcript tests in `TranscriptLab`, placing subtitles slightly above or below the wearer's line of sight (e.g., at the bottom edge) is feasible now. This placement can be optimized through iterative testing.
- **Visual Hierarchy**: Subtitles should remain clear and uncluttered to avoid distraction. Ensuring that subtitles are large enough and legible even when the glasses are moving or in noisy environments is critical. This feasibility can be tested using the `TranscriptLab` app.

## Memory Trust: Feasible Later
- **Memory Storage**: Storing face and name memories on the phone with periodic reinforcement through interactions is a feasible approach for later development. The memory objects can be initially stored as simple data structures (e.g., in Core Data) with timestamps to indicate recency.
- **Confidence Display**: Implementing a confidence display system that shows uncertainty clearly (e.g., "I'm not sure" or "Probably [name]") is feasible later once the core subtitle functionality is stable. This can be tested by incrementally adding this feature and observing user feedback.

## Low-Friction Assistance: Feasible Now
- **One-Line Prompts**: Delivering one-line prompts via the glasses (e.g., "They said your name") can be done through text display on the glasses. The `TranscriptLab` app can be used to test various prompt formats and their effectiveness.
- **Visual UX**: Ensuring that subtitles and prompts coexist without overloading the wearer is a feasible task now. This involves designing a clear visual hierarchy where subtitles are displayed clearly, and one-line prompts do not obstruct the main text.

## Privacy vs Usefulness: Feasible Now
- **Local Processing**: Keeping heavy processing on the phone and using cloud services only when clearly justified aligns with current constraints. Implementing local processing for subtitle generation is feasible now.
- **Data Handling**: Storing minimal data locally (e.g., timestamps, brief interactions) while keeping sensitive information private can be done by implementing appropriate privacy policies in the app.

## Latency vs Richness: Feasible Now
- **Real-Time Subtitles**: The `TranscriptLab` app provides a framework to test real-time subtitles. Ensuring that subtitles are delivered with low latency is critical for user trust and should be prioritized.
- **Memory Lookups**: Initial memory lookups can be performed on the phone, using the local storage mechanism described above. This approach allows for quick responses without relying heavily on cloud services.

## Discreet UX vs Visual Clarity: Feasible Now
- **Subtitle Display**: Implementing subtitles that are discreet yet clear is feasible now by testing various display options in `TranscriptLab`.
- **User Control**: Frame-touch interactions can be tested and refined to ensure they provide enough control without creating social awkwardness.

## Current Open Questions:
- **Subtitle Placement**: Test different placement strategies using the `TranscriptLab` app.
- **Confidence Display**: Incrementally implement confidence display features in subsequent iterations based on user feedback.
- **Memory/Cache Policy**: Implement and test memory caching strategies to ensure they meet performance needs without overloading the phone.
