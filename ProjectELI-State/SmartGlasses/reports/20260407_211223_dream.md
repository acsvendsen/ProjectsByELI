### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states helps ensure that subtitles are always clear and readable without becoming distracting. This improves real-time subtitle clarity, a key attractor, and reinforces trust by making sure the wearer can rely on the subtitles to follow conversations accurately.

2. **What small change unlocks it**

   Define 3-4 fixed subtitle placement rules based on confidence levels: one for high-confidence speakers (e.g., clear and well-known), another for medium-confidence speakers (e.g., new people or less certain matches), and a third for low-confidence situations where the speaker might be hard to identify. 

3. **Likely payoff**

   By having clear placement rules, the subtitles will remain unobtrusive while still being easily readable. This reduces cognitive load and ensures that the wearer can focus on the conversation without distraction, thereby enhancing the overall user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local cache threshold for face/name memory objects on the phone, we ensure that critical information is readily accessible without unnecessary privacy concerns or cloud reliance. This enhances trust by making sure the wearer can rely on stored memories even if network conditions are poor.

2. **What small change unlocks it**

   Define and implement a local cache eviction policy where each person-memory object has a maximum age threshold (e.g., 7 days) after which it is evicted from the local cache unless there is recent interaction or reinforcement.

3. **Likely payoff**

   This policy will ensure that important memories are kept fresh while reducing the risk of storing outdated or irrelevant information, thus balancing memory trust and privacy concerns effectively.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Staying focused on subtitle clarity and memory trust ensures that the primary attractors of real-time subtitle quality and trustworthy personal memory are prioritized in V1. This direct approach helps maintain user trust by delivering clear, reliable subtitles and accurate, non-invasive memory support.

2. **What small change unlocks it**

   Define a specific local cache size limit for face/name recall to ensure that the glasses can quickly access commonly seen individuals without relying on cloud fallbacks unnecessarily often.

3. **Likely payoff**

   By limiting the local cache size, we reduce battery and thermal load while ensuring that frequently encountered people are always available locally with low latency. This improves overall system performance and user trust in memory recall functionality.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
