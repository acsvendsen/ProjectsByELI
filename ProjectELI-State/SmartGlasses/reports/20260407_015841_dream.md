### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain a reliable user experience, which is crucial for the core mission of real-time subtitle clarity. Stable subtitles allow the wearer to trust and rely on the system during conversations, thereby enhancing the overall assistive value.

2. **What small change unlocks it**

   Define 3 fixed subtitle placement rules based on confidence levels: 
   - High confidence: Position subtitles slightly above and to the side of the speaker.
   - Medium confidence: Place subtitles directly below the speaker with minimal animation.
   - Low confidence: Hide subtitles or display them very briefly, then hide.

3. **Likely payoff**

   By defining fixed subtitle placement rules, V1 can achieve a more predictable and reliable user experience. This stability helps in building trust and reduces cognitive load for the wearer, making it easier to follow conversations even in noisy environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format can enhance trust in the system by clearly communicating the reliability of both subtitles and memory support to the wearer. A well-designed confidence label and short reason will help the wearer make informed decisions about which information to act upon.

2. **What small change unlocks it**

   Define a new confidence object format that combines a numeric score, a confidence label, and a short reason. For example: `score 0.84 + "High" + "Seen recently"` for subtitles and `score 0.53 + "Low" + "Weak match"` for memory recall.

3. **Likely payoff**

   By providing clear and concise feedback on the reliability of both subtitles and memory, the wearer can trust the system more, leading to better overall use and engagement with the product. This clarity will also help in reducing social awkwardness by showing when information is less certain.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local cache threshold for face/name memory on the phone, the system ensures that critical information is readily available without overloading the device's memory or introducing unnecessary latency. This helps in maintaining fast lookup and reinforcement over time, which are crucial for building trust and reliability.

2. **What small change unlocks it**

   Define a specific local cache size limit for storing face/name memories on the phone. For example, set a threshold of 50 recently encountered faces and names that are automatically cached locally to ensure quick access and reinforcement.

3. **Likely payoff**

   This change will improve memory recall performance by reducing latency and ensuring that frequently used or recently encountered information is always accessible in real-time. It also helps in maintaining the core attractor of "Trustworthy memory support" without overwhelming the local device, thereby preserving battery and thermal resources for other critical operations.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that the primary subtitles remain stable and responsive in real-time, which is crucial for maintaining trust and clarity during conversations.

2. **What small change unlocks it**

   Define a specific task-boundary rule: For "live subtitle processing," all critical data and computation stay on the phone, with any face or name recognition results cached locally before falling back to cloud if necessary.

3. **Likely payoff**

   This clear boundary will ensure that subtitles remain fast and stable, which is essential for real-time communication. It also reduces latency and optimizes battery usage by keeping critical processing local, thereby maintaining the core attractor of "real-time subtitle clarity."

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can focus on critical information without feeling overwhelmed. A clear distinction will enhance understanding and trust, making the assistant more effective in real-world interactions.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles are prioritized over one-line prompts by default but can be suppressed or reduced in prominence based on context and confidence levels. This ensures that the most important information is always visible, while less critical support remains secondary.

3. **Likely payoff**

   By clearly defining this priority rule, we can ensure that subtitles remain readable and trusted during live conversations, reducing cognitive load and enhancing the wearer's ability to follow the conversation without distraction. This improves overall user experience and trust in the system.

4. **Immediate next probe**
