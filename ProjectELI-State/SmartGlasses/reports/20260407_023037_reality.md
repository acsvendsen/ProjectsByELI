# Reality Check

## Subtitle Placement: Feasible Now
- **Current State**: The current project does not explicitly specify a subtitle placement strategy.
- **Constraints**: Glasses should remain socially acceptable and clear enough to be trusted in live conversation (subtitle clarity).
- **Feasibility**: Given the early V1 focus on frame-touch interaction, subtitles can be placed discretely within the glasses' display area. For example, placing subtitles at the bottom of the glasses' lens or slightly off-center could minimize distraction while ensuring readability.
- **Reasoning**: This approach aligns with the core-deepening mode and avoids broad feature sprawl.

## Confidence Display: Feasible Now
- **Current State**: The confidence display is not yet defined in terms of format, placement, or interaction.
- **Constraints**: Confidence must be represented in a way that builds trust without being intrusive (memory_trust).
- **Feasibility**: Implementing a simple label-based confidence indicator (e.g., "likely" or "probably") could be sufficient for V1. More complex formats like score + label can be considered later if necessary.
- **Reasoning**: This approach is consistent with the core-deepening mode and respects early hardware constraints.

## Memory/Cache Policy: Feasible Now
- **Current State**: The memory/cache policy is not yet defined, but it should support face/name recall without creating corrupted recall (memory_trust).
- **Constraints**: Early versions rely heavily on phone processing and cloud optional where useful.
- **Feasibility**: Implement a basic caching mechanism that stores recently seen faces and names locally. This can be enhanced later as the project evolves.
- **Reasoning**: This approach aligns with the current V1 architecture direction.

## Phone/Cloud Boundary: Feasible Now
- **Current State**: The phone/cloud boundary is not yet fully defined, but it should support live transcription and minimal local processing (phone_first_runtime).
- **Constraints**: Heavy processing on the phone while allowing cloud support where necessary.
- **Feasibility**: Implement a system that offloads speech recognition and heavy processing to the phone, with optional cloud support for more complex operations. This can be refined as the project progresses.
- **Reasoning**: This approach respects the current architecture direction and avoids speculative hardware complexity.

## Visual Hierarchy: Feasible Now
- **Current State**: The visual hierarchy is not yet defined, but it should ensure clear readability in noisy environments (subtitle_clarity).
- **Constraints**: Discreet UX vs enough visual clarity.
- **Feasibility**: Design a simple and readable visual layout for subtitles that minimizes distraction while ensuring they are visible and understandable. For example, using a clean, sans-serif font with appropriate color contrast against the glasses' frame.
- **Reasoning**: This approach aligns with the core-deepening mode and respects early hardware constraints.
