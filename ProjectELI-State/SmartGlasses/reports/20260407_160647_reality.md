# Reality Check for SmartGlasses Core Field

## Feasibility Analysis

### Subtitle Clarity: Real-time subtitle clarity (Subtitle Placement)
- **Feasible Now:** 
  - The current `TranscriptLab` app provides a good test bed for real-time subtitle clarity. Given the success of the recent build, it is feasible to continue refining and optimizing subtitle placement in live scenarios.
  
### Memory Trust: Trustworthy memory support (Memory/Cache Policy)
- **Feasible Now:** 
  - Implementing basic face/name recall with clear uncertainty signals can be done using local caching on the phone. This can be achieved through simple confidence-based mechanisms, such as displaying "Not sure" or "?" when the system is uncertain about a name or face.
  
### Low-friction Assistance: Low-friction assistance (Visual Hierarchy & Confidence Display)
- **Feasible Now:** 
  - One-line prompts can be integrated with subtitles in a way that minimizes visual clutter. For example, using different colors or fonts for prompts vs. subtitles can help distinguish them without overwhelming the wearer.
  
### Privacy vs Usefulness: Privacy vs usefulness (Privacy & Trust Constraints)
- **Feasible Now:** 
  - The current architecture direction of phone-first processing aligns well with privacy constraints. Ensuring that all interactions and memory storage are managed through the phone minimizes potential privacy issues.

### Latency vs Richness: Latency vs richness (Latency Constraints)
- **Feasible Now:** 
  - The `TranscriptLab` app provides a good starting point for real-time performance testing. Ensuring that subtitles remain stable and readable within acceptable latency constraints is feasible with continued optimization of the transcript handling logic.

### Discreet UX vs Visual Clarity: Discreet UX vs visual clarity (Visual Hierarchy & Subtitle Placement)
- **Feasible Now:** 
  - Using clear and unobtrusive subtitle placement, such as at the bottom or side of the field of view, can help maintain a discreet user experience while ensuring subtitles remain legible in noisy environments.

### Core Deepening Over Sprawl: Core-deepening over sprawl (Core-Deepening Priority)
- **Feasible Now:** 
  - Focusing on subtitle clarity, memory trust, and low-friction assistance is aligned with the current core deepening mode. These improvements will have a direct impact on daily-use value without adding unnecessary complexity.

### Phone/Cloud Boundary: Phone-first runtime (Phone/Cloud Interaction)
- **Feasible Now:** 
  - Given that the initial interaction is frame-touch only, and cloud support is optional for now, this boundary can be maintained effectively. Ensuring all core functionality operates on the phone will keep V1 simple and focused.

### Implementation Grounding: Implementation grounding (Development Focus)
- **Feasible Now:** 
  - Leveraging the `TranscriptLab` app to test and refine real-time transcription and confidence display is a concrete approach that aligns with the current development focus. This helps in maintaining a grounded implementation path.

## Assumptions Needing Evidence

### Subtitle Placement
- The best subtitle placement remains an open question. While current testing suggests bottom or side placement, more user feedback will be necessary to confirm this.
  
### Confidence Display
- The format of confidence display (label only, label + short reason, score + label) still needs concrete evidence from user testing and usability studies.

### Memory Cache Policy
- The amount of face/name memory that should be cached locally on the phone needs further exploration. Initial estimates can guide development but require validation through real-world use cases.
