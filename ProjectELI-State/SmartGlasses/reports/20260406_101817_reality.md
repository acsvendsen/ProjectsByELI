# Reality Check for SmartGlasses Core Field

## Current Direction Feasibility Analysis

### V1 Real World Limits

#### Hard Constraints
- **Feasible Now:** Glasses remain lightweight and socially acceptable. This can be achieved through careful design.
- **Feasible Later:** Battery and thermals are major risks for always-on features, but can be mitigated with advancements in technology. Early versions should use the phone for heavy processing to manage battery life.

#### Non-negotiables
- **Feasible Now:** The glasses help the wearer without pretending knowledge they do not have.
- **Feasible Later:** Local processing vs cloud intelligence. Cloud offloading can be used initially, with on-device learning algorithms developed over time to improve performance and privacy.

#### Core Attractors
- **Feasible Now:** Real-time subtitle assistance in noisy environments; personal memory support for names and prior conversations.
- **Feasible Later:** One-line contextual prompts rather than overwhelming paragraphs. This can be refined based on user feedback.

#### Core Tensions
- **Privacy vs Usefulness:** High priority to maintain privacy while providing useful information. Design must ensure that data is handled securely.
- **Always-on Sensing vs Battery and Thermals:** Early versions will rely heavily on the phone, with on-device processing being a later focus area.
- **Local Processing vs Cloud Intelligence:** Initial design should leverage cloud services for heavy computation to optimize battery life.

#### Drift Risks
- **Becoming a Gimmick:** High risk if features are not used daily. Regular user feedback and iterative improvements will be crucial.
- **Feature Sprawl:** Focus on core features (subtitles, memory recall) first. Expansion can happen based on user demand and technological advancements.

#### Why It Matters
- High priority to reduce social and cognitive friction for the wearer in various environments.

#### Evolution Rule
- The project is allowed to evolve if it strengthens the core mission and improves real-world usefulness.

### Open Questions

1. **V1 Split Between Glasses, Phone, and Cloud:**
   - **Feasible Now:** Early versions should rely heavily on the phone for processing.
   - **Assumptions Needing Evidence:** Optimal split will depend on battery life, display quality, and user experience testing.

2. **Face/Name Memory Storage and Reinforcement:**
   - **Feasible Later:** Implement efficient algorithms for face/name recognition and memory recall. Early versions can rely on phone/cloud processing.
   - **Assumptions Needing Evidence:** User feedback on the effectiveness of different storage/reinforcement methods.

3. **Confidence Representation:**
   - **Feasible Now:** Use a simple label with a short reason to represent confidence in face/name recognition.
   - **Assumptions Needing Evidence:** Iterative design and testing to find the best way to communicate uncertainty.

4. **Subtitles and One-Line Prompts Coexistence:**
   - **Feasible Now:** Design a balance where subtitles are clear and one-line prompts do not overwhelm the wearer.
   - **Assumptions Needing Evidence:** User tests to determine optimal display strategies for both features.

5. **V1 Features with Highest Daily-Use Value:**
   - **Feasible Now:** Focus on real-time subtitle assistance in noisy environments, followed by personal memory support for names and prior conversations.
   - **Assumptions Needing Evidence:** User feedback on which features are most valuable and useful.

2. **Design Iteration:** Based on user feedback, refine the V1 split between glasses, phone, and cloud processing.
