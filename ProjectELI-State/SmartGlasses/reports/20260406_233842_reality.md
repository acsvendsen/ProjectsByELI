## Reality Check for SmartGlasses Core Field

### Subtitle Clarity (Real-time subtitle clarity)
- **feasible now**: Ensure the subtitle placement is optimal for readability in live conversation without becoming distracting. The `TranscriptLab` app can help validate subtitle clarity by testing different placements and ensuring they remain stable and trustworthy during real-world interactions.

### Memory Trust (Trustworthy memory support)
- **feasible later**: Implement basic face/name recall with clear uncertainty signals, but avoid overloading the wearer with too much information at once. The current focus on low-friction assistance means that detailed memory functions should be kept simple in V1. However, preliminary tests can start to build a foundation for more robust memory support as hardware and battery constraints allow.

### Low Friction Assistance (Low-friction assistance)
- **feasible now**: Continue refining the one-line prompts to ensure they provide clear, useful information without overwhelming the wearer. Test different prompt formats and placements using `TranscriptLab` to find the most effective low-friction design that enhances understanding while maintaining social acceptability.

### Privacy vs Usefulness
- **constraint pressure**: Ensure all interactions respect privacy by not pretending certainty or creating false positives. V1 should focus on real, useful assistance rather than speculative features. This balance is critical and must be continuously monitored.

### Latency vs Richness
- **feasible now**: Focus on providing timely help with minimal latency to maintain trust. The `TranscriptLab` app can help test the responsiveness of live subtitles and memory support, ensuring that both functions are as fast as possible without compromising battery or thermal limits.

### Discreet UX vs Visual Clarity
- **feasible now**: Optimize subtitle placement for visual clarity while maintaining social acceptability. Use `TranscriptLab` to iterate on different display strategies, ensuring the subtitles remain readable and unobtrusive during real-world interactions.

### Frame-touch-only V1 Interaction
- **feasible now**: Stick to frame-touch interaction in V1 as per the explicit constraints. Any design changes or new command surfaces should be considered only after this mode is completed.

### Phone-first Runtime
- **feasible now**: Ensure all processing remains on the phone, with cloud support kept optional and justified by clear benefits. The `TranscriptLab` app can help validate the real-time transcript path before integrating glasses hardware.

### Core Deepening Over Sprawl
- **feasible now**: Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion. Use the current mode to drive concrete improvements in these areas.

### Constraint Pressure
- **feasible now**: Continuously surface real-world constraints early by using `TranscriptLab` for rapid prototyping and testing. This will help ensure that weak directions are identified and killed quickly, maintaining focus on core mission-critical improvements.

### Implementation Grounding
- **feasible now**: Base all decisions on concrete repo signals and app docs rather than generic ideation. The ongoing development of `TranscriptLab` is a critical step in this process.

## Assumptions Needing Evidence
