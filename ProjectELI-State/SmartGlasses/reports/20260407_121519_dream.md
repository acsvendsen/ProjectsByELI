### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain the wearer's trust in real-time subtitles, which is a primary attractor for the project. By keeping subtitles consistently visible and unobtrusive, we can enhance their reliability and make them more valuable for the wearer.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence speaker names and another for lower-confidence or unknown speakers. This allows us to visually prioritize known faces and names while still providing support for new or uncertain interactions.

3. **Likely payoff**

   By implementing this simple yet effective placement rule, we can ensure that the wearer quickly recognizes familiar names and faces, leading to more engaged and productive conversations. This will also reduce the cognitive load of constantly adjusting subtitle visibility.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring that confidence objects are clearly formatted and labeled helps build trust with the wearer by making the system's certainty explicit. This clarity is crucial for real-time subtitle assistance, as it allows the wearer to understand when they can rely on the subtitles or seek additional context.

2. **What small change unlocks it**

   Define a simple yet clear confidence format that includes both a numeric score and a label with a short reason. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

   By defining a clear and concise confidence format, the system can better manage expectations and reduce misunderstandings about the reliability of subtitles. This improves overall trust and user satisfaction, making real-time subtitle assistance more effective.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that frequently encountered names and faces are stored and recalled efficiently on the phone, reducing latency and ensuring that the wearer can quickly access relevant context without relying heavily on cloud processing. This improves trust by making sure the system is responsive and reliable in real-time interactions.

2. **What small change unlocks it**

   Define a local memory threshold of 5-10 recent face/name encounters per session that triggers automatic caching to the phone for fast lookup, with a minimum refresh interval of every 3 hours to ensure cache freshness.

3. **Likely payoff**

   By optimizing local memory thresholds, the system will reduce the need for frequent cloud requests, making interactions faster and more reliable. This will enhance the user experience by ensuring that common names and faces are always quickly accessible, improving overall confidence in the system's performance.

4. **Immediate next probe**

   Define a local cache eviction policy where frequently encountered face/name memories are retained with a minimum refresh interval of every 3 hours to ensure cache freshness.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus cloud-fallback, we ensure that critical real-time subtitle processing happens on the phone. This reduces latency and enhances trust by keeping the wearer's experience consistent with their current interactions. It also allows us to focus on battery-conscious design choices without affecting live subtitle quality.

2. **What small change unlocks it**

   Define a specific task boundary where subtitles are processed locally: "Live subtitle processing should always run phone-local, while transcript cleanup and face/name recall lookup can fall back to the cloud."

3. **Likely payoff**

   This decision will ensure that subtitles remain crisp and responsive, which is critical for maintaining trust and real-time accuracy. By offloading less-critical tasks like transcription cleanup to the cloud, we can also reduce battery drain on the glasses while keeping core functionality robust.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, the system ensures that the wearer can focus on critical information without being overwhelmed. This helps in maintaining trust by not overloading the user with too much visual data, which could distract them from the conversation.

2. **What small change unlocks it**

   Define a precedence rule where subtitles have higher visual prominence than one-line support, but one-line support is still visible and actionable when needed. This can be done by setting a subtitle placement mode that keeps subtitles at the top of the display area while allowing one-line support to appear in a secondary position.

3. **Likely payoff**

   A well-defined visual hierarchy will reduce cognitive load for the wearer, improving their ability to follow conversations more effectively. This will enhance the overall user experience and trust in the system's assistive capabilities.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
