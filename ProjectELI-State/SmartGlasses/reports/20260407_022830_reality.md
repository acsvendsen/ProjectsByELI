# Reality Check Summary

## Subtitle Placement
- **Subtitle Placement**: Feasible Now  
  Reason: The current project allows for frame-touch interaction in V1, which means the glasses can display subtitles directly without requiring complex AR visuals or heavy on-glasses processing. Given the focus on phone-first runtime and simple hardware constraints, it is feasible to design subtitle placement that remains readable and unobtrusive.

## Confidence Display
- **Confidence Display**: Feasible Now  
  Reason: The project emphasizes clarity over feature density and has a strong bias toward subtitle quality and memory support. A simple confidence format like a label with a short reason can be implemented effectively using the existing `TranscriptLab` framework, which already supports basic transcript readability and stability.

## Memory/Cache Policy
- **Memory/Cache Policy**: Feasible Now  
  Reason: The project is currently focusing on core deepening improvements. Implementing memory caching for names and faces locally on the phone can be done without significant complexity, aligning with the goal of providing helpful yet discrete support.

## Phone/Cloud Boundary
- **Phone/Cloud Boundary**: Feasible Now  
  Reason: The V1 architecture is designed to rely heavily on the phone while keeping cloud usage optional. Implementing memory caching and confidence display locally fits well within this design, reducing battery drain and maintaining a low-latency response.

## Visual Hierarchy
- **Visual Hierarchy**: Feasible Now  
  Reason: Given the current project constraints and focus on low-friction assistance, designing a visual hierarchy that balances subtitle clarity with minimal distraction is feasible. This can be tested using `TranscriptLab` to ensure readability in motion and noise.

### Summary of Findings

- **Subtitle Placement**: The glasses should place subtitles in a way that remains readable without becoming distracting. Given the current focus on phone-first runtime, this is feasible now.
  
- **Confidence Display**: Implementing confidence with a label and short reason can be done using existing tools like `TranscriptLab`. This is feasible now.

- **Memory/Cache Policy**: Caching names and faces locally on the phone to support memory recall is aligned with the current V1 constraints. This is feasible now.

- **Phone/Cloud Boundary**: The focus on a phone-first runtime makes implementing local processing for subtitle clarity and confidence display straightforward, making this feasible now.

- **Visual Hierarchy**: Designing a clear visual hierarchy that balances subtitle readability and low social friction can be tested using `TranscriptLab`. This is also feasible now.

### Likely Waste of Time

- **High-Fidelity AR Visualization**: Given the current constraints on always-on sensing vs. battery and thermals, implementing high-fidelity AR visualization would likely be a waste of time at this stage.

### Assumptions Needing Evidence

- **Voice Command Support**: While the project does not currently support voice commands, exploring their feasibility might need more evidence to justify adding complexity early in V1. 

By focusing on these areas, the project can continue to make meaningful progress while adhering to real-world constraints and prioritizing core improvements.
