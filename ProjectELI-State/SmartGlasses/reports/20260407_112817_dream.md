### Idea 1: Subtitle Placement

1. **Why it benefits the core**

Improving subtitle placement rules enhances the overall usability and trustworthiness of the system. By ensuring subtitles remain stable and in a non-distracting position, we can maintain high clarity and reduce cognitive load for the wearer during conversations.

2. **What small change unlocks it**

Define three fixed subtitle placement modes: one for confident matches (high certainty), another for likely new persons or faces, and a third for general background noise to minimize visual clutter.

3. **Likely payoff**

This approach will provide a clear and consistent visual experience that aligns with the wearer's expectations during conversations. It will reduce distraction from subtitles while maintaining their utility, thereby improving overall understanding and trust in the system’s assistance.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a simple numeric score combined with a label and short reason, the system can provide clear and actionable feedback that enhances trust in its memory and subtitle accuracy. This approach balances simplicity and clarity without adding unnecessary complexity.

2. **What small change unlocks it**

   Define a single confidence format that uses a numeric score from 0 to 1, a label (e.g., High, Medium, Low), and a short reason (e.g., "Seen recently", "Weak match"). For example: `score 0.85 + "High" + "Seen recently"`.

3. **Likely payoff**

   This format will allow the system to convey certainty levels succinctly, helping the wearer understand when information is highly reliable or less certain. It also simplifies user interface elements and reduces cognitive load by minimizing text while still providing necessary context.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds for face/name recall ensures that the system retains enough relevant context without overloading the phone's storage or battery, thereby enhancing the overall trustworthiness and utility of the SmartGlasses in real-world interactions.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects to 5-10 recent encounters, ensuring that only the most relevant names and faces are stored locally on the phone while minimizing storage and processing overhead.

3. **Likely payoff**

   By limiting the local cache to a few key memory objects, the system can maintain sufficient context without overwhelming the phone's resources, leading to faster lookups and more reliable name recall in live interactions. This enhances the wearer's confidence in the assistant’s ability to remember names and faces accurately.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that subtitles remain fast and reliable in real-time scenarios. This decision helps maintain the key attractor of "real-time subtitle clarity" by offloading computationally heavy tasks like deep speech-to-text processing and initial confidence scoring to the more powerful phone or cloud infrastructure when necessary.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that uses local on-device capabilities first, with fallbacks to cloud processing only in cases where real-time responsiveness is critical and local resources are strained.

3. **Likely payoff**

   By keeping the core subtitle rendering process phone-local, we can ensure fast, responsive, and stable subtitles even under network constraints or when the wearer's face is obstructed by movement. This decision will help maintain user trust in the system's reliability and real-time performance.

4. **Immediate next probe**
   - Define the task boundary such that real-time subtitle processing uses phone-local capabilities first, with cloud fallbacks only when local resources are exhausted or unavailable.

It also aligns with the low-friction assistance attractor by keeping one-line prompts unobtrusive until necessary, thereby maintaining a cleaner user experience.
