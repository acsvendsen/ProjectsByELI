# Core Field: SmartGlasses Core Field

## Mission
Create smart glasses that act as a discreet, context-aware personal assistant focused on live subtitles, face/name recall, conversation memory, and one-line support to help the wearer understand and respond better in real-world interactions.

## Non-negotiables
- The glasses help the wearer; they do not pretend knowledge the wearer does not have.
- Early hardware remains simple: display text, record audio/visual input; phone/cloud handles heavy processing.
- Context must persist across sessions.
- New faces and names should be remembered with confidence objects and reinforcement over time.
- Real-world constraints must be surfaced early: latency, battery, privacy, social acceptability, on-device limits.

## Core Attractors
- Real-time subtitle assistance in noisy environments
- Personal memory support for names and prior conversations
- One-line contextual prompts rather than overwhelming paragraphs
- Low-friction human experience; assistive, not deceptive

## Core Tensions
- Privacy vs usefulness
- Always-on sensing vs battery and thermals
- Local processing vs cloud intelligence
- Rich memory vs fast lookup
- Discreet UX vs enough visual clarity

## Drift Risks
- Becoming a gimmick instead of a daily-use assistant
- Feature sprawl before core subtitle/memory loop is excellent
- High-latency responses that break trust
- Storing low-value information instead of weighted relevant memory

## Feasibility Assessment

### Feasible Now
1. **Real-time Subtitle Assistance in Noisy Environments**
   - **Assessment**: Current technology can handle real-time audio-to-text conversion with reasonable accuracy.
   - **Action**: Integrate existing ASR (Automatic Speech Recognition) APIs and text display on the glasses.

2. **Personal Memory Support for Names and Prior Conversations**
   - **Assessment**: Initial memory systems can be implemented using phone/cloud services to store basic data and provide context.
   - **Action**: Develop a simple API that allows the glasses to interact with a cloud service for name recall and conversation history.

3. **Low-friction Human Experience**
   - **Assessment**: Minimal UI design is feasible, focusing on clear text display without overwhelming the user.
   - **Action**: Design a simple overlay or pop-up system that minimally disrupts the wearer's experience.

### Feasible Later
1. **Always-on Sensing vs Battery and Thermals**
   - **Assessment**: While power-efficient sensors are available, always-on sensing may require advancements in battery technology.
   - **Action**: Monitor current battery usage and explore potential improvements or compromises (e.g., turning off certain features during non-critical times).

2. **Local Processing vs Cloud Intelligence**
   - **Assessment**: Initial stages can rely on cloud processing due to the complexity of real-time context-aware AI.
   - **Action**: Gradually incorporate local processing capabilities as hardware improves and power management becomes more efficient.

3. **Discreet UX vs Enough Visual Clarity**
   - **Assessment**: Discreet designs are challenging but feasible with advanced display technology.
   - **Action**: Prototype discreet displays that meet the visual clarity requirements for real-time subtitles.

### Likely Waste of Time
1. **Rich Memory vs Fast Lookup**
   - **Assessment**: Implementing a complex memory system might be premature without extensive user testing and feedback.
   - **Action**: Focus on basic memory recall initially, then iterate based on user needs and technological advancements.

2. **High-latency Responses that Break Trust**
   - **Assessment**: Initial systems are likely to have some latency issues due to the complexity of real-time processing.
   - **Action**: Implement a feedback loop where users can provide input on response times to identify and address bottlenecks.

### Assumptions Needing Evidence
1. **Privacy Concerns**
   - **Assessment**: Users may be hesitant about constant audio recording, especially in public spaces.
   - **Action**: Conduct surveys or focus groups to understand user privacy concerns and develop appropriate safeguards (e.g., explicit consent mechanisms).

2. **Social Acceptability**
   - **Assessment**: Smart glasses could face social stigma due to their novelty.
   - **Action**: Engage with potential users through pilot programs to gather feedback on the glasses' social impact.

3. **On-device Limits**
   - **Assessment**: Current hardware limitations may restrict local processing capabilities.
   - **Action**: Regularly update and test against new hardware releases to ensure that local processing can be optimized as technology advances.

## Conclusion
The core features of real-time subtitles, personal memory support, and low-friction UX are feasible with current technology. However, always-on sensing and rich memory systems will require further development. Privacy concerns and social acceptability need careful consideration through user engagement. By addressing these challenges systematically, the project can progress towards a viable daily-use assistant.
