### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Improving subtitle placement ensures that subtitles remain stable, clear, and in a non-distracting position, which is crucial for maintaining trust and readability during live conversations. This helps the wearer stay focused on the conversation without being interrupted by poorly placed text.

2. **What small change unlocks it**
   - Define 3 fixed subtitle placement rules: one for high-confidence speech (e.g., well-known speakers), one for medium-confidence speech (e.g., new or less familiar speakers), and one for low-confidence speech (e.g., background noise or unclear audio).

3. **Likely payoff**
   - By defining clear and stable subtitle placement rules, the system will provide more reliable and readable subtitles, reducing cognitive load and increasing trust in the assistive feature during live interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining how confidence is displayed through clear labels, short reasons, and numeric scores, we can enhance trust in both subtitle accuracy and memory support. This improves overall user confidence without overloading them with too much detail.

2. **What small change unlocks it**

   Define a new format for confidence objects that combines a numeric score (e.g., 0.85), a label (e.g., "High"), and a short reason (e.g., "Seen recently"). This will provide a clear and concise representation of the system's certainty.

3. **Likely payoff**

   A well-defined confidence format will help users trust the subtitles and memory support more. It will also enable the system to reinforce correct behaviors, such as showing higher confidence for names seen frequently in recent conversations.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory threshold for face/name recall ensures that frequently encountered individuals are remembered and recalled quickly, enhancing the wearer's trust in the system’s ability to handle real-world interactions effectively.

2. **What small change unlocks it**

   Define a local cache size limit of 50 unique names or faces that can be stored on the phone with high confidence without requiring cloud fallbacks.

3. **Likely payoff**

   By setting a specific, finite memory threshold, the system will prioritize frequently encountered individuals and ensure fast recall responses, thereby maintaining trust and reducing latency issues related to frequent name recall during conversations.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that real-time subtitles remain clear and stable enough to maintain trust in noisy environments. This focus on core functionality helps prevent battery drain from heavy cloud processing while still providing essential support.

2. **What small change unlocks it**

   Define a specific boundary where face/name recall lookup falls back to the cloud only when the glasses need more computation than can be handled locally, but keep live subtitle processing entirely phone-local.

3. **Likely payoff**

   This change will ensure that subtitles remain fast and reliable, reducing battery drain and maintaining trust in real-time interactions. By limiting cloud fallbacks for critical tasks like subtitle rendering, we can focus on delivering high-quality core functionality without overburdening the glasses hardware.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles remain stable, readable, and trusted in live conversations is crucial for the wearer's understanding and confidence. By defining clear subtitle placement rules under different confidence states, we can enhance the reliability of the subtitle experience, which directly ties into the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define 2 to 3 subtitle placement rules for different confidence levels (high-confidence faces/names, medium-confidence context, and low-confidence background). This simple change will standardize how subtitles are displayed based on the reliability of the recognized entity, ensuring that critical information is always prominently visible.

3. **Likely payoff**

   By implementing these subtitle placement rules, we can significantly improve the wearer's ability to trust the subtitles in dynamic environments. High-confidence entities like face/names will be given priority and clear visibility, while lower-confidence content will maintain a more subtle presence, reducing visual overload without compromising clarity when it matters most.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
