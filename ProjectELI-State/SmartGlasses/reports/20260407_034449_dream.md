### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules, we can ensure that subtitles remain stable and unobtrusive while still being easily readable. This improves real-time subtitle clarity (attractor: subtitle_clarity) by reducing visual distractions during live conversations.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence speech (90%+ confidence) to be displayed at the bottom of the screen, and another for low-confidence speech (50%-89%) to be shown in a semi-transparent overlay over the wearer's field of view.

3. **Likely payoff**

   This change will enhance user trust by making subtitles more predictable and less distracting during live conversations. It also aligns with the core attractor of real-time subtitle clarity, ensuring that important information is always visible without overwhelming the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

Improving memory cache size and eviction policy ensures that the system can store relevant memories effectively, reducing the need for cloud fallbacks and improving local response times. This directly enhances the core mission by ensuring reliable, fast recall of names and prior context without overloading the wearer with unnecessary information.

2. **What small change unlocks it**

Define a local cache size limit of 10 entries per person, using a least-recently-used (LRU) eviction policy. This ensures that the most relevant memories are retained while maintaining low memory usage.

3. **Likely payoff**

By limiting the cache to 10 entries and evicting the least recently used items first, the system can maintain high-quality recall for names and contexts without consuming excessive phone storage. This will reduce cloud fallbacks, improve response speed, and ensure that the wearer receives contextually relevant support.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.
