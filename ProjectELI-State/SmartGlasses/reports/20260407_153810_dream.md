### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   By defining a fixed subtitle placement rule that prioritizes readability and stability, we can ensure that subtitles remain clear and unobtrusive during live interactions. This helps in maintaining trust and ensuring that the wearer does not experience distractions that could break concentration.

2. **What small change unlocks it**
   Define a fixed subtitle placement mode where subtitles appear at the bottom center of the screen with minimal movement, unless confidence is high enough to warrant repositioning for clarity.

3. **Likely payoff**
   This approach will reduce visual distraction during conversations and maintain consistent subtitle visibility, which enhances trust in the system’s reliability and aids in better understanding without overloading the wearer's attention.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps build trust in the system's reliability, which is crucial for the core mission of providing clear and stable real-time subtitles. A well-crafted confidence label and short reason will ensure that the wearer understands when they can rely on the subtitles or when the system is uncertain.

2. **What small change unlocks it**

   Define a simple but effective confidence format that combines a numeric score with a label and a brief reason for its certainty level. For example, use "0.84 (High) - Seen recently" instead of just a raw number.

3. **Likely payoff**

   By clearly indicating the system's confidence in each subtitle, the wearer will trust the subtitles more, especially during noisy conversations where accuracy is critical. This improves overall user satisfaction and reduces cognitive load by reducing the need for constant verification.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we can ensure that frequently encountered names are kept in the phone's memory, improving the speed and accuracy of new-person recall. This helps maintain the core mission of providing reliable face/name support without overburdening the cloud or battery.

2. **What small change unlocks it**

   Define a local cache threshold for name recall that evicts less frequently used names after a certain number of interactions. For example, limit the local cache to 50 unique names with a refresh interval based on the last seen timestamp.

3. **Likely payoff**

   Implementing this local cache strategy will reduce latency in new-person recall, ensuring faster and more reliable name recognition for common contacts. This improves overall trust and satisfaction without significantly increasing battery usage or cloud dependency.

4. **Immediate next probe**

   Define one local-cache size limit for names that balances memory efficiency with fast lookup performance.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   Improving the phone-cloud boundary for live subtitle processing ensures that subtitles remain real-time and clear, which directly supports the primary attractor of real-time subtitle clarity. By carefully defining what stays on the phone versus what falls back to cloud, we can maintain low latency while still leveraging cloud resources where justified.

2. **What small change unlocks it**
   Define a specific set of live subtitle processing tasks that should be performed locally (on the phone) and those that can safely fall back to the cloud without compromising real-time performance. For example, define rules for local processing of speech-to-text conversion, basic confidence scoring, and initial memory linking, while offloading complex entity resolution or background memory updates to the cloud.

3. **Likely payoff**
   By carefully balancing what stays phone-local and what can go to the cloud, we can ensure that subtitles remain stable and clear in real-time interactions. This will enhance user trust and satisfaction with the product, as well as reduce battery drain on the glasses by offloading non-critical tasks.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles and one-line prompts coexist in a way that respects visual clarity and social acceptability is crucial for maintaining the wearer's trust and comfort. By defining a clear precedence rule, we can ensure that important information like names or context is prioritized without overwhelming the wearer with too much text.

2. **What small change unlocks it**

   Define a single visual priority rule that states: "When subtitles and one-line prompts overlap, prioritize one-line prompts for critical new information (e.g., name recall, key context) over existing subtitles."

3. **Likely payoff**

   This prioritization will help keep the wearer's attention focused on critical new information, reducing cognitive load and ensuring that important details are not missed. It also aligns with the project’s goal of low-friction assistance, making the system more useful without overwhelming the user.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
