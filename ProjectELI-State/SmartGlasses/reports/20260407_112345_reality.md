# Reality Check

## Subtitle Clarity: Feasible Now
- **Subtitle Placement**: The glasses should place subtitles directly below the speaker's face or in a clear, non-distracting area that does not block important visual cues. Given the current focus on V1 interaction being frame-touch only and early hardware remaining simple, this is feasible now.
- **Visual Clarity vs Discreet UX**: Initial tests with `TranscriptLab` can validate placement without overwhelming wearers. This ensures subtitles remain readable but do not distract during conversation.

## Memory Trust: Feasible Later
- **Face/Name Memory Storage and Reinforcement**: Early V1 interaction focuses on frame-touch controls, so memory reinforcement through frequent interactions is not immediately critical. However, early testing can involve storing names and faces locally for quick lookups in subsequent versions.
- **Confidence Display**: The current mode emphasizes core deepening, which means confidence display should focus on clear indicators of certainty or doubt without creating false certainty. This can be implemented later as a refinement based on user feedback.

## Low Friction Assistance: Feasible Now
- **One-Line Prompts**: Given the frame-touch interaction constraint, delivering one-line prompts through text overlay is feasible now. Simple prompts like "Remember Jane" or "Repeat that" can provide low-friction assistance without adding complex command interfaces.
- **Subtitle and Prompt Coexistence**: The `TranscriptLab` app can test different placements of subtitles and prompts to ensure they do not overlap and remain readable.

## Privacy vs Usefulness: Feasible Later
- **Automatic Memory Support vs Confidence and Correction Safety**: Early V1 interaction does not rely on voice commands, so the risk of privacy concerns is minimal. However, as memory support expands, careful design is needed to ensure users trust the system without feeling it oversteps boundaries.

## Latency vs Richness: Feasible Now
- **Real-time Subtitles**: The `TranscriptLab` app tests real-time speech-to-text functionality, which can be optimized for V1 release. Early feedback will help determine if real-time subtitles are possible with current hardware constraints.
- **Confidence Display Timeliness**: Initial confidence display should focus on providing timely and relevant information without overwhelming the wearer.

## Discreet UX vs Visual Clarity: Feasible Now
- **Subtitle Placement**: Initial tests can validate subtitle placement to ensure it remains socially acceptable while still being readable. This can be refined as user feedback comes in, but initial efforts should aim for a balance that is both useful and discreet.

### Summary of Findings

- **Subtitle Clarity** and **Low Friction Assistance** are feasible now and can be implemented through the `TranscriptLab` app.
- **Memory Trust** and **Privacy vs Usefulness** are more complex and will require further development as the system evolves.
- **Latency vs Richness** is a balance that needs to be managed early, with real-time subtitles being a priority.

### Next Steps

1. **Subtitle Placement**: Conduct initial tests in `TranscriptLab` to find an optimal subtitle placement.
2. **Low Friction Assistance**: Implement one-line prompts and test their effectiveness through frame touches.
3. **Memory Support**: Store names and faces locally for future versions while focusing on clear confidence indicators.

By following these steps, the project can maintain its focus on core deepening while addressing real-world constraints early in the development process.
