# Reality Check Summary

## Feasible Now
- **Subtitle Clarity (subtitle_clarity)**: Real-time subtitle clarity that remains readable, stable, and trust-preserving in live conversation.
  - Reasoning: The `TranscriptLab` app is already being used to test and validate subtitle quality. Further refinement of this feature should be feasible now given the existing infrastructure.

- **Memory Trust (memory_trust)**: Remember names, faces, and prior context without pretending certainty or creating corrupted recall.
  - Reasoning: The memory support can be refined by optimizing confidence objects and reinforcement rules within `TranscriptLab`. This is a core feature that should continue to be worked on in the current phase.

- **Low-Friction Assistance (low_friction_assistance)**: Deliver one-line help and visible support without creating command overhead or social awkwardness.
  - Reasoning: The initial V1 interaction through frame touches only can be improved by refining subtitle placement, confidence display, and visual hierarchy. This is a core feature that should be deepened in the current phase.

## Feasible Later
- **Subtitle Placement**: Determine what subtitle placement is most usable without becoming distracting.
  - Reasoning: While this is important for user experience, it requires empirical testing which may not be fully feasible now due to current infrastructure limitations. However, initial hypotheses can be explored and refined as the project progresses.

- **Confidence Display**: Decide on a confidence format that builds trust best (label only, label + short reason, or score + label).
  - Reasoning: This involves UI design and may require additional testing and iteration beyond the current phase. Initial implementations can be tested in `TranscriptLab` but more refined designs will likely come later.

- **Memory Cache Policy**: Determine how much face/name memory should be cached locally on the phone.
  - Reasoning: This requires balancing local storage with battery constraints, which may not be fully feasible now without additional testing. Initial cache policies can be explored and iterated upon in future phases.

## Likely Waste of Time
- **Automatic Memory Support vs Confidence and Correction Safety**: While this is an important tension to manage, the current focus should remain on core deepening rather than exploring new interaction modes or hardware complexity.
  - Reasoning: The project is currently focused on improving subtitle quality, memory support, and confidence behavior. Exploring new interactions in V1 would be premature.

## Assumptions Needing Evidence
- **Frame-Touch Interaction Only**: While this constraint is hard-coded for the current phase, assumptions about its long-term usability should be tested.
  - Reasoning: Voice commands could potentially enhance user experience but need to be evaluated against existing constraints and real-world usage data.
