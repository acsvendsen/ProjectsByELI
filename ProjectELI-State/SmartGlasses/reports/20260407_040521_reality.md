# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now
- **Subtitle Clarity**: The current implementation in `TranscriptLab` already shows that subtitles can be placed near the wearer's ear or directly in their line of sight. This placement is critical to maintaining real-time clarity and readability, especially in noisy environments.
- **Visual Hierarchy**: Given the constraints of V1 (frame-touch interaction), the subtitle display should prioritize simplicity and ease of reading while avoiding distraction.

### Feasibility: Feasible Now
- The `TranscriptLab` app's current design can serve as a proof of concept for subtitle placement. Ensuring subtitles are displayed in a non-distracting but easily readable manner is achievable without significant additional complexity.

## Confidence Display: Feasible Later
- **Confidence Format**: The initial implementation in `TranscriptLab` shows that confidence can be represented with a simple label, such as "High," "Medium," or "Low." This approach balances clarity and utility.
- **Reason for Uncertainty**: Implementing a short reason to accompany the label could provide more context but may add unnecessary complexity early on.

### Feasibility: Feasible Later
- While the core of confidence display can be implemented now, adding detailed reasons might require more complex UI design and processing. Focusing on basic labels first ensures that the core functionality is robust before adding more details.

## Memory/Cache Policy: Feasible Now
- **Face/Name Recall**: The initial implementation in `TranscriptLab` should focus on remembering names and faces with a clear mechanism for reinforcing recall over time.
- **Memory Integrity**: Ensuring memory integrity involves recording interactions, context, and confidence levels. This can be done locally on the phone without significant battery drain.

### Feasibility: Feasible Now
- The current `TranscriptLab` setup is sufficient to implement basic face/name recall with periodic reinforcement. This will help in building trust and providing useful memory support.

## Phone/Cloud Boundary: Likely Waste of Time for V1
- **V1 Interaction**: Given the frame-touch-only constraint, cloud interaction is not a priority for V1.
- **Local Processing**: The initial version should focus on local processing to minimize battery drain and latency issues.

### Feasibility: Likely Waste of Time for V1
- Early versions should rely heavily on phone-side processing. Exploring cloud integration too early might distract from the core functionality needed in V1.

## Visual Hierarchy: Core Deepening Over Sprawl
- **Subtitle vs Prompt**: Subtitles and one-line prompts need to coexist without overwhelming the wearer.
- **Subtitle Clarity**: Ensuring subtitles are clear, fast, and stable is critical. The current `TranscriptLab` setup should guide this decision.

### Feasibility: Core Deepening Over Sprawl
- Focusing on subtitle clarity first ensures that the core functionality is strong before adding more complex UI elements. This approach aligns with the current mode of core deepening.

## Summary

- **Subtitle Placement**: Feasible Now - The `TranscriptLab` setup can serve as a good starting point.
- **Confidence Display**: Feasible Later - Basic labels are sufficient for now, detailed reasons can be added later if needed.
- **Memory/Cache Policy**: Feasible Now - Implementing basic face/name recall with reinforcement is practical and useful.
- **Phone/Cloud Boundary**: Likely Waste of Time for V1 - Focus on local processing to minimize battery drain and latency issues.
- **Visual Hierarchy**: Core Deepening Over Sprawl - Prioritize subtitle clarity over adding new UI elements.

By focusing on these core areas, the project can build a strong foundation before exploring more complex features.
