### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a fixed subtitle placement rule that prioritizes readability and stability over dynamic adjustment, we ensure that subtitles remain clear and unobtrusive in all contexts. This helps maintain the wearer's trust and focus during conversations.

2. **What small change unlocks it**

   Introduce a new subtitle placement mode where subtitles are positioned at the bottom center of the display by default, unless confidence is extremely low (below 0.4), in which case they should move to the top center for high visibility.

3. **Likely payoff**

   This fixed placement rule will reduce visual distraction and maintain readability across various scenarios. It ensures that subtitles do not shift unexpectedly during conversation, thereby improving trust and comprehension without adding complexity or battery drain.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances the trustworthiness of subtitle and memory assistance. By clearly showing the certainty level, the system can better guide the wearer's understanding without overstating its own knowledge. This improves the overall reliability of the assistive behavior, aligning with the mission to help the wearer understand better.

2. **What small change unlocks it**

   Define a simple confidence format that combines a numeric score, label, and short reason. For example: `score 0.84 + "High" + "Seen recently"` for well-known names, or `score 0.35 + "Low" + "Weak match"` for new faces.

3. **Likely payoff**

   By implementing a clear confidence format, the system can better manage its assistive behavior. This will help in maintaining trust by accurately representing its certainty levels, reducing overconfidence and underconfidence errors. The wearer will be able to discern when the system is likely correct and when it might need further input or verification.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache policy helps ensure that frequently recalled names and faces remain available to the wearer quickly, without overburdening battery and thermal constraints. This directly supports the core attractor of "Trustworthy memory support," by ensuring that the system can reliably provide context without creating unnecessary latency or privacy concerns.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory on the phone, set at 50 entities, with a recency threshold of the last week's interactions.

3. **Likely payoff**

   By setting a clear and manageable cache size limit, we ensure that the system can maintain high memory trust without excessive data retention or unnecessary load on the battery and CPU. This will help in maintaining consistent performance and privacy, aligning with the core attractors of low-friction assistance and trustworthy memory support.

4. **Immediate next probe**
   - Define a local cache size limit for face/name memory on the phone at 50 entities.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus cloud, we can ensure that V1 remains focused on delivering high-value subtitle and memory support without overloading the glasses hardware. This will help maintain the low-friction, discreet UX essential to daily use.

2. **What small change unlocks it**

   Define one task-specific fallback rule where live subtitle processing should fall back to cloud if local resources are insufficient. For example, choose whether face/name recall or memory archive sync should be local-first, with a clear fallback strategy for critical tasks like real-time subtitles.

3. **Likely payoff**

   By clearly defining the phone/cloud boundary, we can ensure V1 remains lightweight and socially acceptable while still delivering essential real-time subtitle support. This will help maintain trust and usability in noisy environments and complex social situations.

4. **Immediate next probe**
   - Define the phone/cloud boundary for live subtitle processing, ensuring it falls back to the cloud if local resources are insufficient.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By optimizing the visual hierarchy between subtitles and one-line support, we can ensure that critical information is prioritized for quick understanding while maintaining a low-friction interface. This will help the wearer stay focused on essential conversation details without feeling overwhelmed by excessive text.

2. **What small change unlocks it**

   Define a clear subtitle-vs-one-line priority rule where subtitles are always shown and one-line support is displayed only when necessary, such as during name introductions or important topic transitions.

3. **Likely payoff**

   This prioritization will enhance the wearer's ability to follow conversations in real-time without feeling distracted by too much text. It will also ensure that critical information, like names and key topics, are immediately noticeable, improving overall understanding and engagement.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
