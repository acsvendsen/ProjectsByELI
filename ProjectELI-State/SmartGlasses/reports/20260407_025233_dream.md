### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we ensure that subtitles remain clear and stable enough for the wearer to trust them in live conversations. This improves real-time subtitle clarity (subtitle_clarity attractor) while minimizing distraction.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence content where subtitles are placed at the bottom of the field-of-view, and another for low-confidence content where subtitles are slightly above the gaze to avoid obstruction but still visible.

3. **Likely payoff**

   This approach will provide a clear visual hierarchy that supports trust in real-time subtitles while keeping the interface unobtrusive. It aligns with the core attractor of real-time subtitle clarity and helps maintain the low-friction assistance goal by ensuring that high-confidence content is easily readable without distraction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring clear, consistent confidence labels and short reasons enhances trust in memory recall and subtitle accuracy. This helps maintain the wearer's understanding without creating uncertainty or confusion.

2. **What small change unlocks it**

   Define a standard format for confidence objects that combines a numeric score, label, and a brief reason. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   By providing a clear, concise format for confidence objects, the system can better manage trust and accuracy in memory recall and subtitles. This improves the wearer's perception of reliability and reduces cognitive load.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new faces and names are remembered with stable, reinforced memory objects helps maintain trust in the system's memory capabilities. By default, likely new-person memory should be automatically captured through frame touches, but explicit reinforcement can be used to build stronger confidence over time.

2. **What small change unlocks it**

   Define a local cache threshold for face/name recall that evicts old entries based on recency and confidence score. This ensures that the phone caches only the most relevant memories, reducing memory bloat while maintaining useful recall.

3. **Likely payoff**

   By setting a clear eviction policy, the system can maintain fast lookup performance without overwhelming the local cache. This reduces latency in memory retrieval and keeps the memory objects fresh and reliable, enhancing the overall user experience.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud, we ensure that V1 remains lightweight and socially acceptable while still providing essential functionality. This helps in maintaining high trust by avoiding unnecessary cloud interactions and ensuring real-time responsiveness.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary for live subtitle processing. For example, limit cloud fallbacks to cases where the phone cannot process audio input due to thermal constraints or battery limits.

3. **Likely payoff**

   By carefully defining this boundary, we can ensure that subtitles remain clear and stable during critical conversations, reducing the risk of breaking trust through delayed or corrupted data. This will also help in keeping the user experience low-friction and socially acceptable.

4. **Immediate next probe**

   Define one cloud fallback rule for live subtitle processing where the phone cannot process audio input due to thermal constraints or battery limits.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the wearer's ability to read subtitles during live conversations, thereby improving real-time subtitle clarity and reducing cognitive load. Stable subtitle placement helps maintain trust in the system’s ability to provide accurate and timely support.

2. **What small change unlocks it**

   Define 2 to 3 subtitle placement rules for different confidence states: high-confidence faces/names close to their visual context; medium-confidence faces/names slightly offset but still visible; low-confidence faces/names minimized or hidden until confirmed by additional evidence.

3. **Likely payoff**

   By implementing these subtle yet targeted placement rules, the system can ensure that critical information is always within view when needed, while minimizing distraction during less certain moments. This improvement will directly enhance subtitle clarity and user trust in the system’s reliability.

4. **Immediate next probe**
