### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining clear subtitle placement rules based on confidence levels, we can ensure that subtitles are always visible but not overly distracting. This improves the wearer's trust in real-time information and enhances their ability to follow conversations.

2. **What small change unlocks it**

   Define a rule where subtitles appear at the bottom center of the field of view with high confidence (0.9+), slightly below-center for medium confidence (0.6-0.8), and only briefly on the right side during low confidence (below 0.5) states.

3. **Likely payoff**

   This change will reduce subtitle clutter, ensuring that critical information is always visible without overwhelming the wearer. It also helps in maintaining a balance between providing necessary assistance and avoiding distraction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide clear, concise, and trustworthy certainty indicators, we can enhance the wearer's trust in both subtitles and memory support. This will help ensure that the system remains reliable and useful without overloading the user with unnecessary information.

2. **What small change unlocks it**

   Implement a simple confidence format that includes a numeric score, label, and short reason for each piece of memory or subtitle display. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format will provide a clear indication of the reliability of the information.

3. **Likely payoff**

   A well-defined confidence display format can significantly enhance trust and usability by making it easier for the wearer to distinguish between highly confident and less certain pieces of information. This clarity will reduce cognitive load and help the wearer focus on the most relevant details, thereby improving overall interaction quality.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall on the phone, we can ensure that frequently encountered names are quickly accessible without relying heavily on cloud latency. This improves trust and speed in real-time conversations by reducing the lag between a face or name appearing and the memory being recalled.

2. **What small change unlocks it**

   Define a local cache size limit for person memories on the phone, ensuring that only the most frequently encountered names and faces are stored locally with high confidence levels. This can be done by setting a recency threshold and limiting the number of entries to keep in memory.

3. **Likely payoff**

   Implementing this cache policy will result in faster recall times for common people, reducing the latency in name recognition during live conversations. This will enhance the wearer's trust in the system’s ability to support their memory without delay, leading to a more seamless and natural user experience.

4. **Immediate next probe**

   Set a local cache size limit of 10 frequently encountered names on the phone for V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining which memory tasks run on the phone versus cloud, we can ensure that V1 has a clear focus on delivering real-time subtitle assistance and context-aware support without overwhelming battery or thermal limits. This helps maintain the balance between privacy and usefulness by limiting sensitive operations to the phone where possible.

2. **What small change unlocks it**

   Define specific cloud fallback boundaries for memory tasks, such as face/name recall lookup, while keeping live subtitle processing local. For example, set a rule that face/name recall should only fall back to the cloud if there is no recent local context and the glasses are near the phone.

3. **Likely payoff**

   This approach ensures that V1 can deliver timely and reliable memory support without overloading the phone's limited resources. It also helps maintain user trust by keeping sensitive operations like face recognition on-device, reducing privacy concerns while still providing useful assistance in critical contexts.

4. **Immediate next probe**

   Define one cloud fallback boundary for face/name recall lookup such that it only falls back to the cloud if there is no recent local context and the glasses are within a specific distance from the phone (e.g., less than 5 meters).

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain the wearer's focus on essential information without overwhelming them with too much data. This improves clarity and reduces cognitive load, aligning with the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define a single display rule that prioritizes subtitles over one-line support when both are active. This can be done by setting a precedence order where subtitles are always visible unless explicitly suppressed, while one-line prompts appear only in the margin or as needed.

3. **Likely payoff**

   By establishing a clear visual hierarchy, the system will maintain a consistent and reliable user experience that prioritizes essential information. This enhances the wearer's ability to focus on critical conversation elements without being distracted by less important prompts, thereby improving overall usability and trust in the system.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
