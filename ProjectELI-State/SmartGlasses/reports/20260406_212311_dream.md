### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining fixed subtitle placement rules for different confidence states, we can ensure that subtitles remain stable and readable in various scenarios without becoming distracting. This improves daily-use value by maintaining trust in the system's ability to provide clear and reliable assistance.

2. **What small change unlocks it**

   Introduce a simple rule set where high-confidence subtitles are placed at the bottom of the screen, medium-confidence ones slightly above, and low-confidence ones temporarily hidden until more evidence is gathered. This can be achieved by adding conditional logic in `TranscriptLabRootView.swift` to dynamically adjust subtitle placement based on confidence scores.

3. **Likely payoff**

   Implementing fixed subtitle placement rules will enhance user trust and satisfaction by ensuring that subtitles remain unobtrusive yet always visible when needed. It reduces cognitive load for the wearer, making it easier to follow conversations in noisy environments or while multitasking.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs phone-local versus falling back to cloud for live subtitle processing, we can ensure real-time responsiveness and privacy while maintaining trust in the system's reliability. This helps balance the tension between always-on functionality and battery life, ensuring that the subtitles remain stable and trustworthy during critical interactions.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing to run phone-local with minimal latency, and set clear rules for when to fallback to cloud for transcript cleanup or memory archive sync. This involves defining a policy where subtitle generation is done on-device unless the content requires heavy processing that can be safely offloaded.

3. **Likely payoff**

   By keeping live subtitle processing local, we can ensure faster, more reliable performance and lower battery usage. This approach will also allow for better privacy since sensitive audio data does not need to leave the phone, enhancing user trust in the system’s ability to respect their privacy while still providing essential assistance.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line prompts in V1 helps maintain low-friction assistance without overwhelming the wearer. This balance ensures that important information is easily readable, while minor support remains unobtrusive.

2. **What small change unlocks it**

   Define a priority rule where subtitles are always displayed above one-line prompts unless the one-line prompt is critical and needs immediate attention. This can be achieved by setting `subtitle_priority` to 1 for subtitles and `one_line_priority` to 0.5 for one-line prompts, with higher values indicating higher priority.

3. **Likely payoff**

   By prioritizing subtitles over one-line prompts, the system ensures that the wearer's primary focus remains on the conversation, reducing cognitive load and maintaining the low-friction experience essential for V1.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
