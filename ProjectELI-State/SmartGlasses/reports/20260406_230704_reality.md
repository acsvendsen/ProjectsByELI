# Reality Check

## Subtitle Clarity (Subtitle Placement)
### Feasible Now: **Subtitle placement on the side of the glasses, with minimal visual clutter and high contrast**.
- **Constraints**: Glasses should remain lightweight and socially acceptable; battery and thermal pressure are major risks for always-on features.
- **Implementation Grounding**: The current `TranscriptLab` app provides a good starting point. Early tests suggest that subtitles placed on the side of the glasses (e.g., near the ear) can be clear and unobtrusive without causing distraction.

## Memory Trust (Confidence Display)
### Feasible Now: **Implement confidence as a label with a short reason for uncertainty**.
- **Constraints**: The system should not pretend certainty; face/name recall must expose uncertainty clearly.
- **Implementation Grounding**: The `TranscriptLab` app can be adapted to show confidence levels. A simple label (e.g., "likely" or "uncertain") along with a brief explanation ("based on context," "familiar voice," etc.) would allow for clear and honest feedback.

## Low Friction Assistance (Visual Hierarchy)
### Feasible Now: **Design subtitles and one-line prompts to coexist without overloading the wearer**.
- **Constraints**: Display behavior should remain socially acceptable while still being readable in motion and noise.
- **Implementation Grounding**: The `TranscriptLab` app can simulate different visual hierarchies. Subtitles for live conversation could be larger and more prominent, while one-line prompts (e.g., "Did you mean...?" or "Name: [face]") could appear as smaller overlays or in a separate section.

## Frame-Touch Only V1 Interaction
### Feasible Now: **Ensure all interactions are through frame touches**.
- **Constraints**: V1 explicit interaction should happen through frame touches, not voice commands.
- **Implementation Grounding**: The `TranscriptLab` app can be designed to simulate frame-touch interactions. For example, the wearer could touch a specific area of the screen to toggle memory recall or prompt generation.

## Phone-First Runtime
### Feasible Now: **Heavy processing should primarily happen on the phone**.
- **Constraints**: Early versions should not depend on heavy on-glasses compute; glasses hardware remains simple in V1.
- **Implementation Grounding**: The `TranscriptLab` app can be configured to handle all heavy lifting, ensuring that the glass design is minimalistic and focused on real-time display.

## Core Deepening Over Sprawl
### Feasible Now: **Focus on improving subtitle quality, memory trust, and visual UX**.
- **Constraints**: Prefer work that improves subtitle quality, memory trust, and visual UX over broad feature expansion.
- **Implementation Grounding**: The `TranscriptLab` app can be iterated to improve these core areas. For example, refining the confidence display logic or optimizing subtitle placement.

## Privacy vs Usefulness
### Feasible Now: **Ensure memory support does not create corrupted recall**.
- **Constraints**: Memory support must expose uncertainty clearly and should not pretend certainty.
- **Implementation Grounding**: The `TranscriptLab` app can include tests to ensure that memory recall is accurate and reliable. For example, the system could mark new faces or names with a confidence level, indicating when the recall is uncertain.

## Latency vs Richness
### Feasible Now: **Prioritize real-time subtitle clarity over richer but slower processing**.
- **Constraints**: Subtitles must feel near-real-time or trust breaks; heavy on-glasses computation can lead to thermal and battery issues.
- **Implementation Grounding**: The `TranscriptLab` app can be configured to simulate real-time responses. For example, the system could prioritize streaming audio over complex background processing.

## Discreet UX vs Visual Clarity
### Feasible Now: **Design subtitles and prompts that are clear but unobtrusive**.
- **Constraints**: Display behavior should remain socially acceptable while still being readable in motion and noise.
- **Implementation Grounding**: The `TranscriptLab` app can be used to test different visual hierarchies. Subtitles for live conversation could be designed to fade out slightly, making them less obtrusive.

## V1 Real World Limits
### Feasible Now: **Glasses should remain lightweight and socially acceptable**.
- **Constraints**: Glasses should not depend on heavy on-glasses compute; early versions should rely heavily on phone processing.
- **Implementation Grounding**: The `TranscriptLab` app can be used to simulate different scenarios, ensuring that the glasses design remains minimalistic and unobtrusive.

## Current Unknowns
### Feasible Now: **Define subtitle placement and one-line prompt coexistence**.
- **Constraints**: Open questions include subtitle placement, prompt visual difference, and confidence format.
- **Implementation Grounding**: The `TranscriptLab` app can be iterated to address these unknowns. For example, the system could test different subtitle placements and prompt formats to find the best balance between clarity and unobtrusiveness.

## Summary
The current project inputs suggest that several features are feasible with the existing constraints:
- Subtitle placement on the side of the glasses.
- Confidence display as a label with a short reason.
- Low-friction assistance through visual hierarchy.
- Frame-touch interaction for explicit user control.
- Phone-first runtime to handle heavy processing.
- Core-deepening focus on subtitle quality and memory trust.

These features align well with the project's core mission of creating a discreet, context-aware personal assistant. The `TranscriptLab` app provides a robust framework for testing these elements in an early V1 iteration.
