### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain readable, stable, and unobtrusive, which is crucial for real-time clarity and trust in live conversations. By optimizing where subtitles appear on the frame, we can maintain the wearer's focus while ensuring the subtitles are easily visible.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence content (e.g., names and critical dialogue) that appears prominently at the bottom of the frame, and another for lower-confidence content (e.g., less important dialogue or background noise) that can be slightly smaller and positioned above the main subtitles.

3. **Likely payoff**

   This change will enhance the wearer's ability to follow conversations by ensuring key information is clearly visible while reducing visual clutter from less critical content. It will also help in maintaining the balance between clarity and social acceptability, which are core attractors for the project.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances trust by clearly communicating the system's certainty level to the wearer. A well-designed confidence label and short reason will help the wearer understand when they can rely on the subtitles or memory support, thereby reducing cognitive load and increasing overall user satisfaction.

2. **What small change unlocks it**

   Define a new confidence object that combines a numeric score with a descriptive label and a short reason. This format will provide clear feedback to the wearer about the reliability of the displayed information.

3. **Likely payoff**

   By implementing this improved confidence display, the system can better manage the user's expectations, leading to higher trust in both subtitle accuracy and memory support. This will result in more effective assistance without overwhelming the wearer with too much detail or uncertainty.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

Improving local memory thresholds can enhance trust in memory support by ensuring that critical information is reliably cached on the phone for fast lookup. This reduces dependency on cloud services, which can introduce latency and privacy concerns.

2. **What small change unlocks it**

Define a simple cache eviction policy where recently seen names and faces are kept in local memory, with less frequent interactions being evicted based on recency.

3. **Likely payoff**

This improvement will reduce the need for cloud fallbacks for name recall, leading to faster and more reliable memory support. It will also improve privacy by minimizing data sent to the cloud, as only infrequent or new information would be cached locally.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for which tasks run phone-local versus falling back to cloud, we ensure that V1 focuses on real-time performance and local processing constraints. This helps maintain trust by providing timely and reliable subtitle assistance while respecting battery and thermal limitations.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing.

3. **Likely payoff**

   By setting a clear cloud fallback rule, we can ensure that V1 provides high-quality, real-time subtitles without overloading the phone's battery and thermal resources. This will help maintain the wearer's trust in the product by delivering timely assistance while keeping resource usage in check.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
