# Reality Check

## Subtitle Placement: Feasible Now

### Current Considerations:
- **Constraint**: Frame-touch-only V1 interaction.
- **Implementation Grounding**: Current project focuses on phone-first runtime and live subtitle clarity.

### Assessment:
- Given the current constraint of frame-touch-only interactions, the subtitle placement must be easily discoverable through touch controls. The glasses should allow quick access to subtitles without requiring extensive visual scanning or complex gestures.
- Feasible now: Place subtitles in a prominent but non-distracting location that can be quickly accessed via a touch on the glasses' frame.

## Confidence Display: Feasible Later

### Current Considerations:
- **Core Deepening**: Focus on subtitle and memory improvements over generic confidence display decisions.
- **Implementation Grounding**: No specific code or design elements currently exist for confidence display.

### Assessment:
- While the core mission includes delivering clear, trustworthy subtitles, the current phase is focused more on subtitle clarity rather than diving deeply into confidence display mechanisms.
- Feasible later: Once subtitle placement and memory recall are well established, refine how confidence in memory (e.g., name and face recognition) is visually communicated. For now, prioritize subtitle clarity.

## Memory/Cache Policy: Feasible Now

### Current Considerations:
- **Core Deepening**: Focus on subtitle quality and memory trust.
- **Implementation Grounding**: Current work primarily involves real-time subtitle generation and minimal local processing on the glasses.

### Assessment:
- The initial focus should be on ensuring that names, faces, and prior context are stored securely and can be quickly recalled during live interactions.
- Feasible now: Implement a basic cache policy where recently seen faces and names are stored locally on the phone for fast lookup. This can be refined as more data is collected.

## Phone/Cloud Boundary: Feasible Now

### Current Considerations:
- **Core Deepening**: Bias toward phone-first processing.
- **Implementation Grounding**: The current `TranscriptLab` app focuses on real-time transcript generation and partial/final speech handling entirely on the phone.

### Assessment:
- Given that V1 is phone-first, the boundary between phone and cloud should be kept minimal for simplicity and early adoptability.
- Feasible now: Ensure that all processing, including speech recognition and context management, happens on the phone. Use the cloud only where it clearly adds value (e.g., model updates).

## Visual Hierarchy: Feasible Now

### Current Considerations:
- **Core Deepening**: Focus on subtitle clarity.
- **Implementation Grounding**: The `TranscriptLab` app provides a framework for testing live transcripts.

### Assessment:
- For V1, the primary goal is to ensure that subtitles are clear and stable. The visual hierarchy should be designed to support this primary function without overwhelming the wearer.
- Feasible now: Design a simple subtitle layout that remains readable in motion while being unobtrusive. Use the `TranscriptLab` app to iterate on this design.

## Summary of Findings

### Feasible Now
- **Subtitle Placement**: Place subtitles in a prominent but non-distracting location.
- **Memory/Cache Policy**: Implement basic local caching for names and faces.
- **Phone/Cloud Boundary**: Keep processing localized to the phone.
- **Visual Hierarchy**: Design simple, readable subtitle layouts.

### Feasible Later
- **Confidence Display**: Refine how confidence in memory is visually communicated after core features are well established.

### Likely Waste of Time
- No suggestions fall into this category based on current priorities and constraints.
