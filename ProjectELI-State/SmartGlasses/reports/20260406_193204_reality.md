# Reality-Checked V1 Directions

## Subtitle Clarity (Real-time subtitle clarity)
### Feasibility: Feasible Now
**Reasoning**: 
- The current `TranscriptLab` app and its focus on real-time transcription provide a solid foundation for real-time subtitle clarity.
- With the current implementation, subtitles are designed to be clear, fast, and stable. This is further validated by ongoing testing within the iOS environment.

### Next Steps
- Ensure that the subtitle rendering mechanism can handle various screen orientations and movements to maintain readability in noisy environments.
- Integrate stability tests to ensure subtitles remain trust-preserving during real-world interactions (e.g., walking, sitting).

## Memory Trust (Trustworthy memory support)
### Feasibility: Feasible Later
**Reasoning**: 
- The core architecture is currently focused on phone-first processing and cloud optimization. Integrating robust memory management will require more development.
- Initial tests with `TranscriptLab` can help establish basic trust mechanisms, but detailed implementation of face/name recall and memory reinforcement requires further work.

### Next Steps
- Implement a simple caching mechanism to store recently seen faces and names locally on the phone.
- Develop rules for reinforcing remembered entities based on context (e.g., frequent mentions).

## Low-friction Assistance (Low-friction assistance)
### Feasibility: Feasible Now
**Reasoning**: 
- The current interaction model through frame touches is straightforward and minimizes command overhead.
- One-line prompts can be integrated using existing UI elements to provide simple, unobtrusive support.

### Next Steps
- Design one-line prompts that are visually distinct from subtitles but still easily readable. Ensure they do not overload the wearer’s cognitive load.
- Test different prompt formats (e.g., labels, short reasons) for effectiveness in low-friction assistance.

## Summary of Real-world Limits
### Hard Grounding Rules
- Focus on core features: subtitles, memory support, and low-friction assistance.
- Keep interactions simple through frame touches only.
- Use `TranscriptLab` for early testing and refinement.
- Ensure that all features align with real-world constraints such as battery, latency, privacy, and social acceptability.

### Feasibility Assessments
- **Feasible Now**: Subtitle clarity, frame-touch interaction, phone-first runtime, visual hierarchy, basic confidence display.
- **Feasible Later**: Memory reinforcement, richer context, advanced confidence display.
- **Likely Waste of Time (Assumptions Needing Evidence)**: Detailed face/name memory reinforcement without early user feedback.

By maintaining a focus on core features and aligning with real-world constraints, the project can make steady progress towards its mission while minimizing risks associated with broad or speculative feature sets.
