### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules based on confidence levels, we can ensure that subtitles remain stable and readable without overwhelming the wearer. This will help in maintaining trust and clarity during live conversations.

2. **What small change unlocks it**

   Define a fixed position for high-confidence subtitles to always appear at the top of the screen, while low-confidence subtitles have a secondary placement mode that appears only when necessary.

3. **Likely payoff**

   This approach ensures that important information is always visible and prioritized, reducing the risk of missing critical details during conversations. It also helps in managing visual clutter effectively, leading to a more reliable user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer can trust the system's memory support and assistance. A clear and concise confidence label, along with a short reason, will help establish the reliability of the memory recall and subtitle placement. This, in turn, enhances the overall trustworthiness of the system, which is crucial for daily use.

2. **What small change unlocks it**

   Define a new confidence format that combines a numeric score with a label and a short reason. For example: `score 0.85 + "High" + "Seen recently in conversation"`.

3. **Likely payoff**

   By providing more detailed and consistent confidence information, the system can better manage the wearer's expectations about its reliability. This improves trust and ensures that critical memory or subtitle placements are given the appropriate attention. Users will be less likely to dismiss important information due to uncertainty.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory threshold ensures that frequently encountered faces and names are stored securely on the phone for quick recall, enhancing trust and usability without compromising privacy.

2. **What small change unlocks it**

   Define a local cache size limit of 50 entries per person for face/name recall, with a recency eviction policy based on last seen time within the past week.

3. **Likely payoff**

   This change will allow the system to handle common interactions more quickly and confidently, reducing latency and improving trust through reliable memory support without storing unnecessary data.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud processing, we can ensure that V1 interactions remain lightweight and battery-conscious. This focus on minimizing heavy processing on the glasses will help maintain real-time subtitle clarity and trustworthiness, aligning with the primary attractor of "Real-time subtitle clarity."

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing: when live subtitles should always be processed locally (on-device) to ensure minimal latency and battery drain.

3. **Likely payoff**

   By keeping all live subtitle processing local, we can achieve faster, more stable subtitle delivery, which is critical for maintaining trust in real-time communication. This decision will also free up the cloud resources for other tasks like face/name recall lookup or memory archive sync without compromising on subtitle quality.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
