### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a fixed subtitle placement rule that ensures subtitles remain in a consistent position regardless of confidence levels, we can reduce visual distraction and improve the wearer's trust in the system. This stability allows for better focus during conversations, enhancing overall understanding without overwhelming the wearer with rapid repositioning.

2. **What small change unlocks it**

   Introduce a new constant in the codebase that sets a default subtitle placement mode to "fixed" rather than allowing dynamic changes based on confidence levels. This can be achieved by setting a configuration flag such as `FIXED_SUBTITLE_PLACEMENT`.

3. **Likely payoff**

   Implementing fixed subtitle placement will help reduce visual clutter and distraction, making the subtitles more reliable and easier for the wearer to follow. This stability will enhance trust in the system's performance during live conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a numeric score alongside a label and short reason, we can enhance the trustworthiness of the system in real-time interactions. This will help users understand the reliability of the information being provided and make more informed decisions about when to act on the assistant's suggestions.

2. **What small change unlocks it**

   Modify the confidence display format in V1 to include a numeric score (e.g., 0.84) alongside the label (e.g., "High") and a short reason (e.g., "Seen recently"). This can be done by updating the `TranscriptLabRootView.swift` and ensuring it is reflected in the `TranscriptLabModel.swift`.

3. **Likely payoff**

   Implementing this change will provide users with more concrete information about the reliability of the subtitles and memory support, enhancing their trust in the system. This transparency can lead to better engagement and usage, as users are more likely to rely on the assistant when they understand its level of certainty.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By refining the local memory cache policy to prioritize recently interacted individuals, the system ensures that critical names and faces are quickly accessible during live conversations. This reduces the likelihood of context loss and enhances the wearer's ability to recall important interactions without relying heavily on cloud processing or voice commands.

2. **What small change unlocks it**

   Define a local cache size limit for people and names based on recent interaction history, ensuring that frequently encountered individuals are always stored locally. This can be achieved by setting a threshold (e.g., last 10 encounters) beyond which less recently interacted entities are evicted from the cache.

3. **Likely payoff**

   Implementing this local cache policy will improve the system's responsiveness and reliability during live conversations. By keeping frequently encountered individuals in local memory, the system can provide faster, more accurate name recall without burdening the cloud or requiring additional voice interactions. This will enhance user trust and reduce cognitive load.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary between what stays phone-local and what falls back to cloud for live subtitle processing, we ensure that subtitles remain fast, reliable, and low-latency. This helps maintain the real-time clarity attractor while reducing battery drain and ensuring continuous and stable subtitle delivery.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing should always stay on-device (phone-local). For instance, set a rule that any subtitle data that requires immediate display and cannot tolerate latency should be processed locally before any fallback to the cloud.

3. **Likely payoff**

   By keeping subtitle processing phone-local, we can ensure real-time delivery of subtitles without introducing delays from cloud processing. This will enhance the user experience by maintaining clarity and stability in live conversation, which is crucial for the core attractor of "Real-time subtitle clarity."

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can easily read and understand critical information without being overwhelmed by too much text on screen. This enhances clarity and reduces cognitive load, which is crucial for maintaining the wearer's focus during interactions.

2. **What small change unlocks it**

   Define a visual priority rule that gives higher precedence to subtitles when both are active, but allows one-line support to show briefly if necessary. For example, subtitles should always be shown prominently with larger font size and duration, while one-line prompts can appear in a smaller font or as a brief overlay on the side.

3. **Likely payoff**

   By ensuring that subtitles remain prominent, the wearer will have a stable reference point during conversations, reducing misunderstandings and improving overall comprehension. This clarity also helps to maintain trust in the system's reliability, especially in noisy environments where accuracy is critical.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
