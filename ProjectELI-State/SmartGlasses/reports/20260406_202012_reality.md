# Reality Check for SmartGlasses V1 Direction

## Subtitle Clarity

### Current Open Question: 
- **Subtitle Placement and Visual Hierarchy**: What is the best subtitle placement and visual hierarchy for fast reading with low distraction?

### Decision Area: Subtitle Placement and Visual Hierarchy
- **feasible now**
  - The glasses should focus on clear, fast, and stable subtitles. Given that current hardware can support a simple text display, the placement needs to be strategic.
    - **Top of Frame**: Placing subtitles at the top or side of the frame might minimize occlusion but could introduce visual distractions in motion.
    - **Bottom of Frame**: Placing subtitles at the bottom minimizes occlusion and distraction but may require careful design for readability.
  - Given V1 interaction is frame-touch only, ensuring subtitle placement does not interfere with user comfort should be a primary consideration.
- **Assumptions Needing Evidence**
  - The exact visual hierarchy needs empirical testing to determine what works best in real-world scenarios. This can be done through A/B testing using the `TranscriptLab` app.

## Memory Trust

### Current Open Question: 
- **Memory/Cache Policy**: How should face/name memory be stored and reinforced for fast lookup and trust?

### Decision Area: Memory/Cache Policy
- **feasible now**
  - Initial implementation can focus on remembering new faces and names automatically based on context, with explicit remember-touch behavior as a reinforcement mechanism.
    - **Automatic Memory Storage**: New people and names should be remembered by default when supported by context. This leverages existing phone-side processing capabilities.
    - **Reinforcement Rules**: Explicit remember-touch behavior can be used to prioritize certain memories or reinforce weaker ones.
- **Assumptions Needing Evidence**
  - The reliability of automatic memory storage versus explicit touch-based reinforcement needs empirical validation through real-world use cases.

## Low-Friction Assistance

### Current Open Question: 
- **Confidence Display**: How should confidence be represented: numeric score, label, and short reason?

### Decision Area: Confidence Display
- **feasible now**
  - Confidence display should focus on providing clear, actionable feedback to the user.
    - **Label Only**: A simple "likely" or "unlikely" might suffice for initial implementation. This can be refined later based on user feedback.
    - **Label + Short Reason**: Adding a brief reason could provide more context without overwhelming the wearer. For example: "Likely, seen at event X."
- **Assumptions Needing Evidence**
  - The best confidence format should be determined through user testing and iterative refinement using the `TranscriptLab` app.

- **Assumptions Needing Evidence**
  - The practicality of different cloud-based services should be tested using the `TranscriptLab` app to ensure minimal impact on battery life and user experience.
