### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles are always clear and visible enough to be trusted in live conversations while minimizing distraction.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence cases where precise placement is less critical, and another for low-confidence cases where the subtitle should be placed more prominently to ensure clarity.

3. **Likely payoff**

   This approach will enhance user trust in real-time subtitles during conversations by ensuring that crucial information is always visible without overwhelming the wearer with too many subtitles at once. It also supports the core attractor of "real-time subtitle clarity."

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display through a more precise label, short reason format, and numeric score can enhance the wearer's trust in the system’s memory and subtitle accuracy. This clarity helps the wearer understand when they should rely on the system and when to seek confirmation or additional context.

2. **What small change unlocks it**

   Define a specific confidence format that combines a numeric score with a label and a short reason, ensuring the format is concise yet informative. For example: "score 0.85 + 'High' + 'Seen recently'; score 0.43 + 'Low' + 'Weak match'; score 0.62 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   By providing clear and concise confidence information, the wearer can better trust the system’s memory and subtitles. This clarity reduces uncertainty and enhances the overall user experience by making the system's decisions more transparent.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size for memory objects ensures that frequently referenced people, names, and topics are readily available to the wearer without needing cloud assistance. This reduces latency and ensures trust by providing quick access to relevant context.

2. **What small change unlocks it**

   Define a local cache threshold of 10 most recently seen entities per category (people, places, objects) that are stored in phone memory with a recency-first eviction policy.

3. **Likely payoff**

   By caching the most frequently referenced entities locally, we can significantly reduce the number of times the wearer needs to rely on cloud processing for recall, leading to faster response times and higher trust in the system's ability to support real-time interactions.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains local on the phone allows for faster, more stable performance, which is crucial for maintaining real-time clarity and trust in noisy environments. This focus on local processing also respects the battery and thermal constraints of the glasses while ensuring that the subtitles are always up-to-date without the latency introduced by cloud connections.

2. **What small change unlocks it**

   Define a clear boundary where live subtitle processing stays entirely phone-local, with only transcript cleanup tasks falling back to the cloud if necessary. This can be achieved by setting a local cache threshold for name recall and face recognition that triggers a fallback to the cloud when memory is too strained.

3. **Likely payoff**

   By keeping subtitle processing on the phone, we ensure that subtitles remain fast, clear, and reliable in real-time scenarios. This improves trust and usability for the wearer, especially in critical conversations where misread or delayed subtitles could be detrimental. Additionally, this local-first approach reduces battery drain and thermal load on the glasses.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that the wearer can focus on essential information without being overwhelmed by secondary details. This improves the overall user experience and reduces cognitive load, aligning with the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define a visual priority rule where subtitles are always displayed prominently while one-line support is shown in a smaller, less intrusive format that coexists without overlapping or distracting from the subtitles.

3. **Likely payoff**

   This small change will make the SmartGlasses more effective and user-friendly by ensuring that critical information (subtitles) remains highly visible and readable, while supplementary information (one-line prompts) is presented in a way that does not disrupt the main focus of the wearer's attention.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
