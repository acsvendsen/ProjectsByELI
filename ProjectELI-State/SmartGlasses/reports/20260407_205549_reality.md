# Reality Check for SmartGlasses

## Subtitle Clarity: Feasible Now
- **Summary**: Keep subtitles clear, fast, and stable enough that the wearer can trust them in live conversation.
- **Assessment**: Given that `TranscriptLab` is already testing live microphone capture and partial/final transcript behavior on a real device (iPhone), it is feasible to implement basic subtitle clarity now. The build summary indicates successful tests, which support this feasibility.
- **Constraints**: Early hardware remains simple: display text, record audio/visual input; phone/cloud handles heavy processing.
- **Decision Area**: Implementation Grounding

## Memory Trust: Feasible Later
- **Summary**: Remember names, faces, and prior context without pretending certainty or creating corrupted recall.
- **Assessment**: While the implementation groundwork for memory trust (e.g., confidence behavior) is not yet complete, it is feasible to start laying the foundation. The current mode `Core Deepening` emphasizes improving subtitle quality and confidence, which aligns with building a trustworthy memory system later.
- **Constraints**: Privacy vs usefulness; Rich context vs low-latency response
- **Decision Area**: Core Deepening

## Low-Friction Assistance: Feasible Now
- **Summary**: Deliver one-line help and visible support without creating command overhead or social awkwardness.
- **Assessment**: The current mode `Core Deepening` prioritizes subtitle quality, memory trust, and visual UX improvements. Implementing basic low-friction assistance (e.g., one-line prompts) is within the scope of this mode.
- **Constraints**: Frame-touch-only V1; Phone-first runtime
- **Decision Area**: Core Deepening

## Privacy vs Usefulness: Likely Waste of Time
- **Summary**: Privacy vs usefulness
- **Assessment**: While it is critical to balance privacy and usefulness, focusing on core mission priorities (subtitle clarity, memory support) should be the immediate focus. Addressing privacy concerns too early may distract from more urgent issues.
- **Constraints**: Always-on sensing vs battery and thermals; Rich context vs low-latency response
- **Decision Area**: Constraint Pressure
