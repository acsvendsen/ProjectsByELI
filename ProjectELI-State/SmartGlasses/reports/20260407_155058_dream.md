### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement enhances the wearer's trust in the system during live conversations. By maintaining consistent and reliable subtitle positioning, the system can ensure that subtitles remain readable and unobtrusive, thereby improving the overall assistive experience.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule for different confidence states. For example, place subtitles at the bottom of the frame with higher confidence (0.9+) and slightly less prominent but still visible placements (e.g., top-center) with lower confidence (0.7-0.8).

3. **Likely payoff**

   By implementing a clear and consistent subtitle placement rule based on confidence levels, the system can ensure that subtitles are always readable without being distracting. This will enhance trust in the system’s reliability during live conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format in V1 will enhance the trustworthiness of both subtitle placement and memory support. By clearly showing certainty levels, the system can avoid creating false impressions of understanding or memory, thus maintaining the wearer's confidence without overloading them with too much information.

2. **What small change unlocks it**

   Define a simple numeric score format combined with a label and short reason for confidence objects. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format provides a clear, concise representation of the system's certainty without overwhelming the wearer.

3. **Likely payoff**

   A well-designed confidence display can significantly improve user trust by making it clear when the system is uncertain or has only weak evidence for its claims. This will reduce social awkwardness and ensure that the wearer understands the reliability of each piece of assistance provided, leading to a more effective and less intrusive experience.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache threshold for face/name memory helps ensure that relevant memories are readily accessible to the wearer without overburdening the system with too much data, thus maintaining a balance between rich memory support and fast lookup.

2. **What small change unlocks it**

   Define a specific local cache size limit for storing recently seen faces and names on the phone, ensuring that only the most relevant memories are retained locally.

3. **Likely payoff**

   By setting an optimal local cache threshold, the system can provide faster memory recall with reduced latency and improved trust in the wearer's ability to accurately remember previously encountered individuals or conversations. This also helps manage battery usage by reducing frequent cloud requests for data that is already locally cached.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what stays phone-local versus falling back to cloud processing, we ensure that critical real-time subtitle rendering and memory lookup remain fast and reliable, enhancing the wearer's trust in the system without overloading the device or compromising privacy.

2. **What small change unlocks it**

   Define a single task-specific boundary where live subtitle processing remains fully local on the phone until it reaches a certain complexity threshold, after which cloud fallback is triggered for richer analysis but not real-time generation.

3. **Likely payoff**

   This refined boundary will ensure that subtitles remain clear and stable in real-time, enhancing the wearer's trust, while also allowing for more robust memory lookup without overloading the local device, thus balancing performance and privacy effectively.

4. **Immediate next probe**
   - Define the phone/cloud fallback boundary for live subtitle processing, ensuring that cloud fallback occurs only after a certain complexity threshold is met during real-time generation.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that key information is prioritized for fast reading while minimizing distractions. This improves the overall user experience by keeping the wearer's focus on essential content without overwhelming them with too much text.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles are always visible and take precedence over one-line support, which is displayed only when space permits and does not interfere with subtitle readability.

3. **Likely payoff**

   This simple visual hierarchy will enhance the clarity of real-time subtitles during live conversations, making them more reliable for the wearer. It will also prevent the one-line support from becoming a distraction, thus maintaining the primary focus on understanding spoken words.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
