### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we ensure that subtitles remain readable and unobtrusive while still providing clear support when needed. This improves the wearer's ability to follow conversations without feeling overwhelmed or distracted.

2. **What small change unlocks it**

   Define three subtitle placement modes: fixed at the bottom of the frame, slightly above center for medium confidence, and fixed top-center with a brief fade-in for high confidence. Implement these rules in the V1 subtitle rendering logic.

3. **Likely payoff**

   This approach will enhance the wearer's trust in the system by providing clear, unobtrusive subtitles that are easy to follow. It balances readability with minimal distraction, ensuring the core mission of making conversations easier to understand is met without overloading the user.

4. **Immediate next probe**
   - Define the fixed position for subtitles as the bottom of the frame.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to clearly show certainty levels along with a concise reason, the system can enhance user trust in both subtitles and memory support. This clarity helps users understand when they can rely on the assistive features, which is critical for maintaining engagement and effective use.

2. **What small change unlocks it**

   Define a new confidence format that combines a numeric score (e.g., 0.84) with a label (e.g., "High") followed by a short reason (e.g., "Seen recently").

3. **Likely payoff**

   Users will have a better understanding of the system’s certainty, leading to increased trust and more accurate use of both subtitle and memory support features. This can significantly improve the overall user experience without adding complexity.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds allows for faster and more reliable recall of names and faces during conversations. By setting a clear threshold for when to cache new memories locally, we ensure that critical information is available quickly without overloading the system or relying heavily on cloud resources.

2. **What small change unlocks it**

   Define a recency-based local cache policy where new people and names are cached with a high confidence score if seen within the last 10 minutes. This ensures that recent encounters are prioritized for fast recall, reducing latency during critical moments of conversation.

3. **Likely payoff**

   By implementing this recency-based caching, we can significantly reduce the time it takes to recall new names and faces, enhancing the overall trustworthiness and utility of the memory support feature. This improvement will help in real-world scenarios where fast recognition is crucial for effective communication.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus what falls back to the cloud, we can ensure that critical real-time subtitle processing happens locally, maintaining trust and reducing latency. This focus helps the wearer understand better in noisy environments by providing timely, reliable subtitles without battery-draining heavy computation.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing as running phone-local with minimal fallback to cloud. For example, set a rule that any live subtitle rendering and basic confidence display must be done on the phone's local runtime, with only complex or historical data needing a cloud fallback.

3. **Likely payoff**

   This change will reduce battery drain by offloading less critical tasks such as memory recall and transcript cleanup to the cloud when necessary. It ensures that subtitles remain clear and fast, maintaining the wearer's trust in the system during live interactions. By focusing on local subtitle processing, we can also ensure lower latency, which is crucial for real-time assistance.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are stable and clear in real-time interactions helps maintain the wearer's trust and understanding. By focusing on subtitle placement rules, we can prevent distracting movement or flickering that might break concentration during conversations.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules for different confidence states: high-confidence text always visible, medium-confidence text in a less intrusive area, and low-confidence text as a subtle alert only appearing on specific interactions.

3. **Likely payoff**

   By setting clear, stable subtitle placement rules, the wearer can rely more on the subtitles during conversations, enhancing their understanding without being distracted by frequent changes or unneeded information. This improves the overall user experience and trust in the system.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
