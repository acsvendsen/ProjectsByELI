# Consolidated Signals for SmartGlasses V1

## Core Mission
- Create discreet, context-aware personal assistance through live subtitles, face/name recall, conversation memory, and one-line support.
- Focus on real-time subtitle clarity, trustworthy memory support, and low-friction assistance.

## Core Attractors (Strength: High)
1. **Subtitle Clarity** - Keep subtitles clear, fast, and stable enough that the wearer can trust them in live conversation.
2. **Memory Trust** - Remember names, faces, and prior context without pretending certainty or creating corrupted recall.
3. **Low-Friction Assistance** - Deliver one-line help and visible support without creating command overhead or social awkwardness.

## Core Tensions (Pressure: High)
1. **Privacy vs Usefulness** - Helpful assistive behavior should not quietly slide into invasive capture or retention.
2. **Latency vs Richness** - The system should provide timely help without overloading the runtime with richer but slower processing.
3. **Discreet UX vs Visual Clarity** - Display behavior should remain socially acceptable while still being readable in motion and noise.

## Core Constraints (Type: Hard)
1. **Frame-Touch-Only V1 Interaction**: V1 explicit interaction should happen through frame touches, not voice commands.
2. **Phone-First Runtime**: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.
3. **Core-Deepening Over Sprawl**: Prefer work that improves subtitle quality, memory trust, and visual UX over broad feature expansion.

## Current Mode (Active Mode)
- **Core Deepening**: Bias toward subtitle, memory, confidence, and architecture improvements that increase daily-use value.

## Real-World Limits
1. **Battery and Thermals**: Major risks for always-on features.
2. **Subtitles Must Feel Near-Real-Time**: Trust breaks otherwise.
3. **Face/Name Recall Must Expose Uncertainty Clearly**.
4. **First Versions Rely Heavily on Phone Processing**: Preserve a path to stronger capability later.

## Interaction Constraints
- V1 should not depend on voice activation or spoken user commands for controlling the glasses.
- User control should happen through frame touches only.

## Open Questions and Tensions

- What confidence format builds trust best: label only, label + short reason, or score + label?
- How much face/name memory should be cached locally on the phone?
- Which interactions should work offline versus requiring cloud support?

### Core Tensions
1. **Fast Enough Subtitles vs Battery Drain**
2. **Helpful Memory vs Privacy Perception**
3. **Strong Assistance vs Low Social Friction**
4. **Rich Context vs Low-Latency Response**
