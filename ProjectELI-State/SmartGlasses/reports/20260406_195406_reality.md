# Reality Check for SmartGlasses V1 Direction

## Core Attractors

### Real-time Subtitle Clarity - **feasible now**
- **Reasoning**: The current architecture (phone-first) and available technology should allow for real-time subtitles that are clear, fast, and stable enough to be trusted in live conversation. Initial tests with `TranscriptLab` can provide a baseline.
- **Constraints**: Latency must remain low; confidence in the subtitle system is crucial.

### Trustworthy Memory Support - **feasible later**
- **Reasoning**: Implementing context-aware memory support (e.g., remembering names and faces) will require more advanced algorithms and possibly cloud processing, which can be phased in after initial V1 release.
- **Constraints**: Privacy perception and the reliability of fast lookups are significant concerns that need to be addressed.

### Low-friction Assistance - **feasible now**
- **Reasoning**: One-line prompts and support can be implemented with minimal UI overhead. The focus should remain on low-friction interaction, which aligns with the frame-touch-only V1 constraint.
- **Constraints**: Ensure that one-line support does not overwhelm the user interface.

## Tensions

### Privacy vs Usefulness - **feasible now**
- **Reasoning**: Initial implementation can avoid invasive data capture. The system should focus on providing useful information without overstepping privacy boundaries.
- **Constraints**: Early designs must respect user privacy; any memory or context retention should be clearly communicated and opted into.

### Latency vs Richness - **feasible now**
- **Reasoning**: Core functionality (subtitles, basic memory) can be implemented with minimal latency. The system should prioritize real-time performance to maintain trust.
- **Constraints**: Subtitle quality must remain high; any additional features that increase complexity will need careful balancing.

### Discreet UX vs Visual Clarity - **feasible now**
- **Reasoning**: Initial designs should focus on a discreet UI with clear and readable subtitles. The system can be refined as more user data is gathered.
- **Constraints**: Avoid overwhelming the wearer with too many visual elements; prioritize readability and clarity.

## Constraints

### Frame-touch-only V1 - **hard constraint**
- **Reasoning**: This is explicitly stated in the V1 guardrails, so it must be adhered to. No voice commands or spoken commands should be proposed.
- **Constraints**: Interaction design must strictly follow this rule.

### Phone-first Runtime - **hard constraint**
- **Reasoning**: The system will primarily rely on the phone for heavy processing, with cloud support optional. This ensures early versions remain simple and reliable.
- **Constraints**: Avoid overcomplicating local processing unless it clearly adds value.

## Core-deepening Over Sprawl - **feasible now**
- **Reasoning**: Focus should be on improving subtitle quality, memory trust, confidence display, and low-friction visual UX rather than broad feature expansion.
- **Constraints**: Ensure any new features contribute directly to the core mission without diluting focus.

### Memory/Caching Policy
- **Feasibility**: Feasible now; initial caching policies can be simple, focusing on essential data. More advanced strategies can be explored later based on user feedback and performance testing.

### Confidence Display
- **Feasibility**: Feasible now; basic confidence indicators can be implemented to provide users with a sense of reliability without overcomplicating the UI.

### Phone/Cloud Boundary
- **Feasibility**: Feasible now; initial design should focus on minimizing cloud dependency while ensuring core functionality remains robust. 

### Visual Hierarchy
- **Feasibility**: Feasible now; initial designs should prioritize clear and unobtrusive placement of subtitles to ensure they do not distract from the conversation.

## Assumptions Needing Evidence

- The assumption that the system can provide reliable real-time subtitles without significant battery drain is supported by early tests with `TranscriptLab`.
- The assumption that users will find one-line prompts helpful while keeping them non-intrusive needs to be validated through user testing.
- The assumption that memory support can be implemented in a way that respects privacy and avoids creating corrupted recall requires further exploration.

## Summary

The current direction is feasible for the initial V1 release, focusing on real-time subtitles, basic memory support, and low-friction interaction. Core improvements should prioritize subtitle quality, confidence display, and memory trust while maintaining strict adherence to the V1 constraints. Early user testing will be crucial to validate these assumptions and ensure the system meets its core mission goals.
