### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a specific subtitle placement rule based on confidence state, we can ensure that subtitles are always visible yet unobtrusive. This improves the wearer's trust in real-time understanding and ensures that critical information is not missed during conversations.

2. **What small change unlocks it**

   Define one subtitle placement rule for high-confidence states (e.g., when a face or name has been seen multiple times) where subtitles are placed at the bottom of the field of view, and another for lower confidence states (e.g., first encounters or less certain identifications), where subtitles might be slightly more prominent but still unobtrusive.

3. **Likely payoff**

   This small change will help maintain a balance between ensuring critical information is seen without overwhelming the wearer's attention. It will also reinforce trust by consistently showing relevant information at key moments, enhancing the overall user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display helps ensure that the wearer can trust the subtitles and memory support provided by the glasses. A clear and reliable confidence indication will reduce uncertainty, enhance user trust, and make the system more useful in real-world interactions.

2. **What small change unlocks it**

   Define a simple confidence format for V1 that includes a numeric score, a label (like "High", "Medium", or "Low"), and a short reason (e.g., "Seen recently," "Weak match"). This format will provide the wearer with a clear understanding of the system's certainty about the information being displayed.

3. **Likely payoff**

   By implementing this confidence format, users will be better equipped to understand when they can trust the subtitles or memory support. This increased clarity and trust will make the glasses more reliable in noisy environments and during complex conversations, thereby enhancing the overall user experience.

4. **Immediate next probe**
   - Define the numeric score for the confidence display format in V1.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By optimizing local memory thresholds for new-person recall, we can ensure that likely new faces and names are remembered with high confidence, while less relevant information is discarded to maintain fast lookup performance. This improves trust by providing reliable support without overwhelming the wearer with too much context.

2. **What small change unlocks it**

   Define a simple entity-linking rule for attaching new evidence to an existing person-memory object based on recent encounters and confidence scores. This ensures that every time someone is seen or mentioned, their memory object is updated, reinforcing recognition over time.

3. **Likely payoff**

   Implementing this rule will reduce the likelihood of forgetting new people, enhancing the wearer's ability to recall names and faces accurately during conversations. This pays off by improving the overall trust in the system’s name recall capabilities, making it a more reliable tool for social interactions.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific phone/cloud boundary for live subtitle processing, we ensure that critical real-time subtitle generation remains local to reduce latency and preserve battery life. This focus on early V1 constraints helps maintain trust and usability while surfacing the practical limits of on-device processing.

2. **What small change unlocks it**

   Define one clear task-specific cloud fallback boundary: for live subtitle processing, only fall back to the phone when the glasses are offline or if real-time accuracy cannot be maintained locally.

3. **Likely payoff**

   By localizing live subtitle processing, we can ensure that subtitles remain stable and timely even in low-bandwidth situations. This improves trust and understanding without compromising on the core real-time subtitle mission.

4. **Immediate next probe**

   Define one clear task-specific cloud fallback boundary: for live subtitle processing, only fall back to the phone when the glasses are offline or if real-time accuracy cannot be maintained locally.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By refining the visual hierarchy to prioritize subtitles over one-line support, we ensure that the wearer's primary focus remains on understanding live conversations. This improves subtitle clarity and reduces cognitive load by minimizing distractions from less critical information.

2. **What small change unlocks it**

   Define a clear subtitle-vs-one-line priority rule: For high-confidence situations, show only subtitles; for medium-confidence situations, show both subtitles and one-line support with subtitles taking precedence; for low-confidence situations, hide one-line support to prevent visual clutter.

3. **Likely payoff**

   This refined hierarchy will enhance the wearer's focus on critical information during real-time interactions, leading to better understanding and reduced cognitive strain. It also ensures that the primary assistive feature (subtitles) remains unobtrusive while still providing necessary contextual support when needed.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
