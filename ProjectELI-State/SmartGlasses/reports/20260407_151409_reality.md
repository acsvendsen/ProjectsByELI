# Reality Check Summary

## Subtitle Placement: Feasible Now
- **Subtitle Placement**: The glasses should place subtitles where they can be easily read but do not distract the wearer. Given the current focus on real-time clarity, the subtitle placement must balance readability and non-intrusiveness. **Feasible now**, as this decision can be made based on early testing with the `TranscriptLab` app.

## Confidence Display: Feasible Now
- **Confidence Display**: Implementing a confidence label (e.g., "High," "Medium," or "Low") is feasible now because it aligns with the current `core_deepening` mode and can be iterated on in subsequent versions. This approach respects the simplicity constraint of V1 interaction through frame touches.

## Memory/Cache Policy: Feasible Now
- **Memory/Caching**: Caching face/name memory locally for fast lookup is feasible now, as it aligns with the `memory_trust` attractor and the current architecture direction (phone-first). This can be implemented using the existing phone-side transcript plumbing from `TranscriptLab`.

## Phone/Cloud Boundary: Feasible Now
- **Phone/Cloud**: The initial implementation should primarily leverage the phone for heavy processing, making use of cloud services only where clearly justified. This aligns with the current mode's focus on core deepening and simplicity.

## Visual Hierarchy: Feasible Later
- **Visual Hierarchy**: Determining the best subtitle placement within a visual hierarchy requires more detailed UI design and testing. This decision can be made later once the basic functionality is in place, ensuring that the initial V1 focus remains simple.

## Likely Waste of Time
- **Automatic Memory Support vs Confidence and Correction Safety**: While enhancing memory support is important, focusing on confidence and correction safety first is more pressing given the current constraints. The initial implementation should not assume perfect recall; instead, it should provide a clear indication of certainty.

## Feasible Now/Feasible Later
- **Subtitle Clarity and Memory Trust**: These attractors are core to the project's mission and can be addressed through iterative improvements. Implementing basic functionality now while planning for richer support later is feasible.
  
## Assumptions Needing Evidence
- **Interaction Through Frame Touches Only**: While this constraint is critical, early implementation should not assume specific interaction patterns beyond frame touches. More testing is needed to refine how these interactions manifest in practice.

## Summary of Feasibility
- **Subtitle Placement and Confidence Display** are feasible now.
- **Memory/Caching** can be implemented now but needs further refinement.
- **Phone/Cloud Boundary** should follow the current architecture direction.
- **Visual Hierarchy** is a later decision that depends on V1 functionality.
- Enhancing subtitle clarity and memory trust are ongoing priorities.

By focusing on these specific areas, the project can make meaningful progress while adhering to the core mission and constraints.
