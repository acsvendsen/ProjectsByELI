# Reality-Check Analysis

## Subtitle Placement: Feasible Now
- **Current Status:** V1 is frame-touch only.
- **Feasibility:** Given the frame-touch-only interaction, subtitle placement should focus on clarity and minimal distraction. A bottom-center display (away from the wearer's field of vision) with a small size that can be quickly read is feasible now. This avoids blocking the wearer's view while ensuring subtitles are visible during interactions.

## Confidence Display: Feasible Now
- **Current Status:** Confidence needs to be represented but not overwhelming.
- **Feasibility:** A simple label like "high", "medium", or "low" confidence with a brief explanation can be implemented now. This should be in a small, non-distracting area near the subtitle text. For example:
  - **Subtitle:** "Meeting start"
  - **Confidence Display:** [high: meeting_start_confidence_icon]

This keeps the UI clean and ensures the wearer is aware of reliability without overwhelming them.

## Memory/Cache Policy: Feasible Later
- **Current Status:** Face/name memory caching on the phone.
- **Feasibility:** Implementing a basic cache policy to store recent names and faces can be done now, but optimizing for fast lookup and trust will require more data and testing. For example:
  - Cache last 50 interactions.
  - Use a simple decay function (e.g., less frequent memory refresh) for older entries.

## Phone/Cloud Boundary: Feasible Now
- **Current Status:** Phone-first runtime with optional cloud support.
- **Feasibility:** Implementing basic transcript and subtitle generation on the phone is feasible now. This allows for real-time processing without heavy reliance on cloud resources, aligning with V1 constraints.

## Visual Hierarchy: Feasible Later
- **Current Status:** Needs definition in terms of priority and clarity.
- **Feasibility:** Defining a visual hierarchy will require more detailed UI design and testing to ensure it supports the core attractors. For now, focus on minimizing clutter and ensuring subtitles are easily readable.

## Real-time Subtitle Clarity (subtitle_clarity)
- **Current Status:** Clear, fast, stable subtitles.
- **Feasibility:** Implement basic transcript capture and display on the phone. Test in noisy environments to ensure subtitles remain clear and stable during live conversations.

## Trustworthy Memory Support (memory_trust)
- **Current Status:** Remember names, faces without certainty.
- **Feasibility:** Implement a simple memory cache with decay functions. Use explicit uncertainty labels like "may know" or "possibly seen before."

## Low-friction Assistance (low_friction_assistance)
- **Current Status:** One-line prompts for context.
- **Feasibility:** Implement basic one-line prompts that are visible but unobtrusive. Ensure they do not overwhelm the wearer and provide just enough assistance.

## Privacy vs Usefulness (privacy_vs_usefulness)
- **Current Status:** Balancing helpful behavior with privacy.
- **Feasibility:** Ensure all interactions respect V1 constraints, focusing on frame touches only and minimizing data retention. Test scenarios where explicit user consent is required for memory or confidence updates.

## Always-on Sensing vs Battery and Thermals (latency_vs_richness)
- **Current Status:** Early hardware is simple.
- **Feasibility:** Implement minimal local logic in glasses, with heavy processing on the phone. Ensure battery usage remains low to avoid overheating issues.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Current Status:** Display behavior should be socially acceptable.
- **Feasibility:** Design subtitles and confidence displays that are small, unobtrusive, and easy to read. Use low-contrast colors or transparency to blend into the background.

## Summary of Feasibility
- **Subtitle Placement:** Feasible now with a bottom-center display.
- **Confidence Display:** Feasible now with simple labels.
- **Memory/Cache Policy:** Feasible later, but implement basic caching.
- **Phone/Cloud Boundary:** Feasible now by focusing on phone-first processing.
- **Visual Hierarchy:** Feasible later after detailed design.

By addressing these areas in a structured manner, the project can continue to evolve while respecting current constraints and ensuring core mission alignment.
