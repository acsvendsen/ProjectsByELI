### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we ensure that subtitles remain clear and unobtrusive while still providing critical assistance when needed. This improves the wearer's trust in the system by balancing visibility with usability.

2. **What small change unlocks it**

   Define three different subtitle placement modes:
   - High-confidence subtitles: Always visible at the top of the screen.
   - Medium-confidence subtitles: Visible on swipe or explicit touch.
   - Low-confidence subtitles: Hidden unless explicitly requested.

3. **Likely payoff**

   This approach enhances subtitle clarity and stability, reducing distractions while ensuring that the wearer receives necessary support when unsure. It strengthens trust through predictable behavior and minimal visual noise.

4. **Immediate next probe**
   - Define three subtitle placement modes: always visible, swipe-to-view, and request-only.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a numeric score with a label and short reason, we can provide the wearer with more precise and actionable feedback. This enhances trust through clear communication of certainty levels and reduces ambiguity in memory recall accuracy.

2. **What small change unlocks it**

   Modify the current confidence object to include both a numeric score and a short, neutral reason for that score. For example: `score 0.84 + "High" + "Seen recently"` or `score 0.42 + "Low" + "Weak match"`. This small change allows for more nuanced confidence handling without overcomplicating the interface.

3. **Likely payoff**

   The likely payoff is a significant boost in user trust and memory accuracy. By providing clear, actionable feedback, the system can better manage expectations and reduce errors in memory recall. This improvement also aligns with the core mission of ensuring real-world usefulness and low-friction assistance.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory threshold helps ensure that frequently encountered names and faces are reliably remembered, which strengthens the core attractor of "Trustworthy memory support." By setting a higher local cache size for key entities, the system can reduce reliance on cloud fallbacks, thereby maintaining privacy and reducing latency.

2. **What small change unlocks it**

   Define a specific entity-linking rule that allows attaching new evidence to existing person-memory objects based on repeated encounters. This involves creating a local threshold where if an entity is seen multiple times, its memory object is cached locally with higher confidence.

3. **Likely payoff**

   By caching frequently encountered names and faces locally, the system can provide faster and more reliable memory recall without compromising privacy or relying heavily on cloud processing. This improves trust by ensuring that common entities are always available quickly, reducing the risk of false negatives due to network issues or limited bandwidth.

4. **Immediate next probe**

   Define one entity-linking rule for attaching new evidence to existing person-memory objects based on repeated encounters, with a local cache threshold of at least 3 occurrences before caching is triggered.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that subtitles remain fast and stable enough for real-time conversation support without overloading battery or thermal limits.

2. **What small change unlocks it**

   Define a single task-specific boundary: live subtitle processing should be fully local to the glasses until confidence in word recognition is extremely high (e.g., 95%+ certainty).

3. **Likely payoff**

   This ensures that subtitles are always crisp and fast, maintaining the core attractor of real-time subtitle clarity while respecting V1's phone-first architecture.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By refining the visual hierarchy to prioritize subtitles over one-line support when confidence is low, we ensure that critical information remains clear and prominent. This improves real-time subtitle clarity and trustworthiness, which are primary attractors of our project.

2. **What small change unlocks it**

   Modify the subtitle vs. one-line priority rule to show subtitles first for low-confidence matches, then show one-line support below or beside them with a lower visual prominence.

3. **Likely payoff**

   This change will reduce cognitive overload by prioritizing essential information during uncertain interactions, thereby maintaining trust and improving overall user experience.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
