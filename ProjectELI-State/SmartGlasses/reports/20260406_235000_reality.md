# Reality Check for SmartGlasses Project

## Subtitle Clarity (Real-time subtitle clarity)
### Feasibility: Feasible Now
- **Current State**: The `TranscriptLab` app is currently testing the real-time transcript path, which is essential for ensuring subtitles are clear, fast, and stable.
- **Constraints**: The glasses should remain lightweight and socially acceptable. Early versions must not depend on heavy on-glasses compute, and subtitles need to feel near-real-time or trust breaks.

### Action Items
- Continue optimizing subtitle placement in `TranscriptLab` to ensure it is readable and stable during live tests.
- Ensure the display mechanism used in `TranscriptLab` can be easily transferred to glasses hardware without causing latency issues.

## Memory Trust (Trustworthy memory support)
### Feasibility: Feasible Now
- **Current State**: The system should remember names, faces, and prior context without pretending certainty. Confidence behavior is being developed but needs refinement.
- **Constraints**: Face/name recall must expose uncertainty clearly, and first versions should rely heavily on phone processing.

### Action Items
- Implement a confidence format that builds trust best (e.g., label + short reason) in the `TranscriptLab` app.
- Test memory reinforcement algorithms to ensure they are effective without overburdening the system.

## Low-friction Assistance (Low-friction assistance)
### Feasibility: Feasible Now
- **Current State**: One-line prompts should deliver low-friction assistance. The `TranscriptLab` app is being used to test this functionality.
- **Constraints**: V1 interaction should be controlled through frame touches only, and interactions must remain low-friction.

### Action Items
- Ensure the one-line prompt display in `TranscriptLab` does not overload the wearer with information.
- Test different visual hierarchies for prompts to find a balance between clarity and non-intrusiveness.

## Frame-touch-only V1 (Frame-touch-only V1)
### Feasibility: Feasible Now
- **Current State**: The interaction design is focused on frame touches, as determined by `v1_architecture_direction.md`.

### Action Items

## Phone-first Runtime (Phone-first runtime)
### Feasibility: Feasible Now

- **Constraints**: The system should remain lightweight and socially acceptable.

### Action Items

- Ensure any heavy lifting done by the cloud adds clear value without causing latency issues.
