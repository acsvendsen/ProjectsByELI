# Reality Check for SmartGlasses Project

## Subtitle Clarity (subtitle_clarity)

- **Feasible Now:** 
  - The `TranscriptLab` app has already validated basic subtitle clarity in real-time scenarios.
  - The current focus on ensuring subtitles remain clear, fast, and stable enough to be trusted is feasible with existing technology.

- **Assumptions Needing Evidence:**
  - Further testing under varying environmental conditions (e.g., different noise levels) should confirm that the subtitles are usable in noisy environments.
  - Optimizing subtitle text placement and display duration can ensure they do not distract or become unreadable during motion.

## Memory Trust (memory_trust)

- **Feasible Now:**
  - The initial implementation of face/name recall with confidence objects and reinforcement over time is feasible. The current setup in `TranscriptLab` handles memory storage and lookup, which are critical steps.
  
- **Likely Waste of Time:**
  - Implementing full confidence-based correction mechanisms now might be premature without a robust baseline system to verify the effectiveness of confidence labels.

## Low-Friction Assistance (low_friction_assistance)

- **Feasible Now:**
  - The current interaction through frame touches is practical and aligns with V1 constraints. One-line prompts can coexist with subtitles by using different visual styles, such as a subtle bar or overlay.
  
- **Assumptions Needing Evidence:**
  - Testing the impact of one-line prompts on user experience to ensure they do not overwhelm the wearer without providing substantial value.

## Privacy vs Usefulness (privacy_vs_usefulness)

- **Feasible Now:**
  - The current design avoids invasive data capture by relying heavily on phone processing and cloud optional features. Ensuring that memory recall respects privacy through clear uncertainty and avoid pretending certainty is feasible.
  
- **Assumptions Needing Evidence:**
  - Conducting user surveys to understand how users perceive the balance between utility and privacy in context-aware memory support.

## Latency vs Richness (latency_vs_richness)

- **Feasible Now:**
  - The `TranscriptLab` app already demonstrates real-time transcript behavior, which is essential for maintaining trust.
  
- **Assumptions Needing Evidence:**
  - Further optimization of the speech-to-text engine to ensure latency remains low while adding more sophisticated features might be necessary if richer context support is needed.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)

- **Feasible Now:**
  - The current design for subtitle placement and visual hierarchy in `TranscriptLab` ensures that subtitles remain readable without becoming overly distracting.
  
- **Assumptions Needing Evidence:**
  - User testing to refine subtitle placement further, ensuring it remains discreet yet clear enough for the wearer.
