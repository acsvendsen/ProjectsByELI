# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasibility Now

### Current Considerations:
- **Subtitle Clarity**: Ensure subtitles are clear, fast, and stable enough to be trusted in live conversations.
- **Discreet UX vs Visual Clarity**: The subtitle placement should remain socially acceptable while still being readable in motion and noise.

### Analysis:

**Feasible Now:**
- **Glasses Display Placement**: Positioning the text overlay slightly below the wearer’s line of sight can balance readability with discreetness. Initial tests using `TranscriptLab` on a phone screen suggest that subtitles should be large enough to read but not so large they become distracting.
- **Visual Hierarchy**: Subtitles should have a clean, uncluttered appearance with a clear distinction from the main view. Using a semi-transparent background or a different color can help ensure the subtitles remain readable without drawing too much attention.

**Assumptions Needing Evidence:**
- The exact size and transparency of subtitle text to maintain readability in various environments.
- User feedback on subtitle placement for different scenarios (e.g., standing, sitting, walking).

## Confidence Display: Feasibility Now

### Current Considerations:
- **Confidence Label Only vs. Reason**: Determine the best way to display confidence without overloading the wearer.

### Analysis:

**Feasible Now:**
- **Label Only vs Label + Short Reason**: Using only a label (e.g., "80% confident") can be clear and unobtrusive, reducing cognitive load on the wearer. A short reason (e.g., "face not recognized; asking for help") could add more context but might also introduce noise.
- **Implementation Grounding**: Implement both options in `TranscriptLab` to gather user feedback quickly.

**Assumptions Needing Evidence:**
- The effectiveness of a simple confidence label vs. a label with a short reason in different use cases.
- User preference for quick, clear information over more detailed explanations.

## Memory/Cache Policy: Feasibility Now

### Current Considerations:
- **Face/Name Memory**: Store and reinforce face/name memory for fast lookup and trust.
- **Memory vs Richness Tradeoff**: Ensure that the system does not store too much low-value information.

### Analysis:

**Feasible Now:**
- **Local Cache on Phone**: Use a local cache on the phone to remember recently seen faces and names. This can reduce latency and provide faster lookup times.
- **Reinforcement Mechanism**: Implement reinforcement rules that strengthen memory by associating new entries with context (e.g., time, location) to avoid cluttering the cache.

**Assumptions Needing Evidence:**
- The optimal size of the local cache on the phone.
- How often and under what conditions face/name data should be cleared from the cache.

## Phone/Cloud Boundary: Feasibility Now

### Current Considerations:
- **Phone-First Runtime**: Heavy processing primarily happens on the phone, with cloud optional where clearly justified.
- **Battery and Latency Concerns**: Balancing local processing to minimize battery drain while maintaining acceptable latency.

### Analysis:

**Feasible Now:**
- **Local vs Cloud Processing**: For subtitle generation and memory recall, prioritize local processing using `TranscriptLab`. This reduces dependency on cloud services that could introduce latency.
- **Optimization of Local Logic**: Implement efficient algorithms for real-time subtitle generation to ensure minimal battery drain.

**Assumptions Needing Evidence:**
- The extent of local processing needed without compromising accuracy or responsiveness.
- Cloud usage scenarios where it significantly adds value, such as model updates or background analysis.

## Visual Hierarchy: Feasibility Now

### Current Considerations:
- **Subtitle Placement and Display Priority**: Ensure subtitles are visually clear and unobtrusive.

### Analysis:

**Feasible Now:**
- **Clear Subtitle Display**: Design the subtitle display to be large enough to read but not too distracting. Initial tests with `TranscriptLab` should guide this decision.
- **Priority in UI**: Ensure subtitles have a high priority in the visual hierarchy, making them easy to distinguish from other UI elements.

**Assumptions Needing Evidence:**
- The exact size and style of subtitles for optimal readability.
- User feedback on the subtlety of subtitle display versus their importance.

## Summary

### Feasible Now:
- Subtitle placement should be clear but discreet, using initial tests with `TranscriptLab` to refine this further.
- Confidence display can use a simple label for clarity, with short reasons as needed based on user feedback.
- Face/name memory should be cached locally with reinforcement rules in place.
- Phone-first processing is essential for minimizing battery drain and latency issues.
- Visual hierarchy should prioritize subtitles while ensuring they are readable.

### Assumptions Needing Evidence:
- Detailed size and style of subtitles.
- User preference for confidence display options.
- Optimal cache size for face/name memory.
- Cloud usage scenarios that significantly add value without compromising performance.
