### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states will enhance the wearer's ability to focus on critical information while reducing visual distraction. This refinement ensures that high-confidence subtitles are more prominently displayed, drawing less attention away from lower-confidence subtitled content.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence subtitles and another for medium-to-low confidence subtitles. For high-confidence subtitles, place them closer to the top of the display area where they can be quickly glanced at. For medium-to-low confidence subtitles, use a slightly lower position that still allows quick reading but avoids overlapping with higher-priority content.

3. **Likely payoff**

   By clearly differentiating between high and low confidence subtitle placements, we reduce visual clutter for critical information while ensuring that less certain content is still visible when needed. This will enhance the wearer's trust in the system by making it easier to focus on important details without being overwhelmed by secondary or uncertain information.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer can trust the system's memory and support behaviors by understanding the certainty level behind each piece of information. A clear, consistent, and honest confidence display will reduce the risk of overreliance on uncertain or potentially incorrect data.

2. **What small change unlocks it**

   Define a simple yet effective confidence format that combines a numeric score with a short reason, such as `score 0.85 + "Seen recently"` for high certainty, `score 0.40 + "Weak match"` for low certainty, and `score 0.60 + "Name heard once in introduction"` for medium certainty.

3. **Likely payoff**

   By implementing a clear confidence format, the system can enhance trust through transparent signaling of reliability. This will help prevent overconfidence in uncertain data and ensure that users understand when they are relying on less certain information, which is crucial for maintaining the product's credibility and user satisfaction.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that the system retains enough context to be useful without overloading the phone's memory or draining the battery. This helps in maintaining a balance between providing rich contextual support and keeping the overall system lightweight.

2. **What small change unlocks it**

   Define a specific threshold for how much face and name data should be cached locally on the phone before evicting older entries to make room for new ones. For example, set a limit of 50 face or name entries that are reinforced over time with repeated encounters.

3. **Likely payoff**

   By setting this threshold, the system can maintain a strong memory cache while ensuring it does not consume excessive phone resources. This will enhance the wearer's trust in the system by providing relevant and timely support without unnecessary data retention.

4. **Immediate next probe**

   Define one local-cache size limit for face/name memory to be 50 entries with reinforcement over time.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that critical real-time subtitle processing happens on the device, maintaining low latency and trustworthiness. This focus helps preserve the wearer's ability to understand and respond in real-time without relying on potentially delayed cloud responses.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing as phone-local, while allowing transcript cleanup and memory lookup to fall back to the cloud when needed.

3. **Likely payoff**

   This decision will ensure that subtitles remain clear, fast, and stable enough in real-time interactions, reinforcing trust and improving the wearer's ability to follow conversations without delays. It also allows for more complex processing (like transcript cleanup) to occur off-device without affecting the critical subtitle display in real time.

4. **Immediate next probe**
   - Define the rule that live subtitle generation for real-time conversations is handled phone-local, with a fallback to the cloud if local processing capacity is exceeded.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that critical information (subtitles) remains prominent while supplementary or less urgent prompts are handled discreetly. This balance enhances user trust by clearly distinguishing what is essential from additional context.

2. **What small change unlocks it**

   Define a single subtitle placement rule for different confidence levels: high-confidence subtitles should be placed at the top of the screen, with one-line support (e.g., contextual names) below them but not overlapping or obscuring the main text.

3. **Likely payoff**

   This visual hierarchy will reduce cognitive load by ensuring that the wearer can quickly focus on critical information without being distracted by less important prompts. It also aligns with the core attractor of low-friction assistance, making the system more useful and intuitive in real-world interactions.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
