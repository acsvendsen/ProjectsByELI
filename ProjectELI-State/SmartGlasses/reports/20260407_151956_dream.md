### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a fixed subtitle placement rule, we ensure that subtitles remain stable and predictable, reducing cognitive load and increasing trust in the system's reliability. This consistency helps the wearer focus on understanding the conversation rather than adjusting to dynamic subtitle positions.

2. **What small change unlocks it**

   To define a fixed subtitle placement rule, we need to explicitly set the default subtitle position as a constant value, such as always displaying subtitles at the bottom center of the screen regardless of confidence or speaker identity.

3. **Likely payoff**

   Implementing this fixed subtitle placement will provide a consistent and reliable user experience, reducing cognitive load during conversations and ensuring that subtitles remain easily readable without frequent movement. This stability can help in maintaining trust and improving overall usability.

4. **Immediate next probe**
   - Define the default fixed subtitle placement mode as bottom center of the screen.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving confidence display helps build trust in the wearer by clearly indicating the reliability of the displayed information, which is crucial for subtitle clarity and overall memory support. A well-designed confidence format ensures that the wearer can easily distinguish between high-confidence and low-confidence information, enhancing their ability to understand and respond appropriately.

2. **What small change unlocks it**

Define a simple yet effective confidence format that uses both a numeric score and a label with a short reason for the score. This will allow the system to convey certainty levels in a clear and concise manner without overwhelming the user.

3. **Likely payoff**

Implementing this confidence format will lead to more reliable interactions, as the wearer can quickly assess the reliability of the subtitles or memory support they are receiving. This improvement will enhance trust in the system and make it easier for wearers to rely on the SmartGlasses for their understanding needs.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory, we ensure that the system retains only the most relevant and frequently accessed memories on the phone. This helps in maintaining trust by not overwhelming the wearer with unnecessary information, while still providing reliable recall of important people and contexts.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects stored on the phone to ensure that only the most relevant memories are retained.

3. **Likely payoff**

   This change will help in maintaining a clean and focused memory system, reducing the risk of information overload while still ensuring that critical names and faces are readily accessible when needed. It will also align with the core attractor of "memory trust" by providing reliable and timely recall without unnecessary data.

4. **Immediate next probe**

   Define one local cache size limit for face/name memory objects stored on the phone, limiting the number to 50 entries.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that critical tasks like live subtitle processing stay local to the phone minimizes latency and thermal load, which are key constraints for a wearable device. By keeping these tasks on the phone, we can maintain real-time clarity and stability in subtitles, preserving the wearer's trust in the system.

2. **What small change unlocks it**

   Define one specific task boundary: live subtitle processing. Ensure that all subtitle-related processing stays local to the phone, with no fallbacks or offloading to the cloud for this core function.

3. **Likely payoff**

   By keeping live subtitle processing on the phone, we ensure minimal latency and thermal load, which are critical for maintaining real-time clarity and trust in the system. This also allows for faster, more reliable updates and corrections without relying on potentially slower or less efficient cloud processing.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

3. **Likely payoff**

4. **Immediate next probe**
