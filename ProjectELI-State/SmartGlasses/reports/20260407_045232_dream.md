### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence states, the system can ensure that subtitles are always placed in a way that maximizes readability and trust while minimizing distraction. This will help maintain the core attractor of real-time subtitle clarity and enhance overall user experience.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence face/name recognition (placing subtitles directly below the recognized face) and another for low-confidence situations (using a general text area above the conversation).

3. **Likely payoff**

   Implementing these specific placement rules will lead to more readable and reliable subtitles, reducing cognitive load and increasing trust in the system's accuracy during live conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance the trustworthiness of the system by clearly indicating the reliability of the subtitles and memory support provided to the wearer. A well-designed confidence label, score, and short reason will help the user understand when they can rely on the information being presented.

2. **What small change unlocks it**

   Define a simple numeric score format combined with a clear label and concise reason for each piece of displayed information (e.g., subtitles or memory recall).

3. **Likely payoff**

   By implementing a confidence display that uses a numeric score, label, and short reason, the system will provide users with a clear indication of how reliable the information is. This will help in building trust and reducing cognitive load by allowing the user to quickly assess the quality of the displayed content.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size threshold for name recall, the system can balance memory trust with low-friction support. This ensures that frequently encountered names and faces are quickly accessible without overwhelming local storage, maintaining both the user's ability to have fast, reliable recall and the overall performance of the glasses.

2. **What small change unlocks it**

   Define a local cache size limit for name-related data stored on the phone, with a threshold set at 10-15 recent interactions per person. This limit ensures that only recently encountered names are prioritized in memory while keeping the storage footprint manageable.

3. **Likely payoff**

   Implementing this cache size limit will help in maintaining a balance between rich and reliable memory support and efficient local processing. It will ensure that the system can quickly recall relevant names without consuming excessive resources, thereby improving the overall user experience and reducing battery drain.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus cloud-based processing, we can optimize subtitle rendering and face/name recall lookup to ensure real-time performance and low latency. This balance helps maintain trust in the system by ensuring that critical assistive features are available instantly.

2. **What small change unlocks it**

   Define specific tasks such as live subtitle processing as running phone-local only, while more complex memory archive sync or conversation snapshot upload falls back to the cloud. For example, live subtitles should be processed on the device to ensure minimal latency and high reliability.

3. **Likely payoff**

   By keeping subtitle processing local, we can guarantee near-real-time performance, which is crucial for maintaining the wearer's trust in the system. Additionally, this approach reduces battery drain from constant cloud requests and enhances privacy by keeping sensitive data on-device.

4. **Immediate next probe**

   Define live subtitle processing as a phone-local task with no fallback to the cloud.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that key information is prioritized for the wearer's attention without overwhelming them. This improves overall usability by maintaining a clean interface that remains socially acceptable while providing necessary assistance.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule that routes higher-priority text to a more prominent position and lower-priority text to a less intrusive area of the frame. This could involve setting different display precedence rules for subtitles based on their confidence level or importance.

3. **Likely payoff**

   By optimizing visual hierarchy, we can enhance the wearer's ability to quickly read and understand critical information during conversations, reducing cognitive load and social awkwardness. This will contribute to a more seamless and effective user experience that aligns with the project’s core attractors of real-time subtitle clarity and low-friction assistance.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
