### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Improving subtitle placement rules can enhance the wearer's ability to understand live conversations in noisy environments by reducing distractions and increasing readability. This directly aligns with the primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**
   - Define a fixed subtitle placement rule that keeps subtitles at the bottom center of the field of view, ensuring they do not overlap other important visual elements while remaining clearly visible.

3. **Likely payoff**
   - This simple change will reduce distraction and improve readability, making the subtitles more useful in real-world scenarios. It can also serve as a baseline for further fine-tuning based on user feedback and testing.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that the system can efficiently store and recall names, faces, and prior context without overloading the phone's limited resources. This directly supports the core attractor of "memory_trust" by ensuring that the wearer's memory support is reliable and fast, even when the cloud is not available.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memories on the phone. For example, set the local cache to store up to 50 unique faces or names with recent encounter times, allowing frequent access without frequent network trips.

3. **Likely payoff**

   By limiting the local cache size, we ensure that memory storage is efficient and fast, reducing battery drain and latency during frequent interactions. This will lead to more reliable memory support for the wearer, even in situations where cloud processing might be delayed or unavailable.

4. **Immediate next probe**

   Define a local cache size limit of 50 unique faces/names for face/name recall lookup on the phone.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear phone-cloud boundary for live subtitle processing, we ensure that critical real-time tasks remain local to the phone, maintaining low latency and ensuring the subtitles are delivered with minimal delay. This focuses on the primary need of delivering timely assistance without overloading the battery or introducing thermal risks.

2. **What small change unlocks it**

   Define a specific boundary for live subtitle processing: all face recognition and name recall for subtitle generation should remain local to the phone, while partial transcript generation can use cloud support if needed but still prioritize on-device processing.

3. **Likely payoff**

   This approach will ensure that subtitles are always delivered with minimal delay, preserving trust by providing near-real-time assistance. It also reduces battery drain and thermal issues associated with continuous heavy processing, allowing for a more stable and reliable product experience.

4. **Immediate next probe**

   Define one task-specific cloud fallback boundary for live subtitle processing: all face recognition and name recall should remain local to the phone, while partial transcript generation can use cloud support if needed but still prioritize on-device processing.
