### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules based on confidence levels, we can ensure that subtitles are displayed in a way that maximizes readability while minimizing distraction. This will help maintain trust and improve overall user experience by making sure critical information is clear when needed.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence content (e.g., recognized faces/names) and another for lower-confidence content (e.g., potential new names/voices). For high confidence, subtitles can be placed at the bottom of the frame with clear visual priority. Lower confidence content can have a more subtle display.

3. **Likely payoff**

   Implementing these placement modes will enhance subtitle clarity and reduce cognitive load by making important information stand out while minimizing distractions from less certain data. This balance will support better real-time understanding and trust in the system's accuracy.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By optimizing the confidence display format to provide clear, concise, and trustworthy information, we can enhance the wearer's trust in both subtitles and memory support. A well-designed confidence format ensures that the system neither overpromises nor underdelivers, maintaining a balance between helpfulness and realism.

2. **What small change unlocks it**

   Define a new confidence format that uses a numeric score (0-1) alongside a label ("High", "Medium", "Low") with a short reason why the confidence was assigned to a specific piece of memory or subtitle. This format can be implemented by modifying the `confidenceDisplayFormatter` function in the `TranscriptLabModel.swift`.

3. **Likely payoff**

   Implementing this confidence format will provide users with clear and consistent feedback, enhancing their trust in the system's accuracy. It will help them understand when to rely on the information provided by the glasses and when to seek additional context or confirmation. This clarity can significantly improve the overall user experience and reliability of the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear threshold for local memory retention, we ensure that the system only caches relevant information on the phone, reducing privacy concerns and maintaining the wearer's trust. This helps in managing the balance between providing useful memory support and respecting the wearer's privacy.

2. **What small change unlocks it**

   Define a cache size limit for face/name memories based on recent encounters. For example, if a person is encountered multiple times within an hour, their memory should be cached locally with high confidence; otherwise, it should be marked as low-confidence or not cached at all.

3. **Likely payoff**

   This change will help in reducing the battery load by minimizing unnecessary data storage on the phone, while still ensuring that frequently encountered individuals are remembered and recalled accurately. It also helps in maintaining a clear privacy boundary, which is crucial for building trust with wearers.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By refining the phone/cloud boundary for live subtitle processing, we can ensure that real-time subtitles remain stable and readable while minimizing battery drain and thermal stress on the glasses.

2. **What small change unlocks it**

   Define a local caching policy where recent transcript segments are cached on the phone before falling back to cloud processing if needed.

3. **Likely payoff**

   This will allow for faster, more reliable subtitle delivery in live conversations while reducing the load on the glasses and ensuring that critical information is processed quickly even under high thermal or battery constraints.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are displayed with a clear visual hierarchy helps maintain the wearer's focus on important information while minimizing distractions. By carefully managing which elements (subtitles vs one-line support) take precedence, we can ensure that the wearer remains fully present and engaged in conversations without feeling overwhelmed.

2. **What small change unlocks it**

   Define a simple coexistence rule for subtitles and one-line prompts where both are visible but only one is prioritized at any given time based on current context and confidence levels.

3. **Likely payoff**

   By implementing a clear coexistence rule, we can enhance the wearer's trust in the system by ensuring that critical information (like key names or spoken words) stands out while less essential text remains secondary. This reduces visual clutter and ensures that the wearer’s attention is directed where it matters most.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
