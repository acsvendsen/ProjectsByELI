### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles remain clear, stable, and unobtrusive while still providing useful information to the wearer. This approach helps maintain high real-time subtitle clarity (attractor: `subtitle_clarity`), which is crucial for trust in live conversations.

2. **What small change unlocks it**

   The small change involves defining three distinct subtitle placement rules:
   - Default fixed position at the bottom of the display.
   - Lowered or obscured position for lower confidence subtitles to reduce distraction.
   - Highlighted and slightly moved position for higher confidence subtitles to draw attention without being overly intrusive.

3. **Likely payoff**

   Implementing these rules will result in a more consistent and reliable subtitle experience, reducing visual distractions during low-confidence situations while still providing important information during high-confidence moments. This improvement will enhance the core attractor of real-time subtitle clarity and support the core tension between privacy and usefulness by ensuring that subtitles are relevant without being overly intrusive.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitles and memory support more effectively. By refining the confidence labels, short reasons, and scores, we can better convey the reliability of the information being presented. This helps in maintaining the core attractor of "memory_trust" and "low_friction_assistance," ensuring that the system does not create false certainty.

2. **What small change unlocks it**

   The small change is to define a specific confidence format for V1. For example, we can use a numeric score combined with a label and short reason. This format could look like: `score 0.8 + "High" + "Seen recently"` for high confidence or `score 0.4 + "Low" + "Weak match"` for lower confidence.

3. **Likely payoff**

   By standardizing the confidence display, we can reduce ambiguity and improve the wearer's trust in the system. This clarity will help in situations where the wearer needs to rely on the subtitles or memory support, ensuring that they do not misinterpret uncertain information as certain knowledge. This refinement will also make it easier for the wearer to understand the reliability of the system without having to guess at its certainty level.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size for face/name memory ensures that relevant memories are readily accessible to the wearer without requiring constant cloud queries, thereby enhancing trust and reliability in memory support. By optimizing this threshold, we can balance the need for fast recall with battery constraints, ensuring the system remains both efficient and responsive.

2. **What small change unlocks it**

   Define a local cache size limit of 10 recent face/name interactions that are reinforced over time. This ensures frequent encounters are stored locally, reducing latency and dependency on cloud services while maintaining a manageable cache size to respect battery limits.

3. **Likely payoff**

   By setting this local cache threshold, we can significantly improve the speed and reliability of name recall during conversations. This will help in keeping the memory support feature trustworthy and useful, without overloading the device’s resources or creating unnecessary data transfer demands.

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays phone-local versus what falls back to cloud for live subtitle processing, we can ensure that real-time subtitle clarity is maintained while respecting battery and thermal constraints. This balance helps in delivering high-quality subtitles without overloading the glasses hardware.

2. **What small change unlocks it**

   Define a specific rule for when live subtitle processing should fallback to the cloud based on estimated latency requirements. For example, if the estimated latency exceeds 150ms, initiate cloud fallback for subtitle rendering.

3. **Likely payoff**

   This rule will ensure that subtitles remain fast and stable enough to be trusted in real-time interactions, enhancing the core attractor of real-time subtitle clarity. It also helps in managing battery usage by offloading computationally intensive tasks when necessary.

4. **Immediate next probe**
