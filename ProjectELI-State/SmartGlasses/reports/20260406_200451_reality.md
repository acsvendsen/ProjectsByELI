# Reality Check for SmartGlasses V1 Direction

Based on the provided inputs, we will assess proposed directions against real-world limits and constraints to ensure the project stays focused on feasible core improvements.

## Core Attractors and Tensions

### Subtitle Clarity (Real-time subtitle clarity)
- **Feasibility**: Feasible now
  - **Justification**: The `TranscriptLab` app allows for live microphone capture and partial/final transcript behavior. This means real-time subtitle generation is possible on the phone, which can then be displayed discreetly in glasses.
  - **Constraints**: Battery draw due to always-on transcription needs careful management.

### Memory Trust (Trustworthy memory support)
- **Feasibility**: Feasible now
  - **Justification**: Initial context and entity linking can use simple rules for automatic recall. Reinforcement learning through frame-touch interactions can help build trust.
  - **Constraints**: Privacy concerns must be managed to avoid over-capturing or misrepresenting memory.

### Low-friction Assistance (Low-friction assistance)
- **Feasibility**: Feasible now
  - **Justification**: One-line prompts and confidence indicators are simpler than full command interfaces. They can be designed to minimize user interaction.
  - **Constraints**: Display must remain unobtrusive yet informative.

## Core Tensions

### Privacy vs Usefulness (Privacy vs usefulness)
- **Feasibility**: Feasible now
  - **Justification**: Automatic new-person memory should be based on context and reinforced over time. Explicit remember-touch behavior can add user control.
  - **Constraints**: Need to balance the amount of data captured to avoid privacy concerns.

### Latency vs Richness (Latency vs richness)
- **Feasibility**: Feasible now
  - **Justification**: The phone-first architecture allows for heavy processing off-device, reducing latency on glasses. Confidence displays can provide immediate feedback.
  - **Constraints**: Subtitle generation must remain real-time to maintain trust.

### Discreet UX vs Visual Clarity (Discreet UX vs visual clarity)
- **Feasibility**: Feasible now
  - **Justification**: The design of subtitles and confidence indicators should be minimal but clear. This can be achieved through careful visual hierarchy.
  - **Constraints**: Display must remain unobtrusive yet useful, especially in noisy environments.

## Core Constraints

### Frame-touch-only V1 (Frame-touch-only V1)
- **Feasibility**: Feasible now
  - **Justification**: The current assumption is frame touches for interaction. This constraint limits the complexity of user controls.
  - **Constraints**: No voice activation or complex multimodal UI in V1.

### Phone-first Runtime (Phone-first runtime)
- **Feasibility**: Feasible now
  - **Justification**: Heavy processing should primarily happen on the phone, with cloud optional where justified.
  - **Constraints**: Battery and thermal considerations must be managed.

## Core Modes

### Core Deepening (Core Deepening)
- **Feasibility**: Feasible now
  - **Justification**: Improvements in subtitle quality, memory trust, confidence display, and visual UX should be prioritized.
  - **Constraints**: Broad feature sprawl is not encouraged.

## Visual Hierarchy

- **Feasibility**: Assumptions needing evidence
  - **Justification**: Determining the best placement and clarity of subtitles and confidence indicators requires empirical testing. The `TranscriptLab` app can provide a starting point.
  - **Constraints**: Need to balance readability with social acceptability.

## Memory/Cache Policy

- **Feasibility**: Feasible now
  - **Justification**: Initial memory policies should focus on automatic recall and reinforcement through frame touches.
  - **Constraints**: Privacy and data management must be carefully considered.

### Next Steps

1. **Subtitle Placement and Visual Hierarchy**:
   - Conduct empirical testing with the `TranscriptLab` app to determine optimal subtitle placement and visual hierarchy.
   - Ensure subtitles are clear, readable, and unobtrusive in various real-world environments.

2. **Memory Trust**:
   - Implement automatic memory recall based on context and reinforce through frame touches.
   - Test the effectiveness of different confidence formats (label only, label + short reason, score + label) to ensure trust without privacy concerns.

3. **Low-friction Assistance**:
   - Design one-line prompts that provide contextual support while maintaining a low command interface.
   - Ensure these prompts are unobtrusive yet useful for the wearer.

4. **Privacy Management**:
   - Develop and test memory policies that balance the need for accurate recall with privacy concerns.
   - Use frame touches as a mechanism for explicit reinforcement, ensuring user control over data capture.

By focusing on these areas, we can ensure the V1 direction aligns with real-world constraints and provides significant value to the wearer.
