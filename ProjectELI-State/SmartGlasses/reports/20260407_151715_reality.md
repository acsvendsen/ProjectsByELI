# Reality Check Report

## Subtitle Placement: Feasible Now
- **Subtitle placement** should aim to be readable without becoming distracting, especially in noisy environments where the wearer needs clear information quickly.
- **Assessment**: Based on current implementation constraints and user experience expectations, subtitles need to be placed in a way that ensures they are visible but not overly prominent. The current `TranscriptLab` app provides a good test bed for exploring subtitle placement options without hardware dependency.

## Confidence Display: Feasible Now
- **Confidence display** should clearly indicate the reliability of the subtitle text, helping wearers trust or distrust the information as needed.
- **Assessment**: Current implementation in `TranscriptLab` allows for experimenting with different confidence display formats (label only, label + short reason, score + label). This is feasible now to explore user reactions and refine the design.

## Memory/Cache Policy: Feasible Now
- **Memory/cache policy** should balance between caching useful information locally on the phone and ensuring this does not lead to privacy concerns or battery drain.
- **Assessment**: The current `TranscriptLab` setup can be used to test different caching strategies. Local caching of face/name memory with clear uncertainty signals is feasible now, respecting V1 constraints.

## Phone/Cloud Boundary: Feasible Now
- **Phone/cloud boundary** should prioritize phone-first processing to ensure V1 remains lightweight and socially acceptable.
- **Assessment**: `TranscriptLab` already focuses on reusable transcript plumbing that can be transitioned to actual glasses hardware. This is feasible now as a proof of concept.

## Visual Hierarchy: Feasible Now
- **Visual hierarchy** should prioritize clarity over feature density, ensuring subtitles remain readable and the overall UI does not overwhelm the wearer.
- **Assessment**: The `TranscriptLab` app's simple design allows for exploring visual hierarchy without heavy implementation. This is feasible now to get initial feedback.

## Core Deepening: Likely Waste of Time
- **Core deepening** (bias toward subtitle, memory, confidence, and architecture improvements) seems the most aligned with current project constraints and priorities.
- **Assessment**: Given the current focus on V1 real-world limits and core loop strengthening, further work in this area is likely to yield valuable results. However, specific activities like broad feature expansion or speculative hardware complexity are not currently warranted.

## Low-Friction Assistance: Feasible Now
- **Low-friction assistance** (delivering one-line help and visible support without creating command overhead) needs refinement but is feasible now.
- **Assessment**: The current `TranscriptLab` setup can be used to test different levels of assistive behavior. One-line prompts that are clear, concise, and non-intrusive are achievable.

## Privacy vs Usefulness: Feasible Later
- **Privacy vs usefulness** (managing the balance between helpful assistive behavior and potential privacy concerns) is a long-term consideration.
- **Assessment**: While core functionality can be developed now, detailed work on privacy-preserving mechanisms should be delayed until broader capabilities are in place. Current focus should remain on functional improvements.

## Always-On Sensing vs Battery: Feasible Later
- **Always-on sensing** to enhance context awareness while managing battery constraints.
- **Assessment**: Given current V1 constraints and the need for a phone-first approach, always-on sensing is not feasible now but can be considered for future iterations when hardware allows.

## Rich Context vs Low-Latency Response: Feasible Now
- **Rich context** (relying on heavy processing) versus **low-latency response** needs to balance speed and information richness.
- **Assessment**: The current `TranscriptLab` setup can test various levels of contextual support without full hardware dependencies. This is feasible now for iterative refinement.

## Discreet UX vs Visual Clarity: Feasible Now
- **Discreet UX** versus **visual clarity** requires balancing social acceptability with readability.
- **Assessment**: The current implementation in `TranscriptLab` allows for testing different display designs to ensure they remain discreet while still providing clear and useful information. This is feasible now.

## Interaction Constraints: Feasible Now
- **Interaction constraints** (frame-touch-only V1) must be strictly followed.
- **Assessment**: Current `TranscriptLab` implementation respects these constraints, ensuring that any additional UI elements or interactions are kept minimal and aligned with the frame-touch-first approach.

### Summary
- **Subtitle Placement**, **Confidence Display**, **Memory/Cache Policy**, **Phone/Cloud Boundary**, and **Visual Hierarchy** are all feasible now based on current project inputs.
- **Core Deepening** is most relevant to the current phase but should focus on specific improvements rather than broad expansions.
- **Privacy vs Usefulness**, **Always-On Sensing vs Battery**, and other long-term considerations are likely waste of time at this stage, pending broader feature development.
