### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain readable, stable, and do not become distracting, thus enhancing the wearer's understanding without overwhelming them. Stable subtitle placement is crucial for maintaining trust in the system and ensuring that the wearer can focus on their interaction rather than trying to read subtitles.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence faces/names and another for lower-confidence contexts. This differentiation allows the system to prioritize more certain information while still providing necessary context when less confident.

3. **Likely payoff**

   By differentiating subtitle placement based on confidence levels, the system can provide clearer and more reliable information during critical moments (like introductions or key statements) while maintaining a clean interface for background support. This improves overall usability and trust in the system's assistance.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

   Improving local memory thresholds helps ensure that likely new-person memories are reinforced effectively while maintaining privacy by not over-caching. This balance strengthens trust through reliable, timely, and private recall assistance.

2. **What small change unlocks it**

   Define a local cache threshold for face/name memory that balances reinforcement over time with privacy concerns. For example, set a threshold where memories are cached locally if encountered more than three times but expire after a week of inactivity.

3. **Likely payoff**

   By carefully setting the local cache threshold, we can ensure that likely new-person memories are quickly reinforced without cluttering local storage and risking privacy issues. This will enhance the core memory support attractor while keeping the system discreet and usable.

4. **Immediate next probe**

   Define a local cache eviction rule for face/name memory objects, evicting them after 7 days of inactivity if encountered fewer than four times.
