### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles remain clear and stable without becoming distracting. This will enhance the wearer's trust in the system during live conversations, aligning with the primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Introduce a simple rule: Place subtitles at the bottom center of the display for high confidence (≥0.9) and medium confidence (0.75 to 0.89), while reducing their size or shifting them slightly upwards for low confidence (<0.75). This will create a stable yet unobtrusive layout.

3. **Likely payoff**

   Implementing this rule will make subtitles more readable during critical moments, such as important statements or introductions, thereby improving the overall experience and trust in the system's real-time subtitle capabilities.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a numeric score along with a clear label and short reason, we can enhance the trustworthiness and interpretability of the system's responses. This will help the wearer understand the reliability of the subtitles and memory support more intuitively.

2. **What small change unlocks it**

   Implementing a confidence object that shows the certainty as a numeric score (e.g., 0.84), a label (e.g., "High"), and a short reason (e.g., "Seen recently") for each subtitle or memory item. This requires updating the UI to display this information clearly.

3. **Likely payoff**

   This change will provide users with clearer, more actionable feedback about the reliability of the system's outputs. Users can better trust the subtitles when they see high confidence levels and understand why certain pieces of memory are recalled. It will also reduce the cognitive load on the user by making the confidence information easily accessible.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local memory threshold for face/name recall, we ensure that the system remembers likely new people without overwhelming the wearer's trust or local storage capacity. This helps in maintaining a balance between providing useful memory support and preserving privacy.

2. **What small change unlocks it**

   Define one local cache size limit for face/name memory objects on the phone. This ensures that only relevant and frequently encountered individuals are cached locally, reducing the risk of storing unnecessary information while still providing reliable recall.

3. **Likely payoff**

   Implementing a clear local memory threshold will enhance trust by showing that the system is mindful of privacy concerns. It will also reduce battery and storage usage, making the system more efficient and less intrusive to the wearer's daily life.

4. **Immediate next probe**

   Define one local cache size limit for face/name memory objects on the phone, setting it to 10 entries with a refresh every 24 hours.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for which tasks run on the phone versus which fall back to the cloud, we can ensure that the most critical and privacy-sensitive processes remain local while leveraging the cloud for less critical but resource-intensive tasks. This balance helps maintain battery efficiency and user trust.

2. **What small change unlocks it**

   Define specific tasks for V1 to run locally on the phone: live subtitle processing and face/name recall lookup.

3. **Likely payoff**

   By keeping real-time subtitle processing and face/name recall local, we can ensure that these critical functions remain fast and reliable without draining the battery or compromising user privacy. This will significantly enhance the core mission of helping the wearer understand and remember key information in live interactions.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can focus on the most critical information while maintaining a low-friction experience. This balance helps in reducing cognitive overload, which is crucial for real-time interactions where trust and clarity are paramount.

2. **What small change unlocks it**

   Define a simple subtitle-vs-one-line priority rule that gives higher precedence to subtitles under certain conditions (e.g., high confidence or urgent context) while allowing one-line support to be visible but suppressed when not needed.

3. **Likely payoff**

   By clearly prioritizing and suppressing information, the system can enhance the wearer's ability to follow conversations without feeling overwhelmed. This will lead to a more trusting and reliable experience, which is critical for daily use in noisy environments or complex social settings.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
