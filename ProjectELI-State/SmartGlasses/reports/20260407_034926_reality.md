# Reality-Checked Directions

## Subtitle Placement: feasible now
**Current Context**: 
- The glasses need to remain socially acceptable and readable in motion.
- The subtitle should be clear, fast, and stable enough for the wearer to trust it in live conversation.

**Reasoning**:
- Given that the glasses are V1 frame-touch-only and heavy processing is done on the phone, real-time display of subtitles can currently be achieved without excessive latency or complexity. 
- The existing `TranscriptLab` test app provides a foundation for ensuring subtitle placement does not become distracting.
- The core constraint here is to ensure subtitles remain readable in noisy environments and do not cause social awkwardness.

## Confidence Display: feasible now
**Current Context**: 
- The system needs to maintain trust by clearly displaying confidence levels, which can help the wearer understand when they should pay more attention.
- Current tests aim to balance clarity with providing useful feedback without overwhelming the user.

**Reasoning**:
- With the `TranscriptLab` app already in place, we can iteratively test different confidence display formats (label only, label + short reason, score + label) and choose the best one based on real-world use.
- This involves defining clear candidates for each format, testing them with users, and refining as necessary.

## Memory/Cache Policy: feasible now
**Current Context**: 
- The system should remember names, faces, and prior context without creating corrupted recall or invading privacy.
- Early versions rely heavily on phone processing but need to ensure that local caching is used judiciously.

**Reasoning**:
- Given the current focus on core deepening and avoiding broad feature expansion, we can start by caching minimal necessary data locally.
- The `TranscriptLab` app can help validate memory policies through real-time testing of face/name recall behavior.

## Phone/Cloud Boundary: feasible now
**Current Context**: 
- Heavy processing should primarily happen on the phone to reduce battery drain and thermal pressure.
- Cloud usage is optional where it adds clear value without introducing unacceptable latency or privacy concerns.

**Reasoning**:
- The existing `TranscriptLab` app provides a framework for testing local vs cloud-based processing decisions.
- We can experiment with different levels of cloud dependency and choose the optimal balance that meets the core attractors while respecting battery and thermal constraints.

## Visual Hierarchy: feasible now
**Current Context**: 
- Display behavior should remain socially acceptable while still being readable in motion and noise.
- The system needs to ensure that subtitles do not overwhelm the wearer, providing just enough information without causing distraction or social awkwardness.

**Reasoning**:
- With `TranscriptLab` serving as a test bed, we can iteratively refine subtitle placement and visual hierarchy to ensure they meet the core attractors of real-time clarity and low-friction assistance.
- This involves defining clear candidates for subtitle placement (e.g., corner of eye, bottom center) and testing their effectiveness in different scenarios.

## Summary
Based on the current project inputs, the directions related to subtitle placement, confidence display, memory/cache policy, phone/cloud boundary, and visual hierarchy are feasible now. Each area can be iteratively refined using the existing test framework provided by `TranscriptLab`, ensuring that we stay aligned with the core attractors and constraints of the SmartGlasses project.
