### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Improving subtitle placement rules ensures that subtitles remain clear, readable, and non-distracting, which is critical for maintaining trust in real-time interactions.

2. **What small change unlocks it**
   - Define two fixed subtitle placement modes: one for low confidence states (e.g., uncertain or rare mentions) and another for high confidence states (e.g., frequent speakers).

3. **Likely payoff**
   - By establishing clear rules, the system can provide more reliable and stable subtitles, reducing cognitive load on the wearer and enhancing trust in real-world interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

2. **What small change unlocks it**

3. **Likely payoff**

4. **Immediate next probe**

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By refining the local memory threshold for face/name recall, we can ensure that names and faces are remembered with high confidence over time, while avoiding unnecessary data storage. This helps in maintaining a clean and reliable memory cache, which is crucial for trust and consistency.

2. **What small change unlocks it**

   Define a policy where new faces and names are automatically linked to existing person-memory objects based on visual evidence, but only if the confidence score exceeds a certain threshold (e.g., 0.75). This ensures that only well-recognized entities are stored locally, reducing noise and improving lookup accuracy.

3. **Likely payoff**

   Implementing this policy will reduce false positives in memory recall, leading to more reliable and accurate face/name recognition. It will also help in maintaining a smaller but more useful cache of frequently encountered individuals, thus conserving storage space and improving overall system performance.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that V1 focuses on delivering essential and low-latency assistive behaviors. This helps maintain the balance between privacy and usefulness by keeping sensitive memory tasks local where possible.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing or face/name recall lookup. For example, define a rule that live subtitles stay phone-local to reduce latency and battery drain, while face/name recall can use cloud fallbacks when needed.

3. **Likely payoff**

   This change will help V1 maintain low-latency, high-trust behavior by keeping critical subtitle processing on-device. It also allows for more robust memory support without compromising real-time responsiveness, thus strengthening the core attractors of real-time clarity and memory trust.

4. **Immediate next probe**
   - Define the cloud fallback boundary for live subtitle processing to stay phone-local, ensuring real-time quality and minimizing battery drain.

This pay-off directly aligns with the core attractor of low-friction assistance by making it easier for the wearer to follow conversations.
