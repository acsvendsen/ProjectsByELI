# Reality Check for SmartGlasses

## Feasibility Assessments Based on Current Project Inputs

### Subtitle Placement: feasible now
- **Current State**: The `TranscriptLab` app is being used to validate subtitle placement and readability.
- **Constraints**: Must remain socially acceptable, readable in motion, and stable enough for trust.
- **Reasoning**: Given the real-time transcript capabilities already validated in `TranscriptLab`, placing subtitles on-screen can be designed to avoid distraction while maintaining clarity. The current prototype is sufficient to explore different placements without requiring advanced AR or complex UI.

### Confidence Display: feasible now
- **Current State**: Using a simple label for confidence and potentially adding short reasons.
- **Constraints**: Must balance between clear feedback and avoiding overloading the wearer.
- **Reasoning**: The `TranscriptLab` app has basic confidence display functionality that can be refined to provide helpful, non-overwhelming information. This aligns with the core deepening mode of improving daily-use value.

### Memory/Cache Policy: feasible now
- **Current State**: Initial face/name memory is being cached on the phone.
- **Constraints**: Must ensure privacy and trustworthiness without overloading the user’s memory.
- **Reasoning**: The existing setup for caching face/name data can be optimized to balance local storage with cloud support. This will help in maintaining a useful yet non-intrusive memory feature.

### Phone/Cloud Boundary: feasible now
- **Current State**: Heavy processing is being done on the phone, with optional cloud support.
- **Constraints**: Must ensure that critical functionality works offline while leveraging cloud where beneficial.
- **Reasoning**: The `TranscriptLab` app already demonstrates a clear path for separating local and cloud processing. This separation can be refined to ensure that memory lookups and confidence displays remain functional even when the phone is offline.

### Visual Hierarchy: feasible now
- **Current State**: Initial display controls are in place, focusing on clarity over feature density.
- **Constraints**: Must avoid distraction while ensuring subtitles and prompts are easily readable.
- **Reasoning**: The `TranscriptLab` app’s UI design can be iterated to improve visual hierarchy. This includes making sure subtitles are legible and distinct from other elements.

### Core Deepening Over Sprawl: feasible now
- **Current State**: Focusing on improving subtitle clarity, memory support, and confidence display.
- **Constraints**: Must avoid broad feature expansion that distracts from core mission.
- **Reasoning**: The project inputs strongly emphasize core deepening. Improvements in subtitle quality, memory trust, and visual UX are the highest priority at this stage.
