# Reality Check

## Subtitle Placement
- **Subtitle Clarity Feasibility**: Given the focus on real-time clarity and stability (attractor: `subtitle_clarity`), placing subtitles directly below the speaker's face or slightly above their mouth would be most effective. This ensures they are easily readable and do not distract from the conversation flow.
  - **Reasoning**: Direct placement ensures minimal latency between spoken words and displayed text, enhancing trust in real-time communication.

- **Visual Hierarchy Feasibility**: Subtitles should prioritize clarity over complexity. A simple display with minimal visual elements (e.g., a white box or transparent overlay) would maintain readability without overwhelming the wearer.
  - **Reasoning**: Complexity can detract from readability and introduce visual clutter, especially in noisy environments.

## Confidence Display
- **Confidence Display Feasibility**: The confidence display should use labels only for simplicity. A numeric score could be too distracting and might not provide clear feedback on reliability.
  - **Reasoning**: Labels (e.g., "High" or "Low") are more straightforward and can easily convey the certainty level without adding unnecessary complexity.

## Memory/Cache Policy
- **Memory Trust Feasibility**: Implement a cache policy that stores face/name memory for quick lookup but also allows occasional cloud sync to ensure accuracy. This strikes a balance between local performance and remote correction.
  - **Reasoning**: Frequent updates via the phone can help maintain accurate data, while on-device caching ensures low-latency access.

## Phone/Cloud Boundary
- **Phone-First Runtime Feasibility**: Given the current constraint of `phone_first_runtime` (hard), all heavy processing should remain on the phone. Cloud support is optional and only used where it adds clear value.
  - **Reasoning**: Keeping critical operations local reduces battery drain and ensures real-time response, which is crucial for subtitle clarity.

## Visual Hierarchy
- **Visual Hierarchy Feasibility**: The visual hierarchy should prioritize subtitles over other elements to ensure they are the primary focus. This can be achieved by using a transparent overlay with minimal borders.
  - **Reasoning**: By prioritizing subtitles, we ensure that the most critical information is always visible and easy to read.

## Low-Friction Assistance
- **Low-Friction Feasibility**: Ensure one-line prompts are simple and unobtrusive. These should be displayed briefly in a non-distracting manner.
  - **Reasoning**: Continuous prompts can disrupt natural conversation, so they should only appear when necessary to avoid social awkwardness.

## Privacy vs Usefulness
- **Privacy Feasibility**: Implement privacy features such as face blurring and minimal data retention. Ensure that the system does not store unnecessary information or invade user privacy.
  - **Reasoning**: High privacy standards are essential for maintaining trust and ensuring the technology is used responsibly.

## Discreet UX vs Visual Clarity
- **Discreet UX Feasibility**: Use subtle visual cues to indicate confidence levels. Avoid overly complex interfaces that might be distracting.
  - **Reasoning**: A discreet approach ensures the technology remains unobtrusive while still providing useful information.
