### Improvement 1: Enhanced Subtitle Placement Rules

**Why it benefits the core:** 
Improper subtitle placement can interfere with natural conversation flow, leading to missed social cues or increased cognitive load on the wearer.

**What small change unlocks it:**
Implement a dynamic subtitle placement rule that adjusts based on the context and confidence level of the spoken text. For instance:
- High-confidence subtitles should be placed at the bottom right corner (out of direct eye movement).
- Low-confidence subtitles should be more prominent, appearing in the top center to ensure they are quickly noticed.

**Likely payoff:**
Better subtitle visibility without disrupting natural conversation flow, enhancing user experience and trust.

**Immediate next probe:**
Test different placement rules during noisy environments using real-world conversational data. Evaluate which placements help with understanding while minimizing distraction.

### Improvement 2: Confidence Label Plus Short Reason Format

**Why it benefits the core:** 
Confidence labels alone can be ambiguous without additional context, leading to confusion about why a memory or name lookup is being suggested.

**What small change unlocks it:**
Introduce a confidence label plus a short reason format. For example:
- "High": "Sarah was mentioned earlier."
- "Medium": "Last seen in this meeting."
- "Low": "Possibly new face."

**Likely payoff:**
Increased user trust and understanding of the system's recommendations, reducing misinterpretation.

**Immediate next probe:**
Rank memory suggestions with confidence labels plus short reasons. Experiment with different formatting (e.g., text color, icon) to see which enhances clarity without cluttering the display.

### Improvement 3: Phone-Local Cache for Name Recall

**Why it benefits the core:** 
Name recall must be fast and reliable, but storing all names locally could drain battery or storage. A balanced approach is needed.

**What small change unlocks it:**
Implement a phone-local cache for recently seen faces and names, with periodic updates to prevent staleness. For example:
- Cache new entries for 24 hours.
- Update the cache every 5 minutes during active sessions.

**Likely payoff:**
Faster name recall with minimal impact on battery life or storage, enhancing overall usability.

**Immediate next probe:**
Evaluate phone-local caching policies (e.g., cache size, update frequency) using real-world user data. Compare performance against cloud fallback strategies to determine the best balance.
