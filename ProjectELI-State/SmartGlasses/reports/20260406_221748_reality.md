## Reality Check Summary

### Subtitle Placement
**Feasible Now**: Given that the glasses hardware remains simple and the interaction is frame-touch only, we can focus on placing subtitles where they are most readable without becoming distracting. Initial tests in `TranscriptLab` should allow us to evaluate placement effectiveness.

### Confidence Display
**Feasible Now**: With the `TranscriptLab` app available for testing confidence display, we can experiment with different formats (label only, label + short reason, or score + label) and choose one that builds trust. This is crucial for maintaining user acceptance and trust in the system's accuracy.

### Memory/Cache Policy
**Feasible Now**: We can start by caching face/name memory on the phone to ensure quick lookup without significant battery drain. The `TranscriptLab` app allows us to test different cache sizes and timing strategies to find a balance between utility and resource usage.

### Phone/Cloud Boundary
**Likely Waste of Time**: Given that V1 is phone-first, we should focus on ensuring local processing is robust before considering cloud integration. Early tests in the `TranscriptLab` app can help determine when cloud assistance would be most beneficial without overcomplicating the current implementation.

### Visual Hierarchy
**Feasible Now**: We need to ensure subtitles and one-line prompts are visually distinct but not overly distracting. Initial design iterations within the `TranscriptLab` app should allow us to prototype different visual hierarchies and refine based on user feedback (if any is needed).

### Core Deepening vs Sprawl
**Core Deepening Over Sprawl**: The project should continue to focus on improving subtitle quality, memory trust, and confidence behavior. Broad feature expansion without clear justification from current constraints should be avoided.

### Constraint Pressure
**Feasible Now**: Surface early the real-world limitations like battery, latency, privacy, and usability. Use these constraints to guide decisions in `TranscriptLab` and subsequent design iterations.

### Interaction Constraints
**Feasible Now**: The frame-touch-only interaction model is well-defined. Implementing this in `TranscriptLab` will help ensure that any new features align with the V1 user experience goals.

## Assumptions Needing Evidence

- **Subtitle Placement**: Further testing within `TranscriptLab` is needed to confirm where subtitles are most readable without being distracting.
- **Confidence Display**: More detailed testing and user feedback may be required to refine the confidence display format for maximum trust.
- **Memory/Cache Policy**: Performance metrics from initial tests in `TranscriptLab` should inform more precise cache strategies.
- **Visual Hierarchy**: User testing or mockup reviews could help validate the chosen visual hierarchy.

By focusing on these areas and grounding our decisions in concrete repo signals and project constraints, we can ensure that each new direction is feasible and aligns with the core mission of SmartGlasses.
