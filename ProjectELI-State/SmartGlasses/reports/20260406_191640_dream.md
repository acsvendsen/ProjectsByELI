### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring that subtitles are placed in a stable, predictable position enhances trust and readability. By defining consistent placement rules, the system can reduce visual distractions and ensure that the wearer can always rely on the subtitles for understanding.

2. **What small change unlocks it**

   Define a default subtitle placement rule that centers subtitles at the bottom of the field of view, with an adjustable margin to accommodate different head movements and gaze directions without causing distraction.

3. **Likely payoff**

   This adjustment will reduce the likelihood of subtitles being occluded by objects in the environment or during rapid head movements. It also simplifies the user experience by maintaining a consistent visual anchor for the subtitles, thereby enhancing overall understanding and trust.

4. **Immediate next probe**
   - Define the default subtitle placement rule to center subtitles at the bottom of the field of view with a 10% margin for head movements.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format, we can ensure that users have a clear understanding of how reliable each piece of information is. This enhances trust in the system and ensures that the wearer does not interpret uncertain information as definitive.

2. **What small change unlocks it**

   Define a specific format for confidence objects that includes a numeric score, label, and short reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format clearly communicates the certainty level and source of the information.

3. **Likely payoff**

   A clear and concise confidence display will help users distinguish between highly reliable and less certain information, reducing confusion and increasing trust. Users can better understand when they should rely on the system's suggestions or seek additional context themselves.

4. **Immediate next probe**
   - Define the numeric score format for the confidence display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local memory threshold for face/name recall, we ensure that the glasses can quickly and reliably retrieve relevant memories without overloading the phone or cloud with unnecessary data transfers. This enhances the real-time responsiveness of name recall, making it faster and more trustworthy during conversations.

2. **What small change unlocks it**

   Define a local cache size limit for person-memory objects on the phone, setting it to 5-10 recent encounters per person by default. This ensures that frequently encountered people are quickly accessible locally while minimizing data overhead.

3. **Likely payoff**

   Implementing this cache size limit will significantly improve the speed and reliability of face/name recall during conversations. It reduces latency by keeping commonly encountered faces and names in local memory, ensuring faster lookups without overwhelming the phone or cloud with frequent requests.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Sticking to a phone-first architecture ensures that V1 remains simple, reliable, and focused on delivering essential subtitle and memory support without overloading the glasses hardware. By keeping heavy processing on the phone, we can leverage cloud capabilities where they are clearly justified while minimizing battery and thermal strain.

2. **What small change unlocks it**

   Define a clear boundary for what runs locally versus remotely by explicitly setting which tasks fall back to the cloud and which stay local on the phone. For example, define one task such as live subtitle processing to run entirely on the glasses until proven otherwise.

3. **Likely payoff**

   By rigorously defining this boundary early, we can ensure that V1 remains robust and reliable. This focus allows for more efficient development cycles, clearer UI designs, and a smoother user experience without introducing unnecessary complexity or latency issues.

4. **Immediate next probe**
   - Define the phone/cloud fallback boundary for live subtitle processing to run entirely on the glasses until proven otherwise.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**
   Improving subtitle placement rules can enhance the wearer's trust in the subtitles by ensuring they are clear and stable, which is crucial for real-time understanding.

2. **What small change unlocks it**
   Define two subtitle placement rules: one that keeps subtitles at a fixed position on the screen to maintain stability, and another that slightly adjusts their position based on gaze direction but only when confidence in speaker identity is high.

3. **Likely payoff**
   By providing stable yet context-aware subtitle placement, users will feel more confident in understanding conversations, leading to better overall comprehension and less distraction during interactions.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
