### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules in V1 helps maintain the wearer's trust by keeping subtitles readable and unobtrusive during live conversations. Stable placement ensures that the subtitles do not constantly shift, which can lead to distractions and a breakdown of trust.

2. **What small change unlocks it**

   Define three fixed subtitle placement rules: 
   - Top center for high-confidence text
   - Bottom center for medium-confidence text
   - Hidden or off-screen for low-confidence text

3. **Likely payoff**

   By defining stable subtitle placement rules, the system will be less likely to distract the wearer during live interactions. This consistency in placement can help maintain trust and ensure that the subtitles are always readable when needed, without causing visual clutter.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear, concise format that combines a numeric score with a label and short reason, we can enhance trust in the system's memory support and overall reliability. This clarity ensures that the wearer understands the level of certainty behind each piece of displayed information, which is crucial for maintaining their trust and effective use of the glasses.

2. **What small change unlocks it**

   Introduce a new confidence format that presents the certainty score as "Score X%" followed by a label such as "High", "Medium", or "Low" and a short reason like "Seen recently" or "Weak match". For example, if the system is 84% certain about a name being correctly remembered, it would display: "Score 0.84 High + Seen recently".

3. **Likely payoff**

   This refined confidence format will help build trust by making the wearer aware of how confident the system is in its memory and predictions. It also ensures that the information presented is clear and actionable, leading to more accurate and reliable interactions.

4. **Immediate next probe**
   - Define the label style for the confidence display as either "High", "Medium", or "Low".

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that likely new-person memories are automatically captured and reinforced, reducing the likelihood of needing cloud fallbacks for name recall or face recognition. This strengthens trust by ensuring that common interactions do not require network access, aligning with the core attractor of "Trustworthy memory support."

2. **What small change unlocks it**

   Define a local cache size limit for new-person memories on the phone, specifically for names and faces. This limit should be set to ensure automatic capture without overwhelming the phone's resources.

3. **Likely payoff**

   By setting a clear threshold for local caching of likely new-person memories, we reduce latency in memory recall and reinforce trust by ensuring that common interactions are handled locally. This improves the overall user experience by minimizing interruptions from cloud requests and enhancing the system's reliability.

4. **Immediate next probe**

   Define one local-cache size limit (in MB) for names and faces to ensure automatic capture without overwhelming phone resources, balancing memory use with responsiveness.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus falling back to cloud, we can ensure that critical real-time subtitle processing remains stable and fast, while less urgent tasks like memory archive sync or conversation snapshot upload benefit from potentially richer but slower cloud processing.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary, such as live subtitle processing, which should remain phone-local to preserve real-time performance and stability.

3. **Likely payoff**

   By keeping live subtitle processing on the phone, we ensure that subtitles are always up-to-date and reliable, reducing latency and improving trust. This also allows for more efficient use of cloud resources for less time-critical tasks, optimizing battery usage and overall system performance.

4. **Immediate next probe**

   Define one task-specific cloud fallback boundary where live subtitle processing falls back to the cloud only as a last resort if the phone is under extreme thermal or battery constraints.
