# Reality Check Summary

## Subtitle Placement: Feasible Now

- **Subtitle clarity (real-time):** The current implementation in `TranscriptLab` should focus on achieving clear, stable subtitles that remain readable in live conversation. This is feasible now given the simplicity of the hardware and the phone-first approach.
  
  - **Reasoning:** The `LiveTranscriptTestView.swift` already provides a basic framework for displaying transcripts. Further optimization of text stability and readability can be achieved without heavy GPU or on-glasses processing, making it a low-complexity change.

## Confidence Display: Feasible Later

- **Confidence format (label + short reason):** The current implementation in `TranscriptLab` should focus on basic confidence display. Implementing more complex confidence formats like score + label can be done later when the basic functionality is solidified.
  
  - **Reasoning:** The core attractor of real-time subtitle clarity and memory trust is currently prioritized. Adding a detailed confidence format requires additional complexity that can be deferred until the basic usability is proven.

## Memory/Cache Policy: Feasible Now

- **Local caching for face/name recall:** Local caching on the phone to manage face/name memory should be feasible now. This helps in providing fast and reliable name recall without overloading the cloud, aligning with the V1 real-world limits.
  
  - **Reasoning:** The current implementation already has a basic structure for handling transcripts and confidence displays. Adding local caching for memory can be done incrementally to maintain simplicity.

## Phone/Cloud Boundary: Feasible Now

- **Phone-first processing (live transcript):** The phone should handle the primary processing of live transcripts, with cloud support being optional where clearly justified. This is feasible now given the current architecture.
  
  - **Reasoning:** The `TranscriptLab` app provides a reusable test bed for validating real-time transcript behavior on the phone. Enhancing this to include basic memory caching and confidence display can be done incrementally.

## Visual Hierarchy: Feasible Now

- **Subtitle and prompt visual hierarchy (subtitle vs one-line prompts):** Defining clear visual hierarchies for subtitles and one-line prompts is feasible now. This ensures that the user interface remains usable without overwhelming the wearer.
  
  - **Reasoning:** The current implementation in `LiveTranscriptTestView.swift` already provides a framework to display text. Adjusting the visual hierarchy can be done with minimal additional complexity.

## Feasibility Assessment

- **Subtitle Clarity (real-time):** Feasible Now
- **Memory Trust (trustworthy memory support):** Likely Waste of Time for now, as it requires more development before core functionality is solidified.
- **Low-friction Assistance (low-friction assistance):** Feasible Now, focusing on basic one-line prompts can be done incrementally.

### Additional Thoughts

- The `TranscriptLab` app serves as a critical test bed for real-time subtitle clarity. Ensuring that subtitles remain clear and stable is crucial before moving to more complex features.
- Memory caching and confidence display should be deferred until the core functionality of subtitles and memory support are well-defined and validated.

By focusing on these specific areas, the project can maintain its core mission while ensuring that critical usability elements are prioritized.
