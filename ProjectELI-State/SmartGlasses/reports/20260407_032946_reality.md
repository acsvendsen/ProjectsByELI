# Reality-Checked Directions

## Subtitle Placement: Feasible Now

### Reasoning:
- **Current Implementation**: The `TranscriptLab` app provides a clear test bed for live subtitles, ensuring that the placement can be optimized for readability and distraction.
- **Concrete Constraints**: The glasses should remain lightweight and socially acceptable (hard constraint).
- **Feasibility**: With the current setup of the `TranscriptLab` app, we can experiment with different subtitle placements to ensure they are clear and do not distract the wearer. Testing can involve adjusting text size, font style, and placement within the field of view.

### Conclusion:
**Feasible Now**

## Confidence Display: Feasible Now

### Reasoning:
- **Current Implementation**: The `TranscriptLab` app is designed to test confidence display directionally.
- **Concrete Constraints**: Confidence must be represented in a way that builds trust (hard constraint).
- **Feasibility**: We can experiment with different formats for confidence display, such as labels only, label + short reason, or score + label. Testing these variations will help us determine the best approach.

### Conclusion:
**Feasible Now**

## Memory/Cache Policy: Likely Waste of Time

### Reasoning:
- **Current Implementation**: The `TranscriptLab` app focuses on live transcription and confidence display rather than memory caching.
- **Concrete Constraints**: Face/name recall must expose uncertainty clearly (hard constraint).
- **Feasibility**: While memory caching could be useful, the current focus is on core functionality. Early iterations should prioritize real-time behavior over memory caching to ensure trust and usability.

### Conclusion:
**Likely Waste of Time**

## Phone/Cloud Boundary: Feasible Later

### Conclusion:
**Feasible Later**
