### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the readability and stability of subtitles, ensuring they are clear and unobtrusive during live interactions. This will help maintain trust in the system's real-time capabilities and ensure that the wearer can focus on understanding the conversation without distractions.

2. **What small change unlocks it**

   Define three fixed subtitle placement rules for different confidence levels: 
   - Always visible at a consistent height above the speaker's face.
   - Temporarily lowered or hidden if high-confidence matches are detected to avoid overloading the viewer.
   - Hidden completely if low-confidence matches are detected, reducing visual clutter.

3. **Likely payoff**

   By setting clear placement rules based on confidence levels, the system can balance readability with minimizing distractions. This will improve user trust in the subtitle's accuracy and relevance, enhancing overall interaction quality without overwhelming the wearer.

4. **Immediate next probe**
   - Define a fixed subtitle placement rule that keeps subtitles always visible at a consistent height above the speaker's face.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a numeric score combined with a label and short reason, we can enhance trust in the system's reliability without overwhelming the user. This approach ensures that users understand the level of certainty behind each piece of memory or subtitle information, leading to more informed interactions.

2. **What small change unlocks it**

   The small change involves updating the confidence display format from a simple label to include both a numeric score and a short reason. For example, instead of just "Seen recently," we could show "0.84 (High, Seen last week)." This provides more nuanced feedback that can be trusted by the user.

3. **Likely payoff**

   The likely payoff is increased trust in the system's memory and subtitle accuracy. Users will feel better informed about the reliability of each piece of information provided, leading to fewer misunderstandings and more confident interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - Improving memory cache policies will enhance the trustworthiness of name and face recall, ensuring that the system correctly reinforces new encounters while maintaining a stable and uncluttered memory space.

2. **What small change unlocks it**
   - Define a recency-based eviction policy where older memories are purged less frequently than recent ones, but still given some chance to be reinforced over time.

3. **Likely payoff**
   - This change will help in maintaining a balance between rich memory and fast lookup by ensuring that the most relevant and recently encountered names and faces remain accessible while preventing the cache from becoming overly cluttered with outdated information.

4. **Immediate next probe**
   - Set a recency threshold of 7 days for local caching of person memories, where less recent encounters are cached but given lower priority in lookups compared to more recent ones.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that V1 focuses on delivering essential real-time subtitle clarity and memory support without overburdening the glasses hardware. This balance helps maintain low latency and battery efficiency, which are critical for the wearer's trust and daily-use experience.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing remains phone-local while transcript cleanup tasks can fall back to cloud.

3. **Likely payoff**

   By keeping real-time subtitle processing local, we can achieve faster response times and more stable performance, which are essential for the wearer's trust in the system. Transcript cleanup tasks that do not require immediate feedback can be offloaded to the phone or cloud as needed, balancing resource usage effectively.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
