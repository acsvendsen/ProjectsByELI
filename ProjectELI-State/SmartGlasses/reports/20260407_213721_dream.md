### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules helps ensure that subtitles remain clear, stable, and readable in live conversation, which directly supports the core attractor of real-time subtitle clarity. By defining specific placement rules based on confidence levels, we can reduce visual distractions while ensuring that critical information is always visible.

2. **What small change unlocks it**

   Define two to three subtitle placement rules for different confidence states: low (below 0.7), medium (between 0.7 and 0.9), and high (above 0.9). These rules will dictate where subtitles should appear based on the certainty of the transcription.

3. **Likely payoff**

   By implementing specific subtitle placement rules, we can ensure that subtitles are always visible when needed most—when they contain critical information—and reduce visual distractions during less crucial moments. This improves overall user trust and the reliability of the assistive feature in noisy environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   - Improving confidence display by using a clear, concise format that balances certainty with uncertainty will enhance trust in memory recall and subtitle accuracy. This clarity ensures that the wearer can differentiate between well-remembered information and less certain data.

2. **What small change unlocks it**
   - Define a specific confidence object format that combines a numeric score (e.g., 0.85), a label (e.g., "High"), and a short reason (e.g., "Seen recently"). This will provide the wearer with immediate, actionable information about the reliability of the memory.

3. **Likely payoff**
   - By using this format, the system will be more transparent about its certainty levels, reducing confusion and increasing trust. The wearer will feel that the assistant is reliable but not overly confident in less certain scenarios, which helps maintain a balance between utility and privacy.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

Improving the local memory cache size threshold helps ensure that critical face and name information is readily available to the wearer without overwhelming the phone's storage or battery. This enhances the trustworthiness of memory support, allowing the system to provide reliable one-line prompts and context cues when needed.

2. **What small change unlocks it**

Define a local memory cache size limit for names and faces that balances storage efficiency with fast lookup performance. For example, set a threshold such that any person encountered more than 10 times in the last week is stored locally, while less frequent encounters are only cached if they have high confidence or recent context.

3. **Likely payoff**

By setting a local memory cache size limit, we can ensure that critical names and faces remain available for fast lookup without excessive storage use. This will help maintain the trustworthiness of memory support, allowing the system to provide reliable one-line prompts and context cues when needed, thus enhancing overall user experience.

4. **Immediate next probe**
   - Set a local memory cache size limit such that any person encountered more than 10 times in the last week is stored locally.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud for live subtitle processing, we ensure that the most critical and latency-sensitive tasks remain on-device. This improves the real-time quality of subtitles, enhancing user trust and daily-use value.

2. **What small change unlocks it**

   Define one explicit task-specific rule: For live subtitle processing, any audio input with a confidence score above 0.9 will be processed locally on the phone without fallback to cloud, unless forced by limited local resources or high thermal conditions.

3. **Likely payoff**

   This refined rule ensures that critical subtitles are always available in near-real-time, improving trust and reducing latency. It also helps manage battery usage efficiently while maintaining high-quality subtitle delivery.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the most critical information is always easily readable while minimizing distractions. This balance enhances the wearer's understanding without overwhelming them with too much text, thereby strengthening both subtitle clarity (subtitle_clarity) and low-friction assistance (low_friction_assistance).

2. **What small change unlocks it**

   Define a clear visual priority rule that gives subtitles higher precedence over one-line support when confidence in the subtitle content is high. This can be achieved by setting a higher z-index or a more prominent font size for subtitles compared to one-liners.

3. **Likely payoff**

   By ensuring that subtitles are prioritized and easily readable, users will have less cognitive load when following live conversations. This leads to improved real-time understanding (subtitle_clarity) and reduced need for additional prompts (low_friction_assistance), creating a more seamless and useful experience.

4. **Immediate next probe**
