# Reality Check Summary

## Subtitle Clarity: Real-time subtitle clarity
- **feasible now**: Ensure the subtitles are clear, fast, and stable enough to maintain trust in live conversation. This can be achieved through initial testing with `TranscriptLab` on a real device to assess readability and stability.

## Memory Trust: Trustworthy memory support
- **feasible later**: Implement face/name recall that avoids overconfidence or creating false memories. Use the existing phone-side test framework to iteratively refine this feature. Ensure any memory system includes clear indicators of confidence levels to avoid misleading the wearer.

## Low-friction Assistance: Low-friction assistance
- **feasible now**: Focus on delivering one-line prompts and subtitles through frame-touch interactions. This aligns with the current V1 interaction constraints. Use `TranscriptLab` to prototype and test these features, ensuring they are low-friction and provide clear value.

## Privacy vs Usefulness: Privacy vs usefulness
- **assumptions needing evidence**: Ensure that any memory or confidence display does not infringe on privacy. Test with users to understand their comfort levels with the system remembering names and faces without creating overconfident or false memories.

## Latency vs Richness: Latency vs richness
- **feasible now**: Prioritize real-time subtitle quality and minimal latency for initial V1 functionality. Use `TranscriptLab` to validate that subtitles feel near-real-time, which is critical for trust and utility in noisy environments.

## Discreet UX vs Visual Clarity: Discreet UX vs visual clarity
- **feasible now**: Design subtitles and one-line prompts to be socially acceptable while ensuring readability during motion. This can be tested using the prototype in `TranscriptLab` with a small user group.

## Frame-touch-only V1 interaction: Frame-touch-only V1
- **feasible now**: Ensure all interactions are through frame touches, as this aligns with current constraints and design principles. Use `TranscriptLab` to validate that frame-touch controls provide the necessary functionality without adding unnecessary complexity.

## Phone-first runtime: Phone-first runtime
- **feasible now**: Keep heavy processing on the phone while using the cloud for optional background tasks. This can be tested through ongoing development of the `TranscriptLab` app, ensuring that it mirrors the future glasses experience as closely as possible.

## Core-deepening over sprawl: Core-deepening over sprawl
- **feasible now**: Focus on improving subtitle quality and memory trust rather than broad feature expansion. Use the existing project documentation to guide prioritization towards these core areas.

## V1 Real-world Limits: V1 real-world limits

## V1 Architecture Direction: V1 architecture direction
