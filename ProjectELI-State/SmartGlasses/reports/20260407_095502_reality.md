# Reality Check

## Subtitle Placement: feasible now
- **Subtitle placement** should focus on ensuring clear, readable subtitles that do not distract the wearer. Given the current hardware constraints (frame-touch-only V1 and simple glasses), placing subtitles at the bottom of the frame or slightly off-center would be feasible. This approach minimizes distraction while still providing useful information.

## Confidence Display: feasible now
- **Confidence display** can use a simple numeric score (e.g., 0-5) to indicate the reliability of the subtitle or memory recall. This is feasible now because it can be implemented as a text label on the screen, which aligns with the frame-touch interaction model and does not require complex UI elements.

## Memory/Cache Policy: feasible now
- **Memory caching** should initially focus on storing recent interactions and names for quick lookup. Given the constraints of early V1 (frame touches only), caching the last few conversations and names would be practical. This can be implemented using local storage on the phone, which respects the current architecture direction.

## Phone/Cloud Boundary: feasible now
- **Phone-first processing** is a hard constraint, so any memory or lookup behavior should primarily happen on the phone. The cloud can be used for heavy lifting where clearly justified by performance benefits. This approach aligns with the current V1 design and respects battery and thermal constraints.

## Visual Hierarchy: feasible now
- **Visual hierarchy** should prioritize clarity over feature density to avoid overwhelming the wearer. Simple, clean placement of subtitles and memory prompts would be most effective. For instance, subtitles at the bottom center or slightly off-center could work well with a clear confidence label nearby.

### Summary

1. **Subtitle Placement**: Place subtitles at the bottom of the frame or slightly off-center.
2. **Confidence Display**: Implement using a simple numeric score (0-5) for trust indication.
3. **Memory/Cache Policy**: Cache recent interactions and names on the phone for quick lookup.
4. **Phone/Cloud Boundary**: Ensure heavy processing happens on the phone, with cloud use only where justified.
5. **Visual Hierarchy**: Keep UI clean and focused to avoid distraction.

These approaches are feasible now given the current project constraints and should help improve real-world usability without overcomplicating the initial implementation.
