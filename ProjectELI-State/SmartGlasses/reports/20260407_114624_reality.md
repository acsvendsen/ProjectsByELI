# Reality-Checked Directions

## Subtitle Clarity - Feasible Now
### Reason:
The `TranscriptLab` app indicates that live subtitle behavior is currently being tested and validated on a phone-first basis. Given the focus on real-time clarity, this aligns with current project constraints and attractors.

## Memory Trust - Feasible Later
### Reason:
Implementing face/name memory requires balancing privacy concerns against utility. While confidence objects and reinforcement are already considered, expanding to full memory support is constrained by current battery and thermal limits. Ensuring that the system does not create corrupted recall will require careful implementation as the project matures.

## Low-Friction Assistance - Feasible Now
### Reason:
One-line prompts can be implemented through frame-touch interactions with minimal complexity. These low-friction assistance features align well with V1 interaction constraints and core attractors.

## Privacy vs Usefulness - Likely Waste of Time
### Reason:
Creating a feature to manage privacy settings or user control over data collection will likely not produce high daily-use value in the current V1. The project is focused on core assistive functions, and early implementation of such features might be premature given the constraints.

## Latency vs Richness - Feasible Now
### Reason:
The `TranscriptLab` app is currently optimizing for real-time subtitle clarity. This means that efforts to improve memory recall without impacting live subtitle performance are feasible now as long as they do not introduce significant latency.

## Discreet UX vs Visual Clarity - Feasible Now
### Reason:
Implementing subtitle placement and visual hierarchy in `TranscriptLab` can help determine the best user experience. Ensuring that subtitles remain readable while being discreet is a priority for V1, and early implementation aligns with current constraints.

## Frame-Touch-Only V1 Interaction - Feasible Now
### Reason:
The project explicitly states that frame-touch interactions are preferred in V1. Implementing this constraint through the `TranscriptLab` app ensures that the initial design is aligned with future glasses hardware.

## Phone-First Runtime - Feasible Now
### Reason:
Given the current focus on phone-first processing, implementing core functionality such as subtitle generation and memory support within the `TranscriptLab` app aligns well with V1 constraints.

## Core-Deepening Over Sprawl - Feasible Now
### Reason:
The project is currently focused on deepening core functions. Implementing improvements in subtitle clarity, memory support, and confidence behavior are aligned with this approach.

## Constraint Pressure - Feasible Now

Surface battery, latency, privacy, and usability limits early can be achieved by continuously testing features within the `TranscriptLab` app. This ensures that weak directions are identified and addressed promptly.
