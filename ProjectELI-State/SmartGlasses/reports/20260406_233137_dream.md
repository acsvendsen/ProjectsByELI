### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules will reduce visual distraction and improve the wearer's trust in the subtitles during live conversations. Stable placement allows the wearer to focus on the conversation without being distracted by frequent repositioning of text, which can degrade the overall user experience.

2. **What small change unlocks it**

   Define a single fixed position for subtitles that works across different confidence states, ensuring consistent placement regardless of the speaker's volume or clarity.

3. **Likely payoff**

   By defining stable subtitle placement rules, the system will provide a more predictable and reliable assistive feature, reducing cognitive load and increasing the wearer's trust in the subtitles. This stability also helps in maintaining focus during conversations, enhancing overall understanding and engagement.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

   By refining the confidence display to use a clear numeric score, label, and short reason, we can enhance the wearer's trust in the system's judgments without overwhelming them with complex or ambiguous information. This clarity helps maintain a balance between rich assistance and low social friction.

2. **What small change unlocks it**

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache threshold for face/name memory objects enhances the system's ability to provide fast, reliable recall without overloading the phone or cloud with unnecessary data. This ensures that critical memories are available locally, reducing latency and improving overall trust by ensuring rapid access to key information.

2. **What small change unlocks it**

   Define a local cache threshold for face/name memory objects based on recent interaction frequency and recency. For example, if a person is seen multiple times in the last 30 minutes, their memory object should be retained locally with higher confidence.

3. **Likely payoff**

   By caching frequently encountered people’s memories locally, the system can provide faster and more reliable recall, reducing latency during critical interactions. This improves trust by ensuring that key information is readily available even when network conditions are poor or the phone is in low-power mode.

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that critical real-time processing happens on the device, maintaining low latency and preserving battery life. This will help in delivering consistent subtitle clarity and memory support without compromising on speed or user trust.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing as phone-local while setting a cloud fallback boundary for transcript cleanup. This distinction ensures that real-time responses are handled locally, reducing latency and preserving battery, while background tasks like cleaning up transcripts can leverage the cloud's computational power without affecting user experience.

3. **Likely payoff**

   By keeping live subtitle processing on the phone, we ensure that subtitles remain clear and stable in noisy environments, which is crucial for real-time understanding. Additionally, this approach will allow us to continuously improve subtitle quality through local optimization while leveraging the cloud for more intensive tasks like memory cleanup, ensuring a balance between performance and utility.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.
