## Reality Check for SmartGlasses Project Directions

### Subtitle Placement

**Feasibility:** Feasible now  
**Reasoning:** Given that the glasses are designed to be lightweight and socially acceptable, the subtitle placement should focus on areas where they can be read clearly without being overly distracting. Based on the current project inputs, frame touches in key positions like the temple or side of the glasses seem reasonable for initial testing. This allows for rapid iteration while ensuring the subtitles remain readable and do not interfere with normal wear.

### Confidence Display

**Feasibility:** Feasible now  
**Reasoning:** The confidence display should be simple yet effective to maintain trust in the system. A numeric score (0-100) or a label like "likely" could work well, coupled with a short reason for high-confidence cases. This approach keeps the UI clean while providing enough information to build user trust without overwhelming them.

### Memory/Cache Policy

**Feasibility:** Feasible now  
**Reasoning:** The memory policy should focus on caching relevant names and faces locally to ensure fast recall and reduce cloud dependency, which is critical given battery constraints. For initial testing, caching recently seen faces and names could be prioritized, with the option to extend this as more data shows what is most frequently needed.

### Phone/Cloud Boundary

**Feasibility:** Feasible now  
**Reasoning:** Given that V1 interaction remains frame touch-only, the phone should handle heavy processing like context lookup and memory reinforcement. The cloud can be used for less critical tasks where latency can be managed. This approach aligns with the current V1 architecture direction.

### Visual Hierarchy

**Feasibility:** Feasible now  
**Reasoning:** The visual hierarchy should prioritize subtitles over other UI elements to ensure they remain the primary focus, especially in noisy environments. Subtitles and one-line prompts should visually differ to avoid confusion. For example, subtitles could be displayed prominently at the top of the field of vision, while prompts appear more minimally below or beside them.

### Core Deepening vs Sprawl

**Feasibility:** Feasible now  
**Reasoning:** The project should continue focusing on improving subtitle quality, memory trust, and visual UX. Adding new modes or complex features without clear justification for V1 would distract from these core goals. Therefore, efforts to enhance subtitle clarity, refine confidence display, and improve local processing are aligned with the current core-deepening mode.

### Real-Time Subtitle Clarity

**Feasibility:** Feasible now  
**Reasoning:** The initial design should aim for clear, stable subtitles that can be trusted in live conversation. This is critical to building user trust and ensuring the product remains useful in noisy environments. Initial tests with `TranscriptLab` will provide valuable feedback on achieving this goal.

### Memory Support

**Feasibility:** Feasible now

The system should be designed to avoid making false promises of certainty, which could damage user trust. Initial tests will help identify the most effective ways to provide this support.
