### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining more prominent subtitle placement rules for different confidence states, we can ensure that subtitles remain clear and unobtrusive while still providing necessary assistance. This will enhance the wearer's understanding in noisy environments without overwhelming them.

2. **What small change unlocks it**

   Define two subtitle placement modes: a "default" mode with lower prominence and an "enhanced" mode for higher confidence states to improve readability during critical moments.

3. **Likely payoff**

   Improved subtitle visibility during key interactions will reduce misunderstandings and increase the wearer's trust in the system, especially in noisy or complex environments where clear understanding is crucial.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear label plus a short reason, the system can better convey its certainty level to the wearer in a concise and understandable manner. This improves trust by aligning the system's perceived reliability with its actual accuracy.

2. **What small change unlocks it**

   Define the confidence format as a combination of a numeric score (e.g., 0.84) plus a label (e.g., "High") followed by a short reason (e.g., "Seen recently").

3. **Likely payoff**

   This refined confidence display will help users understand the reliability of the system's outputs more intuitively, reducing misinterpretation and increasing overall trust in the assistant’s judgments.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By refining the local memory cache size, we ensure that critical information is retained for fast lookup without overwhelming the system or the wearer. This helps in maintaining a balance between rich memory support and low-friction UX.

2. **What small change unlocks it**

   Define a specific threshold for the phone's local cache to store face and name memories. For example, set a limit of 100 entries with recent interactions prioritized over older ones.

3. **Likely payoff**

   This approach ensures that common faces and names are quickly accessible during conversations, enhancing memory recall accuracy and reducing the need for frequent cloud lookups. It also helps in managing battery usage by limiting local storage overhead.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

3. **Likely payoff**
