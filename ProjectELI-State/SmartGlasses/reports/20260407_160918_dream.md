### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain the wearer's trust in the system by preventing visual distractions that could break their concentration during live conversations. Stable subtitles are crucial for real-time understanding and support, especially in noisy environments where clarity is paramount.

2. **What small change unlocks it**

   Define a fixed subtitle position rule for V1 that places subtitles at the bottom center of the glasses frame. This simple rule ensures consistent placement regardless of head movement or conversation dynamics, reducing visual distractions and maintaining focus on the conversation.

3. **Likely payoff**

   By implementing a stable subtitle placement rule, V1 will provide a more predictable and trustworthy user experience. The wearer can rely on subtitles appearing in a known location without being disrupted by unexpected changes, thereby enhancing their ability to follow conversations accurately.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a numeric score along with a label and short reason, we can enhance the trustworthiness and clarity of the subtitle memory support. This improves the wearer's understanding of how certain the system is about names and faces, which aligns directly with the `memory_trust` attractor.

2. **What small change unlocks it**

   Introduce a new confidence format that includes a numeric score (e.g., 0.85), a label (e.g., "High"), and a short reason (e.g., "Seen recently"). This can be achieved by updating the `confidenceLabel` in the `TranscriptLabModel.swift`.

3. **Likely payoff**

   Implementing this confidence format will provide the wearer with more granular and transparent feedback on the system's certainty, which can significantly enhance trust in the memory support feature. The numeric score gives a clear indication of the confidence level, while the label and short reason offer context.

4. **Immediate next probe**
   - Define the confidence score presentation format for V1 as a numeric value (e.g., 0.85).

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   Improving local memory thresholds ensures that frequently encountered names and faces are stored in a way that maximizes usability while respecting privacy constraints. This enhances the wearer's confidence in recalling important information without overloading their phone, which is critical for maintaining real-time responsiveness and trust.

2. **What small change unlocks it**
   Define a local cache size limit of 10-15 recent faces/names with a recency threshold of one week. This limit balances memory storage needs against the risk of privacy concerns and ensures that the system remains responsive and uncluttered.

3. **Likely payoff**
   By limiting the local cache to a manageable number of frequently encountered individuals, the system can maintain fast recall performance while respecting user privacy. This will help in quickly identifying new people with high confidence while reducing the risk of storing too much data on the device.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that V1 remains focused on delivering high-quality, low-latency subtitles and memory support without overloading the glasses hardware. This will help maintain the system's reliability and reduce the risk of battery drain or thermal issues.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary for live subtitle processing. Specifically, decide what parts of the live subtitle generation process should be handled locally on the phone versus when a fallback to the cloud is necessary.

3. **Likely payoff**

   By optimizing live subtitle processing to stay phone-local, we can ensure that subtitles are delivered in near-real-time without significant latency or battery drain. This will help maintain the system's trust and usability, as users expect immediate feedback during live conversations. Additionally, this focused approach allows us to prioritize other core features like memory support and confidence display.

4. **Immediate next probe**
   - Define one cloud fallback boundary for live subtitle processing to stay phone-local when possible.
