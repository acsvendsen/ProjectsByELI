# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now

- **Subtitle Placement**: Use the top-center of the glasses display.
  - **Reasoning**: This placement ensures subtitles are easily readable and minimize distraction. The current `TranscriptLab` app can test this by placing text in the top center during live tests.

## Confidence Display: Feasible Now

- **Confidence Display**: Implement a label only, with a short reason if needed.
  - **Reasoning**: Keeping it simple aligns with low-friction assistance and ensures subtitles remain unobtrusive. Initial testing can be done in `TranscriptLab` by adding confidence labels to the transcript text.

## Memory/Cache Policy: Feasible Now

- **Memory/Caching**: Cache names and faces locally on the phone for quick recall.
  - **Reasoning**: Given the current focus is on core deepening, caching basic information like names and faces can enhance memory support without overloading the system. Initial implementation can be tested in `TranscriptLab`.

## Phone/Cloud Boundary: Feasible Now

- **Phone/Cloud Boundary**: Ensure heavy processing happens primarily on the phone with cloud optional for non-critical background tasks.
  - **Reasoning**: This aligns with current hardware and battery constraints. Testing this boundary in `TranscriptLab` can help validate phone-first processing.

## Visual Hierarchy: Feasible Now

- **Visual Hierarchy**: Use a simple, clean layout where subtitles are more prominent than one-line prompts.
  - **Reasoning**: Keeping the UI straightforward ensures low social friction and clarity. Initial design and implementation in `TranscriptLab` can help iterate on this.

## V1 Modes: Core Deepening

- **Core Deepening**: Bias towards subtitle quality, memory trust, and visual UX improvements that increase daily-use value.
  - **Reasoning**: This direction is consistent with the current project inputs. Concrete work like improving real-time subtitle clarity in `TranscriptLab` can be part of this effort.

## Constraints: V1 Real World Limits

- **Constraints**: Glasses should remain lightweight, battery and thermal pressure must be managed, subtitles must feel near-real-time.
  - **Reasoning**: These constraints are critical for the success of early versions. The `TranscriptLab` app is a good tool to test these limits.

## Interaction Constraints: Frame Touch Only V1

- **Interaction Constraints**: V1 interaction should happen through frame touches only, not voice commands.
  - **Reasoning**: This aligns with current project inputs and ensures focus on core features. Testing this in `TranscriptLab` can help validate the frame-touch experience.

## Summary of Feasibility

### Feasible Now
- Subtitle Placement: Top-center display.
- Confidence Display: Label only, short reason if needed.
- Memory/Caching: Local caching for names and faces.
- Phone/Cloud Boundary: Heavy processing on phone.
- Visual Hierarchy: Simple, clean layout with prominent subtitles.

### Not Feasible Now but Likely Waste of Time
- Voice activation as primary control method.
- Full on-glasses inference.
- Complex multimodal UI.
- Heavy autonomous behavior without strong confidence signals.

### Assumptions Needing Evidence
- What subtitle placement is most usable without becoming distracting.
- How one-line prompts visually differ from subtitles.
- Best confidence format for building trust (label only, label + short reason, score + label).

By focusing on these concrete areas and using `TranscriptLab` as a test bed, the project can surface real-world limitations early and ensure core improvements are made first.
