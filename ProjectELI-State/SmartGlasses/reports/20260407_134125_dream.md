### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles remain clear and unobtrusive while still providing reliable information when needed. This will help maintain trust in the system's ability to assist without overwhelming the wearer.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence text (e.g., seen recently) placed at the bottom of the frame, and another for medium- or low-confidence text (e.g., likely seen before but with less certainty) placed slightly above the center to avoid blocking critical visual information.

3. **Likely payoff**

   This approach will enhance the user experience by ensuring that high-confidence subtitles are easily readable without causing distraction, while lower-confidence information is still accessible but does not interfere with the wearer's primary view. This balance will strengthen trust and usability.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide clear, concise, and trustworthy indicators, we can enhance user trust in both subtitle accuracy and memory recall. A well-designed confidence object format will ensure that wearers can quickly understand the reliability of the information provided, reducing cognitive load and increasing overall system acceptance.

2. **What small change unlocks it**

   Introduce a new confidence display format that combines a numeric score with a label and a short reason for the score. For example: `score 0.84 + "High" + "Seen recently"` for well-established names or `score 0.42 + "Low" + "Weak match"` for likely but uncertain names.

3. **Likely payoff**

   This change will provide a clearer and more understandable way to convey the confidence level of memory recall, which can significantly reduce the wearer's cognitive load during interactions. Users will be better able to trust the system’s recommendations, leading to higher overall satisfaction and acceptance.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we ensure that frequently encountered names are stored in a way that is immediately accessible to the wearer without relying on cloud syncs or intensive processing. This improves trust and usability by providing quick responses during conversations.

2. **What small change unlocks it**

   Define a local cache threshold of 5-10 recent face/name interactions that are stored with high confidence for fast lookup, but do not continuously refresh or sync this data to the cloud.

3. **Likely payoff**

   The likely payoff is improved responsiveness and trust during conversations where names need to be recalled quickly. This reduces latency and ensures that common interactions feel seamless, reinforcing the core mission of providing reliable memory support.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays on the phone versus what falls back to cloud for live subtitle processing, we ensure that critical real-time data remains locally processed while less time-sensitive tasks are offloaded. This improves responsiveness and reduces dependency on network latency, thereby enhancing the overall reliability and trust in the system.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitles are processed entirely phone-side, with any memory or contextual data required for subtitle generation cached locally. For example, define that all real-time transcription and initial subtitle placement should be done on the phone, while confidence refinement and occasional fallbacks can use cloud resources.

3. **Likely payoff**

   By keeping live subtitle processing local, we ensure that subtitles are generated quickly enough to remain useful in noisy environments. This reduces dependency on network latency and enhances the reliability of the system, making it more usable and trustworthy for the wearer.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, the system can ensure that key information remains prominent while minimizing distraction. This improves overall usability by allowing the wearer to focus on essential data without being overwhelmed by less critical prompts.

2. **What small change unlocks it**

   Define a priority rule that places subtitles above one-line support in terms of visual prominence and display precedence. Implement a coexistence mechanism that ensures both types of information are visible but not clashing, such as using different colors or sizes for each type of text.

3. **Likely payoff**

   Clear visual hierarchy will enhance the wearer's ability to focus on critical information during conversations, reducing cognitive load and improving overall understanding. This can lead to better real-time comprehension and reduced social awkwardness due to clearer, more organized display behavior.

4. **Immediate next probe**
   - Define a visual hierarchy rule prioritizing subtitles over one-line support in terms of prominence and display precedence.
