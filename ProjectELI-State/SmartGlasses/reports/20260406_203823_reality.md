# Reality Check for SmartGlasses V1

## Core Attractors

### Subtitle Clarity (subtitle_clarity)
- **Feasible Now**: 
  - **Subtitle Placement and Visual Hierarchy**: Given current hardware constraints, the placement of subtitles should prioritize readability over distraction. The glasses should display subtitles directly at or near the wearer’s mouth to minimize head movement needed for reading.
  - **Confidence Display**: Subtitles can initially show confidence levels as simple labels (e.g., "High", "Low") without complex scores or reasons, which are less critical in V1 and could distract from core functionality.

### Memory Trust (memory_trust)
- **Feasible Now**:
  - **Face/Name Memory**: Implement automatic face/name recognition with context-based reinforcement. For example, remember names of people the wearer interacts with frequently. Use explicit touch-to-remember actions for important or uncertain cases.
  - **Memory Caching**: Cache recognized faces and names on the phone to reduce cloud dependency in V1.

### Low-Friction Assistance (low_friction_assistance)
- **Feasible Now**:
  - **One-Line Support**: Provide one-line prompts like “Introduce yourself” or “Say hello” when necessary. Ensure these are brief, unobtrusive, and contextually relevant.
  - **Interaction Management**: Frame touches should be used for actions like initiating memory recall, not for complex commands.

## Core Tensions

### Privacy vs Usefulness (privacy_vs_usefulness)
- **Feasible Now**:
  - **Automatic Memory Support**: Implement automatic face/name recognition with clear, unambiguous confidence levels. For instance, use labels like "Uncertain" or "Confident".
  - **Data Collection and Storage**: Store minimal data locally on the phone to avoid privacy concerns. Use explicit user actions (e.g., touch-to-remember) to reinforce important memories.

### Latency vs Richness (latency_vs_richness)
- **Feasible Now**:
  - **Subtitle Delivery**: Prioritize near-real-time subtitle delivery over rich but slower processing. Ensure subtitles are delivered quickly enough that the wearer can trust them in live conversation.
  - **Memory Lookup**: Implement fast memory lookup on the phone for quick responses without relying heavily on cloud latency.

### Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Feasible Now**:
  - **Subtitle Visibility**: Ensure subtitles are readable but do not distract. Use a high-contrast, minimalistic display that does not cover the wearer’s field of view.
  - **Memory Display**: Design memory prompts to be unobtrusive and easily dismissible once used.

## Core Constraints

### Frame-Touch-Only V1 Interaction (frame_touch_only_v1)
- **Feasible Now**:
  - **Explicit Touch Actions**: Use frame touches for explicit actions like initiating memory recall or adjusting subtitle visibility. Avoid voice commands in V1.
  
### Phone-First Runtime (phone_first_runtime)
- **Feasible Now**:
  - **Central Processing**: Heavy processing should primarily happen on the phone, with cloud support optional where clearly justified by latency or complexity.

## Core Decisions

### Subtitle Placement
- **Best Effort**: Place subtitles directly at or near the wearer’s mouth to minimize head movement and ensure readability. Avoid overly complex visual hierarchies in V1.
  
### Confidence Display
- **Label-Based Approach**: Use simple labels like "High", "Medium", and "Low" for confidence levels, which are easier to implement and less distracting.

### Memory/Cache Policy
- **Automatic Recognition with Reinforcement**: Implement automatic face/name recognition but use explicit touch-to-remember actions for critical or uncertain cases. Cache recognized faces and names on the phone.

### Phone/Cloud Boundary
- **Phone-Centric Approach**: Use the phone for heavy processing, with cloud support optional where it adds clear value (e.g., deep model training).

### Visual Hierarchy
- **Minimalistic Design**: Prioritize readability and usability over visual complexity. Ensure subtitles do not cover the wearer’s field of view.

## Summary

The current V1 direction is feasible given the constraints. Subtitle clarity, memory trust, and low-friction assistance can be implemented with minimal hardware dependencies and clear focus on core functionality. Privacy and usability tensions can be managed through careful implementation choices, ensuring that the system remains discreet and useful without overcomplicating it.

### Assumptions Needing Evidence
- The accuracy of automatic face/name recognition in noisy environments.
- The effectiveness of label-based confidence levels for users.
- The balance between cloud dependency and local processing for memory caching.
