### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles remain clear and stable enough for the wearer to trust them in live conversation. This helps maintain high clarity and reduces visual distractions, which is crucial for real-time understanding.

2. **What small change unlocks it**

   Define two subtitle placement modes: a primary fixed position for high-confidence subtitles and a secondary adaptive mode for lower confidence or uncertain content that adjusts based on gaze direction or face presence.

3. **Likely payoff**

   This approach will provide clear, stable subtitles without overwhelming the wearer with too much visual information. It balances clarity and readability while maintaining trust in the system's accuracy during critical moments of conversation.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving the confidence display format enhances the trustworthiness of memory support by clearly indicating the reliability of recalled information to the wearer. This clarity helps in building a reliable system that does not overpromise on certainty, thereby maintaining user trust and ensuring accurate recall.

2. **What small change unlocks it**

Define a single confidence object format that combines a numeric score with a label and a short reason for the memory support. For example: `score 0.75 + "High" + "Name heard in recent conversation"`. This format provides enough detail to convey certainty without overwhelming the wearer.

3. **Likely payoff**

This change will help in reinforcing trust by ensuring that the wearer understands when a recalled name or face is highly likely to be correct, reducing instances of mistaken recall and enhancing the overall reliability of memory support.

4. **Immediate next probe**
   - Define the certainty wording as `"[Low|Medium|High]"` for the confidence format.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Enhancing local memory thresholds ensures that frequently encountered names and faces are cached more robustly on the phone, reducing latency in recall while maintaining privacy. This improves the trustworthiness of memory support by ensuring quick access to commonly seen entities without overloading the cloud.

2. **What small change unlocks it**

   Define a local cache threshold for face/name memories that evicts less frequently encountered names and faces after a set period, such as 7 days, while keeping those seen more often within a much shorter timeframe, like 30 minutes.

3. **Likely payoff**

   By setting a specific local cache threshold, the system will efficiently manage memory storage, reducing cloud traffic and improving response times for commonly encountered names and faces. This enhances the overall reliability of name recall without compromising privacy or user trust.

4. **Immediate next probe**
   - Set a local cache eviction rule to keep frequently seen faces and names in memory for 30 minutes and less frequently seen ones for 7 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what stays phone-local versus what falls back to cloud, we ensure that V1 remains focused on providing real-time subtitle clarity and low-friction assistance without overloading the wearer's cognitive load or draining battery unnecessarily. This helps maintain trust and usability, aligning with the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define a clear cloud fallback boundary for transcript cleanup. For V1, keep all live subtitle processing phone-local to ensure near-real-time performance. However, for transcript cleanup, where latency can be higher without significantly impacting the wearer's experience, allow cloud support if needed.

3. **Likely payoff**

   By keeping live subtitles phone-local and allowing cloud fallbacks only when necessary (like during transcript cleanup), we maintain a clean UX that remains socially acceptable while ensuring critical real-time functionality is not compromised. This balance strengthens the core attractors of real-time subtitle clarity and low-friction assistance.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving subtitle-vs-one-line support coexistence ensures that subtitles remain clear and unobtrusive while still providing necessary one-line prompts. This balance enhances both the wearer's trust in real-time subtitles and their ability to respond effectively, aligning with the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define a visual hierarchy that prioritizes subtitles over one-line support when confidence in the speaker is high but suppresses subtitles slightly during fast or noisy exchanges where one-line prompts are most needed. This ensures that critical information (subtitles) remains prominent while less urgent text (one-line prompts) stays discreet.

3. **Likely payoff**

   By fine-tuning subtitle and one-line support coexistence, the system can maintain high trust in real-time subtitles even during fast-paced interactions. This improves overall understanding and response quality without overwhelming the wearer with too much information at once, enhancing both the core attractors of clarity and low-friction assistance.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
