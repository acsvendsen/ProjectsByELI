### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules, we can ensure that subtitles remain clear, stable, and unobtrusive during live conversations. This will enhance trust in the system's real-time capabilities and reduce cognitive load on the wearer.

2. **What small change unlocks it**

   Define two fixed subtitle placement rules: one for high-confidence speakers (e.g., faces or voices recently seen/heard) and another for low-confidence speakers (e.g., background noise, distant speakers).

3. **Likely payoff**

   This refined placement will make subtitles more readable in complex environments, reducing the chance of misinterpretation and enhancing overall trust in the system's reliability.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer can trust the system's outputs by clearly conveying the certainty of the information. This is crucial for maintaining the project's mission to assist without deceiving, especially in critical real-time situations where misunderstanding could lead to social or cognitive friction.

2. **What small change unlocks it**

   Define a confidence format that combines a numeric score with a label and a short reason. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

   By implementing a clear and concise confidence format, the system can establish stronger trust in its outputs. This clarity will help reduce social awkwardness and cognitive load for the wearer, making the assistance more reliable and usable in real-world scenarios.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory cache size ensures that frequently encountered faces and names are stored in a way that reduces latency and improves the trustworthiness of memory recall. By setting an optimal threshold for local memory, the system can quickly provide relevant context without relying on cloud fallbacks, enhancing the overall user experience.

2. **What small change unlocks it**

   Define one entity-linking rule for attaching new evidence to an existing person-memory object that prioritizes storing high-confidence entities locally. This rule would ensure that names and faces encountered more than a certain number of times are stored in local memory with minimal latency.

3. **Likely payoff**

   By reducing reliance on cloud fallbacks, the system can provide faster, more reliable memory support. This improvement will lead to a smoother user experience, where the wearer receives timely and accurate information about people they have interacted with before. Additionally, it will enhance trust in the system’s ability to remember and recall context accurately.

4. **Immediate next probe**

   Define one local-cache size limit for storing frequently encountered faces and names, setting it to 100 entities with a refresh interval of once per day.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we ensure that V1 remains focused and efficient. This alignment will help in maintaining low-friction assistance without overloading the wearer's interaction with commands or the glasses themselves.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary for exactly one of the following: live subtitle processing, transcript cleanup, face/name recall lookup, memory archive sync, conversation snapshot upload.

3. **Likely payoff**

   By setting a clear boundary for what runs on the phone and when to fall back to the cloud, we can optimize V1 to be more efficient in battery usage while ensuring that critical functionality remains responsive. This will help in maintaining high confidence in subtitle placement and memory recall without unnecessary network calls.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line prompts enhances the wearer's ability to focus on critical information without distraction, thereby deepening trust in the system’s ability to assist without overwhelming the user.

2. **What small change unlocks it**

   Define a prioritization rule that routes subtitles above one-line support in the visual display order when both are present simultaneously, ensuring that subtitles receive priority in the wearer's field of view.

3. **Likely payoff**

   This change will improve the wearer’s focus and comprehension during conversations by ensuring that essential information (subtitles) is visually prioritized over less critical prompts, reducing cognitive load and enhancing overall user experience.

4. **Immediate next probe**

   Define a subtitle-vs-one-line priority rule where subtitles always appear above one-line support in the visual hierarchy when both are present.
