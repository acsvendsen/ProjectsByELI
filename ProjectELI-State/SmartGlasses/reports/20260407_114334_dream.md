### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain the wearer's trust in the system by providing consistent and reliable information. This stability is crucial for real-time interaction, as inconsistent placements can lead to misreadings and confusion.

2. **What small change unlocks it**

   Define a fixed position rule that prioritizes center screen for subtitles while allowing a slight downward offset to account for reading glasses or other head movements. This rule ensures subtitles remain easily readable without causing visual distractions.

3. **Likely payoff**

   By setting a clear and stable subtitle placement, the system can reduce the cognitive load on the wearer, making it easier to follow conversations in noisy environments. This improvement will enhance overall user trust and satisfaction, contributing to the core mission of improving understanding and comprehension.

4. **Immediate next probe**
   - Define a fixed position rule that centers subtitles on the screen with a slight downward offset for readability.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local memory threshold for face/name recall, the system can balance the need for quick access to recently seen individuals with the constraints of limited phone storage and battery life. This ensures that critical information is readily available while minimizing resource usage.

2. **What small change unlocks it**

   Define a policy where new person memories are cached locally on the phone for 7 days, after which they are evicted from cache but retained in a persistent history index.

3. **Likely payoff**

   This policy will enhance the system's ability to recall and support new people while respecting battery and storage limits. It will ensure that critical information is available without overwhelming the local memory or cloud sync processes, thus maintaining performance and user trust.

4. **Immediate next probe**
   - Set the eviction rule to remove new person memories from local cache after 7 days of no interaction, while retaining them in a persistent history index.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs locally on the phone versus what falls back to the cloud, we can ensure that V1 remains focused and reliable. This helps in maintaining low-latency responses and high privacy standards while ensuring that critical real-time subtitle processing happens locally.

2. **What small change unlocks it**

   Define specific tasks and their associated confidence thresholds for which local processing on the phone is sufficient before falling back to cloud assistance. For example, set a threshold where subtitles with moderate confidence (e.g., 0.75) can be processed locally without cloud fallback, but high-confidence requests (e.g., above 0.90) should use cloud intelligence.

3. **Likely payoff**

   This approach will ensure that V1 remains robust and responsive in real-world noisy environments by leveraging the phone's local processing capabilities for critical tasks. It also helps in reducing privacy risks by limiting data transmission to only when necessary, thus maintaining user trust.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
