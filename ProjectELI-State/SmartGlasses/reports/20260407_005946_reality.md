# Reality Check Assessment

## Subtitle Clarity: Real-time subtitle clarity
- **Feasible Now**: The `TranscriptLab` test app is actively being used to validate subtitle quality in real-time scenarios. Ensuring subtitles are clear, fast, and stable enough for live conversation can be directly tested and iterated on using this setup.

## Memory Trust: Trustworthy memory support
- **Feasible Later**: Implementing face/name recall with confidence objects that surface uncertainty clearly is feasible but requires more development of the phone-side runtime. This should be prioritized after initial subtitle clarity is established to ensure both features are balanced and do not overwhelm early hardware limitations.

## Low-friction assistance: Low-friction assistance
- **Feasible Now**: The core functionality can start with simple, one-line prompts that align with V1 interaction constraints (frame touches only). Enhancing this aspect can be done in parallel with subtitle clarity and memory trust, but should focus on usability rather than complex command interfaces.

## Privacy vs Usefulness: Privacy vs usefulness
- **Constraint Pressure**: Early implementations must prioritize clear privacy practices. Any face/name recall or memory support should be implemented transparently to the user and avoid any invasive data collection. This is a critical constraint that must be managed from day one.

## Latency vs Richness: Latency vs richness
- **Feasible Now**: The `TranscriptLab` app can be used to test real-time performance of subtitles. Initial implementations should focus on providing timely help rather than overloading the runtime with richer but slower processing. Ensuring subtitle delivery is near-real-time is crucial.

## Discreet UX vs Visual Clarity: Discreet UX vs visual clarity
- **Feasible Now**: The `TranscriptLab` setup can also be used to test subtitle placement and visual hierarchy. Early iterations should aim for a balance that remains socially acceptable while ensuring the subtitles are readable in motion and noise.

## Frame-touch-only V1 interaction: Frame-touch-only V1 interaction
- **Feasible Now**: This constraint is currently hard-coded into the system, so all interactions must respect this limitation until further notice. The `TranscriptLab` app should continue to serve as a primary testing ground for these interactions.

## Phone-first runtime: Phone-first runtime
- **Feasible Now**: Heavy processing should remain on the phone initially. The `TranscriptLab` setup aligns with this by keeping most of the heavy lifting on the phone side rather than relying heavily on cloud services, which can introduce latency and battery concerns.

## Core-deepening over sprawl: Core-deepening over sprawl
- **Feasible Now**: Focus on improving subtitle quality, memory trust, and visual UX before expanding into broader feature areas. The `TranscriptLab` setup supports this by providing a clear path to iterate on these core aspects without introducing unnecessary complexity.

## Persistent SmartGlasses Project Inputs Summary

### Subtitle Placement
- **Feasible Now**: Using the `TranscriptLab` app, subtitle placement can be tested and refined for usability. Early iterations should prioritize readability in noisy environments and minimal distraction.

### Confidence Display
- **Feasible Now**: Initial confidence display formats (labels only or with short reasons) can be implemented and tested using the `TranscriptLab` setup. This will help ensure that the system remains trustworthy without overwhelming the user.

### Memory/Cache Policy
- **Feasible Later**: Face/name memory should be stored and reinforced for fast lookup, but this requires more development on the phone-side runtime. Early prototypes can focus on basic memory caching strategies.

### Phone/Cloud Boundary
- **Feasible Now**: The `TranscriptLab` setup supports testing of cloud integration scenarios where it adds clear value without introducing significant latency. This will help in defining appropriate cloud boundaries early.

### Visual Hierarchy
- **Feasible Now**: Early iterations can use the `TranscriptLab` app to test different visual hierarchy designs, ensuring that subtitles and prompts are visually distinct yet readable and unobtrusive.

## Likely Waste of Time
- **Subtitle Management via Voice Commands in V1**: Assuming voice commands for subtitle management, mode switching, or confirmations before expanding beyond frame-touch interactions is likely a waste of time. This should be explored only if the project explicitly changes direction later.

## Assumptions Needing Evidence
- **Assumption that Confidence Objects Will Be Sufficiently Trustworthy**: While the `TranscriptLab` setup can test initial confidence display, more evidence through user testing and iterative refinement is needed to ensure these confidence objects are perceived as trustworthy by users.

By focusing on these areas and using the `TranscriptLab` app for testing and iteration, the project can effectively manage real-world constraints while continuously improving core functionalities.
