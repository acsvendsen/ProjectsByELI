### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring consistent subtitle placement rules based on confidence levels helps maintain a balance between readability and non-intrusiveness. This approach allows subtitles to be positioned in a way that maximizes understanding while minimizing distraction, which is crucial for the wearer's trust and comprehension.

2. **What small change unlocks it**

   Define three distinct subtitle placement modes: high-confidence (fixed position), medium-confidence (semi-fixed with slight movement), and low-confidence (more dynamic placement). This simple change enables a more nuanced approach to subtitle delivery that respects the wearer’s context and confidence in the system's accuracy.

3. **Likely payoff**

   By implementing different subtitle placement rules based on confidence levels, the project can achieve better overall readability and user trust without overwhelming the wearer with too many subtitles or distracting them unnecessarily. This balance is critical for maintaining a low-friction assistive experience that aligns with the core mission of enhancing understanding in real-world interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a clear numeric score along with a label and short reason, we can enhance the wearer's trust in the system's judgments without overwhelming them. This approach maintains a balance between providing enough detail for reinforcement learning and keeping the UI uncluttered.

2. **What small change unlocks it**

   Modify the confidence object to include a numeric score alongside the label and short reason. For example, display "score 0.84 + 'High' + 'Seen recently'". This small change allows for more nuanced feedback and can be easily implemented in V1 while staying within the constraints.

3. **Likely payoff**

   Implementing this confidence format will help users understand the system's certainty levels better, which can lead to increased trust and more effective use of the memory support features. Users will feel their interactions are being accurately captured and remembered, thus reinforcing the core mission of providing reliable memory assistance.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds for face/name recall allows the system to maintain a balance between privacy and usefulness by caching key memories on the phone without overwhelming the device, ensuring that critical information is readily available for fast lookup while respecting battery and thermal constraints.

2. **What small change unlocks it**

   Define a recency-based eviction policy where old but frequently recalled faces/names are retained longer in local cache than less relevant entities, allowing the system to optimize memory storage based on usage patterns rather than fixed intervals.

3. **Likely payoff**

   By optimizing local memory thresholds, the system can enhance both subtitle clarity and memory support. This will enable faster recall of important names and faces, improving the wearer's confidence in understanding conversations without overly taxing the device or creating privacy concerns.

4. **Immediate next probe**

   Define one recency-based eviction rule for face/name memory where frequently recalled entities are cached longer than less relevant ones on the phone.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus falling back to cloud, we ensure that critical real-time subtitle processing happens on the device, maintaining low latency and high reliability. This focus ensures that subtitles remain clear, fast, and stable enough in live conversation, directly supporting our primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary for live subtitle processing. Specifically, decide which parts of the subtitle rendering process should happen locally on the phone to ensure real-time responsiveness, and which can be offloaded to the cloud if needed but with clear latency trade-offs acknowledged.

3. **Likely payoff**

   By keeping critical subtitle rendering local, we maintain the essential qualities of clarity, speed, and reliability required for real-time assistance in noisy environments. This focus on core functionality will enhance user trust and satisfaction, aligning well with our mission to help the wearer understand better without creating social awkwardness or relying on potentially laggy cloud services.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By optimizing the visual hierarchy between subtitles and one-line prompts, we can ensure that the wearer remains focused on essential information without being overwhelmed by too many details. This improvement helps in maintaining a clear and uncluttered field of view, enhancing overall comprehension and reducing cognitive load.

2. **What small change unlocks it**

   Define a clear subtitle-vs-one-line priority rule where subtitles are given higher visual precedence when confidence is high, but one-line prompts can coexist discreetly without distracting the wearer. 3. **Likely payoff**

   Implementing this visual hierarchy will reduce cognitive overload by ensuring that critical information (subtitles) remains prominent while auxiliary support (one-line prompts) is displayed in a less intrusive manner. This improves the wearer's ability to follow conversations effectively without feeling overwhelmed, thus enhancing overall user satisfaction and trust.
