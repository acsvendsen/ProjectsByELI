# Reality Check

## Subtitle Clarity: Feasible Now
- **Subtitle Placement**: The glasses should prioritize a placement that minimizes distraction while ensuring clear readability. Based on the current setup, placing subtitles in the periphery of the wearer's vision (e.g., upper right or lower left corner) can be feasible now. This placement ensures subtitles remain unobtrusive yet visible.
- **Visual Hierarchy**: Designing for fast reading is crucial. A clean and simple font with appropriate size and color contrast should be achievable in early iterations.

## Memory Trust: Feasible Now
- **Memory Storage**: Implement a local memory system that stores names and faces temporarily on the phone. This can use SQLite or Core Data to manage cached entries, ensuring fast lookups.
- **Confidence Display**: Early implementation could use simple labels like "Uncertain" or "Likely Known" with minimal visual impact. As more data is collected, confidence scores can be introduced, but this should remain optional and not overwhelm the wearer.

## Low Friction Assistance: Feasible Now
- **One-Line Prompts**: Implement basic prompts that provide quick context or reminders. These should be short and unobtrusive, appearing as needed to support the user without disrupting their flow.
- **Subtitle vs Prompt Coexistence**: Design a visual hierarchy where subtitles take precedence but can coexist with one-line prompts. This could involve alternating display time between subtitles and prompts.

## Privacy vs Usefulness: Feasible Later
- **Data Collection**: Early implementation should focus on useful functionality rather than extensive data collection. As the system evolves, more detailed privacy considerations can be addressed.
- **User Control**: Ensure users have control over what information is stored and for how long. Implement a clear mechanism to allow users to reset memory or delete specific entries.

## Latency vs Richness: Feasible Now
- **Real-time Subtitles**: Use the TranscriptLab app to test real-time subtitle performance. Optimize microphone capture and transcription speed to ensure subtitles are delivered in near-real time.
- **Memory Lookup Speed**: Implement fast lookup mechanisms on the phone, possibly using background processing to cache frequently accessed information.

## Discreet UX vs Visual Clarity: Feasible Now
- **Subtitle Design**: Design subtitles with a low profile that does not distract during conversations. Ensure they are readable but do not overwhelm the wearer.
- **Prompt Display**: Keep one-line prompts minimal and unobtrusive, allowing them to blend into the overall experience without causing visual clutter.

## Frame Touch Only V1: Feasible Now
- **Interaction Design**: Implement frame touches as the primary interaction method. This can include simple gestures like tapping or swiping for subtitle management.
- **Avoid Voice Commands**: Do not assume voice commands in early iterations to adhere to the V1 constraint.

## Phone First Runtime: Feasible Now
- **Local Processing**: Utilize the phone's capabilities for heavy processing, keeping glasses hardware minimal. Ensure all critical operations are handled on the phone where possible.

## Core Deepening Over Sprawl: Feasible Now
- **Focus on Core Features**: Prioritize improvements in subtitle quality, memory trust, and visual UX over broad feature expansion. This ensures the core mission is strengthened first.

## Constraint Pressure: Feasible Now
- **Battery Management**: Test battery usage with the current setup to ensure it remains within acceptable limits. Optimize power consumption for real-time operations.
- **Thermal Considerations**: Ensure glasses remain cool and lightweight, avoiding any thermal issues that could arise from continuous operation.

By focusing on these specific areas, the project can make significant progress without overcomplicating early iterations. Regular testing with the TranscriptLab app will help surface any constraints early and guide further development.
