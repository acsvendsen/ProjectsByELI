### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a fixed subtitle placement rule that prioritizes readability over distraction, we can ensure that subtitles remain clear and stable enough to support real-time understanding without overwhelming the wearer. This stability is crucial for maintaining trust and usability in noisy environments.

2. **What small change unlocks it**

   Introduce a new subtitle placement mode that places subtitles at the bottom center of the field of view (FOV) during high-confidence interactions, but moves them to the side during low-confidence interactions to avoid overlapping with primary visual tasks.

3. **Likely payoff**

   This refined subtitle placement strategy will enhance readability and reduce distractions, especially in scenarios where the system is uncertain or needs to process more complex information. By minimizing overlap, we can maintain focus on key content while ensuring that necessary subtitles are always visible.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a clear numeric score with a label and short reason, we can enhance the trustworthiness of the system. This improves the wearer's ability to understand when they should rely on the subtitles or seek further clarification, thereby deepening the core mission of providing reliable real-time assistance.

2. **What small change unlocks it**

   To unlock this benefit, we need to define a confidence format that includes a numeric score, a label, and a short reason. For example: "Score 0.84 + 'High' + 'Seen recently'; Score 0.42 + 'Low' + 'Weak match'; Score 0.63 + 'Medium' + 'Name heard once in introduction'. This format provides a clear and concise way to communicate the level of certainty.

3. **Likely payoff**

   Implementing this confidence display will likely result in better wearer trust and understanding, as they can easily interpret when the subtitles or memory support are reliable. This enhances the core mission by ensuring that the system is not overly aggressive in its claims, which could lead to confusion or mistrust.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear threshold for local memory retention on the phone, we can ensure that critical names and faces are cached locally to enable fast lookup and reliable recall without overloading cloud resources. This helps in maintaining trust by providing quick responses and supports the core attractor of "Trustworthy memory support."

2. **What small change unlocks it**

   Define a local cache size limit for face/name memories, ensuring that only recently encountered or frequently seen entities are retained locally. For example, limiting the cache to the most recent 10 names and faces.

3. **Likely payoff**

   By setting a specific threshold for local memory retention, we can improve response speed and reliability without excessive cloud usage. This enhances trust in the system by ensuring quick access to critical information when needed, which is essential for real-time subtitle clarity and effective memory support.

4. **Immediate next probe**

   Define one local-cache size limit of 10 entities (names or faces) for face/name recall.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear phone-local versus cloud boundaries for live subtitle processing, we can ensure that subtitles are delivered with minimal latency, maintaining trust and real-time clarity. This balance helps in keeping the system lightweight and socially acceptable while still providing essential assistance.

2. **What small change unlocks it**

   Define a simple cache policy where face/name recall data is stored locally on the phone for up to 10 minutes after an encounter, with cloud fallback only when new evidence requires updating existing memory objects.

3. **Likely payoff**

   This caching policy ensures that common names and faces are remembered reliably without draining battery or privacy concerns. It also speeds up memory lookups during live interactions, improving overall trust and utility.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
