### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain clear, readable, and stable enough to be trusted during live conversations. This enhances the wearer's ability to follow the conversation without distractions, thereby deepening the core mission of providing real-time, reliable subtitle assistance.

2. **What small change unlocks it**

   Define 2 to 3 fixed subtitle placement rules for different confidence states: high-confidence text always on top center (for known faces and names), medium-confidence text offset slightly below or to the side (for recent encounters but not certain matches), and low-confidence text in a smaller font size at the bottom edge (for unlikely matches).

3. **Likely payoff**

   By establishing clear, stable placement rules based on confidence levels, the system will reduce visual distractions and ensure that high-confidence subtitles are easily visible. This improves overall usability and trust in the subtitle feature, aligning with the core attractors of real-time clarity and low-friction assistance.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving the confidence display format ensures that the wearer can trust the system's memory recall and assistance, enhancing overall user confidence and satisfaction. A well-designed confidence label and short reason will help mitigate privacy concerns while still providing necessary context.

2. **What small change unlocks it**

Define a new confidence object format for V1: `score 0.84 + "High" + "Seen recently"` instead of the existing generic numeric score alone.

3. **Likely payoff**

This change will provide clearer, more reassuring feedback to the wearer about the reliability of name and face memory recall. It will help reduce privacy concerns by being transparent about the confidence level without overcomplicating the interface.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear threshold for local memory retention, we ensure that the system focuses on storing critical information that is frequently referenced and lessens the reliance on cloud storage or frequent refreshes. This improves trust by reducing uncertainty and maintaining a consistent understanding of the wearer's interactions.

2. **What small change unlocks it**

   Define a local cache eviction policy that retains memory objects for at least 30 days, with a strong reinforcement history prioritizing retention. This ensures that frequently encountered people and names are stored locally for faster lookup and more reliable recall.

3. **Likely payoff**

   Implementing this policy will lead to more consistent and trustworthy memory support, reducing the likelihood of forgotten names or faces during conversations. It will also enhance the system's reliability by minimizing latency issues associated with cloud requests, thus improving the overall user experience.

4. **Immediate next probe**

   Define one local cache eviction rule that retains memory objects for at least 30 days, prioritizing frequently encountered people and names for faster lookup and more reliable recall.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Staying focused on a clear, phone-first architecture ensures that early iterations prioritize real-world usability and trust over speculative hardware complexity. By defining what stays phone-local versus falling back to cloud for exactly one task boundary, we can ensure that V1 remains simple yet effective, surfacing critical limitations early.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that stays on the glasses and only falls back to the phone if absolutely necessary due to latency constraints. For example, basic subtitle rendering can happen on-glasses with more complex text formatting or language translation tasks falling back to the phone.

3. **Likely payoff**

   By keeping subtitle rendering local, we reduce thermal and battery load, ensuring that subtitles remain stable and clear in real-time conversations. This reduces the risk of breaking trust due to lag or power issues, while still leveraging cloud capabilities for more complex processing when needed without overloading the glasses.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer remains focused on essential information without being overwhelmed by too much text or distractions. This enhances the overall user experience, making the glasses more useful in real-world interactions.

2. **What small change unlocks it**

   Define a priority rule where subtitles are always displayed prominently, but one-line prompts are shown only when necessary and can be quickly dismissed or minimized to maintain clarity. For example, set a policy that one-line prompts should not obscure the subtitle text unless absolutely needed.

3. **Likely payoff**

4. **Immediate next probe**
