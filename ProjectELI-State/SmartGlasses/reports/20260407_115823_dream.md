### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules helps ensure that subtitles remain readable and stable throughout live conversations. Stable and well-placed subtitles are crucial for maintaining trust in the system, allowing the wearer to follow along without distractions.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence situations where memory is more certain (e.g., familiar faces or known contexts) and another for low-confidence situations where memory may be less reliable (e.g., new people or uncertain contexts).

3. **Likely payoff**

   By differentiating between high- and low-confidence placement rules, the system can maintain clarity and reduce distractions during live conversations. This improves overall trust and utility without overloading the wearer with unnecessary information.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache threshold for face/name memory helps ensure that critical information is readily available to the wearer without unnecessary privacy invasions. By setting a strategic threshold, we can balance the need for fast and reliable recall with the constraints of battery life and thermal management.

2. **What small change unlocks it**

   Define a local-cache size limit for stored names and faces, ensuring that only frequently encountered entities are cached on-device. For example, limiting the cache to the top 100 most recently seen individuals or setting a fixed size of 50 entries.

3. **Likely payoff**

   By implementing a strategic cache size limit, we can improve memory recall efficiency while reducing the thermal and battery load on the device. This will ensure that critical entities are always available quickly, enhancing the wearer's trust in the system without compromising on real-world constraints.

4. **Immediate next probe**

   Define one local-cache size limit for stored names and faces, setting a fixed size of 50 entries to balance memory recall efficiency with battery and thermal management.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud processing, we can ensure that critical real-time subtitle generation and memory recall tasks remain fast and reliable. This focus on local processing for these tasks enhances trust by reducing latency and preserving privacy.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing is handled entirely phone-local, while transcript cleanup falls back to the cloud when needed.

3. **Likely payoff**

   By keeping live subtitle processing on-device, we ensure that subtitles are generated quickly and reliably, enhancing real-time clarity and trust. Transferring less critical tasks like transcript cleanup to the cloud only when necessary helps balance resource usage effectively.

4. **Immediate next probe**

   Define one task-specific phone/cloud fallback boundary for exactly one task such as live subtitle processing.
