### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain the wearer's trust by providing consistent, unambiguous visual cues that do not distract from the conversation. Stable placement allows the subtitles to remain in a fixed position relative to the speaker or the screen, making them easier to follow and more reliable.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for stable, non-reactive positioning during live conversations, and another for dynamic adjustments when the wearer looks away from the speaker. This distinction ensures that subtitles remain clear and unobtrusive while providing necessary support.

3. **Likely payoff**

   By implementing stable subtitle placement, V1 can reduce cognitive load and distraction, enhancing the wearer's ability to follow the conversation without being constantly adjusting their gaze or focusing on shifting text. This stability also reinforces trust in the system as a reliable tool for real-time understanding.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that frequently encountered individuals are quickly recognized and remembered, enhancing the wearer's confidence in real-time interactions. This stability and accuracy in memory recall directly support the core attractor of "Trustworthy memory support" by ensuring that key entities remain top-of-mind without relying on potentially unreliable cloud services.

2. **What small change unlocks it**

   Define a local cache threshold for face/name recognition that automatically evicts old or infrequent entities to keep the memory pool manageable and responsive. This can be as simple as setting a recency or frequency limit, such as caching names seen in the last 30 interactions but removing those not seen within the past hour.

3. **Likely payoff**

   By implementing a clear local cache eviction policy, the system will more accurately recall frequently encountered individuals, reducing the likelihood of memory errors and improving overall interaction trustworthiness. This also ensures that the phone's resources are used efficiently without overwhelming processing or storage.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that memory operations stay phone-local as much as possible while still providing useful and timely assistance helps maintain privacy, reduce latency, and ensure a discreet user experience without overloading the battery or cloud.

2. **What small change unlocks it**

   Define one local-cache size limit for face/name recall lookup to avoid unnecessary cloud requests, thus reducing data transfer and processing load on the phone.

3. **Likely payoff**

   By limiting the amount of memory that is cached locally, we can reduce the need for frequent cloud fallbacks, which will lower battery usage and improve the overall performance of the system in noisy or resource-constrained environments. This change also enhances privacy by minimizing data transmission to the cloud.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
