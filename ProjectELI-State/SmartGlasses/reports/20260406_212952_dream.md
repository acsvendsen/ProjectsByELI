### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Subtitle placement rules that prioritize stability and predictability will reduce visual distraction and maintain the wearer's focus on conversation. This consistency in subtitle appearance can enhance trust in the system, ensuring that subtitles are always readable and reliable.

2. **What small change unlocks it**

   Define three subtitle placement rules: one for high-confidence speech (e.g., clearly heard voices), one for medium-confidence speech (e.g., background noises or less clear conversations), and one for low-confidence speech (e.g., distant or indistinct sounds). Each rule should specify a fixed position, such as top center, bottom left, or bottom right.

3. **Likely payoff**

   By implementing three distinct placement rules based on confidence levels, the system can reduce visual distractions during high-concentration tasks like listening to live conversations. This improves overall readability and trust in subtitle accuracy, which is critical for real-time interaction support.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide a clear and concise representation of certainty and source, we enhance the wearer's trust in the system. This improvement ensures that the wearer can quickly understand the reliability of the subtitles and memory recall, which is crucial for their engagement and acceptance.

2. **What small change unlocks it**

   Define a new confidence object format that uses a numeric score with a label and a short reason. For example, "score 0.95 + 'High' + 'Seen recently'". This format provides a clear indication of certainty without overwhelming the user.

3. **Likely payoff**

   Implementing this change will lead to more reliable subtitle placement and memory recall, reducing instances where the wearer doubts the system's accuracy. This increase in trust can result in higher daily-use value and better engagement with the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - Improving memory cache thresholds helps ensure that relevant names and faces are remembered with high confidence over time, reducing the need for continuous cloud sync while maintaining fast lookup performance.

2. **What small change unlocks it**
   - Define a local-cache size limit for face and name memories on the phone to prioritize frequently encountered entities.

3. **Likely payoff**
   - By setting a smaller cache threshold, we can reduce memory usage while ensuring that key individuals are remembered with high confidence, improving overall user trust and reducing battery drain from frequent cloud syncs.

4. **Immediate next probe**
   - Define one local-cache size limit for face and name memories on the phone, set to 10-20 entities.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus what falls back to the cloud, we ensure that critical real-time processing happens locally where latency is minimal and privacy concerns are mitigated. This helps maintain the trust in subtitle clarity and memory support without compromising battery or thermal constraints.

2. **What small change unlocks it**

   Define a specific task boundary such as "live subtitle processing" and decide which parts of this process should run phone-local versus cloud-fallback.

3. **Likely payoff**

   By optimizing for real-time subtitle processing, the system can deliver clear and stable subtitles that are essential for trust in noisy environments. This also allows for better privacy management by keeping sensitive data like live transcripts on the local device, reducing battery drain, and ensuring fast response times without cloud latency.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing: Should real-time subtitle generation and rendering be fully handled by the glasses (phone) or allowed to fall back to the cloud if local resources are under pressure?
