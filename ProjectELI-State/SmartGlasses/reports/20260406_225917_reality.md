# Reality Check for SmartGlasses

Based on the provided core field, scorecard, and linked docs, we will assess each decision area against real-world limits to determine feasibility now, later, or as a likely waste of time.

## Subtitle Placement: Feasible Now

**Description**: Determine the best placement for subtitles that remain readable without becoming distracting in noisy environments.

- **Constraints**: Must be clear and stable enough that the wearer can trust them in live conversation.
- **Decision Area**: Display priority and visual hierarchy.

**Evaluation**:
- The current project is focusing on making real-time subtitles clear, fast, and stable. This aligns well with V1 interaction constraints (frame touches only) and core attractors (subtitle clarity).
- Given the simplicity of V1 hardware and the emphasis on trustworthiness, subtitle placement should be straightforward to implement in the short term.
  
**Feasibility**: **feasible now**

## Confidence Display: Feasible Now

**Description**: Define a confidence format that builds trust best.

- **Constraints**: Must expose uncertainty clearly for face/name recall.
- **Decision Area**: Representation of confidence, either as a label only, a label with short reason, or a score plus label.

**Evaluation**:
- The project has already considered the importance of confidence display in memory support. The current focus is on clarity and honesty, which fits well with these constraints.
- Concrete implementations like `TranscriptLab` can be used to test different formats without heavy hardware dependencies.
  
**Feasibility**: **feasible now**

## Memory/Cache Policy: Feasible Now

**Description**: Determine how face/name memory should be stored and reinforced for fast lookup and trust.

- **Constraints**: Must not pretend certainty or create corrupted recall.
- **Decision Area**: Implementation of caching, reinforcement rules, and confidence objects.

**Evaluation**:
- The current project is working on a phone-first runtime that can handle heavy processing. This allows for practical caching strategies without overloading the glasses hardware.
- `TranscriptLab` can be used to prototype memory storage and recall mechanisms.

**Feasibility**: **feasible now**

## Phone/Cloud Boundary: Feasible Now

**Description**: Define how phone and cloud should interact in terms of processing, model upgrades, etc.

- **Constraints**: Heavy processing should primarily happen on the phone with cloud optional.
- **Decision Area**: Architecture boundaries and runtime distribution.

**Evaluation**:
- The V1 architecture direction explicitly favors a phone-first approach for practicality and iterability. This aligns well with current constraints.
- `TranscriptLab` can be used to test phone-side transcript plumbing without requiring glasses hardware.

**Feasibility**: **feasible now**

## Visual Hierarchy: Feasible Now

**Description**: Decide how subtitles and one-line prompts coexist on the display.

- **Constraints**: Should not overloading the wearer.
- **Decision Area**: Display priority and visual hierarchy design.

**Evaluation**:
- The current focus is on low-friction assistance, which aligns with the core attractors of real-time clarity and honesty. Subtitles should be designed to complement rather than overwhelm the user.
- `TranscriptLab` can help iteratively test different display priorities without hardware dependencies.

**Feasibility**: **feasible now**

## Summary

### Feasible Now
- Subtitle Placement: Subtitle placement is feasible now, given V1 interaction constraints and the need for clear, trustable subtitles in noisy environments.
- Confidence Display: Confidence display can be implemented using current tools without heavy hardware dependencies.
- Memory/Cache Policy: Face/name memory storage and reinforcement are feasible with a phone-first approach.
- Phone/Cloud Boundary: The architecture boundary is well-defined with practical constraints.
- Visual Hierarchy: Visual hierarchy design for subtitles and prompts can be iterated on without immediate hardware requirements.

### Likely Waste of Time
None of the current decision areas seem likely to waste time based on the provided inputs. Each area directly aligns with existing project goals and constraints.

By focusing on these core areas, the project can ensure that the V1 release is both feasible and aligned with the smart glasses' primary mission.
