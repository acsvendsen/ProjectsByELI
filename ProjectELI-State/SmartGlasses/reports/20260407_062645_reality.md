# Reality Check for SmartGlasses Project

## Subtitle Clarity: Real-time subtitle clarity (strength: high)

### Feasibility Now
- **feasible now**: The current `TranscriptLab` app demonstrates real-time transcription that is clear and stable enough. Given the success of the recent Xcode build, subtitles can be made fast and readable in live conversation.
- **confidence reasoning**: The transcript behavior should remain robust to motion and noise based on the existing test cases.

### Subtitle Placement: Optimal placement for clear but non-distracting subtitles
- **feasible now**: Initial tests with `TranscriptLab` have shown that subtitles can be displayed at the bottom of the frame or near the earpiece. This ensures they are visible without being too intrusive.
- **confidence reasoning**: User testing and early feedback suggest that a lower placement is more acceptable in social contexts.

## Memory Trust: Trustworthy memory support (strength: high)

### Feasibility Now
- **feasible now**: Face/name recall can be implemented with confidence objects. Early prototypes should use on-device storage for quick lookup, with cloud reinforcement to improve accuracy over time.
- **confidence reasoning**: The current `TranscriptLab` app supports partial and final transcript behavior, which can be used to store basic memory entries locally before moving them to the cloud.

### Face/Name Memory Storage
- **feasible now**: Use on-device caching for face/name recall. This allows quick lookups without relying heavily on the phone or cloud.
- **confidence reasoning**: On-device caching reduces latency and ensures that critical memory items are available even in low-bandwidth situations.

## Low-friction Assistance: Low-friction assistance (strength: medium)

### Feasibility Now
- **feasible now**: One-line prompts can be displayed discreetly over subtitles. This approach minimizes distraction while providing necessary support.
- **confidence reasoning**: The `TranscriptLab` app provides a framework for displaying text that can be modified to include one-line prompts.

## Privacy vs Usefulness: Privacy vs usefulness (pressure: high)

### Feasibility Now
- **feasible now**: Ensure that memory and confidence information are handled with strong privacy protections. Only store necessary data and provide clear feedback about what is being remembered.
- **confidence reasoning**: The project docs emphasize the importance of not pretending certainty, which helps maintain user trust.

## Latency vs Richness: Latency vs richness (pressure: high)

### Feasibility Now
- **feasible now**: Prioritize real-time subtitles over richer but slower processing. Initial tests show that real-time performance is crucial.
- **confidence reasoning**: The `TranscriptLab` app focuses on live transcription, which aligns with the need for near-real-time responses.

## Discreet UX vs Visual Clarity: Discreet UX vs visual clarity (pressure: medium)

### Feasibility Now
- **feasible now**: Subtitles and one-line prompts can be designed to blend seamlessly into the wearer's experience without causing distraction.

## Phone-first Runtime (type: hard)

- **feasible now**: The `TranscriptLab` app is structured to keep heavy processing on the phone. This approach ensures that initial deployments remain lightweight and battery-friendly.

### Feasibility Now
