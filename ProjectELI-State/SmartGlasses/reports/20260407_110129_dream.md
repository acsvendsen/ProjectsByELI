### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states will help ensure that subtitles remain clear, readable, and unobtrusive while still providing essential support to the wearer. By defining specific placement rules for low-confidence versus high-confidence scenarios, we can maintain focus on crucial information without causing distraction.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence text (e.g., names and faces) that allows them to appear in a fixed, unobtrusive position near the relevant speaker, and another for low-confidence text (e.g., background noise or less critical words) that can be placed temporarily lower on the screen.

3. **Likely payoff**

   This change will enhance the wearer's ability to focus on essential information while reducing visual clutter. It will also help maintain a consistent and unobtrusive interface, which is crucial for daily use in noisy environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance the wearer's trust in the system by clearly indicating the certainty level behind every piece of information provided, such as subtitles and face/name recognition. This clarity is crucial for maintaining a balance between rich context (which helps with memory support) and low-latency response (to avoid breaking the wearer's flow).

2. **What small change unlocks it**

   Define a simple confidence format that uses a numeric score combined with a label and short reason. For example, "score 0.84 + 'High' + 'Seen recently'". This format will provide enough detail to reinforce trust while remaining clear and concise.

3. **Likely payoff**

   By implementing a well-defined confidence format, the system can better manage expectations around its certainty in providing accurate information. This improves overall user trust, which is critical for real-time subtitle clarity and memory support tasks where accuracy matters.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size threshold for face/name memory helps ensure that common or recently encountered individuals are quickly recalled with high confidence, reducing the need to query the cloud and maintaining a low-friction assistive experience.

2. **What small change unlocks it**

   Define a local cache size limit of 10 recent faces/names that are frequently reinforced through interactions. This ensures that the most relevant memories are prioritized locally for fast lookup.

3. **Likely payoff**

   By keeping commonly encountered individuals in local memory, the system can quickly provide accurate face/name recall without cloud latency, enhancing the trust and reliability of the smart glasses as a daily-use assistant.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Improving the phone/cloud boundary for live subtitle processing ensures that real-time subtitles remain clear and stable enough to be trusted in live conversations, aligning with the core attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing remains local on the phone until high-confidence matches are made, then fall back to cloud for less certain names or faces.

3. **Likely payoff**

   By keeping live subtitle processing local, we reduce latency and ensure that subtitles remain readable and stable in noisy environments, enhancing the wearer's trust in real-time assistance. This also helps manage battery usage more efficiently.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that the primary focus remains on real-time subtitle clarity while still providing necessary contextual assistance without overwhelming the wearer. This balance enhances overall user experience by maintaining trust in the subtitles and reducing cognitive load.

2. **What small change unlocks it**

   Define a single rule that prioritizes subtitles over one-line prompts when both are present, with clear visual cues to differentiate between them. For example, always show subtitles first, then optionally display one-line prompts below or alongside them, depending on space constraints.

3. **Likely payoff**

   Implementing this hierarchy will reduce cognitive overload for the wearer by ensuring that essential information (subtitles) remains visible and prominent, while additional context (one-line prompts) is available but not distracting. This improves trust in real-time subtitles and reduces social awkwardness during conversations.

4. **Immediate next probe**

   Define one visual priority rule between subtitles and one-line support: always display subtitles first, then optionally show one-line prompts below them, with clear visual separation to maintain focus on the primary content.
