### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By establishing stable subtitle placement rules, we ensure that subtitles remain readable and do not become distracting. This improves the wearer's ability to follow conversations in real-time, enhancing the core attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define two specific subtitle placement modes: one for high-confidence states (e.g., well-known names or frequently repeated phrases) and another for low-confidence states (e.g., new faces or unfamiliar speech).

3. **Likely payoff**

   Implementing these rules will reduce subtitle distractions, making the wearer more confident in following conversations. This will enhance the overall user experience without overwhelming them with too much information.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By defining a clear, label-based confidence format that includes short reasons for certainty, the system can better manage trust in its memory and subtitle outputs without overloading the wearer with complex information.

2. **What small change unlocks it**

   Introduce a new confidence object format: `score 0.8 + "High" + "Seen recently"` for recently encountered names or faces, and `score 0.4 + "Low" + "Weak match"` for uncertain matches. This simple, yet informative format will help users trust the system's memory and subtitle accuracy.

3. **Likely payoff**

   Implementing this change will enhance user trust by making the confidence in memory and subtitles more transparent. Users will better understand when they can rely on the system's information, leading to a more natural and effective assistive experience.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache size and eviction rules helps ensure that the system retains relevant information while managing battery constraints, thus enhancing the wearer's trust in the memory support feature.

2. **What small change unlocks it**

   Define a local cache size limit of 10 recent interactions (names, faces) with an eviction policy based on recency and confidence score.

3. **Likely payoff**

   By limiting the local cache to 10 recent interactions, the system can maintain high memory accuracy while reducing battery usage and avoiding clutter, thereby strengthening the core attractor of "Trustworthy memory support."

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundary rules for what runs on the phone versus the cloud, we ensure that V1 focuses on essential, reliable features while offloading less critical tasks to the cloud when necessary. This helps maintain battery life and thermal stability, which are crucial for a lightweight, always-on assistant.

2. **What small change unlocks it**

   Define specific task boundaries such as live subtitle processing versus transcript cleanup or memory archive sync. For example, prioritize real-time subtitle placement over background memory syncing to ensure that the glasses remain responsive during critical interactions.

3. **Likely payoff**

   By clearly defining these boundaries, we can create a more reliable V1 experience where subtitles are always timely and accurate. This reduces the risk of thermal issues or battery drain, maintaining the wearer's trust in the system. Additionally, it allows us to focus cloud resources on non-critical tasks, making better use of available computational power.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for live subtitle processing where the glasses must remain fully functional regardless of network conditions.
