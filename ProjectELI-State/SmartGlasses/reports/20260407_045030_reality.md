# Reality Check for SmartGlasses Project

## Subtitle Placement Feasibility

- **Subtitle Clarity (subtitle_clarity)**
  - **Current Direction**: Place subtitles in a position that is clear and unobtrusive.
  - **Feasible Now**: The current design must ensure subtitles are legible, readable, and do not distract from the conversation. This can be tested using `TranscriptLab` to validate real-time subtitle placement. 
  - **Reasoning**: Given the emphasis on real-time clarity and social acceptability in V1, this is a critical area where we can iterate quickly based on visual tests.

- **Subtitle Visual Hierarchy (subtitle_visual_hierarchy)**
  - **Current Direction**: Ensure subtitles visually prioritize important information.
  - **Feasible Now**: Subtitles should be designed to draw attention to key phrases or names without overwhelming the wearer. `TranscriptLab` can provide initial feedback on subtitle readability and placement.

## Confidence Display Feasibility

- **Confidence Format (confidence_format)**
  - **Current Direction**: Use a label + short reason format for confidence display.
  - **Feasible Now**: Implement a prototype with this format in `TranscriptLab`. This can help surface early feedback on how wearers perceive and trust the system's confidence levels.
  - **Reasoning**: The goal is to build trust without creating an overly complex user interface, aligning well with V1 constraints.

## Memory/Cache Policy Feasibility

- **Face/Name Memory (memory_face_name)**
  - **Current Direction**: Store face/name memory locally on the phone for fast lookup.
  - **Feasible Now**: Implement a basic caching mechanism in `TranscriptLab` to test local storage. This will help understand how much data can be stored and looked up quickly without excessive battery drain.
  - **Reasoning**: Local processing is favored initially, so early implementation and testing of this feature are essential.

## Phone/Cloud Boundary Feasibility

- **Phone-First Processing (phone_first_processing)**
  - **Current Direction**: Keep heavy processing on the phone with cloud as optional.
  - **Feasible Now**: Ensure that `TranscriptLab` is optimized for local processing and minimal battery drain. Test various levels of cloud dependency to understand tradeoffs.
  - **Reasoning**: Early versions should prioritize simplicity and local processing, making it easier to iterate without worrying about remote dependencies.
