# Reality Check for SmartGlasses Project

## Subtitle Clarity: Real-time subtitle clarity (Subtitle Placement)

- **Feasible now**: Ensure that the current implementation in `TranscriptLab` is delivering subtitles that are clear, fast, and stable enough to be trusted during live conversations. Given that `TranscriptLab` is designed to simulate real-time behavior without heavy local processing, this should already be feasible with minor adjustments. 

## Memory Trust: Trustworthy memory support (Memory/Cache Policy)

- **Feasible now**: Implement a basic memory caching strategy on the phone where new faces and names are remembered with confidence objects using reinforcement learning over time. This can be achieved through simple label-based storage and periodic updates to ensure that memory remains trustworthy without overloading the system.

## Low-friction Assistance: Low-friction assistance (Confidence Display)

- **Feasible now**: Develop a confidence display mechanism that uses labels only for simplicity, as initial testing suggests this approach is sufficient. This can be implemented in `TranscriptLab` to provide one-line prompts and ensure they are not overwhelming the wearer.

## Constraint Pressure: Surface battery, latency, privacy, and usability limits (Phone/Cloud Boundary)

- **Feasible now**: Ensure that any new functionality respects the V1 real-world limits by staying lightweight on-glasses. For instance, avoid adding heavy on-device processing until cloud integration is well established and necessary for specific use cases.

## Interaction Constraints: Frame-touch-only V1 interaction (Interaction Direction)

- **Feasible now**: Continue to focus on frame-touch interactions only in `TranscriptLab`. This aligns with the current design constraints and helps ensure that any new feature or improvement respects the simplicity required for V1.

## Current Unknowns

- **Subtitle Placement**: Ensure that subtitles are placed in a non-distracting manner. Initial testing suggests placing subtitles at the bottom of the frame, slightly off-center, to minimize distraction.
  
- **One-line Prompts vs Subtitles**: Keep one-line prompts distinct from subtitles by using a different color or style. This can be achieved through minor adjustments in `TranscriptLab`.

- **Confidence Format**: Implement a simple confidence format that uses labels only for clarity and ease of use.

## V1 Real World Limits

- **Subtitle Clarity vs Battery Drain**: Ensure that subtitles remain clear, fast, and stable to avoid battery drain issues. Given the simplicity of the current implementation in `TranscriptLab`, this should be feasible with minor optimizations.

- **Rich Context vs Low-latency Response**: Maintain a balance by focusing on real-time responses while ensuring memory support remains robust enough for context. This can be tested through iterative improvements in both areas.

## Core Deepening

- **Bias toward subtitle, memory, confidence, and architecture improvements**: Focus on improving subtitle quality, memory trust, and visual UX within the current constraints of `TranscriptLab`.

## Constraint Pressure

- **Surface battery, latency, privacy, and usability limits early**: Ensure that any new feature or change is evaluated against these constraints. Given the success in `TranscriptLab`, this should be straightforward to implement.

### Assumptions Needing Evidence

- **Subtitle Placement**: More testing with real users might help refine subtitle placement further.
- **Confidence Format**: User feedback could inform whether a simple label-only format or more detailed confidence displays are preferred.

## Summary of Feasibility

- **Subtitle Clarity, Memory Trust, Low-friction Assistance** are feasible now and should be prioritized in `TranscriptLab`.
- **Constraint Pressure** is being effectively managed through the current implementation.
- **Interaction Constraints** remain aligned with V1 requirements.
- **Current Unknowns** need iterative testing and user feedback to refine specific aspects.

By focusing on these areas, we can ensure that the project remains grounded in real-world constraints while continuously improving core functionalities.
