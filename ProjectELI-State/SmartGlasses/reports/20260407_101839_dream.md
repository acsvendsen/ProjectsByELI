### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain readable and stable during live conversations. This enhances the wearer's ability to follow the conversation without becoming distracted or missing important information, thereby strengthening the core attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define 3 specific subtitle placement rules for different confidence states: 
   - High confidence (e.g., strong match): center and larger font size.
   - Medium confidence (e.g., weak match or hearsay): bottom-center with smaller font size, slightly less stable.
   - Low confidence (e.g., no match or uncertain): hidden until explicit user touch.

3. **Likely payoff**

   By setting clear placement rules for different confidence states, the system can reduce visual clutter while ensuring that high-confidence subtitles are immediately visible and readable. This improvement will make the subtitles more useful without overwhelming the wearer, thereby improving overall trust and real-time clarity.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that users can trust the system's memory support and subtitle accuracy more effectively. By refining how confidence is shown, we can enhance the wearer's understanding of when to rely on the system and when to seek additional context.

2. **What small change unlocks it**

   Define a simple yet informative confidence label plus short reason format for face/name recall and subtitles. For example, use "High" + "Seen recently" or "Low" + "Weak match".

3. **Likely payoff**

   By providing clear and concise confidence information, users will better understand the reliability of the system's memory support and subtitle accuracy. This improves trust and ensures that the wearer can focus on the most relevant information.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that memory recall for new people is reliable without requiring explicit user capture helps maintain the trust in the system's ability to assist effectively. This improves the wearer's confidence in relying on the glasses for critical moments, such as recognizing a new acquaintance or recalling prior conversations.

2. **What small change unlocks it**

   Define one entity-linking rule that automatically attaches new evidence to an existing person-memory object when there is sufficient similarity and context, but allows explicit user capture for reinforcement over time.

3. **Likely payoff**

   By automating the linking of new faces and names to existing memory objects with high confidence, the system can reduce false negatives in recall while maintaining the low-friction experience intended. This enhances the system's ability to provide timely and accurate assistance without overwhelming the user with too many explicit requests for capture.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays on the phone versus what falls back to the cloud for live subtitle processing, we can ensure that subtitles remain fast and stable enough to be trusted in real-time conversations. This decision directly supports the primary attractor of "Real-time subtitle clarity," ensuring that the glasses do not introduce noticeable latency or jitter.

2. **What small change unlocks it**

   Define a clear boundary where face recognition and name recall, which are critical for memory support, should remain phone-local to ensure fast response times and minimal battery impact. Specifically, set a rule that any task requiring immediate and reliable responses, such as live face/name recall, stays on the phone.

3. **Likely payoff**

   By keeping critical tasks like real-time face/name recall local, we can reduce latency, improve the reliability of memory support, and ensure that the glasses remain socially acceptable by minimizing their computational load and power consumption. This will lead to a more trusted and useful product in noisy environments where quick responses are essential.

4. **Immediate next probe**

   Define one phone-local fallback boundary for live face/name recall such that any new or uncertain face/name encounter falls back to the cloud only if the local processing times out or cannot make a confident decision within 50 milliseconds.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can easily read and understand critical information while minimizing distraction. This balance supports the core attractors of real-time subtitle clarity, memory trust, and low-friction assistance by making sure that essential content is prioritized over less crucial elements.

2. **What small change unlocks it**

   Define a clear precedence rule where subtitles always take priority over one-line support text. Implement a visual hierarchy strategy that ensures subtitles are displayed with higher prominence, while one-line support texts appear as smaller, secondary information that does not overwhelm the wearer's attention.

3. **Likely payoff**

   By ensuring subtitles remain prominently visible and readable, the system will maintain high trust in real-time communication. Additionally, by keeping one-line support text to a lower visual priority, the user experience will be smoother, reducing cognitive load during critical interactions.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
