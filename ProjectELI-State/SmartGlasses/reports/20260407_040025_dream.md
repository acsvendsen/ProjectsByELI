### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, the system can ensure that subtitles remain clear, stable, and unobtrusive during critical moments of conversation. This improves overall user trust by making sure important information is always visible without causing distraction.

2. **What small change unlocks it**

   Define three distinct subtitle placement modes: default hidden (only shown when confidence is low), partially visible at the bottom of the frame (moderate confidence), and prominently displayed across the entire frame (high confidence). This tiered approach allows for a balanced mix of clarity and non-intrusiveness.

3. **Likely payoff**

   Implementing these placement rules will enhance user trust in the system by ensuring that critical information is always legible without overwhelming the wearer. This improves the core attractor of "Real-time subtitle clarity" and helps maintain focus during important interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitles more confidently in noisy environments. A clear and concise confidence label, along with a short reason, helps the wearer understand when to rely on the subtitles and when they might need additional context.

2. **What small change unlocks it**

   Define one simple confidence object format: score + "High" + "Seen recently".

3. **Likely payoff**

   This change will help in building trust by providing clear feedback on the reliability of the subtitles. The wearer will be more likely to use and rely on the system when they see high-confidence indicators, reducing the likelihood of missing important information.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that frequently encountered faces and names are remembered with high confidence, while less relevant information is discarded to prevent cluttering the wearer's mental load. This helps maintain the core mission of providing trustworthy memory support without overwhelming the user.

2. **What small change unlocks it**

   Define a simple cache eviction rule based on recency and frequency of use for person-memory objects. Specifically, prioritize keeping recent and frequently encountered entities in local memory while evicting less relevant information to keep the cache size manageable.

3. **Likely payoff**

   By implementing a well-defined cache policy that respects real-world usage patterns, V1 can achieve better memory trust without adding unnecessary complexity or privacy risks. This will help maintain the core attractors of trustworthy memory support and low-friction assistance, while reducing the cognitive load on the wearer.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   - By defining a clear boundary for what stays phone-local versus falling back to cloud, we ensure that critical subtitle processing happens in real-time on the phone, maintaining low latency and ensuring the wearer can trust the subtitles during live conversations.

2. **What small change unlocks it**
   - Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing, focusing only on what needs to be sent to the cloud for processing and what can stay local.

3. **Likely payoff**
   - By keeping critical subtitle processing local, we reduce latency and ensure that subtitles are displayed in near-real-time, enhancing the wearer's trust in the system during conversations. This also helps manage battery usage by offloading non-critical tasks to the cloud when needed.

4. **Immediate next probe**
   - Define one phone/cloud fallback boundary for live subtitle processing: send all audio input and final transcript text to the cloud for processing, but keep subtitle rendering local on the phone.
