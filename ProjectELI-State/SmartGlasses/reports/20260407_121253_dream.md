### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles remain clear and stable enough to be trusted during live conversations. This will help in reducing social and cognitive friction, aligning with the core mission of the project.

2. **What small change unlocks it**

   Define two fixed subtitle placement modes: one for high-confidence text (e.g., names and faces) and another for lower-confidence text (e.g., contextual prompts). For example:
   
   - High confidence text is placed at a fixed position in the upper right corner.
   - Lower confidence text is placed slightly below or to the side, with less prominence.

3. **Likely payoff**

   This approach will help in maintaining subtitle clarity and reducing distraction during live conversations. It also ensures that high-confidence information (like names) remains prominently visible, while lower-confidence support (like prompts) does not overwhelm the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitle and memory support provided by the system. A clear and consistent confidence label, along with a short reason, helps in building and maintaining trust. This improves the overall reliability of the assistant, which is critical for real-time interaction assistance.

2. **What small change unlocks it**

   Define one specific confidence format candidate for V1 that includes both a numeric score and a concise label with an explanation. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'. This simple but precise format provides clear feedback to the wearer without overwhelming them.

3. **Likely payoff**

   By implementing a confidence display that combines numeric scores with clear labels and short reasons, users can better understand the reliability of the subtitle text and memory support. This will enhance trust in the system, leading to more frequent and reliable use, which is crucial for the core mission of improving real-world interaction understanding.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local memory threshold for name recall on the phone, we can ensure that the system retains enough recent interactions to provide relevant support without overwhelming the wearer with too much information. This helps in maintaining trust by accurately recalling names and prior context, which are critical aspects of the "memory_trust" attractor.

2. **What small change unlocks it**

   Define a local memory threshold for name recall that caps the number of recent interactions stored on the phone. For example, set a rule to keep the most recent 50 face/name interactions in memory.

3. **Likely payoff**

   This change will improve the reliability and accuracy of name recall by ensuring that the system has a manageable amount of recent context available for quick lookup. It will help maintain trust and usefulness while staying within battery constraints, aligning with the "memory_trust" attractor and the overall core mission.

4. **Immediate next probe**

   Define one local-memory threshold for face/name interactions to keep 50 most recent encounters on the phone.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific phone/cloud boundary for live subtitle processing, we ensure that real-time subtitles remain clear and stable without excessive cloud latency impacting performance. This focus helps maintain the core attractor of "Real-time subtitle clarity" by keeping critical processing local where it can be executed quickly.

2. **What small change unlocks it**

   Define a rule stating that all live subtitle processing must happen on the phone, with no fallback to the cloud unless explicitly justified for a specific task.

3. **Likely payoff**

   This boundary ensures that subtitles are delivered in near-real-time, reducing latency and maintaining trust in the system's responsiveness. It also allows the phone to handle local noise filtering and real-time adjustments without overloading the cloud, keeping battery use low.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
