### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance readability and stability, which are critical for maintaining trust in real-time conversations. Stable subtitle placement ensures that subtitles remain visible and unobtrusive, making them a reliable aid without distracting the wearer.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence speech (e.g., clearly heard names or words) and another for lower-confidence speech (e.g., softer background noise). This distinction can be achieved by setting different position offsets based on confidence scores, ensuring that higher-confidence subtitles are placed slightly closer to the edge of the field of view.

3. **Likely payoff**

   By creating distinct placement rules for high- and low-confidence speech, we can improve the overall readability and trustworthiness of subtitles. This will help in reducing visual clutter during clear interactions while keeping important information visible when dealing with less audible input.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a numeric score along with a label and short reason, we can enhance the wearer's trust in the system's understanding and memory accuracy. This approach ensures that the confidence level is transparent and provides contextual insights, which helps in maintaining the wearer's faith in the assistant without overloading them with unnecessary details.

2. **What small change unlocks it**

   Introduce a new `confidenceDisplayFormat` enum within the transcript model to include a numeric score (0-1 range), a confidence label (e.g., "High", "Medium", "Low"), and a short reason for the confidence level. For example, if the system is 85% sure about something, it would display: `score 0.85 + "High" + "Seen recently"`.

3. **Likely payoff**

   This change will make the confidence display more informative and trust-building. It allows the wearer to understand why a memory or prediction is made with a certain level of confidence, thus enhancing their acceptance and reliance on the system. It also aligns well with the core attractor of "Trustworthy memory support" by providing clear and concise feedback.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local cache threshold for name recall, we ensure that the system retains the most relevant memory data while respecting battery constraints and avoiding unnecessary storage. This improves trust by ensuring that names and faces are remembered reliably without overloading the device.

2. **What small change unlocks it**

   Define a specific threshold for the amount of face/name memory to be cached locally on the phone, based on recent interaction frequency and recency.

3. **Likely payoff**

   A well-defined local cache threshold will reduce battery usage by minimizing background syncing and storage requirements while ensuring that key names and faces are reliably recalled when needed. This improves trust and the overall user experience without overwhelming the device.

4. **Immediate next probe**

   Define a local cache eviction rule that retains memory for people seen within the last 7 days with more than 3 interactions, and evicts less frequent memories after 14 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear phone-local vs cloud boundaries for live subtitle processing, we ensure that subtitles remain stable and real-time, which is crucial for trust in noisy environments. This also helps manage battery and thermal constraints by offloading less time-critical tasks to the cloud.

2. **What small change unlocks it**

   Define a simple rule: All live subtitle processing stays local on the phone until explicit user interaction or low-confidence situations trigger a fallback to the cloud.

3. **Likely payoff**

   This approach ensures that subtitles remain crisp and reliable, maintaining high trust in real-time scenarios. It also reduces the risk of battery drain from constant cloud requests and keeps the system performant.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are clear, stable, and fast enough to be trusted in live conversations is crucial for the wearer's understanding and trust in the system. By defining specific subtitle placement rules for different confidence levels, we can create a more reliable visual aid that minimizes distraction while maximizing usability.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules based on confidence scores: one rule for high-confidence matches (e.g., faces and names seen frequently), another for medium-confidence matches (e.g., names heard once in conversation), and a third for low-confidence matches (e.g., new or uncertain faces).

3. **Likely payoff**

   By establishing clear placement rules, the system can reduce visual clutter, ensuring that critical information is always visible and easily readable. This will enhance the wearer's trust in the subtitles, making them more likely to rely on this feature during conversations.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
