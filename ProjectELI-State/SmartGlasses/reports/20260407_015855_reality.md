# Reality Check for SmartGlasses Core Field

## Feasibility Analysis

### Subtitle Clarity (Subtitle Placement)
- **Subtitle Placement**: To ensure subtitles are clear, fast, and stable enough to be trusted in live conversation, the glasses must display text that is readable even when moving or in noisy environments. Given the current hardware constraints (frame-touch-only V1), this can be feasible now by optimizing text size, contrast, and placement on the lens.

- **Visual Hierarchy**: Subtitles should coexist with one-line prompts without overloading the wearer. This can likely be achieved by carefully designing subtitle visibility to avoid distraction while ensuring they are easily readable. Feasible now within V1 constraints.

### Memory Trust (Face/Name Recall)
- **Memory Policy**: Face and name memory should expose uncertainty clearly, which is feasible with current technology but requires careful implementation of confidence objects and reinforcement rules. This can be done using the phone to handle heavy processing, making it a strong candidate for "feasible now."

- **Confidence Display**: Representing confidence as a numeric score or label + short reason can help build trust while maintaining privacy. Implementing this is feasible within current hardware constraints.

### Low-Friction Assistance (One-Line Prompts)
- **Prompt Visuals**: One-line prompts should visually differ from subtitles to avoid overwhelming the wearer. This requires designing a distinct UI element, which is feasible now as it aligns with V1's low-friction design principles.

### Core Deepening Over Sprawl
- **Subtitle Quality**: Improving subtitle clarity and stability is core-deepening work that strengthens the core mission. Feasible now within the current mode of operation.
  
- **Memory Support**: Enhancing memory recall and trustworthiness by implementing confidence objects and reinforcement rules is crucial for daily-use value. This can be done incrementally, making it feasible now.

### Phone/Cloud Boundary
- **Phone-First Runtime**: The phone should handle most of the heavy processing while allowing cloud access where justified. This aligns with current hardware constraints, making it a strong candidate for "feasible now."

### Interaction Constraints
- **Frame-Touch Only V1**: Ensuring all interactions are through frame touches only is critical for early hardware simplicity and social acceptability. This can be achieved by carefully designing the UI to prioritize touch-based controls.

## Assumptions Needing Evidence

- **Automatic Memory Support vs Confidence and Correction Safety**: While enhancing memory support is a core mission, ensuring that it does not create overly confident or incorrect recall requires careful implementation. Evidence from early user testing may help confirm this direction.
  
- **Subtitle Readability in Noisy Environments**: While the current design aims to ensure subtitles are clear, empirical data on how well they perform in noisy environments would be valuable. This could involve real-world user testing.

## Summary

### Feasible Now
- Subtitle clarity and placement
- Memory trust through confidence objects
- Low-friction one-line prompts
- Core deepening focus on subtitle quality and memory support
- Phone-first runtime with cloud as optional

### Feasible Later
- More advanced subtitle enhancements (e.g., real-time adjustments based on environmental factors)
- Advanced multimodal interactions that might become feasible after initial hardware iterations

### Likely Waste of Time
- Broad feature expansion without clear core mission alignment
- Speculative command modes or complex UI designs before V1 is proven effective

### Assumptions Needing Evidence
- Automatic memory support vs confidence and correction safety
- Subtitle readability in noisy environments

By focusing on these areas, the project can continuously surface real-world limitations early and make informed decisions that align with the core mission.
