# Reality Check for SmartGlasses

## Subtitle Clarity (subtitle_clarity)

### Feasibility: Feasible Now
- **Constraints**: Real-time subtitle clarity is crucial to maintaining the trust of users in noisy environments. The current implementation relies on the `TranscriptLab` app, which has successfully validated basic live transcription and confidence display.
- **Assumptions**: The hardware constraints for real-time subtitles are within the bounds of modern smartphones (e.g., sufficient CPU power, display quality). The `TranscriptLab` app is already providing a robust test bed for ensuring that subtitles remain clear, fast, and stable.

## Memory Trust (memory_trust)

### Feasibility: Likely Waste of Time
- **Constraints**: The memory trust aspect requires storing and reinforcing face/name recognition. Given the current constraint of V1 being frame-touch-only and primarily phone-first, adding complex memory mechanisms might be premature.
- **Assumptions**: The core deepening mode prioritizes subtitle quality and low-friction assistance over richer memory features. Implementing a robust memory system that respects privacy constraints could add significant complexity without immediate benefits in the early stages.

## Low-Friction Assistance (low_friction_assistance)

### Feasibility: Feasible Now
- **Constraints**: The V1 interaction should remain simple, focusing on frame-touch controls for subtitles and minimal one-line prompts. This aligns well with the current implementation of `TranscriptLab`, which provides a basic framework.
- **Assumptions**: The primary focus is on ensuring that the assistive text remains readable and unobtrusive. Given the simplicity of V1 interactions, further refinement in this area is feasible now.

## Privacy vs Usefulness (privacy_vs_usefulness)

### Feasibility: Feasible Later
- **Constraints**: Early hardware remains simple, and interaction should be frame-touch-only. The system must avoid creating command overhead or social awkwardness.
- **Assumptions**: While initial implementation can focus on basic functionality, privacy concerns will need to be addressed as the system evolves. Implementing a confidence format that respects user privacy (e.g., label only) is feasible in future iterations.

## Latency vs Richness (latency_vs_richness)

### Feasibility: Feasible Now
- **Constraints**: The system must provide timely help without overloading the runtime with richer but slower processing. The `TranscriptLab` app already provides a test bed for validating latency.
- **Assumptions**: Current implementations are focused on real-time transcription and simple confidence display, which align well with minimizing latency.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)

### Feasibility: Feasible Now
- **Constraints**: The glasses should remain socially acceptable while still being readable in motion and noise. The V1 interaction is frame-touch-only, which aligns with this constraint.
- **Assumptions**: Implementing a visual hierarchy that ensures subtitles are clear without becoming distracting can be done now using the `TranscriptLab` app as a test bed.

## Frame-Touch Only V1 (frame_touch_only_v1)

### Feasibility: Feasible Now
- **Constraints**: Early hardware remains simple, and interaction should remain frame-touch-only. This is already reflected in the current implementation of `TranscriptLab`.
- **Assumptions**: Ensuring that all interactions are handled through frame touches will require refining the user interface but can be done within the current scope.

## Phone-First Runtime (phone_first_runtime)

### Feasibility: Feasible Now
- **Constraints**: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified. The `TranscriptLab` app already implements this.
- **Assumptions**: Moving heavy processing to the phone helps manage battery and thermal constraints, making it a feasible implementation.

## Core Deepening Over Sprawl (core_deepening_over_sprawl)

### Feasibility: Feasible Now
- **Constraints**: Prefer work that improves subtitle quality, memory trust, and visual UX over broad feature expansion. The current focus on `TranscriptLab` aligns with this.
- **Assumptions**: Concentrating efforts on improving core functionality is a prudent approach given the early stage of development.

## V1 Real World Limits (v1_real_world_limits)

- **Assumptions**: Ensuring that the system remains lightweight and socially acceptable is a core focus of the initial development.
