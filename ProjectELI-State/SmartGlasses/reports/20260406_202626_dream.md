### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain a consistent, predictable user experience that reduces cognitive load and enhances trust in the system's reliability. Stable placement allows users to focus on the conversation rather than adjusting their gaze or trying to read subtitles that move erratically.

2. **What small change unlocks it**

   Define 3 fixed subtitle placement rules for different confidence states: high (always visible), medium (visible but slightly lower priority), and low (temporarily hidden until more evidence is gathered).

3. **Likely payoff**

   By implementing stable, state-based subtitle placement, users can rely on the system to present subtitles in a predictable manner, reducing cognitive effort and increasing trust in the assistive nature of the glasses.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring clear, consistent confidence display helps build trust in the system's reliability. By clearly indicating the certainty of information provided (e.g., through a numeric score and label), the wearer can better assess the accuracy of subtitles and memory recall. This transparency enhances the user's confidence in the system without making the interface overly complex.

2. **What small change unlocks it**

   Define one confidence format that uses a numeric score, label, and short reason to describe certainty. For example: `score 0.84 + "High" + "Seen recently"` for high-confidence information, `score 0.42 + "Low" + "Weak match"` for less certain data.

3. **Likely payoff**

   Implementing a clear confidence display will reduce user frustration by providing context when the system is unsure about something, and it will increase overall trust in the system's accuracy. This clarity can lead to more natural interactions and better acceptance of the glasses as a useful tool rather than a potential source of error.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   Improving the local cache size for memory lookup ensures that frequently encountered names and faces are readily available, reducing latency and enhancing the wearer's confidence in the system’s reliability.

2. **What small change unlocks it**
   Define a local cache threshold for face/name recall objects on the phone to prioritize recent or frequent encounters while minimizing storage overhead.

3. **Likely payoff**
   By caching frequently seen names and faces locally, the system can quickly retrieve this information during conversations, improving response time and reducing the need for cloud queries. This enhances overall user trust and satisfaction by providing faster, more reliable memory support.

4. **Immediate next probe**
   - Define a local cache size for face/name recall objects on the phone to balance storage efficiency with quick lookup performance.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs locally on the phone versus what falls back to the cloud, we ensure that critical real-time processing and user experience elements remain stable and responsive. This allows the glasses to provide consistent, low-latency support without overloading the device's limited resources.

2. **What small change unlocks it**

   Define a single task boundary for live subtitle processing: if the glasses cannot process subtitles in real time locally, fallback to cloud processing only for those instances where latency is acceptable and privacy risks are minimal.

3. **Likely payoff**

   By ensuring that live subtitle processing remains local, we maintain high-quality, reliable subtitles even under low battery conditions or thermal constraints. This improves trust and overall user experience by providing consistent real-time support without the risk of dropped or delayed text.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.

3. **Likely payoff**
