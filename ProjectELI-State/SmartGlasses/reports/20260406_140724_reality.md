# Reality Check for SmartGlasses V1 Direction

## Core Mission
The mission of creating discreet, context-aware smart glasses that provide live subtitles, face/name recall, conversation memory, and one-line support remains focused on enhancing the wearer's understanding and interaction in real-world scenarios.

## Decision Areas and Feasibility Assessments

### Subtitle Placement: feasible now
- **Reasoning**: With current hardware constraints, placing subtitles discreetly but clearly visible is critical. A good starting point would be to position subtitles at the bottom of the field of view (FOV), slightly offset from the center, ensuring they do not block the user's primary line of sight.
- **Constraints**: Must remain unobtrusive while providing sufficient readability.

### Confidence Display: feasible later
- **Reasoning**: Implementing a confidence format that builds trust could include a label only, label + short reason, or score + label. However, initial versions should prioritize subtitle clarity and usability over complex confidence indicators.
- **Constraints**: High latency in processing could degrade user experience; thus, this feature is better suited for later iterations.

### Memory/Cache Policy: feasible now
- **Reasoning**: Implementing a basic memory policy that automatically remembers new faces and names with context-based reinforcement should be straightforward. This can involve using a simple cache on the phone to store recent interactions.
- **Constraints**: Battery usage must be managed, and privacy concerns should be addressed by being transparent about how memories are stored.

### Phone/Cloud Boundary: feasible now
- **Reasoning**: The current architecture direction emphasizes a phone-first approach for processing and memory lookup. This allows for quick iterations and reduces the thermal load on the glasses.
- **Constraints**: Ensuring fast enough responses in noisy environments while keeping latency within acceptable limits is crucial.

### Visual Hierarchy: feasible now
- **Reasoning**: Designing a visual hierarchy that prioritizes subtitles over other UI elements will ensure they remain useful without overwhelming the user. One-line prompts should visually differ from subtitles to maintain clarity.
- **Constraints**: Must balance the need for clear information with social acceptability and usability.

### Interaction Constraints: feasible now
- **Reasoning**: Frame touches as the primary method of interaction aligns well with current hardware constraints and is socially acceptable. Avoiding voice commands in V1 ensures a focus on core functionality.
- **Constraints**: Ensuring that frame-touch interactions are intuitive and effective requires careful design but is within the bounds of current technical capabilities.

### Drift Risks
- **Feature Sprawl**: Deepen subtitle quality, memory trust, confidence display, and low-friction visual UX rather than adding unnecessary features.
- **Interaction Complexity**: Stick to simple interaction methods like frame touches until V1 is proven successful.
- **Latency Issues**: Ensure that responses feel near-real-time; otherwise, user trust will be compromised.

### Reality Constraints
- **Battery and Thermals**: Keep early versions phone-first to manage these constraints effectively.
- **Privacy**: Be transparent about how memory is stored and managed. Use contextual reinforcement for automatic learning without overwhelming the user with explicit actions.
- **Usability**: Prioritize clear, unobtrusive design that enhances rather than distracts from the primary task of understanding and interacting.

### Open Questions
1. **Subtitle Placement**: Determine a placement strategy that minimizes distraction while ensuring readability.
2. **Confidence Format**: Decide on the best confidence format to build trust without overwhelming users.
3. **Memory Policy**: Define a caching strategy for face/name recall that respects battery limits and user privacy.
4. **Visual Hierarchy**: Design a clear visual hierarchy that prioritizes subtitles over other UI elements.

### Assumptions Needing Evidence
- **Cloud Dependency**: Evaluate whether cloud support is essential for certain features or can be avoided in V1.
- **User Trust**: Confirm through testing how users perceive the system's trustworthiness and reliability.

## Summary
The current direction of creating smart glasses that provide live subtitles, face/name recall, conversation memory, and one-line support is feasible now. Key decisions should focus on subtitle placement, confidence display (with an emphasis on later iterations), memory policy, phone/cloud architecture, and visual hierarchy. These elements can be implemented while respecting the constraints of battery, privacy, and usability.
