## Reality Check Summary for SmartGlasses V1 Direction

### Core Deepening and Constraints

#### Subtitle Clarity: Feasible Now
- **Current Decision**: More Prominent subtitle placement.
- **Feasibility**: High. The glasses already have a minimal display setup, so shifting the text can be done without significant hardware changes.

#### Confidence Display: Feasible Later
- **Current Decision**: Label + Reason for confidence.
- **Feasibility**: High potential. However, implementing this requires fine-tuning of confidence algorithms and UI design, which might be resource-intensive in V1 but is a good long-term goal.

#### Memory Policy: Recency First Cache
- **Current Decision**: Recency-first cache policy.
- **Feasibility**: Feasible now with some adjustments. The memory caching can start simple, focusing on recency to reduce cloud dependency and thermal pressure early on.

#### Phone/Cloud Boundary: Phone First
- **Current Decision**: Primary runtime on the phone for speech processing, context lookup, etc.
- **Feasibility**: Feasible now. This aligns with the current architecture direction of keeping V1 simple and ensuring fast iteration.

#### Visual Hierarchy: Subtitles Dominate
- **Current Decision**: Subtitles should dominate to ensure clarity.
- **Feasibility**: Feasible now. Ensuring that subtitles remain dominant will help in maintaining readability without overwhelming the user.

### Core Mission and Constraints

#### Frame-Touch Interaction Only
- **Current Constraint**: V1 interaction is frame-touch only.
- **Feasibility**: Feasible now with clear constraints on simplicity. This ensures low friction for users while staying within hardware limitations.

#### Phone-First Architecture
- **Current Decision**: Primary runtime on the phone.
- **Feasibility**: Feasible now. This approach reduces thermal and battery pressure, allowing for a more focused V1 release.

#### Real-Time Subtitle Latency
- **Current Constraint**: Subtitles must feel near-real-time or risk breaking trust.
- **Feasibility**: Feasible now with the TranscriptLab app providing a test bed. Ensuring latency is managed through this testing will help maintain real-time responsiveness.

### Tensions and Trade-offs

#### Privacy vs Usefulness
- **Current Tension**: Need to balance helping the wearer without invading privacy.
- **Feasibility**: Feasible later. Implementing automatic memory support while ensuring it does not feel invasive or create corrupted recall requires careful implementation and user testing, which is beyond V1.

#### Always-On Sensing vs Battery and Thermals
- **Current Tension**: Early versions should not depend on heavy on-glasses compute.
- **Feasibility**: Feasible now. The current architecture focuses on keeping early hardware simple to manage battery and thermals effectively.

- **Feasibility**: Likely waste of time. Early focus should be on core functionality rather than adding complex interactions that are not part of the current design constraints.

- **Feasibility**: Likely waste of time. Core features like subtitle clarity, memory support, and confidence display should take precedence over new interaction patterns in V1.
