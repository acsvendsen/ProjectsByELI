## Reality Check for SmartGlasses Project

### Subtitle Clarity (Real-time subtitle clarity)
- **Feasible Now**: The current system should focus on delivering clear, stable subtitles that are fast enough to be trusted in live conversation. Given the success of `TranscriptLab`, this is achievable with further optimization of text rendering and stability.
- **Assumptions Needing Evidence**: Ensure the subtitles can handle motion well without distorting or breaking during movement. This will require fine-tuning the display algorithm.

### Memory Trust (Trustworthy memory support)
- **Feasible Now**: Implement face/name recall that clearly indicates uncertainty when appropriate, such as using "Maybe John" instead of "John". This requires a confidence mechanism that can be grounded in real-world interactions.
- **Assumptions Needing Evidence**: Determine how the system will handle ambiguous situations (e.g., seeing someone who looks like they know but are unsure) and ensure it does not overpromise.

### Low-friction Assistance (Low-friction assistance)
- **Feasible Now**: Deliver one-line prompts that add value without overwhelming the wearer. The current mode of interaction, frame touches, should be sufficient for this.
- **Assumptions Needing Evidence**: Test different types of one-liners to ensure they are helpful and not intrusive.

### V1 Interaction Constraints
- **Feasible Now**: Frame-touch interactions remain the primary method for now. This aligns with the `TranscriptLab` focus on simplicity and avoids unnecessary complexity.
- **Assumptions Needing Evidence**: Validate that frame touches can handle all necessary functions, such as toggling subtitle visibility or confirming memory entries.

### Phone/Cloud Boundary
- **Feasible Now**: Continue to bias towards phone-first processing for heavy tasks like context lookup and model inference. Cloud support should be optional where latency is critical.
- **Assumptions Needing Evidence**: Evaluate the specific use cases that would benefit from cloud processing and ensure they are justified by current constraints.

### Confidence Display
- **Feasible Now**: Implement a confidence display format that builds trust, such as a label with a short reason or a score. This should be tied to real-world testing.
- **Assumptions Needing Evidence**: Determine the best way to convey uncertainty without confusing the wearer and ensure it aligns with user feedback.

### Subtitle Placement
- **Feasible Now**: The placement should remain unobtrusive but still readable, such as in a corner of the field of view. This requires balancing visual clarity with social acceptability.
- **Assumptions Needing Evidence**: Conduct usability tests to determine if the current placement works well and make adjustments as needed.

### Visual Hierarchy
- **Feasible Now**: Ensure subtitles are prioritized over other elements but remain readable in a noisy environment. This can be tested through real-world usage scenarios.
- **Assumptions Needing Evidence**: Verify that the visual hierarchy supports the core mission of improving understanding without overwhelming the wearer.

### Battery and Latency
- **Feasible Now**: Given the focus on phone-first processing, ensure the system remains power-efficient. The `TranscriptLab` tests should help validate this.
- **Assumptions Needing Evidence**: Monitor battery usage during real-world testing to ensure it stays within acceptable limits.

### Privacy and Usability
- **Feasible Now**: Implement privacy features that avoid over-capturing data, such as only remembering names when explicitly prompted. This aligns with the project's non-negotiables.
- **Assumptions Needing Evidence**: Test various scenarios to ensure the system respects user privacy while still providing useful assistance.

### Core Deepening
- **Feasible Now**: Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion. This is aligned with the current mode of operation.
- **Assumptions Needing Evidence**: Continue to refine these core areas through iterative testing and user feedback.

By focusing on these specific areas, the project can maintain its core mission while addressing real-world constraints and ensuring continuous improvement.
