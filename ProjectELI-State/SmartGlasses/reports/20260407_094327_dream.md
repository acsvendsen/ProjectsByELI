### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Stable subtitle placement rules ensure that subtitles remain readable, clear, and non-distracting during live conversations. This improves the wearer's ability to follow along without being interrupted by constantly moving or fluctuating text.

2. **What small change unlocks it**

   Define three fixed subtitle placement modes: top center, bottom center, and offscreen. Automatically select the best mode based on context (e.g., background noise level, screen orientation).

3. **Likely payoff**

   By choosing a stable subtitle placement strategy, V1 can ensure that subtitles are always visible and readable, reducing cognitive load and increasing trust in the system during critical interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance the trustworthiness of memory support, ensuring that the wearer can rely on accurate and clear indications of when a name or face is recognized correctly.

2. **What small change unlocks it**

   Define a confidence object format that combines a numeric score with a label and short reason, such as "score 0.85 + 'High' + 'Seen recently in conversation'".

3. **Likely payoff**

   By providing clear and detailed confidence indicators, the system will build trust through transparent and reliable memory support, reducing uncertainty and enhancing the wearer's confidence in the accuracy of remembered information.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Memory policies that limit local cache sizes for face/name recall can reduce memory clutter while ensuring critical information is quickly accessible. This helps maintain a clean and focused visual environment, reducing cognitive load and improving overall trust in the system's ability to support real-time interactions.

2. **What small change unlocks it**

   Define a local cache size threshold of 10 entries for face/name recall. Entries older than one week should be evicted first to make room for more recent and relevant information.

3. **Likely payoff**

   By limiting the number of stored memories, the system can maintain faster lookups and a cleaner UI, enhancing the wearer's trust in the assistant’s reliability during real-time interactions.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we ensure that critical real-time subtitle processing happens locally. This reduces latency and keeps the system more reliable, enhancing trust and the overall user experience.

2. **What small change unlocks it**

   Define one local-cache size limit for face/name memory lookup that ensures frequent but not overburdened access to recently seen entities, allowing fast retrieval of necessary context without excessive data transfer.

3. **Likely payoff**

   This approach will reduce latency and improve the reliability of subtitle processing, making the system more responsive and trustworthy during live interactions. It also ensures that critical memory lookups are fast, enhancing the overall user experience by reducing the burden on cloud resources while maintaining essential functionality locally.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**
