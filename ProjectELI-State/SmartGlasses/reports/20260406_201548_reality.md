# Reality Check for SmartGlasses V1 Direction

## Core Attractors and Tensions

### Real-time Subtitle Clarity (subtitle_clarity)
- **Feasibility**: Feasible now. The current transcript test app (`TranscriptLab`) provides a solid foundation for real-time subtitle clarity. With ongoing optimization, we can maintain readability, stability, and timely updates.
- **Constraints**: Ensure that subtitles do not lag beyond 50ms to 100ms latency; otherwise, trust will be compromised.

### Trustworthy Memory Support (memory_trust)
- **Feasibility**: Feasible now. Implementing basic face/name recall with context-based reinforcement should be achievable using local phone storage and minimal cloud support for model updates.
- **Constraints**: Need to ensure that memory does not over-rely on cloud processing, which could introduce latency or privacy concerns.

### Low-friction Assistance (low_friction_assistance)
- **Feasibility**: Feasible now. Simple one-line prompts can be designed without requiring complex interaction patterns like voice commands.
- **Constraints**: Ensure that the one-line prompts are unobtrusive and do not create social awkwardness, especially during conversations.

## Tensions

### Privacy vs Usefulness (privacy_vs_usefulness)
- **Feasibility**: Feasible now. Design memory and face/name recall to be context-aware and reinforce over time rather than creating a history of data points.
- **Constraints**: Avoid storing unnecessary personal information locally; use cloud only for model updates where latency is not an issue.

### Latency vs Richness (latency_vs_richness)
- **Feasibility**: Feasible now. Focus on providing timely and concise assistance rather than overloading the wearer with rich but slower processing.
- **Constraints**: Ensure that any additional features do not introduce unacceptable latency, which could break the wearer's trust.

### Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Feasibility**: Feasible now. Design subtitles and prompts to be readable in motion and noise while minimizing distraction.
- **Constraints**: Ensure that visual clarity does not compromise battery or thermal constraints, particularly for always-on features.

## Implementation Grounding

### Frame-touch-only V1 Interaction
- **Feasibility**: Feasible now. V1 should stick to frame touches as the primary method of interaction.
- **Constraints**: Avoid suggesting voice activation or spoken command control until a clear need emerges and is properly justified by real-world constraints.

### Phone-first Runtime
- **Feasibility**: Feasible now. Heavy processing should be handled on the phone, with cloud support optional where clearly needed.
- **Constraints**: Do not assume heavy local computation; maintain a path to stronger local capability later if necessary.

### Core-deepening Over Sprawl
- **Feasibility**: Feasible now. Focus improvements that deepen subtitle quality, memory trust, confidence display, and low-friction visual UX over broad feature expansion.
- **Constraints**: Avoid adding unnecessary complexity or features until their value is clearly demonstrated through concrete use cases.

## Current Unknowns

### Subtitle Placement
- **Feasibility**: Feasible now. Use best effort within `subtitle placement`.
- **Constraints**: Ensure that subtitles do not distract the wearer and are placed in a way that maximizes readability while minimizing visual clutter.

### Confidence Display
- **Feasibility**: Feasible now. Implement confidence display formats such as labels or short reasons for quick comprehension.
- **Constraints**: Avoid overly complex displays; simpler formats like label only or label + short reason should suffice initially.

### Memory/Cache Policy
- **Feasibility**: Feasible now. Develop a basic memory policy that remembers names, faces, and prior context with reinforcement over time.
- **Constraints**: Ensure that the cache is not bloated with unnecessary data; prioritize useful and relevant information.

### Phone/Cloud Boundary
- **Feasibility**: Feasible now. Keep processing primarily on the phone while using cloud for model updates where latency is manageable.
- **Constraints**: Avoid heavy reliance on cloud for real-time decisions; keep core functionality local to maintain responsiveness.

### Visual Hierarchy
- **Feasibility**: Feasible now. Design a visual hierarchy that prioritizes subtitles and prompts without overwhelming the wearer.
- **Constraints**: Ensure that the display remains unobtrusive and does not create social awkwardness during conversations.

## Summary

The current V1 direction is feasible with the given constraints, but continuous attention to subtitle latency, memory trust, user interaction simplicity, and visual clarity will be crucial. The project should focus on deepening core capabilities while avoiding broad feature sprawl or unnecessary complexity. Early iterations should remain phone-first and frame-touch-only to ensure practicality and usability.

By surfacing these constraints early, the team can make informed decisions that stay aligned with the mission of discreet, context-aware personal assistance through live subtitles, face/name recall, conversation memory, and one-line support.
