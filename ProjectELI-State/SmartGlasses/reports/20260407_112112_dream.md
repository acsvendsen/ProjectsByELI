### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states helps ensure that subtitles are always in a visible and non-distracting position, which enhances the wearer's ability to follow live conversations. This stability and clarity in subtitle presentation aligns with the core attractor of real-time subtitle clarity and supports the core mission of making the wearer understand better without overloading their visual field.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules for different confidence states, such as "always visible at the bottom center," "adjustable based on head movement with a minimum height," and "slightly above the bottom edge for low-confidence content."

3. **Likely payoff**

   By establishing clear subtitle placement rules, V1 can ensure that subtitles remain readable and unobtrusive during live conversations, thereby increasing user trust and satisfaction. This will help maintain the core mission of making the wearer understand better in real-world interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring that confidence labels are clear and concise helps maintain the wearer's trust in the system's accuracy without overwhelming them with complex explanations. This clarity is crucial for the memory support attractor, as it ensures that when names or faces are recalled, the wearer understands the level of certainty behind each piece of information.

2. **What small change unlocks it**

   Define a consistent confidence format that uses a score (e.g., 0.85) combined with a label and short reason (e.g., "High" + "Seen recently"). This format provides enough detail to reinforce memory trust while remaining simple and unobtrusive.

3. **Likely payoff**

   By providing clear, concise confidence labels, the system can better manage the wearer's expectations about the accuracy of name and face recall. This reduces cognitive load and builds trust over time as the wearer comes to rely on the system for accurate memory support.

4. **Immediate next probe**
   - Define the confidence score presentation as 0.85 for V1.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - Improving memory cache policy helps ensure that the system can quickly recall names and faces, which is crucial for maintaining trust in name and face recognition. This enhances the overall memory trust attractor and ensures that the wearer feels supported without false certainty.

2. **What small change unlocks it**
   - Define a local cache threshold for name recall based on recency and frequency of use, ensuring that recently encountered names are prioritized over older ones to maintain high confidence in active contexts.

3. **Likely payoff**
   - By focusing the cache on recently seen names, the system can provide faster and more accurate face/name recognition, reducing latency and improving the reliability of memory support. This will enhance user trust and satisfaction with the product's core functionality.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what data stays phone-local versus falling back to the cloud, we can ensure that sensitive or frequently accessed memory remains on-device while still leveraging cloud processing where it adds significant value. This helps balance privacy concerns with useful functionality and aligns with the project's focus on core deepening.

2. **What small change unlocks it**

   Define a specific task boundary for face/name recall lookup, such as deciding that real-time lookups for names should stay phone-local to maintain local processing of sensitive data.

3. **Likely payoff**

   By keeping name recall primarily phone-local, we can reduce battery drain from frequent cloud requests and maintain a higher level of privacy by not transmitting potentially identifiable information over the network. This also allows for faster lookups and more stable behavior in noisy environments where latency is critical.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that the most critical information (subtitles) remains prominently visible while still allowing for low-friction assistance through minimal intrusion from one-line prompts.

2. **What small change unlocks it**

   Define a precedence rule where subtitles are always displayed with higher priority over one-line support, but allow one-line support to be shown when there is no current subtitle text or the wearer has touched the glasses frame.

3. **Likely payoff**

   This decision will improve the wearability of the glasses by ensuring that critical information (subtitles) remains unobstructed while still providing necessary contextual support without overwhelming the wearer with too much visual data.

4. **Immediate next probe**

   Define one visual priority rule between subtitles and one-line support, prioritizing subtitles over one-line prompts when both are available.
