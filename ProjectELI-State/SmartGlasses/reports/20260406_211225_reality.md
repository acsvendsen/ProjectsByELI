# Reality Check Summary

## Subtitle Clarity: Real-time subtitle clarity (Subtitle Placement)
- **Feasible Now**: The core `TranscriptLab` test app can validate basic subtitle display quality and stability on a real device. This feasibility does not change given the current hardware constraints.
  - **Reasoning**: The initial prototype in `TranscriptLab` should be able to demonstrate whether subtitles are clear, fast, and stable enough for live conversation without needing complex hardware or processing.

## Memory Trust: Trustworthy memory support (Memory/Cache Policy)
- **Feasible Now**: Implementing face/name recall with confidence objects that allow users to distinguish between remembered names and new faces can be done locally on the phone.
  - **Reasoning**: Given the constraint of frame-touch-only V1 interaction, a simple implementation using local storage and real-time updates via cloud (if needed) can ensure that memory support is trustworthy.

## Low-friction Assistance: Low-friction assistance (Confidence Display)
- **Feasible Now**: Designing one-line prompts with clear confidence indicators can be done within the current V1 interaction constraints.
  - **Reasoning**: One-line prompts can be designed to display in a way that minimizes command overhead and social awkwardness, using labels or short reasons for confidence.

## Frame Touch Only Interaction (V1 Interaction)
- **Feasible Now**: The initial V1 interaction should focus on frame touches. This does not change given the project inputs.
  - **Reasoning**: No changes to this constraint are proposed; it remains a hard requirement that must be respected in V1 design.

## Phone-first Runtime (Phone/Cloud Boundary)
- **Feasible Now**: The phone should handle heavy processing, with cloud optional where clearly justified. This does not change given the project inputs.
  - **Reasoning**: The current implementation of `TranscriptLab` aligns with this constraint by keeping heavy processing on the phone and using the cloud only for background tasks.

## Core Deepening Over Sprawl (Core Deepening)
- **Feasible Now**: Focusing on subtitle quality, memory trust, confidence display, and visual UX improvements is a valid direction.
  - **Reasoning**: The project inputs clearly state that core-deepening over sprawl is the current mode, and these areas align with the attractors defined.

## Privacy vs Usefulness (Privacy vs Usefulness)
- **Feasible Now**: Implementing memory support that does not pretend certainty can be done. This does not change given the project inputs.
  - **Reasoning**: The system should remember names and faces without creating corrupted recall, aligning with the privacy vs usefulness tension.

## Latency vs Richness (Latency vs Richness)
- **Feasible Now**: Ensuring that subtitles are near-real-time is critical for trust. This does not change given the project inputs.
  - **Reasoning**: The core functionality of providing real-time subtitles requires low latency, which can be validated in `TranscriptLab`.

## Discreet UX vs Visual Clarity (Discreet UX vs Visual Clarity)
- **Feasible Now**: Designing subtitles and prompts that remain socially acceptable while still being readable is a valid direction.
  - **Reasoning**: The current focus on subtitle clarity and one-line assistance aligns with the need for discreet, clear UI.

## Real-world Constraints (V1 Real World Limits)
- **Feasible Now**: Keeping glasses hardware simple in V1 and biasing toward phone-first processing is feasible. This does not change given the project inputs.
  - **Reasoning**: The project explicitly states that early versions should rely heavily on phone processing, which `TranscriptLab` currently supports.
