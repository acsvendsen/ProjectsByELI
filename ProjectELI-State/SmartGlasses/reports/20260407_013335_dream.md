### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules ensures that subtitles remain clear, readable, and unobtrusive during live conversations. Stable and well-placed subtitles enhance trust in the system's real-time capabilities, which is crucial for the wearer to rely on the assistant effectively.

2. **What small change unlocks it**
   Define a fixed position for subtitles that prioritizes readability while minimizing distraction. For example, place subtitles at the bottom center of the frame, with a slight bias towards the left edge to avoid blocking important visual context.

3. **Likely payoff**
   A well-defined and stable subtitle placement rule will reduce user frustration related to distracting or unreadable subtitles. This improvement will enhance the overall trust in the system's real-time capabilities, making it more reliable for the wearer in noisy environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display by using a label-only format with clear short reasons can enhance trust without overwhelming the wearer. This ensures that the system's certainty is communicated clearly, helping the wearer understand when to rely on the subtitles and when they might need to pay closer attention.

2. **What small change unlocks it**

   Define one simple confidence format for V1: use a label only (e.g., "High," "Low") with a short reason (e.g., "Seen recently," "Weak match"). This can be achieved by setting the default confidence display in the `TranscriptLabModel.swift` file to include both a label and a brief description.

3. **Likely payoff**

   By using this simple format, the system can communicate its certainty levels clearly without adding unnecessary complexity. This will help build trust over time as users see consistent and understandable confidence indicators, leading to better overall acceptance of the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   Improving the local cache size threshold for face/name memory ensures that frequently encountered individuals are quickly recognized and remembered, enhancing the wearer's trust in the system's ability to recall names and faces accurately. This reduces the likelihood of incorrect or forgotten recollections, which can undermine the wearer's confidence.

2. **What small change unlocks it**
   Define a local cache size threshold for face/name memory that prioritizes frequently encountered individuals while ensuring that less common entities are not forgotten entirely but rather remembered with lower frequency. For instance, set the cache to retain information about faces and names seen more than 5 times in recent sessions.

3. **Likely payoff**
   By setting a reasonable local cache size threshold, the system can maintain a balance between remembering new people while ensuring that frequent individuals are not overburdening the memory resources. This approach enhances the overall trustworthiness of the memory support and ensures that the wearer feels confident in the system's ability to recall important names and faces.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining which memory operations fall back to the cloud versus staying local on the phone, we can ensure that V1 remains focused and efficient. This helps maintain the low-friction UX while providing robust support for critical functionalities like face/name recall and conversation memory.

2. **What small change unlocks it**

   Define a clear rule for what stays phone-local and what falls back to cloud for live subtitle processing. For example, keep local caching of recently seen faces and names but fall back to the cloud for older or less frequently accessed memories.

3. **Likely payoff**

   By keeping critical memory operations local, we can ensure fast lookups and reliable performance even with limited network availability. This improves the overall trustworthiness and usability of V1 without overloading the phone's resources.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

It will help the wearer stay focused on real-time subtitles during conversations, thereby improving their understanding and reducing cognitive load.
