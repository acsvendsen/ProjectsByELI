# Consolidation of Core Signals for SmartGlasses V1

## Strengthening Signals

1. **Subtitle Quality**: Focus on making subtitles clear, fast, and stable enough that they are trust-preserving during live conversations. This is critical for the wearer's understanding and acceptance.

2. **Memory Trust and Speed**: Enhance face/name recall with clear confidence indicators and ensure memory is reinforced over time without creating false certainty. Memory should be recency-first to maintain relevance.

3. **Low-Friction UX**: Ensure that all assistive behavior, including subtitles and one-line prompts, remains low-friction and does not become a social burden. 

4. **Phone-First Architecture**: Continue prioritizing phone processing for heavy tasks like context lookup and orchestration while keeping glasses hardware lightweight to avoid battery and thermal issues.

## Weakening Signals

1. **Command Surfaces**: Reduce the inclination towards adding command surfaces or voice activation in V1, maintaining frame-touch-only interaction.
  
2. **Complex Visuals**: Minimize the use of complex AR visuals or multimodal UI that could distract from core functionality.

3. **Heavy Autonomous Behavior**: Avoid speculative heavy autonomous behavior without strong confidence signals and clear value added by cloud processing.

## Contradictions That Must Stay Alive

1. **Privacy vs Usefulness**: Balancing the system’s helpfulness with its invasiveness, ensuring it does not quietly slide into invasive capture or retention practices.
  
2. **Latency vs Richness**: Prioritizing timely help over richer but slower processing to avoid breaking trust.

3. **Discreet UX vs Visual Clarity**: Striking a balance between making the system socially acceptable and ensuring that subtitles are readable in motion and noise.

## Dormant Ideas Worth Reactivating

1. **Subtitle Placement**: Re-evaluate subtitle placement options, particularly more prominent displays, to ensure they do not become distracting but remain useful.
  
2. **Confidence Display**: Consider different confidence formats (label only vs label + short reason) to enhance trust while maintaining visual clarity.

## Concrete Tensions Around Core Areas

1. **Subtitle Reasoning and Visual UX**:
   - **Subtitle Quality**: Ensure subtitles are clear, fast, and stable enough to maintain wearer trust.
   - **Visual Hierarchy**: Optimize subtitle placement for readability without causing distraction.

2. **Confidence and Memory Policies**:
   - **Memory Cache Policy**: Implement recency-first memory caching on the phone while maintaining clear confidence indicators.
   - **Privacy vs Usefulness**: Ensure memory support is useful but does not create privacy concerns.

3. **Interaction Constraints**:
   - **Frame-Touch-Only Interaction**: Focus on frame touches for all interactions, avoiding voice commands in V1.
   - **Phone/Cloud Boundaries**: Keep heavy processing on the phone while using cloud only where clearly justified.

## Open Questions

1. **Subtitle Placement**: Determine if more prominent subtitle placement is beneficial without causing distraction.
2. **Confidence Display**: Decide between a label-only or label + short reason format for confidence indicators.
3. **Memory/Cache Policy**: Define how much face/name memory should be cached locally and the criteria for cache eviction.

## Real-World Constraints

1. **Battery and Thermals**: Avoid always-on features that could drain batteries too quickly, focusing on real-time performance instead.
2. **Privacy**: Ensure that any memory or context capture does not create privacy concerns.
3. **Usability and Social Acceptance**: Maintain the system's utility while ensuring it remains socially acceptable.

## Summary

The project should continue to focus on improving subtitle clarity, memory trust, and low-friction UX while maintaining a phone-first architecture. Key tensions like privacy vs usefulness and latency vs richness must be carefully managed. Open questions around subtitle placement and confidence display need concrete answers. Real-world constraints such as battery life and social acceptability are critical to address early in the project.
