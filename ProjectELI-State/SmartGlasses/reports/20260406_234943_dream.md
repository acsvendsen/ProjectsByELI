### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a fixed subtitle placement rule that balances readability with stability, we ensure that subtitles remain clear and unobtrusive during live conversations. This improves the wearer's trust in real-time assistance without overwhelming them visually or becoming distracting.

2. **What small change unlocks it**

   Define a single, stable subtitle placement rule that places subtitles at the bottom center of the field of view (FOV) for all confidence states and scenarios. This fixed rule simplifies the visual hierarchy and reduces cognitive load on the wearer by providing consistent, unchanging placement.

3. **Likely payoff**

   Implementing this fixed placement rule will enhance the wearer's trust in real-time subtitles by reducing eye strain and improving readability across various contexts. It ensures that critical information is always visible without becoming a distraction, aligning with the core attractor of low-friction assistance.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitles and memory support more reliably. A well-designed confidence label, short reason, and score will help the wearer understand when to rely on the system and when they should focus on context clues or other inputs.

2. **What small change unlocks it**

   Define a clear format for confidence objects: use a numeric score (e.g., 0-1), a brief label (e.g., "High", "Medium", "Low"), and a short reason (e.g., "Seen recently", "Weak match").

3. **Likely payoff**

   By providing a transparent and understandable confidence display, the system will build trust with the wearer. They can rely on high-confidence subtitles during critical moments and use low-confidence signals as prompts for verification or additional context.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring a robust memory cache policy helps in maintaining trust by consistently providing accurate and timely recall of names, faces, and prior context. This is crucial for the core attractor of "Memory Trust" because it directly supports the wearer's ability to remember and understand past interactions without the risk of false certainty.

2. **What small change unlocks it**

   Define a local cache size limit that evicts less frequently recalled entities to ensure the memory cache remains relevant and responsive. This involves setting up an eviction rule based on recency, where items are removed if they have not been accessed within a certain timeframe.

3. **Likely payoff**

   By implementing this small change, we can significantly reduce the risk of corrupted recall due to too many outdated or irrelevant entities in the cache. This will enhance the overall trustworthiness of the memory support system and align better with user expectations for reliable assistance.

4. **Immediate next probe**
   - Define an eviction rule that removes items from the local memory cache if they have not been accessed within the last 7 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that V1 remains focused on delivering high-quality subtitles and memory support without overloading the battery or creating privacy concerns. This helps in maintaining the core mission of providing real-time, trustworthy assistance while keeping the system practical and user-friendly.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary for live subtitle processing that explicitly states what data must stay phone-local and what can fall back to the cloud. For example, local face recognition and name recall should be cached on the phone, while complex transcript cleanup or memory archive sync can use cloud resources.

3. **Likely payoff**

   This small change will help in creating a more stable and efficient V1 by ensuring that critical processing stays local where it is less impacted by latency and battery concerns. It also helps in building trust with users by maintaining privacy and providing timely, reliable assistance during live interactions.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
