### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles remain stable and clear enough to be trusted in live conversations while minimizing distraction.

2. **What small change unlocks it**

   Define three subtitle placement rules: 
   - For high-confidence text (above 0.9), place subtitles at the bottom of the screen.
   - For medium-confidence text (between 0.7 and 0.89), place subtitles slightly above center.
   - For low-confidence text (below 0.69), display subtitles at the top of the screen.

3. **Likely payoff**

   This approach will help maintain a clear visual hierarchy, ensuring that high-priority information is easily readable while reducing distraction from less certain or lower priority content. It also aligns with the core attractor of real-time subtitle clarity by providing consistent and stable placement rules.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring a stable memory cache for face and name recall helps maintain trust by providing reliable, quick responses to new interactions. A well-designed local cache ensures that the system can confidently identify known individuals even when the internet connection is weak or unavailable, thus reducing latency-induced inaccuracies.

2. **What small change unlocks it**

   Define a local cache size limit for face and name recognition data on the phone. This limit should be set to retain recent encounters but not consume excessive memory, ensuring that the system can quickly recall known individuals with high confidence.

3. **Likely payoff**

   By setting a reasonable local cache size, the system will provide faster and more accurate responses to known faces and names, enhancing the overall trust in the system’s memory capabilities. This improvement will also reduce dependency on cloud services during offline or low-bandwidth scenarios, maintaining reliability and reducing latency.

4. **Immediate next probe**

   Define one local-cache size limit for face and name recognition data on the phone, set to 50 entries with a retention period of 7 days.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing stays on the phone reduces battery drain and thermal stress, allowing for more stable and reliable real-time subtitles. By keeping this task local, we can avoid network latency issues and ensure that subtitles are always available without depending on cloud connectivity.

2. **What small change unlocks it**

   Define a strict boundary where any live subtitle processing must be done locally on the phone first before falling back to the cloud if necessary. This involves setting up clear criteria for when the cloud should be used as an optional fallback, such as complex or noisy environments that might degrade local processing capabilities.

3. **Likely payoff**

   By keeping live subtitle processing on the phone, we can maintain higher subtitle quality and stability, which are critical for trust and usefulness. This also helps in preserving battery life and ensuring that subtitles are always available even if cloud connectivity is unreliable.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
