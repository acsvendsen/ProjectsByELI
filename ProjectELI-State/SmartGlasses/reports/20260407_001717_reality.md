# Reality Check for SmartGlasses

## Feasibility Assessments

### Subtitle Placement: feasible now
- **Current Status**: The `TranscriptLab` app provides a reusable test bed that focuses on real-time subtitle clarity.
- **Reasoning**: With the current setup, subtitles can be placed and tested in a non-distracting manner. The `TranscriptLabRootView.swift` can be adjusted to ensure that subtitles are readable without overwhelming the wearer.

### Confidence Display: feasible now
- **Current Status**: The `TranscriptLabApp` includes basic confidence display options for testing.
- **Reasoning**: Given the current setup, adding different confidence formats (label only, label + short reason, or score + label) can be implemented and tested in the `LiveTranscriptTestView.swift`. This ensures that confidence is displayed clearly without overwhelming the user.

### Memory/Cache Policy: likely waste of time
- **Current Status**: The current focus is on subtitle clarity and confidence display.
- **Reasoning**: Until we have a more robust memory model, investing heavily in cache policy may be premature. Focus should remain on core functionalities like subtitles and confidence before expanding into memory caching.

### Phone/Cloud Boundary: feasible now
- **Current Status**: The `TranscriptLab` app operates primarily on the phone with optional cloud support.
- **Reasoning**: This setup allows for a clear separation of concerns, where heavy processing can be offloaded to the phone or cloud as needed. Testing this boundary in the current app ensures that we do not overcomplicate early iterations.

### Visual Hierarchy: feasible now
- **Current Status**: The `TranscriptLabRootView.swift` and `LiveTranscriptTestView.swift` provide basic UI elements for testing.
- **Reasoning**: Implementing a clear visual hierarchy can be done iteratively based on feedback from the `TranscriptLab`. This ensures that subtitles are prioritized without overwhelming other screen elements.

### Drift Risks
- **Drift Risk: Becoming a gimmick** - Feasible now. The current focus is on core functionalities and usability, which helps in avoiding becoming a mere gimmick.
- **Drift Risk: Feature sprawl before core subtitle/memory loop is excellent** - Infeasible now. Core deepening should be prioritized over broad feature expansion.

### Reality Guardrails
- **Core Deepening Over Sprawl**: Feasible now. The current mode focuses on improving subtitle quality, memory trust, and visual UX.
- **Interaction Constraints**: Feasible now. The `TranscriptLab` ensures that V1 interaction remains frame-touch-only.

## Assumptions Needing Evidence

### Subtitle Placement
- **Assumption**: Subtitles should be placed in a way that is readable but not distracting.
- **Evidence Needed**: Conduct user tests to determine the optimal placement and readability of subtitles on different screen sizes and orientations.

### Confidence Display
- **Assumption**: Confidence can be displayed effectively through labels or scores without causing distraction.
- **Evidence Needed**: User feedback and testing with various confidence display formats to ensure they are clear and not overwhelming.

### Memory/Cache Policy
- **Assumption**: Implementing a robust memory policy is necessary for future iterations.
- **Evidence Needed**: Detailed analysis of the current memory behavior in `TranscriptLab` and how it affects subtitle performance before making assumptions about caching.
