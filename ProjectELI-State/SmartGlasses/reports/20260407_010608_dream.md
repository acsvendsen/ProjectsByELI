### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a consistent subtitle placement rule based on confidence levels, we can ensure that subtitles remain stable and unobtrusive while still providing clear, actionable information to the wearer. This enhances trust in the system by maintaining a clean visual experience, which is crucial for real-time interaction.

2. **What small change unlocks it**

   Define three distinct subtitle placement rules: 
   - Fixed bottom-center position with high confidence.
   - Floating above the speaker’s face with medium confidence.
   - Temporarily hidden with low confidence to avoid distraction.

3. **Likely payoff**

   Implementing these rules will provide a more predictable and consistent user experience, reducing visual clutter during moments of high clarity while ensuring important information is not missed when confidence is lower. This approach aligns with the core mission of providing clear, unobtrusive support in real-time conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the system's output more effectively. By clearly indicating certainty levels through a numeric score, label, and short reason, the system enhances its credibility and reliability in real-time interactions.

2. **What small change unlocks it**

   Define a simple confidence format: `score 0.84 + "High" + "Seen recently"` for high-confidence outputs, where the score is displayed as a decimal between 0 and 1, the label provides a quick sense of certainty (e.g., High, Medium, Low), and the short reason explains why this level of confidence was assigned.

3. **Likely payoff**

   By implementing a clear and concise confidence format, users will be better informed about the reliability of the system's output, leading to increased trust in both subtitles and memory recall. This will result in fewer misunderstandings and more accurate interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size for face/name memory enhances the system's ability to provide fast, reliable recall during live conversations. A larger cache ensures that frequently encountered faces and names are available quickly, reducing the need for cloud fallbacks and maintaining trust by providing prompt responses.

2. **What small change unlocks it**

   Define a local cache size limit of 10 entries for face/name memory objects on the phone. This threshold will ensure that the most recently seen or interacted-with people are stored locally, allowing for quick recall without excessive storage overhead.

3. **Likely payoff**

   By setting a local cache size of 10 entries, the system can provide faster and more reliable name and face recall during live interactions. This improvement will reduce latency in responses, enhance trust through consistent behavior, and minimize cloud fallbacks, thereby improving overall user satisfaction and core functionality.

4. **Immediate next probe**
   - Define a local cache size limit of 10 entries for face/name memory objects on the phone.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for which subtitle processing tasks should run locally on the phone versus those that can be handled by cloud fallback, we ensure that V1 remains focused and reliable. This helps maintain real-time performance and privacy while still leveraging cloud resources where necessary.

2. **What small change unlocks it**

   Define a specific task boundary: live subtitle processing should stay local to the phone to minimize latency and preserve trust. Transcript cleanup can be done as a fallback to the cloud if needed, ensuring that the glasses remain lightweight and responsive.

3. **Likely payoff**

   This approach ensures real-time subtitles are always available without delay, maintaining high confidence in their accuracy and relevance. It also keeps memory and face/name recall tasks off the phone's limited resources, extending battery life and reducing thermal stress.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

   Improving subtitle-vs-one-line support ensures that both types of information coexist without overwhelming the wearer. This balance is crucial for maintaining clarity and trust, as well as ensuring low friction in real-world interactions.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prioritizes subtitles over one-line prompts when both are available, but allows one-line prompts to show briefly if necessary.

3. **Likely payoff**

   By defining this rule, we can ensure that subtitles remain the primary focus, enhancing trust and readability in noisy environments while still providing contextual support where needed. This will help maintain a low-friction user experience without overwhelming the wearer with too much information.
