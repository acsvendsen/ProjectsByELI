### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules enhances the wearer's ability to trust and rely on subtitles in noisy environments, which is crucial for real-time understanding and engagement.

2. **What small change unlocks it**
   Define two subtitle placement modes: one fixed at the bottom of the field of view (FOV) with minimal motion sensitivity, and another that adjusts slightly based on head motion but remains stable overall.

3. **Likely payoff**
   By offering a more predictable placement option, users can focus better during conversations without worrying about subtitles moving out of sight or becoming difficult to read due to excessive movement. This improves the overall assistive value and trust in the system.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear, concise format, we can enhance the wearer's trust in both subtitles and memory support. This will make the system more reliable and reduce cognitive load, ensuring that the wearer feels supported without unnecessary doubt.

2. **What small change unlocks it**

   Introduce a new confidence label "High" for high-confidence matches and remove the numeric score to simplify the display. This can be unlocked by redefining the `confidenceObject` format in the application code.

3. **Likely payoff**

   Simplifying the confidence display will make it easier for wearers to quickly understand when information is highly reliable, reducing cognitive load and increasing trust in the system's accuracy. This clarity will help maintain a balance between providing enough assurance without overwhelming the wearer with too much detail.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that the system retains enough relevant information to provide fast and accurate support, while also respecting battery and thermal constraints. This balance enhances trust by ensuring that important contextual details are available when needed without overwhelming the device.

2. **What small change unlocks it**

   Define a local memory threshold for face and name recall objects on the phone, allowing them to persist in low-power state but automatically expire after a set period of inactivity or lack of reinforcement.

3. **Likely payoff**

   By setting a reasonable local cache size limit, the system can maintain strong memory support without draining battery resources excessively. This ensures that new interactions are promptly remembered and that older, less relevant information is pruned to keep the device efficient and responsive.

4. **Immediate next probe**

   Define one local-cache size limit for face and name recall objects on the phone, with a default threshold of 20 entries per person, expiring after 7 days of inactivity or lack of reinforcement.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we can optimize local processing to handle critical real-time tasks like live subtitle generation and face/name recall with high confidence. This ensures that the wearer receives timely, reliable assistance without relying on potentially laggy cloud responses.

2. **What small change unlocks it**

   Define one task-specific cloud fallback boundary for exactly one core activity: live subtitle processing. For instance, set a rule that subtitles are generated locally unless the confidence score drops below a certain threshold, in which case the phone falls back to the cloud for help.

3. **Likely payoff**

   This approach will ensure that critical real-time subtitles remain stable and trustworthy, enhancing user trust and satisfaction. It also allows the system to leverage cloud resources when needed without compromising on timely response times, maintaining a balance between local processing efficiency and broader capabilities.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By carefully defining how subtitles coexist with one-line support, we ensure that the wearer can rely on both forms of assistance without visual overload or distraction. This balance enhances the overall assistive experience by providing just-in-time context while maintaining readability and comprehension.

2. **What small change unlocks it**

   Define a priority rule where subtitles have precedence over one-line support when confidence levels are high, but one-line support can be shown alongside subtitles for additional context without overwhelming the wearer.

3. **Likely payoff**

   This approach ensures that critical information from subtitles is not obscured by less urgent prompts, thereby maintaining trust in the system and reducing cognitive load during crucial conversations. It also allows for flexible and dynamic display strategies based on real-time confidence levels, enhancing the user experience.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
