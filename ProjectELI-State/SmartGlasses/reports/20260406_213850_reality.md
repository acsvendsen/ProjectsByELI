# Reality Check Summary

## Subtitle Placement: 
- **Feasible Now**: The glasses should prioritize subtitle placement that is readable in motion without becoming distracting. Given the current constraint of frame-touch interaction and minimal local processing, the placement should be simple yet effective. This can start with a top-center or side-center position on the display.

## Confidence Display: 
- **Feasible Now**: Implementing a confidence label (e.g., "High" or "Low") for subtitles is both feasible now and likely to improve user trust. A short reason might add complexity unnecessarily in V1, so it's better to start with a simple label that users can quickly understand.

## Memory/Cache Policy: 
- **Feasible Now**: For memory storage and reinforcement, the initial implementation could focus on caching the most recently seen names and faces. This can be managed through local phone storage or temporary cache files. Over time, as the system learns more about what is valuable to remember, the policy can become more sophisticated.

## Phone/Cloud Boundary: 
- **Feasible Now**: V1 should stick to a phone-first architecture where heavy processing happens locally on the phone. Cloud support can be considered for background tasks like model updates but not for real-time interaction unless strictly necessary and latency is acceptable.

## Visual Hierarchy: 
- **Feasible Now**: The initial visual hierarchy should prioritize readability and clarity over feature density. A simple subtitle display with minimal overlay elements is appropriate in V1. Overlays can be used sparingly to indicate confidence or memory status without overwhelming the user.

### Feasibility Reasoning

#### Subtitle Placement
Given that the glasses must remain socially acceptable, a top-center or side-center placement is reasonable and avoids blocking peripheral vision too much. The display should also move slightly as the user moves their head to maintain readability in motion.

#### Confidence Display
A confidence label like "High" or "Low" can be implemented quickly without adding significant complexity. This allows users to understand when they can trust the subtitles more easily, which is critical for real-time interactions.

#### Memory/Cache Policy
Initial caching of recently seen names and faces on the phone is a straightforward approach that respects battery constraints while providing useful memory support. As the system evolves, more sophisticated caching strategies can be implemented.

#### Phone/Cloud Boundary
V1 should focus on using the phone's capabilities fully to minimize battery draw and thermal issues. Cloud access can be reserved for background tasks like model updates or voice commands if latency is not an issue.

#### Visual Hierarchy
The initial visual hierarchy should prioritize readability, with minimal overlays that do not distract from the primary functionality (i.e., subtitles). Overlays can be introduced gradually as the system learns more about what information users need most frequently.

### Assumptions Requiring Evidence

- **Subtitle Quality**: Ensure that the real-time subtitle quality remains clear and stable enough for live conversations. This will require iterative testing with different placement strategies.
- **Memory Recall Accuracy**: Verify that the memory support provided by caching recently seen names and faces is accurate and useful. This may require user feedback and adjustment of the caching policy over time.

By focusing on these specific areas, the project can ensure that V1 meets its primary attractors while respecting real-world constraints.
