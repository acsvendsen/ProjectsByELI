### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining fixed subtitle placement rules based on confidence levels, the system can ensure that subtitles remain visible and unobtrusive while still providing critical assistance. This approach helps in maintaining the wearer's focus during live conversations without overwhelming them with too much information.

2. **What small change unlocks it**

   To unlock this improvement, we need to define three subtitle placement rules:
   - Low confidence: Place subtitles at the bottom of the frame.
   - Medium confidence: Position subtitles slightly above the center.
   - High confidence: Center the subtitles and make them larger for emphasis.

3. **Likely payoff**

   Implementing these fixed placement rules will reduce visual clutter, ensuring that subtitles are only prominent when most needed (high confidence). This approach maintains readability while minimizing distraction during lower-confidence situations. It also provides a consistent UI experience that can be trusted over time.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds for face/name recall ensures that likely new-person memories are automatically stored with high confidence, enhancing trust in real-world interactions without overloading the system's resources.

2. **What small change unlocks it**

   Define a local cache threshold of 3 to 5 recent face and name encounters per session, where each encounter triggers an explicit reinforcement if the person is interacted with again within the next hour.

3. **Likely payoff**

   This approach allows for automatic memory support while ensuring that only frequently encountered new individuals are reinforced, reducing the risk of storing low-value information and preserving system resources.

4. **Immediate next probe**

   Define one local cache threshold between 3 to 5 recent face and name encounters per session, where each encounter triggers an explicit reinforcement if the person is interacted with again within the next hour.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud for live subtitle processing, we ensure that the glasses provide near-real-time subtitles without overloading the battery or thermal limits. This focus on local processing for critical real-time tasks strengthens the core attractor of "Real-time subtitle clarity" and aligns with the constraint of "Always-on sensing vs battery and thermals."

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that runs entirely phone-local, where any fallback to cloud is limited to non-critical tasks like transcript cleanup or memory archive sync.

3. **Likely payoff**

   By keeping live subtitle processing phone-local, we reduce thermal and battery strain while ensuring the subtitles remain clear and stable. This improves the user experience and aligns with the core attractor of real-time subtitle clarity. It also sets a precedent for other critical tasks, guiding future decisions on which processes should stay local.

4. **Immediate next probe**
   - Define one task-specific cloud fallback boundary for live subtitle processing to ensure critical real-time tasks remain phone-local.
