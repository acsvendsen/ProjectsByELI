# Reality Check for SmartGlasses

## Subtitle Placement: feasible now
- **Current State**: Use best effort within `subtitle placement`.
- **Constraints**: Glasses should remain lightweight and socially acceptable, with early versions not depending on heavy on-glasses compute.
- **Feasibility Analysis**:
  - The current approach of using a simple text display on the glasses is feasible given the hardware constraints. 
  - Subtitle placement can be tested in `TranscriptLab` to ensure it remains unobtrusive and readable during live conversations.
  - The goal should be to keep subtitles at the bottom edge or side of the glasses, ensuring they do not distract from the wearer's natural head movements.

## Confidence Display: feasible now
- **Current State**: Use best effort within `confidence display`.
- **Constraints**: Keep UI favoring clarity over feature density.
- **Feasibility Analysis**:
  - A simple confidence label (e.g., "High," "Low") can be implemented and tested in `TranscriptLab` to gauge user trust without overwhelming the wearer.
  - Introduce a short reason next to the label only if it significantly enhances trust, as additional text could reduce readability.

## Memory/Cache Policy: feasible now
- **Current State**: Use best effort within `memory/cache policy`.
- **Constraints**: Face/name recall must expose uncertainty clearly and heavily rely on phone processing.
- **Feasibility Analysis**:
  - Implement a caching strategy where the phone stores face and name data, with confidence scores indicating memorability. 
  - Test different caching policies in `TranscriptLab` to ensure that new faces and names are remembered but not over-relied upon.

## Phone/Cloud Boundary: feasible now
- **Current State**: Use best effort within `phone/cloud boundary`.
- **Constraints**: Bias toward phone-first processing, with cloud optional where useful.
- **Feasibility Analysis**:
  - Ensure that the phone handles all critical real-time processing and caching. Cloud should only be used for heavy lifting or background tasks.
  - Test the phone’s processing capabilities in `TranscriptLab` to confirm that it can handle subtitle generation and memory updates without excessive battery drain.

## Visual Hierarchy: feasible now
- **Current State**: Use best effort within `visual hierarchy`.
- **Constraints**: Favor clarity over feature density, ensuring subtitles remain readable.
- **Feasibility Analysis**:
  - Design the visual hierarchy to prioritize readability and user trust. Subtitles should be large enough to read quickly but small enough not to distract during conversation.
  - Test various subtitle placement and size configurations in `TranscriptLab` to find a balance that works well.

## Summary
Based on the current constraints and implementation grounding, the proposed directions for subtitle placement, confidence display, memory/cache policy, phone/cloud boundary, and visual hierarchy are feasible now. These areas should be tested iteratively using `TranscriptLab` to ensure they meet the core mission of enhancing real-world understanding without overwhelming the wearer.

### Recommendations
- Continue testing and refining these areas in `TranscriptLab`.
- Ensure that all implementations respect the hardware constraints and user trust considerations.
- Regularly surface battery, latency, privacy, and usability limits early through ongoing tests and feedback.
