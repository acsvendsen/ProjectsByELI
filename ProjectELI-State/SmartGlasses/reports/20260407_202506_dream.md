### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules under different confidence states ensures that subtitles are always in a clear and unobtrusive position, enhancing readability and trust without causing distraction.

2. **What small change unlocks it**
   Define three distinct subtitle placement modes: one for high-confidence text (e.g., names and critical information), another for medium-confidence text (e.g., casual conversation snippets), and a third fallback mode for low-confidence text that minimizes visual disruption.

3. **Likely payoff**
   By clearly separating subtitle placement based on confidence, the system can avoid overwhelming the wearer with too much text during moments of lower certainty while ensuring critical information remains easily readable.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear label with a short reason, we can enhance trust in the system's memory support and subtitle accuracy. This helps in ensuring that the wearer understands when the system is certain about a name or face versus when there is less certainty.

2. **What small change unlocks it**

   Introduce a simple confidence format like `score 0.84 + "High" + "Seen recently"` for high-confidence matches and `score 0.42 + "Low" + "Weak match"` for lower-confidence ones. This format provides a clear indication of the system's certainty.

3. **Likely payoff**

   Implementing this confidence format will allow the wearer to quickly understand the reliability of the displayed names and faces, leading to better trust in the memory support feature. It also helps in reducing social awkwardness by making it clear when the system is unsure about a name or face.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local memory threshold for face/name recall, we ensure that the system retains enough recent interactions to support fast lookup while respecting battery and thermal constraints. This helps in maintaining trust by providing timely and accurate information without overloading the device.

2. **What small change unlocks it**

   Define a memory eviction policy where each person-memory object is retained for at least 30 minutes after its last interaction, but evicted if no further interactions occur within 1 hour.

3. **Likely payoff**

   This policy allows for timely reinforcement of recently seen faces and names while ensuring that the local cache remains manageable, reducing memory overhead and battery drain.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we can ensure that V1 focuses on delivering essential functionality with minimal latency and battery impact. This helps maintain trust and usability, which are critical for the SmartGlasses' core mission.

2. **What small change unlocks it**

   Define explicit rules for when live subtitle processing should stay phone-local versus falling back to cloud. For example, real-time face/name recall can be handled locally until a clear match is found, but continuous streaming of raw audio data could fall back to the cloud for more advanced transcription.

3. **Likely payoff**

   By keeping critical real-time processes like live subtitle generation on-device, we reduce latency and ensure that subtitles remain reliable even under network conditions. This enhances trust and usability, aligning with our core attractors of real-time clarity and low-friction assistance.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
