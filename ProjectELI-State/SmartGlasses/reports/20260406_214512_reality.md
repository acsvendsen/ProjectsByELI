# Reality Check for SmartGlasses V1

## Subtitle Clarity (Subtitle Placement)

### Feasibility: Feasible Now
- **Current Approach**: Use TranscriptLab to test subtitle placement in a phone-first environment.
- **Constraints**: Battery and thermal pressure, real-time stability, readability in motion and noise.
- **Reasoning**: The current implementation uses simple text display on the TranscriptLab app. This approach is feasible now because it aligns with the V1 frame-touch interaction constraint.

## Confidence Display

### Feasibility: Feasible Now
- **Current Approach**: Use labels and short reasons to convey confidence in a clear, non-overwhelming manner.
- **Constraints**: Battery draw, real-time response, user trust.
- **Reasoning**: The TranscriptLab app uses labels such as "low," "medium," and "high" along with short reasons for the confidence level. This approach is feasible now because it respects V1 interaction constraints and ensures minimal battery usage.

## Memory/Cache Policy

### Feasibility: Likely Waste of Time
- **Current Approach**: Store recent face and name interactions in memory, using a caching mechanism to manage local storage.
- **Constraints**: Battery, thermal pressure, cloud dependency.
- **Reasoning**: Early versions rely heavily on phone processing. Storing significant amounts of memory locally would add unnecessary complexity without providing immediate value given the V1 constraints.

## Phone/Cloud Boundary

### Feasibility: Feasible Now
- **Current Approach**: Heavy processing happens on the phone with optional cloud support for background tasks.
- **Constraints**: Battery, latency, privacy perception.
- **Reasoning**: The current implementation already aligns with this approach. Cloud usage is kept to a minimum in V1, making it feasible now.

## Visual Hierarchy

### Feasibility: Feasible Now
- **Current Approach**: Design the UI for clear, unobtrusive placement of subtitles and confidence labels.
- **Constraints**: Social acceptability, distraction levels, readability.
- **Reasoning**: The TranscriptLab app provides a basic design that respects V1 interaction constraints. Further refinements can be made as needed.

## Summary

### Core Deepening vs Sprawl
- Focus on subtitle clarity, memory support, and confidence display. These are core to the mission and align with current constraints.
- Avoid broad feature sprawl; stick to deepening existing capabilities.

### Constraint Pressure
- Surface real-world limitations early by continuously assessing battery, latency, privacy, and usability impacts of proposed changes.
- Use concrete repo signals like TranscriptLab for validation.

### Interaction Constraints
- Ensure all proposed UI and interaction designs align with V1 frame-touch only constraint.

By focusing on these areas, the project can maintain a clear path toward realizing its core mission while respecting real-world limitations.
