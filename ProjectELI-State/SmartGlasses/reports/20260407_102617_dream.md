### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain consistent and reliable subtitle visibility, which is crucial for the wearer's trust in real-time subtitles. By setting fixed position or minimally adaptive placement rules, we can reduce visual distractions while ensuring that subtitles remain readable and useful.

2. **What small change unlocks it**

   Define two subtitle placement modes: a stable fixed position and a slightly adaptive mode based on confidence levels. For high-confidence states, the subtitle should stay in a fixed position; for medium- or low-confidence states, allow minimal movement to ensure the wearer can follow the conversation without constant refocusing.

3. **Likely payoff**

   By implementing these placement modes, we can significantly reduce visual distractions and improve overall readability. This will help maintain the wearer's focus on the conversation and trust in the subtitles, enhancing their ability to understand the context and respond appropriately.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

   Ensuring a clear and consistent confidence display helps maintain trust in the system's reliability. By improving how certainty is communicated, users can better understand when they should rely on the subtitles and memory support provided by the glasses.

2. **What small change unlocks it**

   Define one specific confidence format that combines a numeric score with a label and short reason. For example, use "score 0.84 + 'High' + 'Seen recently'". This clear and concise display will help users quickly understand the reliability of the information provided.

3. **Likely payoff**

   A well-designed confidence display will reduce user anxiety about missing critical information or relying on uncertain data. Users will feel more confident in the system's ability to provide accurate subtitles and memory support, leading to a better overall experience.

4. **Immediate next probe**
   - Define the specific confidence score presentation format as "score [0-1] + label (High/Medium/Low) + short reason" for V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for which tasks run phone-local versus falling back to the cloud, we can ensure that critical real-time subtitle processing remains on-device while still leveraging the cloud for less time-sensitive operations like memory archive sync and conversation snapshot upload. This balance helps maintain low-latency subtitle delivery and preserves battery life.

2. **What small change unlocks it**

   Define a single task boundary where live subtitle processing runs phone-local, with face/name recall lookup falling back to the cloud when the local cache is insufficient or outdated.

3. **Likely payoff**

   By keeping subtitle processing on-device, we can maintain real-time accuracy and stability, which are crucial for the wearer's trust in the system. The cloud fallback ensures that memory and context retrieval remain robust even under battery constraints, thus providing a reliable user experience without compromising on critical functionalities.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
