### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules helps ensure that subtitles remain clear, stable, and unobtrusive during live conversations. This directly supports the primary attractor of real-time subtitle clarity by reducing visual distractions and ensuring that the subtitles are always in a prime position for quick reading.

2. **What small change unlocks it**

   Define two fixed subtitle placement rules: one for confident speech (high confidence) and another for less certain speech (low to medium confidence). For high-confidence speech, place subtitles slightly above the speaker's face; for low to medium confidence, place them just below or on the same line as the speaker.

3. **Likely payoff**

   By defining clear placement rules, V1 can ensure that subtitles are always in a prime position for quick reading and do not become visually distracting. This will enhance the wearer's ability to focus on the conversation while still benefiting from real-time subtitles.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring a clear and consistent confidence display format helps the wearer trust the system more. By standardizing the confidence labels, short reasons, and numeric scores, the system can convey certainty levels in a way that is both understandable and reliable.

2. **What small change unlocks it**

   Define a specific confidence object format for V1: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   This standardization will help users quickly understand the system's certainty, which enhances trust and usability. Clear confidence indicators reduce the cognitive load on the wearer by making it easier to interpret the system’s reliability.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a specific local memory threshold for face/name recall, the system ensures that only highly relevant and frequently encountered entities are stored locally, reducing privacy concerns while maintaining useful context. This approach helps in balancing the need for rich memory support with the constraints of battery and thermal management.

2. **What small change unlocks it**

   Define a local cache size limit for person-memory objects that triggers automatic eviction when the threshold is exceeded. For example, set a maximum of 10 recent face/name interactions to be stored locally, with less frequent encounters being moved to cloud storage or discarded.

3. **Likely payoff**

   Implementing this policy will reduce memory overhead and ensure that the system does not consume excessive resources. It also helps in maintaining privacy by limiting local storage to only the most relevant information, thereby enhancing trust through conservative behavior and efficient use of resources.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific phone/cloud fallback boundary for live subtitle processing, we ensure that subtitles remain stable and reliable in real-time scenarios. This boundary helps balance the need for immediate response with the constraints of battery and thermal limits, ensuring that critical functionality stays local to reduce latency and improve trust.

2. **What small change unlocks it**

   Define a clear threshold for when live subtitle processing should fall back to the cloud based on the current device's resource availability and real-time conditions. For example, if the phone is at 50% battery or higher CPU usage, subtitles should remain local; otherwise, they can fallback to the cloud.

3. **Likely payoff**

   By implementing a specific live subtitle processing boundary, we can significantly improve the stability and reliability of subtitles during critical conversations. This will enhance user trust in the system's ability to provide clear, timely assistance without causing unnecessary load on the device or compromising battery life.

4. **Immediate next probe**

   Define one live subtitle processing fallback boundary such that subtitles remain local when the phone has at least 50% battery and does not exceed a certain CPU usage threshold.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that critical information is prioritized for quick readability while minimizing distraction. This helps maintain trust by ensuring that the wearer can easily follow important conversations without being overwhelmed by additional information.

2. **What small change unlocks it**

   Define a clear priority rule where subtitles take precedence over one-line prompts, but allow coexistence to provide relevant support when needed. This can be achieved by setting a display precedence order: subtitles always appear first, followed by one-line prompts only if there is enough space and the context warrants additional information.

3. **Likely payoff**

   By establishing a clear visual hierarchy that prioritizes subtitles over one-line prompts, the system will maintain higher trust and usability. The wearer can focus on understanding the conversation without being distracted by less critical information, leading to better real-time comprehension and engagement.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
