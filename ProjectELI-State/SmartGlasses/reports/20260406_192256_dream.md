### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain readable, stable, and trust-preserving during live conversations. Stable, well-placed subtitles enhance the wearer's ability to follow spoken interactions in noisy environments or with hearing challenges.

2. **What small change unlocks it**

   Define a fixed position for subtitles that is consistent across different confidence states, ensuring that subtitles do not flicker between positions and remain easily readable even when the system’s certainty about spoken words decreases.

3. **Likely payoff**

   By defining a fixed subtitle placement rule, the system can ensure that subtitles are always in a predictable location, reducing cognitive load for the wearer and maintaining their trust in the assistive technology. This consistency will make it easier to follow conversations without constantly adjusting gaze or attention between spoken words and subtitles.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the system's outputs, which is crucial for maintaining the core mission of helping the wearer understand and respond better in real-world interactions.

2. **What small change unlocks it**

   Define a confidence format that uses a numeric score combined with a label and a short reason. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'.

3. **Likely payoff**

   A clear and concise confidence display will help the wearer understand the reliability of the subtitles and memory outputs, thereby increasing trust in the system. This will reduce cognitive load and improve overall user experience.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size threshold for face/name memory, we ensure that the system retains the most relevant and frequently encountered memories while reducing unnecessary data storage on the phone. This helps in maintaining a balance between rich memory support and fast lookup performance, ensuring that the wearer can quickly access important information without overwhelming the device.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects stored on the phone, with a default threshold of 10 entries. This limit ensures that only the most recent and frequently encountered faces/names are cached locally, while older or less relevant memories are evicted to keep storage usage minimal.

3. **Likely payoff**

   Implementing this local cache size limit will improve the system's responsiveness and reduce battery consumption by minimizing the amount of data that needs to be managed on the phone. This will also help in maintaining a clear and uncluttered memory lookup experience for the wearer, ensuring that they can quickly find relevant information without facing delays or errors.

4. **Immediate next probe**

   Define one local-cache size limit for face/name memory objects stored on the phone with a default threshold of 10 entries.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus falling back to cloud, we ensure that critical processing remains on-device, preserving low-latency responsiveness and respecting user privacy. This alignment with real-world constraints helps maintain trust and usability.

2. **What small change unlocks it**

   Define one specific task-based fallback boundary for live subtitle processing: use the phone for real-time transcription but fall back to cloud for transcript cleanup only when necessary, such as after a significant edit or during poor network conditions.

3. **Likely payoff**

   This refined approach will reduce battery drain and thermal load on the glasses while ensuring that critical real-time subtitles remain crisp and reliable. It also prevents over-reliance on cloud services for core functionality, enhancing privacy and user control.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
