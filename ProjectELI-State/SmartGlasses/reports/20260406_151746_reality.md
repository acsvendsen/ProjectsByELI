## Reality Check: V1 Direction Feasibility

### Subtitle Placement: More Prominent
- **Feasible Now**: The repo provides a `LiveTranscriptTestView` where subtitles can be placed more prominently. This is achievable within the current architecture and does not add significant complexity. Ensure that the placement does not become overly distracting.
- **Assumptions Needed**: Confirm that placing subtitles more prominently does not significantly affect battery draw or thermal management.

### Confidence Display: Label + Reason
- **Feasible Now**: The repo supports a confidence display format that includes both a label and a short reason. This can be implemented as `Label + Short Reason`.
- **Assumptions Needed**: Validate the UI design to ensure it fits well within the overall visual hierarchy without overwhelming the user.

### Memory/Cache Policy
- **Feasible Later**: The repo does not explicitly set a memory/cache policy, but it provides enough flexibility for implementing one. This can be explored in future iterations.
- **Assumptions Needed**: Determine how much face/name memory should be cached locally and ensure that this does not overwhelm the phone’s storage.

### Phone/Cloud Boundary: Phone First
- **Feasible Now**: The current architecture strongly favors a phone-first approach, which is suitable for V1. This can be directly implemented without significant changes.
- **Assumptions Needed**: Ensure that all critical functions (like real-time transcription and memory management) are well-optimized on the phone to avoid latency issues.

### Visual Hierarchy: Subtitles Dominate
- **Feasible Now**: The repo supports a visual hierarchy where subtitles dominate. This can be implemented by adjusting the layout in `LiveTranscriptTestView`.
- **Assumptions Needed**: Confirm that this design does not conflict with any other UI elements and remains user-friendly.

### Core Attractors & Tensions
1. **Real-time subtitle assistance**:
    - **Feasible Now**: The repo provides a robust foundation for real-time transcription, which can be further optimized in V1.
2. **Personal memory support**:
    - **Assumptions Needed**: Confirm the accuracy and reliability of face/name recall and ensure that it respects user privacy.
3. **One-line contextual prompts**:
    - **Feasible Now**: Implement one-line prompts as needed, ensuring they do not overwhelm the user.
4. **Discreet UX vs enough visual clarity**:
    - **Feasible Now**: Balance can be achieved by carefully designing the UI elements and their interactions.

### Core Tensions & Constraints
1. **Battery and thermal management**:
    - **Assumptions Needed**: Monitor battery usage closely to ensure that subtitle display and memory processing do not drain the phone’s power excessively.
2. **Privacy vs usefulness**:
    - **Feasible Now**: Implement face/name recall with clear uncertainty indicators to maintain privacy.
3. **Always-on sensing vs battery and thermals**:
    - **Assumptions Needed**: Optimize the transcription process to minimize continuous processing while maintaining real-time capabilities.

### Reality Rules & Constraints
- **Early V1 Interaction is Frame Touch Only**: This constraint is well-supported by the current repo structure, ensuring that interactions remain simple.
- **Avoid Voice Activation in V1**: The repo does not include any voice activation logic, aligning with the project constraints.
- **Phone-first Architecture**: The current architecture strongly favors a phone-first approach, which simplifies early development.

### Drift Risks
- **Feature Sprawl Before Core Loop is Excellent**: Focus on refining the core subtitle/memory loop before adding broader features.
- **Interaction Sprawl That Adds Command Modes or Hardware Complexity**: Stick to frame-touch interactions and avoid unnecessary complexity in V1.

### Summary of Feasibility Assessments
- **Subtitle Placement & Confidence Display**: Both are feasible now with minor adjustments.
- **Memory/Caching Policy, Phone/Cloud Boundary, Visual Hierarchy**: These can be tackled later but are currently supported by the repo.
- **Core Mission Alignment**: The current direction is well-aligned with the core mission of providing discreet assistance through subtitles and memory support.

This structured approach ensures that the project stays focused on its primary goals while respecting real-world constraints.
