### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules can enhance readability and stability, ensuring that subtitles are clear and do not distract the wearer during live conversations. This will strengthen the core attractor of real-time subtitle clarity.

2. **What small change unlocks it**
   Define 3 fixed subtitle placement modes: one for high-confidence speech (e.g., known speakers), one for medium-confidence speech (e.g., likely new people), and one for low-confidence speech (e.g., background noise). Each mode will have specific rules about where to place subtitles relative to the speaker or other context.

3. **Likely payoff**
   By providing clear guidelines on subtitle placement, this change will reduce visual distractions during live conversations, making subtitles more useful without overwhelming the wearer. This improves trust in the assistive nature of the glasses and aligns with the core attractor of real-time subtitle clarity.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining which subtitle processing tasks stay local to the phone and which fall back to the cloud, we can ensure that V1 remains lightweight and responsive while still delivering high-quality real-time subtitles. This balance is crucial for maintaining trust and ensuring the wearer feels supported without overburdening the glasses.

2. **What small change unlocks it**

   Define a clear local-to-cloud boundary for live subtitle processing: all subtitle generation should be done on-device, with cloud fallbacks limited to specific, high-value tasks such as transcript cleanup or memory archive sync.

3. **Likely payoff**

   By keeping subtitle generation phone-local, we ensure that subtitles remain fast and stable in real-time scenarios, which is critical for maintaining the wearer's trust and confidence in the system. This approach also minimizes battery drain from always-on cloud processing while ensuring that essential background tasks can still be performed when needed.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
