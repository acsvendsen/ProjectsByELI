### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring consistent, stable subtitle placement helps maintain the wearer's trust in the system. By setting clear rules for where subtitles should appear on the screen, we can reduce visual distraction and ensure that important information is always visible without causing discomfort or confusion.

2. **What small change unlocks it**

   Define a fixed position rule for subtitles: place subtitles 10% of the way from the top center of the screen, ensuring they are easily readable but not intrusive to the wearer's field of view.

3. **Likely payoff**

   By implementing this fixed placement rule, we can create a more predictable and stable user experience. Subtitles will consistently appear in the same location, reducing cognitive load and making it easier for wearers to follow conversations without constantly adjusting their gaze or attention.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display ensures that the wearer can trust the subtitles and memory support provided by the glasses. Clear and reliable confidence indicators help maintain the wearer's confidence in the system, which is crucial for real-world usability.

2. **What small change unlocks it**

   Define a simple but effective confidence format that uses both a label (e.g., High, Low) and a short reason (e.g., Seen recently, Weak match). This will provide enough context to reinforce the wearer's trust without overwhelming them with too much information.

3. **Likely payoff**

   By implementing a clear and concise confidence display, the glasses can maintain high trust levels among wearers. This will result in more reliable usage of subtitle assistance and memory support, leading to a better overall user experience.

4. **Immediate next probe**
   - Define the label style for the confidence display as "High" or "Low."

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - Improving the local cache size and eviction policy for face/name memory enhances the trustworthiness of the system by ensuring that commonly encountered names and faces are quickly accessible, thus reducing latency and increasing the reliability of memory support.

2. **What small change unlocks it**
   - Define a local cache threshold for frequently seen people and names, setting a recency and frequency-based eviction rule to keep recently interacted with entities in memory while freeing up space for new evidence.

3. **Likely payoff**
   - By optimizing the cache policy, the system will provide faster and more accurate memory recall, reducing the need for cloud fallbacks and improving overall user trust and satisfaction.

4. **Immediate next probe**
   - Define a local cache threshold for frequently seen people and names, prioritizing recently interacted with entities to minimize latency in memory lookups.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that memory lookup is handled primarily on the phone keeps the system lightweight and reduces battery drain while maintaining fast, reliable recall of names and faces for the wearer. This balance enhances trust by providing quick access to relevant information without overloading the cloud, which could introduce latency.

2. **What small change unlocks it**

   Define a local-cache size limit for face/name memory on the phone that allows frequent lookups but avoids excessive memory usage. This can be achieved by setting a recency threshold and limiting the number of stored entries.

3. **Likely payoff**

   By keeping memory lookups locally, we reduce dependency on cloud services, which helps in maintaining fast response times even under poor network conditions. This improves the overall user experience and trust in the system's reliability for critical memory tasks like face/name recall.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy rule that prioritizes subtitles over one-line prompts, we ensure that the wearer's primary focus remains on understanding the conversation through real-time subtitles. This enhances clarity and reduces cognitive load, maintaining the trust in the system’s ability to provide accurate information.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles are displayed prominently at the top of the visual hierarchy unless the confidence score is below a certain threshold (e.g., 0.6), in which case one-line prompts can appear below them with lower prominence.

3. **Likely payoff**

   This change will reduce cognitive overload and maintain focus on real-time subtitles, making the system more effective and trustworthy during live conversations. It will also ensure that less important information is presented only when necessary, enhancing the overall user experience.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
