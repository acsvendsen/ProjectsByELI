# Reality Check Summary

## Subtitle Placement
- **Feasible Now**: Ensure subtitles are placed in a way that minimizes distraction while maximizing readability. Early experiments should focus on different placement strategies (e.g., temporal positioning, font size) and validate which works best without overloading the wearer.
  
## Confidence Display
- **Feasible Now**: Implement confidence displays using a label only or label + short reason approach. Focus on clarity rather than complexity in V1 to ensure the display does not create cognitive load.
  
## Memory/Cache Policy
- **Assumptions Needing Evidence**: The cache policy should balance local storage (e.g., on the phone) with cloud reliance for rich context. Early experiments should validate how much face/name memory can be cached locally without impacting battery and data usage.

## Phone/Cloud Boundary
- **Feasible Now**: Continue to optimize the phone-first runtime, ensuring that heavy processing is offloaded to the phone whenever possible. This includes refining the SpeechTranscriber and TranscriptLabModel implementations.
  
## Visual Hierarchy
- **Feasible Now**: Design a visual hierarchy that supports subtitle clarity while remaining unobtrusive. Early design iterations should focus on readability in motion, ensuring subtitles do not interfere with the wearer’s natural gaze.

### Core Deepening Over Sprawl
- **Core Deepening**: Focus on improving subtitle quality and memory trust rather than expanding to new features. The current mode (core deepening) is appropriate given the project constraints and goals.
  
### Constraint Pressure
- **Constraint Pressure**: Early testing should surface real-world limitations such as battery draw, latency, and social acceptability. For example, early experiments in `TranscriptLab` can help identify where heavy processing might be problematic.

### Interaction Constraints
- **Feasible Now**: Stick to frame-touch interactions for V1 and avoid adding voice commands or complex UI elements that do not match the current interaction assumptions.

## Likely Waste of Time
- **Assumptions Needing Evidence**: Investigating multimodal UIs, heavy autonomous behavior, or full on-glasses inference before these features are explicitly needed might be a waste of time. Focus on core functionality first.
  
### Reality Rules Check
- Ensure all proposed directions align with the project’s real-world constraints and attractors. For example:
  - **Subtitle Clarity**: Test different subtitle placements in noisy environments to ensure they remain readable and stable.
  - **Memory Trust**: Implement and validate face/name memory reinforcement over time without compromising privacy or user trust.

## Summary
- The current project direction is focused on core deepening, which aligns well with the attractors and constraints. Early testing in `TranscriptLab` will help surface key limitations early, ensuring that any proposed changes are grounded in real-world realities.
  
- **Feasible Now**: Focus on subtitle placement, confidence display, memory cache policy, phone/cloud boundary, and visual hierarchy within V1 interaction constraints.
  
- **Assumptions Needing Evidence**: Continue to validate core features like face/name memory before expanding into more complex interactions or heavy local inference.
