### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Stabilizing subtitle placement rules under different confidence states ensures that subtitles remain readable, stable, and trustworthy during live conversations. This improves the wearer's ability to understand real-time interactions without being distracted by moving or unstable text.

2. **What small change unlocks it**

   Define 3 to 5 fixed subtitle placement rules based on confidence levels: high, medium, and low. For example:
   - High confidence: Place subtitles at the bottom center.
   - Medium confidence: Place subtitles slightly above the bottom center with a slight fade-out effect.
   - Low confidence: Place subtitles at the top center but prioritize visual stability over perfect placement.

3. **Likely payoff**

   By defining clear subtitle placement rules, we reduce visual distractions and ensure that critical information is presented in a consistent, stable manner. This improves the wearer's trust in the system and enhances their ability to follow conversations accurately.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear, concise format, we can enhance the wearer's trust in both subtitles and memory support. A well-designed confidence system will provide just enough context to avoid overloading the wearer while still ensuring that critical information is conveyed accurately.

2. **What small change unlocks it**

   Introduce a two-part confidence label for V1: one for the primary certainty (e.g., "High", "Medium", "Low") and another for a short reason (e.g., "Seen recently", "Weak match"). This can be formatted as `score X + Y + Z`, where `X` is a numeric score, `Y` is the label, and `Z` is a brief reason.

3. **Likely payoff**

   A clear confidence display will help build trust by making the system's certainty explicit to the wearer. This transparency can reduce misunderstandings and improve the overall user experience, leading to higher satisfaction and more consistent use of the glasses in real-world scenarios.

4. **Immediate next probe**
   - Define the format for the confidence display as `score X + Y + Z` for V1, where `X` is a numeric score, `Y` is the label, and `Z` is a brief reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a local memory threshold for cache size, we can ensure that the system retains critical context and person memories without overwhelming the phone's limited storage. This helps in maintaining trust by providing timely and accurate support while respecting battery constraints.

2. **What small change unlocks it**

   Define a specific local-cache size limit (e.g., 50 recent entries) for storing face and name memory objects, ensuring that frequently encountered individuals are prioritized over less relevant data.

3. **Likely payoff**

   Implementing this cache policy will help in reducing the load on cloud sync while still providing reliable support through frequent interactions. It ensures that the most relevant information is available locally, improving response times and overall user experience without consuming excessive storage resources.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific phone/cloud boundary for live subtitle processing, we ensure that subtitles are generated in real-time and remain stable enough to be trusted during live conversations. This directly addresses the "subtitle_clarity" attractor by ensuring that the glasses do not introduce latency or instability that would break trust.

2. **What small change unlocks it**

   Define a single task boundary where subtitle processing is done locally on the phone, with no fallback to the cloud for this function in V1.

3. **Likely payoff**

   This decision will result in more stable and responsive subtitles, which are crucial for maintaining the wearer's trust during live interactions. It also simplifies the system architecture by reducing the need for complex cloud-to-phone communication, thus saving battery and processing resources.

4. **Immediate next probe**
   - Define the boundary such that all subtitle processing is done locally on the phone in V1, with no fallback to the cloud for this function.

3. **Likely payoff**

Subtitles will remain the primary focus, ensuring that critical information is not missed, while one-line support remains visible but less intrusive.

4. **Immediate next probe**
