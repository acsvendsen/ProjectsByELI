### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Stable subtitle placement rules enhance trust by ensuring that subtitles remain in a predictable location, reducing cognitive load and distraction for the wearer.

2. **What small change unlocks it**
   - Define two fixed subtitle placement modes: one for high-confidence interactions (e.g., clear speakers) and another for low-confidence interactions (e.g., noisy environments).

3. **Likely payoff**
   - By establishing consistent placement rules, the system can maintain a higher level of trust and reliability in real-time interactions, which is critical for the core mission of helping the wearer understand better.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances trust by clearly indicating the reliability of the displayed information. This directly supports the core attractor of memory support (memory_trust) and the core mission of providing reliable, context-aware assistance.

2. **What small change unlocks it**

   Define a clear, concise confidence format that includes a numeric score, label, and short reason. For example: "score 0.84 + 'High' + 'Seen recently'".

3. **Likely payoff**

   By standardizing the confidence display, the system can clearly communicate its level of certainty to the wearer, reducing ambiguity and increasing trust in the displayed information. This will help the wearer make better decisions based on the system's recommendations.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local memory threshold for name recall, the system can ensure that frequently encountered names are always available locally, reducing latency and improving trust. This helps in maintaining consistent and reliable support without overloading the phone's resources.

2. **What small change unlocks it**

   Define a local cache size limit for frequently seen people (e.g., 5-10 recent names) to be stored on the phone, with weaker evidence (less frequent encounters or new faces) kept in the cloud until explicitly reinforced by user interaction.

3. **Likely payoff**

   This change will reduce the need for frequent network requests, thereby improving real-time responsiveness and reducing battery consumption. It also ensures that the most relevant memory is always available locally, enhancing the overall trustworthiness of name recall functionality.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear phone-cloud boundary for live subtitle processing, we ensure that subtitles remain reliable and fast. This helps in maintaining the real-time subtitle clarity attractor while reducing battery drain and thermal load on the glasses.

2. **What small change unlocks it**

   Define a rule that all live subtitle processing must happen locally on the glasses until explicit user interaction (frame touch) triggers a fallback to cloud processing for complex or uncertain situations.

3. **Likely payoff**

   This approach ensures that subtitles are fast and reliable, leveraging the local hardware capabilities of the glasses. It also minimizes battery usage and thermal load during normal operation, which is crucial for maintaining a long-lasting, discreet device.

4. **Immediate next probe**
   - Define the rule that all live subtitle processing must happen locally on the glasses until explicit user interaction (frame touch) triggers a fallback to cloud processing for complex or uncertain situations.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain the wearer's focus on critical information without overwhelming them. This improves both subtitle clarity and memory trust by preventing confusion and ensuring that important prompts stand out.

2. **What small change unlocks it**

   Define a single rule for displaying subtitles and one-line support such that subtitles remain prominent but do not overshadow crucial contextual cues. For example, subtitles could be displayed at the top of the field of view with one-line support appearing below them in a less dominant font size or color.

3. **Likely payoff**

   By clearly distinguishing between subtitles and one-line prompts, the wearer can more easily follow along during conversations without being distracted by less relevant information. This enhances the overall user experience and maintains trust in the system's ability to provide useful assistance without overloading the wearer.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
