### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a stable subtitle placement rule that ensures subtitles remain visible yet unobtrusive, we can enhance the wearer's trust in the system without creating distraction. This rule will keep subtitles always near the center of the field of view, allowing for quick reading while minimizing visual intrusion.

2. **What small change unlocks it**

   Define a simple subtitle placement rule that keeps subtitles centered within a 10% buffer from the top and bottom edges of the display area, ensuring they remain visible yet do not occupy significant vertical space.

3. **Likely payoff**

   A stable and unobtrusive subtitle placement will lead to higher trust in the system's reliability during live conversations. This will reduce cognitive load on the wearer, allowing them to focus more on the conversation itself rather than trying to read subtitles that are constantly moving or too small to read.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances trust in the wearer's understanding by clearly indicating the certainty level of the provided information. This is crucial for maintaining the balance between helpfulness and accuracy, ensuring that the wearer can rely on the system without feeling overwhelmed by uncertainty.

2. **What small change unlocks it**

   Define a simple numeric score + label + short reason format for confidence objects, such as `score 0.84 + "High" + "Seen recently"` or `score 0.63 + "Medium" + "Name heard once in introduction"`.

3. **Likely payoff**

   By adopting a clear and concise confidence display format, the system can better convey the reliability of its information to the wearer, thereby enhancing trust and reducing cognitive load during interactions. This simple but effective change helps maintain the balance between providing enough context for accuracy and avoiding unnecessary complexity.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we ensure that frequently encountered names are stored locally on the phone to provide fast and reliable lookup. This improves the confidence in memory support by reducing latency and enhancing the user's trust in the system's ability to quickly retrieve relevant information.

2. **What small change unlocks it**

   Define a local cache threshold of 5 recent face/name encounters, where each encounter must have at least three touches or explicit reinforcement to be stored locally.

3. **Likely payoff**

   This small change will significantly enhance the speed and reliability of name recall for the wearer. By caching frequently encountered names locally, the system can provide faster and more accurate responses, reducing latency and improving overall confidence in memory support.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary between what runs on the phone and what falls back to the cloud for live subtitle processing, the system can ensure that real-time performance is maintained while still leveraging cloud resources when necessary. This balance helps in maintaining trust through fast and accurate subtitles, which are essential for the core mission of enhancing real-world understanding.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing runs entirely on the phone. For example, set a rule that all subtitle processing for real-time conversations falls back to the phone's local runtime only. This means any speech-to-text work happens locally without cloud latency affecting the user experience.

3. **Likely payoff**

   By keeping subtitle processing local, the system can ensure sub-second response times, reducing the risk of lag and maintaining high confidence in the subtitles. This will help in creating a more reliable assistive tool that the wearer can trust during conversations.

4. **Immediate next probe**

   Define one phone-local subtitle processing rule for live conversation, where all real-time speech-to-text work is handled on the phone without cloud fallbacks.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles remain clear, fast, and stable enough for real-time use helps the wearer maintain trust in the system during live conversations. This improves the overall assistive value by ensuring that the wearer can rely on the subtitles to understand what is being said without distraction.

2. **What small change unlocks it**

   Define specific subtitle placement rules based on confidence levels: 
   - For high-confidence speakers, place subtitles at the bottom of the field of view.
   - For medium-confidence speakers, center the subtitles in a slightly larger box.
   - For low-confidence speakers, show subtitles with a slight offset to avoid occlusion.

3. **Likely payoff**

   By defining clear subtitle placement rules based on confidence levels, the system can reduce visual clutter and ensure that the most critical information is always easily readable. This will improve trust and usability in noisy or complex environments where multiple people are speaking.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
