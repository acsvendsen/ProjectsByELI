# Reality Check for SmartGlasses V1 Direction

## Subtitle Placement: Feasible Now

**Current Decision**: No concrete candidate selected; use best effort within `subtitle placement`.

- **Real-world Limit**: Real-time subtitle assistance is critical. Any delay in display can break trust.
- **Assessment**: Given the need for near-real-time subtitles, glasses must handle this task effectively without relying heavily on cloud processing to maintain latency requirements.

**Recommendation**: 
- **Top Priority**: Ensure minimal lag between text input and display on the glasses. Consider using advanced text-to-speech (TTS) algorithms optimized for SmartGlasses hardware.
- **Backup Plan**: Use simple, lightweight TTS solutions that can run locally with high efficiency to minimize battery drain.

---

## Confidence Display: Feasible Now

**Current Decision**: No concrete candidate selected; use best effort within `confidence display`.

- **Real-world Limit**: Confidence in memory recall and subtitle accuracy is crucial for maintaining user trust.
- **Assessment**: The confidence should be displayed clearly but not overly prominently. A balance between clarity and non-distracting must be struck.

**Recommendation**: 
- **Option 1**: Use a simple label with a brief reason (e.g., "High", "Medium", or "Low" with a short explanation like "Based on context").
- **Option 2**: Implement a numeric score system that is only shown when the confidence level drops below a certain threshold.
- **Avoid**: Complex, highly detailed feedback systems as they can distract from core functionality.

## Memory/Cache Policy: Feasible Now

**Current Decision**: No concrete candidate selected; use best effort within `memory/cache policy`.

- **Real-world Limit**: Memory policy must balance the need for fast lookup with battery and thermal constraints.
- **Assessment**: Automatic memory should be reinforced over time, especially in contexts where confidence is high.

**Recommendation**: 
- **Automatic Memory**: Store new faces and names automatically when context supports it. Reinforce this information through repeated interactions.
- **Explicit Reinforcement**: Allow users to explicitly reinforce memories through touch inputs for critical situations.
- **Cache Management**: Use a simple caching mechanism on the phone that expires older data to save resources.

## Phone/Cloud Boundary: Feasible Now

**Current Decision**: No concrete candidate selected; use best effort within `phone/cloud boundary`.

- **Real-world Limit**: Heavy cloud dependency can compromise battery and latency.
- **Assessment**: Use the phone for most processing, with limited cloud interaction only where it adds clear value.

**Recommendation**: 
- **Primary Processing**: Handle speech-to-text, context analysis, and memory lookup on the phone.
- **Cloud for Deep Analysis**: Use the cloud for background model training, deep analysis of complex queries, or non-critical tasks that do not affect real-time performance.
