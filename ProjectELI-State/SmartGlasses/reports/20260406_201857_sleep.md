# Consolidation of Key Signals

## Strengthening Signals
- **Subtitle Clarity**: The core mission is to ensure real-time subtitles are clear, fast, and stable enough for the wearer to trust them in live conversations.
- **Memory Trust**: Names, faces, and prior context should be remembered with confidence objects and reinforced over time without pretending certainty or creating corrupted recall.

## Weakening Signals
- **Low-Friction Assistance**: While important, this is currently being pushed down as the project focuses on core functionality (subtitle clarity and memory trust).

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: The system must balance providing useful assistance with maintaining privacy. Ineffective memory support could compromise user trust.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement**: Explore different subtitle placements to ensure they are readable in motion and noise, without becoming distracting.
- **Confidence Display**: Define the best format for confidence (label only, label + short reason, or score + label) to build trust.

## Concrete Tensions Around Core Areas

### Subtitle Quality
- **Latency vs Richness**: The system should provide timely help without overloading the runtime with richer but slower processing.
  
### Memory and Confidence
- **Automatic Memory Support vs Confidence and Correction Safety**: Automatic memory behavior needs to be reliable, but explicit remember-touch behavior ensures correction safety.

### Visual UX
- **Discreet UX vs Visual Clarity**: Display behavior should remain socially acceptable while still being readable in motion and noise. 

## Open Questions

1. **Subtitle Placement**: What is the best V1 split between glasses, phone, and cloud to ensure subtitles are clear and readable?
2. **Confidence Display**: How should confidence be represented (numeric score, label, and short reason) to build trust without overwhelming the wearer?
3. **Memory/Cache Policy**: How much face/name memory should be cached locally on the phone for fast lookup and reinforcement?

## Core Deepening Over Sprawl

- The project is allowed to evolve beyond its original form if that evolution strengthens the core mission, improves real-world usefulness, or increases trust, clarity, and assistive value.

## Reality Rules

- **Reality Check**: Surface battery, latency, privacy, and usability limits early so weak directions are killed quickly.
- **Core Deepening**: Bias toward subtitle quality, memory trust, confidence display, and architecture improvements that increase daily-use value.
