# Reality Check for SmartGlasses Project

## Subtitle Clarity (Subtitle Placement)

**Decision Area:** subtitle placement

### Feasibility Now: 
- **Subtitle Positioning**: Placing subtitles at the bottom of the field of view is a feasible approach. This minimizes occlusion and ensures they are visible without causing distraction.
- **Visual Hierarchy**: Ensure subtitles are designed with a simple, non-intrusive font and color scheme to maintain readability in motion. The placement should be such that it does not interfere with natural gaze direction.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app provides a test bed for live subtitle rendering, which can help determine the optimal position.
- **Concrete Constraints**: Given the current focus on phone-first runtime and minimal local compute, simple subtitle placement is more feasible now than complex AR overlays or dynamic adjustment.

## Confidence Display (Confidence Label + Short Reason)

**Decision Area:** confidence display

### Feasibility Now: 
- **Label Only vs. Label + Short Reason**: Implementing a label-only approach for initial V1 release might be the most feasible option. This keeps the user interface simple and avoids overwhelming them with detailed explanations.
- **Score + Label**: Introducing a score-based system later can provide more granular feedback, but this is likely to be a feature addition rather than core functionality in the first version.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app currently focuses on basic confidence display without detailed explanations. Gradually introducing more complex labels and reasons as needed.
- **Concrete Constraints**: Early versions should prioritize simplicity and low-friction over feature bloat, aligning with the core-deepening mode.

## Memory Trust (Face/Name Recall)

**Decision Area:** face/name memory storage

### Feasibility Now: 
- **Confidence Objects and Reinforcement**: Implement confidence objects for new faces and names using a simple reinforcement learning approach. This can be done on the phone, ensuring minimal local compute.
- **Persistent Storage**: Use lightweight persistent storage (like Core Data or SQLite) to cache face/name memory data locally on the phone.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app and related documentation provide a clear path for implementing basic memory storage and recall.
- **Concrete Constraints**: Given early versions should rely heavily on phone processing, this approach fits well within the current constraints of low local compute requirements.

## Low-Friction Assistance (Subtitle & Prompt Coexistence)

**Decision Area:** subtitle and prompt coexistence

### Feasibility Now: 
- **Coexistence Strategy**: Design subtitles and one-line prompts to coexist without overloading the wearer. For example, keep subtitles focused on essential information and use shorter, context-specific prompts for additional help.
- **Visual Separation**: Ensure that subtitles and prompts are visually distinct but still integrated into the overall UI.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app can be used to test different display strategies. Initial designs should prioritize clarity over complexity.
- **Concrete Constraints**: Ensuring low-friction interaction aligns with the frame-touch-only V1 interaction constraint and respects the need for minimal local processing.

## Phone/Cloud Boundary (Phone-First Runtime)

**Decision Area:** phone/cloud architecture

### Feasibility Now: 
- **Primary Processing on Phone**: Continue to prioritize heavy processing on the phone, using cloud only where clearly justified. This can include model updates or background data synchronization.
- **Local Context Handling**: Implement local context handling for subtitle generation and memory recall, reducing dependency on real-time cloud requests.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app provides a practical test bed for phone-side processing and transcript behavior. The project inputs emphasize phone-first runtime as the current direction.
- **Concrete Constraints**: Given the emphasis on battery and thermal constraints, local processing is a feasible approach to ensure reliable performance.

## Visual Hierarchy (Subtitle Placement & UX)

**Decision Area:** visual hierarchy

### Feasibility Now: 
- **Subtitle Placement**: Place subtitles at the bottom of the field of view for optimal readability. Ensure they are designed with simple, non-intrusive styling.
- **Prompt Design**: Design prompts to be small and unobtrusive, ensuring they do not interfere with natural eye movement.

### Reasoning:
- **Current Implementation Grounding**: The `TranscriptLab` app can be used to validate different subtitle and prompt placement strategies. Initial designs should focus on clarity and simplicity.
- **Concrete Constraints**: Ensuring low-friction interaction aligns with the frame-touch-only V1 interaction constraint and respects the need for minimal local processing.

### Summary

Based on the current project inputs and implementation grounding, the following directions are feasible now:

- **Subtitle Placement**: Bottom of field of view with simple styling.
- **Confidence Display**: Label only initially, score + label later if needed.
- **Memory Trust**: Confidence objects using simple reinforcement learning.
- **Low-Friction Assistance**: Subtitles focused on essential information, short prompts for additional help.
- **Phone/Cloud Boundary**: Heavy processing on phone with cloud support for background tasks.
- **Visual Hierarchy**: Clear distinction between subtitles and prompts.

These decisions align with the core-deepening mode and respect the current project constraints. Future iterations can build upon these foundations as needed.
