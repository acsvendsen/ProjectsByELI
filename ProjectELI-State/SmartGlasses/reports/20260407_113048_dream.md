### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain clear, readable, and stable enough for the wearer to trust them in live conversation. This is crucial for maintaining real-time subtitle clarity (subtitle_clarity attractor) and enhancing overall user experience.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule based on confidence levels: low-confidence subtitles should be shown at the bottom of the frame, medium-confidence ones slightly above that, and high-confidence ones near the top or in a consistent prominent position.

3. **Likely payoff**

   By implementing this fixed placement rule, we can ensure that subtitles are always visible but not overly distracting, improving trust and usability without adding complexity. This will help maintain focus on the conversation while providing necessary support.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

3. **Likely payoff**

4. **Immediate next probe**

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache threshold for name recall ensures that frequently encountered names are readily available without cloud dependency, thereby enhancing memory trust and low-friction assistance. This reduces latency and improves the reliability of real-time subtitle clarity by ensuring quick access to commonly remembered names.

2. **What small change unlocks it**

   Define a local cache threshold that stores recently seen names for at least 10 minutes, with a minimum of three encounters required before storing in the cache. This ensures that names are not only remembered but also quickly recalled when needed, without overwhelming the phone's memory or cloud storage.

3. **Likely payoff**

   By caching names locally and ensuring they are readily available within short-term memory, the system can provide faster name recall with higher accuracy, enhancing the wearer’s confidence in both subtitle clarity and memory support. This reduces the need for frequent cloud queries and improves overall user trust.

4. **Immediate next probe**

   Define a local cache threshold that stores recently seen names for at least 10 minutes, with a minimum of three encounters required before storing in the cache.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining which tasks run phone-local versus falling back to cloud, we ensure that subtitle processing remains fast and reliable in live interactions. This reduces latency, preserves battery life, and maintains the wearer's trust by providing near-real-time assistance.

2. **What small change unlocks it**

   Define a clear boundary for what runs on the phone and what falls back to the cloud specifically for live subtitle processing. For example, keep all subtitle rendering and basic confidence display local, but defer complex memory lookups or transcript cleanup to the cloud only when necessary.

3. **Likely payoff**

   This small change will ensure that subtitles remain fast and reliable in noisy environments, enhancing the wearer's trust and real-time understanding. It also allows for more complex memory operations without significantly impacting battery life, balancing performance and usability effectively.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain the wearer's focus on the primary content (subtitles) while still providing essential contextual information without overwhelming them. This balance enhances both the subtitle clarity and low-friction assistance attractors, making interactions more intuitive and less distracting.

2. **What small change unlocks it**

   Define a visual precedence rule where subtitles always appear above one-line prompts in the display order, with one-line prompts suppressed or reduced in size when subtitles are present but not active (e.g., during natural pauses).

3. **Likely payoff**

   By prioritizing subtitles over one-line support visually and temporarily suppressing less critical information, users will have a more consistent and distraction-free experience, leading to better trust in the system's reliability and usability.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
