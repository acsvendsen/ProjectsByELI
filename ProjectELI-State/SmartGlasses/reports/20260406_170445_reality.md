# Reality Check for SmartGlasses V1 Direction

Based on the provided inputs, here's a reality-check assessment of proposed directions against real-world limits:

## Subtitle Clarity (Subtitle Placement & Visual Hierarchy)

- **Subtitle Placement**: 
  - **Feasible Now**: Place subtitles near the bottom center of the glasses frame to minimize occlusion and ensure they are easily readable. Given that the glasses will be discreet, this placement balances visibility with social acceptability.
  - **Visual Hierarchy**:
    - **Feasible Now**: Design the subtitle display so it is more prominent than other visual elements but still unobtrusive. Use a large enough font size to ensure readability in motion and noise while maintaining a low profile.

- **Assumptions Needing Evidence**:
  - Conduct A/B testing with different placement and hierarchy designs to determine what minimizes distraction without sacrificing clarity.

## Memory Trust (Face/Name Recall & Confidence Display)

- **Memory Policy**: 
  - **Feasible Now**: Implement face/name memory using a recency-first cache on the phone. This approach ensures that recently encountered individuals are remembered with confidence, while less frequent encounters have lower certainty.
  - **Assumptions Needing Evidence**:
    - Test how users react to different levels of confidence in memory recall (e.g., label + short reason vs score + label).

- **Confidence Display**: 
  - **Feasible Now**: Use a label and short reason to display confidence. This approach provides enough clarity without overwhelming the user.
  - **Assumptions Needing Evidence**:
    - Conduct user testing to determine if users find the label + reason format more useful than other formats.

## Low-Friction Assistance (One-Line Support & Interaction Design)

- **Low-Friction Interaction**: 
  - **Feasible Now**: Ensure that one-line support is concise and easy to understand. Avoid overloading the wearer with too much information.
  - **Assumptions Needing Evidence**:
    - Test different lengths and formats of one-liners to ensure they provide helpful context without causing distraction.

- **Frame-Touch Interaction Only**: 
  - **Feasible Now**: Stick to frame-touch interactions for V1. This approach aligns with the core-deepening focus on subtitle quality, memory trust, and visual UX.
  - **Assumptions Needing Evidence**:
    - Conduct user research to ensure that frame touches are intuitive and sufficient for all necessary interactions.

## Phone-First Architecture

- **Phone-First Processing**: 
  - **Feasible Now**: Keep the phone as the primary runtime for processing heavy tasks like speech recognition, context analysis, and memory lookups.
  - **Assumptions Needing Evidence**:
    - Monitor battery usage on the phone to ensure that cloud reliance is justified by performance gains.

- **Cloud Optional**: 
  - **Feasible Later**: Consider using cloud services where there is a clear benefit in terms of model accuracy or computational efficiency, but keep this optional until proven necessary.
  - **Assumptions Needing Evidence**:
    - Evaluate the trade-offs between local processing and cloud-based models to determine when cloud support adds significant value.

## Core Deepening

  - **Assumptions Needing Evidence**:

  - **Feasible Now**: Ensure that memory support is trustworthy by providing clear indications of confidence levels and avoiding overconfidence.
