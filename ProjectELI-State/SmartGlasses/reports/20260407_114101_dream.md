### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles remain clear and unobtrusive while still providing necessary support. This improves the wearer's trust in the system by reducing visual distractions and ensuring that critical information is always visible.

2. **What small change unlocks it**

   Define three subtitle placement rules: one for high-confidence (likely correct) subtitles, another for medium-confidence (uncertain but useful) subtitles, and a third for low-confidence (needs verification) subtitles. For each rule, set the position to be slightly above the center of the wearer's field of view.

3. **Likely payoff**

   By implementing these rules, we can create a more predictable and user-friendly experience. High-confidence subtitles will remain unobtrusive but always visible, while low-confidence ones will be placed in less prominent areas. This reduces cognitive load and ensures that critical information is not missed, thereby improving the overall trust and usability of the system.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps in maintaining trust and clarity for the wearer. By refining how certainty is communicated through a clear, concise label combined with a short reason, users can better understand when they should pay extra attention to certain information or actions.

2. **What small change unlocks it**

   Define one confidence format candidate that uses a numeric score, a label (like "High", "Medium", "Low"), and a short reason (e.g., "Seen recently", "Weak match").

3. **Likely payoff**

   By implementing this refined confidence format, users will have clearer understanding of the reliability of the information being displayed, leading to increased trust in the system's judgments and more effective use of its features.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory objects, the system can balance memory trust with real-world constraints. This ensures that likely new-person memories are automatically stored but also prevents unnecessary storage of low-value information.

2. **What small change unlocks it**

   Define and set a threshold for the number of local cache entries or memory objects retained on the phone. For instance, limit the face/name cache to the top 10 most recently encountered individuals.

3. **Likely payoff**

   This approach will help maintain trust by ensuring that the system does not become overly intrusive with repeated reminders about individuals who are unlikely to be relevant in ongoing conversations. It also helps manage storage and processing load on the phone, enhancing battery efficiency and performance.

4. **Immediate next probe**

   Define a local cache size limit of 10 entries for face/name memory objects to balance memory trust and resource constraints.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that memory support remains phone-local for tasks like face/name recall lookup reduces battery drain and thermal stress on the glasses. This allows the system to provide faster, more reliable assistance without overloading the wearable device.

2. **What small change unlocks it**

   Define a local cache eviction policy for name recall that keeps recently seen faces and names in phone memory while evicting less frequently used entries after a certain period or under low-memory conditions.

3. **Likely payoff**

   By keeping face/name recall locally, the system can quickly provide confidence objects and fast lookups during conversations, reducing latency and improving trust. This also aligns with the core attractors of real-time subtitle clarity and memory support that is trustworthy without overburdening the glasses hardware.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

Improving subtitle vs one-line support coexistence ensures that both elements enhance the wearer's understanding without overwhelming them. This balance supports real-time subtitle clarity and low-friction assistance, two primary attractors.

2. **What small change unlocks it**

Define a visual hierarchy rule that prioritizes subtitles over one-line prompts when confidence is high but suppresses the subtitle display if the one-line prompt provides enough context.

3. **Likely payoff**

By optimizing this balance, the system will reduce cognitive load and distraction during live conversations, ensuring that critical information (subtitles) remains clear while less essential contextual support (one-liners) can be given prominence when needed. This enhances overall trust in the assistive features without overwhelming the wearer.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
