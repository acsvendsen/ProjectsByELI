### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Stabilizing subtitle placement rules helps ensure that subtitles remain readable, unobtrusive, and reliable throughout conversations, reducing cognitive load on the wearer and increasing trust in the assistive system.

2. **What small change unlocks it**

   Define two fixed subtitle placement rules: one for high-confidence states (e.g., familiar speakers) where subtitles can be placed slightly lower or more subtly, and another for low-confidence states (e.g., unfamiliar speakers or noisy environments) where subtitles should be more prominently displayed to ensure clarity.

3. **Likely payoff**

   By defining clear subtitle placement rules based on confidence levels, the system will provide a consistent and predictable experience that enhances trust and readability without overwhelming the wearer during critical moments of conversation.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance trust in both subtitle accuracy and memory recall. A well-designed confidence indicator ensures that the wearer can quickly assess the reliability of displayed information, thereby reducing uncertainty and improving overall user satisfaction.

2. **What small change unlocks it**

   The small change is to define a specific format for confidence objects: using a numeric score combined with a label and a short reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format provides clear and concise information about the confidence level of the displayed data.

3. **Likely payoff**

   By implementing a structured confidence display, the system will become more transparent and reliable. The wearer can better understand the context behind the displayed information, leading to improved trust in both subtitles and memory recall. This clarity will help reduce cognitive load and enhance overall usability.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size threshold for name recall helps ensure that frequently mentioned people and contexts are quickly available, reducing latency and enhancing trust in the memory support system.

2. **What small change unlocks it**

   Define a local cache size limit of 50 entries for names and faces, prioritizing recent encounters to maintain fast lookup performance without overloading storage.

3. **Likely payoff**

   By setting this threshold, we ensure that the wearer can quickly recall frequently mentioned individuals, enhancing the overall usability and trust in memory support. This reduces the need for frequent cloud lookups, conserving battery and reducing latency, while still maintaining a robust memory cache for repeated interactions.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that memory lookups stay local to the phone improves privacy, reduces latency, and maintains a low-friction experience for the wearer. Local processing ensures that sensitive information about names and faces is not unnecessarily sent to the cloud, thereby enhancing trust and reducing potential privacy risks.

2. **What small change unlocks it**

   Define one fast-lookup index policy for people, names, and topics on the phone that prioritizes local storage over cloud fallback for memory lookups.

3. **Likely payoff**

   By keeping memory lookups local, we can significantly reduce latency during critical moments like introducing new people or recalling past conversations. This ensures that the glasses remain highly responsive and trustworthy in social settings, where even minor delays can break the user's flow of conversation.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
