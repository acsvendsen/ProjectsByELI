# Reality Check for SmartGlasses V1 Direction

## Core Attractors and Tensions

### Attractor: Real-time subtitle clarity (Subtitle Clarity)
- **Feasibility**: Feasible now.
  - **Reasoning**: With current hardware, real-time subtitles can be generated on the phone using iOS's `AVAudioEngine` combined with speech-to-text services. The latency of this process can be managed to ensure subtitles are displayed near-real-time, making them useful for live conversations.

### Attractor: Trustworthy memory support (Memory Trust)
- **Feasibility**: Feasible now.
  - **Reasoning**: Context-aware name and face recall can be implemented using a local memory cache on the phone. This can use simple heuristics to remember names and faces based on recent interactions, with clear indications of confidence levels when possible.

### Attractor: Low-friction assistance (Low Friction Assistance)
- **Feasibility**: Feasible now.
  - **Reasoning**: One-line support can be implemented through a context-aware system that triggers brief prompts or reminders. These prompts should be designed to minimize disruption while providing useful information.

## Core Tensions

### Tension: Privacy vs Usefulness (Privacy vs Usefulness)
- **Feasibility**: Feasible now.
  - **Reasoning**: The system can use context and recent interactions to make reasonable guesses about who the wearer is likely talking to, but it should not pretend certainty where it does not exist. This can be balanced by providing clear indications of confidence in the memory support.

### Tension: Latency vs Richness (Latency vs Richness)
- **Feasibility**: Feasible now.
  - **Reasoning**: While richer features like detailed context or complex multimodal interactions might provide more value, they can introduce significant latency. A balance can be struck by providing useful one-line prompts and clear confidence indicators.

### Tension: Discreet UX vs Visual Clarity (Discreet UX vs Visual Clarity)
- **Feasibility**: Feasible now.
  - **Reasoning**: The system should focus on making the UI as unobtrusive as possible while still being readable in noisy environments. This can be achieved through careful subtitle placement and visual hierarchy design.

## Core Constraints

### Constraint: Frame-touch-only V1 Interaction (Frame-Touch-Only V1)
- **Feasibility**: Feasible now.
  - **Reasoning**: Given the early hardware constraints, frame touches are a practical choice for interaction. This can be expanded later if necessary, but it aligns well with current constraints.

### Constraint: Phone-first Runtime (Phone-First Runtime)
- **Feasibility**: Feasible now.
  - **Reasoning**: The phone can handle heavy processing tasks while the glasses remain simple in terms of hardware and battery requirements. This allows for iterative improvements as technology evolves.

## Core Modes

### Mode: Core Deepening
- **Feasibility**: Feasible now.
  - **Reasoning**: Prioritizing subtitle clarity, memory trust, confidence display, and visual UX will provide the most immediate value to users. These core features should be refined iteratively based on user feedback.

## Implementation Grounding

### Subtitle Placement (Subtitle Placement)
- **Feasibility**: Feasible now.
  - **Reasoning**: Initial placement can focus on areas of the glasses that remain unobtrusive while still being readable, such as near the edge or corner. This can be optimized based on user testing.

### Confidence Display (Confidence Display)
- **Feasibility**: Feasible later.
  - **Reasoning**: While simple confidence indicators are feasible now, more complex systems like a label and short reason might require more hardware support that is not currently available.

### Memory/Cache Policy (Memory/Cache Policy)
- **Feasibility**: Feasible now.
  - **Reasoning**: Implement basic memory caching on the phone with clear indications of confidence. This can be expanded as the system learns from user interactions and feedback.

### Phone/Cloud Boundary (Phone/Cloud Boundary)
- **Feasibility**: Feasible now.
  - **Reasoning**: The initial implementation should rely heavily on the phone for processing, with cloud support optional where it adds clear value. This can evolve as needed based on user testing and technological advancements.

### Visual Hierarchy (Visual Hierarchy)
- **Feasibility**: Feasible now.
  - **Reasoning**: Design a visual hierarchy that prioritizes clarity over feature density, ensuring the wearer can quickly understand the information being presented without distractions.

## Reality Rules

- The current approach of focusing on core functionality like real-time subtitles and memory support is well-grounded in current hardware constraints and user needs.
- The use of frame-touch interactions aligns with early-stage hardware limitations and helps maintain a low-friction UX.
- The initial implementation should prioritize clarity, trustworthiness, and low-latency responses to ensure the system remains useful and reliable.

## Next Steps

1. **Subtitle Clarity**: Optimize subtitle generation using available speech-to-text services and ensure they are displayed near-real-time.
2. **Memory Support**: Implement a basic caching mechanism on the phone for remembering names and faces with clear confidence indicators.
3. **Low Friction Assistance**: Design one-line prompts that are useful but unobtrusive, focusing on common use cases like reminders or context clues.

By focusing on these core areas, the project can provide immediate value while maintaining a path to future enhancements as technology evolves.
