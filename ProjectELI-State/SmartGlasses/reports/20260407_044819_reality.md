# Reality Check for SmartGlasses Project

## Feasibility Assessments

### Subtitle Placement: feasible now
- **Current State**: The `TranscriptLab` app provides a clear and usable interface to test subtitle placement.
- **Constraints**: V1 interaction is frame-touch only, so subtitle placement should not be distracting. 
- **Decision Area**: Given the current design and testing framework, subtitle placement can be iterated on without complicating the initial release.

### Confidence Display: feasible now
- **Current State**: The `TranscriptLab` app supports confidence display, allowing for early iteration.
- **Constraints**: Real-time clarity is a high priority, so any confidence display must not interfere with subtitles. 
- **Decision Area**: Using label-only or short reason formats can be implemented quickly and tested without affecting subtitle readability.

### Memory/Cache Policy: feasible now
- **Current State**: The `TranscriptLab` app supports memory recall, allowing for early testing of local caching strategies.
- **Constraints**: V1 should not rely on heavy on-glasses computation to avoid battery drain. 
- **Decision Area**: Implementing a simple cache policy that respects the current phone-first architecture can be tested effectively.

### Phone/Cloud Boundary: feasible now
- **Current State**: The `TranscriptLab` app is designed for phone-first processing, allowing for early validation of cloud integration.
- **Constraints**: Cloud support should be optional and justified by clear value. 
- **Decision Area**: Implementing basic cloud functionality as needed can be done without complicating the initial release.

### Visual Hierarchy: feasible now
- **Current State**: The `TranscriptLab` app provides a testbed for visual hierarchy design.
- **Constraints**: V1 interaction is frame-touch only, so visual hierarchy should not complicate this process. 
- **Decision Area**: Early designs can be iterated on to ensure subtitles and prompts are clear without overwhelming the wearer.

## Reality Guardrails

### Subtitle Placement
- The placement of subtitles should remain unobtrusive yet clear enough for real-time reading. Testing in `TranscriptLab` will help identify optimal placements.
- **Assumptions**: Current testing shows that top-center placement is readable and minimally distracting.

### Confidence Display
- Using a label-only format or short reasons can be implemented quickly without adding significant complexity.
- **Assumptions**: A simple confidence label (e.g., "Maybe", "Likely") will provide enough trust signals for users without overwhelming them.

### Memory/Cache Policy
- Implementing basic caching on the phone to support name and face recall is feasible. 
- **Assumptions**: Caching can be done using local storage mechanisms that do not drain the battery significantly.

### Phone/Cloud Boundary
- Basic cloud functionality can be integrated as needed, such as model updates or background processing.
- **Assumptions**: Initial cloud integration should focus on non-critical tasks to avoid complicating V1.

### Visual Hierarchy
- The visual hierarchy of subtitles and prompts should remain simple and clear. 
- **Assumptions**: A clean design with distinct separators between subtitles and prompts will work well in the initial release.

## Feasibility Outcomes

- **Subtitle Placement**: Current testing shows top-center placement is feasible.
- **Confidence Display**: Label-only or short reason formats can be implemented quickly.
- **Memory/Cache Policy**: Basic caching on the phone is practical without significant battery impact.
- **Phone/Cloud Boundary**: Basic cloud functionality can be integrated as needed.
- **Visual Hierarchy**: A clean, simple design will work for initial release.
