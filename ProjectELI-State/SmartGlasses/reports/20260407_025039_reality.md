# Reality Check for SmartGlasses

## Subtitle Placement: feasible now
- **Current Context**: The primary attractor is real-time subtitle clarity, and the system should be able to deliver clear and stable subtitles in live conversations.
- **Constraints**: Given the focus on phone-first processing and minimal local logic on glasses, the glasses will primarily display text from the phone. This means the subtitle placement is already being tested and optimized within `TranscriptLab`.
- **Reasoning**: Since `TranscriptLab` is designed to mimic a future glasses experience without heavy on-glasses computation, it can effectively test different subtitle placements through UI tweaks.

## Confidence Display: feasible now
- **Current Context**: The attractor for confidence display is set at 0.68, indicating that the system should deliver one-line help and visible support while minimizing command overhead.
- **Constraints**: The system must maintain trust without overwhelming the wearer with too much information. This aligns well with the existing design in `TranscriptLab`, which can test different ways of displaying confidence.
- **Reasoning**: Given the current setup, we can iteratively adjust the confidence display to ensure it provides just enough clarity and does not become a distraction.

## Memory/Cache Policy: feasible now
- **Current Context**: The attractor for memory support is set at 0.78, indicating that the system should remember names, faces, and prior context effectively.
- **Constraints**: Memory policies must respect privacy while providing useful recall. This can be tested through the `TranscriptLab` model and state management.
- **Reasoning**: The current setup in `TranscriptLab` allows for iterative testing of memory caching strategies to ensure they provide rich but fast lookup, aligning with the attractor goals.

## Phone/Cloud Boundary: feasible now
- **Current Context**: V1 is phone-first with minimal on-glasses compute. This ensures heavy processing happens on the phone while preserving a path to stronger local capability later.
- **Constraints**: The system must not rely heavily on cloud services for basic functionality, and interactions should be controlled through frame touches only.
- **Reasoning**: Given that `TranscriptLab` is designed to test these boundaries without cloud dependencies, it can effectively simulate the V1 phone-first model.

## Visual Hierarchy: feasible now
