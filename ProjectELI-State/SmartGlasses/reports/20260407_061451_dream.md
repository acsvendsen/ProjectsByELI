### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles are always clear, stable, and easy to read, even in rapidly changing conversation contexts. This improves real-time subtitle clarity (subtitle_clarity attractor) and enhances the wearer's ability to follow conversations without distractions.

2. **What small change unlocks it**
   - Define two subtitle placement rules: one for high-confidence subtitles that can be placed centrally and prominently on the screen, and another for low-confidence subtitles that are placed slightly off-center or in a less dominant position.

3. **Likely payoff**
   - This tweak ensures that critical information is always visible, while less certain information does not distract from the primary conversation flow. It strengthens trust by making sure the wearer can rely on the subtitles even when the system's confidence is low.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   - By refining the confidence display format, we can enhance the trustworthiness of the subtitle and memory support provided to the wearer. A well-crafted confidence object will help the wearer understand when they should pay more attention to a subtitle or when they can rely on the system's recall.

2. **What small change unlocks it**
   - Define a consistent format for confidence objects that includes a numeric score, label, and short reason. For example: "score 0.84 + 'High' + 'Seen recently';" "score 0.42 + 'Low' + 'Weak match';" "score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**
   - A well-defined confidence format will help the wearer trust the system more, leading to a better user experience and increased daily use. It also simplifies the visual hierarchy, making it easier for the wearer to distinguish between different levels of certainty.

4. **Immediate next probe**
   - Define the numeric score format for the confidence display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear recency-based local cache threshold for new-person memory objects, we can ensure that likely new faces and names are stored with high confidence while maintaining privacy and reducing unnecessary data retention. This helps in quickly retrieving recent memories without overwhelming the local cache, thus improving subtitle quality and context support.

2. **What small change unlocks it**

   Introduce a simple recency-based eviction rule where memory objects for people and names are kept in the local cache based on their last interaction time. Objects that have not been interacted with within a certain timeframe (e.g., 30 minutes) can be evicted to make space for more recent interactions.

3. **Likely payoff**

   This change will enhance the system's ability to provide relevant and timely memory support while keeping the local cache size manageable, reducing privacy concerns and improving overall performance by freeing up resources for more frequent interactions.

4. **Immediate next probe**

   Define a 30-minute recency threshold for local caching of new-person memory objects, ensuring that only recently interacted individuals are stored in the local cache.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for live subtitle processing on the phone versus fallback to cloud, we ensure that real-time subtitles remain stable and reliable. This reduces latency and keeps the glasses lightweight, maintaining trust and usability in noisy environments where timely assistance is critical.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary: live subtitle processing should be done locally on the phone with minimal fallback to the cloud only for specific failure cases like severe network issues or offline states.

3. **Likely payoff**

   This will result in more consistent and timely subtitle delivery, reducing latency-induced errors and improving overall trust in the system. It also allows the glasses to remain lighter and more socially acceptable by minimizing data transfer overhead.

4. **Immediate next probe**
   - Define a single task-specific cloud fallback boundary for live subtitle processing: the process should be handled locally on the phone with minimal fallback to the cloud only during severe network issues or offline states.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain focus during live conversations, reducing cognitive overload and enhancing the wearer's ability to follow the conversation without distraction.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule that ensures subtitles are always prioritized over one-line prompts when both appear at the same time. This can be achieved by setting a higher visual prominence for subtitles, such as displaying them slightly larger or in a more contrasting color than one-line support.

3. **Likely payoff**

   By clearly prioritizing subtitles, the system reduces visual clutter and maintains the wearer's attention on the most critical information. This enhances the overall user experience by making the content easier to read and follow during live interactions.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
