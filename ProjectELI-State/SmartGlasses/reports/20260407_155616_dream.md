### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states will ensure that subtitles are always in a visible and non-distracting position, enhancing the wearer's trust in the system without overwhelming them with too much information.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence matches (where the name or face is strongly recognized) and another for low-confidence matches (where new faces/names are being encountered). This will allow the system to dynamically adjust subtitle visibility based on certainty, reducing visual clutter when trust is higher.

3. **Likely payoff**

   By implementing dynamic subtitle placement rules, the system can maintain a balance between providing necessary assistance and avoiding distraction. This will enhance user trust and satisfaction, as subtitles are more likely to be noticed when needed and less likely to cause annoyance when they are not.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format directly enhances user trust by ensuring that the wearer understands the reliability of the information presented. A clear, concise, and context-aware confidence label improves the system's perceived honesty and reliability, which is crucial for maintaining daily-use value.

2. **What small change unlocks it**

   Define a simple yet effective confidence format: "score 0.85 + 'High' + 'Seen recently'" for high-confidence items and "score 0.45 + 'Low' + 'Weak match'" for low-confidence items. This format combines a numeric score with labels that indicate the level of certainty and a short reason.

3. **Likely payoff**

   By implementing this confidence format, users will quickly understand the reliability of the information being presented. High-confidence items will be trusted more, while low-confidence items will prompt the user to seek additional context or confirmation, thus enhancing overall trust and reducing cognitive load.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

   By defining a local cache size limit for name recall memory objects, we can ensure that relevant names remain fresh while managing storage efficiently. This helps maintain trust and utility by keeping frequently recalled names readily available without overwhelming the device.

2. **What small change unlocks it**

   To unlock this improvement, we need to set a specific threshold for the local cache size on the phone, such as limiting name recall memory objects to the top 10 most recent interactions or appearances.

3. **Likely payoff**

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays on the phone versus what falls back to the cloud for transcript cleanup, we can ensure that subtitle quality remains stable and responsive in real-time interactions. This decision will prevent unnecessary data transfers, reduce battery drain, and maintain the wearability of the glasses.

2. **What small change unlocks it**

   Define a specific task boundary where transcripts are cleaned up on-device before being sent to cloud storage for memory archive sync. For example, set a rule that any transcript cleanup involving more than 3 seconds of audio or complex face/name recognition should fall back to the cloud.

3. **Likely payoff**

   This change will reduce battery drain by minimizing data transfers and ensure that real-time subtitle processing remains quick and reliable. It also helps maintain privacy by keeping sensitive data locally until it is necessary to send it for memory storage.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
