# Reality Check Summary

## Subtitle Clarity - Real-time subtitle clarity (subtitle_clarity)

- **Feasible now**: The `TranscriptLab` app provides a real-time transcript test bed for live microphone capture, partial and final transcript behavior, and confidence display. This allows us to iteratively improve subtitle quality in a concrete, measurable way.
- **Assumptions needing evidence**: Ensure that the subtitle placement is optimal without becoming distracting. Testing with different placements will help determine what works best.

## Memory Trust - Trustworthy memory support (memory_trust)

- **Feasible now**: Implement face/name recall through confidence objects and reinforcement over time, as outlined in the current architecture direction. This can be done by integrating the existing phone-side transcript plumbing into a memory caching policy.
- **Assumptions needing evidence**: Define how to best represent confidence for face/name memory—should it be numeric, labeled with reasons, or something else? This will impact the trust users place in the system.

## Low-friction Assistance - Low-friction assistance (low_friction_assistance)

- **Feasible now**: The `TranscriptLab` app can help evaluate one-line prompts and their visual distinction from subtitles. Implementing these low-friction interactions through frame touches is a core V1 constraint.
- **Assumptions needing evidence**: Determine how the one-line prompts should visually differ from subtitles to ensure they do not create command overhead or social awkwardness.

## Core Deepening - Core-deepening over sprawl (core_deepening)

- **Feasible now**: Focus on subtitle quality, memory trust, and visual UX improvements as these align with the current `Core Deepening` mode. These efforts will strengthen the core mission.
- **Assumptions needing evidence**: Clarify the specific changes needed for subtitle clarity, memory support, and confidence behavior to ensure they meet the high-strength requirements.

## Constraint Pressure - Surface battery, latency, privacy, and usability limits (constraint_pressure)

- **Feasible now**: Use the `TranscriptLab` app's real-time transcript path to test battery consumption. Ensure that the system remains within acceptable thermal and battery limits.
- **Assumptions needing evidence**: Define clear thresholds for what constitutes "acceptable" battery drain and how these will be monitored in future builds.

## Implementation Grounding - Reason from actual repo files, app docs, and build truth (implementation_grounding)

- **Feasible now**: The `TranscriptLab` project provides a concrete starting point. Implement changes directly based on the current state of the repository.
- **Assumptions needing evidence**: Verify that the changes made in `TranscriptLab` are practical within the existing constraints and do not introduce new problems.

## Interaction Direction - Frame-touch-only V1 interaction (frame_touch_only_v1)

- **Feasible now**: The `TranscriptLab` app should be used to test frame-touch interactions. Ensure that all proposed subtitle and memory management actions can be performed through these touches.
- **Assumptions needing evidence**: Define the exact touch-based interactions required for subtitle management, mode switching, and confirmations.

## Phone/Cloud Boundary - Phone-first runtime (phone_first_runtime)

- **Feasible now**: The `TranscriptLab` app should remain phone-centric. Ensure that all heavy processing is handled on the phone while keeping cloud usage minimal.
- **Assumptions needing evidence**: Define which parts of the transcript and memory handling can be offloaded to the cloud without affecting performance or user experience.

## Visual Hierarchy - Clear visual distinction for one-line prompts (visual_hierarchy)

- **Feasible now**: The `TranscriptLab` app should help in defining how one-line prompts visually differ from subtitles. This will ensure that they are distinguishable and do not create command overhead.
- **Assumptions needing evidence**: Define the specific design elements that make one-line prompts easily distinguishable.

## Summary

The current project direction is feasible now based on the concrete test bed provided by `TranscriptLab`. The core attractors can be addressed through iterative improvements in subtitle quality, memory trust, and visual UX. However, some assumptions need further evidence to ensure these changes align with user expectations and technical constraints.
