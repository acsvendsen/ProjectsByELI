## Feasibility Assessment

### Subtitle Placement: feasible now

- **Current State**: The `TranscriptLab` app provides a phone-first test bed for validating real-time transcripts.
- **Constraints**: The glasses should remain lightweight and socially acceptable, with minimal on-glasses compute. 
- **Feasibility**: Given the current focus is on phone processing, implementing basic subtitle placement in the `TranscriptLab` app is feasible now. This can include simple tests like fixed positions (e.g., top center) to ensure readability without distraction.

### Confidence Display: feasible later

- **Current State**: The confidence display needs further refinement based on user feedback and testing.
- **Constraints**: Early versions should rely heavily on phone processing, with clear UI for confidence labels and short reasons.
- **Feasibility**: While the current `TranscriptLab` app does not have explicit confidence display features, adding basic confidence indicators can be done later. This might involve integrating existing `SpeechTranscriber.swift` functionality into a simplified UI that reflects the current project attractors.

### Memory/Cache Policy: feasible now

- **Current State**: The memory policy is still open-ended, but the focus on phone-first processing and minimal local logic on glasses implies simpler caching strategies.
- **Constraints**: Local processing should be kept to a minimum, with cloud optional where clearly justified.
- **Feasibility**: Implementing basic caching policies for face/name recall can be done now in `TranscriptLab`. This could involve storing recent faces/names locally and using the phone for more complex lookups.

### Phone/Cloud Boundary: feasible later

- **Current State**: The current architecture is biased toward phone-first processing, with cloud optional where useful.
- **Constraints**: The system should avoid overbuilding hardware in V1 to reduce battery and thermal pressure.
- **Feasibility**: Defining clear boundaries between phone and cloud can be refined later. For now, ensure that the `TranscriptLab` app reflects these principles by minimizing heavy processing on the glasses.

### Visual Hierarchy: feasible later

- **Current State**: The visual hierarchy for subtitles is not yet defined.
- **Constraints**: The UI should favor clarity over feature density to remain socially acceptable and readable in motion and noise.
- **Feasibility**: Implementing a basic visual hierarchy can be done later once more concrete requirements are known. This could involve simple A/B testing with different subtitle placements.
