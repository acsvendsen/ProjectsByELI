# Reality Check for SmartGlasses

## Subtitle Clarity - Real-time subtitle clarity (subtitle_clarity)

### Feasibility Now: **Feasible now**
- **Current Status**: The TranscriptLab app provides a framework to test live subtitles, ensuring they remain readable and stable in real-time scenarios.
- **Concrete Constraints**:
  - **Latency**: Current tests should ensure that subtitle updates are fast enough to be useful in conversation. This can be tested using the `LiveTranscriptTestView` within TranscriptLab.
  - **Battery Draw**: The initial design focuses on minimal local logic, which helps with battery management.

### Subtitle Placement
- **Current Status**: The placement of subtitles is not yet optimized but should remain non-intrusive and readable in motion. This can be iterated upon based on real user feedback.
- **Concrete Constraints**:
  - **Visual Clarity**: Subtitles must be clear enough to read without being too distracting, especially during movement.

## Memory Trust - Trustworthy memory support (memory_trust)

### Feasibility Now: **Feasible now**
- **Current Status**: The system can use a confidence model to represent the trustworthiness of face and name recall. This can be implemented using labels and short reasons.
- **Concrete Constraints**:
  - **Privacy Perception**: Memory support should not appear overly intrusive or create privacy concerns. Confidence objects and reinforcement learning are key here.
  - **Latency**: The system must provide timely updates to memory, ensuring that the wearer does not experience delays in recall.

## Low Friction Assistance - Low-friction assistance (low_friction_assistance)

### Feasibility Now: **Feasible now**
- **Current Status**: One-line prompts can be designed to assist the user without requiring additional commands or interactions. The initial design should focus on simple, clear text.
- **Concrete Constraints**:
  - **Battery Draw**: Keeping the UI minimal helps with battery management.
  - **Discreet UX**: Prompts must remain unobtrusive and aligned with the wearers' natural flow of conversation.

### Subtitle Placement & Visual Hierarchy
- **Current Status**: The placement of subtitles should be optimized for quick reading while minimizing distraction. This can involve iterative testing and user feedback.
- **Concrete Constraints**:
  - **Discreet UX**: The subtitle design must respect the social acceptability of the glasses, ensuring they are not too noticeable.

## Phone/Cloud Boundary
- **Current Status**: Early versions should rely heavily on phone processing with cloud support as optional. This aligns well with the initial V1 constraints.
- **Concrete Constraints**:
  - **Battery Draw**: Cloud-based processing can be used when it adds clear value and does not exceed latency limits.

## Interaction Constraints (frame_touch_only_v1)
- **Current Status**: V1 interaction should remain frame-touch only, ensuring simplicity and ease of use. This is a hard constraint.
- **Concrete Constraints**:
  - **Interaction Design**: Any changes to this interaction model must be explicitly justified by the project direction.

### Summary
- The current focus on subtitle clarity, memory trust, and low-friction assistance are feasible now given the existing implementation constraints and the current state of the TranscriptLab app. These features should continue to be prioritized as they align with the core mission of the SmartGlasses.
- The phone-first runtime and frame-touch-only interaction model also support these goals without introducing significant complexity.

## Future Considerations
- **Subtitle Placement**: Further iterations may involve optimizing subtitle placement based on user feedback, ensuring it remains clear and unobtrusive.
- **Memory Trust**: Confidence objects and reinforcement learning can be refined to better manage memory recall and trustworthiness.
- **Low Friction Assistance**: One-line prompts should remain simple and effective, avoiding unnecessary complexity.

By focusing on these core areas, the project can continue to make meaningful progress while respecting real-world constraints.
