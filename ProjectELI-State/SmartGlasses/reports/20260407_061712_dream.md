### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states will ensure that subtitles are visible, clear, and do not distract the wearer during conversations. This enhances the real-time subtitle clarity attractor by making sure that when the system is more confident about a name or word, the subtitle appears in a way that minimizes distraction while still being readable.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules for different confidence states: one for high confidence (e.g., seen multiple times), one for medium confidence (e.g., seen once recently), and one for low confidence (e.g., first time seen).

3. **Likely payoff**

   By carefully defining these subtitle placement rules, the system can maintain a good balance between being helpful and not intrusive. This will enhance user trust in the system's accuracy and reliability during live conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitles and memory support more reliably. A clear and concise confidence object, such as a numeric score with a label and short reason, helps the wearer understand the reliability of the information being provided in real-time.

2. **What small change unlocks it**

   Define a new confidence format for V1 that includes a numeric score, a label (e.g., "High", "Medium", "Low"), and a short reason (e.g., "Seen recently", "Weak match"). For example, a confidence object could be displayed as: score 0.84 + "High" + "Seen recently".

3. **Likely payoff**

   By implementing this confidence format, the system will provide clear indicators of how reliable the subtitles and memory support are, which will help build trust and ensure that the wearer can rely on the smart glasses for accurate information in real-time interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local cache size limit for face/name memory objects on the phone, we ensure that only the most relevant and frequently accessed information remains in memory. This reduces the risk of storing unnecessary or outdated data, which can degrade trust and performance over time. A well-defined cache size also helps manage battery usage by limiting the number of memory refreshes required.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects on the phone that balances the need to retain recent interactions with the risk of excessive data storage.

3. **Likely payoff**

   Implementing this cache size limit will help maintain high trust and performance by ensuring that only the most relevant information is retained in memory, reducing the likelihood of corrupted or outdated recall. This improvement will also contribute to better battery management by minimizing unnecessary memory refreshes.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining which subtitle processing and memory tasks run on the phone versus falling back to cloud, we ensure that V1 can deliver fast, reliable, and private real-time subtitles while maintaining a low-friction user experience for name recall and conversation support.

2. **What small change unlocks it**

   Define a clear boundary where live subtitle processing runs locally on the phone with minimal latency, but heavier memory tasks like face/name recall fallback to cloud processing when needed.

3. **Likely payoff**

   This approach ensures that subtitles remain clear and usable in real-time conversations, while still allowing for useful name and context recall from prior interactions without compromising privacy or battery life.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for face/name recall lookup.
