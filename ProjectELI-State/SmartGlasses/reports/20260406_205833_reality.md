# Reality Check for SmartGlasses V1

## Subtitle Clarity (Subtitle Placement)

- **Feasible Now**: The current focus on subtitle clarity is feasible and aligns with the core mission of providing real-time, clear subtitles in noisy environments. Given the existing prototype setup via `TranscriptLab`, it's possible to refine subtitle placement through visual tests and adjustments. For example, testing different screen areas (top vs. bottom) and ensuring text does not flicker or distort during motion can be done without significant hardware constraints.

## Memory Trust (Memory Policy)

- **Feasible Now**: Implementing basic memory trust mechanisms such as confidence objects for names and faces is feasible with the current V1 interaction constraint of frame touches only. This can involve storing recent interactions in a simple cache on the phone to recall names and faces accurately, using explicit touch interactions to confirm or deny memories.

## Low Friction Assistance (Confidence Display)

- **Feasible Now**: Implementing one-line prompts for context that do not overburden the wearer is feasible. This can be achieved by developing a confidence display system where prompts are shown briefly and then fade out, ensuring they do not disrupt normal conversation flow. The prototype in `TranscriptLab` can provide initial testing ground to develop this behavior.

## Phone/Cloud Boundary

- **Feasible Now**: Keeping the phone as the primary runtime for heavy processing aligns with current constraints. The existing setup allows for basic memory and confidence tracking on the phone, which can be enhanced through iterative improvements in `TranscriptLab`. This approach respects the V1 architecture direction of phone-first processing.

## Implementation Grounding

- **Feasible Now**: The reality-check process is grounded in concrete implementation efforts such as `TranscriptLab` and `Shared Transcript Notes`. These provide clear paths for further development. For example, refining subtitle placement through visual hierarchy can be done by iterating on `LiveTranscriptTestView.swift`.

## Core Deepening

- **Feasible Now**: The focus on improving core aspects like subtitle quality, memory trust, confidence display, and low-friction UX is aligned with the current project direction of core deepening. These improvements will strengthen the system's daily-use value without introducing unnecessary complexity.

## Constraint Pressure

- **Feasible Later/Assumptions Needing Evidence**: While surface-level battery and thermal constraints are not currently a bottleneck (since early versions are phone-first), deeper exploration into long-term battery management for always-on features may be necessary. For now, this is an assumption needing more evidence to determine feasibility.

## Drift Risks

- **Feasible Now**: The current direction focuses on core improvements and avoids broad feature sprawl, which helps mitigate the risk of drift towards unnecessary complexity. This focus will keep the project aligned with its mission statement.

## Non-Negotiables

- **Feasible Now**: The non-negotiable constraints such as frame-touch-only interaction and phone-first processing are being respected in V1 development efforts. These constraints ensure that early versions remain usable and avoid premature speculation on more complex interactions or hardware capabilities.

In summary, the current direction of focusing on core improvements like subtitle clarity, memory trust, and low-friction assistance is feasible now based on the existing prototype setup and clear implementation paths provided by `TranscriptLab`. However, deeper exploration into long-term battery management remains an assumption needing evidence for future feasibility.
