# Reality Check for SmartGlasses Core Field

## Subtitle Clarity (Real-time subtitle clarity)

- **Current Status:** Feasible now  
- **Rationale:** The `TranscriptLab` app provides a clear path to real-time subtitles. Given that the build summary indicates successful runs and no errors, it is feasible to implement and continuously refine this feature in V1. The primary constraint here will be ensuring subtitles remain readable and stable during live conversation without causing visual fatigue or distraction.

## Memory Trust (Trustworthy memory support)

- **Current Status:** Feasible now  
- **Rationale:** The system can start with basic face/name recall mechanisms that rely on cloud storage for reinforcement learning. Since the current version is phone-first, it can leverage the existing TranscriptLab app to test and iterate on confidence display and memory lookup behavior. The key constraint here will be ensuring any stored information is handled securely and transparently.

## Low-friction Assistance (Low-friction assistance)

- **Current Status:** Feasible now  
- **Rationale:** The V1 interaction should focus on frame touches, which are already defined as the primary method for user control. One-line prompts can coexist with subtitles without overwhelming the wearer by carefully managing their placement and frequency. The main constraint here is ensuring that any additional prompts do not disrupt the wearer's natural flow of conversation.

## Frame-touch-only V1 Interaction

- **Current Status:** Feasible now  
- **Rationale:** The project explicitly states that V1 interaction should happen through frame touches only, so this constraint is already in place and does not need further elaboration. The main challenge will be ensuring that the frame touch interactions are intuitive and useful without requiring too many physical inputs.

## Phone-first Runtime

- **Current Status:** Feasible now  
- **Rationale:** Given the current setup with `TranscriptLab` as a test bed, it is feasible to keep heavy processing on the phone for V1. The cloud can be used selectively where clear value is added and latency remains acceptable. The main constraint here is battery management, especially during always-on features like subtitle generation.

## Core-deepening Over Sprawl

- **Current Status:** Feasible now  
- **Rationale:** Since the current mode is focused on core deepening, it is appropriate to prioritize improvements in subtitle quality, memory trust, and visual UX over broad feature expansion. The main challenge will be ensuring that any new features or changes do not detract from the core mission.

## Core Deepening vs Constraint Pressure

- **Current Status:** Feasible now  
- **Rationale:** While the project should focus on core deepening, it is still important to surface constraints early. The `v1_real_world_limits.md` document provides clear guidance on hardware and battery limits, which need to be continuously monitored.

## Visual Hierarchy

- **Current Status:** Feasible now  
- **Rationale:** The visual hierarchy should be designed with the wearer's experience in mind, ensuring that subtitles are easily readable while minimizing distractions. Given the emphasis on low-friction assistance, the design must balance clarity and utility without overwhelming the user.

## Confidence Display

- **Current Status:** Feasible now  
- **Rationale:** The confidence display needs to be clear and transparent. The main constraint will be ensuring that the confidence display does not create unnecessary cognitive load.
