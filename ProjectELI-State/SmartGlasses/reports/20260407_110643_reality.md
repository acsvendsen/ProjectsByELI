# Reality Check

## Subtitle Clarity: Feasible Now
- **Subtitle Placement:** The glasses should use a clear, stable display that minimizes distraction while maximizing readability. Given the current focus on real-time clarity and the available hardware (display only), subtitle placement can be optimized through visual design tweaks.
- **Feasibility:** V1 should aim for subtitles that are readable in motion and noise. Early tests with `TranscriptLab` will provide data to refine this further.

## Memory Trust: Feasible Now
- **Face/Name Recall:** Implement face/name memory using a simple caching mechanism on the phone, updating as new interactions occur.
- **Confidence Representation:** Use a label-only approach for initial V1. This can evolve into more complex confidence indicators as needed based on user feedback and testing with `TranscriptLab`.
- **Feasibility:** Memory should be lightweight initially, focusing on clear reinforcement rules that do not introduce unnecessary privacy concerns.

## Low-Friction Assistance: Feasible Now
- **One-Line Prompts:** Deliver short, relevant prompts to help the wearer understand conversations better. Avoid overloading with information.
- **Visual Hierarchy:** Design subtitle and prompt visual hierarchy so they are easily distinguishable yet unobtrusive.
- **Feasibility:** Early V1 should focus on simplicity, ensuring that assistance is helpful without causing social awkwardness or confusion.

## Privacy vs Usefulness: Feasible Now
- **Memory Implementation:** Ensure memory recall respects user privacy by avoiding overconfidence and using clear uncertainty signals. This can be tested through interactions in `TranscriptLab`.
- **Confidence Display:** Label-only confidence display minimizes privacy risks while providing useful feedback.
- **Feasibility:** Early V1 should prioritize usefulness without invading privacy, ensuring that any data retained is necessary for functionality.

## Latency vs Richness: Feasible Now
- **Subtitle Clarity:** Use the `TranscriptLab` to fine-tune subtitle clarity and stability. This will help in balancing real-time responsiveness with visual quality.
- **Memory Recall:** Implement basic memory recall functions that can be tested for latency in `TranscriptLab`.
- **Feasibility:** V1 should focus on delivering clear, stable subtitles and fast memory recall without overcomplicating the system.

## Discreet UX vs Visual Clarity: Feasible Now
- **Subtitle Design:** Ensure subtitles are designed to remain unobtrusive while still being readable in noisy environments.
- **Prompt Design:** Prompts should be short, clear, and visually distinct from subtitles.
- **Feasibility:** V1 should use simple, effective visual design that respects user privacy and enhances usability.

## Interaction Constraints: Feasible Now
- **Frame Touches Only:** Focus on developing frame-touch interaction methods to ensure simplicity and ease of use.
- **V1 Design Assumptions:** Do not incorporate voice commands or complex multimodal interactions until explicitly directed otherwise.
- **Feasibility:** V1 should strictly adhere to the frame-touch-only design constraint, ensuring that any new feature is consistent with this primary user interface.

## Phone/Cloud Boundary: Feasible Now
- **Phone Processing:** Use phone-first processing for initial subtitle and memory functions. Cloud integration can be optional where clearly justified.
- **V1 Implementation:** Ensure all V1 features are implemented primarily on the phone to maintain simplicity and avoid unnecessary cloud dependency.
- **Feasibility:** Early V1 should rely heavily on local processing, with minimal reliance on cloud services.

## Summary
Given the current constraints and priorities outlined in the project inputs, the proposed directions for subtitle clarity, memory trust, low-friction assistance, privacy vs usefulness, latency vs richness, discreet UX vs visual clarity, interaction constraints, and phone/cloud boundary are all feasible now. These efforts should focus on core deepening improvements while respecting the hard-coded V1 constraints.
