### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states will enhance the wearer's trust in the subtitles, making them more reliable and easier to follow during live conversations.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence subtitles (e.g., names of people already seen multiple times) and another for low-confidence subtitles (e.g., new faces or names).

3. **Likely payoff**

   By clearly distinguishing between highly confident and less confident subtitles, the system will provide more accurate support to the wearer, reducing cognitive load and increasing trust in the subtitles.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer can trust the system's assistance, which is crucial for maintaining the core attractor of "memory_trust." A well-designed confidence format reinforces the reliability of memory support and prevents any misleading certainty.

2. **What small change unlocks it**

   Define a confidence format that uses a numeric score combined with a label and a short reason to explain the certainty level. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'.

3. **Likely payoff**

   A clear and concise confidence format will enhance the wearer's trust in memory support, reducing perceived uncertainty and increasing the reliability of the system during critical interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Memory policy improvements ensure that the system's ability to recall names, faces, and prior context remains trustworthy and useful without creating unnecessary privacy concerns or overloading the user with irrelevant information.

2. **What small change unlocks it**

   Define a local memory cache threshold for storing face and name recognition results on the phone. This limits the amount of data stored while ensuring that frequently encountered individuals are always recalled correctly.

3. **Likely payoff**

   By setting a clear, manageable limit on the number of entities cached locally, the system can provide reliable memory support without consuming excessive storage or battery resources. This enhances trust and practicality in noisy environments where quick recall is crucial.

4. **Immediate next probe**

   Define one local-cache size limit for storing frequently encountered faces and names, ensuring that the cache does not exceed 50 entries at any time.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing stays local to the phone minimizes latency and thermal load, preserving real-time clarity and trust. This focus on local processing also aligns with the project's constraint of always-on sensing while keeping within battery limits.

2. **What small change unlocks it**

   Define a clear boundary where all subtitle-related processing happens locally unless explicitly flagged for cloud fallback. For example, set a policy that any subtitle generated or updated in real-time must run on the phone first before considering a cloud fallback.

3. **Likely payoff**

   By keeping subtitle processing local, we ensure that subtitles remain stable and responsive, enhancing the wearer's trust in the system during live interactions. This reduces the risk of dropped frames or delayed text updates, which could otherwise disrupt the conversation flow.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line prompts helps maintain the wearer's focus on critical information, reducing cognitive load and improving overall usability. By prioritizing subtitle clarity over minor distractions from one-line support, we enhance the wearer's ability to follow the conversation, thereby deepening the core mission of helping the wearer understand better in noisy environments.

2. **What small change unlocks it**

   Define a visual hierarchy rule that routes subtitles to the primary display area and suppresses or hides one-line prompts during active speech. This ensures subtitles remain the highest priority for readability and comprehension.

3. **Likely payoff**

   By prioritizing subtitles, we reduce visual distractions during live conversations, making the system more effective in noisy environments. This clarity can significantly improve user trust and satisfaction, aligning with the core mission of helping wearers understand better without creating unnecessary command overhead or social awkwardness.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
