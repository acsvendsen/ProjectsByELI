### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules will enhance the wearer's ability to read subtitles clearly and quickly without distraction. This directly supports the primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**
   Define two subtitle placement rules: one for low-confidence states (when the system is less certain) where subtitles should be displayed in a larger, more prominent position on the screen, and another for high-confidence states where subtitles can be smaller but still visible.

3. **Likely payoff**
   By making subtitles easier to read during uncertain times, the wearer will trust the system more, which aligns with our core attractor of real-time subtitle clarity. This will also reduce cognitive load in noisy or challenging environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring a stable cache size for face/name memory helps maintain consistent performance and reduces latency during live interactions. By setting a fixed local cache threshold, we can avoid frequent cloud requests, which helps in reducing battery drain and ensuring low-latency responses.

2. **What small change unlocks it**

   Define a maximum local cache size of 50 entries (e.g., names, faces) for face/name memory on the phone. This limits the amount of data stored locally to ensure that only relevant and recent memories are cached.

3. **Likely payoff**

   A fixed local cache size will provide several benefits:
   - Reduced cloud requests, leading to lower battery usage.
   - Consistent performance in live interactions due to faster memory lookups.
   - Enhanced privacy by keeping less data on the phone.

4. **Immediate next probe**

   Set a local cache size limit of 50 entries for face/name memory objects on the phone.
