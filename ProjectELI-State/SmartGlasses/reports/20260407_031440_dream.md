### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules in V1 will enhance the wearer's trust in real-time subtitles, making them more readable and less distracting. This improvement is crucial for maintaining clarity and stability during live conversations.

2. **What small change unlocks it**
   Define two subtitle placement modes: a fixed position mode that keeps subtitles at the bottom of the frame but allows them to adjust slightly based on head movement; and a fallback mode that moves subtitles out of the way if they overlap with important visual content like faces or text.

3. **Likely payoff**
   By defining these placement rules, we can ensure that subtitles remain visible and readable while minimizing distractions during conversations. This will improve overall user trust and satisfaction, aligning better with our core attractor of real-time subtitle clarity.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the system's assistance, enhancing overall reliability and user confidence. By clearly showing the certainty level of the memory and subtitles, the system maintains a balance between providing useful information and avoiding overconfidence or under-confidence.

2. **What small change unlocks it**

   Define one simple yet informative confidence label plus short reason format for both subtitle and memory entries. This involves choosing labels like "High," "Medium," or "Low" combined with reasons such as "Seen recently," "Weak match," or "Name heard once."

3. **Likely payoff**

   By implementing a clear and concise confidence display, the system can significantly reduce user skepticism and increase trust. This improvement will help users better understand when to rely on the system's suggestions and when they might want to seek additional confirmation.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local memory threshold for face/name recall, we ensure that the system remembers new individuals confidently and reduces the risk of incorrect or forgotten recollections. This helps maintain trust in the memory support feature while keeping the phone's storage requirements reasonable.

2. **What small change unlocks it**

   Define a specific number of recent interactions to be cached locally on the phone as high-confidence face/name memories, with less frequent encounters stored only temporarily or not at all.

3. **Likely payoff**

   This approach will reduce memory overhead while ensuring that key individuals are consistently remembered and recalled reliably. It also helps in balancing privacy concerns by limiting data retention without compromising functionality.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains phone-local optimizes battery life and thermal management, which are critical for always-on functionality in noisy environments where subtitles are most needed.

2. **What small change unlocks it**

   Define a rule to keep subtitle rendering entirely on the phone, with no fallback to the cloud for real-time transcript processing.

3. **Likely payoff**

   By keeping subtitle processing local, we reduce thermal and power strain, ensuring that the glasses remain comfortable and usable in extended sessions without draining the battery or overheating.

4. **Immediate next probe**

   Define one rule that keeps all live subtitle rendering phone-local for V1, with no cloud fallback.
