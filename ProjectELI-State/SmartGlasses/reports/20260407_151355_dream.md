### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain clear, readable, and stable enough to be trusted in live conversation. Stable subtitle placement reduces cognitive load on the wearer, allowing them to focus more on the interaction rather than constantly adjusting their gaze or attention.

2. **What small change unlocks it**

   Define three fixed subtitle placement rules for different confidence states: high-confidence subtitles always above visual content, medium-confidence subtitles at the bottom of the screen, and low-confidence subtitles in a dimmed state that only appear when explicitly requested by the wearer through frame touches.

3. **Likely payoff**

   By defining clear placement rules, the system will reduce cognitive overload for the wearer, ensuring that high-priority information is always visible without distraction. This improves trust in the subtitle accuracy and enhances the overall user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring a clear and consistent confidence display helps maintain the wearer's trust in the system's reliability. By refining how confidence is shown, we can better convey when the system is certain about its information versus when it needs more context or verification.

2. **What small change unlocks it**

   Define a simple numeric score + label + short reason format for confidence objects. This format ensures that users can quickly grasp the level of certainty and the basis for it without overwhelming them with complex explanations.

3. **Likely payoff**

   A well-defined confidence display will help in building trust by making the system's uncertainty explicit, thus preventing the wearer from over-relying on uncertain information. It also enables the system to provide more targeted assistance that is appropriate given its current level of certainty.

4. **Immediate next probe**
   - Define the score format for confidence display as 0.85.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By optimizing local memory thresholds for face/name recall, we can ensure that the system maintains a balance between rich memory support and fast lookup, without overloading the phone's storage or creating unnecessary privacy concerns. This will help in delivering trustworthy memory support while keeping the assistive behavior discreet and useful.

2. **What small change unlocks it**

   Define one local-memory threshold policy for face/name recall that limits cache size based on recency and frequency of encounters. For example, keep recent and frequently encountered faces/names in a smaller cache, with less frequent ones being evicted after a certain period.

3. **Likely payoff**

   Implementing this memory threshold will allow the system to maintain a good balance between rich context support and battery efficiency. It will ensure that common names and faces are quickly accessible while minimizing storage usage, which is crucial for real-time performance and user trust.

4. **Immediate next probe**

   Set a local-cache size limit of 20 entries for frequent face/name encounters to balance memory richness and battery/thermal constraints.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that subtitles remain fast and reliable. This reduces latency and preserves the real-time nature of the subtitles, which is crucial for maintaining trust and usability.

2. **What small change unlocks it**

   Define one task-specific phone-cloud fallback boundary for live subtitle processing. This involves setting a rule such as: "Live subtitles should be processed on-device unless there's a significant drop in accuracy or if the audio quality degrades too much."

3. **Likely payoff**

   By keeping subtitle processing local, we reduce latency and ensure that the subtitles are always readable and stable. This enhances trust and usability, making the glasses more effective in noisy environments where real-time understanding is critical.

4. **Immediate next probe**

   Define one task-specific phone-cloud fallback boundary for live subtitle processing based on accuracy and audio quality metrics.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear and stable visual hierarchy between subtitles and one-line support helps maintain low-friction assistance by preventing overload or distraction. By defining rules for coexistence, the system can deliver necessary information without overwhelming the wearer, thus reinforcing trust and usability.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule that favors subtitles in high-confidence scenarios while allowing one-line support to appear when confidence is lower but still relevant.

3. **Likely payoff**

   This change will enhance the visual clarity of the interface, ensuring that critical information (subtitles) remains prominent and readable, even during fast-paced interactions. It will reduce cognitive load by minimizing distractions and providing just-in-time assistance without overburdening the wearer with unnecessary prompts.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
