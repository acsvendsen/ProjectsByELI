### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states ensures that subtitles remain readable and unobtrusive while maintaining trust in live conversations. This is crucial for the core mission of providing real-time, clear, and stable subtitle assistance.

2. **What small change unlocks it**

   Define three specific subtitle placement rules: one for high-confidence text (e.g., names and faces), another for medium-confidence text (e.g., context and partial memories), and a third for low-confidence text (e.g., less certain face or name mentions).

3. **Likely payoff**

   By defining clear placement rules, the system will reduce visual clutter, maintain readability in various contexts, and enhance overall trust in the subtitle accuracy during live interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format helps ensure that the wearer understands when the system is certain versus uncertain about a piece of information. This directly supports the core attractor of real-time subtitle clarity and memory trust by making the system's level of certainty more transparent to the user.

2. **What small change unlocks it**

   Define one confidence format candidate for V1 that includes a numeric score, label, and short reason. For example: "score 0.89 + 'High' + 'Seen recently in this conversation'".

3. **Likely payoff**

   By making the system's certainty more explicit through clear labels and concise reasons, users will be able to better trust the subtitles and memory support they receive. This reduces cognitive friction by ensuring that when a name or context is recalled incorrectly, the wearer knows it might not be accurate.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache size and eviction policy ensures that the system can efficiently store and retrieve frequently used names and faces without overwhelming local storage, thereby maintaining trust and providing reliable support to the wearer.

2. **What small change unlocks it**

   Define a simple cache policy that retains recently seen entities for 10 minutes before evicting them, with an additional eviction based on least recently used (LRU) strategy.

3. **Likely payoff**

   By implementing a clear and efficient memory cache, the system can ensure that names and faces are reliably remembered and quickly recalled, enhancing the trustworthiness of name recall functionality and reducing the likelihood of missed interactions due to memory lapses.

4. **Immediate next probe**
   - Set a local cache size limit of 20 entities for V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud for live subtitle processing, we ensure that the glasses remain lightweight and socially acceptable while still providing high-quality real-time subtitles. This helps in maintaining the core attractor of real-time subtitle clarity without overloading the glasses hardware.

2. **What small change unlocks it**

   Define a specific task boundary: live subtitle processing should be handled phone-first, with cloud fallback only for very complex or uncertain scenarios that require richer processing capabilities.

3. **Likely payoff**

   By keeping live subtitle processing on-device, we reduce battery and thermal load on the glasses, ensuring more stable performance in noisy environments. This enhances the core attractors of real-time subtitle clarity and low-friction assistance without making the glasses overly complex or resource-intensive.

4. **Immediate next probe**

   Define one phone-first subtitle processing task boundary where live subtitles are generated locally with cloud fallback for edge cases.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain focus on the most critical information while reducing cognitive overload. This balance enhances trust by making sure the wearer can easily distinguish essential live subtitles from supplementary contextual prompts, thus improving overall usability.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule where subtitles are always prioritized for display precedence and prominence unless the one-line support provides critical context that cannot be delayed. This rule ensures that subtitles remain visible even if the one-line support is suppressed temporarily to avoid visual clutter.

3. **Likely payoff**

   By maintaining clear visibility of live subtitles while appropriately suppressing or coexisting with one-line prompts, the system can enhance trust and usability. The wearer will be more confident in relying on the glasses for critical information, leading to better engagement and understanding in noisy environments.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
