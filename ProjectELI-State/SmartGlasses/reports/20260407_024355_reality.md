# Reality Check

## Subtitle Clarity: Feasible Now
- **Reasoning**: The current `TranscriptLab` app provides a live transcript test bed that can validate subtitle clarity in real-time environments. Given the success of the recent build (no errors or warnings), we have a working framework to iteratively improve subtitle rendering and stability.
- **Constraints**: Must stay within hardware limits, avoid battery drain, and ensure subtitles remain readable and stable during frame touches.

## Memory Trust: Feasible Later
- **Reasoning**: The memory trust aspect is more complex due to the need for reliable face/name recall with clear uncertainty handling. This can be addressed as we gather more data through real-world usage of `TranscriptLab` and integrate it into a phone runtime that talks to glasses hardware.
- **Constraints**: Battery and thermal limits, latency requirements, and privacy perception must be managed carefully.

## Low-Friction Assistance: Feasible Now
- **Reasoning**: Implementing simple one-line prompts can be done using the existing `TranscriptLab` setup. This aligns with the V1 interaction constraints of frame touches only.
- **Constraints**: Must ensure that these prompts do not overload the wearer and remain socially acceptable.

## Constraints: Surface Early
- **Battery and Thermal Limits**: The current build has succeeded, but we must continue to monitor battery usage in `TranscriptLab` tests to ensure we stay within safe limits.
- **Latency**: Real-time subtitle clarity is feasible now with `TranscriptLab`, but any additional processing should be carefully managed to avoid latency issues.
- **Privacy Perception**: The initial implementation of memory support can focus on clear uncertainty handling without overly invasive behavior.

## Interactions: Frame Touches Only
- **Reasoning**: Given the current constraint, all interactions should remain frame touches for V1. Implementing voice commands would be premature and speculative at this stage.
- **Constraints**: Adhering to the `frame_touch_only_v1` constraint ensures we do not introduce unnecessary complexity.

## Phone/Cloud Boundary: Core Deepening
- **Reasoning**: Early versions should rely heavily on phone processing with cloud optional where clearly justified. The current `TranscriptLab` setup can be further refined to better simulate glasses behavior.
- **Constraints**: Must keep the initial focus on real utility without overcomplicating the architecture.

## Visual Hierarchy: Feasible Now
- **Reasoning**: Implementing simple subtitle placement and visual hierarchy using `TranscriptLab` is feasible. We can start with a clean layout that remains socially acceptable while being readable in motion and noise.
- **Constraints**: Ensure subtitles are positioned well to avoid distraction and remain readable during live conversations.

## Summary of Feasibility
- **Subtitle Clarity**: Feasible now, based on the current setup.
- **Memory Trust**: Feasible later, as it requires more data collection and refinement.
- **Low-Friction Assistance**: Feasible now, with a focus on simple one-line prompts.
- **Constraints and Interactions**: Surface early and manage carefully to ensure V1 constraints are respected.

## Assumptions Needing Evidence
- The current `TranscriptLab` setup is sufficient for initial subtitle clarity testing. However, more evidence is needed to ensure memory support is reliable and trustworthy in real-world scenarios.
- The visual hierarchy and subtitle placement should be validated through user feedback before finalizing the design.
