### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the clarity and readability of subtitles, making them more reliable for live conversation support. By setting stable and unobtrusive subtitle positions, we ensure that subtitles do not distract the wearer while still providing essential context. This improvement helps in maintaining the balance between providing useful information and avoiding distraction.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule based on the confidence level of the speaker. For example, if the system is 90% certain about who is speaking (high confidence), place the subtitles at the bottom center; for medium confidence (75-89%), place them slightly to the side; and for low confidence (below 75%), show a prompt in a neutral area.

3. **Likely payoff**

   Implementing these fixed subtitle placement rules will likely result in more stable and readable subtitles, reducing cognitive load during live conversations. This improvement can significantly enhance the wearer's understanding without causing visual distractions, thereby increasing trust and daily-use value.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide a clear and concise representation of certainty, the system can maintain trust while ensuring that the wearer is not overwhelmed with too much information. This helps in balancing the need for rich contextual support without creating social awkwardness or cognitive overload.

2. **What small change unlocks it**

   Implementing a two-part confidence display: a numeric score (e.g., 0.84) combined with a label and short reason (e.g., "High" + "Seen recently"), which can be shown in the subtitle area when necessary. This format provides both precision and clarity without being intrusive.

3. **Likely payoff**

   The two-part confidence display will help build trust by showing the wearer that the system is not guessing or over-relying on assumptions. It will also allow the wearer to quickly understand the reliability of the information provided, thereby enhancing their understanding and comfort with the assistant.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache size helps ensure that relevant names and faces are stored long enough to be useful for quick recall and reinforcement over time, enhancing the wearer's understanding and trust in the system.

2. **What small change unlocks it**

   Define a local cache threshold for storing name and face memory on the phone, ensuring that frequently encountered individuals are retained for at least 10 minutes after last interaction before being evicted to maintain performance without overwhelming memory storage.

3. **Likely payoff**

   By setting a reasonable retention period for names and faces, the system can provide faster and more reliable recall, reducing the need for frequent lookups and improving overall confidence in memory support.

4. **Immediate next probe**

   Define one local cache eviction rule for storing name and face memory on the phone, with a minimum retention time of 10 minutes after last interaction before eviction to balance performance and utility.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that critical processing happens on-device while leveraging remote resources only when necessary. This approach enhances privacy and reduces latency, aligning with the core attractors of real-time subtitle clarity and memory trust.

2. **What small change unlocks it**

   Introduce a specific rule: For live subtitle processing, all computations should remain phone-local to ensure sub-second response times. Only for memory archive sync or conversation snapshot upload should cloud fallback be used when local storage is full or during initial setup.

3. **Likely payoff**

   This decision will help maintain real-time subtitle clarity by keeping all subtitle processing on-device and minimize latency, thus reinforcing the trust of the wearer in the system's responsiveness. It also ensures that personal memory data remains secure and private, as no such data should be sent to the cloud unless absolutely necessary.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support helps maintain a clear and uncluttered display, ensuring that the wearer can easily focus on the most relevant information without distractions. This enhances the low-friction assistance attractor by making the product more usable in noisy environments.

2. **What small change unlocks it**

   Define a visual hierarchy rule where subtitles are prioritized over one-line prompts when confidence is high, but both are displayed coexisting with clear distinction when confidence is lower.

3. **Likely payoff**

   By clearly distinguishing between high-confidence subtitles and one-line prompts, the wearer can more easily focus on key information during conversations. This reduces cognitive load and social awkwardness, aligning better with the core attractors of real-time subtitle clarity and low-friction assistance.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
