### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states ensures that subtitles remain clear and stable, enhancing trust and readability in live conversations. This is crucial for real-time subtitle clarity (subtitle_clarity) as it directly impacts how well the wearer can follow the conversation without distraction.

2. **What small change unlocks it**

   Define two to three subtitle placement rules for different confidence states: high-confidence subtitles always visible, medium-confidence subtitles visible with a delay, and low-confidence subtitles hidden or shown only on user request.

3. **Likely payoff**

   By having clear rules for subtitle visibility based on confidence, the system can maintain a balance between providing necessary assistance and avoiding overloading the wearer’s visual field. This improves trust in the subtitles and ensures that critical information is always visible when needed most.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache size and eviction rules directly enhances the trustworthiness and reliability of name and face recall in live conversations. By optimizing how new and old evidence are stored and accessed, we can ensure that likely new people are remembered confidently while maintaining a clean and uncluttered memory cache.

2. **What small change unlocks it**

   Define one specific eviction rule based on recency: If an entity has not been seen for more than 30 seconds, its associated cache entry should be evicted to make room for newer evidence.

3. **Likely payoff**

   This change will help in reducing memory bloat while ensuring that the system remains responsive and accurate. By keeping only recently seen entities, we can enhance the trust in new-person recognition without overloading the local cache.

4. **Immediate next probe**

   Set a recency-based eviction rule where cache entries are removed after 30 seconds of inactivity for any entity.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays on the phone versus what falls back to the cloud for transcript cleanup, we can ensure that the primary subtitle display remains smooth and responsive while leveraging cloud resources for more intensive processing tasks. This balance enhances real-time subtitle clarity and memory support, which are critical for achieving high daily-use value without overloading the glasses hardware.

2. **What small change unlocks it**

   Define a specific task-boundary rule: For live subtitle processing, keep transcript cleanup on the phone and only fallback to the cloud in cases of heavy load or when there is no local cache available.

3. **Likely payoff**

   By keeping real-time subtitle processing local, we can ensure that subtitles remain clear, stable, and responsive during critical interactions. Fallbacks to the cloud will be handled gracefully, ensuring that memory support and transcript cleanup are still effective without compromising the glasses' usability in noisy environments or during live conversations.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
