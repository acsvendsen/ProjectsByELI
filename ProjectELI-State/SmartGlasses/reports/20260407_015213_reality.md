# Reality Check

## Subtitle Placement: Feasible Now
- **Current State**: The core deepening mode favors subtitle quality improvements.
- **Constraints**: Glasses should remain lightweight and socially acceptable, with minimal local compute to avoid battery and thermal pressure. 
- **Assessment**: Given the current focus on real-time clarity and stability, implementing a simple yet effective subtitle placement can be feasible now. For instance, placing subtitles directly below the speaker’s face in the user's peripheral vision could enhance readability without causing distraction.

## Confidence Display: Feasible Now
- **Current State**: The system should provide timely help while avoiding overloading the wearer.
- **Constraints**: Early versions rely on phone processing and should not be overly complex. 
- **Assessment**: A simple label-based confidence display (e.g., "likely," "possibly") could be feasible now, with a short reason (e.g., "name seen before," "face recognized") to add clarity without overwhelming the wearer.

## Memory/Cache Policy: Feasible Now
- **Current State**: Face/name recall must expose uncertainty clearly and support context without pretense.
- **Constraints**: V1 should not rely on heavy on-glasses compute, with phone-first processing being dominant.
- **Assessment**: Implementing a basic cache policy where recently seen faces or names are stored locally can be feasible now. This helps in reducing cloud dependency while maintaining trust by clearly showing uncertainty.

## Phone/Cloud Boundary: Feasible Now
- **Current State**: Heavy processing should happen on the phone, with optional cloud support.
- **Constraints**: V1 interaction is frame-touch only; avoid speculative hardware complexity.
- **Assessment**: Designing a clear interface where phone-based memory lookup and confidence behavior are prominent can be feasible now. This ensures that the system remains lightweight and responsive.

## Visual Hierarchy: Feasible Now
- **Current State**: The UI should favor clarity over feature density.
- **Constraints**: V1 interaction is frame-touch only, with minimal local logic on glasses.
- **Assessment**: Prioritizing clear placement of subtitles and confidence displays can be feasible now. A simple hierarchy where subtitles are easily readable and confidence labels are prominent but unobtrusive could enhance the wearer's experience.

## Frame Touch Only V1: Feasible Now
- **Current State**: Interaction should happen through frame touches only.
- **Constraints**: Early hardware remains simple, with heavy processing on the phone.
- **Assessment**: Implementing a robust touch-based interaction system can be feasible now. Ensuring that all interactions are handled through intuitive frame touches will keep the system focused and user-friendly.

## Phone First Runtime: Feasible Now
- **Current State**: Heavy processing should primarily happen on the phone, with cloud optional.
- **Constraints**: V1 is phone-first, with minimal hardware dependencies.
- **Assessment**: Building a transcript test bed in `TranscriptLab` can be feasible now. This allows for continuous validation of real-time subtitle clarity and memory support without overloading glasses hardware.

## Core Deepening Over Sprawl: Feasible Now
- **Current State**: Focus on subtitle quality, memory trust, and visual UX.
- **Constraints**: Early versions should not introduce broad features or speculative hardware complexity.
- **Assessment**: Prioritizing core improvements such as better subtitle clarity and more reliable memory support can be feasible now. These improvements directly align with the current focus on core deepening.

## Likely Waste of Time: Constraint Pressure
- **Current State**: Surface battery, latency, privacy, and usability limits early.
- **Constraints**: V1 interaction is frame-touch only; avoid speculative hardware complexity.
- **Assessment**: While it's important to surface constraints early, exploring broad feature sprawl or speculative hardware complexities at this stage would likely be a waste of time. Focusing on concrete core improvements will help in identifying and addressing real-world limitations more effectively.
