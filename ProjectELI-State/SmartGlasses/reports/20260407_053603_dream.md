### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - By defining specific subtitle placement rules based on confidence states, V1 can maintain a balance between readability and distraction, ensuring that subtitles are always visible when needed but not overwhelming.

2. **What small change unlocks it**
   - Define 3 to 5 subtitle placement rules for different confidence levels: high (always visible), medium (visible with user touch or certain conditions), low (only shown on user touch).

3. **Likely payoff**
   - Improving subtitle visibility based on confidence will reduce cognitive load and enhance the wearer's understanding, while also maintaining a subtle and unobtrusive UX that respects battery and thermal constraints.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will ensure that the wearer can trust the subtitles and memory support more effectively. By refining how certainty is communicated, we can reduce misunderstandings and increase overall system reliability.

2. **What small change unlocks it**

   Define a simple yet clear confidence format: use a numeric score (e.g., 0-1), a label (e.g., High, Medium, Low), and a short reason (e.g., "Seen recently", "Weak match").

3. **Likely payoff**

   A well-defined confidence format will help the wearer understand the reliability of the subtitles and memory support more intuitively. This clarity can significantly reduce cognitive load and improve trust in the system.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory cache size ensures that frequently encountered faces and names are stored in a way that reduces latency and improves trust. By setting a threshold for what constitutes frequent encounters, the system can dynamically adjust its cache to prioritize recently seen individuals while still respecting privacy constraints.

2. **What small change unlocks it**

   Define a low-friction entity-linking rule where new evidence (e.g., seeing a face or name) is attached to an existing memory object with a high confidence level after a minimum of three encounters within one session. This rule allows the system to remember likely new people without requiring explicit user input.

3. **Likely payoff**

   By implementing this entity-linking rule, the system will better handle likely new-person memory automatically, reducing the need for manual reinforcement and improving overall trust in the memory component. The payback is a more seamless and reliable experience for the wearer, as their interactions with new people are remembered correctly without needing explicit user touches.

4. **Immediate next probe**

   Define one entity-linking rule for attaching new evidence to an existing person-memory object based on three encounters within a session.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs on the phone versus the cloud, we can ensure that V1 remains focused and lightweight while still delivering critical functionality. This helps maintain battery efficiency and privacy, ensuring that real-time subtitle clarity (subtitle_clarity) is not compromised by heavy cloud processing. Additionally, it aligns with the core mission of providing discreet, context-aware support without unnecessary complexity.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing to run entirely on the phone. For instance, set a rule that any live subtitle request must be processed locally within 500ms to avoid falling back to the cloud.

3. **Likely payoff**

   This ensures that subtitles remain clear and stable in real-time, which is critical for maintaining trust during conversations. It also reduces latency and conserves battery, making the system more reliable and user-friendly.

4. **Immediate next probe**
   - Define a rule that live subtitle processing must be completed locally within 500ms to avoid cloud fallback.
