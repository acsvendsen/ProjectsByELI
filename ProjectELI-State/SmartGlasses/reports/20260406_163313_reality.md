## Reality Check for SmartGlasses V1 Direction

### Feasibility Assessments Against Real-World Limits

#### Subtitle Placement: More Prominent (Selected)

**Feasible Now**
- **Justification:** Given the lightweight hardware constraint, more prominent placement can be achieved through subtle yet effective design choices like a slightly offset corner or edge display. This respects the need to remain socially acceptable and avoid distraction.
- **Constraints:** Ensure that the placement does not interfere with the wearer's natural field of view and does not cause discomfort from prolonged use.

#### Confidence Display: Label + Reason (Selected)

**Feasible Now**
- **Justification:** A simple label with a short reason for confidence can provide users with enough information to trust the system without overwhelming them. This aligns well with the low-friction UX requirement.
- **Constraints:** The display should be fast and reliable, given that any delay or failure could break user trust.

#### Memory/Cache Policy: Recency First (Selected)

**Feasible Now**
- **Justification:** A recency-first cache policy can help in managing memory efficiently without requiring extensive local storage. This respects the phone-first architecture where heavy processing is done off-glass.
- **Constraints:** Ensure that the system can quickly retrieve and update recent memories to maintain a high level of utility.

#### Phone/Cloud Boundary: Phone First (Selected)

**Feasible Now**
- **Justification:** Using the phone as the primary runtime for speech, context, memory lookup, and orchestration aligns with minimizing on-glasses computation. This approach balances utility with battery and thermal constraints.
- **Constraints:** Ensure that cloud dependencies are minimal or only used where they add clear value, such as complex model updates.

#### Visual Hierarchy: Subtitles Dominate (Selected)

**Feasible Now**
- **Justification:** Dominating the display with subtitles ensures that the primary function of the glasses is to provide real-time assistance. One-line prompts should be designed to complement this without overwhelming the wearer.
- **Constraints:** Ensure that one-line prompts are visually distinct from subtitles but still prominent enough to be useful.

### Assumptions Needing Evidence

1. **Subtitle Latency:**
   - **Current Direction:** Subtitles must feel near-real-time or trust breaks.
   - **Feasibility:** This is a hard constraint, and evidence needs to be gathered on how quickly the system can process audio input and display subtitles.

2. **Face/Name Memory Trust:**
   - **Current Direction:** New faces and names should be remembered with confidence objects and reinforcement over time.
   - **Feasibility:** Evidence is needed on the accuracy and reliability of face/name recognition in noisy environments, as well as the effectiveness of reinforcement learning techniques for memory.

3. **Battery Draw:**
   - **Current Direction:** Early versions should not depend on heavy on-glasses compute.
   - **Feasibility:** Detailed analysis is required to determine how much local processing can be done without significant battery drain.

4. **Thermal Pressure:**
   - **Current Direction:** Battery and thermals are major risks for always-on features.
   - **Feasibility:** Testing with prototype hardware is necessary to ensure that the glasses do not overheat during prolonged use, especially in scenarios requiring heavy processing.

5. **Privacy Perception:**
   - **Current Direction:** Face/name recall must expose uncertainty clearly.
   - **Feasibility:** User studies are needed to understand how users perceive and trust face/ name recognition technology in real-world settings.

6. **User Friction:**
   - **Current Direction:** The system should help the wearer understand better, not fake understanding.
   - **Feasibility:** Surveys or small-scale user tests can provide insights into the effectiveness of various design choices on user perception and trust.

- **Memory Policy & Confidence Display:** Feasible now with clear constraints.
- **Phone/Cloud Boundary:** Feasible now with focused off-glass processing.
- **Visual Hierarchy:** Feasible now with a prioritized display approach.
