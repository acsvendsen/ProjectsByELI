# Reality Check Summary for SmartGlasses Project

## Feasibility Assessments

### Subtitle Placement: feasible now
**Reasoning**: The TranscriptLab app provides a simple, reusable test bed that can help determine optimal subtitle placement without adding unnecessary complexity. Given the current focus on core deepening and real-time subtitle clarity, refining subtitle placement is within the realm of immediate feasibility.

### Confidence Display: feasible now
**Reasoning**: The shared transcript layer can be used to experiment with different confidence display formats (numeric score, label only, label + short reason) to find the best balance between clarity and simplicity. This aligns well with the current core-deepening focus on subtitle quality and trustworthiness.

### Memory/Cache Policy: feasible later
**Reasoning**: While initial testing can be done using simple cache policies within TranscriptLab, more complex memory caching strategies will require deeper integration with both phone and potential cloud components. Given the current constraints of a phone-first approach, this is best tackled after the core subtitle and confidence display improvements are in place.

### Phone/Cloud Boundary: feasible now
**Reasoning**: The TranscriptLab app already provides a clear separation between phone-side processing (speech transcription) and reusable UI components. This can be further refined to ensure that cloud dependencies are clearly defined and justified, aligning with the current focus on phone-first practicality.

### Visual Hierarchy: feasible later
**Reasoning**: Defining an optimal visual hierarchy for subtitles and confidence displays is complex and will require more detailed design work. It should be tackled after the core subtitle clarity and confidence display issues have been resolved to ensure that any visual changes are grounded in a solid functional foundation.

## Reality Rules Compliance

- **Core-deepening over sprawl**: Focus remains on improving subtitle quality, memory trust, and visual UX without broad feature expansion.
- **Constraint pressure**: Early hardware constraints mean heavy reliance on TranscriptLab for initial testing. This helps surface battery, latency, privacy, and usability limits quickly.
- **Implementation grounding**: Decisions are based on the current project inputs and repo files rather than generic advice.

## Reality Guardrails

- **Subtitle Placement**: Use TranscriptLab to experiment with different placements to find a balance between readability and distraction.
- **Confidence Display**: Experiment with display formats in TranscriptLab before considering more complex implementations.
- **Memory/Cache Policy**: Integrate simple caching strategies first, then revisit for richer capabilities later.
- **Phone/Cloud Boundary**: Ensure clear boundaries are maintained in the current implementation to support future cloud integrations where necessary.
- **Visual Hierarchy**: Address visual hierarchy after core functionality is well-defined and tested.

## Assumptions Needing Evidence
