### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules under different confidence states ensures that subtitles remain clear, readable, and stable enough to maintain trust in live conversations. By defining specific placement modes for high-confidence versus low-confidence scenarios, the system can avoid distracting the wearer with overly frequent or unstable subtitle updates.

2. **What small change unlocks it**

   Define a simple two-mode subtitle placement rule: fixed position for high-confidence subtitles and flexible but non-distracting movement for lower confidence subtitles.

3. **Likely payoff**

   This change will help maintain consistent and reliable subtitle delivery, reducing the risk of distraction or misplacement that could undermine trust in live interactions. The wearer can focus more on the conversation, knowing they have reliable support when needed.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving the confidence display format ensures that the wearer can quickly understand the certainty behind memory recall and subtitles, which is crucial for maintaining trust in the system's assistance.

2. **What small change unlocks it**

Define a confidence object that combines a numeric score with a label and a short reason for the score. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

This change will provide the wearer with clear, concise, and trust-building information about the certainty of memory recall and subtitles. It will help in situations where the system might need to downplay its confidence due to noise or uncertainty, thus maintaining a balance between assistance and honesty.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local memory threshold for face and name recall, the system can ensure that critical information is readily available to the wearer without overwhelming the cache with less relevant data. This improves the overall trustworthiness of the memory support feature by maintaining a balance between rich context and fast lookup.

2. **What small change unlocks it**

   Define a local cache size limit for face and name recall, ensuring that only recent and frequently encountered entities are retained in the cache to avoid cluttering the memory subsystem with less relevant data.

3. **Likely payoff**

   By limiting the cache size to retain only recently seen faces and names, the system can provide faster, more reliable access to commonly recalled information, enhancing the overall trustworthiness of the memory support feature without consuming excessive local storage resources.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   - By optimizing which tasks are handled locally on the phone versus falling back to the cloud, we can ensure that subtitle processing is always fast and reliable in real-time. This reduces latency and ensures that the wearer receives clear and timely assistance, which directly supports the primary attractor of "Real-time subtitle clarity."

2. **What small change unlocks it**
   - Define a single task boundary where live subtitle processing remains local to the phone. For example, prioritize live subtitle rendering for the current conversation in real-time without cloud fallback.

3. **Likely payoff**
   - By keeping live subtitle rendering local, we can significantly reduce latency and ensure that subtitles are delivered at near-real-time speeds, enhancing the wearer's trust and understanding during conversations. This directly supports the core attractor of "Real-time subtitle clarity" by ensuring a smooth and uninterrupted user experience.

4. **Immediate next probe**
   - Define one task-specific cloud fallback boundary for live subtitle processing, ensuring that all real-time rendering remains local to the phone.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we can ensure that the wearer is not overloaded with information while still receiving necessary assistance in real-time. This improves the overall user experience by maintaining focus on critical information.

2. **What small change unlocks it**

   Define a single rule for subtitle vs one-line support precedence based on confidence level: prioritize subtitles when confidence is high and one-line prompts when confidence is medium or low, ensuring that critical information is always visible without clutter.

3. **Likely payoff**

   This visual hierarchy will reduce cognitive load by keeping the most important information in view, enhancing the wearer's ability to follow conversations while reducing distractions from less crucial prompts. It also aligns with the core attractors of real-time subtitle clarity and low-friction assistance.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
