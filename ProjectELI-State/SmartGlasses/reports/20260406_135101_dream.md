### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - By defining a clear memory cache size threshold for face/name recall, we ensure that the system retains key information while minimizing privacy concerns and managing battery consumption.

2. **What small change unlocks it**
   - Define one local-cache size limit for storing likely new faces and names.

3. **Likely payoff**
   - This will help in balancing memory utility with privacy by ensuring that only frequently encountered or recently seen people are cached, thus reducing the risk of storing unnecessary information.

4. **Immediate next probe**
   - Define a local cache size threshold of 5 to 10 likely new faces and names for V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   - Ensuring that critical memory objects like face/name recall are cached locally reduces latency, which is crucial for maintaining trust and real-time responsiveness.

2. **What small change unlocks it**
   - Define a local cache eviction policy based on recent interaction history to keep key entities (like frequently seen faces or names) in local storage while evicting less relevant data.

3. **Likely payoff**
   - This will significantly reduce the latency for memory lookups, making face and name recall faster and more reliable during interactions.

4. **Immediate next probe**
   - Define criteria for a local cache eviction policy that keeps frequently used face and name data on the device and offloads less relevant data to the cloud when needed, based on recent interaction history.
