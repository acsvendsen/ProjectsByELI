### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement stability enhances the wearer's trust in the system. By ensuring subtitles remain visible and clear even during rapid head movements or background noise, the system can provide more reliable real-time assistance. This strengthens the core attractor of "Real-time subtitle clarity" by making the subtitles a dependable reference for the wearer.

2. **What small change unlocks it**

   Define 3 to 5 fixed subtitle placement rules based on confidence levels: high-confidence (always visible), medium-confidence (visible with slight head movements), and low-confidence (faded or hidden until confirmed). This approach balances visual clarity with non-intrusiveness.

3. **Likely payoff**

   By implementing these fixed placement rules, the system will reduce subtitle visibility issues during dynamic head movements and noisy environments. This improves overall trust in the subtitles, making them a more reliable reference for the wearer. The wearer can focus on the conversation without constantly adjusting their gaze to read subtitles, enhancing the flow of interaction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format directly enhances the trustworthiness and clarity of subtitle delivery. A well-crafted confidence label, short reason, and score will help users understand the reliability of the subtitles in real-time, which is crucial for maintaining their engagement and focus during conversations.

2. **What small change unlocks it**

   Define a concise and clear format for confidence objects that includes both a numeric score and a descriptive label with a short reason. For example: "score 0.9 + 'High' + 'Seen recently'".

3. **Likely payoff**

   By providing users with explicit and understandable confidence information, the system can build trust over time. Users will feel more confident in relying on the subtitles for their understanding, which can lead to better overall user satisfaction and continued use of the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Memory caching policies that define how much local memory to keep for names and faces benefit the core by ensuring fast recall and reinforcement over time, which is crucial for building trust in the system's ability to remember important information. This helps maintain a balance between privacy and usefulness by allowing the system to support the wearer without excessive data retention or processing.

2. **What small change unlocks it**

   Define a local cache size limit that caps the number of name and face memories stored on the phone, with a default threshold set at 10 most recent entries. This simple cap ensures that memory storage remains manageable while still providing strong support for frequently encountered people.

3. **Likely payoff**

   By setting a clear limit on the amount of local memory, the system can prioritize the most relevant and recently interacted-with individuals, reducing battery usage and simplifying memory management. This leads to faster lookups and more reliable face/name recall during conversations, enhancing trust in the system's memory capabilities.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud processing for live subtitle rendering, we ensure that subtitles remain fast and stable enough to be trusted in real-time interactions. This helps maintain high subtitle clarity while adhering to battery and thermal constraints.

2. **What small change unlocks it**

   Define a single task-specific boundary where face/name recall lookup always stays local on the phone. For all other tasks, determine if they can safely run locally or should rely on cloud fallbacks based on latency requirements.

3. **Likely payoff**

   By keeping critical real-time subtitle processing local, we reduce battery drain and ensure that subtitles remain smooth and readable in noisy environments. This improves the core attractor of real-time subtitle clarity while also respecting the hard constraint of lightweight glasses hardware.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are prioritized over one-line prompts in low-conflict situations helps maintain clarity and focus for the wearer. This improves the wearer's ability to understand live conversations without being overwhelmed by additional text.

2. **What small change unlocks it**

   Define a visual hierarchy rule that places subtitles ahead of one-line support when the confidence level is high but not critical enough to suppress all other prompts. For example, if the subtitle confidence is above 0.85, suppress one-line support; otherwise, allow both to coexist.

3. **Likely payoff**

   This change will reduce visual clutter in high-confidence scenarios, making subtitles more prominent and easier for the wearer to follow. It also ensures that critical information (subtitles) remains unobtrusive while still providing helpful context when needed (one-line support).

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
