# Reality Check Summary

## Subtitle Clarity: Real-time subtitle clarity (subtitle_clarity)
- **Feasible Now**: 
  - The `TranscriptLab` app is already providing a real-time transcript path, which is crucial for verifying subtitle clarity.
  - Given the simplicity of V1 interaction through frame touches, we can focus on ensuring subtitles remain readable and stable without causing distraction.

## Memory Trust: Trustworthy memory support (memory_trust)
- **Feasible Now**: 
  - The current implementation in `TranscriptLab` can start storing basic face/name data for fast lookup.
  - Implementing confidence objects to represent uncertain memory recall helps maintain trust. This can be done incrementally, ensuring that the system does not pretend certainty where it is unsure.

## Low-friction Assistance: Low-friction assistance (low_friction_assistance)
- **Feasible Now**: 
  - The `TranscriptLab` app already supports one-line prompts without heavy command overhead.
  - Ensure these prompts are brief and relevant, aligning with the low-friction requirement.

## Core Deepening vs. Sprawl
- **Core Deepening Over Sprawl**: 
  - Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion.
  - Concrete changes such as refining subtitle placement, enhancing confidence display, and optimizing memory caching are more valuable at this stage.

## Privacy vs Usefulness (privacy_vs_usefulness)
- **Feasible Now**: 
  - Implement confidence objects to handle uncertainty in face/name recall without over-relying on invasive data collection.
  - Ensure that the system respects privacy by not pretending certainty where it is unsure, maintaining a balance between utility and respect for user boundaries.

## Latency vs Richness (latency_vs_richness)
- **Feasible Now**: 
  - The `TranscriptLab` app can focus on delivering timely help while keeping subtitle processing lightweight.
  - Ensure that real-time subtitles are prioritized, even if they might be slightly simplified to reduce latency.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Feasible Now**: 
  - Design subtitles and prompts with low visual clutter but ensure they remain readable.
  - Use best effort in `TranscriptLab` to test different subtitle placements and visual hierarchies that strike a balance between clarity and discreetness.

## Frame Touch-only V1 Interaction (frame_touch_only_v1)
- **Feasible Now**: 
  - Stick to frame-touch interactions for V1, avoiding assumptions about voice activation.
  - The `TranscriptLab` app is already set up to test this interaction model.

## Phone-first Runtime (phone_first_runtime)
- **Feasible Now**: 
  - Leverage the phone as the primary runtime for heavy processing while keeping glasses hardware simple.
  - Use the `TranscriptLab` app to validate this approach before moving to more complex interactions or hardware features.

## Visual Hierarchy and UX (visual_hierarchy)
- **Feasible Now**: 
  - Design subtitles and prompts with clear visual hierarchy in mind, ensuring they are readable without overwhelming the user.
  - Test different visual layouts in `TranscriptLab` to find a balance that works best for real-time interaction.

### Assumptions Needing Evidence
- **Subtitle Placement**:
  - Further testing is needed to determine the most effective subtitle placement within `TranscriptLab`.
  
- **Confidence Display**:
  - The specific format (label only, label + short reason, or score + label) for confidence display needs more concrete evidence from user testing in `TranscriptLab`.

### Conclusions
The current implementation in `TranscriptLab` provides a solid foundation to test and improve core features such as subtitle clarity, memory trust, and low-friction assistance. The project should continue focusing on these areas while respecting the constraints of V1 interaction through frame touches and phone-first runtime.

By continuously iterating on `TranscriptLab`, we can ensure that the final product aligns with the core mission without unnecessary complexity or feature sprawl.
