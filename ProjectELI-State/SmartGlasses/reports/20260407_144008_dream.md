### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement that does not distract the wearer is crucial for maintaining their trust and attention during conversations. Stable placement rules help in making sure subtitles remain readable and do not blink or jump around, which can otherwise break concentration.

2. **What small change unlocks it**

   Define a default fixed subtitle position near the center of the glasses display, with minor adjustments based on head movement but minimal repositioning overall. This ensures that subtitles are always visible without requiring constant recentering.

3. **Likely payoff**

   By maintaining stable and predictable subtitle placement, users can focus more on the conversation rather than worrying about where to look for subtitles. This reduces cognitive load and enhances the overall user experience, leading to higher satisfaction and trust in the product.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   
   Improving the confidence display format will enhance trust in the system's memory and assistive behavior, ensuring that the wearer can discern between certain and uncertain information effectively.

2. **What small change unlocks it**

   Define a consistent confidence format for all face and name memory objects that includes both a numeric score and a label with a short reason for the score. For example: "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format will provide clear, non-narrative confidence information.

3. **Likely payoff**

   By clearly labeling the confidence of each memory object, the system will maintain higher trust with the wearer, as they can easily understand when a piece of information is highly certain versus less so. This clarity will help in reducing social awkwardness and ensuring that the wearer feels supported without over-reliance on uncertain data.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size for face/name memory ensures that common encounters are quickly and reliably recalled, enhancing the trustworthiness of name recognition without overloading the cloud or wearing out the battery.

2. **What small change unlocks it**

   Define a local cache size limit for frequently encountered faces and names, ensuring that these entities remain cached in phone memory for fast lookup, but do not exceed reasonable thresholds to avoid excessive data storage.

3. **Likely payoff**

   By setting an optimal local cache size, the system can quickly retrieve commonly seen faces and names without frequent cloud requests, reducing latency and enhancing user trust through reliable and immediate responses during interactions.

4. **Immediate next probe**

   Define a local cache size limit of 10-20 frequently encountered entities for fast name recall in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining what stays local on the phone versus what falls back to the cloud for memory lookup, we can ensure that critical memory support is always available in real-time without overloading the glasses' limited resources. This improves the trust and reliability of name and face recall during live interactions.

2. **What small change unlocks it**

   Define a clear boundary where name and face memory lookups are handled locally on the phone, while more computationally intensive tasks like advanced context analysis or periodic updates can fall back to the cloud. For example, set a rule that local memory lookup handles recent encounters within the last 30 minutes.

3. **Likely payoff**

   This change will reduce latency and improve the reliability of name recall during live interactions. By keeping critical memory lookups local, we ensure faster response times and more accurate face/name recognition, which enhances trust in the assistant’s capabilities.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
