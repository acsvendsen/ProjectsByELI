## Reality Check for SmartGlasses Project

### Subtitle Placement Feasibility
- **Subtitle Clarity**: The glasses should place subtitles in a way that remains readable, stable, and trust-preserving during live conversations. Current V1 constraints favor minimal on-glasses processing, so placing subtitles on the lens or as close to the eye as possible would be feasible now.
  - **Feasible Now**: Place subtitles near the center of the lens where they are easily readable but not overly distracting.

### Confidence Display Feasibility
- **Confidence Label + Short Reason**: Given that the initial interactions are frame-touch based, a confidence display that includes both a label and a short reason would be more complex but still feasible. This ensures users can understand when the system is uncertain.
  - **Feasible Now**: Implement a confidence format such as "Uncertain [Reason]" to provide clear feedback.

### Memory/Cache Policy Feasibility
- **Local vs Cloud Storage**: The glasses should rely on cloud storage for memory support, with local caching only where absolutely necessary due to battery and thermal constraints.
  - **Feasible Now**: Implement a limited local cache (e.g., for the last few faces/names) to improve lookup speed while keeping the core processing on the phone.

### Phone/Cloud Boundary Feasibility
- **Phone-First Processing**: Given V1 constraints, the phone should handle most of the heavy lifting. Cloud integration is optional and only used where it adds clear value.
  - **Feasible Now**: Design the app to use cloud services for memory updates and model upgrades but keep core subtitle generation on the phone.

### Visual Hierarchy Feasibility
- **Discreet UX vs Visual Clarity**: The visual hierarchy should prioritize discreetness while ensuring subtitles are readable in motion and noise.
  - **Feasible Now**: Use a simple, unobtrusive display style for subtitles that can be quickly read. Ensure the subtitle font size and position do not distract from the main interaction.

### Core Deepening vs Sprawl
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion.
  - **Feasible Now**: Prioritize refining subtitle generation algorithms to improve clarity and stability. Enhance face recognition and confidence display for more accurate memory support.

### Interactions Feasibility
- **Frame-Touch Interaction Only**: V1 interactions should remain frame-touch based, avoiding voice commands entirely until a clear justification is provided.
  - **Feasible Now**: Implement frame-touch controls for subtitle management, mode switching, and confirmations to ensure compliance with current constraints.

### Tension Management
- **Privacy vs Usefulness**: Ensure that memory support does not pretend certainty or create corrupted recall. This tension requires careful design of the confidence behavior.
  - **Feasible Now**: Design a system where memory support is clear about its limitations, providing users with accurate and trustworthy information.

### Real-Time Subtitle Clarity
- **Subtitle Quality**: Achieving real-time subtitle clarity that remains readable and stable in live conversation is critical for user trust.
  - **Feasible Now**: Use the `TranscriptLab` app to test and refine subtitle generation algorithms. Ensure subtitles are clear, stable, and provide a good reading experience.

### Constraint Pressure
- **Battery, Latency, Privacy, Usability**: Surface these constraints early so that weak directions can be quickly identified.
  - **Feasible Now**: Continuously monitor the `TranscriptLab` app's battery usage and latency to ensure they remain within acceptable limits. Use real-world testing to refine subtitle generation algorithms.
