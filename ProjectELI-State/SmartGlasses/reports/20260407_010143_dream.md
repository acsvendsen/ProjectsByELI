### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining a stable subtitle placement rule based on confidence state, we can ensure that subtitles remain clear and unobtrusive while still providing essential information when needed. This improves the wearer's trust in the system by maintaining readability without overwhelming them.

2. **What small change unlocks it**

   Define a simple subtitle placement rule: place subtitles at the bottom center of the frame for low-confidence matches, and center them slightly lower (10-15%) for high-confidence matches. This rule can be implemented as a fixed position relative to the screen.

3. **Likely payoff**

   Implementing this stable placement rule will lead to more consistent and reliable subtitle presentation. It will help reduce distraction while ensuring that critical information is always visible, thereby enhancing the wearer's trust in the system's ability to provide accurate and timely support.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to include a numeric score alongside a label and short reason, we can enhance the trustworthiness of the system. This format provides users with more nuanced understanding, allowing them to assess the reliability of the displayed information better.

2. **What small change unlocks it**

   The small change is defining a specific confidence object format that combines a numeric score with a label and a short reason for the confidence level. For example: "score 0.85 + 'High' + 'Seen recently'. This can be implemented in the `TranscriptLabModel.swift` to ensure consistency across all instances.

3. **Likely payoff**

   Introducing this format will likely lead to increased user trust and more accurate decision-making based on the confidence of the displayed information. Users will have a clearer understanding of when they should rely on the system’s suggestions, thereby enhancing their overall experience and interaction with the device.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear cache eviction rule for face/name memory objects, we can ensure that the system retains enough recent evidence to maintain trust and recall without overwhelming local storage. This will help in managing the balance between rich memory support and fast lookup, ensuring that critical context is available when needed.

2. **What small change unlocks it**

   Implement a cache eviction policy that prioritizes recently seen faces and names while removing older entries based on a fixed recency threshold or least-recently-used (LRU) algorithm.

3. **Likely payoff**

   The defined cache eviction rule will allow the system to maintain a high level of memory trust by keeping relevant information fresh, thereby reducing the risk of outdated or irrelevant data being recalled. This will enhance the wearer's confidence in the system’s ability to remember and support them accurately during interactions.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud processing for live subtitle processing, we ensure that critical real-time data and behavior remain on-device, reducing latency and ensuring fast, stable subtitles. This improves the overall trust in the system and aligns with the core attractors of real-time subtitle clarity and low-friction assistance.

2. **What small change unlocks it**

   Define a single task boundary for live subtitle processing that prioritizes phone-local processing for critical data such as current face/facial landmark recognition, name recall, and confidence display, while falling back to cloud only when high-resolution image or speech transcription is required.

3. **Likely payoff**

   This decision will ensure real-time subtitles remain crisp and reliable, enhancing the wearer's trust in the system during live conversations. It will also reduce battery drain from continuous network usage for subtitle processing, aligning with the core tension of latency vs richness.

4. **Immediate next probe**

   Define one task-specific cloud fallback boundary for exactly one task such as live subtitle processing: For face and name recognition within a 5-meter radius, prioritize phone-local processing; fall back to cloud only when high-resolution image or speech transcription is required.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving subtitle vs one-line support coexistence ensures that the wearer can easily distinguish between critical subtitles and contextual prompts. This helps in maintaining clarity and reducing cognitive load, which is crucial for real-time understanding.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prioritizes subtitles over one-line support but allows both to be visible on screen at the same time. The subtitle should remain prominently displayed with a higher visual weight, while the one-line support should have a lower visual priority.

3. **Likely payoff**

   By clearly distinguishing between critical information (subtitles) and contextual prompts, the wearer can focus better on real-time communication without being distracted by less important notifications. This improves overall understanding and trust in the system's assistive capabilities.

4. **Immediate next probe**
   - Define a visual hierarchy rule that gives higher precedence to subtitles over one-line support.
