# Reality Check for SmartGlasses

## Subtitle Clarity: Real-time subtitle clarity
- **Feasible Now:** 
  - The `TranscriptLab` app provides a clear path to real-time transcription with minimal latency, which is essential for maintaining trust during live conversations.
  - Current hardware and software constraints should allow for subtitles that are stable and readable within the bounds of the glasses' display.

## Memory Trust: Trustworthy memory support
- **Feasible Now:** 
  - The face/name recall mechanism can be implemented using local caching on the phone, with periodic reinforcement through interactions.
  - Confidence objects and short reasons can provide a clear indication of memory reliability without overloading the user.
  
- **Assumptions Needing Evidence:**
  - The effectiveness of confidence objects in building user trust needs further testing to ensure that they do not create unnecessary cognitive load.

## Low-friction Assistance: Low-friction assistance
- **Feasible Now:** 
  - One-line prompts can be designed as discreet and unobtrusive, ensuring they provide just-in-time support without disrupting the flow of conversation.
  
- **Assumptions Needing Evidence:**
  - The design for one-line prompts needs to balance utility with minimal disruption. Testing in real-world scenarios will help refine this.

## Frame-touch-only V1 Interaction
- **Feasible Now:** 
  - Frame touches are a simple, user-friendly interaction method that aligns well with the current hardware constraints.
  
## Phone-first Runtime: Phone-first runtime
- **Feasible Now:** 
  - The `TranscriptLab` app demonstrates that heavy processing can be offloaded to the phone without significant battery drain issues. Early versions should rely heavily on the phone.

## Core Deepening Over Sprawl
- **Feasible Now:** 
  - Focusing on subtitle quality, memory trust, and visual UX improvements will strengthen the core mission without adding unnecessary complexity.
  
- **Assumptions Needing Evidence:**
  - The effectiveness of current design choices in achieving these goals should be validated through iterative testing.

## Constraint Pressure
- **Feasible Now:** 
  - Early testing with `TranscriptLab` can surface real-world limitations, such as battery and thermal constraints.
  
## Implementation Grounding
- **Feasible Now:** 
  - The current implementation in `TranscriptLab` provides a solid foundation for core functionality. Any new features should be grounded in the existing codebase.

## Subtitle Placement: Subtitle placement
- **Feasible Now:** 
  - Initial designs can use a fixed position or semi-transparent overlay that minimizes distraction while ensuring readability.
  
- **Assumptions Needing Evidence:**
  - The exact placement needs further user testing to ensure it does not become distracting.

## Confidence Display: Confidence display
- **Feasible Now:** 
  - Implementing confidence as a label + short reason can provide clear, non-intrusive feedback about the reliability of memory recall.
  
- **Assumptions Needing Evidence:**
  - The effectiveness of this approach in building trust should be tested with real users.

## Memory/Cache Policy: Memory/cache policy
- **Feasible Now:** 
  - Implementing a caching strategy that balances local storage and cloud support can be done using the phone as a primary processing unit.
  
- **Assumptions Needing Evidence:**
  - The optimal size of cache and refresh frequency should be determined through iterative testing.

## Phone/Cloud Boundary: Phone/cloud boundary
- **Feasible Now:** 
  - Early versions should rely heavily on local processing, with cloud support limited to non-critical tasks.
  
- **Assumptions Needing Evidence:**
  - The impact of cloud dependency on overall system performance and user experience needs validation.

## Visual Hierarchy: Visual hierarchy
- **Feasible Now:** 
  - Initial designs can prioritize clarity over feature density, ensuring that subtitles are readable without being overwhelming.
  
- **Assumptions Needing Evidence:**
  - User testing should be conducted to ensure the visual hierarchy meets user expectations for readability and distraction.

## Summary of Reality Checks
- The core functionalities (subtitle clarity, memory support, low-friction assistance) can all be implemented within current constraints.
- Key assumptions need further evidence through iterative testing and refinement.
- Continuous surface of real-world limitations will help prevent wasted effort on infeasible directions.
