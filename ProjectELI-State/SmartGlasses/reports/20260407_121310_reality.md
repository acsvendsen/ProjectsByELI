# Reality Check

## Subtitle Placement: Feasible Now

- **Subtitle Clarity (subtitle_clarity)**: Given the current focus on real-time subtitle clarity in noisy environments, the placement should ensure subtitles are visible and stable enough for the wearer to trust them. A lower edge of the glasses frame or a central position might be optimal to avoid distraction while ensuring readability.

- **Reasoning**: The `TranscriptLab` app can help test different subtitle placements. By iteratively adjusting subtitle positions in this app, we can find the best balance between clarity and social acceptability without overloading the wearer with too much information. This is feasible now given the current V1 constraints.

## Confidence Display: Feasible Now

- **Confidence Format (memory_trust)**: The confidence display should be clear enough to convey trustworthiness but not overly complex. A simple label plus a short reason might be most effective, especially if it balances between providing useful information and maintaining social acceptability.

- **Reasoning**: Implementations like `TranscriptLab` can experiment with different confidence formats. Testing these in real-time scenarios will help determine the best format that aligns with the core mission of enhancing understanding without causing social awkwardness or overloading the user.

## Memory/Cache Policy: Feasible Later

- **Face/Name Recall (memory_trust)**: Implementing face and name recall with confidence objects and reinforcement requires more sophisticated backend handling. While initial local caching can be done on the phone, a full memory policy will likely need to evolve as we gather more data and refine our understanding of what works best.

- **Reasoning**: The current `TranscriptLab` app can focus on basic text display and minimal confidence indicators. However, developing a robust memory cache policy that respects privacy and ensures trustworthiness is a future task given the complexity involved.

## Phone/Cloud Boundary: Feasible Now

- **Phone-First Runtime (phone_first_runtime)**: The glasses should remain simple in V1 with most processing happening on the phone. This approach minimizes thermal and battery pressure while providing immediate value to the wearer.

- **Reasoning**: Since `TranscriptLab` is designed to mimic the future glasses experience, it can be used as a test bed for phone-first runtime scenarios. Further refining interactions and confidence displays in this context will help define clearer boundaries between local processing and cloud assistance where necessary.

## Visual Hierarchy: Feasible Now

- **Visual Clarity vs Discreet UX (discreet_ux_vs_visual_clarity)**: The visual hierarchy should prioritize clarity of subtitles while ensuring they do not become too distracting. Using `TranscriptLab` to test different UI elements and their placement can help achieve this balance.

- **Reasoning**: By experimenting with different subtitle sizes, colors, and placements in `TranscriptLab`, we can determine the optimal visual hierarchy that enhances understanding without overwhelming the user.

## Evolution Rule: Core Deepening Over Sprawl

- **Core Deepening (core_deepening)**: The current focus on improving subtitle quality, memory trust, and low-friction assistance aligns with the core mission. Expanding into broader feature areas should be done cautiously to ensure it deepens rather than dilutes the core.

- **Reasoning**: The project documentation explicitly encourages bias towards core improvements. Therefore, any new features or interactions should be evaluated against their contribution to these core areas before implementation.

## Reality Check Rule: Surface Real-world Limitations

- **Constraint Pressure (constraint_pressure)**: Early surface of real-world limitations is critical. Given the current V1 constraints on battery and thermal pressure, it's essential to regularly test prototypes in real-world conditions to identify weak points early.

- **Reasoning**: By continuously assessing the feasibility of proposed directions against these constraints, we can avoid wasting time on impractical features or overly complex solutions that do not align with our core mission.

## Summary

- **Subtitle Placement and Confidence Display (feasible now)**: These can be effectively tested using `TranscriptLab`.
- **Memory/Cache Policy and Phone/Cloud Boundary (feasible later)**: These require more development time but are essential for the long-term success of the project.
- **Visual Hierarchy and Core Deepening**: These should continue to focus on improving core functionality without unnecessary expansion.

By following these guidelines, we can ensure that our efforts align with the project's goals while respecting real-world constraints.
