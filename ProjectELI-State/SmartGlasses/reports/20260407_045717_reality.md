# Reality Check

## Subtitle Clarity: Feasible Now
- **Current Status**: The `TranscriptLab` test app has been successfully built and can be run on an iPhone or simulator, providing a real-time transcript path.
- **Assessment**: Given that the current implementation already supports live microphone capture and partial/final transcript behavior, it is feasible to work on improving subtitle clarity in real-time. The focus should remain on ensuring subtitles are clear, fast, and stable enough for live conversations without causing distraction or breaking trust.

## Memory Trust: Feasible Later
- **Current Status**: Face/name memory storage and reinforcement have not been implemented yet.
- **Assessment**: Implementing face/name memory with confidence objects and reinforcement will likely require more complex backend processing and data management. Given the current V1 constraint of phone-first runtime, it is feasible to implement this feature later when the core subtitle functionality is well-established. The initial focus should be on ensuring real-time subtitles are reliable.

## Low Friction Assistance: Feasible Now
- **Current Status**: The `TranscriptLab` app allows for one-line prompts and confidence displays.
- **Assessment**: Implementing low-friction assistance, such as delivering one-line help and visible support through the existing UI, is feasible now. This can be done by ensuring that any prompts or subtitles are brief and non-intrusive.

## Privacy vs Usefulness: Feasible Now
- **Current Status**: The project explicitly avoids heavy on-glasses compute to mitigate privacy concerns.
- **Assessment**: Since the glasses remain lightweight in V1, it is feasible to focus on delivering useful assistive behavior that does not slide into invasive capture or retention. Ensuring that any memory support provided respects user privacy by being honest and clear about uncertainty can be a priority now.

## Latency vs Richness: Feasible Now
- **Current Status**: The `TranscriptLab` app supports partial/final transcript behavior, which helps in managing real-time data.
- **Assessment**: Given that the initial focus is on delivering timely help without overloading the runtime, it is feasible to work on improving the balance between richness of information and latency. Ensuring that any additional features do not introduce significant latency issues can be a priority now.

## Discreet UX vs Visual Clarity: Feasible Now
- **Current Status**: The `TranscriptLab` app already supports minimalistic UI design.
- **Assessment**: Implementing discreet subtitle placement and visual hierarchy that are both readable in motion and noise is feasible now. Ensuring the subtitles remain unobtrusive while still providing clear, useful information can be a priority.

## Frame Touch Only V1 Interaction: Feasible Now
- **Current Status**: The project explicitly states frame-touch interaction for V1.
- **Assessment**: Given that the current implementation already adheres to this constraint, it is feasible to ensure all interactions are handled through frame touches only. This can be further refined as needed but does not require immediate new development.

## Phone First Runtime: Feasible Now
- **Current Status**: The `TranscriptLab` app is designed to test phone-side processing.
- **Assessment**: Ensuring that heavy processing remains on the phone and using cloud services only when clearly justified is feasible now. This can be further refined as more features are added, but it aligns with current project constraints.

## Core Deepening Over Sprawl: Feasible Now
- **Current Status**: The current mode is set to core deepening.
- **Assessment**: Focusing on subtitle quality, memory trust, and visual UX improvements that increase daily-use value is feasible now. These areas can be refined further as needed but should remain the primary focus.

## Constraint Pressure: Feasible Now
- **Current Status**: The project acknowledges real-world limitations early.
- **Assessment**: Surfaceing battery, latency, privacy, and usability constraints is feasible now. This can involve continuous monitoring of these constraints through ongoing development and testing.

## Likely Waste of Time: Face/Name Memory Implementation
- **Assessment**: While face/name memory support is important for the long-term mission, implementing it in V1 with complex backend processing might be a waste of time given current constraints. It should be prioritized only after core subtitle functionality is well-established and proven.

## Assumptions Needing Evidence: Voice Activation in V1
- **Assessment**: Assuming voice activation control for subtitle management, mode switching, or confirmations in V1 is not feasible now given the explicit constraint that V1 interaction should happen through frame touches only. This can be explored later if the project direction changes.

### Summary:
- **Feasible Now**: Subtitle clarity, low-friction assistance, privacy vs usefulness, latency vs richness, discreet UX vs visual clarity, frame-touch-only V1 interaction, phone-first runtime.
- **Feasible Later**: Face/name memory implementation.
- **Likely Waste of Time**: Voice activation in V1.
- **Assumptions Needing Evidence**: Complex backend processing for face/name memory and other features that introduce significant complexity without clear justification.
