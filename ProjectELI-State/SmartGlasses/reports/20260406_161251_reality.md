# Reality Check for SmartGlasses V1 Direction

## Core Mission and Constraints

### Mission
Create discreet assistive glasses that provide real-time subtitles, personal name recall, conversation memory support, and one-line contextual prompts.

### Non-negotiables
- Frame-touch-only interaction.
- Phone-first architecture; do not assume heavy on-glasses compute unless justified.
- No voice activation or spoken command control in V1.
- Context must persist across sessions.
- New faces and names should be remembered automatically by default when supported by context, with explicit remember touches for reinforcement.

### Core Attractors
- Real-time subtitle assistance in noisy environments.
- Personal memory support for names and prior conversations.
- One-line contextual prompts rather than overwhelming paragraphs.
- Low-friction human experience; assistive, not deceptive.

### Core Tensions
- Privacy vs. usefulness.
- Always-on sensing vs. battery and thermal constraints.
- Local processing vs. cloud intelligence.
- Rich memory vs. fast lookup.
- Discreet UX vs. enough visual clarity.

### Drift Risks
- Gimmick over utility.
- Feature sprawl before core loop is established.
- Interaction complexity before touch-first V1 is solidified.
- High-latency responses breaking trust.
- Storing irrelevant information instead of weighted relevant memory.

## Current Core Focus

### Subtitle Placement and Visual Hierarchy
- **Subtitle Placement**: More Prominent (feasible now).
  - Reason: Ensures subtitles are visible but not overly intrusive, maintaining a balance between usability and social acceptability. This can be tested with user feedback to fine-tune the placement.

### Confidence Display
- **Label + Reason** (feasible now).
  - Reason: Provides clear indication of confidence level, building trust without overwhelming the user. This can be refined based on initial user reactions and real-world testing.

### Memory/Cache Policy
- **Recency First** (feasible now).
  - Reason: Ensures the most recent interactions are remembered with high priority, which is practical given battery constraints and the need for immediate assistance.

### Phone/Cloud Boundary
- **Phone First** (feasible now).
  - Reason: Minimizes thermal and power draw on glasses, allowing more processing to be done off-glass, which aligns with early hardware limitations. This can evolve as technology improves but is currently practical.

### Visual Hierarchy
- **Subtitles Dominate** (feasible now).
  - Reason: Ensures that subtitles are the primary focus of the UI, providing clear and essential information without overwhelming the user.
