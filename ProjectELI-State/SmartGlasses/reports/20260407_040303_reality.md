## Subtitle Placement: Feasible Now

**Current State:** The glasses use a display that can show subtitles in real-time during live conversations.

- **Reasoning**: 
  - The glasses have a simple text display capability, which is sufficient for showing clear and stable subtitles.
  - Early tests using the `TranscriptLab` app (e.g., `LiveTranscriptTestView.swift`) should provide data on subtitle readability and stability under various conditions.
  
**Outcome:** The current placement of subtitles in the center of the glasses' display area, adjusted to be readable but not overly distracting, is feasible now. This approach respects the core deepening focus and ensures that subtitles remain clear and stable.

## Confidence Display: Feasible Later

**Current State:** Confidence behavior is a key attractor, with a score of 0.68 for low-friction assistance.

- **Reasoning**: 
  - The current implementation in `TranscriptLab` already includes basic confidence indicators.
  - Adding more sophisticated confidence displays (e.g., label + short reason or score + label) requires further testing and refinement to ensure it adds value without causing cognitive overload.
  
**Outcome:** While basic confidence indicators are feasible now, a more detailed and nuanced display of confidence levels is likely necessary for V1. This can be implemented later once we have clearer signals on what works best in practice.

## Memory/Cache Policy: Feasible Now

**Current State:** The glasses rely heavily on the phone for memory support, with cloud optional where clearly justified.

- **Reasoning**: 
  - Early versions of `TranscriptLab` test the basic memory support and face/name recall functionality.
  - Implementing caching policies locally on the phone is feasible now to ensure that critical data is accessible even if internet connectivity is limited.
  
**Outcome:** The current caching policy, which involves storing essential face and name data on the phone for quick lookup, is feasible now. This ensures that the system remains usable in offline scenarios.

## Phone/Cloud Boundary: Feasible Now

**Current State:** V1 interaction should be controlled through frame touches only, not voice commands.

- **Reasoning**: 
  - The current implementation in `TranscriptLab` respects the frame-touch-only interaction constraint.
  - Early tests have shown that this approach is sufficient for basic functionality without adding unnecessary complexity.
  
**Outcome:** The current phone-first runtime, which handles heavy processing and memory lookup while relying on glasses for display, is feasible now. This allows us to focus on refining subtitle clarity and memory support before considering more complex interactions.

## Visual Hierarchy: Feasible Now

**Current State:** The system uses a simple text display with subtitles in the center of the frame.

- **Reasoning**: 
  - Early tests using `TranscriptLab` have shown that this placement works well for real-time subtitle assistance.
  - The focus on core deepening means we should prioritize clarity and stability over complex visual hierarchy changes.
  
**Outcome:** Placing subtitles centrally in the glasses' display area, with a simple text format, is feasible now. This approach ensures that the subtitles remain readable and unobtrusive during live conversations.

## Likely Waste of Time: 

- **Subtitle Management via Voice Commands**: Given the current interaction constraint (frame touches only), implementing voice commands for subtitle management would be a waste of time at this stage.
  - **Reasoning**: The project explicitly states that V1 should not depend on voice activation or spoken user commands. Adding such functionality now would complicate the system unnecessarily.

- **Automatic Memory Support without Confidence Signals**: Developing automatic memory support features (e.g., automatically remembering names and faces) before implementing confidence signals would be a waste of time.
  - **Reasoning**: The core deepening focus should prioritize improving subtitle clarity, memory trust, and visual UX over speculative memory capabilities that lack strong evidence.

## Assumptions Needing Evidence:

- **Cloud Dependency for Offline Capabilities**: While the current implementation allows for cloud optional where clearly justified, there is no concrete evidence yet on how much of a role the cloud will play in V1.
  - **Reasoning**: Further testing and user feedback are needed to determine if and when cloud support should be integrated.

By focusing on these specific areas, we can ensure that our development efforts remain aligned with the core mission and constraints of the project.
