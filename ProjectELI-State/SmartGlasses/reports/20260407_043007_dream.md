### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the wearer's trust in the system by ensuring that subtitles are always readable and do not become distracting. This is crucial for maintaining a high level of understanding and confidence during conversations.

2. **What small change unlocks it**

   Define three subtitle placement modes based on confidence levels: low-confidence (always visible), medium-confidence (visible with frame touches), and high-confidence (dynamic but hidden by default).

3. **Likely payoff**

   By providing different placement options, the system can adapt to various scenarios without overwhelming the wearer. This will lead to higher trust in real-time subtitle clarity and overall user satisfaction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to be more clear and concise, we enhance the wearer's trust in the system. A well-defined confidence label combined with a short reason will help the wearer understand when they can rely on the system and when further caution is needed.

2. **What small change unlocks it**

   Define the confidence object as a numeric score + label + short reason, where:
   - The score ranges from 0 to 1.
   - The label uses simple words like "High", "Medium", or "Low".
   - The short reason provides context without being overly narrative.

3. **Likely payoff**

   This change will make the confidence display more intuitive and reliable for the wearer, reducing uncertainty and increasing trust in the system's judgments. It will also help in fine-tuning the system’s behavior to provide appropriate support based on the level of certainty.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory objects on the phone, we can ensure that only the most relevant and frequently accessed memories are kept in memory, reducing the risk of privacy concerns and improving lookup performance.

2. **What small change unlocks it**

   Define a local cache size threshold (e.g., 10 recent faces or names) for storing face/name memory objects on the phone to limit the amount of data stored locally.

3. **Likely payoff**

   This approach will reduce memory usage, improve lookup speed by reducing the number of items that need to be searched, and ensure that only relevant memories are kept in cache, thereby enhancing privacy while maintaining useful memory support for the wearer.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs on the phone versus what falls back to the cloud, we ensure that V1 remains focused on delivering essential subtitle and memory support without overburdening the hardware. This clarity helps in managing battery life and thermal constraints while maintaining a balance between local processing efficiency and remote intelligence.

2. **What small change unlocks it**

   Define specific tasks for which phone-local processing is crucial, such as live subtitle processing, face/name recall lookup, or memory archive sync, and clearly outline when cloud fallbacks are necessary, like transcript cleanup or conversation snapshot upload.

3. **Likely payoff**

   By carefully selecting what runs on the phone and what falls back to the cloud, we can ensure that V1 is lean yet powerful enough to provide real-time subtitle clarity and reliable memory support without sacrificing battery life or thermal management. This setup will also set a strong foundation for future expansions where cloud capabilities become more integrated.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing, ensuring that the glasses can provide near-real-time subtitles while conserving power and thermal resources.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the subtitle-vs-one-line priority rule ensures that the most critical information is always visible, reducing cognitive overload and maintaining the wearer's focus on the conversation. This aligns with the core attractor of low-friction assistance by ensuring that essential subtitles are prioritized over one-line prompts.

2. **What small change unlocks it**

   Define a visual hierarchy where subtitles take precedence over one-line prompts when both are present, but only if the confidence in the subtitle is above a certain threshold (e.g., 0.8). This simple rule can be implemented by adjusting the `subtitle_priority_rule` function to consider both the confidence level and the presence of one-line prompts.

3. **Likely payoff**

   By ensuring that high-confidence subtitles are always prioritized, the system will maintain a clear and uncluttered visual display during critical moments, enhancing the wearer's ability to follow conversations without distraction. This can significantly improve the overall user experience by reducing cognitive load and maintaining trust in the assistant.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
