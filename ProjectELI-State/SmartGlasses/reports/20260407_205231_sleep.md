# Consolidated Signals

## Strengthening Signals
- **Subtitle Clarity**: The importance of real-time subtitle clarity is increasing. This means we must ensure subtitles remain clear, fast, and stable enough to be trusted during live conversations.
- **Memory Trust**: The trustworthiness of memory support for names, faces, and prior context is becoming more critical. We need to avoid overconfidence or creating false memories.
- **Core Deepening**: The current focus on deepening the core mission (subtitle quality, memory trust, visual UX) remains strong.

## Weakening Signals
- **Low Friction Assistance**: The initial medium strength of low-friction assistance is decreasing in importance compared to subtitle clarity and memory trust. This suggests we may need to prioritize subtitle and memory support over one-line prompts for now.
- **Constraint Pressure**: While the pressure to surface real-world constraints remains high, the focus might shift slightly away from immediate constraint resolution towards core improvements.

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: The tension between privacy and usefulness is critical. We must ensure that assistive features do not inadvertently lead to privacy concerns.
- **Latency vs Richness**: Balancing real-time response with richer context remains a significant challenge. We need to be cautious about overloading the system with too much processing.
- **Discreet UX vs Visual Clarity**: The balance between discreet use and visual clarity must remain a core tension, especially as we design subtitle placement and confidence display.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement**: Although no specific action is chosen yet, subtitle placement remains an open question that should be revisited to find the optimal balance.
- **Confidence Display**: Similarly, the best format for confidence display needs further consideration, even though it’s not a current focus.

## Concrete Tensions Around Subtitle Quality, Confidence Trust, Automatic Memory, Memory Reinforcement, Fast Lookup, Privacy, Latency, Battery, and Visual UX
- **Subtitle Quality**: Ensuring subtitles are clear, fast, and stable is crucial for user trust.
- **Confidence Trust**: The format of confidence display (label only, label + short reason, score + label) needs careful consideration to build trust without overwhelming the wearer.
- **Automatic Memory vs Explicit Remember-Touch Behavior**: While automatic memory behavior should reinforce known contexts, explicit remember-touch behavior remains important for user control and correction.
- **Memory Reinforcement**: The balance between persistent local caching on the phone versus cloud access must be managed carefully to avoid overloading both devices.
- **Fast Lookup**: Supporting quick lookups of names and faces is essential but must be balanced against battery and latency concerns.
- **Privacy**: Ensuring that memory support does not lead to privacy issues, especially regarding face and name recall.
- **Latency**: Balancing real-time responses with richer context to avoid lagging or delayed interactions.
- **Battery**: Managing thermal and battery constraints in always-on features without compromising core functionality.
- **Visual UX**: Designing the visual hierarchy and placement of subtitles while ensuring they remain readable and unobtrusive.

## Open Questions
- **Subtitle Placement**: What is the best V1 split between glasses, phone, and cloud?
- **Confidence Display**: How should confidence be represented: numeric score, label, and short reason?
- **Memory/Cache Policy**: How should face/name memory be stored and reinforced for fast lookup and trust?
- **Phone/Cloud Boundary**: What is the best V1 feature set that keeps hardware complexity low while providing useful assistive features?

## Action Areas
- **Subtitle Placement**: Ensure subtitles are clear, readable, and unobtrusive.
- **Confidence Display**: Develop a confidence display format that builds user trust without overwhelming them.
- **Memory Policy**: Balance persistent local caching with cloud access to avoid privacy issues.
- **Phone/Cloud Boundary**: Optimize the phone-first runtime while keeping V1 interaction simple.
