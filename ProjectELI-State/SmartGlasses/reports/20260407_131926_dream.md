### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles are always visible and readable while minimizing distraction. This will enhance the wearer's ability to follow conversations in noisy environments without being overwhelmed by too much information.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for low-confidence situations where additional support is needed (e.g., near the bottom of the display), and another for high-confidence situations where subtitles can be more subtle (e.g., slightly above eye level).

3. **Likely payoff**

   This approach will help maintain a balance between providing necessary assistance and avoiding visual overload, thereby enhancing the wearer's confidence in understanding conversations without causing distraction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring a clear and concise confidence format helps in building trust with the wearer by providing transparent certainty levels for memory support and subtitle accuracy. This enhances the reliability of the system, making users more likely to rely on its assistance.

2. **What small change unlocks it**

   Define a simple confidence format that combines a numeric score, a label, and a short reason. For example: "score 0.84 + 'High' + 'Seen recently'". This format provides a clear indication of the system's certainty level and the basis for this certainty.

3. **Likely payoff**

   By using a straightforward confidence format, users will gain more trust in the system’s memory support and subtitle accuracy. This clarity can reduce user skepticism and increase reliance on the product, ultimately improving overall satisfaction and daily-use value.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local memory cache size ensures that frequently encountered names and faces are always available to the wearer without latency or battery overhead. This directly supports the core attractor of **memory_trust**, enhancing the wearer's ability to recall key people and context in real-time interactions.

2. **What small change unlocks it**

   Define a fixed-size local cache on the phone that retains entities seen recently, with a priority for names and faces. This can be implemented as an eviction policy where less recent or less frequently encountered entities are purged first.

3. **Likely payoff**

   By limiting the memory to relevant and frequent entities, the system can maintain a reliable and lightweight cache without overwhelming the local storage, thus enhancing trust in name recall during live conversations. This reduces the risk of missed recalls and supports more natural interaction.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what runs phone-local versus cloud, we can ensure that critical real-time subtitle processing remains on-device to maintain trust and low latency. This approach helps balance privacy concerns with the need for timely assistance, ensuring that the wearer always has access to reliable information without the risk of data leakage.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing where only necessary components are offloaded to the cloud. For example, real-time speech-to-text conversion can be handled locally while context and memory support may require periodic cloud checks.

3. **Likely payoff**

   By keeping critical subtitle processing phone-local, we reduce latency, enhance reliability, and maintain trust in the system's accuracy. This also allows for better privacy management as sensitive data does not need to leave the device during real-time interactions.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By optimizing subtitle placement for low distraction while ensuring clear visibility, the system can maintain high subtitle clarity and trust in live conversations. This improves the wearer's ability to follow real-time interactions without visual overload.

2. **What small change unlocks it**

   Define a new subtitle placement rule that prioritizes stable, non-overlapping subtitle areas on one side of the field of view while allowing smaller, one-line support prompts to coexist minimally in the opposite area. This avoids overlapping subtitles and ensures both are readable without distraction.

3. **Likely payoff**

   The payoff includes improved subtitle readability and trust during live conversations, reducing cognitive load and enhancing the wearer's ability to follow spoken interactions effectively. This supports the core attractor of real-time subtitle clarity while minimizing visual intrusion.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
