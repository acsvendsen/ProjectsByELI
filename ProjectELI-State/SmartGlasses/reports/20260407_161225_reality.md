# Reality Check

## Subtitle Clarity: Feasible Now
- **Current Status**: The `TranscriptLab` app is already providing a framework for real-time subtitle testing, which means we can focus on optimizing clarity and stability of subtitles.
- **Constraints**: Battery constraints are currently managed by phone processing. Early hardware remains simple, so display performance is the primary concern.
- **Action Items**:
  - **Refine Speech Recognition Accuracy**: Ensure that the speech-to-text engine in `SpeechTranscriber.swift` has minimal latency and high accuracy.
  - **Optimize Display Timing**: Work on ensuring that subtitles are displayed as soon as possible after spoken words to maintain real-time perception.

## Memory Trust: Feasible Later
- **Current Status**: The memory system is not yet fully implemented, but the groundwork for face/name recall is laid in `TranscriptLab`.
- **Constraints**: Privacy vs. usefulness tension means we must ensure that memory systems do not inadvertently create false positives or invade privacy.
- **Action Items**:
  - **Implement Confidence Objects**: Use `confidence objects` to represent uncertainty in memory recall, ensuring users know when the system is guessing.
  - **Test Memory Recall Accuracy**: Gradually integrate memory recall into the system and test its accuracy with real-world data.

## Low-Friction Assistance: Feasible Now
- **Current Status**: The `TranscriptLab` app already provides basic interaction through frame touches, allowing for low-friction one-line prompts.
- **Constraints**: V1 interactions should remain simple to avoid social awkwardness and battery drain.
- **Action Items**:
  - **Integrate Confidence Indicators**: Use a label or short reason format within subtitles to provide context about the reliability of memory assistance.
  - **Test Prompt Placement and Visibility**: Ensure that one-line prompts are displayed clearly without overwhelming the user.

## Privacy vs. Usefulness: Likely Waste of Time
- **Current Status**: While privacy is important, focusing on it at this stage could delay essential features like real-time subtitles and memory recall.
- **Constraints**: Early hardware constraints mean we must prioritize functionality over privacy concerns for V1.
- **Action Items**:
  - **Monitor User Feedback**: Keep an eye on user feedback regarding privacy concerns but do not prioritize immediate implementation of complex privacy controls.

## Always-On Sensing vs. Battery: Feasible Later
- **Current Status**: Early versions will primarily rely on the phone, with some optional cloud support.
- **Constraints**: Battery constraints mean we cannot overburden early hardware for always-on features.
- **Action Items**:
