### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules based on confidence levels helps ensure that subtitles remain clear and stable enough for the wearer to trust them in live conversation. This improves real-time subtitle clarity, a key attractor of the system.

2. **What small change unlocks it**

   Define three different subtitle placement rules: one for high-confidence interactions (e.g., when the wearer is certain about the speaker's identity), another for medium-confidence situations (e.g., where there might be uncertainty but no significant risk of confusion), and a third for low-confidence scenarios (e.g., where the system is uncertain or the context is noisy).

3. **Likely payoff**

   By defining clear subtitle placement rules based on confidence, the system can reduce visual distraction during high-confidence interactions while ensuring that important details are still visible in more uncertain situations. This will help maintain trust and readability without overwhelming the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

   By implementing this refined confidence display, the system will better convey its reliability and accuracy, which can enhance the wearer's overall trust in the product. This clarity can lead to more effective use of one-line support and memory recall features, ultimately improving real-world interaction outcomes.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local cache threshold for face/name memory objects, the system can ensure that frequently encountered people are remembered more reliably while respecting battery and thermal constraints. This helps in maintaining high trust through stable behavior and rapid lookup of relevant memories.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects, specifically targeting entities seen within the last 30 minutes with at least one touch interaction, and reset their cache upon new interactions or after 1 hour without further use.

3. **Likely payoff**

   This approach will ensure that likely new-person memories are automatically stored in a way that reinforces trust through quick recall while reducing unnecessary memory storage that could drain the battery. It also helps in maintaining a clean and relevant memory cache, enhancing the overall user experience by making common interactions smoother and faster.

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that subtitle processing remains local to the phone minimizes latency and keeps the system responsive in real-time scenarios. This focus on local subtitle handling helps maintain clarity and stability, which are crucial for the wearer's trust in the system.

2. **What small change unlocks it**

   Define a strict rule that all live subtitle processing runs locally on the phone until explicitly overridden by cloud fallback for specific tasks such as transcript cleanup or memory archive sync.

3. **Likely payoff**

   By keeping subtitles local, we ensure real-time performance and responsiveness, which are key to building trust with the wearer. This will also help in maintaining battery efficiency and reducing thermal strain on the glasses hardware.

4. **Immediate next probe**
