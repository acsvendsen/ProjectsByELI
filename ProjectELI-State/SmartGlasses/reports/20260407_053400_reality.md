# Reality Check Summary

## Feasibility Assessments

### Subtitle Clarity (Real-time subtitle clarity)
- **Feasible now**: The `TranscriptLab` app provides a good foundation for testing and validating real-time subtitle behavior. Given the current focus on phone-first processing, it is feasible to improve subtitle clarity through incremental enhancements in this V1 frame-touch interaction mode.

### Memory Trust (Trustworthy memory support)
- **Feasible later**: Implementing face/name recall with clear uncertainty signals will require more complex backend processing and possibly cloud integration. This can be developed after initial core features are established, but it is a high-stakes area that needs careful design to balance utility against privacy concerns.

### Low Friction Assistance (Low-friction assistance)
- **Feasible now**: The current focus on frame-touch interaction makes one-line prompts more feasible to implement and test. Ensuring these prompts do not create command overhead or social awkwardness aligns with the V1 constraints.

## Constraints and Tensions

### Privacy vs Usefulness
- **Feasible later**: Balancing the usefulness of memory support with privacy concerns is a significant tension. For now, focus on core functionality while gathering evidence for how to handle this tradeoff effectively.

### Latency vs Richness
- **Feasible now**: With the current phone-first architecture and frame-touch interaction constraints, focusing on real-time subtitle clarity can be achieved without heavy cloud reliance. This ensures a low-latency experience that builds trust.

### Discreet UX vs Visual Clarity
- **Feasible now**: The `TranscriptLab` app provides a good starting point for designing subtitled text and one-line prompts in a visually clear manner, respecting the need for discretion and clarity in V1.

## Core Deepening Over Sprawl

- **Core-deepening over sprawl**: Prioritizing subtitle quality, memory trust, and visual UX improvements is aligned with the current mode of core deepening. This ensures the project stays focused on essential features rather than broad expansions that might dilute the core mission.

### V1 Constraints

- **Frame-touch-only V1**: Ensuring interactions through frame touches only aligns well with the current implementation and provides a solid foundation for future voice interaction explorations.
- **Phone-first runtime**: The `TranscriptLab` app supports this constraint by keeping heavy processing on the phone, making it easier to iterate quickly without overloading battery or thermal limits.

### Constraint Pressure

- **Constraint pressure**: Early iterations should focus on real-time subtitle clarity and memory trust while surfacing constraints like battery and latency. This approach ensures that weak directions are identified early in development.

## Open Questions

1. **Subtitle Placement**: Use the `TranscriptLab` app to iteratively test different subtitle placements, ensuring they remain clear and unobtrusive.
2. **Confidence Display**: Experiment with various confidence display formats (label only, label + short reason, score + label) using the `TranscriptLab` app to find the best balance between clarity and trust.
3. **Memory/Cache Policy**: Develop a caching strategy for face/name recall that respects privacy constraints while providing useful memory support.

## Summary

- **Subtitle Clarity (Real-time subtitle clarity)**: Feasible now, focus on improving real-time behavior using `TranscriptLab`.
- **Memory Trust (Trustworthy memory support)**: Feasible later, gather evidence and design before implementation.
- **Low Friction Assistance (Low-friction assistance)**: Feasible now, implement one-line prompts within frame-touch constraints.

By focusing on these core areas, the project can build a robust foundation while continuously addressing real-world constraints.
