# Reality Check for SmartGlasses

## Subtitle Clarity - Feasible Now
- **Description**: Ensure subtitles are clear, fast, and stable enough that the wearer can trust them in live conversation.
- **Constraints**:
  - **Latency**: Subtitles must be near-real-time to maintain trust.
  - **Battery Draw**: Glasses should remain lightweight and socially acceptable.
  - **Thermal Pressure**: Early versions should not depend on heavy on-glasses compute.

### Feasibility: Feasible Now
- **Reasoning**: The `TranscriptLab` app (and related code) is already testing real-time transcription quality, providing a solid foundation for subtitle clarity. Ensuring the current implementation meets these constraints is within reach given the existing test infrastructure.

## Memory Trust - Feasible Later
- **Description**: Implement memory support that helps the wearer recall names, faces, and prior context without creating corrupted or certain recall.
- **Constraints**:
  - **Privacy vs Usefulness**: The system should not pretend certainty.
  - **Rich Context vs Latency**: Memory must be reliable but also fast enough to provide useful information.

### Feasibility: Feasible Later
- **Reasoning**: Current memory support is minimal and relies heavily on cloud-based lookups. Improving this will require more robust local caching and reinforcement learning mechanisms, which are not yet in place. However, this can be a focus for later development given the existing architecture direction.

## Low Friction Assistance - Feasible Now
- **Description**: Deliver one-line help and visible support without creating command overhead or social awkwardness.
- **Constraints**:
  - **Interaction Mode**: Frame-touch interaction only in V1.
  - **User Trust**: The assistance should not be overwhelming but rather discreet.

### Feasibility: Feasible Now
- **Reasoning**: Given the current focus on core deepening and the existing implementation of `TranscriptLab`, adding one-line prompts that fit well within frame-touch interactions is achievable. This can involve refining existing subtitle behavior to include brief, helpful text overlays when appropriate.

## Frame-Touch Only V1 - Feasible Now
- **Description**: Ensure all explicit user interaction through frame touches.
- **Constraints**:
  - **No Voice Commands**: Avoid voice activation in the current version.

### Feasibility: Feasible Now
- **Reasoning**: The current project inputs explicitly require that V1 interactions happen through frame touches only. This is currently being followed by `TranscriptLab`, ensuring that this constraint is respected in development.

## Phone-First Runtime - Feasible Now
- **Description**: Heavy processing should primarily happen on the phone.
- **Constraints**:
  - **Battery and Latency**: Limit reliance on always-on sensors to reduce battery drain and latency issues.
  - **Thermal Pressure**: Keep glasses hardware simple in V1.

### Feasibility: Feasible Now
- **Reasoning**: The `TranscriptLab` app is designed to test phone-side processing, ensuring that heavy computations remain off-glasses. This setup aligns with the current architecture direction and can be further refined as needed.

## Core Deepening Over Sprawl - Feasible Now
- **Description**: Focus on improving subtitle quality, memory trust, and visual UX.
- **Constraints**:
  - **Implementation Grounding**: Base decisions on actual repo files and app documentation rather than generic ideation.

### Feasibility: Feasible Now
- **Reasoning**: The current mode (`core_deepening`) explicitly focuses on core improvements. This is well-aligned with the existing implementation in `TranscriptLab` and other relevant projects, making it a feasible direction to pursue now.

## Constraint Pressure - Feasible Now
- **Description**: Surface real-world limitations early.
- **Constraints**:
  - **Battery, Latency, Privacy, Usability**: Early versions should address these constraints clearly.

### Feasibility: Feasible Now
- **Reasoning**: The `TranscriptLab` app already provides a platform to test and refine key aspects like subtitle clarity and memory support. Addressing real-world limitations through iterative development on this app is within reach.

## Visual Hierarchy - Likely Waste of Time
- **Description**: Determine the best subtitle placement and visual hierarchy for fast reading with low distraction.
- **Constraints**:
  - **Discreet UX vs Visual Clarity**: The display behavior should remain socially acceptable while still being readable in motion and noise.

### Feasibility: Likely Waste of Time
- **Reasoning**: While defining a clear visual hierarchy is important, the current project inputs suggest that initial focus should be on core functionality. Fine-tuning the visual hierarchy too early may lead to over-complication before more critical features are well-established. Once the core interactions and memory support are better understood through `TranscriptLab`, revisiting this might be worthwhile.

## Summary
- **Feasible Now**: Subtitle clarity, frame-touch interaction, phone-first runtime, core deepening.
- **Feasible Later**: Memory trust.
- **Likely Waste of Time**: Visual hierarchy fine-tuning until core features are well-defined.
