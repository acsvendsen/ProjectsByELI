# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now

- **Description**: Ensure subtitles are placed in a way that maximizes readability without becoming distracting.
- **Constraints**: Must remain socially acceptable and readable in motion and noise.
- **Feasibility**: Feasible now. The current `TranscriptLab` app should allow for testing subtitle placement with minimal complexity. Early tests can use simple overlays on the screen, adjusting text size, color, position, and animation to ensure they do not become distracting.

## Confidence Display: Feasible Later

- **Description**: Implement a confidence display that helps users understand the reliability of subtitles.
- **Constraints**: Must be clear but not overly complex; should avoid creating social awkwardness.
- **Feasibility**: Likely waste of time. The current mode is focused on core deepening, and adding a confidence display could delay essential subtitle clarity improvements. Once basic subtitle functionality is well established, this can be revisited.

## Memory/Cache Policy: Feasible Later

- **Description**: Define how face/name memory should be stored and reinforced for fast lookup.
- **Constraints**: Must balance privacy with usefulness; must not create corrupted recall.
- **Feasibility**: Likely waste of time. The current focus is on subtitle clarity and real-time responses, so this can be postponed until the core functionality is solidified.

## Phone/Cloud Boundary: Feasible Later

- **Description**: Determine when cloud processing should be introduced for heavy lifting.
- **Constraints**: Early versions should rely heavily on phone processing; cloud use must add clear value without excessive latency.
- **Feasibility**: Likely waste of time. The current implementation grounds the project in a phone-first approach, so this can be explored later based on real-world needs and technical feasibility.

## Visual Hierarchy: Feasible Now

- **Description**: Define how subtitles and one-line prompts coexist without overloading the wearer.
- **Constraints**: Must remain low-friction and not create command overhead or social awkwardness.
- **Feasibility**: Feasible now. The `TranscriptLab` app can be used to test different visual hierarchy options, ensuring that both subtitles and prompts are clear but non-intrusive.

## Core Deepening vs Sprawl

- **Description**: Ensure the project stays focused on improving core functionality before expanding.
- **Constraints**: Must not distract from the core subtitle/memory loop.
- **Feasibility**: Feasible now. The current mode of operation is to bias toward core deepening, so any new features or changes should directly support this goal.

## Summary

### Feasible Now
- Subtitle Placement: Early tests can be conducted using `TranscriptLab`.
- Visual Hierarchy: Use `TranscriptLab` for initial testing and refinement.
- Core Deepening: Focus on improving subtitle clarity, memory trust, and confidence display.

### Feasible Later
- Confidence Display: Introduce this once core functionality is well established.
- Memory/Cache Policy: Define storage and reinforcement strategies after the core loop is strong.
- Phone/Cloud Boundary: Explore cloud integration when necessary to add value without compromising usability.

### Likely Waste of Time
- These areas should be prioritized only after ensuring the project has a solid foundation in subtitle clarity, memory trust, and interaction design.
