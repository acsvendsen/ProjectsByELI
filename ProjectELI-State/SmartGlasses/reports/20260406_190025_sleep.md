# Consolidation of Recent Project Signals

## Core Field

### Mission
Create smart glasses that act as a discreet, context-aware personal assistant focused on live subtitles, face/name recall, conversation memory, and one-line support to help the wearer understand and respond better in real-world interactions.

### Non-negotiables
- The glasses help the wearer; they do not pretend knowledge the wearer does not have.
- Early hardware remains simple: display text, record audio/visual input; phone/cloud handles heavy processing.
- V1 interaction is frame-touch only; do not assume voice activation or spoken command control.
- Context must persist across sessions.
- New faces and names should be remembered with confidence objects and reinforcement over time.
- Real-world constraints must be surfaced early: latency, battery, privacy, social acceptability, on-device limits.

### Core Attractors
1. **Subtitle Clarity**: Keep subtitles clear, fast, and stable enough that the wearer can trust them in live conversation (strength: high; score: 1.0).
2. **Memory Trust**: Remember names, faces, and prior context without pretending certainty or creating corrupted recall (strength: high; score: 0.78).
3. **Low Friction Assistance**: Deliver one-line help and visible support without creating command overhead or social awkwardness (strength: medium; score: 0.68).

### Core Tensions
1. **Privacy vs Usefulness**: Helpful assistive behavior should not quietly slide into invasive capture or retention.
2. **Latency vs Richness**: The system should provide timely help without overloading the runtime with richer but slower processing.
3. **Discreet UX vs Visual Clarity**: Display behavior should remain socially acceptable while still being readable in motion and noise.

### Core Modes
- **Core Deepening (score: 0.84)**: Bias toward subtitle, memory, confidence, and architecture improvements that increase daily-use value.
- **Constraint Pressure (score: 0.58)**: Surface battery, latency, privacy, and usability limits early so weak directions are killed quickly.
- **Implementation Grounding (score: 0.74)**: Reason from actual repo files, app docs, and build truth instead of generic ideation.

### Current Open Questions
1. What is the best V1 split between glasses, phone, and cloud?
2. How should face/name memory be stored and reinforced for fast lookup and trust?
3. How should confidence be represented: numeric score, label, and short reason?
4. How should subtitles and one-line prompts coexist without overloading the wearer?
5. What is the best subtitle placement and visual hierarchy for fast reading with low distraction?

### Recent Signals from V1 Real World Limits

#### Hard Constraints
- Glasses should remain lightweight and socially acceptable.
- Early versions should not depend on heavy on-glasses compute.
- Battery and thermals are major risks for always-on features.
- Subtitles must feel near-real-time or trust breaks.
- Face/name recall must expose uncertainty clearly.
- First versions should rely heavily on phone processing, with cloud optional where useful.

#### Practical Implications
- Keep glasses hardware simple in V1.
- Bias toward phone-first processing.
- Use cloud only when it adds clear value and latency remains acceptable.
- UI should favor clarity over feature density.
