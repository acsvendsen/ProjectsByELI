# Reality Check Summary

## Subtitle Clarity (subtitle_clarity)
- **Feasible Now**: Ensure that the subtitle text is clear and fast enough to be trusted in live conversations. Given current hardware, this should focus on optimizing the display logic and ensuring stability without introducing heavy processing.
  
## Memory Trust (memory_trust)
- **Feasible Later**: Implement face/name memory with confidence objects and reinforcement over time. This will require more sophisticated backend support but can be prototyped in a way that respects V1 constraints.

## Low Friction Assistance (low_friction_assistance)
- **Feasible Now**: Deliver one-line help and visible support through frame touches, ensuring the UI is simple and unobtrusive.
  
## Privacy vs Usefulness (privacy_vs_usefulness)
- **Constraint Pressure**: Surface early that heavy memory storage and processing should be limited to ensure privacy. V1 should focus on context recall without pretending certainty.

## Latency vs Richness (latency_vs_richness)
- **Constraint Pressure**: Keep subtitle generation fast enough to feel near-real-time, avoiding delays that might break trust.

## Discreet UX vs Visual Clarity (discreet_ux_vs_visual_clarity)
- **Feasible Now**: Design the subtitle display to be readable in motion and noise. Ensure that the text is large enough to read easily without overwhelming the user.

### V1 Real World Limits
- **Frame-touch-only V1 Interaction**: Focus on frame touches for interaction, ensuring that no voice commands are assumed until explicitly allowed.
  
- **Phone-first Runtime**: Heavy processing should remain on the phone, with cloud support used only where justified by clear benefits and acceptable latency.

## Core-deepening over Sprawl
- **Core Deepening**: Prioritize subtitle quality, memory trust, and visual UX improvements rather than broad feature expansion.

### Open Questions and Tensions
- **Subtitle Placement**: Ensure that the placement is both usable and unobtrusive.
- **Confidence Display**: Determine a confidence format that builds trust without overloading the user.
- **Memory/Cache Policy**: Decide on caching strategies for names and faces, balancing local storage with privacy concerns.

## Action Items

### Subtitle Placement
- Ensure subtitles are positioned in a way that minimizes distraction but remains readable. Current efforts should focus on clarity rather than extensive optimization.

### Confidence Display
- Use a label + short reason format to provide confidence in memory recall without overwhelming the user. This approach respects V1 constraints and can be iterated upon later.

### Memory/Cache Policy
- Implement caching strategies for names and faces that respect privacy, storing only necessary information locally on the phone.

### Phone/Cloud Boundary
- Keep cloud support minimal in V1, focusing on local processing until clear benefits justify remote computation. Ensure all interactions are frame-touch-based.

### Visual Hierarchy
- Design subtitles to coexist with one-line prompts without overloading the UI. The subtitle display should be clean and unobtrusive.

## Conclusion

The current project inputs indicate that core-deepening efforts, focusing on subtitle clarity, memory trust, and visual UX, are feasible now. Privacy and latency constraints require early consideration to ensure the system remains useful and trusted. Discreet interaction methods and minimal cloud reliance align with V1 goals, making these approaches both practical and necessary for a successful launch.
