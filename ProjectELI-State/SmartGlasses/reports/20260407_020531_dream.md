### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining fixed subtitle placement rules based on confidence levels, we can ensure that subtitles remain stable and unobtrusive while still providing clear support in critical moments.

2. **What small change unlocks it**

   Introduce a simple subtitle placement policy where:
   - Subtitles are always placed at the bottom of the screen.
   - Low-confidence subtitles are slightly dimmed or blurred to reduce distraction.

3. **Likely payoff**

   This approach enhances user trust by maintaining a consistent visual layout, reducing distractions during high-concentration tasks like conversation, and ensuring that critical information is clearly visible without overwhelming the wearer.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format in V1 ensures that the wearer can trust the memory support more effectively. A clear, concise, and unambiguous confidence indicator helps the wearer understand the reliability of name and face recall without creating false certainty or uncertainty.

2. **What small change unlocks it**

   Define a consistent confidence object format for names and faces: a numeric score (e.g., 0.85), label (e.g., "High"), and short reason (e.g., "Seen recently").

3. **Likely payoff**

   By clearly indicating the reliability of name and face recall, the system can build trust with the wearer more effectively. This will reduce social awkwardness and increase the overall utility of the memory support feature.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for name recall, we ensure that the system can quickly retrieve relevant information from memory without overloading the phone's resources. This helps maintain real-time responsiveness and reduces battery drain, aligning with the core attractor of low-friction assistance while also addressing the constraint pressure on latency and battery.

2. **What small change unlocks it**

   Define a local cache size limit for name recall that caps the number of recently seen names stored on the phone. This can be set to a value like 10-20 entries, depending on testing results.

3. **Likely payoff**

   The system will retain fast and reliable name recall for recent interactions while conserving battery life and minimizing thermal strain, enhancing the overall user experience and core attractor of low-friction assistance.

4. **Immediate next probe**

   Define a local cache size limit for name recall set to 15 entries to balance memory retention with real-time performance.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for transcript cleanup, we ensure that V1 remains focused on delivering real-time subtitles and basic memory support without overloading the glasses hardware. This alignment helps maintain low latency, preserves battery life, and ensures the system provides timely help, which is crucial for the core attractors of real-time subtitle clarity and trustworthy memory support.

2. **What small change unlocks it**

   Define a specific cloud fallback boundary for transcript cleanup where confidence scores fall below a certain threshold (e.g., <0.7). This means that when transcripts are highly uncertain or low-quality, they will be sent to the phone for processing before being displayed on the glasses. Conversely, high-confidence transcripts can remain local.

3. **Likely payoff**

   By centralizing transcript cleanup only in cases of low confidence, we reduce the need for heavy cloud processing during live interactions, which helps maintain a fast and reliable real-time subtitle experience. This approach also ensures that the phone remains the primary device for critical operations, thus preserving battery life and ensuring timely responses.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles are displayed in a way that coexists with one-line support without overloading the wearer helps maintain the core mission of low-friction assistance and clear, reliable real-time subtitle clarity. By defining how these elements prioritize each other, we can reduce visual clutter and ensure that critical information is always accessible.

2. **What small change unlocks it**

   Define a simple coexistence rule where subtitles are given priority in wide-view modes (like while the wearer is looking away or during complex interactions) but one-line support has higher precedence when the wearer's focus needs to be maintained on the conversation.

3. **Likely payoff**

   By maintaining clear visibility of critical information, we can enhance the trustworthiness and usability of the system in noisy environments and dense social contexts. This will help ensure that the wearer remains confident and informed without feeling overwhelmed by too much visual data.

4. **Immediate next probe**

   Define one subtitle-vs-one-line priority rule for wide-view modes versus focused interaction modes, prioritizing subtitles when the wearer's focus can be shifted to the display but giving one-line support higher precedence during critical conversations.
