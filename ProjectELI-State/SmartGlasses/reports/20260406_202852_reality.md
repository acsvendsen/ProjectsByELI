# SmartGlasses V1 Reality Check

## Core Attractors and Tensions

### Subtitle Clarity (Real-time subtitle clarity)
- **Feasible Now:** Feasible now with current hardware constraints. The phone-first architecture allows for real-time transcript processing, although the system must manage latency effectively to ensure subtitles are clear and stable.
- **Assumptions Needing Evidence:** Ensure that the TranscriptLab app can handle the necessary real-time requirements without excessive battery drain or thermal issues.

### Memory Trust (Trustworthy memory support)
- **Feasible Now:** Feasible now with context-aware automatic new-person memory. The system should use reinforcement learning and contextual cues to remember names and faces reliably.
- **Assumptions Needing Evidence:** Validate the accuracy of face/name recognition and the effectiveness of confidence indicators in conveying uncertainty.

### Low-friction Assistance (Low-friction assistance)
- **Feasible Now:** Feasible now with frame-touch interactions. The system can provide one-line prompts without requiring spoken commands, ensuring a low-friction experience.
- **Assumptions Needing Evidence:** Ensure that the prompts are clear and unobtrusive to maintain social acceptability.

## Core Tensions

### Privacy vs Usefulness
- **Privacy vs Usefulness:** Feasible now. The system should store minimal data locally on the phone, ensuring that memory is based on context and not on invasive tracking.
- **Assumptions Needing Evidence:** Validate user comfort with the level of automatic memory support provided.

### Latency vs Richness
- **Latency vs Richness:** Feasible now. The system should prioritize real-time subtitles over richer but slower processing to maintain trust.
- **Assumptions Needing Evidence:** Conduct user testing to determine the acceptable latency threshold for subtitle clarity and stability.

### Discreet UX vs Visual Clarity
- **Discreet UX vs Visual Clarity:** Feasible now. The system can balance discreetness with sufficient visual clarity by carefully designing the placement and display of subtitles.
- **Assumptions Needing Evidence:** Use the TranscriptLab app to test different subtitle placements and visual hierarchies for user acceptance.

## V1 Interaction

### Frame-touch-only V1
- **Feasible Now:** Feasible now. The system should rely on frame touches for all interactions, ensuring that voice commands are not part of the initial release.
- **Assumptions Needing Evidence:** Ensure that users find frame-touch interaction intuitive and sufficient.

## Technical Realities

### Phone-first Runtime
- **Feasible Now:** Feasible now. The phone handles heavy processing while the glasses remain simple, allowing for rapid iteration without overburdening the hardware.
- **Assumptions Needing Evidence:** Confirm that the phone can handle real-time transcription and memory lookup efficiently.

### Memory/Cache Policy
- **Feasible Now:** Feasible now. Implement a caching policy that stores minimal data locally on the phone to ensure trust and privacy.
- **Assumptions Needing Evidence:** Validate the effectiveness of local caching versus cloud storage for context recall and memory support.

## Visual Hierarchy

### Subtitle Placement
- **Feasible Now:** Feasible now. The system can determine a placement that is both readable in motion and unobtrusive.
- **Assumptions Needing Evidence:** Use the TranscriptLab app to test different subtitle placements for user acceptance.

### Confidence Display
- **Feasible Later:** Feasible later, but evidence needed first. A confidence display can be implemented after initial testing to ensure it does not overwhelm the wearer.
- **Assumptions Needing Evidence:** Conduct user tests to determine the best format for confidence indicators (e.g., label only vs. score + label).

## Conclusion

The core features of real-time subtitle clarity, memory trust, and low-friction assistance are feasible with the current hardware constraints and the phone-first architecture. The project should focus on refining these core components while continuously testing and validating assumptions to ensure a high-quality user experience.
