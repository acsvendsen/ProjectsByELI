# Reality Check for SmartGlasses Project

## Subtitle Clarity (Subtitle Placement)

- **Feasible Now:** 
  - The current implementation in `TranscriptLab` already provides a clear and stable transcript path, which is essential for real-time subtitle clarity. Since the `TranscriptLabApp.swift`, `LiveTranscriptTestView.swift`, and related files are working well, subtitle placement should focus on ensuring that subtitles remain readable while not becoming distracting.
  - **Action:** Continue to refine the placement of subtitles within `LiveTranscriptTestView.swift` to ensure they do not interfere with the user's primary view but remain visible enough for real-time understanding.

## Memory Trust (Memory Policy)

- **Feasible Now:**
  - Implementing a system that remembers names, faces, and prior context can be done using local caching on the phone. This approach respects the current V1 constraint of heavy processing happening primarily on the phone.
  - **Action:** Develop a basic memory policy where new faces and names are stored with confidence objects and reinforced over time. Use the `TranscriptLab` app to test different memory recall strategies and confidence labels.

## Low-Friction Assistance (Visual Hierarchy)

- **Feasible Now:**
  - The current V1 interaction is frame-touch only, which means subtitle and one-line prompt display should be straightforward.
  - Ensure that subtitles are easily readable but not overly prominent to avoid distraction. One-line prompts can be displayed in a different color or style to distinguish them from subtitles.
  - **Action:** Implement a simple visual hierarchy where subtitles have higher priority than one-line prompts, ensuring the wearer can focus on conversation without being overwhelmed.

## Confidence Display

- **Feasible Now:**
  - The `TranscriptLab` app is currently set up for confidence display direction testing. This provides an excellent starting point.
  - Implement a label-only or label + short reason approach to ensure that the wearer understands the reliability of subtitles and prompts.
  - **Action:** Use `TranscriptLabModel.swift` to test different confidence labels and formats, focusing on clarity and trust-building.

## Phone/Cloud Boundary

- **Feasible Now:**
  - The current V1 architecture direction emphasizes phone-first processing. This is feasible given the existing implementation in `SpeechTranscriber.swift`.
  - Ensure that any cloud interaction is optional and clearly justified to avoid battery drain.
  - **Action:** Review and optimize the phone-side transcript plumbing in `SpeechTranscriber.swift` to ensure it remains efficient and does not depend on heavy cloud processing unless necessary.

## V1 Real World Limits

- **Feasible Now:**
  - The glasses should remain lightweight and socially acceptable, with early versions relying heavily on phone processing.
  - Ensure that any new feature or interaction mode is grounded in the current project inputs to avoid overbuilding hardware.
  - **Action:** Refine the `TranscriptLab` app to test subtitle placement and confidence display without introducing unnecessary complexity.

## Interaction Constraints

- **Feasible Now:**
  - V1 should not depend on voice activation for controlling the glasses. Frame-touch interaction is sufficient for now.
  - Ensure that any new feature or interaction mode respects this constraint.
  - **Action:** Focus on frame-touch interactions in `LiveTranscriptTestView.swift` and ensure that all new features can be controlled through these interactions.

## Current Unknowns

- **Subtitle Placement:**
  - The most usable subtitle placement is likely to be at the bottom of the field of view, but this needs further testing.
  - **Action:** Conduct user tests with `TranscriptLab` to determine the optimal subtitle placement without becoming distracting.

- **One-Line Prompts vs Subtitles:**
  - Visual differentiation between subtitles and one-line prompts should be clear. Use distinct colors or styles in `LiveTranscriptTestView.swift`.
  - **Action:** Implement a clear visual hierarchy in `LiveTranscriptTestView.swift` to differentiate between subtitles and one-line prompts.

- **Confidence Format:**
  - A label-only approach is likely sufficient for now, but testing with a short reason could provide better clarity.
  - **Action:** Test different confidence formats using the `TranscriptLabModel.swift` and choose the most effective one based on user feedback.

## Core Deepening vs Constraint Pressure

- **Core Deepening:**
  - Focus on improving subtitle quality, memory trust, and visual UX in the current `TranscriptLab` setup.
  - **Action:** Prioritize work that improves core mission components over broad feature expansion.

- **Constraint Pressure:**
  - Surface battery, latency, privacy, and usability limits early to ensure weak directions are killed quickly.
  - **Action:** Regularly check the `TranscriptLab` app for any potential battery drain or latency issues and address them promptly.

## Summary

- The current implementation in `TranscriptLab` is feasible now and should be used as a testing ground for subtitle placement, memory policy, confidence display, and visual hierarchy.
- Focus on core deepening improvements while surfacing real-world constraints early to avoid overbuilding hardware or introducing unnecessary complexity.
