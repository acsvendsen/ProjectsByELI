## Subtitle Placement: Feasible Now

**Reasoning**: The glasses must provide subtitles that are clear, stable, and fast enough to be trusted during live conversations. Given the current focus on real-time subtitle clarity (high strength), placing subtitles in a way that they do not distract but still remain readable is feasible with existing hardware.

- **Subtitle Placement**: Place subtitles at the bottom of the screen or just below the conversation area where they can be easily glanced at without disrupting the wearer’s view. This placement ensures subtitles are visible while minimizing distraction, aligning with low-friction assistance and real-time clarity requirements.
  
## Confidence Display: Feasible Now

**Reasoning**: The system must provide a clear indication of confidence to ensure that the user understands when they can trust the information being provided.

- **Confidence Format**: Use a label only for initial V1, possibly with a color indicator (e.g., green for high confidence, yellow for medium, red for low). Adding a short reason later might be considered if it does not add significant complexity or battery draw.
  
## Memory/Cache Policy: Feasible Later

**Reasoning**: The memory policy must ensure that face and name recall is reliable without creating privacy concerns. Given the constraints on early hardware and always-on sensing, caching locally on the phone for fast lookup can be explored but is not critical in V1.

- **Initial Approach**: Implement a local cache of recently seen faces and names with weak associations (e.g., "recently met" vs. strong confidence). This approach respects the privacy vs. usefulness tension while providing useful memory support.
  
## Phone/Cloud Boundary: Feasible Now

**Reasoning**: The phone should handle heavy processing, with cloud assistance being optional where latency remains acceptable.

- **Boundary Implementation**: Use the phone for speech recognition and partial transcript storage. Cloud can be used for model updates or background analysis but must not introduce significant latency.
  
## Visual Hierarchy: Feasible Now

**Reasoning**: The visual hierarchy should support subtitle clarity without overwhelming the user with additional information.

- **Visual Hierarchy**: Design subtitles to appear at the bottom of the screen, slightly offset from the center. Use a simple layout that allows for quick reading and minimal distraction.
