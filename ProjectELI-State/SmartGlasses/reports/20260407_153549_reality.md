## Memory Trust (memory_trust)

### Feasibility: Feasible Now
- **Current Status:** The core memory trust attractor is focused on remembering names and prior context without overconfidence. The current `TranscriptLab` app tests basic confidence displays, which are crucial for building user trust.
- **Constraints:** V1 should focus on discrete interactions and avoid voice commands.
- **Assessments:**
  - **Face/Name Recall:** Implementing face/name memory with clear uncertainty signals (e.g., "Not sure" or "Maybe") will help build initial trust. This can be achieved through simple confidence labels in the current `TranscriptLab` setup.
  - **Memory Persistence Across Sessions:** Ensure that memory is saved and loaded correctly, persisting across sessions without user intervention.

### Feasibility: Likely Waste of Time
- **Current Status:** There is no evidence to suggest memory trust should be delayed. The core attractors are clear and the current tests align with these goals.
- **Assessments:**
  - **Privacy vs Usefulness Tension:** Implementing basic confidence signals will not significantly compromise privacy while providing necessary utility, staying true to the `privacy_vs_usefulness` tension.
