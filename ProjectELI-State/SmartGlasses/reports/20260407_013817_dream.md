### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the wearer's trust in real-time subtitles by ensuring they are always readable and unobtrusive. This improves overall understanding and reduces cognitive load during conversations.

2. **What small change unlocks it**

   Define a set of fixed subtitle placement rules based on confidence levels: 
   - High-confidence subtitles (e.g., frequently mentioned people or topics) can be placed at the bottom center.
   - Medium-confidence subtitles (e.g., less frequent mentions) can be slightly above and to one side, without obstructing vision.
   - Low-confidence subtitles (e.g., occasional mentions) can be displayed very briefly or hidden entirely unless explicitly touched.

3. **Likely payoff**

   By implementing these rules, the system will provide a more stable and predictable experience, reducing the likelihood of subtitle placement causing distraction or confusion. This can lead to higher trust in the system’s reliability during real-world interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format, we can enhance trust in the system's memory support and subtitle quality. A clear and consistent confidence indicator will help the wearer understand the reliability of the information being presented, thereby improving their overall experience.

2. **What small change unlocks it**

   Implementing a confidence object that displays as "score 0.84 + 'High' + 'Seen recently'" for highly certain memories and "score 0.35 + 'Low' + 'Weak match'" for less certain ones will provide immediate feedback on the reliability of the information.

3. **Likely payoff**

   This change will help establish a clear trust signal in the system, making it more reliable and useful for the wearer. It will also enable better reinforcement learning by marking instances where the system is uncertain, thus prompting further interaction or correction if necessary.

4. **Immediate next probe**
   - Define the confidence score format as "score [0-1] + 'Low', 'Medium', or 'High' + 'Seen recently', 'Weak match', or 'Never seen' for V1."

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local memory threshold for face/name recall, we ensure that the system maintains a balance between useful contextual support and privacy. This helps in reinforcing the memory of likely new persons while respecting the wearer's need for privacy by not storing or constantly updating low-value information.

2. **What small change unlocks it**

   Define a simple entity-linking rule that attaches new evidence to existing person-memory objects based on recent encounters, but with a local memory threshold to prevent excessive updates.

3. **Likely payoff**

   This change will lead to more accurate and contextually relevant face/name recall over time while keeping the system lightweight and respecting privacy constraints. It will help in reinforcing memory for likely new people without creating unnecessary data overhead.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that V1 can focus on providing real-time, low-latency subtitle clarity and confidence behavior without overloading the glasses hardware with heavy processing tasks. This helps maintain the lightweight, socially acceptable design of the glasses while ensuring core functionality is robust.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that stays phone-local and another for memory archive sync that falls back to cloud. For example, real-time subtitle processing should be handled by the phone, while less time-sensitive tasks like syncing name memories can use the cloud as an optional fallback.

3. **Likely payoff**

   This clear separation will reduce the glasses' thermal load and battery drain, ensuring that V1 is lightweight and reliable. It also allows for more robust memory support through periodic syncs to the phone or cloud without compromising real-time performance. The wearer will benefit from clearer subtitles with less distraction and a faster, smoother interaction experience.

4. **Immediate next probe**
   - Define the boundary for real-time subtitle processing to stay phone-local, while less time-sensitive subtitle data syncing falls back to the cloud.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can focus on critical information while maintaining a clear understanding of their surroundings. This balance enhances trust and usability by providing just enough context without overwhelming the wearer.

2. **What small change unlocks it**

Define a prioritization rule where subtitles have higher precedence over one-line support, but allow for coexistence in a way that one-line prompts do not disrupt subtitle readability. This can be achieved by setting a visual hierarchy where subtitles are always displayed prominently and one-line support is shown only when necessary.

3. **Likely payoff**

This change will reduce cognitive load by ensuring the wearer’s attention remains on essential information, thereby improving their overall interaction experience and trust in the system. It will also help maintain social acceptability and usability, aligning with the core attractors of low-friction assistance and real-time subtitle clarity.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
