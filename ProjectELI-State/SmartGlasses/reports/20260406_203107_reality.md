# Reality Check for SmartGlasses V1 Direction

## Core Attractors and Tensions

### Feasible Now: Real-time Subtitle Clarity (`subtitle_clarity`)

- **Current Status**: High priority.
- **Constraints**:
  - **Latency**: Must feel near-real-time to maintain trust. This likely means sub-20ms processing, which is achievable with cloud processing and optimized network conditions.
  - **Battery**: Minimal impact since the phone handles heavy lifting.
  - **Thermals**: Low concern as this does not involve on-glasses compute.

### Feasible Now: Trustworthy Memory Support (`memory_trust`)

- **Current Status**: High priority.
- **Constraints**:
  - **Privacy vs. Usefulness**: Need to balance remembering names and context without overstepping privacy boundaries (e.g., explicit remember-touch behavior).
  - **Confidence Display**: Must clearly show confidence levels for memory accuracy to avoid creating false certainty.
  - **Memory Policy**: Memory should be reinforced through interactions rather than relying solely on automatic recall.

### Feasible Now: Low-friction Assistance (`low_friction_assistance`)

- **Current Status**: Medium priority.
- **Constraints**:
  - **Interaction Design**: Frame-touch interaction is simple and low-friction. Adding spoken commands in V1 would introduce unnecessary complexity.
  - **Contextual Relevance**: One-line prompts should be concise and relevant to the current context without overwhelming the wearer.

## Core Tensions

### Privacy vs Usefulness (`privacy_vs_usefulness`)

- **Current Status**: High pressure.
- **Constraints**:
  - **Memory Storage**: Automatic memory of new people must be reinforced through explicit remember-touch behavior to build trust.
  - **Explicit Reinforcement**: Explicit actions should validate or correct memories, ensuring they remain accurate and useful.

### Latency vs Richness (`latency_vs_richness`)

- **Current Status**: High pressure.
- **Constraints**:
  - **Subtitle Clarity**: Subtitles must be clear and fast enough to not break the wearer's flow. This can be achieved with cloud processing and optimized network conditions.
  - **Memory Lookup**: Fast lookup of names and context is crucial but should not compromise real-time subtitle performance.

### Discreet UX vs Visual Clarity (`discreet_ux_vs_visual_clarity`)

- **Current Status**: Medium pressure.
- **Constraints**:
  - **Subtitle Placement**: Subtitles must be placed in a way that they are readable and non-distracting. Current prototypes should focus on minimal visual disruption.
  - **Visual Hierarchy**: The visual hierarchy should prioritize subtitles over other elements to ensure they remain the primary focus.

## Real-world Limits

### Frame-touch-only V1 Interaction (`frame_touch_only_v1`)

- **Current Status**: Hard constraint.
- **Constraints**:
  - **User Experience**: Ensures a low-friction interaction without introducing voice commands or complex multimodal interfaces in V1.
  - **Implementation Simplicity**: Keeps the initial development straightforward and focused on core functionality.

### Phone-first Runtime (`phone_first_runtime`)

- **Current Status**: Hard constraint.
- **Constraints**:
  - **Battery Management**: Cloud processing can help manage battery usage by offloading heavy tasks to the phone or cloud as needed.
  - **Thermal Pressure**: Minimal on-glasses compute reduces thermal pressure, ensuring glasses remain lightweight and socially acceptable.

### Core-deepening Over Sprawl (`core_deepening_over_sprawl`)

- **Current Status**: Guiding principle.
- **Constraints**:
  - **Subtitle Quality**: Focus on improving subtitle clarity and stability before adding more complex features.
  - **Memory Trust**: Ensure memory is trustworthy through explicit user reinforcement rather than relying solely on automatic recall.
