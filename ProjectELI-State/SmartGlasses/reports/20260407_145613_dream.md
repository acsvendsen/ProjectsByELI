### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring consistent subtitle placement rules improves the wearer's ability to trust and understand real-time subtitles in noisy environments. Stable and predictable placement reduces distraction and cognitive load, allowing the wearer to focus more on the conversation.

2. **What small change unlocks it**

   Define two fixed subtitle placement modes: one for high-confidence speech and another for lower-confidence or background speech.

3. **Likely payoff**

   By defining these fixed modes, V1 can ensure that subtitles remain clear and unobtrusive, enhancing trust in the system's accuracy and reliability. This will make it easier for wearers to follow conversations without being distracted by constantly moving text.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitled information more effectively. By clearly indicating the certainty of each subtitle, the system enhances the reliability and accuracy of the assistance provided, aligning closely with the core attractors of real-time subtitle clarity and memory support.

2. **What small change unlocks it**

   Define a confidence display format that combines a numeric score with a label and a short reason for the certainty level. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

   By providing clear, concise confidence information, the system will reduce user uncertainty about the accuracy of the subtitles. This clarity enhances trust in the assistant's reliability and helps the wearer understand when they can depend on the information provided, which is crucial for real-time interaction.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear local cache size limit for face/name memory objects, we ensure that the system retains only relevant and frequently accessed memories, which reduces memory overhead while maintaining essential context.

2. **What small change unlocks it**

   Define a local cache size limit of 5-10 entries for each person or name, with periodic refreshes based on recent interactions.

3. **Likely payoff**

   This approach will reduce the memory footprint and improve lookup speed by prioritizing frequently accessed memories. It also helps in maintaining privacy by not storing irrelevant data long-term, which aligns with the core tension of balancing privacy vs usefulness.

4. **Immediate next probe**
   - Define a local cache size limit of 10 entries for each person or name.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By optimizing cloud fallback boundaries for real-time subtitle processing, we ensure that critical live subtitle information is handled locally where possible to maintain near-real-time performance and reduce latency. This focus on local processing improves trust by delivering accurate subtitles without delays or network interruptions, which aligns with the core attractor of "Real-time subtitle clarity."

2. **What small change unlocks it**

   Define one local fallback boundary for real-time subtitle processing that prioritizes phone-first handling for live streams and critical transcript data. This can be a simple rule like: "For live audio inputs, use phone-side processing unless explicit offline mode is triggered."

3. **Likely payoff**

   By keeping subtitle processing on the phone where feasible, we ensure faster response times, reduced latency, and more reliable subtitle delivery in noisy or challenging environments. This improvement directly supports the core attractor of real-time subtitle clarity, enhancing user trust and satisfaction.

4. **Immediate next probe**

   Define one local fallback boundary for live subtitle processing that prioritizes phone-side handling unless explicitly set to offline mode.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear precedence rule between subtitles and one-line support in the visual hierarchy, we ensure that the most critical information (subtitles) remains prominent while still providing low-friction assistance when needed. This helps maintain the wearer's focus on understanding conversation without being overwhelmed by additional information.

2. **What small change unlocks it**

   Define a single subtitle-vs-one-line priority rule where subtitles always take precedence, with one-line support displayed as secondary text that can be scrolled or dismissed easily. This rule ensures that critical real-time information is prioritized and does not get buried under less important prompts.

3. **Likely payoff**

   Implementing this simple but effective visual hierarchy rule will reduce cognitive load by keeping the most essential information at the forefront, enhancing the wearer's ability to follow conversations in noisy environments without feeling inundated with additional support text. This improves overall user experience and trust in the product’s assistive capabilities.

4. **Immediate next probe**

   Define one subtitle-vs-one-line priority rule where subtitles always take precedence over one-line prompts.
