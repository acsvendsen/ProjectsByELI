# Reality Check for SmartGlasses

## Subtitle Clarity - Real-time subtitle clarity (Subtitle Placement, Confidence Display)

### Feasibility: **Feasible Now**

- **Current State**: The `TranscriptLab` app provides a test environment to validate real-time transcript behavior. This is currently working within the constraints of live microphone capture and partial/final transcript handling.
- **Constraints**: 
  - **Latency**: Real-time subtitles need to be stable and fast enough that they do not introduce significant lag in conversation.
  - **Battery Draw**: Current implementation should aim for minimal impact on battery life. The `TranscriptLab` app's success indicates that real-time transcription is feasible with current hardware.

### Action Items:
- Continuously monitor the stability of subtitles during live testing.
- Ensure subtitle placement and visual hierarchy are optimized to avoid distraction without compromising readability.

## Memory Trust - Trustworthy memory support (Memory/Cache Policy)

### Feasibility: **Feasible Now**

- **Current State**: The system currently supports face/name recall, with a focus on clear uncertainty indication. This is being tested through the `TranscriptLab` app.
- **Constraints**:
  - **Latency**: Memory retrieval should be fast enough to provide useful context without significant delay.
  - **Privacy Perception**: Ensure that memory support does not create an invasion of privacy or unrealistic expectations.

### Action Items:
- Implement and test different confidence display formats (e.g., label only, label + short reason) to ensure trustworthiness.
- Continue refining the caching policy on the phone to balance memory retention with battery considerations.

## Low-friction Assistance - Low-friction assistance (Visual Hierarchy)

### Feasibility: **Feasible Now**

- **Current State**: The `TranscriptLab` app is focusing on delivering one-line help and visible support through minimal interaction. This aligns well with the low-friction design.
- **Constraints**:
  - **Latency**: One-line prompts should be delivered quickly to avoid breaking user flow.
  - **Battery Draw**: Ensure that these interactions do not significantly impact battery life.

### Action Items:
- Define and implement a clear visual hierarchy for one-line prompts, ensuring they are distinct from subtitles but still easily readable.
- Test different interaction patterns within the `TranscriptLab` app to ensure low-friction usability.

## Interaction Constraints - Frame-touch-only V1 (Interaction Constraints)

### Feasibility: **Feasible Now**

- **Current State**: The project explicitly states that V1 should not rely on voice commands. Current interactions are controlled through frame touches only.
- **Constraints**:
  - **Battery Draw**: Voice activation would increase battery usage, which is a risk in early hardware iterations.

### Action Items:
- Ensure all current interactions and prompts can be managed via frame touches alone.
- Continue refining the interaction design within `TranscriptLab` to ensure compliance with V1 constraints.
