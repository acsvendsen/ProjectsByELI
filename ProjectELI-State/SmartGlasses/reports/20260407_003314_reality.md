# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now
- **Subtitle Clarity (Core Attractor):** The glasses should display subtitles clearly and stably enough to be trusted in live conversation. This is feasible now as the `TranscriptLab` app can test and validate subtitle placement and readability.
  - **Reason:** The current implementation groundwork, particularly in `LiveTranscriptTestView.swift`, allows for initial testing of subtitle placement without significant complexity.

## Confidence Display: Feasible Now
- **Confidence Display (Core Attractor):** Implementing a confidence format that builds trust best is feasible now. While specific implementations are still being tested, the groundwork exists to explore different formats.
  - **Reason:** The `TranscriptLab` app can be used to test and refine various confidence display formats, such as labels or numerical scores.

## Memory/Cache Policy: Feasible Now
- **Memory Support (Core Attractor):** Implementing memory support that remembers names, faces, and prior context is feasible now. Initial implementation in the `TranscriptLab` app can lay the groundwork for this feature.
  - **Reason:** The existing `SpeechTranscriber.swift` and `TranscriptLabModel.swift` can be extended to include basic memory caching and recall.

## Phone/Cloud Boundary: Feasible Now
- **Phone-First Runtime (Core Constraint):** Early versions should rely heavily on phone processing, with cloud optional where clearly justified. This is feasible now as the current implementation in `TranscriptLab` focuses primarily on phone-side transcript behavior.
  - **Reason:** The `TranscriptLabApp.swift` and related views are designed to be close to the future glasses experience without introducing heavy cloud dependency.

## Visual Hierarchy: Feasible Now
- **Visual Clarity (Core Attractor):** Designing a low-friction UI that clearly differentiates between subtitles and one-line prompts is feasible now. The `LiveTranscriptTestView.swift` can be used to prototype visual hierarchy.
