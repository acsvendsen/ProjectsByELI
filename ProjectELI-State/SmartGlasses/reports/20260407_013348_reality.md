# Reality Check Summary

## Subtitle Clarity: Feasible Now
- **Subtitle Placement**: Ensure subtitles are positioned in a way that minimizes distraction but remains readable. Based on the current project inputs, the best placement is likely to be near the bottom of the field of view where they do not obscure important visual information.
- **Visual Hierarchy**: Use a clear and simple design for subtitles with sufficient contrast and size to ensure they are easily readable in motion. This can help maintain clarity without overwhelming the user.

## Memory Trust: Feasible Now
- **Face/Name Recall**: Implement a face/name memory system that uses confidence objects and reinforcement learning over time. This approach helps build trust by acknowledging uncertainty when necessary.
- **Confidence Display**: Use a simple label or short reason to indicate confidence levels, ensuring the user understands the reliability of the information provided.

## Low-Friction Assistance: Feasible Now
- **One-Line Prompts**: Design prompts that are concise and directly relevant to the context. Ensure these do not introduce unnecessary command overhead but still provide useful assistance.
- **Subtitle Coexistence**: Use a visual hierarchy to differentiate subtitles from one-line prompts, ensuring they do not overlap or interfere with each other.

## Privacy vs. Usefulness: Likely Waste of Time
- Focus on enhancing core functionality rather than adding complex privacy controls in the early V1 version. Early interactions should be straightforward and not overly burdened by privacy features that could complicate implementation and user experience.
- Consider implementing a basic UI that allows users to opt-out or adjust privacy settings later if needed.

## Latency vs. Richness: Feasible Later
- **Subtitle Clarity**: Continue optimizing subtitle clarity with real-time processing, but prioritize clear and stable text over more complex features in the initial release.
- **Memory Support**: Enhance memory support by adding richer context and faster lookup capabilities as hardware constraints allow.

## Discreet UX vs. Visual Clarity: Feasible Now
- Ensure subtitles are displayed discreetly enough to avoid social awkwardness while still being readable. Use a balance between visual clarity and minimalism in design.
- Continuously iterate on subtitle placement and size to find the optimal tradeoff.

## Frame-Touch Only V1 Interaction: Feasible Now
- Stick to frame-touch interaction for now, ensuring that all user interactions are simple and straightforward. This aligns with the current project constraints.

## Phone-First Runtime: Feasible Now
- Prioritize heavy processing on the phone while keeping glasses hardware minimal. Ensure that cloud services are used only where they add clear value and do not introduce significant latency issues.

## Core-Deepening Over Sprawl: Feasible Now
- Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion. This will help build a robust core experience before considering additional features.

### Assumptions Needing Evidence
- The exact design for confidence display (label only, label + short reason, or score + label) needs more evidence to determine which format builds the most trust.
- The optimal subtitle placement and visual hierarchy need further testing to ensure they meet both clarity and social acceptability requirements.

By focusing on these areas, the project can make meaningful progress while adhering to the current constraints and prioritizing core functionality.
