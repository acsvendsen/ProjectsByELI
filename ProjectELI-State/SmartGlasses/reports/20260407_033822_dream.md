### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules will enhance the wearer's trust in the subtitles by ensuring they are always visible and not distracting. This will help in maintaining a clear, uninterrupted flow of conversation without causing cognitive or social friction.

2. **What small change unlocks it**

   Define two fixed subtitle placement rules: one for high-confidence speech (e.g., "Always on bottom third") and another for low-confidence speech (e.g., "Fade out after 5 seconds").

3. **Likely payoff**

   By implementing stable, predictable subtitle placement rules, the system will become more reliable and less distracting, leading to increased trust in the subtitles during live interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display to use a clear, concise format that balances certainty with uncertainty, the system can better manage the wearer's trust in both subtitles and memory support. This will ensure that the user is not misled by overconfident or ambiguous information, thus maintaining the reliability of the assistant.

2. **What small change unlocks it**

   Define one confidence format for V1: a score + label + short reason combined into a single line without extraneous words. For example, "score 0.84 High (seen recently)" or "score 0.42 Low (weak match)".

3. **Likely payoff**

   This refined confidence display will help the wearer trust the system more by providing clear and honest feedback on the reliability of subtitles and memory support. It will reduce confusion and misuse, enhancing overall user satisfaction and the assistant's perceived reliability.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local memory threshold for name recall, we ensure that the system retains relevant and frequently encountered names in the phone's cache, enhancing trust through consistent and reliable memory support without overwhelming the wearer with too many names.

2. **What small change unlocks it**

   Define a policy where names are retained locally on the phone if they have been seen multiple times within a recent session, but expire after a certain period of inactivity to manage storage efficiently.

3. **Likely payoff**

   This approach will improve memory trust by ensuring that frequently encountered names remain accessible and relevant, while maintaining low device usage for less commonly used names. It balances the need for consistent recall with battery and thermal constraints.

4. **Immediate next probe**
   - Set the cache size limit for frequently encountered names to 20 entries per session.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Sticking to phone-first architecture ensures that V1 remains lightweight, socially acceptable, and battery-conscious. By keeping heavy processing on the phone, we can focus on delivering real-time, clear subtitles and reliable memory support without overloading the glasses hardware.

2. **What small change unlocks it**

   Define one specific task boundary for cloud fallback, such as live subtitle processing or face/name recall lookup, where cloud support is strictly optional unless explicitly justified by latency constraints.

3. **Likely payoff**

   By carefully defining when and how to use cloud resources, we can ensure that V1 operates efficiently on the phone, maintaining a smooth and reliable user experience. This will reduce battery drain, maintain social acceptability, and keep the initial implementation simple and focused.

4. **Immediate next probe**
   - Define the cloud fallback boundary for live subtitle processing to ensure real-time clarity without overloading the phone's resources.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**
   - By defining a clear precedence rule between subtitles and one-line support, the system can ensure that the most critical information is always prioritized and easily accessible to the wearer without overwhelming them with too much text.

2. **What small change unlocks it**
   - Define a visual hierarchy rule that prefers subtitles over one-line prompts when both are visible simultaneously.

3. **Likely payoff**
   - This change will reduce cognitive overload by ensuring that the primary focus (subtitles) remains clear and unobstructed, while still allowing for necessary contextual support through one-line prompts without disrupting the wearer's flow of conversation.

4. **Immediate next probe**
   - Define a visual hierarchy rule that gives subtitles higher precedence over one-line prompts when both are visible simultaneously.
