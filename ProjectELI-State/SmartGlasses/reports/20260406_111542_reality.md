# Reality Rules for SmartGlasses Core Field

## Current V1 Direction Assessment

### Core Mission
Create discreet, context-aware personal assistant smart glasses focusing on live subtitles, face/name recall, conversation memory, and one-line support.

### Non-negotiables
- **No voice activation or spoken command control in V1.**
- **Frame-touch-only interaction remains the core.**
- **Phone handles heavy processing; minimal local compute.**

## Core Attractors

- **Real-time subtitle assistance in noisy environments**: Feasible now with existing display technology.
- **Personal memory support for names and prior conversations**: Feasible later, subject to battery constraints.
- **One-line contextual prompts rather than overwhelming paragraphs**: Feasible now, aligns with minimal interaction design.
- **Low-friction human experience; assistive, not deceptive**: Feasible now, essential for user trust.

### Core Tensions

- **Privacy vs usefulness**: Likely waste of time without evidence of significant privacy concerns in the target use cases.
- **Always-on sensing vs battery and thermals**: Feasible later, but must consider battery draw and thermal management.
- **Local processing vs cloud intelligence**: Feasible now with minimal on-device computation.
- **Rich memory vs fast lookup**: Feasible now, prioritize high-confidence recall over extensive memory storage.

### Drift Risks

- **Gimmick vs daily-use assistant**: Likely waste of time without robust user testing to ensure core features are valuable.
- **Feature sprawl before core subtitle/memory loop is excellent**: Assumptions needing evidence; focus on essential features first.
- **Interaction sprawl that adds command modes or hardware complexity before the touch-first V1 is excellent**: Feasible later, prioritize minimal interaction design.

### Why it Matters

The system should reduce social and cognitive friction for users, especially in noisy environments, hearing-challenged situations, memory-challenged situations, and dense multi-person contexts. It should help users stay present, informed, and confident without pretending understanding.

### Evolution Rule

Expand the project only if that expansion strengthens the core mission or improves real-world usefulness significantly.

### Current Open Questions

- **Best V1 split between glasses, phone, and cloud**: Feasible now, given existing architecture.
- **Face/name memory storage and reinforcement for fast lookup and trust**: Feasible later, subject to battery constraints.
- **Confidence representation: numeric score, label, and short reason**: Feasible now, aligns with minimal complexity.
- **Subtitle and one-line prompt coexistence without overloading the wearer**: Feasible now, prioritize low-friction design.
- **Subtitle placement and visual hierarchy for fast reading with low distraction**: Feasible now, focus on user testing.

### Reality Check

The system should continuously surface real-world limitations early, including hardware, battery, thermal, latency, privacy, and usability constraints. 

## Open Assumptions

1. **Battery Draw**: Can the glasses handle real-time subtitle rendering without significantly draining the battery?
2. **Subtitle Latency**: How much delay can be tolerated in subtitle delivery while maintaining user trust?
3. **Thermal Management**: Are current display technologies capable of operating efficiently within thermal limits?

## Recommendations

- Focus on minimal interaction design to ensure low complexity.
- Prioritize real-time subtitle rendering and one-line prompts to address immediate needs.
- Conduct early user testing to validate core assumptions about memory, confidence, and user experience.
- Monitor battery draw and thermal management closely to avoid over-reliance on heavy processing.

By addressing these constraints and focusing on essential features, the project can maintain a clear path forward while ensuring real-world usability and user trust.
