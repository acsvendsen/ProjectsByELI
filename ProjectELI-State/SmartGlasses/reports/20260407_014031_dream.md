### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring consistent subtitle placement rules helps maintain trust by providing a predictable reading experience that does not distract the wearer during live conversations. Stable subtitle positioning reduces cognitive load and ensures that subtitles remain visible, clear, and readable.

2. **What small change unlocks it**

   Define two fixed subtitle placement modes: one for high-confidence contexts (e.g., familiar faces or names) where subtitles are placed at a consistent position in the center of the display, and another for low-confidence contexts (e.g., new people or less clear speech) where subtitles are slightly offset to avoid distraction but still remain visible.

3. **Likely payoff**

   By providing stable subtitle placement rules based on confidence levels, the system can maintain a balance between readability and non-distracting behavior. This will help in reducing cognitive overload during live conversations and ensuring that the wearer can trust the displayed subtitles without frequent distractions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide clear, concise, and reliable information about the certainty of memory recall or subtitle placement, we can enhance trust in the system's accuracy and reduce cognitive load on the wearer. This clarity will help the user better understand when they should pay more attention or when a less certain memory or subtitle is still useful.

2. **What small change unlocks it**

   Introduce a two-tier confidence display format: use a numeric score (0-1) with a corresponding label ("Very Low", "Low", "Medium", "High", "Very High") and a short reason for the score, such as "Seen recently" or "Weak match". This format provides both quantitative and qualitative information, enhancing the wearer's confidence in the system.

3. **Likely payoff**

   A well-crafted confidence display will help users quickly assess the reliability of memory recall and subtitles, reducing cognitive friction and increasing overall trust in the system. Users will be more likely to focus on critical interactions while ignoring less certain data, improving their understanding and response times in real-world scenarios.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds for face/name recall enhances V1's ability to provide trustful, consistent support without overloading the phone or cloud. This ensures that critical contextual information is readily available on-device, reducing latency and dependency on network access, which aligns with the low-latency response attractor.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects on the glasses. Specifically, set a threshold of 10-15 entries that can be stored locally without expiring older entries too quickly or retaining unnecessary data.

3. **Likely payoff**

   By limiting the number of face/name memories to a manageable 10-15 entries, the system can provide fast, reliable recall for recent interactions while keeping memory management simple and battery-conscious. This also ensures that the glasses remain socially acceptable and unobtrusive during extended use.

4. **Immediate next probe**

   Define one local-cache size limit between 10 to 15 entries for face/name memories on the glasses, ensuring fast lookup and minimal resource usage.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays on the phone versus what falls back to the cloud, we can ensure that V1 remains focused and efficient, reducing battery drain and thermal issues while maintaining critical functionality. This helps in delivering reliable subtitle assistance and memory support without overburdening the glasses hardware.

2. **What small change unlocks it**

   Define a specific task for which phone-local processing is essential and explicitly state the boundary conditions under which cloud fallback should occur. For instance, define local subtitle processing rules that ensure real-time delivery and stability, with cloud fallback only for transcript cleanup or memory archive sync.

3. **Likely payoff**

   By defining clear phone/cloud boundaries, we can achieve a more stable V1 experience with minimal battery drain and thermal issues. This will help in maintaining the core mission of providing reliable real-time subtitle assistance and memory support without overcomplicating the system.

4. **Immediate next probe**
