### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By refining subtitle placement rules for different confidence states, we can ensure that subtitles remain clear and stable enough to be trusted in live conversations while minimizing visual distraction. This improves real-time subtitle clarity (subtitle_clarity) and ensures a low-friction assistance experience (low_friction_assistance).

2. **What small change unlocks it**

   Define 2 to 3 specific subtitle placement rules based on confidence levels: one for high-confidence matches, another for medium-confidence matches, and a third for low-confidence matches.

3. **Likely payoff**

   Implementing these rules will reduce the visual clutter of subtitles while ensuring that critical information is always prominently displayed. This will enhance the wearer's ability to trust the subtitles in noisy environments and during dense interactions, thereby improving overall understanding and interaction quality.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to provide clear, concise, and reliable certainty information, the system can maintain high trust in its assistance while minimizing visual distractions. This ensures that the wearer can easily understand when they should pay attention to a subtitle or memory prompt.

2. **What small change unlocks it**

   Define a confidence object format that combines a numeric score with a short label and reason. For example: `score 0.84 + "High" + "Seen recently"` for well-established memories, or `score 0.35 + "Low" + "Weak match"` for less certain identifications.

3. **Likely payoff**

   This format will help the wearer quickly distinguish between high-confidence and low-confidence prompts, reducing cognitive load during conversations while maintaining a clear signal of reliability. It ensures that the system's assistance is seen as credible but not overbearing.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By optimizing the local cache size for face/name memory on the phone, we can ensure that frequently recalled names and faces are readily available to support quick lookups and reduce latency during live conversations. This improves trust by ensuring that critical memory cues are always within reach without overloading the device's storage.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memories on the phone, set at 50 entries with a recency threshold of 7 days. This ensures that only recently encountered or frequently recalled names and faces are cached locally, minimizing memory usage while maximizing the benefit of fast lookups.

3. **Likely payoff**

   By maintaining a smaller but highly relevant cache of face/name memories, we can significantly reduce latency during live conversations, ensuring that the wearer can quickly recall important contacts without waiting for cloud requests or searches. This will enhance trust and usability by making the memory support more reliable and responsive.

4. **Immediate next probe**
   - Define the local cache size limit for face/name memories on the phone, set at 50 entries.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that subtitles remain real-time and stable. This helps maintain trust in the system by ensuring that even when the cloud is involved, the delay is minimized.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary for live subtitle processing. Specifically, decide if low-latency critical data (e.g., speaker ID, initial context) should always stay on the phone and only higher latency or less critical data (e.g., full transcript text) can fall back to the cloud.

3. **Likely payoff**

   By maintaining real-time subtitle quality, we enhance the wearer's trust in the system during live interactions, which is crucial for daily-use value and core mission success. This reduces the risk of dropped or delayed subtitles breaking the user experience.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

1. **Why it benefits the core**

   By defining a clear visual hierarchy that prioritizes subtitles over one-line support, we ensure the wearer can focus on understanding live conversation without information overload. This improves subtitle clarity and trust, aligning with the primary attractor of real-time subtitle clarity.

2. **What small change unlocks it**

   Define a visual priority rule where subtitles are always displayed prominently, while one-line prompts are hidden or shown in a less intrusive manner when not necessary for understanding. This ensures that critical information is always visible and easily readable.

3. **Likely payoff**

   The payoff includes improved trust in the subtitle system as the wearer can focus on live conversation without being distracted by additional prompts. This reduces cognitive load and enhances overall comprehension during interactions, thereby reinforcing the core mission of the product.

4. **Immediate next probe**
