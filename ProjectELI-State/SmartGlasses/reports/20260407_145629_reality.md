# Reality Check for SmartGlasses Project

## Subtitle Clarity (Subtitle Placement)
- **Feasible Now:** 
  - The `TranscriptLab` app provides a good test bed to ensure subtitles are clear, fast, and stable enough. Focus on optimizing the subtitle display to be readable in noisy environments.
  
## Memory Trust (Face/Name Recall and Prior Context)
- **Feasible Later:**
  - Implement basic face/name memory with confidence objects and reinforcement learning. This can start as a simple offline process but should evolve over time, especially after more data is gathered.

## Low Friction Assistance
- **Feasible Now:** 
  - Introduce one-line prompts in the `TranscriptLab` app to ensure they are low-friction and do not create command overhead or social awkwardness. 

## Privacy vs Usefulness
- **Constraint Pressure:**
  - Ensure that memory and confidence behavior respect privacy constraints. Avoid creating false certainty or corrupted recall, which can erode trust.

## Latency vs Richness
- **Constraint Pressure:**
  - Prioritize real-time subtitles over richer but slower processing. Delays should be minimized to keep the wearer's experience seamless.

## Discreet UX vs Visual Clarity
- **Constraint Pressure:**
  - Balance between discreet behavior and visual clarity, ensuring that subtitles are readable in motion and noise without becoming distracting.

## Frame-Touch-Only V1 Interaction
- **Feasible Now:** 
  - Focus on refining the frame-touch interactions to ensure they meet the needs of V1. Avoid adding voice commands for now.

## Phone-First Runtime
- **Feasible Now:**
  - Continue with the phone-first approach, leveraging the `TranscriptLab` app to test and refine real-time transcript behavior before moving to glasses hardware.

## Core Deepening Over Sprawl
- **Core Deepening:**
  - Prioritize subtitle quality, memory trust, and visual UX improvements over broad feature expansion. This ensures the core mission remains strong.

## Current Unknowns
- **Subtitle Placement:** 
  - Use the `TranscriptLab` app to test different subtitle placements and determine what is most usable without becoming distracting.
  
- **Confidence Display:**
  - Test various confidence display formats (label only, label + short reason) in the `TranscriptLab` app to see which builds trust best.

- **Memory/Caching Policy:** 
  - Start with basic offline memory caching and gradually expand as more data is collected and tested.

## Phone/Cloud Boundary
- **Feasible Now:**
  - Keep heavy processing on the phone, using cloud support where clearly justified. The `TranscriptLab` app can help validate this boundary.

### Conclusions

1. **Subtitle Clarity:** Continue refining subtitle placement in `TranscriptLab`.
2. **Memory Trust:** Implement basic memory and confidence mechanisms but test thoroughly to avoid privacy issues.
3. **Low Friction Assistance:** Introduce one-line prompts in the app to ensure they are user-friendly.
4. **Privacy vs Usefulness:** Ensure that any memory or confidence behavior respects privacy constraints.
5. **Latency vs Richness:** Prioritize real-time subtitles over richer but slower processing.
6. **Discreet UX vs Visual Clarity:** Balance between discreet behavior and visual clarity in the app.
7. **Frame-Touch-Only V1 Interaction:** Focus on refining frame-touch interactions without adding voice commands.
8. **Phone-First Runtime:** Use `TranscriptLab` to test real-time transcript behavior.
9. **Core Deepening Over Sprawl:** Prioritize subtitle quality, memory trust, and visual UX improvements.

### Recommendations

  - Test different placement options in the `TranscriptLab` app.
  
- **Confidence Display:**

- **Memory/Caching Policy:**
