# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now
- **Subtitle Visibility**: Ensure subtitles are readable but not overly distracting in various environments (e.g., noisy, bright). The current TranscriptLab app can be used to test different subtitle placements and ensure they remain clear and stable.
- **Visual Clarity**: Test subtitle placement to balance readability with social acceptability. For example, placing subtitles below the frame or near the earpiece could minimize distractions while ensuring text is legible.

## Confidence Display: Feasible Now
- **Label + Short Reason**: Implement a confidence display that provides both a label (e.g., "High," "Medium," "Low") and a short reason if possible. This approach ensures clarity without overwhelming the wearer.
- **User Testing**: Use the TranscriptLab app to conduct user tests on different confidence formats to see which one builds trust best.

## Memory/Cache Policy: Feasible Later
- **Local Cache for Face/Name Recognition**: Given the current constraint of phone-first processing, plan to cache basic face and name information locally. This can be explored as a future feature where the phone stores limited memory data that can be quickly looked up.
- **Incremental Memory Updates**: Allow the system to update its local cache incrementally over time, ensuring that new memories are reinforced but not overwhelming.

## Phone/Cloud Boundary: Feasible Now
- **Phone Handling Heavy Processing**: Continue focusing on making heavy processing happen primarily on the phone. Use cloud services only where clearly justified by latency or other constraints.
- **Offline Mode Testing**: Implement and test offline mode to ensure core functionalities can run without internet connectivity, aligning with V1 interaction being frame-touch-only.

## Visual Hierarchy: Feasible Later
- **Design Guidelines**: While not yet critical, start designing guidelines for how subtitles and prompts coexist visually. This ensures that the final product remains user-friendly.
- **Prototyping**: Use mockups or early prototypes to explore different visual hierarchy options before implementing them in the actual app.
