# Consolidation of Recent Project Signals for SmartGlasses V1

## Core Mission Reinforcement
The system should continue focusing on real-time subtitles, face/name recall, conversation memory, and one-line support to assist users in noisy or complex environments without overburdening them.

### Strengthened Signals:
- **Subtitle Quality**: Subtitles must be near-real-time and accurate to maintain user trust.
- **Memory Trust**: Memory for names and prior conversations should build confidence over time through explicit reinforcement mechanisms.
- **Visual UX**: Subtitle placement, visual hierarchy, and confidence display should prioritize clarity without being distracting.

### Weakened Signals:
- **Interaction Complexity**: Interaction should remain simple with frame touches; avoiding voice activation or command controls in V1.

## Core Tensions
Key tensions persist around subtitle quality, memory trust, confidence representation, fast lookup, privacy, battery, latency, and visual UX. These must be continuously addressed to ensure the system remains useful without compromising on these critical factors.

### Concrete Tensions:
- **Subtitle Quality vs Battery Drain**: Strive for real-time subtitles while minimizing energy consumption.
- **Memory Trust vs Privacy Perception**: Balance between providing robust memory support and respecting user privacy concerns.
- **Always-On Sensing vs Battery and Thermals**: Optimize for continuous operation without overheating or excessive battery drain.
- **Rich Memory vs Fast Lookup**: Ensure both detailed context and quick access to essential information.

## Open Questions
Several open questions remain regarding subtitle placement, confidence display format, memory caching policy, interaction offline capabilities, and the balance between rich context and low-latency responses. These need further exploration to refine V1 design decisions.

### Key Questions:
- **Subtitle Placement**: What is the most usable subtitle placement without becoming distracting?
- **Confidence Format**: How should confidence be displayed—label only, label + short reason, or score + label?
- **Memory Caching**: How much face/name memory should be cached locally on the phone to balance offline functionality and privacy?
- **Interaction Offline Capabilities**: Which interactions should work offline versus requiring cloud support?

## Reality Rules
The project must remain grounded in real-world constraints and avoid overbuilding complex features. Early versions should focus on providing core utility without sacrificing battery, thermals, or social acceptability.

### Key Realities:
- **Phone-First Architecture**: Rely primarily on the phone for processing to manage thermal and battery issues.
- **Frame Touch Interaction**: Ensure all interactions are frame touch-based; avoid voice commands in V1.
- **Battery Management**: Prioritize design choices that minimize energy consumption, especially for always-on features like subtitles.
