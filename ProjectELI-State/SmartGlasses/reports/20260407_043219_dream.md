### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules based on confidence state will ensure that subtitles are positioned in a way that maximizes readability without causing distraction. This enhances the wearer's ability to follow live conversations, thereby improving real-time subtitle clarity and trust.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence matches (e.g., known names or frequently encountered people) and another for low-confidence matches (e.g., new faces or less familiar voices). The high-confidence mode could place subtitles slightly above the speaker's face, while the low-confidence mode could position them more centrally on the screen.

3. **Likely payoff**

   By tailoring subtitle placement to confidence levels, we can improve the wearer’s ability to focus on the conversation without being distracted by poorly placed text. This will enhance the overall user experience and trust in the system's real-time captioning capabilities.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display in V1 will enhance trust in the system's memory support and overall reliability. By clearly showing the wearer when information is uncertain, we reduce social awkwardness and improve the perceived honesty of the product.

2. **What small change unlocks it**

   Define a simple but effective confidence format that includes both a numeric score and a short reason for its accuracy level. For example: "score 0.84 + 'High' + 'Seen recently'".

3. **Likely payoff**

   By implementing a clear, concise confidence display, the system will appear more honest and reliable to users. This can lead to increased user trust and better overall acceptance of the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a specific local cache size limit for face/name memory, the system can ensure that only the most relevant and frequently accessed information is retained on-device. This reduces the risk of privacy breaches while maintaining useful memory support.

2. **What small change unlocks it**

   Define one local cache threshold for storing face/name memories, limiting the number of entities cached to a value between 50 and 100.

3. **Likely payoff**

   Implementing this cache size limit will help balance privacy concerns with the need for useful memory support. It ensures that only the most frequently accessed names and faces are stored locally, reducing storage needs while maintaining key assistance features.

4. **Immediate next probe**

   Define a local cache size limit of 75 entities for face/name memories.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear phone/cloud boundary for live subtitle processing, we ensure that real-time subtitles remain stable and fast, which is crucial for maintaining the wearer's trust in the system during live conversations. This focus on local processing reduces latency and battery drain, ensuring high-quality real-time support without overloading the cloud.

2. **What small change unlocks it**

   To achieve this, we can define a single rule: all subtitle-related audio data (transcription input) should be processed locally on the phone before any memory or confidence updates are sent to the cloud. This ensures that subtitles remain responsive and reliable even if cloud processing experiences delays.

3. **Likely payoff**

   By keeping real-time subtitle processing local, we significantly reduce latency, which is critical for maintaining trust and ensuring that subtitles are always up-to-date. This also helps in conserving battery life, as less data needs to be sent over the network, leading to a more seamless user experience.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a visual hierarchy rule that prioritizes subtitles over one-line prompts when both are visible simultaneously, we ensure that the wearer remains focused on critical information (subtitles) without being overwhelmed by additional text. This enhances trust and readability in noisy environments.

2. **What small change unlocks it**

   Introduce a simple precedence rule where subtitles take priority over one-line support. For example, if both are present, hide or reduce the prominence of one-line prompts to avoid visual clutter.

3. **Likely payoff**

   The wearer can focus more on understanding spoken content without being distracted by less critical text, leading to better comprehension and reduced cognitive load. This prioritization also aligns with the core attractor of low-friction assistance, ensuring that the product remains unobtrusive yet effective.

4. **Immediate next probe**

   Define one visual priority rule between subtitles and one-line support, where subtitles take precedence over one-line prompts when both are visible simultaneously.
