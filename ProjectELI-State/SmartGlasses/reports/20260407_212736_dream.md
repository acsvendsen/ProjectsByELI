### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles are always clear, stable, and unobtrusive, enhancing the wearer's trust in the system during live conversations.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules based on the confidence of the spoken words: low-confidence (e.g., uncertain names or faces), medium-confidence (e.g., known people but less certain context), and high-confidence (e.g., clear and familiar speakers).

3. **Likely payoff**

   Implementing these rules will help maintain consistent, stable subtitle placement that is not distracting yet still provides critical support during conversations. This improves the wearer's trust in the system and makes it more useful in noisy or challenging environments.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display ensures that the wearer can trust the system's assistance more effectively. By clearly indicating the certainty behind name or face recognition, the glasses help in reducing cognitive load and increasing overall understanding during interactions. This clarity is crucial for maintaining the system's role as a discreet assistant rather than an invasive tool.

2. **What small change unlocks it**

   Define a simple confidence format that includes both a numeric score and a label with a short reason. For example, "score 0.8 + 'High' + 'Seen recently'". This format provides enough detail for the wearer to understand the reliability of the memory without overwhelming them.

3. **Likely payoff**

   A clear and concise confidence display will lead to better trust in the system's memory support. Wearers can quickly assess whether a name or face recognition is likely accurate, reducing uncertainty and enhancing their confidence in the glasses' assistance during social interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local cache threshold for face/name memory on the phone, we can ensure that critical information is always readily available to the wearer without overwhelming their device's resources. This improves trust and reliability in memory support, which is a key attractor.

2. **What small change unlocks it**

   Define a specific recency rule where face/name memories are kept in local cache for at least 7 days after an encounter but not more than 30 days to balance memory freshness with storage efficiency.

3. **Likely payoff**

   This local cache threshold will ensure that the wearer can rely on accurate and recent name recall, enhancing their confidence in the system's ability to support them during interactions. It will also reduce the likelihood of forgotten names or faces, thereby improving the overall trustworthiness of memory support.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By carefully defining what stays phone-local versus what falls back to cloud for live subtitle processing, we ensure that critical real-time performance is maintained without overloading the battery or creating latency issues. This balance enhances the wearer's trust in the product by providing near-instant feedback and clear subtitles.

2. **What small change unlocks it**

   Define a single local cache size limit for face/name recall objects to ensure that frequent, high-confidence matches are kept on-device while less critical or older information is managed through cloud fallbacks.

3. **Likely payoff**

   By limiting the amount of local memory used for face/name recall, we can reduce battery drain and thermal load, ensuring that the glasses remain usable in long sessions without overheating. This also allows for faster subtitle processing and more reliable memory support during critical interactions.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles remain stable and unobtrusive during live conversations directly supports the primary attractor of real-time subtitle clarity. By optimizing subtitle placement, we enhance the wearer's ability to follow the conversation without being distracted by fluctuating or poorly placed text, thereby increasing trust in the system.

2. **What small change unlocks it**

   Define a set of static subtitle placement rules for different confidence states that minimize movement and maintain readability. For example:
   
   - High-confidence subtitles are displayed at the bottom center.
   - Medium-confidence subtitles are slightly offset to avoid overlap with high-confidence text but remain visible.
   - Low-confidence subtitles are hidden or shown in an overlay mode that does not interfere with reading.

3. **Likely payoff**

   By implementing static subtitle placement rules, we reduce eye strain and improve readability during live conversations. This stability enhances the wearer's trust in the system, aligning more closely with the attractor of real-time subtitle clarity. The reduced flickering and movement of subtitles also contribute to a cleaner visual hierarchy, further supporting the core mission.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
