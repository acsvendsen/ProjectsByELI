### Subtitle Placement
**Feasibility**: Feasible now  
**Confidence**: High

- **Current State**: The current `TranscriptLab` implementation is focused on basic real-time transcription with minimal visual clutter. This provides a good starting point.
- **Constraints**: Must remain socially acceptable, readable in motion, and stable enough for live conversation.
- **Reasoning**: Given the simplicity of the initial design, subtitle placement can be optimized further without introducing new hardware or complex interactions. Adjustments like font size, color contrast, and screen position can be made iteratively through visual testing and user feedback.

### Confidence Display
**Feasibility**: Feasible now  
**Confidence**: Medium

- **Current State**: The `TranscriptLab` app uses a simple confidence label for transcriptions. This is already in place but could benefit from more detailed reasoning.
- **Constraints**: Must expose uncertainty clearly to maintain trust and avoid overloading the wearer with too much information.
- **Reasoning**: Implementing a short reason or score next to the label can provide more nuanced feedback without overwhelming the user. This can be done incrementally based on real-world testing.

### Memory/Cache Policy
**Feasibility**: Feasible now  
**Confidence**: High

- **Current State**: The `TranscriptLab` app does not yet implement face/name memory, but this is a core feature.
- **Constraints**: Must balance local caching with cloud support to ensure fast lookup and persistence across sessions without draining the phone's battery.
- **Reasoning**: Implement basic face detection and name recall on the phone. Use cloud storage for reinforcement learning over time. This can be done incrementally, starting with simple caching strategies.

### Phone/Cloud Boundary
**Feasibility**: Feasible now
