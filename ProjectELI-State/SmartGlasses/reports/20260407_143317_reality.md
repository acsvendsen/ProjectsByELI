## Subtitle Clarity: Feasible Now

**Reasoning**: 
- The current implementation of `TranscriptLab` in the shared transcript notes has basic real-time transcription functionality.
- With minimal effort, this can be optimized for clarity and stability. Given that `TranscriptLab` is a phone-first test app, it already respects the hardware constraints and does not require heavy on-device processing.
- The project documentation and existing codebase provide enough signals to proceed with optimizing subtitles now.

## Memory Trust: Feasible Later

**Reasoning**: 
- The current implementation of memory support in `TranscriptLab` is basic. It focuses on real-time transcription rather than long-term memory storage and retrieval.
- However, the groundwork for memory trust can be laid by using a reliable phone-side state management system that persists data across sessions. This would allow for future work to focus on implementing face/name recall with confidence objects.
- The current version of `TranscriptLab` uses a simple state model that can be extended to include memory components without significant refactoring.

## Low-Friction Assistance: Feasible Now

**Reasoning**: 
- The core functionality of delivering one-line prompts is already present in the form of real-time subtitles and basic confidence displays.
- Enhancing this by adding more contextual information (e.g., quick memory recall) can be done incrementally without major changes to the existing system.
- The current implementation in `TranscriptLab` supports frame-touch interactions, which aligns with the V1 interaction constraints.

- Adding extensive privacy measures now might distract from more immediate priorities like subtitle clarity and memory support.

**Reasoning**:
