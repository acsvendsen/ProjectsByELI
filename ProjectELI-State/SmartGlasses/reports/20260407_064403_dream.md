### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that face/name memories are cached locally on the phone with a threshold-based eviction policy helps maintain privacy while providing fast recall capabilities. This approach allows the system to quickly retrieve relevant information without constantly querying the cloud, thus reducing latency and preserving battery life.

2. **What small change unlocks it**

   Define a local cache size limit for storing face/name memories based on recent interactions. This limit should be set to store only the most frequently encountered individuals over the past few sessions, ensuring that memory usage remains manageable.

3. **Likely payoff**

   By limiting the local cache size and using an eviction policy based on recency, the system can provide quick and reliable name recall during conversations while respecting privacy constraints. This approach will reduce the frequency of cloud queries, thereby saving bandwidth and battery life, and maintaining a discrete user experience.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.
