### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining fixed subtitle placement rules for different confidence states, V1 can ensure that subtitles remain stable, readable, and trustworthy during live conversations. This improves real-time subtitle clarity (subtitle_clarity) by reducing distraction and ensuring the wearer can focus on the conversation.

2. **What small change unlocks it**

   Define a set of two to three fixed subtitle placement rules for different confidence levels: high-confidence text always at the bottom center, medium-confidence text slightly below the center with a slight blur effect, and low-confidence text only appearing in the corner when necessary.

3. **Likely payoff**

   Implementing these fixed placement rules will reduce subtitle movement and ensure that even low-confidence subtitles do not distract the wearer. This stability will improve trust in the system's accuracy during live conversations, thereby enhancing real-time subtitle clarity and overall user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance the trustworthiness of both subtitles and memory support. A well-designed confidence label with a short reason will help the wearer understand the reliability of the information being displayed, ensuring they do not misinterpret uncertain data as certain.

2. **What small change unlocks it**

   Define a consistent format for confidence labels that includes a numeric score, a simple label, and a brief description of why the score is assigned. For example: "score 0.84 + 'High' + 'Seen recently'".

3. **Likely payoff**

   By providing clear and concise confidence information, users will be better equipped to trust the system's outputs in real-time interactions. This clarity reduces cognitive load and increases overall user satisfaction.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - By setting a specific local memory threshold for name recall, we can ensure that only relevant and frequently encountered names are cached locally on the phone. This helps in maintaining a balance between privacy and usefulness by reducing unnecessary storage while still providing reliable support.

2. **What small change unlocks it**
   - Define a local cache size limit for name recall based on the number of recent encounters with each person or name.

3. **Likely payoff**
   - This change will help reduce memory pressure on the phone, ensuring that only the most relevant names are stored locally. It will also enhance privacy by limiting the amount of data retained without compromising on the quality and reliability of face/name recall support.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific phone/cloud boundary for live subtitle processing, we ensure that subtitles remain real-time and stable, which is crucial for maintaining trust in V1. This focus helps balance the need for always-on functionality with the constraints of battery and thermal management.

2. **What small change unlocks it**

   Define a rule that all live subtitle processing must run locally on the phone without falling back to the cloud until the transcript is finalized. This ensures minimal latency and stable performance, even under varying conditions.

3. **Likely payoff**

   By keeping subtitle processing local, we reduce battery drain and ensure consistent subtitle delivery. This will enhance user trust by providing timely and reliable subtitles in noisy environments, aligning with the core attractor of real-time subtitle clarity.

4. **Immediate next probe**
   - Define a rule that all live subtitle processing must run locally on the phone without falling back to the cloud until the transcript is finalized.
