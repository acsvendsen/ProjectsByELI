# Recent Signals Consolidation

## Strengthening Signals
- **Subtitle Clarity**: The real-time subtitle clarity attractor is strong and remains a top priority. Ensuring subtitles are clear, fast, and stable enough to be trusted in live conversations will enhance the wearer's confidence.
- **Memory Trust**: Trustworthy memory support for names, faces, and prior context continues to be crucial. This ensures that the system does not overcommit or create false certainty, maintaining user trust.

## Weakening Signals
- **Low-Friction Assistance**: The low-friction assistance attractor is medium strength but shows signs of weakening compared to other core attributes. While it remains important, it has seen less emphasis in recent work.

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness**: This tension must remain alive and balanced as the project progresses. It's essential to ensure that assistive features do not inadvertently compromise privacy.
- **Latency vs Richness**: The need for timely responses versus richer but slower processing remains a critical balance.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement**: There is an open question about what subtitle placement is most usable without becoming distracting. This idea should be revisited to ensure the subtitles remain useful and not overly intrusive.
- **Confidence Display**: The confidence format that builds trust best (label only, label + short reason, or score + label) needs further exploration.

## Concrete Tensions Around Subtitle Quality, Confidence Trust, Automatic New-Person Memory, Memory Reinforcement, Fast Lookup, Privacy, Battery, Latency, and Visual UX
- **Subtitle Quality**: Continuously work on improving subtitle clarity to ensure they are clear, fast, and stable.
- **Confidence Trust**: Ensure confidence displays are accurate and transparent to build user trust. Consider different formats (label only, label + short reason) for optimal results.
- **Automatic New-Person Memory**: Develop a system that can remember new faces and names with confidence objects and reinforcement over time.
- **Memory Reinforcement**: Focus on how memory should be stored and reinforced for fast lookup and trust.
- **Fast Lookup**: Balance the need for quick access to previously learned information without overwhelming the user.
- **Privacy**: Ensure that any assistive behavior does not quietly slide into invasive capture or retention.
- **Battery**: Continuously manage battery usage, especially given the always-on sensing requirements.
- **Latency**: Prioritize timely responses to maintain trust but be mindful of computational load.
- **Visual UX**: Design subtitles and one-line prompts in a way that is readable yet unobtrusive.

## No Fluff
- The project should continuously surface real-world limitations early, including hardware, battery, thermal, latency, privacy, and usability constraints. These limits must be addressed promptly to avoid wasting development time on impractical directions.
- Focus on core-deepening work over broad feature expansion unless the project docs justify a broader move.
