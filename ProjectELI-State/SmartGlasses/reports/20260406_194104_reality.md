# Reality Check for SmartGlasses V1 Direction

## Subtitle Clarity

**Subtitle Placement**
- **Feasibility:** Feasible now.
  - **Reasoning:** The `TranscriptLab` app provides a robust test bed for subtitle placement. Early iterations can focus on clear, readable text without complex AR overlays or high thermal demands. Given the current hardware constraints, placing subtitles in the lower third of the frame is practical and low-impact.

**Subtitle Latency**
- **Feasibility:** Feasible now.
  - **Reasoning:** The `TranscriptLab` app already includes partial and final transcript behavior. Real-time text updates can be prioritized to ensure minimal latency, allowing the wearer to trust the subtitles in live conversations.

## Memory Trust

**Face/Name Memory Storage**
- **Feasibility:** Feasible later.
  - **Reasoning:** Current `TranscriptLab` focuses on real-time subtitle behavior. Implementing memory storage and recall will require more complex interactions with the phone runtime, which is a future task given V1 constraints.

**Reinforcement Rules for Memory**
- **Feasibility:** Likely waste of time at this stage.
  - **Reasoning:** Reinforcement rules are too early to implement in V1. The focus should be on getting basic memory recall working first before worrying about reinforcement and optimization over time.

## Low-Friction Assistance

**One-Line Prompt Coexistence**
- **Feasibility:** Feasible now.
  - **Reasoning:** One-line prompts can coexist with subtitles by using a different color or format. The `TranscriptLab` app allows for the design of both elements without overwhelming the wearer.

**Confidence Display Format**
- **Feasibility:** Feasible later.
  - **Reasoning:** Confidence display needs to be tested in real-world scenarios but can initially focus on simple, readable labels (e.g., "High", "Low") before adding more complex feedback mechanisms.

## Privacy vs Usefulness

**Privacy Considerations for Memory**
- **Feasibility:** Feasible now.
  - **Reasoning:** Initial memory recall should be non-invasive and context-driven. The `TranscriptLab` can help prototype these interactions to ensure they do not overstep privacy boundaries.

## Latency vs Richness

**Subtitle Real-Time Behavior**
- **Feasibility:** Feasible now.
  - **Reasoning:** The `TranscriptLab` app already tests real-time transcription, which is critical for subtitle clarity. Initial efforts should focus on ensuring this behavior remains stable and reliable.

## Discreet UX vs Visual Clarity

**Frame-Touch Interaction**
- **Feasibility:** Feasible now.
  - **Reasoning:** The `TranscriptLab` can simulate frame-touch interactions, allowing early design iterations to focus on low-friction, touch-based user controls. This will help ensure that V1 interactions remain simple and intuitive.

## Implementation Grounding

**Core-Deepening Over Sprawl**
- **Feasibility:** Feasible now.
  - **Reasoning:** Given the current constraints, it is important to prioritize core features like subtitle clarity and memory support over broad feature expansion. The `TranscriptLab` app can serve as a ground truth for these improvements.

## Summary of Findings

### Feasible Now
- Subtitle placement
- Subtitle latency
- One-line prompt coexistence
- Frame-touch interaction

### Feasible Later
- Memory storage and recall
- Confidence display format optimization

### Likely Waste of Time
- Reinforcement rules for memory

By focusing on these areas, the project can ensure that V1 remains grounded in real-world constraints while setting a clear path for future improvements.
