# Reality Check for SmartGlasses Project

## Subtitle Clarity (subtitle_clarity)

### Feasibility Analysis:
- **Current Open Questions**: What is the best V1 split between glasses, phone, and cloud?
- **Constraints**: Phone-first runtime, frame-touch-only interaction.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality.

**Conclusion:**
- **Feasible Now**: Given that `TranscriptLab` has been successfully built, it is feasible to start working on subtitle clarity by refining the real-time transcription algorithm in `SpeechTranscriber.swift`. This should be done within the constraints of the phone-first architecture.
- **Likely Waste of Time**: Attempting to implement advanced AR visuals or complex multimodal UIs prematurely would distract from core functionality.

## Memory Trust (memory_trust)

### Feasibility Analysis:
- **Current Open Questions**: How should face/name memory be stored and reinforced for fast lookup and trust?
- **Constraints**: Phone-first runtime, frame-touch-only interaction.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality and memory support.

**Conclusion:**
- **Feasible Now**: Implement a basic memory caching system in the `TranscriptLabModel.swift` to store recently seen faces and names. This can be extended with reinforcement learning algorithms over time but should start simple.
- **Likely Waste of Time**: Adding full-blown machine learning models for face recognition at this stage might be premature.

## Low Friction Assistance (low_friction_assistance)

### Feasibility Analysis:
- **Current Open Questions**: How should subtitles and one-line prompts coexist without overloading the wearer?
- **Constraints**: Phone-first runtime, frame-touch-only interaction.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality and memory support.

**Conclusion:**
- **Feasible Now**: Design a simple interface for delivering one-line prompts in `LiveTranscriptTestView.swift` that do not overwhelm the wearer. This can be as basic as showing text overlays that are easy to read during conversation.
- **Likely Waste of Time**: Introducing full command modes or complex UI elements at this stage would add unnecessary complexity without providing significant daily-use value.

## Phone/Cloud Boundary (phone/cloud boundary)

### Feasibility Analysis:
- **Current Open Questions**: Which V1 features produce the highest daily-use value with the lowest complexity?
- **Constraints**: Phone-first runtime, frame-touch-only interaction.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality and memory support.

**Conclusion:**
- **Feasible Now**: Ensure that all heavy processing is handled by the phone. The cloud should only be used where it clearly adds value (e.g., for model updates or background processing).
- **Likely Waste of Time**: Assuming advanced cloud capabilities like real-time face recognition will distract from achieving core functionality on the phone.

## Visual Hierarchy and Subtitle Placement

### Feasibility Analysis:
- **Current Open Questions**: What is the best subtitle placement and visual hierarchy for fast reading with low distraction?
- **Constraints**: Discreet UX vs enough visual clarity.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality and memory support.

**Conclusion:**
- **Feasible Now**: Experiment with different subtitle placements in `LiveTranscriptTestView.swift` to find the best balance between readability and distraction. Start with simple, non-intrusive placement like corner subtitles.
- **Likely Waste of Time**: Complex visual hierarchies or advanced AR effects should be deferred until core functionality is established.

## Confidence Display

### Feasibility Analysis:
- **Current Open Questions**: How should confidence be represented: numeric score, label, and short reason?
- **Constraints**: Phone-first runtime, frame-touch-only interaction.
- **Core Deepening Over Sprawl**: Focus on improving subtitle quality and memory support.

**Conclusion:**
- **Feasible Now**: Implement a simple confidence display in `LiveTranscriptTestView.swift` using labels or a combination of labels and short reasons. This can be refined over time as more data is collected.
- **Likely Waste of Time**: Adding complex multi-step UI elements to handle different levels of confidence should be deferred.

### Summary:
The current focus on improving subtitle clarity, memory trust, low-friction assistance, phone/cloud boundaries, visual hierarchy, and confidence display should proceed with the constraints in mind. These core improvements will form a solid foundation for the SmartGlasses project without overcomplicating the V1 release.
