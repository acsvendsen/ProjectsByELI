# Reality Check for SmartGlasses V1 Direction

## Core Field Overview

### Mission
Create smart glasses that act as a discreet, context-aware personal assistant focused on live subtitles, face/name recall, conversation memory, and one-line support to help the wearer understand and respond better in real-world interactions.

### Non-negotiables
- The glasses help the wearer; they do not pretend knowledge the wearer does not have.
- Early hardware remains simple: display text, record audio/visual input; phone/cloud handles heavy processing.
- V1 interaction is frame-touch only; do not assume voice activation or spoken command control.
- Context must persist across sessions.
- New faces and names should be remembered with confidence objects and reinforcement over time.
- Real-world constraints must be surfaced early: latency, battery, privacy, social acceptability, on-device limits.

### Core Attractors
- Real-time subtitle assistance in noisy environments
- Personal memory support for names and prior conversations
- One-line contextual prompts rather than overwhelming paragraphs
- Low-friction human experience; assistive, not deceptive

### Core Tensions
- Privacy vs usefulness
- Always-on sensing vs battery and thermals
- Local processing vs cloud intelligence
- Rich memory vs fast lookup
- Discreet UX vs enough visual clarity

### Drift Risks
- Becoming a gimmick instead of a daily-use assistant
- Feature sprawl before core subtitle/memory loop is excellent
- Interaction sprawl that adds command modes or hardware complexity before the touch-first V1 is excellent
- High-latency responses that break trust
- Storing low-value information instead of weighted relevant memory

## Reality Check

### Subtitle Placement and Visual Hierarchy (Subtitle Feasibility)
**Feasible Now:**
- **Positioning:** Place subtitles at the bottom center of the screen to minimize visual distraction while ensuring they are easily readable.
- **Visual Clarity:** Use a clean, sans-serif font with appropriate size and color contrast for readability without overwhelming the wearer.

**Reasoning:**
- Subtitle latency should be near-real-time (ideally <100ms) to maintain user trust.
- The visual hierarchy should prioritize clarity over complexity to ensure subtitles are quickly readable.

### Confidence Display (Confidence Feasibility)
**Feasible Now:**
- **Format:** Use a simple label format, such as "High," "Medium," or "Low," with occasional short reasons for low-confidence cases.
- **Placement:** Display confidence next to the relevant text for easy reference without overwhelming the wearer.

**Reasoning:**
- A simple, easily understandable confidence display can help build trust and provide context when needed.
- Overcomplicating this aspect could lead to visual clutter that distracts from the primary task of reading subtitles.

### Memory/Cache Policy (Memory Feasibility)
**Feasible Now:**
- **Local Storage:** Cache new faces and names locally on the phone for quick recall but ensure it is not overly complex.
- **Cloud Dependency:** Use cloud storage only as a fallback when local memory is insufficient, ensuring minimal data transfer.

**Reasoning:**
- Memory policies should be designed to balance between usability and privacy concerns.
- Automatic new-person memory with reinforcement over time can help users feel more comfortable with the system while maintaining privacy.

### Phone/Cloud Boundary (Phone/Cloud Feasibility)
**Feasible Now:**
- **Primary Function:** Keep the phone as the primary processing unit for heavy tasks such as context analysis, memory lookup, and model updates.
- **Lightweight Glasses:** Use glasses primarily for text display and minimal local logic to reduce thermal and battery pressure.

**Reasoning:**
- A phone-first architecture is practical given current hardware limitations.
- Using cloud only where it adds clear value can help manage complexity while ensuring reliability.

### Visual Hierarchy (Visual Hierarchy Feasibility)
**Feasible Now:**
- **Priority:** Ensure subtitles are displayed first, followed by confidence labels and one-line prompts if applicable.
- **Simplicity:** Keep the overall visual interface simple to avoid overwhelming the wearer with too much information at once.

**Reasoning:**
- A well-defined visual hierarchy can help users prioritize what is most important, reducing cognitive load.
- Simplifying the UI ensures that the primary function (reading subtitles) remains clear and uncluttered.

### Interaction Constraints
**Feasible Now:**
- **Frame Touches Only:** Ensure all interactions are controlled through frame touches to maintain simplicity and low-friction use.
- **Avoid Voice Activation:** Do not assume voice activation or spoken command control for subtitle management, mode switching, or confirmations in V1.

**Reasoning:**
- Frame-touch interaction is a practical constraint given the current hardware limitations.
- Voice commands can be explored as a future feature but should not complicate the initial design.

### Drift Risks
- **Feature Sprawl:** Focus on core functionalities (subtitles, memory, one-line prompts) before expanding into more complex features.
- **Interaction Complexity:** Maintain simplicity in interactions to avoid overwhelming users and reducing overall usability.

**Reasoning:**
- Early iterations should focus on delivering high-value, low-complexity features.
- Overcomplicating the initial design can lead to user dissatisfaction and reduced adoption.

### Persistent Unknowns
- **Subtitle Placement:** Further testing is needed to determine the most effective placement that minimizes distraction while ensuring readability.
- **Confidence Format:** User feedback should inform the best format for confidence display, considering both usability and trust.
- **Memory Policy:** The balance between local storage and cloud dependency requires further exploration based on user needs.

**Reasoning:**
- These unknowns need concrete testing to validate initial assumptions.
- Relying on user feedback can help refine these aspects over time while maintaining focus on core functionalities.

## Conclusions

The current V1 direction is feasible now, given the constraints and non-negotiables. Focusing on essential features like real-time subtitles, simple confidence display, and frame-touch interactions will ensure a practical and effective initial release. However, ongoing testing and user feedback are crucial to refine these aspects further.

### Actions
- **Subtitle Placement:** Conduct usability tests with different subtitle placements.
- **Confidence Display:** Gather user feedback on various confidence formats.
- **Memory Policy:** Implement local caching strategies for new faces/names while considering cloud fallbacks.

By addressing these specific areas, the project can continue to evolve while maintaining a focus on delivering high-value, low-friction features.
