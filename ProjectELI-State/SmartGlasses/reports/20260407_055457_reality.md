# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now

- **Subtitle Placement**: The subtitle placement should balance readability with social acceptability.
  - **Feasibility**: Given the current hardware constraints, subtitles placed at the bottom of the display are likely feasible. This position allows for a clean look and minimizes distraction while remaining accessible to the wearer.
  - **Constraints**: Frame-touch-only V1 interaction limits where subtitles can be positioned without creating additional visual clutter.

## Confidence Display: Feasible Later

- **Confidence Display**: Implementing confidence indicators (e.g., labels or scores) should be considered later when subtitle clarity and memory trust are well-established.
  - **Feasibility**: Adding a confidence label or score now could introduce unnecessary complexity. The primary focus should be on ensuring the subtitles themselves are clear, stable, and fast enough to gain user trust.
  - **Constraints**: The project is currently in "core deepening" mode, focusing on subtitle clarity, memory support, and low-friction assistance.

## Memory/Cache Policy: Feasible Later

- **Memory/Caching Policy**: Implementing local caching for face/name recognition should be a later focus once the core subtitle and memory loops are well-defined.
  - **Feasibility**: Early versions can rely heavily on phone processing. Local caching introduces complexity early, which may not yield significant benefits in V1 given the current constraints.
  - **Constraints**: The system should remain simple in V1 to ensure real-time performance.

## Phone/Cloud Boundary: Feasible Now

- **Phone/Cloud Boundary**: The glasses should primarily rely on the phone for processing while using cloud services where clearly justified.
  - **Feasibility**: Given the current hardware constraints, this boundary is feasible. Early versions should focus on keeping the glasses simple and relying on the phone's capabilities.
  - **Constraints**: Glasses hardware remains lightweight and socially acceptable in V1.

## Visual Hierarchy: Feasible Now

- **Visual Hierarchy**: The visual hierarchy for displaying subtitles and one-line prompts should be designed to ensure clarity without overloading the wearer.
  - **Feasibility**: Designing a simple, clean interface is feasible now. This can be iterated upon as the core functionality stabilizes.
  - **Constraints**: V1 interaction should remain frame-touch only.

## Assumptions Needing Evidence

- **Subtitle Placement and Visual Hierarchy**: While subtitle placement at the bottom of the display seems feasible, concrete user testing would help validate this assumption.
- **Confidence Display**: Implementing confidence indicators now may be premature. More focus on real-time subtitle quality should come first, followed by user feedback to determine if and how confidence indicators are needed.

## Summary

The project is currently in a "core deepening" mode, focusing on improving subtitle clarity, memory support, and low-friction assistance. Here’s the breakdown of feasibility based on current constraints:

- **Subtitle Placement**: Feasible now.
- **Confidence Display**: Feasible later once core functionality is solidified.
- **Memory/Caching Policy**: Feasible later as well.
- **Phone/Cloud Boundary**: Feasible now.
- **Visual Hierarchy**: Feasible now.

This approach ensures that the project remains focused on its core mission while addressing real-world constraints early.
