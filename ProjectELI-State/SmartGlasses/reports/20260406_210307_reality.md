# Reality Check Summary

Based on the provided inputs and constraints, here is a reality check for the proposed directions:

## Subtitle Placement
- **Feasible Now**: The glasses should prioritize subtitle placement that keeps subtitles readable without becoming distracting. A good starting point could be placing subtitles slightly below the center of the frame or off to one side. This needs further testing but can start with this baseline.
  - Reasoning: Initial testing in `TranscriptLab` can help determine optimal placement.

## Confidence Display
- **Feasible Now**: The confidence display should use a simple label format, e.g., "likely," "possibly," or "uncertain." This avoids overloading the wearer and ensures clarity.
  - Reasoning: Simple labels are less visually intrusive and easier to process quickly. More complex displays can be evaluated later if needed.

## Memory/Cache Policy
- **Feasible Now**: Face/name memory should be cached locally on the phone with a limited capacity (e.g., recent interactions, known faces). This ensures faster lookup times and reduces cloud dependency.
  - Reasoning: Local caching aligns with V1 constraints of minimal local logic and heavy reliance on the phone for processing.

## Phone/Cloud Boundary
- **Feasible Now**: The system should primarily rely on the phone for processing. Cloud interaction should be optional where it clearly adds value (e.g., model updates, background processing).
  - Reasoning: This aligns with V1 real-world limits and keeps early hardware simple.

## Visual Hierarchy
- **Feasible Now**: Subtitles and one-line prompts should coexist without overwhelming the wearer. One approach could be using a different color for subtitles compared to prompts, or varying their display duration.
  - Reasoning: Clear visual distinction helps in prioritizing information without causing cognitive overload.

### Additional Feasibility Comments

- **Subtitle Clarity**: The current focus on real-time clarity is critical but needs concrete testing. `TranscriptLab` can provide a practical starting point for optimizing subtitle quality.
  - **Assumptions Needing Evidence**: Further testing with actual content and noise levels to ensure subtitles remain readable and stable.

- **Memory Trust**: Memory support should be designed to avoid creating false certainty, which is essential for user trust. This could involve implementing a confidence score or label that indicates the reliability of name/face recall.
  - **Assumptions Needing Evidence**: Implementing and testing various memory reinforcement strategies to ensure they do not lead to false positives.

- **Low-Friction Assistance**: One-line prompts should be concise and non-intrusive. This can be achieved by limiting the frequency and providing only relevant, contextual information.
  - **Assumptions Needing Evidence**: Conducting user tests with real-world scenarios to gauge how much and what type of assistance is most beneficial.

### Likely Waste of Time

- **Assuming Voice Activation in V1**: Given the current constraint that interaction should be frame-touch-only, assuming voice activation now could lead to unnecessary complexity without adding immediate value.
  - **Reasoning**: This assumption may distract from core deepening and does not align with current constraints.

By focusing on these specific areas and adhering to the defined constraints, the project can ensure it remains grounded in real-world limitations while continuously improving its core functionality.
