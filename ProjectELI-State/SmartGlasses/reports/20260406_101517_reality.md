# Core Field: SmartGlasses Core Field

## Feasibility Assessment

### Current Open Questions
1. **What is the best V1 split between glasses, phone, and cloud?**
   - **Feasible Now**: Start with minimal local processing on the glasses for real-time subtitle rendering and basic facial recognition. Offload complex tasks like heavy computational work (e.g., face/name memory training) to the phone or cloud.
   
2. **How should face/name memory be stored and reinforced for fast lookup and trust?**
   - **Feasible Now**: Use local storage on glasses for immediate recall, with periodic synchronization to the cloud. Implement a simple reinforcement system where users can confirm correct memories.
   - **Assumptions Needing Evidence**: Validate that real-time updates are feasible without excessive battery drain.

3. **How should confidence be represented: numeric score, label, and short reason?**
   - **Feasible Now**: Use a label with a brief explanation (e.g., "likely," "possibly"). Avoid complex numbers to keep the UI simple.
   
4. **How should subtitles and one-line prompts coexist without overloading the wearer?**
   - **Feasible Now**: Designate separate areas in the field of view for different types of information, ensuring that subtitles are always visible while prompts can be shown as needed but not too frequently.
   - **Assumptions Needing Evidence**: Conduct user testing to determine optimal placement and frequency.

5. **Which V1 features produce the highest daily-use value with the lowest complexity?**
   - **Feasible Now**: Prioritize real-time subtitles for noisy environments, followed by basic face/name recall. More advanced features like conversation memory can be added in later versions.
   - **Assumptions Needing Evidence**: Quantify user needs and prioritize based on feedback.

### Feasibility Analysis

#### Hardware
- **Display Text**: Current AR glasses hardware supports real-time text rendering within acceptable power consumption limits.
- **Record Audio/Visual Input**: Cloud-based processing can handle recording without significant thermal issues.

#### Battery
- **Simple Display and Basic Processing**: Early designs should focus on minimizing power consumption by offloading heavy tasks to the cloud, ensuring that battery life remains manageable.

#### Latency
- **Real-time Subtitles**: Low latency is critical; initial implementations should leverage local processing for real-time text rendering.
- **Face/Name Recognition**: Cloud-based processing can handle higher latency but must ensure quick feedback loops for user trust.

#### Privacy
- **Local Storage and Synchronization**: Use encrypted storage and secure synchronization protocols to protect user data. Provide clear privacy controls in the UI.

#### Social Acceptability
- **Discreet UX**: Design the glasses with a minimalistic aesthetic that blends into various social settings, avoiding excessive complexity or conspicuous features.

#### Manufacturability
- **Simple Hardware**: Early versions should focus on offloading complex processing to reduce manufacturing costs and simplify production.

#### Software Complexity
- **Focused Features**: Start with essential functionalities (real-time subtitles, basic face/name recall) to minimize initial software development and testing efforts.

### Likely Waste of Time

1. **Complex Local Processing**: Attempting heavy local processing for all features initially may lead to excessive battery drain and thermal issues.
2. **Advanced Memory Systems**: Developing highly sophisticated memory systems with deep learning capabilities might be premature, especially without clear validation of user needs.

### Assumptions Needing Evidence

- **User Acceptance of Minimal UI Elements**: Conduct initial user testing to ensure that the proposed design elements (e.g., placement of subtitles and prompts) meet real-world user expectations.
- **Accuracy of Face/Name Recognition**: Validate through pilot studies if local storage for face/name recognition is effective in maintaining high accuracy while managing battery consumption.

### Reality-check Rule

Ensure that all features are grounded in practical limitations. Early iterations should focus on basic but essential functionalities to build a solid foundation before adding more complex features.
