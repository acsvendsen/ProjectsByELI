### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining clear subtitle placement rules for different confidence states, we can ensure that subtitles remain readable and stable without becoming distracting. This improves the wearer's trust in the system by maintaining a consistent and reliable visual presentation.

2. **What small change unlocks it**

   Define 3 to 5 subtitle placement rules based on confidence levels: high (always visible), medium (conditional visibility, e.g., when speaker changes or context is uncertain), and low (hidden or minimally displayed).

3. **Likely payoff**

   Clear and consistent subtitle placement will enhance the wearer's trust in the system, making it more useful and less distracting during conversations. This will lead to a better user experience and increased daily-use value.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances the wearer's trust in the system by clearly indicating the certainty of the information provided. A well-designed confidence object helps the wearer understand when they can rely on the subtitles or memory support, which is crucial for maintaining their focus and comprehension during conversations.

2. **What small change unlocks it**

   Define a simple confidence format that includes a numeric score, label, and short reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**

   By providing clear and concise confidence information, the system can reduce cognitive load on the wearer. This reduces the chance of misunderstandings and increases overall trust in the assistance provided by the glasses.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we can ensure that frequently mentioned people are always available quickly and accurately in memory lookups. This reduces latency and improves the reliability of face/name recognition, thereby enhancing the wearer's trust in the system without compromising battery life or privacy.

2. **What small change unlocks it**

   Define a local cache threshold for name recall where names seen more than 5 times are stored locally on the phone with a recency limit of 30 days.

3. **Likely payoff**

   This cache policy will provide fast and accurate face/name recognition, reducing the need for frequent cloud requests and minimizing battery usage. It will also ensure that common names are always available quickly, enhancing the overall user experience and trust in the system's memory capabilities.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for which tasks run on the phone versus falling back to the cloud, we can ensure that real-time subtitle processing and one-line prompts are handled promptly without draining battery or causing thermal issues. This will maintain trust and usability while leveraging cloud resources only when absolutely necessary.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing where critical real-time decisions (e.g., initial text placement, stability checks) run locally on the phone. For less time-sensitive tasks like transcript cleanup or memory archive sync, fall back to the cloud.

3. **Likely payoff**

   This approach will enhance user trust by ensuring that subtitles and one-line prompts are delivered quickly and stably. It also optimizes battery usage and thermal management, preventing overheating issues during long sessions. The clear task boundary will help maintain a low-friction UX without sacrificing assistive functionality.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

By defining a clear visual hierarchy rule between subtitles and one-line support, we ensure that the most critical information is always easily accessible while minimizing visual clutter. This enhances trust by maintaining clarity in live conversations, which aligns directly with the "Real-time subtitle clarity" attractor.

2. **What small change unlocks it**

Define a priority rule where one-line prompts are suppressed when subtitles are active and visible, and vice versa. This ensures that neither type of information overpowers the other, providing a balanced visual experience.

3. **Likely payoff**

This rule will reduce visual overlap and distraction, improving the overall clarity and readability of both subtitle text and one-line support. It will help maintain trust by ensuring that critical real-time information is not obscured by less necessary prompts, thereby enhancing the wearer's ability to focus on the conversation.

4. **Immediate next probe**

Define a priority rule where subtitles have higher visual precedence over one-line prompts when both are active simultaneously.
