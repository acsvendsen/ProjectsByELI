### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement helps maintain trust by preventing distracting movements that could interrupt the wearer's attention during live conversations. Stable, predictable subtitle placement allows the system to deliver real-time clarity consistently, which is crucial for the wearer's understanding and confidence.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule based on the bottom center of the field of view (FOV) that applies universally across different confidence states, ensuring subtitles do not jump around or become too visible in noisy environments.

3. **Likely payoff**

   By maintaining stable subtitle placement, the system will reduce cognitive load and distraction for the wearer during live interactions, thereby enhancing overall trust and understanding. This stability also makes it easier to read subtitles without losing focus on the conversation.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format, we can ensure that the system's certainty about names and faces is clear and trustworthy to the wearer. This improves memory trust, a primary attractor for the project.

2. **What small change unlocks it**

   Define a confidence object that includes both a numeric score (e.g., 0.84) and a short reason (e.g., "Seen recently"). This format allows the system to convey its level of certainty in a concise, understandable way without being overly narrative or complex.

3. **Likely payoff**

   The likely payoff is improved user trust in memory recall. When the wearer sees that a name has been seen "recently," they are more likely to remember and correctly identify the person, enhancing the overall assistive value of the system.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds helps ensure that critical information, such as names and recent contexts, are available quickly without overloading the phone's storage or causing unnecessary cloud requests. This reinforces trust by making sure the system is reliable and responsive.

2. **What small change unlocks it**

   Define a local cache size limit for face and name memory objects, ensuring that only recently seen individuals and critical context remain cached on the phone for fast lookup. For example, set a threshold of 10 recent faces and names to be stored locally with quick access.

3. **Likely payoff**

   By setting a clear threshold for local cache size, the system can maintain efficient memory management while ensuring that key information is readily available. This reduces latency, improves trust in memory recall, and keeps the phone from overloading due to excessive data storage.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that V1 remains focused on providing real-time, low-latency subtitle assistance and memory support without overburdening the glasses hardware or draining the battery.

2. **What small change unlocks it**

   Define a single task-specific cloud fallback boundary for live subtitle processing. This means deciding which parts of subtitle generation can be processed locally to ensure fast response times, while other parts that might require more complex processing are offloaded to the phone when necessary.

3. **Likely payoff**

   By keeping subtitle processing local and only using the cloud as a fallback, we can maintain low latency and high clarity in subtitles, which directly supports the core attractor of real-time subtitle clarity. This approach also ensures that the system remains lightweight and socially acceptable, adhering to the constraints on battery and always-on sensing.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

3. **Likely payoff**

4. **Immediate next probe**
