### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules that prioritize readability without becoming distracting helps maintain trust in real-time subtitles. Stable and predictable placement minimizes cognitive load, allowing the wearer to focus more on the conversation rather than adjusting or re-reading subtitles.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule for different confidence states: 
   - High confidence: Place subtitles at the bottom of the frame.
   - Medium confidence: Position subtitles in a less prominent corner.
   - Low confidence: Display subtitles as short, semi-transparent text on the side.

3. **Likely payoff**

   By defining stable rules, the system can reduce the need for frequent repositioning or scrolling to read subtitles, which improves overall usability and trust in the subtitle feature. This stability also helps in creating a more predictable visual experience, reducing cognitive load during real-time interactions.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format to use a score + label + short reason combination, we can ensure that the wearer gets clear, concise, and trustworthy feedback on the reliability of each piece of memory or subtitle information. This improves the overall trustworthiness of the system without overwhelming the user with too much detail.

2. **What small change unlocks it**

   Update the confidence display to use a numeric score + label (e.g., "High," "Medium," "Low") and a short reason (e.g., "Seen recently," "Weak match," "Name heard once in introduction"). This change provides a clear and consistent format that can be easily understood by the wearer.

3. **Likely payoff**

   The likely payoff is an increase in user trust as they can quickly understand the reliability of each piece of information. This clarity will help the wearer to better focus on important details without being distracted by uncertain or less relevant information, thereby enhancing their overall experience and confidence in using the system.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall, we can ensure that frequently encountered names are quickly accessible even when internet connectivity is limited or offline. This improves trust and reliability by reducing latency in memory lookups, which is crucial for maintaining the real-time subtitle assistance.

2. **What small change unlocks it**

   Define a local-cache size limit of 50-100 entries for frequently encountered names, ensuring that these names are cached on the phone to be quickly accessible without relying on cloud sync.

3. **Likely payoff**

   This caching strategy will reduce memory lookup latency by at least 200ms in most cases, improving the overall user experience and trust in the system's reliability during live conversations. It also ensures that common names are always readily available, enhancing the assistive value of the glasses.

4. **Immediate next probe**

   Set a local-cache size limit of 75 entries for frequently encountered names to balance memory use with lookup speed.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud, we ensure that V1 interactions remain simple and low-friction while still leveraging powerful backend capabilities where needed. This balance helps maintain the core attractor of "Low-friction assistance" by keeping user commands straightforward and responsive.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing that stays phone-local, such as real-time speech-to-text conversion, while moving transcript cleanup and memory archive sync to cloud where necessary.

3. **Likely payoff**

   By maintaining a clear local/cloud split for live subtitle processing, we can ensure the subtitle generation is near-real-time and reliable, enhancing trust and usability without overwhelming the phone's resources or compromising privacy. This approach also allows us to focus on refining the local subtitle quality and stability in V1.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
