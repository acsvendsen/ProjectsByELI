# Reality Check

## Subtitle Placement: Feasible Now
- **Subtitle Clarity**: The subtitle placement should be designed to remain readable, stable, and trustworthy in live conversations. Given the current constraints of V1 frame-touch interaction (no voice commands), subtitles need to be easily accessible but not overly distracting.
  - **Conclusion**: Feasible now. Current implementations like `TranscriptLab` provide a good starting point for testing subtitle placement.

## Confidence Display: Feasible Now
- **Confidence Behavior**: The confidence display should be clear and help build trust without overloading the wearer with too much information.
  - **Current Implementation**: `TranscriptLab` uses a simple label-based approach to show confidence, which is currently working well. Adding short reasons might provide more clarity but could add complexity.
  - **Conclusion**: Feasible now. Keep simple for V1 and consider adding short reasons in later iterations.

## Memory/Cache Policy: Feasible Later
- **Memory Support**: The memory policy should remember names, faces, and prior context without creating false certainty or corrupted recall.
  - **Current Implementation**: Initial tests are focusing on real-time transcripts. Memory support is being considered but not yet implemented.
  - **Conclusion**: Feasible later. Current focus is on subtitle clarity; memory implementation can be explored in future phases.

## Phone/Cloud Boundary: Feasible Now
- **Phone-First Runtime**: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.
  - **Current Implementation**: `TranscriptLab` is a good test bed for phone-first processing. The system currently relies heavily on the phone.
  - **Conclusion**: Feasible now. Continue to optimize the phone-side implementation.

## Visual Hierarchy: Likely Waste of Time
- **Visual Clarity**: Display behavior should remain socially acceptable while still being readable in motion and noise.
  - **Current Implementation**: `TranscriptLab` is currently focusing on subtitle clarity without adding unnecessary visual complexity.
  - **Conclusion**: Likely waste of time. Current focus should be on core functionality rather than complex visual designs.

## Frame-Touch-Only V1: Feasible Now
- **Interaction Constraints**: V1 interaction should happen through frame touches, not voice commands.
  - **Current Implementation**: `TranscriptLab` aligns with this constraint by focusing on frame-touch interactions.
  - **Conclusion**: Feasible now. Continue to refine the frame-touch interaction model.

## Privacy vs Usefulness: Feasible Now
- **Privacy Considerations**: The system should not quietly slide into invasive capture or retention without clear value.
  - **Current Implementation**: Initial implementations in `TranscriptLab` are keeping privacy in mind by focusing on real-time transcripts and minimal local processing.
  - **Conclusion**: Feasible now. Continue to prioritize privacy while building functionality.

## Latency vs Richness: Feasible Now

## Discreet UX vs Visual Clarity: Feasible Now

## Core-Deepening Over Sprawl: Feasible Now
