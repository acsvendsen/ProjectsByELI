### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules enhances the wearer's trust in real-time subtitles, making them more reliable and less distracting. Stable placement reduces cognitive load by allowing the wearer to focus on understanding the conversation rather than constantly adjusting their gaze.

2. **What small change unlocks it**

   Define a fixed subtitle placement rule that centers subtitles at the bottom of the field of view for all confidence states, ensuring they remain visible but not obstructive.

3. **Likely payoff**

   By maintaining consistent and stable subtitle placement, the system can reduce visual distractions during conversations. This stability will help maintain the wearer's focus on the conversation itself, thereby enhancing overall understanding and trust in the assistive technology.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display ensures that the wearer can trust the system's responses more effectively. By clearly and accurately showing the level of certainty in memory recall or subtitle rendering, the system maintains the wearer's trust and enhances their ability to understand and respond appropriately in real-world interactions.

2. **What small change unlocks it**

   Define a clear confidence format that combines a numeric score with a label and short reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'." This format provides enough detail for the wearer to understand the reliability of the memory or subtitle.

3. **Likely payoff**

   By providing a transparent and nuanced confidence display, users will feel more secure in trusting the system's memory recall and subtitles. This can lead to increased user satisfaction and trust, reducing cognitive load and improving overall interaction quality.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local cache size threshold for face/name memory, we ensure that the system retains enough recent and relevant information to provide accurate and timely assistance while managing battery and thermal constraints effectively.

2. **What small change unlocks it**

   Define a local cache size limit of 50 entries for face and name memories, ensuring that only the most recently encountered individuals are cached locally on the phone. This limit balances memory retention with system efficiency.

3. **Likely payoff**

   Implementing this cache size limit will reduce memory usage, improve response times, and maintain a high level of accuracy in face/name recognition. It will also help in managing battery consumption by limiting the amount of data that needs to be processed and stored locally.

4. **Immediate next probe**

   Define one local-cache size limit for face and name memories at 50 entries to optimize memory usage while maintaining accurate recall.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a specific cloud fallback boundary for live subtitle processing, we can ensure that critical real-time subtitles are always available and accurate, even when the phone is in low-power mode or temporarily out of sync with the cloud. This improves the reliability and trustworthiness of the system without overwhelming local resources.

2. **What small change unlocks it**

   Define a clear boundary where live subtitle processing falls back to the cloud only if the phone’s local processing capacity drops below a certain threshold, such as when the battery is critically low or during periods of high thermal stress.

3. **Likely payoff**

   This will ensure that subtitles remain reliable and useful even under constrained conditions, enhancing user trust and satisfaction. It also optimizes resource usage by offloading less critical tasks to the cloud only when necessary.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for live subtitle processing based on local battery level and thermal state.

3. **Likely payoff**

4. **Immediate next probe**
