### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement rules for different confidence states ensures that subtitles are always readable and do not distract the wearer from their conversation. This enhances the real-time subtitle clarity attractor, making sure the wearer can trust the information provided.

2. **What small change unlocks it**
   Define two to three subtitle placement rules based on confidence levels: high confidence (always visible), medium confidence (visible with a slight delay), and low confidence (only shown upon explicit user request).

3. **Likely payoff**
   By having clear placement rules, the subtitles will be more effective in real-time interactions. This reduces cognitive load for the wearer by ensuring that critical information is always easily readable while minimizing distraction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format ensures that the wearer can trust the subtitles and memory support more effectively. A clear, consistent, and neutral confidence label with a short reason will help the wearer understand when to rely on the system's suggestions and when to be cautious.

2. **What small change unlocks it**

   Define a new confidence object format that combines a numeric score with a label and a short reason. For example: "score 0.85 + 'High' + 'Seen recently';" or "score 0.30 + 'Low' + 'Weak match'".

3. **Likely payoff**

   By providing a clear, structured confidence format, the system can build more trust with the wearer. This will help in situations where the wearer needs to be cautious about relying on the system's suggestions, such as when dealing with new faces or names.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a clear local cache threshold for face/name memory objects on the phone, we ensure that the system has a balanced amount of memory to support quick recall while respecting battery and thermal constraints. This helps in maintaining trust by ensuring that the wearer can rely on immediate access to frequently encountered people without overloading the device.

2. **What small change unlocks it**

   Define a local cache threshold for face/name memory objects, setting a limit on how many recent encounters are cached locally with high confidence. For example, caching up to 10 high-confidence face/name interactions that have been reinforced recently.

3. **Likely payoff**

   This approach will reduce the risk of memory overflow and improve response times, leading to faster and more reliable face/name recall. It also ensures that the system remains light and efficient, which is crucial for battery life and thermal management in an always-on device.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what stays phone-local versus what falls back to cloud, we can ensure that V1 remains simple yet effective. This will help maintain low latency and privacy while ensuring that critical assistive functions are reliable.

2. **What small change unlocks it**

   Define a specific task boundary such as "live subtitle processing" and set clear rules for what runs phone-local versus falling back to the cloud. For example, define that real-time subtitles should be processed on-device with minimal latency, while more complex tasks like memory archive sync can use cloud resources.

3. **Likely payoff**

   By clearly defining these boundaries, we can avoid unnecessary data transfers and processing delays, maintaining a smooth user experience without compromising on privacy or functionality. This will also allow us to focus development efforts where they are most needed, leading to faster iteration cycles and better overall performance.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
