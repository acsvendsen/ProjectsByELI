# Reality Check for SmartGlasses Project

## Subtitle Clarity: Real-time subtitle clarity
- **Feasibility**: feasible now  
- **Reasoning**: The `TranscriptLab` app has succeeded in building a live transcript path, indicating that real-time subtitle generation is technically possible. Given the success of this test, it is feasible to continue developing and refining subtitle quality in V1.

## Memory Trust: Trustworthy memory support
- **Feasibility**: likely waste of time  
- **Reasoning**: The current version of `TranscriptLab` focuses on live transcription rather than long-term memory. Developing a robust memory system that can remember names, faces, and prior context is complex and should be deferred until the core real-time subtitle functionality is well established. Early efforts should focus on getting the subtitles right before moving to more complex memory solutions.

## Low-friction assistance: Low-friction assistance
- **Feasibility**: feasible now  
- **Reasoning**: The current project direction is to keep interactions simple, with frame touches as the primary method of interaction. Adding one-line prompts can be implemented through text overlays on subtitles without introducing additional command overhead or social awkwardness.

## Privacy vs usefulness: Privacy vs usefulness
- **Feasibility**: feasible now  
- **Reasoning**: The glasses should prioritize privacy by not pretending to have knowledge that the wearer does not. This can be managed by clearly indicating uncertainty and avoiding invasive data collection. Given the current constraints, focusing on useful but non-invasive features is a good approach.

## Latency vs richness: Latency vs richness
- **Feasibility**: feasible now  
- **Reasoning**: The `TranscriptLab` app has succeeded in providing near-real-time transcripts, indicating that latency is currently manageable. Richer memory or other features can be explored once the core subtitle functionality is well established.

## Discreet UX vs visual clarity: Discreet UX vs visual clarity
- **Feasibility**: feasible now  
- **Reasoning**: The current `TranscriptLab` app demonstrates a discreet UI that does not become distracting. Ensuring subtitles are clear and unobtrusive while still providing useful information is a feasible goal.

## Frame-touch-only V1: Frame-touch-only V1
- **Feasibility**: feasible now  
- **Reasoning**: The current project constraints explicitly state that frame touches should be the primary method of interaction in V1. Implementing touch controls will help maintain this constraint and ensure a low-friction user experience.

## Phone-first runtime: Phone-first runtime
- **Feasibility**: feasible now  
- **Reasoning**: The `TranscriptLab` app already demonstrates a phone-first approach, where the phone handles heavy processing while the glasses focus on display. This aligns with the current project constraints and is a feasible implementation strategy.

## Core-deepening over sprawl: Core-deepening over sprawl
- **Feasibility**: feasible now  
- **Reasoning**: The current mode of operation is "core deepening," which prioritizes improving subtitle quality, memory trust, and visual UX. This focus on core features is a good approach for V1.

## Current Unknowns: What subtitle placement is most usable without becoming distracting?
- **Feasibility**: assumptions needing evidence  
- **Reasoning**: The ideal subtitle placement has not yet been defined or tested. More research and user testing are needed to determine the best placement that remains unobtrusive while still being readable.

## Current Unknowns: How should one-line prompts visually differ from subtitles?
- **Feasibility**: assumptions needing evidence  
- **Reasoning**: The visual distinction between one-line prompts and subtitles is not yet defined. This needs further design exploration to ensure clarity and usability without adding complexity.

## Current Unknowns: What confidence format builds trust best: label only, label + short reason, or score + label?
- **Feasibility**: assumptions needing evidence  
- **Reasoning**: The current project does not specify a confidence format. User testing is needed to determine the most effective and trustworthy way to display confidence levels.

## Current Unknowns: How much face/name memory should be cached locally on the phone?
- **Feasibility**: assumptions needing evidence  
- **Reasoning**: The amount of local caching for face and name recognition has not been defined. This requires more research to balance between utility, privacy, and battery constraints.

## Current Unknowns: Which interactions should work offline versus requiring cloud support?
- **Feasibility**: assumptions needing evidence  
- **Reasoning**: Determining which features require cloud support is an open question that needs further exploration. Offline functionality should be prioritized where possible to reduce dependency on the cloud.

### Summary
- The core functionality of real-time subtitles and low-friction assistance are feasible now and align with current project constraints.
- Developing complex memory systems, rich visual designs, or cloud dependencies should be deferred until the core functionality is well established.
- Key unknowns such as subtitle placement, confidence format, and caching strategies need further evidence through user testing.
