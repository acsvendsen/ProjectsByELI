### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement that avoids distractions while maintaining readability is crucial for the core attractor of real-time subtitle clarity. Stable placement rules prevent subtitles from flickering or moving in a way that disrupts the wearer's focus, thereby enhancing trust and usability.

2. **What small change unlocks it**

   Define three fixed subtitle placement rules: one for high-confidence matches (e.g., names and faces seen multiple times), another for medium-confidence matches (e.g., recently heard names), and a third for low-confidence matches (e.g., new or rarely encountered names). Each rule should have a defined visual priority to avoid distraction.

3. **Likely payoff**

   By defining clear placement rules, the system can maintain a consistent and unobtrusive subtitle experience that remains readable even during rapid head movements. This will enhance user trust in the subtitles and their reliability for real-time communication.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display ensures that the wearer can trust the system's assistance in real-time conversations. By providing clear and honest feedback about the certainty of the information, the system maintains its credibility and reinforces the wearer's reliance on it.

2. **What small change unlocks it**

   Define a consistent confidence format for all memory objects, such as names and faces, that includes a numeric score, label, and short reason. This ensures that the confidence display is always clear and provides sufficient context to the wearer.

3. **Likely payoff**

   A well-defined confidence format will reduce the risk of misunderstandings or incorrect assumptions about the system's knowledge, thereby enhancing trust and reliability in real-world interactions.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache threshold for name recall on the phone, we can ensure that frequently encountered names are quickly accessible to the wearer without significantly impacting battery life or thermal load. This improves memory trust by providing faster and more reliable recall of recently seen people, thus enhancing the wearer's ability to understand and respond in social situations.

2. **What small change unlocks it**

   Define a local cache size limit for frequently encountered names on the phone that is optimized for V1's interaction constraints (frame touches only) and hardware limitations (lightweight sensors). This limit should be set to allow quick access to names seen within the last 30 minutes, but not store all potential names indefinitely.

3. **Likely payoff**

   By implementing a local cache size limit of 20-50 frequently encountered names for quick recall on the phone, we can significantly reduce latency in name memory lookups while keeping battery and thermal impact minimal. This will provide faster, more reliable support for name recall during social interactions, thereby strengthening trust in the product's assistive capabilities.

4. **Immediate next probe**
   - Define a local cache size limit of 30 frequently encountered names for quick memory recall on the phone.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary between what stays phone-local and what falls back to cloud for live subtitle processing, we ensure that real-time subtitle clarity is maintained without overburdening the glasses or degrading battery life. This helps in keeping the system lightweight and socially acceptable while ensuring high-quality subtitles.

2. **What small change unlocks it**

   Define a specific task boundary: For live subtitle processing, all speech-to-text transcription should happen on the phone until explicit user interaction is required to trigger cloud fallbacks. This can be achieved by setting up a local cache or threshold for when to switch from phone-local to cloud-based processing.

3. **Likely payoff**

   By keeping live subtitle processing phone-local, we ensure that subtitles remain stable and real-time, which is crucial for the wearer's trust and understanding in noisy environments. This reduces battery drain associated with continuous cloud communication and maintains a discreet UX. Additionally, this decision allows for faster fallbacks to cloud if needed, without compromising on immediate quality.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring that subtitles coexist harmoniously with one-line prompts without overwhelming the wearer benefits the core by maintaining a clean, uncluttered visual hierarchy. This enhances both subtitle clarity and overall low-friction assistance, which are primary attractors of the project.

2. **What small change unlocks it**

   Define a clear precedence rule that prioritizes subtitles over one-line support in fast-paced interactions while allowing coexistence for more relaxed contexts. This rule would ensure that critical information (subtitles) remains prominent without obscuring important contextual cues (one-line prompts).

3. **Likely payoff**

   By defining this visual hierarchy, the project can achieve a balanced user experience where subtitles are always easily readable and one-line support is neither overbearing nor hidden when needed. This balance strengthens trust by ensuring that the wearer can rely on both forms of assistance without feeling overwhelmed.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
