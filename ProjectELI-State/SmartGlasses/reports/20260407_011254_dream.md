### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules ensures that subtitles remain clear, stable, and unobtrusive, which directly supports the real-time subtitle clarity attractor. By defining specific placement modes for different confidence states, we can enhance the wearer's trust in the subtitles without causing visual distraction.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence text (e.g., names and spoken words) that appears at the top of the display with a fixed position, and another for lower-confidence text (e.g., background noise or less certain transcription) that appears as a translucent overlay at the bottom.

3. **Likely payoff**

   By implementing these placement rules, we can ensure that high-priority information is always visible without causing visual clutter. This will reduce cognitive load and improve the wearer's ability to follow conversations in noisy environments, directly enhancing the real-time subtitle clarity attractor and overall user experience.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   - Improving the confidence display format ensures that users can trust the system's memory support and subtitle placement more effectively. A clear, concise, and consistent confidence label and short reason will help build user trust and ensure that the wearer understands the reliability of the information being displayed.

2. **What small change unlocks it**
   - Define a simple confidence format for V1 that uses a numeric score, a label, and a brief reason. For example, "score 0.84 + 'High' + 'Seen recently'; score 0.42 + 'Low' + 'Weak match'; score 0.63 + 'Medium' + 'Name heard once in introduction'. This format provides enough information to the user without overwhelming them.

3. **Likely payoff**
   - By implementing a clear confidence display, users will feel more confident in the system’s memory and subtitle accuracy. This increased trust can lead to higher daily-use value and better overall satisfaction with the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory on the phone, we ensure that critical memories are retained while reducing storage pressure and improving response speed. This balance helps maintain trust through fast recall without overwhelming the system with unnecessary data.

2. **What small change unlocks it**

   Define a specific local cache size limit (e.g., 10 most recent names) for face/name memory on the phone, which will be managed by a least-recently-used (LRU) eviction policy.

3. **Likely payoff**

   Implementing this cache size limit will enable fast and reliable name recall during live interactions, reducing latency and ensuring that critical memories are readily available without consuming excessive local storage resources. This improves the overall user experience by maintaining responsiveness and trust in the memory support system.

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains phone-local optimizes battery usage and reduces latency, maintaining real-time clarity essential for trust in noisy environments. This focus on local computation also helps preserve privacy by keeping sensitive audio data off the cloud.

2. **What small change unlocks it**

   Define a specific task boundary: live subtitle processing should always stay local to the phone until proven necessary otherwise. This can be achieved by setting up an explicit cloud fallback rule that only triggers when the phone’s battery is critically low and recharges are not expected soon.

3. **Likely payoff**

   By keeping live subtitle processing on-device, we reduce latency, enhance privacy, and ensure the system remains functional even if the connection to the cloud is lost temporarily. This improves daily-use value by providing reliable, clear subtitles that do not depend on network availability.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing. If the battery level drops below 20%, automatically use a high-latency but bandwidth-efficient cloud service to process subtitles when the glasses are stationary and recharging.
