# Reality Check for SmartGlasses Project

## Subtitle Clarity: Real-time subtitle clarity (feasible now)
- **Subtitle Placement**: The glasses should display subtitles in a way that remains readable and stable during live conversations. Given the current implementation groundwork, it is feasible to focus on placing subtitles where they do not distract from the conversation but are still visible. For example, displaying subtitles near the bottom center of the field of view can be tested and iterated on.
- **Visual Hierarchy**: Ensure that subtitles blend well with the environment without causing visual fatigue or distraction. This involves refining the font size, color contrast, and position to avoid drawing too much attention away from the conversation.

## Memory Trust: Trustworthy memory support (feasible now)
- **Face/Name Memory Storage**: Implement a simple but effective mechanism for storing face/name pairs with associated confidence objects. This can be done using local storage on the phone until more sophisticated caching strategies are developed.
- **Reinforcement Learning**: Use frame touches to reinforce memories over time, making sure that the system learns which interactions are significant and should be remembered more strongly.

## Low-friction Assistance: Low-friction assistance (feasible now)
- **One-line Prompts**: Design one-line prompts that provide context without overwhelming the wearer. This can include brief reminders or suggestions, ensuring they do not require any additional command input from the user.
- **Interaction Mode**: Stick to frame-touch interactions for V1, avoiding voice commands which are not yet supported in the current version.

## Privacy vs Usefulness (likely waste of time)
- **Privacy Concerns**: While it is important to ensure that the system does not invade privacy, excessive focus on this tension could lead to unnecessary complexity. For now, ensuring that the system only assists where the wearer explicitly requests help and providing clear feedback mechanisms should be prioritized.

## Latency vs Richness (feasible now)
- **Real-time Subtitles**: Ensure that subtitles are delivered in real time, which is crucial for maintaining trust. The current TranscriptLab app can be used to test and refine this behavior.
- **Memory Lookups**: Balance the need for rich memory recall with ensuring fast lookups. This can involve implementing a lightweight on-device cache while still allowing cloud-based support where necessary.

## Discreet UX vs Visual Clarity (feasible now)
- **Subtitle Display**: Keep subtitles subtle enough to not draw too much attention, but clear enough that they are helpful in noisy environments.
- **Confidence Display**: Implement confidence indicators that help the wearer understand the reliability of the information provided. This can be done using simple labels or short reasons.

## Frame-touch Only V1 (feasible now)
- Ensure all interactions and features are designed with frame touches as the primary input method, aligning with the current constraints.
  
## Phone-first Runtime (feasible now)
- Continue to leverage the phone for heavy processing tasks while keeping the glasses hardware simple. This can include using cloud services only where they add clear value.

## Core Deepening Over Sprawl (feasible now)
- Focus on improving subtitle quality, memory trust, and visual UX rather than broad feature expansion. This ensures that the core mission is strengthened without unnecessary complexity.

## Constraint Pressure (feasible now)
- Surface battery, latency, privacy, and usability limits early to ensure weak directions are quickly identified and discarded.

## Implementation Grounding (feasible now)
- Base decisions on concrete repo signals from files like `TranscriptLab`, ensuring that the implementation aligns with current project constraints.

### Summary
The project is well-positioned to focus on core mission improvements while respecting real-world constraints. Prioritize subtitle clarity, memory trust, and low-friction assistance without getting sidetracked by broader features or speculative interactions until they are explicitly justified in the context of the project's current direction.
