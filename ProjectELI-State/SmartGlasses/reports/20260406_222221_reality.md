## Reality Check Summary for SmartGlasses Project

### Subtitle Placement
**Subtitle Clarity Feasibility**: Given the core attractors and constraints, subtitle placement should prioritize readability without becoming distracting. **Feasible Now**: The current implementation in `TranscriptLab` can be used to test and refine placement. Ensure subtitles are placed where they do not obstruct the wearer's view but remain visible and readable.

### Confidence Display
**Confidence Feasibility**: Confidence needs to be displayed in a way that builds trust without overwhelming the user. **Feasible Now**: Implement basic confidence indicators like labels or scores in `TranscriptLab`. Use simple, clear labels (e.g., "Low", "Medium", "High") and consider adding short reasons for high-confidence matches.

### Memory/Cache Policy
**Memory Trust Feasibility**: Face/name memory must be stored and reinforced correctly to build trust. **Feasible Now**: Implement basic caching and reinforcement rules in the phone-side runtime, as shown in `TranscriptLab`. Ensure memory objects are updated over time with user interactions and context.

### Phone/Cloud Boundary
**Phone-First Runtime Feasibility**: Early versions should rely heavily on the phone for processing. **Feasible Now**: Continue to use the phone-first approach detailed in `v1_architecture_direction.md`. Ensure cloud usage is only where it adds clear value, such as in complex model updates or background processing.

### Visual Hierarchy
**Discreet UX Feasibility**: The display should remain socially acceptable while being readable and useful. **Feasible Now**: Use the `TranscriptLab` UI to prototype different visual hierarchies. Focus on making subtitles clear and non-intrusive, with subtle confidence indicators that do not distract.
