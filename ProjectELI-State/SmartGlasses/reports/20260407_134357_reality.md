# Reality Check

## Subtitle Placement: Feasible Now
- **Subtitle Clarity**: The current implementation in `TranscriptLab` is focused on real-time clarity and stability, which are crucial for the core mission of providing useful subtitles. The existing setup should be sufficient to assess basic subtitle placement without significant changes.
  - **Reasoning**: The transcript test bed in `TranscriptLab` already provides a clear display that can be used to evaluate subtitle visibility and readability. Since this is V1, simplicity and minimal complexity are preferred.

## Confidence Display: Feasible Now
- **Current State**: The current confidence display in `TranscriptLab` uses a numeric score with a label, which helps convey the reliability of the subtitles.
  - **Reasoning**: Given that the primary focus is on real-time clarity (subtitle_clarity), using a simple numeric score and label is feasible now. This can be adjusted or expanded later as needed.

## Memory/Cache Policy: Feasible Later
- **Current State**: The memory cache policy for face/name recall is currently being explored, but no specific implementation details are available yet.
  - **Reasoning**: Since the primary focus of V1 is on subtitle clarity and low-friction assistance, refining the memory cache policy can be considered later. For now, it should remain as an open question to explore during further development.

## Phone/Cloud Boundary: Feasible Now
- **Current State**: The phone-first runtime approach is well-established in `TranscriptLab`, where heavy processing happens on the phone with optional cloud support.
  - **Reasoning**: This boundary is already defined and implemented, making it feasible now. Ensuring that the phone handles primary processing aligns with V1 constraints.

## Visual Hierarchy: Feasible Now
- **Current State**: The visual hierarchy in `TranscriptLab` focuses on clarity rather than feature density, which aligns with the core mission.
  - **Reasoning**: The existing design in `TranscriptLab` prioritizes clear and readable subtitles over complex visual layouts. This can be further refined as needed.

## Assumptions Needing Evidence
- **Subtitle Placement**: While the current implementation provides a basic framework for subtitle placement, more concrete evidence is needed to determine the most usable and non-distracting position.
  - **Reasoning**: The subtitle placement should remain within the frame of the glasses without being overly intrusive. This can be tested through user feedback or further prototyping.

- **Memory Object Reinforcement**: The reinforcement rules for face/name memory are still unclear, making it a critical area that needs more evidence.
  - **Reasoning**: The effectiveness of memory recall and reinforcement must be validated to ensure that the system builds trust without overloading the wearer. This can be tested through iterative user research.

- **Interaction Modes**: Although V1 is frame-touch-only, there may still be subtle interaction modes that could enhance usability without breaking core constraints.
  - **Reasoning**: Exploring minimal interaction gestures or haptic feedback might provide a better user experience while remaining within the defined V1 constraints. This should be tested through user studies.

## Summary
- **Subtitle Placement and Confidence Display**: These are feasible now, given the current implementation in `TranscriptLab`.
- **Memory Cache Policy**: This is feasible later as it requires more exploration and evidence.
- **Phone/Cloud Boundary and Visual Hierarchy**: These are well-defined and feasible now.
- **Assumptions Needing Evidence**: Subtitle placement, memory object reinforcement, and interaction modes require further validation through user testing.

By focusing on the core mission of subtitle clarity and low-friction assistance, the project can continue to refine these areas while maintaining a clear path for future improvements.
