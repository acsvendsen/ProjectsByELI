### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining stable subtitle placement rules, we ensure that subtitles remain readable and unobtrusive, enhancing the wearer's ability to follow conversations in noisy environments without distraction. This stability builds trust in the system’s reliability and improves overall user experience.

2. **What small change unlocks it**

   Introduce a single fixed subtitle position rule: place subtitles at the bottom center of the screen with a slight offset to the left, ensuring they remain visible but do not interfere with face recognition or direct gaze.

3. **Likely payoff**

   Implementing this fixed placement will reduce visual clutter and ensure that subtitles are consistently visible, even during quick head movements or changes in focus. This consistency will help maintain trust and enhance the wearer's ability to follow conversations without interruption.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   - Improving confidence display ensures that the wearer can trust the system's output, which is crucial for maintaining their engagement and understanding in real-world interactions. Clear and reliable confidence indicators help in situations where subtitles might be ambiguous or noisy.

2. **What small change unlocks it**
   - Define a consistent format for confidence objects that includes both a label (e.g., "High," "Medium," "Low") and a short reason (e.g., "Seen recently," "Weak match," "Name heard once in introduction"). This will provide a clear and concise way to communicate the system's certainty about the accuracy of the subtitles or memory recall.

3. **Likely payoff**
   - By clearly communicating the confidence level, users will be better informed about the reliability of the system’s output. This transparency can reduce anxiety and increase trust, leading to more effective use of the glasses in noisy environments or when dealing with unfamiliar people.

4. **Immediate next probe**
   - Define the label style for confidence objects as either "High," "Medium," or "Low" for V1.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Memory trust is crucial for the core mission of enhancing real-world understanding and reducing cognitive friction. A robust memory system that accurately recalls names, faces, and prior context builds a foundation of reliable support for the wearer. This reduces the likelihood of misunderstandings or embarrassing situations in social settings.

2. **What small change unlocks it**

   Define one entity-linking rule for attaching new evidence to an existing person-memory object. Specifically, set a threshold for how many times a name must be heard before it is confidently linked to a memory object.

3. **Likely payoff**

   By implementing a clear and consistent rule for linking names to memories based on hearing frequency, the system can ensure that names are only stored in memory objects when they have been encountered multiple times. This reduces false positives and keeps the memory cache clean, enhancing trust and reliability.

4. **Immediate next probe**

   Define one entity-linking rule where a name must be heard at least 3 times before being confidently linked to a person-memory object.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-locally versus what falls back to the cloud, we can ensure that critical real-time subtitle processing happens on-device, reducing latency and maintaining trust. This also allows us to leverage the phone’s computational resources for heavy processing tasks without sacrificing real-time performance.

2. **What small change unlocks it**

   Define a specific task boundary where live subtitle processing is handled phone-locally. For example, set a rule that all subtitle generation and placement decisions are computed on the phone in real time, with minimal fallback to the cloud.

3. **Likely payoff**

   By keeping subtitle generation local, we can ensure that subtitles are generated and displayed instantaneously, reducing latency and maintaining high trust levels. This will also allow for better optimization of the subtitle rendering algorithm without needing to consider cloud delays.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear, stable, and unobtrusive visual hierarchy between subtitles and one-line support improves the overall readability and usability of the SmartGlasses. This enhances the wearer's ability to focus on conversation while still receiving necessary contextual aids without feeling overwhelmed.

2. **What small change unlocks it**

   Define a visual priority rule where subtitles are given higher prominence but coexist with one-line support in a way that minimizes distraction. For example, prioritize subtitle placement over one-line prompts when both are present.

3. **Likely payoff**

   By carefully managing the visual hierarchy, the system can provide more useful and timely information to the wearer without disrupting their natural conversation flow. This reduces cognitive load and enhances the overall user experience, making the glasses a more reliable assistive tool in various social settings.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
