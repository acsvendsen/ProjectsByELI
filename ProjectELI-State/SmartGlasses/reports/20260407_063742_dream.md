### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, V1 can ensure that subtitles are displayed in a way that maximizes readability and trust without becoming overly distracting. This approach will help maintain the wearer's focus on the conversation while ensuring critical information is not missed.

2. **What small change unlocks it**

   Define a simple rule that places subtitles at the bottom of the field of view with higher confidence values, but lower confidence values appear slightly above or to the side, fading out as confidence decreases. This rule can be implemented in `TranscriptLabRootView.swift`.

3. **Likely payoff**

   Implementing this rule will help reduce subtitle clutter and ensure that only high-confidence subtitles are prominently displayed, while lower-confidence ones remain unobtrusive yet still visible when needed. This balance will enhance the wearer's ability to follow conversations without feeling overwhelmed.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format will enhance trust in both subtitle accuracy and memory support, thereby strengthening the wearer's belief in the system's reliability. A clear, concise, and consistent confidence indicator will help users understand when they can rely on the subtitles or memory aids.

2. **What small change unlocks it**

   Define a new confidence object format that combines a numeric score with a label and a short reason for the confidence level. For example: `score 0.84 + "High" + "Seen recently"`; `score 0.42 + "Low" + "Weak match"`.

3. **Likely payoff**

   By clearly indicating the confidence in each piece of information provided, users will feel more secure and better able to trust the system's output. This clarity can reduce cognitive load by making it easier for the user to prioritize which information is most likely correct.

4. **Immediate next probe**

   Define one confidence format candidate for V1: `score [0-1] + "High/Medium/Low" + "Reason"` where "Reason" provides a brief explanation of why the confidence level was assigned.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size limit for face/name memory, we ensure that the system retains a useful amount of recent interactions while respecting battery and thermal constraints. This helps in maintaining fast recall times without overwhelming the device's resources.

2. **What small change unlocks it**

   Define a local cache size limit for face/name memory objects on the phone, ensuring that only a certain number of recent encounters are stored to optimize both performance and memory usage.

3. **Likely payoff**

   Implementing this will reduce the risk of battery drain due to excessive memory processing while still providing reliable recall of recently seen individuals. This balance improves overall system stability and trust without compromising on core functionalities.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what runs phone-local versus what falls back to cloud, we ensure that critical subtitle processing happens on-device, maintaining real-time performance and reducing latency. This helps in keeping subtitles readable and stable enough for live conversation, which is crucial for the "Real-time subtitle clarity" attractor.

2. **What small change unlocks it**

   Define a specific task boundary for live subtitle processing to run phone-local: "Live subtitle processing should remain on-device until battery constraints are proven otherwise."

3. **Likely payoff**

   By keeping live subtitle processing local, we can ensure that the system remains responsive and stable, providing clear and timely subtitles even in high-latency environments. This enhances user trust and satisfaction with the core functionality.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line support helps maintain the wearer's focus on critical information while minimizing distraction. This improves the overall assistive experience by ensuring that the most relevant information is prioritized, thereby enhancing understanding and engagement in real-world interactions.

2. **What small change unlocks it**

   Define a rule that prioritizes subtitles over one-line support when confidence in identifying the speaker is high but reduces subtitle prominence slightly when additional context from one-line prompts could be beneficial. This can be achieved by setting a threshold for confidence where subtitles remain dominant, and below this threshold, one-line prompts gain more visual weight.

3. **Likely payoff**

   By optimizing the visual hierarchy, the system can ensure that the wearer's attention remains on the most relevant information, reducing cognitive load during complex interactions. This improves both the trust in the assistive behavior and the overall user experience by making critical information more accessible without overwhelming the wearer with excessive text.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
