# SmartGlasses V1 Reality Check

## Core Attractors

### Feasibility Analysis

- **Subtitle Clarity**  
  - **Current Status**: Feasible now.
  - **Reasoning**: The current hardware setup allows for real-time transcription with minimal delay. The `TranscriptLab` app demonstrates this capability effectively. Real-time subtitles must remain readable, stable, and clear enough to maintain trust during live conversations. This can be achieved through careful placement, font size, and speed optimization.
  
- **Memory Trust**  
  - **Current Status**: Feasible now.
  - **Reasoning**: Memory recall should be handled by the phone or cloud for accurate context and name recall. The system must ensure that recalled information is presented with appropriate confidence indicators to avoid creating false certainty. This can be implemented through a robust memory cache policy on the phone, ensuring that new faces and names are remembered and reinforced over time.

- **Low-Friction Assistance**  
  - **Current Status**: Feasible now.
  - **Reasoning**: One-line support should provide quick, context-specific assistance without overwhelming the wearer. This can be achieved through a simple UI design that limits text length and complexity while ensuring relevance to the current conversation context.

## Core Tensions

### Privacy vs Usefulness  
- **Current Status**: Feasible now.
- **Reasoning**: The system must balance providing useful memory support with respecting user privacy. Automatic new-person memory should be enabled by default when supported by context, but explicit remember-touch behavior can reinforce and capture user-prioritized data without overstepping boundaries.

### Latency vs Richness  
- **Current Status**: Feasible now.
- **Reasoning**: The system should aim for timely responses while avoiding overly complex processing that could increase latency. Real-time subtitles are essential, but the memory support can be optimized to provide quick and relevant context without excessive delay.

### Discreet UX vs Visual Clarity  
- **Current Status**: Feasible now.
- **Reasoning**: The UI design should prioritize readability and minimal distraction while maintaining a discreet appearance. This can be achieved through careful placement of subtitles and confidence indicators, ensuring they are clear but do not interfere with the wearer's natural interaction.

## Core Constraints

### Frame-Touch-Only V1 Interaction  
- **Current Status**: Feasible now.
- **Reasoning**: The system should focus on frame touches as the primary interaction method for V1. This simplifies user experience and aligns with the goal of discreet, low-friction assistance.

### Phone-First Runtime  
- **Current Status**: Feasible now.
- **Reasoning**: Heavy processing should primarily happen on the phone, leveraging cloud services only where clearly justified. The `TranscriptLab` app provides a good example of this approach by focusing on real-time transcription and confidence display while keeping complexity low.

## Core Modes

### Core Deepening  
- **Current Status**: Feasible now.
- **Reasoning**: The system should prioritize improvements that increase daily-use value, such as subtitle quality, memory trust, and visual UX. This mode helps maintain focus on the core mission without broad feature sprawl.

### Constraint Pressure  
- **Current Status**: Feasible later.
- **Reasoning**: Early in the project, it is more important to surface constraints through concrete implementations rather than prematurely optimizing for them. As the system matures, these constraints can be better managed and addressed.

## Open Questions

1. **Subtitle Placement**  
   - **Status**: Feasible now.
   - **Reasoning**: The best subtitle placement should balance readability with minimal distraction. Initial testing in `TranscriptLab` can provide insights into effective placement strategies.

2. **Confidence Display**  
   - **Status**: Feasible now.
   - **Reasoning**: Confidence indicators should be clear and concise to build trust without overwhelming the wearer. Testing various formats (label only, label + short reason) can help determine the most effective approach.

3. **Memory/Cache Policy**  
   - **Status**: Feasible now.
   - **Reasoning**: The cache policy should ensure that memory recall is accurate and reliable. Initial implementation on the phone with reinforcement learning can provide a solid foundation for this feature.

4. **Phone/Cloud Boundary**  
   - **Status**: Feasible now.
   - **Reasoning**: Clear boundaries between local processing and cloud services should be established early to maintain performance and privacy. The `TranscriptLab` app provides a good starting point for defining these boundaries.

5. **Visual Hierarchy**  
   - **Status**: Feasible now.
   - **Reasoning**: The visual hierarchy of subtitles, confidence indicators, and memory recall should prioritize readability and clarity. Initial designs can be refined through iterative testing with the `TranscriptLab` app.

## Summary

The current V1 direction is feasible now for subtitle clarity, memory trust, low-friction assistance, frame-touch-only interaction, phone-first runtime, core deepening, and constraint management. The project should focus on refining these core features while keeping real-world constraints in mind to avoid premature overcomplication.
