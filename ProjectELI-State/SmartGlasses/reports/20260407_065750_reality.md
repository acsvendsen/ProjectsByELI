# Reality Check for SmartGlasses Project

## Subtitle Clarity: Real-time subtitle clarity (Subtitle Placement)
- **Feasible Now**: 
  - The `TranscriptLab` app provides a solid foundation for testing real-time transcript behavior on the phone. Given that we have working live microphone capture and partial/final transcript display, ensuring subtitles are clear, fast, and stable is achievable with incremental improvements in subtitle rendering.
  - **Constraints**:
    - Latency: Ensure real-time processing does not introduce significant delays.
    - Battery: Minimize battery draw from ongoing audio processing.
    - Thermal: Keep the phone cool during continuous operation.

- **Feasible Later**: 
  - Integrate more advanced rendering techniques or hardware-accelerated layers to enhance subtitle clarity and performance without overwhelming the phone's resources.
  
## Memory Trust: Trustworthy memory support (Face/Name Memory)
- **Feasible Now**: 
  - Implement basic confidence objects and reinforcement learning for face and name recognition. Use existing memory caching policies in `TranscriptLab` as a starting point to ensure accurate but not overconfident recall.
  - **Constraints**:
    - Privacy: Ensure that the system does not store unnecessary data or create privacy concerns.
    - Battery: Minimize battery usage from frequent memory updates and lookups.

- **Feasible Later**: 
  - Expand face/name recognition algorithms with more sophisticated machine learning models, but do so in a way that maintains user trust through clear confidence indicators.

## Low-friction Assistance: Low-friction assistance (One-line prompts)
- **Feasible Now**:
  - Introduce one-line prompts for immediate support during conversations. Ensure these prompts are unobtrusive and provide meaningful, relevant information.
  - **Constraints**:
    - Battery: Avoid frequent prompt updates that might drain the phone's battery.
    - Display Clarity: Make sure prompts do not interfere with subtitle readability.

- **Feasible Later**:
  - Develop more complex interaction flows for one-line prompts, such as context-aware suggestions based on conversation history. Ensure these enhancements do not add unnecessary complexity to the current V1 design.

## Interaction Constraints
- **Frame-touch-only V1**: 
  - This constraint is well-grounded in the current project inputs and should be strictly adhered to. Any new interaction pattern that deviates from this assumption should require explicit permission.
  
## Battery and Thermal Management
- **Battery Usage**:
  - The phone-first approach minimizes on-glasses hardware requirements, which helps with battery management. Ensure continuous audio processing does not significantly drain the phone's battery.
- **Thermal Pressure**: 
  - Keep thermal management in mind during real-time transcript tests. Ensure that the system can operate continuously without overheating.

## Privacy and Usability
- **Privacy vs Usefulness**:
  - Implement clear confidence indicators to maintain user trust while providing useful memory support. Avoid overconfidence or invasive data collection.
- **Discreet UX**: 
  - Design subtitle placement and one-line prompts in a way that minimizes distraction but provides necessary clarity.

## Core Deepening
- **Core-deepening Over Sprawl**:
  - Focus on improving subtitle quality, memory trust, and visual UX rather than expanding features that may distract from the core mission. Use `TranscriptLab` to iteratively test these improvements.
