# Reality Check for SmartGlasses V1 Direction

## Core Attractors
### Subtitle Clarity (Real-time subtitle clarity)
- **Feasibility**: Feasible now.
  - **Reasoning**: The current hardware and software can handle real-time transcription with adequate stability. The `TranscriptLab` app provides a robust test bed for verifying real-time transcript quality, which is essential for ensuring the subtitles are clear, fast, and stable enough to be trusted in live conversations.

### Memory Trust (Trustworthy memory support)
- **Feasibility**: Feasible later.
  - **Reasoning**: While initial memory support can automatically remember new faces and names with context, more complex trust mechanisms like confidence levels and correction signals will require further development. The current architecture is phone-first, which means these features need to be tested and refined on the phone before being implemented in glasses hardware.

### Low-friction Assistance (Low-friction assistance)
- **Feasibility**: Feasible now.
  - **Reasoning**: One-line prompts can be handled through frame-touch interactions, which aligns with the V1 interaction constraints. This feature does not require heavy on-glasses processing and is well-suited for early implementation.

## Core Tensions
### Privacy vs Usefulness (Privacy vs usefulness)
- **Feasibility**: Feasible now.
  - **Reasoning**: The system should only remember names and faces with context, avoiding any privacy concerns. Reinforcement rules can ensure that the memory support is transparent to the wearer while providing useful assistance.

### Latency vs Richness (Latency vs richness)
- **Feasibility**: Feasible now.
  - **Reasoning**: Initial subtitle quality and memory recall should focus on simplicity and speed, reducing latency issues. Once these core features are solidified, richer processing can be explored if it does not significantly impact performance.

### Discreet UX vs Visual Clarity (Discreet UX vs visual clarity)
- **Feasibility**: Feasible now.
  - **Reasoning**: The current design should focus on a discreet and readable user experience. Frame-touch interactions and minimal UI elements can ensure that the glasses remain unobtrusive, even in noisy environments.

## Core Constraints
### Frame-touch-only V1 Interaction (Frame-touch-only V1 interaction)
- **Feasibility**: Feasible now.
  - **Reasoning**: The project explicitly states that V1 will use frame touches for interaction. This constraint should be strictly followed to ensure consistency and simplicity in the initial implementation.

### Phone-first Runtime (Phone-first runtime)
- **Feasibility**: Feasible now.
  - **Reasoning**: Early versions of the glasses should rely heavily on the phone for processing, as this approach reduces battery and thermal pressure. The `TranscriptLab` app provides a reliable test environment to validate core functionality.

## Core Modes
### Core Deepening (Core deepening)
- **Feasibility**: Feasible now.
  - **Reasoning**: Focusing on subtitle clarity, memory trust, confidence display, and low-friction UX aligns with the current mission. These improvements will strengthen the core loop before expanding into broader features.

## Current Open Questions
### Subtitle Placement (Subtitle placement)
- **Feasibility**: Feasible now.
  - **Reasoning**: The `TranscriptLab` app can be used to test different subtitle placements and visual hierarchies, ensuring that subtitles remain readable without becoming distracting.

### Confidence Display (Confidence display)
- **Feasibility**: Feasible later.
  - **Reasoning**: While initial confidence indicators should focus on clarity, more complex confidence displays will require further development. The current architecture is phone-first, so these features can be tested and refined after the core functionality is established.

### Memory/Cache Policy (Memory/cache policy)
- **Feasibility**: Feasible later.
  - **Reasoning**: Initial memory policies should focus on automatic new-person recognition with context. More complex cache management and confidence correction will require further development and testing, which can be done after the core features are solidified.

### Phone/Cloud Boundary (Phone/cloud boundary)
- **Feasibility**: Feasible now.
  - **Reasoning**: The current architecture is phone-first, so early versions should focus on minimal local logic. Cloud support can be added later if it provides clear value and does not introduce significant latency issues.

### Visual Hierarchy (Visual hierarchy)
- **Feasibility**: Feasible now.
  - **Reasoning**: A clear visual hierarchy for subtitles and one-line prompts can be designed early, ensuring that the UI remains unobtrusive while providing necessary assistance.

## Summary
The current V1 direction is well-grounded in real-world constraints and aligns with the core mission. Subtitle clarity and memory support should focus on simplicity and speed initially, while low-friction interactions and a discreet UX are crucial for early success. The `TranscriptLab` app provides a robust test bed to validate these core features before expanding into more complex functionality.
