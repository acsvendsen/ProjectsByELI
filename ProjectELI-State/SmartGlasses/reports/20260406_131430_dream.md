### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain a consistent and predictable user experience, reducing cognitive load by providing a reliable visual anchor for subtitles. This consistency is crucial in noisy environments where the wearer relies on clear, unambiguous text to follow conversations.

2. **What small change unlocks it**

   Define 3 to 5 fixed subtitle placement rules based on confidence levels: low (below 0.6), medium (0.6-0.8), and high (above 0.8) confidence in the speaker identity.

3. **Likely payoff**

   By defining clear placement rules, the glasses can minimize distracting shifts in subtitles, ensuring that the wearer remains focused on the conversation without the need to constantly adjust their gaze. This improves overall comprehension and trust in the system's reliability.

4. **Immediate next probe**
   - Define fixed position, placement mode, and placement fallback rules for subtitle placement based on confidence states: low (below 0.6), medium (0.6-0.8), and high (above 0.8) confidence.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving the confidence display format ensures that the wearer understands the reliability of the information presented, which is crucial for building trust and reducing cognitive friction. A clear and concise confidence label, score, and reason will help the wearer assess the quality of subtitles and memory support more accurately.

2. **What small change unlocks it**

Define a specific confidence object format that includes:
- A numeric score between 0.00 and 1.00
- A label (low, medium, high)
- A short reason describing the main evidence

3. **Likely payoff**

By clearly indicating the reliability of subtitles and memory support, this change will enhance user trust and ensure that the wearer understands when to rely on the system's assistance. This will reduce cognitive load by making it easier for the wearer to focus on the conversation rather than questioning the accuracy of the displayed information.

4. **Immediate next probe**
   - Define the certainty wording for each confidence level: "High," "Medium," and "Low."

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear threshold for local memory cache size, we ensure that the system retains only the most relevant and frequently accessed memories. This reduces memory bloat while maintaining essential context for fast recall, thus enhancing the wearer's ability to follow conversations effectively without being overwhelmed by irrelevant or outdated information.

2. **What small change unlocks it**

   Define a local cache threshold for face/name memories based on recent encounters and frequency of interaction. For example, limit stored memories to those encountered within the last 30 minutes with more than three interactions, or reduce the memory size if the wearer frequently moves between different groups of people.

3. **Likely payoff**

   By keeping the local cache manageable, the system can quickly retrieve relevant context when needed, reducing latency and improving overall conversational flow. This also helps in maintaining a low-friction user experience by minimizing the number of times the glasses need to access the phone or cloud for memory lookup.

4. **Immediate next probe**
   - Define a local memory threshold for face/name memories to include only those encountered within the last 30 minutes with more than three interactions, reducing the cache size and improving recall efficiency.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries on what runs phone-local versus what falls back to cloud, we ensure that V1 remains lightweight and socially acceptable while still leveraging powerful off-device processing when necessary.

2. **What small change unlocks it**

   Define a simple rule: all memory objects are cached locally on the phone for fast retrieval and reinforcement over time. Only send new or updated memory objects to the cloud as fallbacks or for deeper analysis, such as entity linking or complex context merging.

3. **Likely payoff**

   This approach ensures that V1 operates with minimal battery drain and thermal load while maintaining strong local processing capabilities. It aligns with the core mission of creating a discreet, always-on assistant without overloading the wearer’s glasses hardware.

4. **Immediate next probe**
   - Define one phone-local vs cloud fallback boundary rule for memory objects: cache all memory locally on the phone and send new or updated memory objects to the cloud as fallbacks or for deeper analysis, such as entity linking or complex context merging.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving the visual hierarchy between subtitles and one-line support ensures that the wearer can easily distinguish and prioritize information, reducing cognitive overload while maintaining clarity.

2. **What small change unlocks it**

   Define a priority rule where subtitles are always given higher visual prominence than one-line prompts unless explicitly overridden by a user touch or context-specific conditions.

3. **Likely payoff**

   By prioritizing subtitles over one-line prompts, the system ensures that critical information is more easily readable and accessible, enhancing the wearer's understanding during conversations without overwhelming them with additional text.

4. **Immediate next probe**
   - Define a display precedence rule where subtitles have higher prominence than one-line prompts, except when overridden by user touch or specific context conditions.
