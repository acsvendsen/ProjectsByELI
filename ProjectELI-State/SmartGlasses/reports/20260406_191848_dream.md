### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   - Stable subtitle placement rules ensure that subtitles remain readable and unobtrusive, enhancing trust in real-time conversation assistance.

2. **What small change unlocks it**
   - Define three fixed subtitle placement modes: centered, bottom edge, and top edge, with automatic fallbacks to avoid visual obstruction during high-action scenes.

3. **Likely payoff**
   - By providing consistent subtitle placement, users will experience more reliable and less distracting subtitles, leading to higher trust in the system's real-time assistance capabilities.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining how confidence is displayed, we can ensure that the wearer understands when a memory or subtitle is highly reliable versus less certain. This enhances trust and ensures that the system remains a helpful assistant rather than a source of confusion.

2. **What small change unlocks it**

   Introduce a simple numeric score next to each confidence label, ranging from 0 (low) to 1 (high), along with a corresponding short reason for the score. For example: "score 0.84 + 'High' + 'Seen recently'".

3. **Likely payoff**

   This change will provide the wearer with clear and actionable feedback on the reliability of each piece of information, reducing uncertainty and increasing trust in the system’s accuracy.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving the local cache size for name recall helps ensure that frequently mentioned individuals are always available quickly, reducing the need to query the cloud and maintaining a consistent level of assistance without overloading the user with too much information.

2. **What small change unlocks it**

   Define a specific local cache threshold for storing names and faces on the phone, ensuring that commonly encountered people remain in memory while less frequent ones are periodically cleared or queried from the cloud.

3. **Likely payoff**

   By setting an optimal local cache size, the system will provide faster and more reliable name recall without constantly querying the cloud, thus improving overall user trust and reducing latency during critical moments of interaction.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries for what stays phone-local versus what falls back to cloud, we can ensure that V1 remains focused on delivering core functionality with minimal latency and high trustworthiness. This decision will help maintain a discreet UX while ensuring real-time subtitle clarity and memory support.

2. **What small change unlocks it**

   Define one specific task boundary for live subtitle processing, such as "live transcription" versus "offline transcript cleanup."

3. **Likely payoff**

   By clearly separating tasks like live transcription from offline operations, we can optimize the phone's local processing to deliver real-time subtitles with minimal delay and high accuracy. This will reduce battery drain and ensure that the wearer remains focused on the conversation without distraction.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.
