# Reality Check for SmartGlasses V1 Core Field

## Subtitle Placement: Feasible Now
**Reasoning:** The glasses should be able to display subtitles in a clear, unobtrusive manner that does not distract the wearer or interfere with their ability to interact naturally. Given current hardware constraints (lightweight and socially acceptable), placing subtitles at the bottom of the frame without overlapping other important UI elements is feasible now. This ensures that the subtitle text remains readable and stable.

## Confidence Display: Feasible Later
**Reasoning:** Implementing a confidence display that provides feedback on the reliability of the subtitles requires more complex design considerations, such as balancing visual clarity with information density. While it's not essential for the initial V1 interaction model (frame-touch only), refining this feature later would enhance user trust and understanding.

## Memory/Cache Policy: Feasible Now
**Reasoning:** Implementing basic face/name memory support that is stored and reinforced over time on the phone can be done now. This involves storing minimal data locally and ensuring it updates as new interactions occur, without overwhelming battery or storage resources.

## Phone/Cloud Boundary: Feasible Now
**Reasoning:** Given the current constraints (phone-first runtime with cloud optional), implementing core functionality that relies heavily on the phone for processing and memory management is feasible. This includes real-time subtitle generation, memory support, and confidence display logic.

## Visual Hierarchy: Feasible Now
**Reasoning:** Designing a visual hierarchy that supports both subtitles and one-line prompts without overloading the wearer can be done now. The key is to ensure clarity and minimal distraction while allowing for essential assistive information.

## Constraints Check

### Frame-Touch-Only V1 Interaction
- **Feasible Now**: The glasses should primarily rely on frame touches for interaction, which aligns with current hardware constraints.

### Phone-First Runtime
- **Feasible Now**: Heavy processing should remain on the phone, with cloud support as optional where clearly justified. This is consistent with the current design direction.

### Core Deepening Over Sprawl
- **Feasible Now**: Focusing on subtitle quality, memory trust, and visual UX improvements is essential for V1. Broad feature expansion should be avoided until core functionalities are well-established.

## Assumptions Needing Evidence

- The exact placement of subtitles needs further testing to ensure it remains readable without being distracting.
- The best confidence format (label only, label + short reason, or score + label) requires empirical validation through user feedback and usability tests.

## Summary
Based on the current project inputs and constraints, focusing on subtitle clarity, basic memory support, and ensuring a low-friction interaction model are feasible now. Implementing advanced features like rich confidence displays can be done later after core functionalities are established and validated.
