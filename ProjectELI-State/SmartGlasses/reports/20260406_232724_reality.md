# Reality Check

## Subtitle Placement: Feasible Now
- **Subtitle Placement**: Subtitles should be placed in a way that is readable yet non-distracting. Given the current focus on real-time subtitle clarity and low-friction assistance, feasible placements could include:
  - **Top-right corner**: Minimally intrusive while still allowing the wearer to glance at subtitles.
  - **Bottom center or slightly above**: Ensures the text remains visible without blocking important visual information.

- **Feasibility Reasoning**: The `TranscriptLab` app allows us to test different placement options. Placing subtitles in the top-right corner is a good starting point as it minimizes distraction while still providing sufficient visibility. This aligns with our core-deepening focus on subtitle clarity and user trust.

## Confidence Display: Feasible Now
- **Confidence Display**: Implementing confidence scores or labels to help the wearer understand the reliability of subtitles.
  - **Label Only (e.g., "Low", "Medium", "High")**
  - **Label + Short Reason (e.g., "Low: Weak Signal" or "High: Clear Speech")**

- **Feasibility Reasoning**: The `TranscriptLab` app can include simple confidence indicators. For instance, using a label system like "Low," "Medium," and "High" could provide immediate feedback on subtitle reliability. This approach is feasible now as it aligns with the current core-deepening mode and does not require complex UI changes.

## Memory/Cache Policy: Likely Waste of Time
- **Memory/Cache Policy**: Deciding how much face/name memory should be cached locally.
  - **Local Cache vs Cloud Storage**: Early versions should rely heavily on phone processing, making local caching a key consideration.
  
- **Feasibility Reasoning**: Given the current focus on core deepening and the V1 real-world limits that emphasize minimal on-glasses computation, it is likely premature to deeply explore memory policies. Instead, we can start with simple caching strategies based on current usage patterns and refine as needed.

  - **Local vs Cloud Processing**: Early versions should primarily use the phone for heavy processing while allowing cloud access where clearly justified.
  
- **Feasibility Reasoning**: The `TranscriptLab` app provides a good testbed to explore local and cloud processing. Implementing core functionality on the phone first is feasible now as it aligns with our current architecture direction.

- **Feasibility Reasoning**: The `TranscriptLab` app allows us to test different visual hierarchies. Prioritizing subtitles over shorter prompts is a feasible approach that aligns with our core-deepening focus on real-time clarity and user trust.
