### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles are always clear and unobtrusive, enhancing the wearer's trust in real-time understanding without causing distraction.

2. **What small change unlocks it**

   Define three subtitle placement modes: 
   - **Low Confidence**: Subtitles appear at the bottom of the screen, slightly overlapping with the main view.
   - **Medium Confidence**: Subtitles are positioned centrally on the right side, partially visible to indicate additional information without overwhelming the wearer.
   - **High Confidence**: Subtitles are hidden until explicitly requested by a frame touch.

3. **Likely payoff**

   This approach will provide a clear visual hierarchy that respects privacy and cognitive load while ensuring important information is always accessible when needed. It balances the need for continuous subtitle support with reducing distraction, thereby maintaining trust and usability.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

3. **Likely payoff**

4. **Immediate next probe**

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   - Improving memory cache retention rules ensures that names, faces, and prior context are remembered more reliably over time, reducing the need for frequent reinforcement through frame touches. This enhances the trust in the system's memory support, aligning with the core attractor of "Trustworthy memory support."

2. **What small change unlocks it**
   - Define a local cache eviction policy that retains face and name memories based on recency and frequency of interaction, but allows older or less relevant entries to be evicted after a period without reinforcement.

3. **Likely payoff**
   - By retaining key person-memory objects more effectively, the system will provide faster and more accurate recall in subsequent interactions with these individuals, reducing the cognitive load on the wearer and improving overall trust in the memory support feature.

4. **Immediate next probe**
   - Define a local cache eviction rule that retains face and name memories for at least 7 days of consistent interaction, but allows less frequent or older entries to be evicted after 30 days without reinforcement.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what stays phone-local versus what falls back to cloud, we ensure that V1 focuses on real-time subtitle clarity and memory trust without overloading the glasses with heavy processing tasks. This helps maintain battery efficiency and ensures that critical assistive features remain responsive and reliable.

2. **What small change unlocks it**

   Define a single task boundary for live subtitle processing that stays phone-local, ensuring that all subtitle-related computations are handled on the phone to minimize latency and resource usage.

3. **Likely payoff**

   By keeping subtitle processing local, we can achieve faster, more stable, and more energy-efficient real-time subtitles. This improves the wearer's trust in the system during live conversations, aligning with the core attractor of real-time subtitle clarity.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for exactly one task such as live subtitle processing.
