### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules for different confidence states ensures that subtitles are always readable and unobtrusive, which is crucial for maintaining the wearer's trust in the system. By providing clear and stable subtitles, the system can enhance the wearer's understanding without overwhelming them.

2. **What small change unlocks it**

   Define two subtitle placement rules: one for high-confidence states (e.g., names or faces seen multiple times) where subtitles should be placed prominently but not obstructively, and another for low-confidence states (e.g., new faces or names) where subtitles can be slightly smaller and less prominent to avoid distraction.

3. **Likely payoff**

   By defining clear subtitle placement rules based on confidence levels, the system will maintain a balance between readability and unobtrusiveness. This approach ensures that important information is always visible while reducing visual clutter during casual conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   Improving the confidence display format enhances the wearer's trust in the subtitles by providing clear and concise certainty indicators. This helps reduce social friction and ensures that the wearer can rely on the system's judgments without feeling overly uncertain or corrected.

2. **What small change unlocks it**
   Define a confidence object format that includes a numeric score, a short label, and a brief reason for the judgment. For example: "score 0.85 + 'High' + 'Face seen recently';" "score 0.45 + 'Low' + 'Weak match';" "score 0.60 + 'Medium' + 'Name heard once in introduction'."

3. **Likely payoff**
   By providing a clear and concise confidence format, the system can build trust with the wearer over time. This will reduce the need for frequent corrections or explanations, making the assistive behavior more accepted and useful.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a local cache size threshold for name recall, we can ensure that commonly encountered names are stored in phone memory to provide fast and reliable lookups. This improves the wearer's trust in the system by making name recall more consistent and reducing the latency of responses.

2. **What small change unlocks it**

   Define a specific number of entries (e.g., 10) for the local cache that stores recently seen names, and use this limit to trigger memory eviction when new entries are added.

3. **Likely payoff**

   This change will significantly enhance the speed and reliability of name recall in V1, reducing latency and improving the overall user experience by ensuring that frequently encountered names can be quickly accessed without cloud dependency.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that subtitle processing remains local on the phone for live interactions helps maintain low latency and stable performance, which are crucial for real-time clarity and trust. By keeping this task phone-local, we avoid introducing any potential delays or instability that could arise from cloud network issues.

2. **What small change unlocks it**

   Define a clear boundary where subtitle processing is handled entirely on the phone. Specifically, set a rule that all live subtitle generation and rendering must occur locally, with no fallback to the cloud unless explicitly justified by a strong constraint (e.g., high bandwidth usage or complex speech-to-text tasks).

3. **Likely payoff**

   By maintaining local subtitle processing, we ensure that subtitles remain highly reliable and responsive during live conversations. This stability is critical for building trust and providing the wearer with clear, continuous information without any interruptions from network delays.

4. **Immediate next probe**
   - Define a rule that all live subtitle processing must occur locally on the phone, with no fallback to the cloud unless there is a high bandwidth usage issue.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   By defining a clear visual hierarchy between subtitles and one-line support, we ensure that the most critical information is prioritized and displayed prominently, reducing cognitive load and increasing overall usability. This enhances the wearer's ability to understand and respond effectively in real-world interactions.

2. **What small change unlocks it**

   Define a subtitle-vs-one-line priority rule that places subtitles first in the visual hierarchy, followed by one-line support, with each line receiving distinct prominence through larger font sizes, brighter colors, or more significant spacing.

3. **Likely payoff**

   This prioritization will make key information immediately accessible and distinguishable, reducing the chance of missing important context during conversations. It also ensures that subtitles remain the primary focus, providing a clear distinction between core content (subtitles) and supplementary support (one-line prompts).

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
