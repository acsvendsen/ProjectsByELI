### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring stable subtitle placement rules helps maintain a consistent and reliable experience, reducing visual distractions and enhancing trust in the system's real-time assistance. By defining clear placement rules, the wearer can focus more on conversation without constantly adjusting to see subtitles.

2. **What small change unlocks it**

   Define 2 to 3 subtitle placement rules for different confidence states: high-confidence (always visible), medium-confidence (floating near bottom of screen during speech), and low-confidence (visible only when needed).

3. **Likely payoff**

   This approach ensures that critical information is always visible while reducing visual clutter, which can enhance the overall usability and trust in the system. Stable placement rules will also make it easier for the wearer to predict where subtitles will appear, improving their ability to follow conversations.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that local memory thresholds are set appropriately helps maintain a balance between rich, contextual memory support and low-friction UX. By limiting the amount of data stored locally, we can prevent the glasses from becoming overly complex while still providing relevant and timely assistance.

2. **What small change unlocks it**

   Define a local cache size limit for person memories that caps the number of recent interactions stored on the phone to, say, 10 entries per day. This ensures that memory support remains focused and relevant without overwhelming the user or device resources.

3. **Likely payoff**

   By capping the local memory at 10 entries per day, we can maintain a balance between providing rich memory support and avoiding clutter. This limit helps in reinforcing recent interactions while not retaining old information indefinitely, which could lead to confusion or privacy concerns.

4. **Immediate next probe**

   Set a local cache size limit of 10 person memories per day for the initial V1 release.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains phone-local optimizes battery efficiency and latency, while also maintaining a high level of trust with real-time performance. By keeping subtitle processing on the phone, we can avoid the potential latency introduced by cloud processing, which is critical for maintaining the wearer's ability to follow conversations in real time.

2. **What small change unlocks it**

   Define one local subtitle processing boundary that routes all live transcription and rendering tasks to the phone, with a clear threshold for when to fallback to the cloud if necessary.

3. **Likely payoff**

   By keeping subtitle processing local, we can ensure faster response times, lower battery consumption, and more reliable performance, which are crucial for maintaining trust in our real-time subtitle functionality. This also allows us to leverage the phone's computational resources more effectively without the overhead of constant cloud communication.

4. **Immediate next probe**
   - Define one subtitle processing rule that routes all live transcription tasks to the phone locally, with fallback to the cloud if latency exceeds 100ms.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**
   - Ensuring that subtitles and one-line prompts coexist in a way that does not overwhelm the wearer is crucial for maintaining their trust and focus during conversations. A well-defined visual hierarchy helps balance the need for clear, real-time subtitles with the benefit of low-friction contextual support.

2. **What small change unlocks it**
   - Define a simple precedence rule: prioritize subtitles over one-line prompts when confidence in speaker identity or text is high, but allow one-line prompts to show through on lower-confidence or less critical content.

3. **Likely payoff**
   - By defining this rule, the system can provide more critical information (subtitles) without distracting the wearer with less important contextual cues (one-line prompts), thus maintaining their trust and focus during conversations. This balance ensures that the wearer is always aware of key information while still receiving helpful context when needed.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
