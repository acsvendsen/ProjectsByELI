# Reality Check for SmartGlasses Project

## Subtitle Placement: Feasible Now
- **Subtitle Clarity**: The glasses should display subtitles in a manner that is clear, fast, and stable enough to remain readable during live conversations. Given the current implementation of `TranscriptLab`, we can test subtitle placement to ensure it remains non-distracting while still being effective.
  - **Reasoning**: The `LiveTranscriptTestView.swift` file in `TranscriptLab` provides a starting point for testing subtitle visibility and placement. We should experiment with different positions (e.g., bottom center, top right) to find the best balance between clarity and non-distracting.

## Confidence Display: Feasible Now
- **Memory Trust**: The confidence display format needs to be clear and trustworthy. Given that we are currently using a simple label system (`high`, `medium`, `low`), we can refine this further.
  - **Reasoning**: Based on the current implementation, adding short reasons (e.g., "uncertain", "likely") to the labels could help build trust without overwhelming the user. We should experiment with different confidence display formats in `TranscriptLab`.

## Memory/Cache Policy: Feasible Now
- **Low-Friction Assistance**: The memory support should be reliable and not create command overhead.
  - **Reasoning**: Implementing a simple caching policy on the phone can help store recently seen faces/names. We can use the `TranscriptLab` app to test how much memory should be cached locally versus requiring cloud lookup.

## Phone/Cloud Boundary: Feasible Now
- **Phone-First Processing**: Early versions should rely heavily on phone processing, with cloud optional where it adds clear value.
  - **Reasoning**: The `TranscriptLab` app already provides a reusable test bed for validating transcript behavior. We can use this to fine-tune the balance between local and cloud processing by experimenting with different levels of offline functionality.

## Visual Hierarchy: Feasible Now
- **Discreet UX vs Visual Clarity**: Display behavior should remain socially acceptable while still being readable in motion and noise.
  - **Reasoning**: The current implementation in `LiveTranscriptTestView.swift` can be used to test different visual hierarchies. We should experiment with fading subtitles after a certain period, adjusting font size, and using color contrast that remains non-distracting.

## Summary

- **Subtitle Placement**: Experimentation is feasible now within the `LiveTranscriptTestView` in `TranscriptLab`.
- **Confidence Display**: Refinement of confidence display format is feasible now.
- **Memory/Cache Policy**: Implementing a simple caching policy on the phone and testing it with `TranscriptLab` is feasible now.
- **Phone/Cloud Boundary**: Fine-tuning the balance between local and cloud processing using `TranscriptLab` is feasible now.

## Assumptions Needing Evidence

- **Subtitle Placement**: While experimenting, we need to ensure that any changes do not significantly increase battery draw or latency.
- **Confidence Display**: The addition of short reasons to confidence labels needs evidence from user testing to validate its impact on trust and usability.
- **Memory/Cache Policy**: We need empirical data on the effectiveness of caching certain memory objects locally versus relying on cloud lookups.

By focusing on these specific areas, we can iteratively refine the core functionality without overcomplicating the system.
