# Reality Check for SmartGlasses V1 Direction

## Core Attractors
- **Subtitle Clarity** (feasible now): Real-time subtitles need to be clear, fast, and stable enough that the wearer can trust them in live conversation.
  
  - **Reasoning**: The initial version of the glasses must focus on delivering reliable subtitle content. The current implementation in `TranscriptLab` is a good start for validating this core feature.

- **Memory Trust** (feasible now): Remember names, faces, and prior context without pretending certainty or creating corrupted recall.
  
  - **Reasoning**: Early versions should rely heavily on the phone to handle memory and context. The phone can store basic memories, and the glasses will provide reminders and support based on this data.

- **Low Friction Assistance** (feasible now): Deliver one-line help and visible support without creating command overhead or social awkwardness.
  
  - **Reasoning**: One-line prompts should be clear and unobtrusive. The current implementation of frame-touch interactions in `TranscriptLab` aligns with this goal.

## Tensions
- **Privacy vs Usefulness** (feasible now): Helpful assistive behavior should not quietly slide into invasive capture or retention.
  
  - **Reasoning**: The system should respect the wearer's privacy while providing useful assistance. This tension is best managed by ensuring that memory and context are stored only when necessary and with clear user consent.

- **Latency vs Richness** (feasible now): The system should provide timely help without overloading the runtime with richer but slower processing.
  
  - **Reasoning**: Subtitle latency must be near-real-time to maintain trust. This can be managed by optimizing the transcript capture and display process in `TranscriptLab`.

- **Discreet UX vs Visual Clarity** (feasible now): Display behavior should remain socially acceptable while still being readable in motion and noise.
  
  - **Reasoning**: The current implementation of subtitle placement and confidence display in `TranscriptLab` focuses on readability without overwhelming the user.

## Constraints
- **Frame-Touch Only V1 Interaction** (hard constraint): V1 explicit interaction should happen through frame touches, not voice commands.
  
  - **Reasoning**: This is a hard requirement to maintain simplicity and social acceptability. Any future consideration of voice commands must be treated as a separate exploration.

- **Phone-First Runtime** (hard constraint): Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.
  
  - **Reasoning**: The current implementation in `TranscriptLab` is focused on the phone-first approach. This ensures early hardware simplicity while allowing for future cloud integration if needed.

## Core Deepening Over Sprawl
- **Core Deepening** (current mode): Bias toward subtitle, memory, confidence, and architecture improvements that increase daily-use value.
  
  - **Reasoning**: The current focus on core features aligns with the project's mission of creating a discreet personal assistant. Improving these core areas will provide more value to the user.

## Decision Areas

### Subtitle Placement
- **Current Plan**: Use the `TranscriptLab` implementation for initial subtitle placement.
  
  - **Reasoning**: The current implementation is focused on clarity and stability, which are crucial for real-time subtitles. Further adjustments can be made as needed based on user feedback.

### Confidence Display
- **Current Plan**: Implement a simple confidence display that provides clear, non-invasive information to the wearer.
  
  - **Reasoning**: Early versions should prioritize clarity over complex UI elements. The current implementation in `TranscriptLab` is a good starting point.

### Memory/Cache Policy
- **Current Plan**: Use the phone as the primary memory store with periodic caching of critical data on the glasses.
  
  - **Reasoning**: This approach balances privacy and utility, ensuring that the system remains lightweight while still providing useful assistance.

### Phone/Cloud Boundary
- **Current Plan**: Focus on a robust phone-first architecture with minimal cloud dependency.
  
  - **Reasoning**: The current implementation in `TranscriptLab` is designed to keep heavy processing off-glasses. This approach helps manage battery and thermal constraints effectively.

### Visual Hierarchy
- **Current Plan**: Ensure that subtitles are prioritized over other UI elements, maintaining a clear visual hierarchy.
  
  - **Reasoning**: The primary goal is to provide clear, unobtrusive assistance without overwhelming the user. The current implementation in `TranscriptLab` supports this by keeping the subtitle display simple and prominent.

## Conclusion

The initial direction of the SmartGlasses project is feasible now given the constraints and core attractors defined. Further refinement through iterative testing and user feedback will be crucial to ensure that these features meet the needs of the target users. The current implementation in `TranscriptLab` serves as a good starting point for validating these core areas.

### Next Steps
- Continue developing the `TranscriptLab` app to improve subtitle clarity, memory trust, and low-friction assistance.
- Gather user feedback on the initial implementation and make necessary adjustments.
- Explore ways to further optimize battery and thermal management without compromising real-time performance.
