### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules for different confidence states, we can ensure that subtitles remain clear and stable enough to be trusted in live conversation while avoiding unnecessary distractions. This will help maintain the wearer's focus on the conversation without overloading them with too much visual information.

2. **What small change unlocks it**

   Define two subtitle placement rules: 
   - One for high-confidence (0.8+ confidence) subtitles, which should be placed at the bottom center of the field of view.
   - Another for lower-confidence (0.5-0.79 confidence) subtitles, which can be slightly above the center but still within a safe reading zone.

3. **Likely payoff**

   By maintaining clear and unobtrusive subtitle placement, we reduce visual clutter while ensuring that important information is always visible. This will improve trust in the system and help the wearer stay focused on the conversation without being overwhelmed by too many subtitles at once.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

Improving the confidence display format helps maintain trust by clearly indicating the reliability of the memory and subtitles to the wearer. A well-designed confidence format ensures that the wearer understands when information is likely correct, thereby reducing uncertainty and increasing overall system trustworthiness.

2. **What small change unlocks it**

Define a new confidence object format that combines a numeric score with a label and a short reason for the confidence level. For example: `score 0.85 + "High" + "Seen recently"` or `score 0.40 + "Low" + "Weak match"`.

3. **Likely payoff**

By clearly indicating the certainty of memory matches and subtitle accuracy, this format will help users understand when to trust the system. This clarity can significantly reduce cognitive load by ensuring that users are not confused about the reliability of the information presented, thereby enhancing the overall user experience and trust in the product.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new face and name memory is automatically captured with minimal user interaction strengthens the core mission of providing trustworthy memory support without overloading the wearer.

2. **What small change unlocks it**

   Introduce a simple touch-based memory capture mechanism where a single tap on an unfamiliar face or name during a conversation will create a basic memory object that can be reinforced over time.

3. **Likely payoff**

   This change reduces the friction of memory creation, leading to more frequent and consistent memory reinforcement without requiring explicit user effort every time. It enhances trust in the system by demonstrating its ability to remember important details automatically, thereby reinforcing the core mission of providing reliable support through accurate recall.

4. **Immediate next probe**

   Define one entity-linking rule for attaching new evidence to an existing person-memory object that automatically creates a basic memory entry when a face or name is touched once during a conversation.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that memory recall for names and faces is handled phone-locally can significantly reduce latency, improve privacy, and maintain trust by avoiding unnecessary cloud data transfers and processing delays.

2. **What small change unlocks it**

   Define a local cache eviction policy where face/name memory is cached on the phone with a finite size limit, triggering fallback to the cloud only when the local cache reaches its threshold or if specific entities are encountered less frequently.

3. **Likely payoff**

   By keeping common and frequently recalled names and faces local, we reduce battery drain from continuous background syncing and improve response speed during critical interactions. This also enhances privacy by minimizing data sent to the cloud, making the system more acceptable in social contexts.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear and stable visual hierarchy between subtitles and one-line prompts is crucial for maintaining the wearer's focus without overwhelming them with too much information. This improves the overall user experience by ensuring that critical live subtitle text remains prominent, while additional support or reminders are relegated to a secondary but still accessible position.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prioritizes subtitles over one-line prompts during high-confidence states and coexists with lower-confidence one-line prompts in other cases. This can be achieved by setting different precedence rules based on the confidence level of the content being displayed.

3. **Likely payoff**

   By clearly defining the visual hierarchy, we ensure that the wearer remains focused on the most critical information—the subtitles—while still having access to necessary support or reminders without distraction. This will enhance trust and usability in noisy environments where understanding is crucial.

4. **Immediate next probe**
   - Define one visual priority rule between subtitles and one-line support in V1.
