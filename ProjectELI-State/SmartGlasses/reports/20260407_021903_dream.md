### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Improving subtitle placement rules can enhance the wearer's ability to read subtitles quickly and accurately without becoming distracting. Stable and consistent subtitle positioning ensures that the wearer can focus on the conversation, reducing cognitive load and increasing trust in the system.

2. **What small change unlocks it**

   Define a fixed position for subtitles at the bottom center of the display during live conversations. This simple rule avoids frequent repositioning due to changing confidence levels or other factors, ensuring that subtitles remain readable and unobtrusive.

3. **Likely payoff**

   By maintaining a consistent subtitle placement, the system will reduce cognitive load on the wearer, allowing them to focus more easily on the conversation. This can lead to better understanding of the spoken content, which is crucial for the core mission of enhancing real-world interaction clarity and trust.

4. **Immediate next probe**
   - Define a fixed position for subtitles at the bottom center of the display during live conversations.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving confidence display by using a numeric score with a clear label and short reason will enhance trust in the system’s reliability. This will make users more confident in the accuracy of subtitles and memory support, which is crucial for real-time assistance.

2. **What small change unlocks it**

   Define a specific format for confidence objects that combines a numeric score, a label, and a short reason. For example: `score 0.84 + "High" + "Seen recently"`.

3. **Likely payoff**

   By clearly displaying the certainty of subtitles and memory support, users will be able to better judge when they can rely on the system’s output. This clarity will help in maintaining trust and improving overall user satisfaction.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving local memory thresholds ensures that critical information like names and faces are retained in a way that is useful yet unobtrusive, aligning with the core attractors of real-time subtitle clarity and trustworthiness in memory support.

2. **What small change unlocks it**

   Define a local cache size limit for person memories on the phone, ensuring that only recently seen or frequently encountered individuals are cached locally to maintain performance without overwhelming the device's resources.

3. **Likely payoff**

   By limiting the amount of memory stored locally, we can ensure that the glasses remain responsive and do not drain battery excessively. This will also help in maintaining a clear and uncluttered UI, reducing potential visual distractions during critical interactions.

4. **Immediate next probe**

   Set a local cache size limit for person memories on the phone to 50 entries with frequent encounters having higher priority for retention.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By refining the cloud fallback boundary for live subtitle processing, we ensure that subtitles remain clear and stable in real-time, which is crucial for maintaining trust and clarity during conversations. This refinement helps balance the need for always-on functionality with battery and thermal constraints.

2. **What small change unlocks it**

   Define a specific task for phone-local processing: Live subtitle processing should be handled by the phone whenever possible to ensure minimal latency and real-time stability. For fallbacks, the glasses should only request cloud support if the local processing encounters significant errors or if the scene is too complex.

3. **Likely payoff**

   This refined boundary will help maintain high-quality subtitles even in challenging environments, thereby increasing user trust and satisfaction. It also ensures that battery consumption remains low by keeping heavy processing on the phone where it can be managed more efficiently.

4. **Immediate next probe**

   Define one cloud fallback boundary for live subtitle processing: glasses should request cloud support only if local processing encounters significant errors or if the scene is too complex to handle locally.
