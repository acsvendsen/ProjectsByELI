# Project Memory

This repo stores durable reasoning principles, project continuity, review structures, prompts, and status snapshots that should survive tool changes.

It is not tied to a single host surface or a single project.

This repo should preserve both system maturity and practical usefulness. It should help keep architectural strength, readiness honesty, and real build/usefulness gaps visible at the same time.

## Purpose

Keep safe:
- what should shape future reasoning
- what should survive tool changes
- what should not be flattened or forgotten

## Main layers

- `core/` — durable principles
- `frameworks/` — recurring models and progression rules
- `projects/` — project-specific continuity
- `prompts/` — reusable prompt library
- `templates/` — reusable operating templates
- `status/` — current checkpoints and real gaps

## Role clarity

- `core/` should define durable principles and narrow doctrine files
- `frameworks/` should define reusable structural models
- `projects/` should hold project-specific continuity and interpretation
- `prompts/` should hold reusable prompt fragments and prompt patterns
- `templates/` should stay copyable and lightweight
- `status/` should tell the current truth, not become doctrine

## Working rules

- do not confuse internal maturity with concrete usefulness
- do not sacrifice architecture for shortcuts
- do not let elegant structure hide weak build-facing output
- use coarse readiness bands for user-facing maturity
- treat draft artifact emission as staged and grounding-dependent
