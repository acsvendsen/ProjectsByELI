### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new people and names are remembered automatically by default helps maintain a low-friction experience for the wearer, reducing cognitive load during interactions. This approach fosters trust by showing that the system can handle routine tasks without explicit user intervention, thus keeping the focus on real-time assistance.

2. **What small change unlocks it**

   Implement a default automatic memory policy where new faces and names are recognized with high confidence (e.g., over 80% match) and stored in local cache for fast recall. This can be done by setting up a basic entity-linking rule that attaches new evidence to existing person-memory objects.

3. **Likely payoff**

   By automatically caching likely new people, the system reduces the need for explicit user touches while still providing accurate memory support when needed. This improves the overall user experience and builds trust in the system's ability to handle routine tasks discreetly.

4. **Immediate next probe**

   Define a local cache size limit of 20-30 person-memory objects that are automatically reinforced over time, ensuring frequent interactions with individuals are prioritized for faster recall.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that critical memory and confidence handling remain phone-local helps maintain real-time responsiveness and reduces battery drain, which is crucial for the wearer's trust and continuous usability.

2. **What small change unlocks it**

   Define a clear boundary where face/name recall and confidence objects are stored locally on the phone unless explicitly required to be cloud-synced due to high certainty or new evidence.

3. **Likely payoff**

   By keeping local memory and confidence handling robust, we can ensure that the system remains responsive even when the wearer is in areas with poor internet connectivity. This will enhance trust and reliability, making the smart glasses a more reliable assistant in real-world scenarios.

4. **Immediate next probe**
