# Reality Check for SmartGlasses V1 Direction

## Subtitle Placement

### Feasible Now:
- **Bottom of Frame:** Placing subtitles at the bottom of the frame is a feasible initial approach because it minimizes visual distraction while ensuring clear visibility. This placement can be tested to ensure that subtitles are easily readable without causing discomfort or social awkwardness.

### Assumptions Needing Evidence:
- Confirm through user testing if this placement works best for real-world interactions, especially in noisy environments and during group conversations.
- Evaluate the impact on social acceptability and readability without overwhelming the wearer with too much visual information.

## Confidence Display

### Feasible Now:
- **Label Only:** Using a simple label like "Low" or "High" to indicate confidence can be a feasible starting point. This approach minimizes complexity while providing necessary feedback.
- **Label + Short Reason:** While this could provide more detail, it might become too cluttered and reduce the overall usability of the system.

### Infeasible Now:
- **Numeric Score Only:** Displaying only a numeric score without any context or labels is likely to be confusing and does not align with the need for clear and simple feedback.

## Memory/Cache Policy

### Feasible Now:
- **Automatic New Person Memory with Reinforcement:** Remembering new faces and names automatically based on contextual clues can be feasible. This approach respects the current interaction constraints (frame-touch only) while providing a useful feature.
- **Explicit Remember-Touch Behavior for Reinforcement or Prioritization:** Allowing users to reinforce memory entries through frame touches is a practical way to enhance trust in the system without adding too much complexity.

### Assumptions Needing Evidence:
- Confirm through user testing how well automatic new person memory works in real-world scenarios.
- Evaluate if explicit remember-touch behavior is necessary for reinforcing and prioritizing certain memories over others.

## Phone/Cloud Boundary

### Feasible Now:
- **Phone-First Architecture:** Leverage the phone as the primary runtime for processing heavy tasks such as context analysis, memory lookup, and orchestration. Use cloud services only where it adds clear value.
- **Local Processing for Subtitles and Basic Memory:** Prioritize local processing on the glasses for displaying subtitles and basic memory operations to minimize battery draw and thermal pressure.

### Assumptions Needing Evidence:
- Confirm through user testing if the current phone-first architecture provides sufficient performance without overwhelming the phone’s resources.
- Evaluate the balance between using cloud services and maintaining a lightweight, always-on experience on the glasses.

## Visual Hierarchy

### Feasible Now:
- **Clear Separation Between Subtitles and One-Line Prompts:** Designing a clear visual hierarchy where subtitles are displayed prominently but one-line prompts are less obtrusive can be feasible. This approach helps in managing the complexity of the interface.
- **Subtitle Priority Over One-Line Prompts:** Ensure that subtitles take precedence over one-line prompts to avoid overwhelming the wearer with too much information at once.

### Assumptions Needing Evidence:
- Confirm through user testing if this visual hierarchy works well for different types of interactions and scenarios.
- Evaluate if additional layers of complexity (e.g., more frequent or detailed one-line prompts) are necessary or desirable.

## Interaction Constraints

### Feasible Now:
- **Frame Touches Only:** Stick to frame touches as the primary interaction method, avoiding voice activation or spoken commands in V1. This approach respects the current constraints and ensures a low-friction user experience.
- **Explicit User Controls for Reinforcement:** Allow users to explicitly reinforce memory entries through frame touches, which can be tested to ensure it adds value without complicating the interface.

### Assumptions Needing Evidence:
- Confirm if explicit remember-touch behavior is sufficient or if more sophisticated interaction methods are needed.
- Evaluate the impact of this approach on overall usability and user trust.

## Real-world Constraints

### Feasible Now:
- **Low Latency Subtitles:** Ensure that subtitles feel near-real-time to maintain trust. This can be achieved by optimizing subtitle processing locally where possible, reducing latency without relying heavily on cloud services.
- **Battery Draw Management:** Optimize the glasses for low battery draw while ensuring they remain functional and useful over extended periods.

### Infeasible Now:
- **High Latency Responses:** Avoid solutions that introduce significant delays in response times as these can break user trust quickly.
- **Overcomplicated Interfaces:** Refrain from adding too many features or complex interactions until their value has been proven through testing.

## Summary

The current direction is feasible with a focus on simplicity, low-friction interaction, and practical constraints. Key decisions include:
- Subtitle placement at the bottom of the frame for ease of reading.
- Using labels to display confidence levels.
- Implementing automatic new person memory with explicit reinforce behavior through frame touches.
- Leveraging a phone-first architecture while using cloud services selectively.
- Designing a clear visual hierarchy that prioritizes subtitles over one-line prompts.

These decisions align well with the real-world constraints and core mission of the system. Further user testing is necessary to validate these choices and ensure they meet the desired goals effectively.
