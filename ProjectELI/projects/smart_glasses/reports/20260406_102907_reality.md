# Reality Check for SmartGlasses Core Field

## Feasible Now

### Glasses Design & Display
- **Text Display**: Use simple, lightweight displays that can handle basic text rendering. This is feasible now given current display technology.
- **Sensors/Input**: Include minimal sensors (e.g., accelerometer, proximity sensor) to support basic interactions without overburdening the battery.

### Subtitle Delivery
- **Near-Real-Time Subtitles**: Leverage existing speech-to-text and text-to-speech libraries for near-real-time subtitle generation. This is feasible now with current computing power on phones.
  
### Face/Name Memory & UI
- **Simple Confidence Indicators**: Implement basic confidence indicators (e.g., "uncertain" or "low certainty") using labels rather than scores to avoid overwhelming the user.

## Feasible Later

### Advanced Processing
- **On-Glasses Inference**: Develop more advanced on-glasses inference capabilities as battery and thermal constraints improve. This is currently a feasibility challenge but could be feasible with future hardware advancements.
  
### Multimodal UI
- **Complex AR Visuals & Interactions**: Introduce richer multimodal interactions such as visual cues or augmented reality features after initial usability testing shows high value.

## Likely Waste of Time

### Overbuilding Features in V1
- **Full On-Glasses Inference**: Focusing on full on-glasses inference in the first version is likely a waste of time. Current hardware constraints make this impractical.
  
### Fancy AR Visuals
- **Complex Multimodal UI Elements**: Incorporating complex multimodal UI elements without solid user validation is premature and risky.

## Assumptions Needing Evidence

### Subtitle Placement & Prompt Design
- **Subtitle Placement**: Conduct usability testing to determine the most effective subtitle placement that minimizes distraction.
  
- **One-Line Prompts vs. Subtitles**: Test different visual treatments for one-line prompts to find a balance between clarity and social acceptability.

### Memory Caching Strategy
- **Local vs. Cloud Processing**: Gather data on how much face/name memory should be cached locally versus what needs cloud support, based on user experience feedback.

## Reality Check Rule

The project should focus on delivering core functionalities such as real-time subtitles, context-aware memory prompts, and basic confidence indicators in the first version while keeping hardware dependencies minimal. As we gather more data through testing and user feedback, we can gradually enhance these features without compromising initial usability and acceptability.

### Evolution Rule
- **Core Mission Focus**: Ensure all development efforts reinforce the core mission of helping wearers understand and respond better in real-world interactions.
  
- **User Feedback Loop**: Regularly incorporate user feedback to refine and expand functionalities in a way that deepens their value rather than broadening them superficially.

## Next Steps

1. **Usability Testing**: Conduct initial usability testing with prototypes to gather insights on subtitle placement, prompt design, and confidence indicators.
2. **Prototype Development**: Build a basic prototype focusing on real-time subtitles, context-aware memory prompts, and simple face/name recall.
3. **Battery & Thermal Testing**: Perform early-stage battery and thermal stress tests to identify hardware constraints.
4. **Confidence Indicator Design**: Develop and test different confidence indicator formats (labels vs. scores) for the best user experience.

By following these steps, we can ensure that our development efforts are grounded in real-world feasibility and user needs.
