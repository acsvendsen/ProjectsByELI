### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Stable subtitle placement rules help ensure that subtitles are always readable and unobtrusive, reducing cognitive load and maintaining trust in the system's ability to provide accurate and timely information.

2. **What small change unlocks it**

   Define two subtitle placement modes: one for high-confidence content (e.g., names and key phrases) and another for lower-confidence content (e.g., background noise or less critical words).

3. **Likely payoff**

   By having distinct placement rules for different confidence levels, the system can prioritize readability and clarity without overwhelming the wearer with subtitles that are less certain. This improves overall user trust and satisfaction.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring that confidence objects are clearly displayed helps build trust with the wearer by showing them when the system is confident about a name or face recognition, thus making the experience more reliable and less prone to errors.

2. **What small change unlocks it**

   Define a simple numeric score + label + short reason format for confidence display. For example: "score 0.84 + 'High' + 'Seen recently';" this format is straightforward and easily understood by users, providing immediate clarity about the system's certainty level.

3. **Likely payoff**

   By using a clear and concise confidence format, the system can enhance user trust in its accuracy, leading to better overall acceptance and usage of the glasses. This also helps prevent false positives or negatives that could otherwise confuse the wearer.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By defining a local cache threshold for face/name memory on the phone, we ensure that frequently encountered individuals are stored locally with high confidence, reducing latency and ensuring persistent availability even when cloud access is limited.

2. **What small change unlocks it**

   Define a specific local cache size limit of 10 people for frequent contacts (e.g., family, friends, colleagues) to be stored with high confidence on the phone.

3. **Likely payoff**

   This approach will significantly improve memory recall and confidence during interactions with known individuals, reducing reliance on cloud access and enhancing real-time responsiveness in noisy or low-bandwidth environments.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining what data should remain on-device versus what can be offloaded to the cloud, we ensure that the glasses provide real-time, low-latency assistance while respecting battery and thermal constraints.

2. **What small change unlocks it**

   Define one task-specific phone/cloud fallback boundary for live subtitle processing: use local processing for new conversations or where the cloud is unavailable; fall back to the cloud for historical context and heavy memory lookups.

3. **Likely payoff**

   This decision will help balance real-time responsiveness with battery efficiency, ensuring that critical live subtitles are always available without overwhelming the glasses' limited power resources. It also aligns with the project's commitment to discreet UX by minimizing on-glasses processing during new interactions.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Improving subtitle vs one-line prompt coexistence ensures that subtitles remain clear and unobtrusive while still providing essential contextual information through brief, one-line prompts. This balance enhances the wearer's ability to focus on spoken conversation without feeling overwhelmed by additional text.

2. **What small change unlocks it**

   Define a visual hierarchy rule that prioritizes subtitles over one-line prompts but allows for coexistence under low-confidence conditions or when one-line prompts are highly relevant and brief.

3. **Likely payoff**

   By refining the subtitle vs one-line prompt display precedence, users will experience smoother interaction flows where critical information is not lost to screen clutter. This leads to a more natural and less distracting user experience, reinforcing trust in the system's ability to assist without overburdening the wearer.

4. **Immediate next probe**

   Define one visual priority rule between subtitles and one-line support that prioritizes subtitles by default but allows brief prompts when highly relevant.
