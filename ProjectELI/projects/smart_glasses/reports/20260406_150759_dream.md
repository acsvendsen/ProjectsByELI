### Idea 3: Memory/Cache Policy

### 1. **Why it benefits the core**

Ensuring that new faces and names are remembered with high confidence can significantly enhance the wearer's trust in the system, making interactions feel more natural and less intrusive. This helps in reducing the "new person" learning curve, allowing the user to focus on the conversation rather than worrying about whether they will remember a name.

### 2. **What small change unlocks it**

Define a local cache size limit for new-person memory objects. When a new face or name is encountered, add it to a limited-size cache that automatically removes older entries as newer ones are added.

### 3. **Likely payoff**

By setting a clear local cache threshold, the system can reinforce the most relevant memories more effectively, ensuring that critical names and faces are always available without overwhelming the memory space. This will improve trust and make new interactions smoother, reducing the user's cognitive load during conversations.

### 4. **Immediate next probe**
   - Set a local cache size limit for new-person memory objects to 5 entries based on frequent reinforcement over time.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   Ensuring that live subtitle processing remains local until absolutely necessary helps preserve battery life and maintain real-time performance. This approach aligns with the project's focus on discreet, context-aware assistance by minimizing the reliance on cloud resources.

2. **What small change unlocks it**

   Define a local cache threshold for live subtitles where if the confidence level is above 0.95 (High), subtitle processing stays entirely on-device; otherwise, it falls back to the phone or cloud.

3. **Likely payoff**

   By keeping high-confidence subtitles local, we can significantly reduce battery consumption and maintain a seamless user experience without compromising on the quality of real-time assistance for frequently encountered content. This also aligns with the core mission by ensuring that the glasses remain lightweight and socially acceptable in public settings.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
