# Consolidated Signals for SmartGlasses V1

## Strengthening Signals
- **Subtitle Clarity (subtitle_clarity)**: Ensure subtitles are clear, fast, and stable enough to be trusted in real-time conversations.
- **Memory Trust (memory_trust)**: Enhance the reliability of memory support by remembering names, faces, and prior context without creating false certainty or corrupt recall.

## Weakening Signals
- **Low-Friction Interaction**: Reduce reliance on complex interactions that could create social awkwardness. Prioritize simplicity in one-line prompts and visible support.

## Contradictions That Must Stay Alive
- **Privacy vs Usefulness (privacy_vs_usefulness)**: Ensure assistive behavior is useful but does not become invasive or capture sensitive data.
- **Latency vs Richness (latency_vs_richness)**: Balance between providing timely help and avoiding overloading the system with richer, slower processing.

## Dormant Ideas Worth Reactivating
- **Subtitle Placement**: Explore more prominent subtitle placement to ensure they remain readable in motion and noise without becoming distracting.
- **Confidence Display**: Revisit the confidence display format (label + short reason) to enhance trust. Evaluate if a numeric score should be added for richer feedback.

## Concrete Tensions Around Core Areas
1. **Subtitle Quality vs Memory Richness**
   - **Rich Context vs Low-Latency Response**: Ensure subtitles remain clear and stable while managing memory support for names, faces, and prior context.
   
2. **Discreet UX vs Visual Clarity**
   - **Subtitles Dominate vs Discreet Display**: Balance between a strong visual presence of subtitles that are easily readable in motion and noise with the need to maintain social acceptability.

3. **Phone-First Processing**
   - **Heavy Phone Processing vs Light Glasses Compute**: Continue favoring heavy processing on the phone, leveraging cloud only where clearly justified by real-world constraints like battery and latency.

## Core Deepening Over Sprawl
- Focus on improving subtitle quality, memory trust, confidence display, and visual UX rather than broad feature expansion. Avoid command interfaces or hardware complexity that could distract from core mission.

## Reality Rules and Constraints
- **Frame-Touch-Only Interaction**: Ensure all interactions happen through frame touches only, not voice commands.
- **Phone-First Architecture**: Primary runtime should be on the phone with cloud optional for heavy processing.
- **Battery and Thermal Management**: Address battery and thermal constraints early to ensure V1 remains practical.

## Open Questions
- **Subtitle Placement**: Determine the best placement that balances readability and non-distracting behavior.
- **Confidence Display**: Decide between label + reason, score + label, or other formats for confidence display.
- **Memory Cache Policy**: Evaluate how much face/name memory should be cached locally to balance privacy and utility.

## Core Field
- Strengthen core functionality like live subtitles, face/name recall, conversation memory, and one-line support without compromising on battery life, privacy, or social acceptability.
