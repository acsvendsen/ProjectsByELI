# Reality Check for SmartGlasses V1 Direction

## Subtitle Placement and Visual Clarity

### Current Input: `More Prominent`

**Feasible Now:**  
- **Subtitle Placement**: Placing subtitles more prominently (e.g., near the center or slightly off-center, but clearly visible) can improve readability in noisy environments. This approach is feasible now as it does not require additional hardware and can be optimized through software adjustments.

### Confidence Display

### Current Input: `Label + Reason`

**Feasible Now:**  
- **Confidence Display**: Using a label (e.g., "High", "Medium") along with a short reason (e.g., "Based on context, name frequency, recent mentions") can provide clear and trustworthy feedback to the user. This approach is feasible now as it leverages existing text display capabilities.

### Memory/Cache Policy

### Current Input: `Recency First`

**Feasible Now:**  
- **Memory/Caching**: Implementing a recency-first caching policy on the phone can help ensure that recently seen names and faces are prioritized for quick recall. This is feasible now as it relies on existing memory management techniques.

### Phone/Cloud Boundary

### Current Input: `Phone First`

**Feasible Now:**  
- **Phone/Cloud**: Relying primarily on the phone for processing and storage while using cloud services where clearly justified aligns with V1 constraints. This approach is feasible now as it respects current hardware limitations and ensures quick response times.

### Visual Hierarchy

### Current Input: `Subtitles Dominate`

**Feasible Now:**  
- **Visual Hierarchy**: Ensuring that subtitles dominate the screen while maintaining a clear, uncluttered interface can help in reducing distractions. This is feasible now as it does not require additional hardware and can be optimized through software design.

### Core Deepening Over Sprawl

**Core-deepening over sprawl**:
- **Subtitle Quality**: Improving subtitle accuracy and clarity by fine-tuning speech-to-text models.
- **Memory Trust**: Enhancing memory support to ensure names, faces, and context are remembered accurately without creating false certainty.
- **Low-friction UX**: Ensuring that one-line prompts and confidence displays do not overwhelm the user.

### Constraint Pressure

**Battery, Latency, Privacy, Usability Limits**:
- **Subtitle Latency**: Ensuring subtitles feel near-real-time is critical. This can be managed through optimized speech-to-text processing on the phone.
- **Memory Trust**: Balancing memory support with privacy concerns by ensuring that data retention policies are transparent and user-friendly.
- **User Friction**: Keeping interactions simple (frame-touch only) helps maintain a low-friction experience.

### Interaction Constraints

**Frame Touch Only V1**:
- **Interaction Patterns**: Any proposed interaction pattern should respect the frame-touch-only constraint unless explicitly changed later. This ensures that early designs remain simple and usable.

### Drift Risks

- **Gimmick vs Daily-use Assistant**: Ensuring that the system remains a daily-use assistant rather than a gimmick.
- **Feature Sprawl**: Avoiding broad feature sprawl before core subtitle/memory loop is excellent.
- **Interaction Sprawl**: Avoiding unnecessary hardware or interaction complexity.
