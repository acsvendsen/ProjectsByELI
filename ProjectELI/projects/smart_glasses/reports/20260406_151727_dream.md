### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   Ensuring subtitle placement rules are well-defined helps maintain consistent, non-distracting subtitles for the wearer. This improves the overall user experience by making real-time subtitles more useful and less intrusive.

2. **What small change unlocks it**

   Define specific subtitle placement rules based on confidence levels: high-confidence text in a fixed position near the center of the glasses, low-confidence text slightly offset or in a secondary position, with no reactive movement or animation.

3. **Likely payoff**

   By establishing clear and unambiguous subtitle placement rules, the system can provide more stable and predictable subtitles. This reduces user confusion and increases trust that the system is reliable and not overly dynamic.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   Improving the confidence display format enhances the trustworthiness of the system by clearly communicating the reliability of the subtitles and memory recall to the wearer. A well-designed confidence object helps the user understand when they can rely on the information provided, thereby reducing cognitive load and increasing overall comfort.

2. **What small change unlocks it**

   Define a simple confidence format that includes both a numeric score and a short reason for the score.

3. **Likely payoff**

   By providing users with clear and concise confidence indicators, the system can reduce uncertainty and increase trust in its accuracy. This can lead to better user adoption and more frequent use of the SmartGlasses, as the wearer feels more confident about relying on the assistant.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   By setting a clear threshold for local memory caching of face/name evidence, the system can maintain a balance between fast lookup performance and privacy concerns. This ensures that frequently encountered individuals are remembered reliably without storing low-value or infrequently used names, thus optimizing both usability and user trust.

2. **What small change unlocks it**

   Define a specific recency threshold for local memory caching of face/name evidence. For example, set the threshold to 10 recent encounters within the last week before cached memories are considered stale and cleared from the local cache.

3. **Likely payoff**

   Implementing this threshold will help in reducing unnecessary storage overhead while ensuring that new or frequently encountered individuals remain reliably remembered. This balance enhances both memory efficiency and user trust, as the system can quickly recall names without making users feel their personal information is being retained excessively.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining clear boundaries between what runs locally on the phone versus what falls back to the cloud for memory lookup, we ensure consistent and fast memory recall without overloading the always-on system. This helps maintain low latency and preserves battery life.

2. **What small change unlocks it**

   Define a specific task boundary such as face/name recall lookup and explicitly state that any face or name recognition should be handled locally on the phone first, with fallback to the cloud only under certain conditions (e.g., if not enough local data exists).

3. **Likely payoff**

   This clear separation will allow for faster memory lookups, reduce battery drain from frequent cloud requests, and ensure that core functionality remains reliable even in low-bandwidth or offline scenarios.

4. **Immediate next probe**

   Define one phone-local vs cloud fallback boundary for face/name recall lookup.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

   Ensuring a clear visual hierarchy between subtitles and one-line prompts enhances the wearer's ability to focus on essential information without being overwhelmed by too much text. This clarity supports faster understanding and reduces cognitive load, which is crucial for real-time interactions.

2. **What small change unlocks it**

   Define a simple rule that prioritizes subtitles over one-line prompts when both are present in close proximity. For example, if the one-line prompt contains critical information (e.g., "Excuse me, I didn't catch that"), ensure this message overrides any subtitle text for a brief period.

3. **Likely payoff**

   By ensuring critical messages like one-line prompts take precedence over subtitles when necessary, the system can provide essential contextual cues without overwhelming the wearer. This improves overall user experience and ensures important information is not missed in noisy or fast-paced conversations.

4. **Immediate next probe**

   Define one visual priority rule between subtitles and one-line support for critical interactions.
