### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, the system can ensure that subtitles are always visible but not overly distracting. This helps maintain the wearer's focus while providing critical information when needed most.

2. **What small change unlocks it**

   Define three subtitle placement rules: default fixed position (e.g., bottom center), reactive placement (adjusting based on head movement), and high-confidence fallback to a fixed position.

3. **Likely payoff**

   This approach ensures that subtitles remain consistently visible without constantly moving, which can be distracting. It provides a stable experience while still accommodating dynamic scenarios where the wearer might need to look around more frequently.

4. **Immediate next probe**
   - Define the default fixed position for subtitles as bottom center.

### Idea 2: Confidence Display

1. **Why it benefits the core**
   Improving confidence display clarity helps build trust in the system's reliability, ensuring the wearer can confidently rely on the subtitles and contextual information provided.

2. **What small change unlocks it**
   Define a simple numeric score format for confidence objects that clearly indicates certainty levels without overwhelming the user.

3. **Likely payoff**
   A straightforward numeric score (e.g., 0 to 1, with increments) along with a brief label (High, Medium, Low) and short reason (e.g., "Seen recently," "Weak match") will make confidence more accessible and easier for users to interpret quickly.

4. **Immediate next probe**
   - Define the numeric score format for V1 confidence objects as: 0.8 for High certainty with "Seen frequently"; 0.5 for Medium certainty with "Somewhat familiar"; 0.3 for Low certainty with "Unsure".

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**
   Improving the cache size and eviction policy for local face/name memory ensures that the system can maintain a stable, useful set of recent encounters without overwhelming the wearer with too much information. This helps in reinforcing trust by providing timely and relevant support.

2. **What small change unlocks it**
   Define a simple cache eviction rule where old entries are removed based on recency and frequency of use. For example, keep 10 most recently seen faces/names, evicting the least frequently used ones to maintain relevance.

3. **Likely payoff**
   By implementing this rule, the system can provide faster and more accurate recall of recent interactions without overwhelming the cache with irrelevant data. This will help in maintaining a clear and useful memory pool for both the wearer and the assistant.

4. **Immediate next probe**
   Set a local cache size limit of 10 entries for face/name memory to ensure fast, relevant lookups.
