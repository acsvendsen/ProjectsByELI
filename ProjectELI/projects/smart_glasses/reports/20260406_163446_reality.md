# Reality Check for SmartGlasses V1 Direction

## Core Mission Alignment
The system remains focused on discreet assistive glasses with live subtitles, face/name recall, conversation memory, and one-line support, which is aligned with the project's mission.

### Feasible Now
- **Subtitle Placement**: **More Prominent**. Given the current focus on V1 interaction being frame-touch only, a more prominent subtitle placement (like edge of the glasses' display) can be feasible now to ensure readability without overwhelming the user.
  
- **Confidence Display**: **Label + Reason**. This option provides enough clarity for the wearer while avoiding clutter and maintaining simplicity.

- **Memory/Cache Policy**: **Recency First**. Implementing recency first ensures that recent interactions are prioritized, reducing the burden on the phone/cloud while providing relevant memory support.

- **Phone/Cloud Boundary**: **Phone First**. Given current constraints, keeping heavy processing off the glasses and leveraging cloud capabilities only where necessary is sensible.
  
- **Visual Hierarchy**: **Subtitles Dominate**. This approach ensures that subtitles are prioritized but still allows for one-line prompts to be visible when necessary.

### Feasible Later
- **Subtitle Latency**: Once battery technology improves, real-time subtitle processing on the glasses could become feasible, reducing dependency on cloud latency.
  
- **Battery and Thermal Management**: Advanced thermal management techniques can be explored in future versions. For now, focusing on minimal local logic is essential to avoid overheating.

### Likely Waste of Time
- **Voice Activation for V1**: Given the frame-touch-only interaction constraint, proposing voice activation as a primary control method in V1 is not feasible and should be deferred until after V1 is proven.
  
- **Complex AR Visuals**: These can wait until V2 or later when glasses hardware supports more complex processing.

### Assumptions Needing Evidence
- **Automatic New-Person Memory**: While automatic memory of new faces and names makes sense, the reliability and confidence in these memories need further evidence to ensure they are useful without overwhelming the wearer.
  
- **Reinforcement Rules for Memory**: The rules governing how and when memories should be reinforced need more detailed testing to determine their effectiveness.

## Core Tensions
- **Privacy vs. Usefulness**: Ensuring that memory policies respect privacy while still providing useful assistance is a key tension. Implementing recency-first caching can balance these concerns.
  
- **Battery and Thermals**: Minimizing local processing reduces thermal issues but means heavier reliance on the phone/cloud, which needs to be managed carefully.

## Drift Risks
- Becoming a gimmick: Ensuring that V1 focuses on core features like subtitles, memory recall, and one-line support is crucial to avoid deviating from the mission.
  
- Feature sprawl: Deepening subtitle quality, memory trust, confidence display, and visual UX should be prioritized over adding unnecessary complexity.

## Reality Rules
- **Subtitle Quality**: Real-time subtitles are feasible now given current hardware limits but will require optimization for clarity and speed.
  
- **Memory Trust**: Face/name recall must expose uncertainty clearly. Implementing a recency-first policy can help manage memory load without overwhelming the wearer.

- **Interaction Constraints**: Frame-touch interactions should be prioritized, with voice commands reserved as an exploration topic for future iterations.

## Summary
The current V1 direction is feasible now and well-aligned with core mission goals. Key areas like subtitle placement, confidence display, and memory caching policies can be implemented effectively while managing constraints on battery, thermals, and privacy. Voice activation should be deferred until after V1 validation to ensure focus remains on essential features.
