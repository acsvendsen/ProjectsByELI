# Reality Check for SmartGlasses V1 Direction

## Core Field
The project aims to create discreet assistive glasses focused on live subtitles, face/name recall, conversation memory, and one-line support. The initial interaction is frame-touch only.

### Current Open Questions
- What subtitle placement is most usable without becoming distracting?
- How should one-line prompts visually differ from subtitles?
- What confidence format builds trust best: label only, label + short reason, or score + label?
- How much face/name memory should be cached locally on the phone?
- Which interactions should work offline versus requiring cloud support?

## Core Attractors
- Real-time subtitle assistance in noisy environments.
- Personal memory support for names and prior conversations.
- One-line contextual prompts rather than overwhelming paragraphs.
- Low-friction human experience; assistive, not deceptive.

## Core Tensions
- Privacy vs usefulness.
- Always-on sensing vs battery and thermals.
- Local processing vs cloud intelligence.
- Rich memory vs fast lookup.
- Discreet UX vs enough visual clarity.

## Current Reality Rules
1. **Mission**: The glasses must act as a discreet, context-aware personal assistant focused on live subtitles, face/name recall, conversation memory, and one-line support to help the wearer understand better without pretending understanding.
2. **V1 Interaction**: Frame touches only; no voice activation or spoken command control in V1.
3. **Phone/Cloud Architecture**: Phone-first architecture with cloud support where clearly justified by latency considerations.

## Decision Areas

### Subtitle Placement and Visual Hierarchy
- **Subtitle Placement**: The glasses should place subtitles in a way that is prominent yet minimally distracting to ensure they are quickly readable without causing cognitive overload.
  - **Feasible Now**: More Prominent (selected).
    - Reasoning: Balancing visibility with distraction, ensuring subtitles remain easily readable.

### Confidence Display
- **Confidence Format**: The confidence format should build trust while avoiding overwhelming the user. A combination of labels and short reasons might be most effective.
  - **Feasible Now**: Label + Reason (selected).
    - Reasoning: Provides clear indication of reliability without overly complex UI, enhancing user trust.

### Memory Policy
- **Face/Name Memory**: Face/name memory should be stored with a recency-first cache policy to ensure the most relevant information is available quickly.
  - **Feasible Now**: Recency First (selected).
    - Reasoning: Helps prioritize useful and recent memories over older, less relevant ones.

### Phone/Cloud Boundary
- **Phone-First Processing**: Given current constraints, the phone should handle primary runtime for speech, context, memory lookup, and orchestration to reduce on-glasses compute load.
  - **Feasible Now**: Phone First (selected).
    - Reasoning: Ensures efficient use of resources and maintains real-time responsiveness without overloading the glasses.

### Visual Hierarchy
- **Subtitles Dominate**: Subtitles should have a clear visual hierarchy, with one-line prompts appearing as secondary information to avoid clutter.
  - **Feasible Now**: Subtitles Dominate (selected).
    - Reasoning: Ensures primary content remains prominent while providing additional support where needed.

## Reality Constraints
- **Battery and Thermal**: Glasses should remain lightweight and socially acceptable. Early versions must not depend on heavy on-glasses compute to avoid battery drain.
  - **Feasible Now**: Minimal local logic on the glasses, with most processing handled by the phone.
    - Reasoning: Ensures efficient use of resources while maintaining real-time responsiveness.

- **Real-Time Subtitles**: Subtitle placement and confidence display must feel near-real-time or trust breaks. This is critical for V1 success.
  - **Feasible Now**: High priority on subtitle latency and accuracy.
    - Reasoning: Ensures the system remains useful and trusted by providing timely information.

- **Face/Name Recall Uncertainty**: Face/name recall should clearly expose uncertainty to maintain user trust.
  - **Feasible Now**: Implement a mechanism that indicates when memory is uncertain, such as using a question mark or exclamation point in the UI.
    - Reasoning: Enhances transparency and builds confidence over time.

## Summary of Feasibility
- **Subtitle Placement (More Prominent)**: Feasible now. Ensures subtitles are visible without overwhelming the wearer.
- **Confidence Display (Label + Reason)**: Feasible now. Provides clear, concise information to build trust.
- **Memory Policy (Recency First)**: Feasible now. Prioritizes relevant and recent memories for fast lookup.
- **Phone/Cloud Boundary (Phone First)**: Feasible now. Ensures efficient use of resources while maintaining real-time responsiveness.
- **Visual Hierarchy (Subtitles Dominate)**: Feasible now. Keeps primary content prominent with secondary support.

## Evolution Rule
The project should evolve beyond its original form if that evolution strengthens the core mission, improves real-world usefulness, or increases trust, clarity, and assistive value. Expansion is good when it deepens the core, not when it distracts from it.
- **Next Steps**: Focus on iterating based on these decisions while continuously surfacing real-world limitations to avoid wasting time on low-value directions.

## Assumptions
- The glasses will remain simple in V1 with minimal local processing and heavy reliance on cloud services where necessary.
- Frame-touch interaction will be the primary method of control, ensuring a low-friction UX.
- User trust is critical, so clear indicators of uncertainty and real-time performance are essential.
