## Reality Check for SmartGlasses V1 Direction

### Core Mission
The project aims to create discreet assistive glasses focused on live subtitles, face/name recall, conversation memory, and one-line support.

### Decision Areas

#### Subtitle Placement and Visual Hierarchy
- **Subtitle Placement: More Prominent**  
  - **Feasible Now**: Placing subtitles more prominently can enhance readability but must avoid overwhelming the user. A balance is needed to ensure subtitles are clear without becoming distracting.
  - **Reasoning**: This aligns with reducing social friction by making essential information visible enough to be helpful without causing discomfort.

- **Visual Hierarchy: Subtitles Dominate**  
  - **Feasible Now**: Given that subtitles are the primary function, they should dominate the visual hierarchy. However, this must not compromise other important functionalities like confidence labels or memory prompts.
  - **Reasoning**: Ensuring subtitles remain the focal point can help in maintaining focus during conversations while allowing for secondary information to be accessible when needed.

#### Confidence Display
- **Label + Reason**  
  - **Feasible Now**: Using both a label and a short reason (e.g., "confident" or "uncertain") can provide users with clarity on the reliability of the subtitle text.
  - **Reasoning**: This approach strikes a balance between providing enough detail to build trust without overwhelming the user.

#### Memory/Cache Policy
- **Recency First**  
  - **Feasible Now**: Implementing recency first for face/name memory can ensure that recent interactions are remembered and recalled quickly, improving the real-time relevance of memory support.
  - **Reasoning**: This policy aligns with the need to provide timely assistance based on recent context.

#### Phone/Cloud Boundary
- **Phone First**  
  - **Feasible Now**: Relying primarily on the phone for processing heavy tasks such as speech recognition and context analysis can help manage battery usage and ensure real-time responses.
  - **Reasoning**: This approach leverages existing infrastructure while minimizing thermal and power consumption on the glasses.

#### Interaction Constraints
- **Frame Touches Only**  
  - **Feasible Now**: Frame touches should be used for all interactions in V1. This ensures a low-friction user experience that avoids unnecessary complexity.
  - **Reasoning**: This constraint aligns with the need to keep the system simple and discreet, reducing potential distractions.

#### Privacy vs. Usefulness
- **Balancing Act**  
  - **Feasible Now**: Implementing face/name memory should automatically store new entities but allow for reinforcement through explicit touch interactions.
  - **Reasoning**: This approach respects user privacy by not assuming knowledge the wearer does not have, while still providing useful support over time.

#### Real-time Subtitle Assistance
- **Near-Real-Time**  
  - **Feasible Now**: Ensuring subtitles are near-real-time can maintain user trust and effectiveness. Any delay in subtitle delivery should be minimized.
  - **Reasoning**: Near-real-time performance is critical for the glasses to provide meaningful assistance.

#### Interaction Constraints (Revisited)
- **No Voice Activation**  
  - **Feasible Now**: Do not assume voice activation or spoken commands in V1. Frame touches are sufficient for user control.
  - **Reasoning**: This constraint ensures a simple and reliable interaction model that is less likely to cause distractions.

### Assumptions Needing Evidence
- **Automatic New-person Memory**  
  - **Assessment Needed**: While automatic memory of new faces and names can be useful, the effectiveness and accuracy need more evidence. Contextual reinforcement should be the primary mechanism for memory recall.
  - **Reasoning**: Without robust context signals, automatically stored memories might not always be accurate or relevant.

### Summary
- The V1 direction is feasible now with the current constraints and assumptions. However, certain areas such as automatic new-person memory require further evidence to ensure they do not introduce unnecessary complexity or risk user trust.
- Focusing on core mission elements like real-time subtitles, face/name recall, and low-friction interactions will help maintain a simple yet effective design.

### Next Steps
1. **Develop Prototypes**: Create prototypes for subtitle placement, confidence display, and memory policies to validate the chosen approaches.
2. **User Testing**: Conduct initial user testing with frame touches as the primary interaction method to gather real-world feedback on usability and effectiveness.
3. **Evidence Gathering**: Collect data on automatic memory storage accuracy to refine reinforcement rules before considering broader implementation.

By addressing these points, the project can ensure that V1 is both feasible and effective in meeting its core mission without unnecessary complications.
