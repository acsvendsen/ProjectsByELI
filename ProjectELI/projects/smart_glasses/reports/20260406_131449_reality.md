# Reality Check for V1 Direction

## Core Field Overview
The core mission of the SmartGlasses project is to create discreet, context-aware personal assistance focused on live subtitles, face/name recall, conversation memory, and one-line support. The V1 direction will focus on frame-touch interactions, minimal local processing, and phone-first architecture.

## Decision Areas and Feasibility

### Subtitle Latency and Confidence
- **Subtitle Placement:** Subtitles should be placed in a way that they do not obstruct the wearer's view but remain easily readable. Placing subtitles below the text or near the lens area could work.
  - **Feasible Now:** Yes, with careful design to avoid obstruction.

- **Confidence Display:** Displaying confidence levels for memory objects and subtitles should be done in a way that is clear yet unobtrusive. Using labels like "low," "medium," and "high" alongside the text can help.
  - **Feasible Now:** Yes, with simple label formats.

### Memory Object Model
- **Automatic New-Person Memory:** Likely new people should be remembered automatically when context supports it (e.g., during introductions).
  - **Feasible Now:** Yes, based on the current design decisions and non-goals for V1.
  
- **Memory Reinforcement Over Time:** Existing memory objects should reinforce over time to improve accuracy without creating fragmented duplicates.
  - **Feasible Later:** Yes, with ongoing optimization as more data is collected.

### Phone Cloud Boundary
- **Phone First Architecture:** The system will primarily rely on the phone for heavy processing and cloud support where necessary. This reduces thermal and battery strain on the glasses.
  - **Feasible Now:** Yes, based on existing decisions (0001-phone-first-architecture).

### Interaction Design
- **Frame-Touch Interactions:** Frame-touch interactions are the primary user control mechanism in V1. No voice activation or spoken commands will be introduced initially.
  - **Feasible Now:** Yes, with frame touch as the sole interaction method.

### Privacy and Consent
- **Confidentiality of Data:** The system must handle sensitive data like face/name memory and contextual transcripts carefully to avoid privacy concerns.
  - **Feasible Now:** Yes, with conservative defaults and clear controls in place.

### Visual Hierarchy and UX
- **Subtitle vs. One-Line Prompts:** Subtitles should be designed to coexist without overwhelming the wearer. One-line prompts can appear as needed.
  - **Feasible Now:** Yes, with careful design ensuring neither overwhelms the user.

### Battery and Thermal Management
- **Low Power Requirements:** The glasses will use minimal local processing, reducing thermal pressure and battery drain.
  - **Feasible Now:** Yes, based on current hardware constraints and V1 scope.

### Usability and Social Acceptability
- **Discreet UX:** The system should remain unobtrusive to ensure social acceptability. This involves careful UI design and minimal visual interference.
  - **Feasible Now:** Yes, with focus on discreet form factors and interactions.

## Assumptions and Evidence Needed

### Subtitle Behavior
- **Subtitle Quality:** Ensuring that subtitles are clear, readable, and synchronized with the active speaker remains a high priority. This requires robust audio processing and real-time transcription.
  - **Assumption Needing Evidence:** The system must accurately detect and transcribe the active speaker in noisy environments.

### Confidence Feasibility
- **Label + Reason Format:** Using labels like "low," "medium," and "high" alongside a short reason can help build trust. This requires clear and concise confidence models.
  - **Assumption Needing Evidence:** The confidence model must be tested to ensure it is both effective and understandable.

### Memory Policy
- **Automatic New-Person Detection:** Automatically remembering new people based on context requires reliable face recognition and name association.
  - **Assumption Needing Evidence:** Face detection and name recognition models need validation in real-world settings.

### Phone/Cloud Boundaries
- **Remote Processing:** Ensuring that the system can handle heavy processing tasks off-glasses without significant latency issues is crucial.
  - **Assumption Needing Evidence:** Remote processing capabilities must be thoroughly tested to ensure they meet V1 performance requirements.

### Visual Hierarchy
- **Subtitles and Prompts:** The visual hierarchy should prioritize subtitles for active speakers while providing a clear path for one-line prompts. This requires user testing and iterative design.
  - **Assumption Needing Evidence:** User studies need to be conducted to validate the effectiveness of this approach in real-world scenarios.

## Conclusion

The current V1 direction is feasible now, focusing on discreet interactions, minimal local processing, and phone-first architecture. Key assumptions about subtitle quality, confidence display, memory policy, and visual hierarchy require further evidence through testing and user validation.
