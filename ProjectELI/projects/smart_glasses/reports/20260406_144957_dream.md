### Idea 1: Subtitle Placement

1. **Why it benefits the core**
   Improving subtitle placement stability ensures that subtitles remain consistently visible without being overly distracting, thereby enhancing the wearer's understanding and engagement in real-world interactions.

2. **What small change unlocks it**
   Define 2 to 3 fixed subtitle placement rules for different confidence states: high-confidence faces/names always at eye level, medium-confidence entities below the eyes with minimal movement, and low-confidence subtitles off-screen until more context is gathered.

3. **Likely payoff**
   By stabilizing subtitle placement, the system will reduce visual clutter and improve the overall user experience, making it easier for the wearer to follow conversations without being distracted by frequent subtitle movements or placements that are too high or low on the screen.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   By refining the confidence display format, we can ensure that the system's certainty about a name or face is communicated clearly and consistently. This helps build trust with the user by providing accurate feedback on the reliability of the information being shown.

2. **What small change unlocks it**

   Define a confidence format that uses a numeric score combined with a label and a short reason. For example: "score 0.84 + 'High' + 'Seen recently'" or "score 0.42 + 'Low' + 'Weak match'".

3. **Likely payoff**

   A clear and consistent confidence format will help users understand the reliability of the information, thereby increasing trust in the system's memory and recognition abilities.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new faces and names are automatically remembered with high confidence objects and reinforced over time helps maintain a consistent, reliable memory system for the wearer. This reduces the cognitive load on the user by providing stable and trustworthy recall of important individuals.

2. **What small change unlocks it**

   Define an automatic memory reinforcement rule that prioritizes new face/name encounters by setting a higher initial confidence threshold and increasing the frequency of updates for newly recognized entities in the cache.

3. **Likely payoff**

   By automatically reinforcing new memories, the system can quickly build up trust with the user through reliable recall of important individuals. This will reduce the need for explicit framing or constant reminders from the glasses, making the experience more seamless and effective.

4. **Immediate next probe**

   Set a local cache size limit of 10 entities for automatic memory reinforcement, ensuring that new faces and names are given priority over older memories in terms of recall accuracy and reliability.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By defining a clear boundary for what tasks run locally on the phone versus when cloud fallbacks occur, we ensure that V1 remains focused on delivering high-quality live subtitles and contextually relevant one-line support without overwhelming the glasses' limited computational resources.

2. **What small change unlocks it**

   Define explicit rules for which subtitle processing and memory lookup tasks can be handled by the local phone or require a cloud fallback.

3. **Likely payoff**

   This will reduce battery drain, improve real-time response times, and ensure that critical subtitle rendering happens on-device, enhancing trust and usability in noisy environments.

4. **Immediate next probe**
   - Choose one phone-local versus cloud fallback boundary for face/name recall lookup in V1.
