### Idea 2: Confidence Display

1. **Why it benefits the core**

   By clearly defining how confidence levels are displayed, the system can enhance trust and reliability. A well-chosen format helps the wearer understand the certainty of information provided by the glasses, which is crucial for building long-term trust.

2. **What small change unlocks it**

   Define a consistent confidence display that includes both a label (e.g., "High", "Medium", "Low") and a short reason (e.g., "Seen recently", "Weak match", "First impression").

3. **Likely payoff**

   A clear and concise confidence display will help the wearer trust the system more, leading to higher engagement and better use of the smart glasses in real-world scenarios. This improves overall user satisfaction and perceived value.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Ensuring that new face and name memories are automatically cached on the phone with a local threshold can help maintain trust by reducing the risk of privacy breaches while ensuring that critical information is readily available.

2. **What small change unlocks it**

   Define a local cache size limit for new person memory objects, setting an initial threshold where new faces and names are stored locally unless explicitly reinforced through touch interactions.

3. **Likely payoff**

   This approach will allow the system to quickly recall recently encountered individuals without relying on continuous cloud connections, enhancing both privacy and response speed while maintaining a stable user experience.

4. **Immediate next probe**

   Define one local-cache size limit for new person memory objects, set at 10 face/name entries by default.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By clearly defining what stays phone-local and what falls back to cloud for live subtitle processing, we ensure that subtitles are delivered with minimal latency and high quality, enhancing the wearer's real-time understanding in noisy environments.

2. **What small change unlocks it**

   Define a clear boundary rule: live subtitle processing should be done locally on the glasses if possible, falling back to the phone only when glasses processing fails due to thermal or battery constraints.

3. **Likely payoff**

   This will lead to more reliable and faster subtitle delivery, which is critical for maintaining the wearer's trust in the system during real-time interactions. Users are more likely to find the glasses useful if they receive subtitles immediately without delays.

4. **Immediate next probe**

   Define one local subtitle processing rule: live subtitle generation should be prioritized on the glasses with a fallback mechanism only when glasses reach thermal or battery thresholds.

### Idea 5: Visual Hierarchy

1. **Why it benefits the core**

2. **What small change unlocks it**

3. **Likely payoff**

4. **Immediate next probe**
