# Reality Check for SmartGlasses V1 Direction

## Core Mission
Create discreet smart glasses focused on live subtitles, face/name recall, conversation memory, and one-line support.

## Current V1 Guardrails
- Frame-touch only interaction
- Phone-first architecture
- Minimal local processing to reduce battery and thermal load
- Avoid new sensors or hardware unless directly justified by current inputs

## Core Tensions and Constraints
### Hard Grounding Rules
- **Hardware:** Glasses should remain lightweight. Heavy on-glasses compute is not feasible now.
- **Battery & Thermals:** Early versions must minimize power draw to ensure long battery life.
- **Latency:** Subtitles must feel near-real-time or trust breaks.
- **Privacy:** Memory recall and face/name recognition must respect user privacy.
- **Usability:** UX should be low-friction and discreet.

## Reality Check

### Subtitle Latency
**Feasible Now:** Ensure subtitles are displayed as close to real-time as possible. Any noticeable delay can degrade the user experience significantly.

### Face/Name Memory
**Likely Waste of Time:** Implementing robust face/name recognition with high accuracy in V1, given current hardware constraints and power limitations, is likely not feasible. Consider a more basic implementation that focuses on fast memory lookup using cached data from the phone.

### One-Line Support Prompts
**Feasible Now:** Design one-line prompts as lightweight UI elements that can be displayed discreetly without overwhelming the user. Ensure these are contextually relevant and add value quickly.

### Confidence Display
**Assumptions Needing Evidence:** Determine the best format for confidence display (label only, label + short reason, or score + label) through user testing. Focus on a simple but effective solution in V1.

### Subtitle Placement and Visual Hierarchy
**Feasible Now:** Experiment with different subtitle placements to find the balance between visibility and distraction. Prioritize designs that do not significantly interfere with the wearer's natural field of view.

### Interaction Design
**Feasible Now:** Stick to frame-touch interaction for V1, avoiding any new commands or modes until further evidence suggests they are necessary.

## Specific Probes

### Subtitle Display
- **Option A:** Simple text display at the bottom edge.
- **Option B:** Text displayed in a semi-transparent overlay slightly above the wearer's field of view.
- Test these options with users to determine which is most usable and least distracting.

### Confidence Labeling
- **Option 1:** Use a simple "Uncertain" label for face/name recognition.
- **Option 2:** Add a short reason like "Not recognized" or "Likely known."
- Conduct user tests to see how these labels affect trust and usability.

### Memory Lookup Caching
- Cache the most frequently seen faces/names locally on the phone. Test this caching strategy in real-world scenarios to ensure it meets V1 requirements without overloading the device.

## Summary

The current direction is **feasible now** for subtitle display, one-line prompts, confidence labeling, and minimal interaction through frame touches. Face/name memory implementation can be deferred until more advanced hardware or cloud capabilities are available. The project should continuously surface real-world limitations to ensure that V1 remains focused on delivering high-value, low-friction assistance.
