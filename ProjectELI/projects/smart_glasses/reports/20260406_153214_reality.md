# Reality Check for SmartGlasses V1 Direction

## Subtitle Placement: More Prominent

### Feasibility Analysis:
- **Current Realization**: The glasses should display subtitles more prominently, ensuring they are visible but not overwhelming the wearer's field of view. This involves finding a balance between clarity and distraction.
- **Feasibility Now**: Given the current hardware constraints, using a simple text overlay with clear font choices can be implemented without significant thermal or battery issues. 
- **Constraints**: Subtitles must feel near-real-time to maintain user trust.

### Assumptions:
- The glasses have a display capable of showing subtitles in a readable format.
- The phone can handle the initial subtitle processing and transmission efficiently.

## Confidence Display: Label + Reason

### Feasibility Analysis:
- **Current Realization**: Displaying confidence as both a label (e.g., "High," "Medium") and a short reason (e.g., "Context-based") provides users with clear feedback on the reliability of the information.
- **Feasibility Now**: This approach is feasible given current hardware constraints. It can be implemented using simple text overlays that do not heavily impact battery or thermal management.
- **Constraints**: Confidence must be displayed clearly and concisely to avoid overwhelming the user.

### Assumptions:
- The glasses have a display capable of showing additional text without significant thermal or battery issues.
- The phone can handle the processing required for generating confidence levels and reasons efficiently.

## Memory/Cache Policy

### Feasibility Analysis:
- **Current Realization**: Implementing best-effort local caching on the phone to store face/name memory, with frequent updates from the cloud when available.
- **Feasibility Now**: Given the current phone-first architecture, this approach is feasible. The glasses will rely on the phone for initial memory lookup and can fall back to local cache if necessary.
- **Constraints**: Local storage must be managed efficiently to avoid battery drain.

### Assumptions:
- The phone has sufficient storage and processing power to handle caching and occasional cloud updates.
- The user trust in memory recall is maintained by frequent syncs with the cloud.

## Phone/Cloud Boundary: Phone First

### Feasibility Analysis:
- **Current Realization**: The glasses primarily rely on the phone for heavy processing, with minimal local computation. Cloud services are used only when necessary to avoid overloading the hardware.
- **Feasibility Now**: This approach is feasible given the current hardware constraints and battery limitations.
- **Constraints**: The system must handle edge cases where the cloud service is unavailable without breaking user trust.

### Assumptions:
- The phone has a reliable connection to the cloud for occasional updates.
- The glasses can handle basic local processing with minimal thermal or battery impact.

## Visual Hierarchy: Subtitles Dominate

### Feasibility Analysis:
- **Current Realization**: Ensuring subtitles dominate the visual hierarchy, while one-line prompts are clearly distinct and less prominent.
- **Feasibility Now**: This approach is feasible given current hardware constraints. It ensures that subtitles remain the primary focus without overwhelming the wearer.
- **Constraints**: The glasses must display both subtitles and prompts in a way that does not distract from the main content.

### Assumptions:
- The glasses have sufficient display space to show both subtitles and one-line prompts effectively.
- The user interface is designed to minimize visual clutter while maintaining clarity.

## Interaction Constraint: Frame Touches Only

### Feasibility Analysis:
- **Current Realization**: All interactions with the glasses are controlled through frame touches, avoiding voice commands or spoken user inputs in V1.
- **Feasibility Now**: This approach is feasible given current hardware constraints and interaction design principles.
- **Constraints**: The system must ensure that all necessary functions can be performed using simple touch gestures.

### Assumptions:
- The glasses have a responsive touch interface capable of handling frequent interactions without thermal or battery issues.
- Users are willing to use frame touches for managing the glasses, considering it a low-friction interaction method.

## Summary

The proposed directions in V1 are generally feasible now given the current constraints and hardware capabilities. However, continuous monitoring and adjustments will be necessary as the project evolves. The core mission of discreetly assisting the wearer through live subtitles, face/name recall, conversation memory, and one-line support should remain the focus to ensure real-world usefulness and user trust.

### Next Steps
- **Subtitle Placement**: Optimize font choices and placement for clarity without distraction.
- **Confidence Display**: Implement a clear label and reason format.
- **Memory Policy**: Ensure efficient local caching with frequent cloud updates.
- **Phone/Cloud Boundary**: Maintain phone-first architecture while preparing for potential cloud services.
- **Visual Hierarchy**: Design interfaces to prioritize subtitles over prompts.
- **Interaction Constraint**: Refine touch interactions to ensure smooth and reliable user control.

By addressing these areas, the project can continue to evolve while staying true to its core mission.
