## Reality Check for SmartGlasses V1 Direction

### Subtitle Placement
**Feasible Now**
- **Reasoning:** Given the current architecture focusing on phone-first processing, subtitle placement can be optimized through lightweight sensors that detect user gaze or head movements. Initial placements could start with a fixed position at the bottom of the field of view and adjust based on user feedback.
- **Concrete Example:** Display subtitles 10 cm below the center of the glasses' display area.

### Confidence Display
**Feasible Now**
- **Reasoning:** Confidence can be displayed using a simple label (e.g., "likely," "uncertain") that changes color to indicate certainty. This can be integrated into the visual hierarchy without overwhelming the user.
- **Concrete Example:** Use a green color for high confidence and red for low confidence, with labels like "likely" or "unsure."

### Memory/Cache Policy
**Feasible Now**
- **Reasoning:** Memory should leverage phone storage to cache recent interactions and faces. This reduces on-glasses complexity while ensuring reliable recall.
- **Concrete Example:** Cache the last 20 encounters (with their confidence levels) locally, refreshing with new interactions.

### Phone/Cloud Boundary
**Feasible Now**
- **Reasoning:** The system should rely heavily on the phone for complex memory and context processing. Cloud access can be optional for background updates.
- **Concrete Example:** Use the phone to perform entity linking and context retrieval, while keeping heavy processing tasks like model training in the cloud.

### Visual Hierarchy
**Feasible Now**
- **Reasoning:** The visual hierarchy should prioritize subtitles over prompts and ensure that both elements are easily distinguishable. Subtitles can be placed at the bottom of the field of view with a semi-transparent background, while one-line prompts appear slightly above them.
- **Concrete Example:** Subtitles use 80% opacity for readability but minimal distraction; one-line prompts use 50% opacity and appear 1 cm above subtitles.

### Interaction Constraints
**Feasible Now**
- **Reasoning:** Frame-touch interactions are the primary input method, ensuring low complexity and ease of use.
- **Concrete Example:** Implement a simple double-tap to confirm or dismiss subtitles, single tap for memory reinforcement, and long press to switch between different modes (e.g., subtitles on/off).

### Hard Grounding Rules
**Feasible Now**
- **Reasoning:** Adhering strictly to the frame-touch-only interaction ensures a low-friction user experience.
- **Concrete Example:** Do not implement voice commands or spoken commands until explicitly changing direction.
