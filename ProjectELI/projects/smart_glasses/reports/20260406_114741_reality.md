# Reality Check for SmartGlasses V1 Direction

## Core Mission Alignment

### Feasible Now: Subtitle Placement and Visual Hierarchy
- **Subtitle Placement**: Place subtitles just below the field of view, ensuring they are readable without obstructing the wearer's natural gaze. A fixed position slightly above or to the side of the visual center can be tested.
- **Visual Hierarchy**: Ensure subtitles and one-line prompts have distinct and non-overlapping visual elements. Use color contrast and size differences to distinguish between live subtitles and memory-related prompts.

### Feasible Now: Confidence Display
- **Confidence Label Only**: For initial V1, a simple confidence label (e.g., "low," "medium," "high") can be used without a detailed reason. This helps in managing complexity while providing clear user feedback.
- **User Trust and Clarity**: Keep the display of confidence labels minimalistic to avoid overwhelming the wearer but ensure they are visible enough to build trust.

### Feasible Now: Memory Policy
- **Local Cache vs Cloud Storage**: For V1, use a local cache for frequently encountered faces/names on the phone. This reduces dependency on cloud storage and minimizes latency issues.
- **Memory Reinforcement Mechanism**: Implement a reinforcement learning mechanism where the system remembers new faces/names with increasing confidence over time through repeated interactions.

### Feasible Now: Interaction Design
- **Frame-Touch Only Interaction**: Ensure that all interactions, including subtitle management and confirmation of memory entries, are controlled through frame touches. Avoid voice commands or spoken commands in V1 to keep the interaction simple and low-friction.

## Real-World Constraints

### Subtitle Latency and Confidence Clarity
- **Subtitle Latency**: Ensure subtitles appear within 300ms of hearing speech for real-time assistance, especially in noisy environments. This can be tested with initial prototypes.
- **Confidence Clarity**: Use a simple confidence label to indicate the reliability of memory entries. Avoid complex explanations that might distract or confuse the wearer.

### Battery and Thermal Management
- **Battery Draw**: Optimize the glasses' hardware for minimal power consumption by using low-power displays and sensors. Ensure the phone handles heavy processing without draining the battery too quickly.
- **Thermal Pressure**: Design the glasses to have a lightweight form factor and use materials that can dissipate heat efficiently.

### Privacy and User Trust
- **Privacy Perception**: Clearly indicate when the system is actively recording or processing audio/visual data. Provide options for users to disable certain features if they prefer not to share this information.
- **User Trust**: Implement mechanisms to ensure that the system does not over-rely on memory entries, maintaining a balance between assistance and privacy.

### Social Acceptability
- **Discreet UX**: Design the glasses to be as unobtrusive as possible. Use subtle visual cues for confidence labels and minimize distractions from subtitles and prompts.

## Evolution Rule

- **Core Deepening Changes**: Focus on improving subtitle quality, memory trust, and confidence display rather than broad feature sprawl.
- **User-Centric Iteration**: Continuously gather user feedback to refine the interaction design and ensure it aligns with real-world needs.

## Drift Risks

- **Gimmick Risk**: Avoid overcomplicating the system by focusing on core features that provide immediate value.
- **Complexity Risk**: Keep interactions simple and low-friction, ensuring the glasses remain a helpful tool rather than a source of confusion or anxiety.

### Open Questions

1. **Subtitle Placement and Visual Hierarchy**:
   - What is the best fixed position for subtitles to ensure readability without distraction?
   - How should one-line prompts visually differ from subtitles in terms of color, size, and placement?

2. **Confidence Display Format**:
   - Should confidence be represented as a numeric score, label only, or both with a short reason? What format builds trust best?

3. **Memory Cache Strategy**:
   - How much memory should be cached locally on the phone to balance between performance and privacy?
   - What is an effective reinforcement learning mechanism for remembering new faces/names over time?

4. **Interaction Design**:
   - Which interactions should work offline versus requiring cloud support? What are the trade-offs in terms of user experience and system reliability?

### Reality Check Summary

- Subtitle placement, confidence display, memory policy, interaction design, and visual hierarchy can be tackled with feasible solutions that align with V1 constraints.
- Focus on minimizing complexity while ensuring core mission alignment.
- Continuously surface real-world limitations to guide future iterations without wasting time on low-value directions.
