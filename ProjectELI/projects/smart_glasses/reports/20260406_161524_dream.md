### Idea 1: Subtitle Placement

1. **Why it benefits the core**

   By defining specific subtitle placement rules based on confidence levels, we can ensure that subtitles are always visible when needed most, reducing cognitive load without overwhelming the wearer.

2. **What small change unlocks it**

   Define three subtitle placement rules: 
   - "Fixed Position" for high-confidence entities (e.g., known people).
   - "Above Speaker" for medium-confidence entities (e.g., likely new faces and names).
   - "Contextual Fallback" to the bottom of the frame when confidence is low.

3. **Likely payoff**

   This approach will provide a stable and unobtrusive subtitle placement strategy that enhances understanding without causing distraction, thereby deepening trust in the system's core functionality.

4. **Immediate next probe**
   - Define one fixed subtitle position rule for V1: keep subtitles at the bottom center of the display.

### Idea 2: Confidence Display

1. **Why it benefits the core**

   A well-defined confidence format helps build trust by providing clear, concise feedback on the reliability of the information being displayed. This enhances the wearer's understanding and acceptance of the system, ensuring that they are more likely to rely on the subtitles and memory support provided.

2. **What small change unlocks it**

   Define a simple yet informative confidence object format: use a score (e.g., 0-1), a label (e.g., High, Medium, Low), and a short reason (e.g., "Seen recently," "Weak match").

3. **Likely payoff**

   By providing clear and consistent feedback on the reliability of the information, users will trust the system more. This can lead to increased usage and better real-world utility as users feel they can depend on the subtitles and memory support.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

4. **Immediate next probe**

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**
   - Ensuring that critical subtitle processing and face/name recall operations remain local helps maintain real-time performance and reduces battery drain, both of which are crucial for trust and usability.

2. **What small change unlocks it**
   - Define a clear boundary rule: live subtitle rendering and initial face/name recognition run on the phone, with fallback to cloud only when latency is acceptable.

3. **Likely payoff**
   - This approach ensures that the primary V1 interactions are fast and reliable, reducing the risk of delayed or corrupted subtitles which could break user trust. It also allows for more efficient use of the cloud where it can add value without sacrificing performance.

4. **Immediate next probe**
   - Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing: "Define a rule that all live subtitle rendering runs on the phone, with a maximum acceptable latency of 100ms, and falls back to cloud only if the delay exceeds this threshold."
