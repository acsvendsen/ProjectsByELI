## Reality Check for SmartGlasses V1 Direction: Subtitles, Memory, Interaction, Phone/Cloud Boundary, Visual Hierarchy

### Core Mission Alignment

The project aims to create smart glasses that act as a discreet, context-aware personal assistant focusing on live subtitles, face/name recall, conversation memory, and one-line support. The core mission is to help the wearer understand better without pretending knowledge they do not have.

### V1 Direction Feasibility

#### Subtitle Placement
**Feasible now:** Given the current interaction constraint of frame-touch-only control, subtitle placement should be designed to minimize disruption while ensuring clarity and ease of reading. Placing subtitles more prominently could enhance usability but must avoid becoming overly distracting. Early testing can help determine the optimal balance between visibility and distraction.

#### Confidence Display
**Feasible now:** Using a label + short reason format for confidence display can build trust by providing clear feedback on the reliability of information provided to the wearer. This approach respects the need for clarity over feature density while adhering to battery and thermal constraints.

#### Memory/Cache Policy
**Feasible later:** The initial version should rely heavily on the phone for memory lookup, with minimal caching on the glasses themselves. As the system evolves, more sophisticated local processing could be introduced if it does not significantly impact battery life or thermal management. For now, keeping the architecture as a phone-first model is practical.

#### Phone/Cloud Boundary
**Feasible now:** Given the current direction of phone-first processing with cloud support only where necessary, this approach aligns well with the real-world constraints. Full on-glasses inference should be avoided until hardware and thermal management can support it effectively.

#### Visual Hierarchy
**Feasible now:** Prioritizing subtitles over other UI elements by ensuring they dominate the visual hierarchy can help maintain focus without overwhelming the wearer. This approach respects the need for a low-friction user experience while providing essential information quickly.

### Interaction Constraints

- **Frame Touches Only:**
  - **Feasible now:** Frame-touch-only interaction is a concrete constraint that should be adhered to in V1. Any suggestions or designs that deviate from this constraint without explicit justification are likely waste of time.
  
- **No Voice Activation:**
  - **Feasible now:** Voice activation as a primary user-control method is not part of V1. Any exploration into voice interaction should be considered a future direction rather than an immediate design assumption.

### Real-World Constraints

#### Battery and Thermal Pressure
- **Feasible now:** Early versions should avoid heavy on-glasses computation to manage battery draw and thermal management. Subtitles must feel near-real-time or risk breaking trust. Face/name recall must also expose uncertainty clearly to maintain user trust.

#### Social Acceptability and Privacy
- **Feasible now:** The system should help the wearer understand better, not fake understanding. Memory policies should respect privacy by being transparent about how new faces and names are handled while providing necessary support.

### Core Tensions

- **Privacy vs Usefulness:**
  - **Likely waste of time:** Exploring overly complex memory policies that prioritize broad utility over user privacy may be premature. Focus on core functionality first, then refine as trust is established.
  
- **Always-on Sensing vs Battery and Thermals:**
  - **Feasible now:** Early versions should rely heavily on the phone for processing to avoid battery drain and thermal issues.

### Evolution Rule

The project can evolve beyond its original form if it strengthens the core mission, improves real-world usefulness, or increases trust. Expansion is good when it deepens the core, not when it distracts from it.

### Drift Risks

- **Becoming a Gimmick:**
  - **Assumptions needing evidence:** Before expanding features beyond the core subtitle/memory loop, ensure each addition significantly enhances real-world usefulness and trust.
  
- **Feature Sprawl:**
  - **Feasible now:** Focus on refining core functionality rather than broadening feature sets. Early versions should be simple yet effective.

### Conclusion

The current direction of V1 is feasible given the constraints and core mission. Subtitle placement, confidence display, memory policy, phone/cloud boundary, and visual hierarchy are all areas that can be addressed with concrete design choices while respecting real-world limitations. Continuous surface of these constraints early will ensure the project stays on track to deliver a useful, discreet, and assistive smart glasses system.
