# Reality Check for SmartGlasses V1

## Core Field and Attractors

### Subtitle Clarity - **Feasible Now**
- **Current Status**: Real-time subtitles need to be clear, fast, and stable.
- **Concrete Constraints**:
  - **Latency**: Subtitles must remain near-real-time; any delay can break user trust.
  - **Display Quality**: Text clarity and readability are critical in noisy environments.
  - **Implementation Grounding**: The `TranscriptLab` test app is a good start for validating subtitle behavior.

### Memory Trust - **Feasible Later**
- **Current Status**: Remember names, faces, and context without over-reliance on certainty.
- **Concrete Constraints**:
  - **Memory Policy**: Recency-first caching can help maintain relevance but must be balanced with privacy concerns.
  - **Confidence Display**: Label + reason approach is promising but needs further testing to ensure it does not overwhelm the user.
  - **Implementation Grounding**: The `TranscriptLab` app provides a foundation for testing memory recall and confidence display.

### Low-Friction Assistance - **Feasible Now**
- **Current Status**: Deliver one-line help without command overhead.
- **Concrete Constraints**:
  - **Interaction Mode**: Frame-touch interactions should be sufficient for initial V1.
  - **Visual Hierarchy**: Subtitles dominate the UI, ensuring minimal disruption to the user experience.
  - **Implementation Grounding**: Current design choices in `TranscriptLab` align well with this goal.

## Core Tensions

### Privacy vs Usefulness - **Constraint Pressure**
- **Current Status**: Balancing help and privacy is crucial.
- **Concrete Constraints**:
  - **User Trust**: Automatic memory support must be balanced against the risk of creating overly confident or inaccurate recall.
  - **Implementation Grounding**: The `TranscriptLab` app can test different levels of confidence display to gauge user trust.

### Latency vs Richness - **Constraint Pressure**
- **Current Status**: Need for timely assistance versus richer context is a key tension.
- **Concrete Constraints**:
  - **Subtitle Latency**: Subtitles must be fast enough to be useful without breaking real-time conversation.
  - **Memory Recall**: Fast lookup and memory recall are essential but should not overwhelm the user interface.
  - **Implementation Grounding**: The `TranscriptLab` app can help validate these trade-offs.

### Discreet UX vs Visual Clarity - **Constraint Pressure**
- **Current Status**: Display behavior must remain socially acceptable while being readable in motion and noise.
- **Concrete Constraints**:
  - **Subtitle Placement**: Subtitles should be prominently displayed but not overly intrusive.
  - **Confidence Display**: Confidence labels and reasons need to be clear without overwhelming the user.
  - **Implementation Grounding**: `TranscriptLab` can test different subtitle placements and confidence displays.

## Core Tensions (Continued)

### Always-On Sensing vs Battery and Thermals - **Constraint Pressure**
- **Current Status**: Early hardware remains simple, with heavy processing on the phone.
- **Concrete Constraints**:
  - **Battery Draw**: Subtitle generation and memory lookup should be optimized to minimize battery drain.
  - **Thermal Management**: Continuous always-on sensing is not advisable in early V1.
  - **Implementation Grounding**: The `TranscriptLab` app can help optimize power consumption.

### Rich Context vs Low-Latency Response - **Constraint Pressure**
- **Current Status**: Need for timely assistance versus rich contextual support.
- **Concrete Constraints**:
  - **Subtitle Quality**: Subtitles should be clear and accurate, even if they are not always the most context-rich.
  - **Memory Lookup**: Fast lookup is essential but should not compromise real-time responsiveness.
  - **Implementation Grounding**: The `TranscriptLab` app can test different levels of contextual support.

## Core Tensions (Final)

### Discreet UX vs Visual Clarity - **Constraint Pressure**
- **Current Status**: Display behavior must remain socially acceptable while being readable in motion and noise.
- **Concrete Constraints**:
  - **Subtitle Placement**: Subtitles should be prominently displayed but not overly intrusive.
  - **Confidence Display**: Confidence labels and reasons need to be clear without overwhelming the user.
  - **Implementation Grounding**: `TranscriptLab` can test different subtitle placements and confidence displays.

## Core Tensions (Summary)

### Broad Recommendations
- **Subtitle Placement**: Prominent placement is essential for clarity but must avoid being too distracting.
- **Confidence Display**: Label + reason approach is promising but needs further testing to ensure it does not overwhelm the user.
- **Memory Policy**: Recency-first caching can help maintain relevance but must be balanced with privacy concerns.

## Core Constraints

### Frame Touch Only V1 - **Hard Constraint**
- **Current Status**: V1 interaction should happen through frame touches, not voice commands.
- **Concrete Constraints**:
  - **User Control**: Frame-touch interactions are the primary control method for V1.
  - **Interaction Design**: The `TranscriptLab` app provides a foundation for testing and refining these interactions.

### Phone-First Runtime - **Hard Constraint**
- **Current Status**: Heavy processing should primarily happen on the phone, with cloud optional where clearly justified.
- **Concrete Constraints**:
  - **On-Glasses Compute**: Early hardware remains simple, with heavy processing offloaded to the phone.
  - **Cloud Use**: Cloud support is optional and only used where it adds clear value.

### Core Deepening Over Sprawl - **Guiding Constraint**
- **Current Status**: Focus on improving subtitle quality, memory trust, confidence display, and visual UX over broad feature expansion.
- **Concrete Constraints**:
  - **Feature Prioritization**: Core improvements should be prioritized over broad feature sprawl.
  - **Implementation Grounding**: The `TranscriptLab` app provides a foundation for testing these core features.

## Reality Check Summary

### Feasible Now
- Subtitle Clarity
- Low-Friction Assistance

### Feasible Later
- Memory Trust

### Likely Waste of Time
- Broad feature sprawl without core improvements
- Voice activation in V1

### Assumptions Needing Evidence
- Specific confidence display format (label + reason vs. score + label)
- Optimal subtitle placement and visual hierarchy

## Final Thoughts

The current direction is focused on improving the core functionality of subtitles, memory recall, and low-friction assistance. The `TranscriptLab` app provides a strong foundation for validating these features. Key constraints include maintaining social acceptability, minimizing battery draw, and ensuring real-time responsiveness. Early hardware remains simple, with heavy processing offloaded to the phone. The focus should remain on core improvements rather than broad feature expansion in V1.
