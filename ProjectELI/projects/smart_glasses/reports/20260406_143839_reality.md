# Reality Check for SmartGlasses Project Cognition System (V1 Direction)

## Core Mission and Non-negotiables
- **Discreet, context-aware personal assistant** focusing on live subtitles, face/name recall, conversation memory, and one-line support.
- **Frame-touch only interaction**: no voice activation or spoken command control in V1.
- **Phone-first architecture**: rely heavily on phone processing with cloud optional where it adds clear value.

## Core Attractors
- Real-time subtitle assistance in noisy environments.
- Personal memory support for names and prior conversations.
- One-line contextual prompts rather than overwhelming paragraphs.
- Low-friction human experience; assistive, not deceptive.

## Core Tensions
- **Privacy vs Usefulness**: Balancing the need to remember new faces and names with privacy concerns.
- **Always-on sensing vs Battery and Thermals**: Minimizing battery drain while providing useful always-on features.
- **Local processing vs Cloud Intelligence**: Deciding where heavy lifting should occur.
- **Rich Memory vs Fast Lookup**: Managing memory storage and retrieval for optimal performance.

## Drift Risks
- Becoming a gimmick instead of a daily-use assistant.
- Feature sprawl before core subtitle/memory loop is solidified.
- Interaction sprawl that adds unnecessary complexity before the touch-first V1 is stable.
- High-latency responses breaking trust.
- Storing low-value information instead of weighted relevant memory.

## Core Decision Areas
### Subtitle Placement and Confidence Display

**Subtitle Placement**
- **Feasible Now**: Ensure subtitles are placed in a non-distracting manner that does not block the user’s view. For instance, placing them slightly above or below the speaker's mouth.
- **Assumptions Needing Evidence**: Conduct user studies to determine optimal placement for different types of environments (e.g., noisy vs quiet settings).

**Confidence Display**
- **Feasible Now**: Use a simple label format (e.g., "Possible" or "Certain") that can be quickly understood. Include short reasons if space allows.
- **Assumptions Needing Evidence**: Test various confidence formats to see which builds trust best without overwhelming the user.

### Memory/Cache Policy

**Face/Name Memory**
- **Feasible Now**: Remember new faces and names automatically with context support, while providing reinforcement for explicit memories.
- **Likely Waste of Time**: Assuming high accuracy in automatic memory capture without strong contextual evidence. Consider initial manual tagging or reinforcement.

**Reinforcement Rules**
- **Feasible Now**: Implement rules where the system reinforces remembered entities over time. For example, if a name is remembered multiple times in different contexts.
- **Assumptions Needing Evidence**: Determine how many interactions are needed for confidence to increase significantly.

### Phone/Cloud Boundary

**Local vs Cloud Processing**
- **Feasible Now**: Use the phone primarily for processing and orchestration while keeping heavy lifting off-glasses. For instance, use cloud services for complex face recognition but keep core subtitle generation on-device.
- **Assumptions Needing Evidence**: Evaluate battery usage with different levels of cloud dependency to ensure minimal impact.

### Visual Hierarchy

**Subtitle vs One-line Prompts**
- **Feasible Now**: Design a visual hierarchy that clearly distinguishes subtitles from one-line prompts. For example, using different colors or sizes.
- **Likely Waste of Time**: Overcomplicating the visual design with too many elements if it does not significantly improve user experience.

### Interaction Constraints

**Frame Touches Only**
- **Feasible Now**: Ensure all interactions are handled through frame touches to maintain simplicity and ease of use.
- **Assumptions Needing Evidence**: Test different touch-based interaction patterns to find the most intuitive and least obtrusive way for users to control the glasses.
