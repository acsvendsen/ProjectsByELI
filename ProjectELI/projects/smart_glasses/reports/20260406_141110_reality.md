# Reality Check for SmartGlasses V1 Direction

## Core Mission Alignment

### Feasible Now: Subtitle Placement and Confidence Display
- **Subtitle Placement**: 
  - *Placement*: Ensure subtitles appear below or near the relevant speech. This keeps them unobtrusive yet easily readable.
  - *Visual Hierarchy*: Prioritize text clarity over fancy animations; use a consistent, non-distracting layout.

### Feasible Now: Memory Policy and Confidence Representation
- **Memory/Cache Policy**: 
  - *Local Storage*: Automatically store new faces and names with moderate confidence until reinforced. This aligns with the V1 frame-touch interaction.
  - *Reinforcement Rules*: Reinforce memory by touching the glasses frame when remembering something important.

- **Confidence Display**:
  - *Label Only vs Label + Reason*: Use a simple label (e.g., "Uncertain") with a brief reason when appropriate. This provides clear, non-overwhelming feedback to the user.
  - *Label Format*: Keep labels concise and easily readable in small form factors.

### Feasible Later: Phone/Cloud Boundary
- **Phone Processing**: 
  - Use the phone for heavy processing such as context analysis, memory lookup, and model inference. Ensure the glasses remain lightweight.
  - Consider cloud support only where it significantly improves performance without adding unacceptable latency or complexity.

## Interaction Constraints

### Frame Touch Only
- *Interaction Design*: Frame touches should control basic functions like confirming subtitles or switching modes. Voice interaction is not part of V1 but could be explored later as a future feature.

## Real-world Limits and Practical Implications

### Battery and Thermal Management
- **Simplify Hardware**: Keep the glasses hardware minimal to reduce thermal and battery demands.
- **Optimize Subtitle Latency**: Ensure subtitles feel near-real-time. Any delay can break user trust and perceived utility.

### Privacy and Usability
- **Low Friction UX**: Design interactions that are quick and unobtrusive. Avoid overwhelming the user with too much information at once.
- **User Trust**: Be transparent about what memory is being stored and how it is used. Use simple, clear labels to convey confidence levels.

## Evolution Rule

### Core Deepening
- *Subtitle Quality*: Focus on improving subtitle accuracy and speed of appearance over adding more complex features.
- *Memory Trust*: Ensure that new face/name recognition is reliable but not overly intrusive. Reinforcement through frame touches should be the primary mechanism for building trust.

### Discreet UX
- Keep the glasses discreet and unobtrusive, focusing on clear, straightforward interactions rather than complex visual effects.

## Open Questions

### Subtitle Placement and Visual Hierarchy
- *Subtitle Layout*: Experiment with different subtitle placements to find a balance between visibility and non-distractiveness.
- *Visual Clarity*: Ensure subtitles are easily readable without overwhelming the user. Use contrasting colors and clear fonts.

### Confidence Display
- *Feedback Design*: Test different confidence formats (label only, label + short reason) to see which builds trust most effectively.
- *User Feedback*: Collect feedback on how users perceive the current confidence labels and make iterative improvements based on this input.

## Reality Rules

### Core Mission Focus
- Prioritize subtitle quality and memory reliability over additional features until V1 is proven effective.
- Ensure that any new feature adds value to the core mission without complicating the user experience.

### Interaction Patterns
- Stick to frame touches for V1 interactions. Avoid introducing more complex interaction patterns unless explicitly justified by real-world testing.

### Cloud Dependency
- Limit cloud dependency to scenarios where it significantly improves performance or utility. Always ensure that local processing can handle critical tasks.
  
## Summary

- **Subtitle Placement and Confidence Display**: Feasible now, focus on usability and clarity.
- **Memory Policy and Reinforcement Rules**: Feasible now, prioritize reliability and user trust.
- **Phone/Cloud Boundary**: Feasible later, explore when necessary to improve performance.
- **Frame Touch Only Interaction**: Feasible now, ensure interactions are simple and unobtrusive.

By focusing on these areas, the project can build a robust V1 that sets a strong foundation for future improvements while adhering to the core mission of discreet, context-aware personal assistance.
