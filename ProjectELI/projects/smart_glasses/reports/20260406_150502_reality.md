# Reality Check for SmartGlasses V1 Direction

## Core Feasibility Assessments

### Subtitle Placement: More Prominent
- **Feasible Now**: The glasses can display subtitles more prominently while maintaining social acceptability. The current design should focus on ensuring the subtitles are readable and not overly distracting.
- **Reasoning**: With minimal local processing, the glasses can handle simple subtitle rendering without significant battery or thermal strain.

### Confidence Display: Label + Reason
- **Feasible Now**: Implementing confidence as a label with a brief reason (e.g., "likely," "maybe") will help users understand the reliability of the information. This approach is lightweight and can be updated based on real-time context.
- **Reasoning**: A simple, visual label combined with a short reason provides clear feedback without overwhelming the user.

### Memory/Cache Policy: Best Effort Within Phone
- **Feasible Now**: The phone can cache face/name memories using best-effort techniques. This approach balances memory storage and lookup speed while minimizing cloud dependency.
- **Reasoning**: Cloud storage is optional, so local caching on the phone is a practical choice to ensure fast recall and reduce latency.

### Phone/Cloud Boundary: Phone First
- **Feasible Now**: The system should primarily rely on the phone for processing. Using the cloud only where it adds clear value (e.g., complex entity linking) will keep V1 lightweight.
- **Reasoning**: Local processing reduces battery draw and thermal stress, aligning with the current focus on social acceptability.

### Visual Hierarchy: Subtitles Dominate
- **Feasible Now**: The display should prioritize subtitles to ensure they are easily readable. One-line prompts can be displayed in a secondary position without overwhelming the user.
- **Reasoning**: This hierarchy helps maintain clarity and usability, ensuring that the primary information (subtitles) is prioritized over supplementary text.

### Interaction Constraints: Frame Touches Only
- **Feasible Now**: All interactions should remain frame touch-based. Voice activation or spoken command control can be explored in later versions.
- **Reasoning**: This approach aligns with the current V1 design and respects social acceptability constraints.

## Core Tensions

### Privacy vs Usefulness
- **Real-world Limits**: Implementing automatic memory of new faces and names must balance between usefulness and privacy. The system should clearly indicate when it is remembering information.
- **Feasible Now**: Integrate a framing mechanism that allows the wearer to understand when the glasses are capturing or remembering information.

### Always-on Sensing vs Battery and Thermals
- **Real-world Limits**: Continuous subtitle generation and memory recall can strain battery life. The system must remain lightweight.
- **Feasible Now**: Optimize subtitle rendering and memory processing to minimize thermal and power consumption while maintaining functionality.

### Local Processing vs Cloud Intelligence
- **Real-world Limits**: Relying heavily on the phone for processing reduces cloud dependency but limits real-time capabilities.
- **Feasible Now**: Use the phone for primary runtime and only offload heavy tasks when necessary, ensuring low latency and reliability.

## Evolution Rule

### Core Mission: Discreet, Context-aware Personal Assistant
- **Real-world Limits**: Evolve beyond the initial form if it strengthens the core mission or improves real-world usefulness.
- **Feasible Now**: Focus on deepening subtitle quality, memory trust, confidence display, and low-friction visual UX to create a more useful and discreet assistant.

### Feature Sprawl vs Core Deepening
- **Real-world Limits**: Avoid broad feature sprawl that distracts from the core mission. Ensure new features add value.
- **Feasible Now**: Prioritize improvements that enhance subtitle quality, memory trust, confidence display, and low-friction visual UX.

## Drift Risks

### Gimmick vs Daily-use Assistant
- **Real-world Limits**: The system should remain a practical assistant rather than a gimmick. Focus on daily usability.
- **Feasible Now**: Design with clear user benefits in mind to ensure the glasses are useful and not just novel.

### Interaction Complexity vs Usability
- **Real-world Limits**: Overcomplicated interactions can reduce user trust and acceptability. Keep interactions simple and intuitive.
