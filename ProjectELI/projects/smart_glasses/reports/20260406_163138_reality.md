## Reality Check for SmartGlasses V1 Direction: Core Mission vs Real-World Limits

### Core Mission vs Real-World Constraints

#### Subtitle Placement
- **Feasible Now:** `More Prominent` placement is a reasonable choice given the need for fast, unobtrusive reading. However, the glasses must remain socially acceptable and not distract too much from the wearer's view. Experimenting with slightly more prominent but still unobtrusive placements like near the center or slightly above eye level could be tested early.

#### Confidence Display
- **Feasible Now:** Label + Reason is a practical approach that provides clarity without overwhelming the user. This can be implemented as a simple text overlay next to subtitles, ensuring it does not interfere with reading speed but still builds trust through transparent communication of confidence levels.

#### Memory/Cache Policy
- **Feasible Now:** Recency First caching on the phone makes sense given the need for fast lookups and context persistence. This approach minimizes storage overhead while maintaining recent and relevant information, reducing cloud dependency and thermal/battery strain.

#### Phone/Cloud Boundary
- **Feasible Now:** A strong focus on `Phone First` processing aligns with current hardware constraints and reduces unnecessary cloud reliance. Cloud integration can be explored for deeper analysis or background tasks where it adds significant value without compromising real-time performance.

#### Visual Hierarchy
- **Feasible Now:** Subtitles dominating the visual hierarchy is a sensible approach, ensuring that key information (subtitles) remains prominent while still allowing space for less critical elements like confidence labels. This balance helps in maintaining clear and uncluttered user experience.

### Interaction Constraints

#### Frame Touch Only Interactions
- **Feasible Now:** Frame touches as the sole interaction method is well-supported by current hardware constraints. Ensuring that all necessary functions can be controlled through this minimalistic approach will help in maintaining a discreet and unobtrusive design. Further, early testing with users to validate touch-based interactions can inform any necessary adjustments.

### Core Attractors

#### Real-Time Subtitle Assistance
- **Feasible Now:** Real-time subtitles are crucial for noisy environments and hearing-challenged situations. Implementing this feature as V1 will provide immediate value while keeping complexity manageable.

#### Personal Memory Support
- **Feasible Later:** Personal memory support can be a valuable addition but may require more development time to ensure robustness and privacy controls. Initial testing could focus on contextually relevant information with explicit user consent and reinforcement mechanisms.

#### One-Line Contextual Prompts
- **Feasible Now:** Implementing one-line prompts for quick, contextual assistance is feasible and aligns well with the V1 interaction constraints. These can be used to provide brief reminders or clarifications without overwhelming the user.

### Core Tensions

#### Privacy vs Usefulness
- **Assumptions Needing Evidence:** The system should balance privacy by default with the usefulness of remembering names and faces. Explicit touch-based reinforcement could be a viable way to address this tension, ensuring that new entities are remembered based on explicit user interaction rather than passive recognition.

#### Always-On Sensing vs Battery/Thermals
- **Feasible Now:** Early versions should avoid always-on sensing to mitigate battery drain and thermal issues. Only critical sensors (like microphones for real-time speech input) can be used, with non-critical functions relying on user-initiated interactions or cloud processing.

### Drift Risks

#### Gimmick Risk
- **Feasible Now:** Focusing on core features like subtitles and memory recall will help avoid the risk of becoming a gimmick. Ensuring that these features provide tangible value will keep the system relevant and useful.

#### Feature Sprawl
- **Assumptions Needing Evidence:** Expanding beyond core features should be done with caution to maintain focus. User testing can help identify which additional features add significant value without complicating the user experience.

### Why It Matters

The core mission of creating a discreet, context-aware personal assistant is essential for addressing real-world challenges like understanding in noisy environments or memory support during conversations. Ensuring that these features are implemented with clear and unobtrusive design will help in achieving this mission effectively.
