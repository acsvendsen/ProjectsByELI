# Reality Check for SmartGlasses V1 Direction

## Core Mission & Constraints

### Feasible Now: 
- **Subtitle Placement:** Given current hardware, a simple, unobtrusive placement such as directly below the user's line of sight would be feasible now. This avoids distracting the wearer while still providing essential information.
- **Confidence Display:** A label with a short reason (e.g., "High confidence: Person X") could provide enough context without overwhelming the wearer. Numeric scores might be too complex for V1, but can be explored later if needed.
- **Memory/Cache Policy:** Automatically remembering new people based on contextual clues and reinforcing them over time is feasible now. This approach respects user trust by not assuming constant reinforcement.

### Feasible Later: 
- **Phone/Cloud Boundary:** While the current architecture prefers phone-first processing, more complex cloud-based features could be explored later for enhanced memory recall or real-time updates.
- **Visual Hierarchy:** Enhancing visual hierarchy to ensure subtitles and prompts coexist without overloading the wearer can be addressed in future iterations based on user feedback.

### Likely Waste of Time:
- **High-Frequency Face/Name Recognition:** Implementing high-frequency face/name recognition without significant hardware support or cloud resources would likely waste time given current constraints. A more context-aware approach is preferred for now.
  
### Assumptions Needing Evidence: 
- **Specific Interaction Patterns:** While frame-touch interaction remains the V1 assumption, more concrete interaction patterns (e.g., specific touch sequences) should be defined and tested to ensure they meet user needs without causing social friction.

## Core Tensions

### Privacy vs Usefulness
- Storing new face/name memories automatically with context is a good balance between usefulness and privacy. Reinforcement rules can help manage how often explicit memory capture is needed, ensuring trust remains high.

### Always-On Sensing vs Battery & Thermals
- Early versions should use minimal on-glasses sensing and rely heavily on the phone for processing. This reduces thermal pressure and battery drain while maintaining real-time responsiveness.

### Local Processing vs Cloud Intelligence
- Given current constraints, local processing is limited to basic text display and minimal input handling. Cloud resources can be leveraged where they add clear value without significantly impacting user experience or hardware load.

## Core Attractors

### Real-Time Subtitle Assistance
- Subtitles must feel near-real-time for trust. Latency should be minimized, and confidence indicators should clearly show when information is uncertain to maintain credibility.

### Personal Memory Support
- Implementing automatic memory of new faces and names with context-based reinforcement will enhance user trust and usefulness. Explicit remember-touch can serve as a fallback or additional layer of confirmation.

## Core Tensions Resolved

### Fast Enough Subtitles vs Battery Drain
- Prioritizing battery efficiency in V1 means subtitles should be optimized for minimal impact on power usage while maintaining real-time relevance.

### Helpful Memory vs Privacy Perception
- Contextual memory that automatically remembers new people based on user interaction is a balance between helpfulness and privacy. Explicit reinforcement can further refine this approach as needed.

## Real Implementation Constraints

### Subtitle Latency & Confidence Clarity
- Ensuring subtitles are displayed with low latency and confidence indicators clearly convey when the system is uncertain will prevent breaking trust.

### Memory Trust & Entity Linking Reliability
- Automatic memory of new people should be reliable enough to be trusted by the user. This can be improved over time as more data is collected, but initial implementation must focus on maintaining high confidence in remembered entities.

### Battery Draw & Thermal Pressure
- Early versions should minimize on-glasses processing and rely on the phone for heavy computation. Careful management of power usage ensures V1 remains usable without excessive battery drain or thermal issues.

### Social Acceptability & Usability
- The design must ensure that subtitles are unobtrusive yet effective, balancing social acceptability with functional utility. Visual hierarchy should support this balance by ensuring information is clear and easy to parse quickly.

## Evolution Rule

The project can evolve beyond its original form if it strengthens the core mission of being a discreet, context-aware personal assistant focused on live subtitles, face/name recall, conversation memory, and one-line support. Expansions that deepen the core without distracting from it are encouraged.

- **Confidence Display:** Feasible now with label + short reason.
- **Memory/Cache Policy:** Feasible now with context-based reinforcement.
- **Phone/Cloud Boundary:** Feasible later, but prefer phone-first for early iterations.
- **Visual Hierarchy:** Feasible later based on user feedback.

This summary aligns with the current V1 direction and constraints while surfacing potential next steps and ensuring real-world limitations are considered early in the development process.
