### Idea 2: Confidence Display

1. **Why it benefits the core**

   Ensuring that confidence labels are clear, concise, and appropriately formatted helps build trust in the system's reliability and accuracy. This is crucial for the wearer to understand when they can rely on the subtitles and memory support.

2. **What small change unlocks it**

   Define a simple, two-part confidence label format: "High" or "Low", with a short reason such as "Seen recently" or "Weak match". For example:
   - Confidence 0.84 → High (Seen recently)
   - Confidence 0.42 → Low (Weak match)

3. **Likely payoff**

   By providing clear and concise confidence labels, the wearer will have a better understanding of when to trust the subtitles or memory support, enhancing the overall user experience and reliability.

4. **Immediate next probe**
   - Choose one confidence display format for V1: label only or label plus short reason.

### Idea 3: Memory/Cache Policy

1. **Why it benefits the core**

   Improving memory cache retention strategies ensures that likely new-person memories are stored reliably while preventing unnecessary storage of less relevant information. This enhances trust by consistently providing accurate and up-to-date recall, which is crucial for maintaining the wearer's confidence in the system.

2. **What small change unlocks it**

   Define a recency-first eviction policy where recently seen or heard names and faces have higher retention priority compared to older entries. This can be implemented by setting a threshold on the number of interactions before an entry is evicted from local memory, ensuring that recent encounters are prioritized over stale ones.

3. **Likely payoff**

   By implementing a recency-first eviction policy, the system will maintain a more accurate and up-to-date set of names and faces in its cache, leading to improved recall accuracy and reduced chances of displaying outdated or irrelevant information. This enhances the overall user trust and satisfaction by providing timely and relevant assistance.

4. **Immediate next probe**
   - Set one local cache eviction rule for face/name memory in V1.

### Idea 4: Phone/Cloud Boundary

1. **Why it benefits the core**

   By optimizing the balance between what runs locally on the phone versus what is offloaded to the cloud, we can ensure that the system remains lightweight and socially acceptable while still providing essential real-time subtitle clarity and memory support. This helps maintain the wearer's trust and ensures that the assistive features are always available when needed.

2. **What small change unlocks it**

   Define a clear rule for local processing versus cloud fallback based on task urgency and resource availability. For example, critical live subtitles should remain local to ensure real-time delivery, while memory lookup tasks can use cloud resources to enhance recall accuracy without significantly impacting battery or latency.

3. **Likely payoff**

   By implementing this balance correctly, the system will provide more reliable and timely assistance, reducing the risk of overheating or draining the battery. This ensures that key features like live subtitles remain stable and trustworthy, while memory support benefits from richer processing capabilities when needed without overloading the device.

4. **Immediate next probe**

   Define one phone/cloud fallback boundary for exactly one task such as live subtitle processing.
