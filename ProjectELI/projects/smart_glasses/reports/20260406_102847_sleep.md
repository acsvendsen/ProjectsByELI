# Consolidated Signals for SmartGlasses Project

## Strengthening Signals
1. **Core Mission Clarity**: The glasses should remain focused on discreet, context-aware personal assistant features such as live subtitles, face/name recall, and one-line prompts.
2. **Early Architecture Direction**: Prioritize a simple V1 hardware setup with primary processing on the phone and optional cloud support for heavy tasks.
3. **Real-World Constraints Early Surface**: Continuously surface and address real-world constraints like battery life, thermal management, and social acceptability.

## Weakening Signals
1. **Feature Sprawl**: Avoid adding features that do not directly enhance core mission areas such as subtitle accuracy, face/name recall reliability, or low-latency response times.
2. **Complex UI Elements**: Simplify the user interface to avoid overloading the wearer with too much information and reduce social friction.

## Contradictions That Must Stay Alive
1. **Privacy vs Usefulness**: Balancing the need for personal memory and contextual assistance while respecting privacy concerns.
2. **Always-On Sensing vs Battery/Thermal Limits**: Managing always-on sensing requirements to prevent excessive battery drain or thermal issues.
3. **Local Processing vs Cloud Intelligence**: Finding a balance between on-device processing capabilities and leveraging cloud resources for more complex tasks.

## Dormant Ideas Worth Reactivating
1. **Subtitle Placement Optimization**: Further explore subtitle placement options that maximize usability without becoming distracting.
2. **Confidence Formats Evaluation**: Revisit confidence representation methods such as labels, short reasons, or numeric scores to build user trust effectively.
3. **Face/Name Memory Caching**: Investigate caching strategies on the phone for face and name memory recall to improve speed and reliability.

## No Fluff
1. **Real-Time Subtitle Assistance**: Ensure subtitles feel near-real-time to maintain wearer trust.
2. **Personal Memory Support**: Develop a robust system for fast, accurate face/name recall that respects privacy boundaries.
3. **Low-Friction UX**: Design the interface to be as unobtrusive and user-friendly as possible.

## Key Questions and Tensions
1. **What is the best V1 split between glasses, phone, and cloud?**
2. **How should face/name memory be stored and reinforced for fast lookup and trust?**
3. **How should confidence be represented: numeric score, label, and short reason?**
4. **How should subtitles and one-line prompts coexist without overloading the wearer?**

## Core Tensions
- **Privacy vs Usefulness**: Ensure that while memory features are useful, they do not compromise privacy.
- **Always-On Sensing vs Battery/Thermal Limits**: Manage always-on sensing to prevent battery drain or thermal issues.
- **Local Processing vs Cloud Intelligence**: Leverage cloud resources when necessary but keep local processing simple and efficient.

## Evolution Rule
The project should evolve beyond its original form only if it strengthens the core mission, improves real-world usefulness, or increases trust, clarity, and assistive value without distracting from it.
