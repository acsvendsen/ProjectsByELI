# Reality Check for SmartGlasses V1 Direction

## Core Mission Alignment
The proposed direction focuses on creating discreet, context-aware personal assistance through live subtitles, face/name recall, conversation memory, and one-line support. This is aligned with the core mission.

### Subtitle Feasibility: Feasible Now
- **Real-time subtitle placement**: Given current hardware constraints, placing subtitles in a way that minimizes distraction while ensuring they are quickly readable remains feasible now.
- **Subtitle latency**: With frame-touch interaction and phone-first architecture, real-time or near-real-time subtitles are achievable. The glasses can display subtitles as soon as the phone processes them.

### Confidence Display Feasibility: Feasible Later
- **Confidence format**: Introducing a confidence label + short reason is currently infeasible due to hardware constraints. However, starting with a simple confidence label could be feasible later if the system proves useful and trust can be built.
- **Display integration**: The glasses should display a confidence indicator when needed (e.g., low-confidence face recognition), but this can be a future addition.

### Memory Trust: Feasible Now
- **Face/name memory caching on phone**: Caching memory data locally on the phone is feasible now. This allows for faster lookups and maintains privacy by keeping sensitive information off-device.
- **Memory reinforcement over time**: The system should prioritize storing low-value but contextually relevant memory to build trust incrementally.

### Interaction Constraints: Feasible Now
- **Frame-touch interaction**: Frame-touch controls are the current direction, making interactions simple and socially acceptable. This is in line with V1 requirements and does not introduce new hardware or complex UI elements.
- **No voice activation**: Voice commands are explicitly excluded from V1 to maintain simplicity.

### Phone/Cloud Architecture: Feasible Now
- **Phone-first processing**: Utilizing the phone for heavy processing aligns well with current constraints. The glasses handle display, while the phone manages context and memory lookup.
- **Limited cloud dependency**: Using the cloud only where it adds clear value keeps V1 focused on practical utility.

### Battery and Thermal: Feasible Now
- **Lightweight hardware**: Early versions of the glasses should remain simple to avoid overheating or high battery draw. This is aligned with current constraints.

### Privacy Perception: Feasible Now
- **Minimal local processing**: By keeping heavy processing off-device, privacy concerns are minimized.
- **Clear uncertainty exposure**: The system can expose uncertainty clearly for face/name recall and other features without compromising user trust.

### Visual Hierarchy: Feasible Now
- **Subtitle and one-line prompt placement**: Balancing subtitle placement to ensure they are visible but not distracting is feasible. One-line prompts should visually differ from subtitles to maintain clarity.
  
## Assumptions Needing Evidence
- **Subtitle latency vs battery trade-off**: More detailed analysis on how much processing can be done on the glasses without significant thermal or battery issues.
- **User trust in confidence indicators**: Further research is needed to determine if a simple confidence label + short reason format would build enough trust for V1.

## Core Tensions and Drift Risks
- **Privacy vs usefulness**: Ensuring that memory caching does not overly compromise privacy while providing useful context.
- **Always-on sensing vs battery pressure**: Balancing the need for always-on features with thermal and battery constraints.
- **Rich memory vs fast lookup**: Determining how to balance detailed memory storage with quick lookups without overloading the system.

## Summary
The current V1 direction is feasible now given the constraints. However, some assumptions (like confidence display) may require further evidence before implementation. The project should continue to surface real-world limitations early and avoid broad feature sprawl or unnecessary complexity.
