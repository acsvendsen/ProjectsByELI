# Reality Check for SmartGlasses V1 Direction

## Core Field Alignment

### Mission
The system aims to provide discreet assistive glasses focused on live subtitles, face/name recall, conversation memory, and one-line support.

### Non-negotiables
- Frame-touch-only interaction.
- Phone-first architecture with minimal local processing.
- Focus on real-time subtitle assistance and memory reinforcement.
- Low-friction UX prioritizing clarity over complexity.

## Core Attractors

1. **Real-time Subtitle Assistance**: Essential for noisy environments, hearing-challenged situations, etc.
2. **Personal Memory Support**: Names and prior conversations to enhance understanding.
3. **One-line Contextual Prompts**: Provide brief, actionable guidance without overwhelming the user.
4. **Discreet UX**: Assist the wearer while maintaining a low profile.

## Core Tensions

- **Privacy vs. Usefulness**
- **Battery vs. Always-on Sensing**
- **Local Processing vs. Cloud Intelligence**
- **Rich Memory vs. Fast Lookup**

## Drift Risks

- Becoming a gimmick instead of a daily-use assistant.
- Feature sprawl before core mission is solidified.

## Current Open Questions

1. **Subtitle Placement and Visual Hierarchy**: Best way to display subtitles without distraction.
2. **Confidence Display**: Numeric score, label, or reason for confidence?
3. **Memory/Cache Policy**: Recency first vs. comprehensive caching.
4. **Phone/Cloud Boundary**: How much processing should be done locally versus on the phone/cloud?
5. **Visual Hierarchy**: Subtitles dominate or share screen space?

## Reality Check

### Feasible Now
- **Subtitle Placement and Visual Hierarchy**
  - **More Prominent** for subtitles: This is feasible now as it aligns with the need for fast reading without distraction.
  
- **Confidence Display**
  - **Label + Reason**: This provides clear feedback while remaining simple. It's feasible given current constraints.

### Feasible Later
- **Memory/Cache Policy**
  - **Recency First**: Implementing this policy is viable as it respects the need for low-friction interactions and minimal battery drain.
  
- **Phone/Cloud Boundary**
  - **Phone First**: This direction aligns with reducing thermal and battery pressure, making iteration faster.

### Likely Waste of Time
- **Full On-Glasses Inference**: Given current constraints, full on-glasses inference is not feasible now. It should be explored later if hardware advances allow it.
  
- **Fancy AR Visuals**: These are likely to add complexity without immediate benefits and should be considered in future iterations.

### Assumptions Needing Evidence
- **Interaction Sprawl**: Ensuring interactions remain low-friction through frame-touch only interaction is critical. Further evidence from user studies or prototypes would help validate this.
  
- **Battery Management**: Detailed analysis of subtitle latency requirements versus battery drain will be needed to ensure the system remains usable and unobtrusive.

## Conclusion

The current V1 direction is feasible with minimal local processing, focusing on real-time subtitles, frame-touch interaction, and memory reinforcement. Key areas like subtitle placement, confidence display, and memory policy are well-defined and align with practical constraints. Future iterations can explore more complex features but should maintain a focus on core mission and user experience.

### Specific Recommendations
- **Subtitle Placement**: More prominent subtitles to ensure quick reading.
- **Confidence Display**: Label + short reason for clarity.
- **Memory Policy**: Implement recency first caching to balance memory retention with battery efficiency.
- **Phone/Cloud Boundary**: Focus on phone-first processing, with cloud support only when necessary.

These recommendations are grounded in current constraints and prioritize the core mission of creating a discreet, useful assistant. Further evidence from user studies or prototypes will be essential for validating these choices as the project evolves.
