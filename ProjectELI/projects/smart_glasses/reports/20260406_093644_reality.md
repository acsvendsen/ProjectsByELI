```markdown
# Reality-Checked SmartGlasses Core Field

## Current Open Questions and Assumptions
### V1 Split Between Glasses, Phone, and Cloud?
- **Feasible Now**: Given current hardware constraints, the glasses can handle text display but should offload heavy processing to a phone or cloud server. The glasses could feature a low-power microcontroller for minimal local processing.
- **Assumptions Needing Evidence**: Exact distribution of tasks between devices (e.g., audio recording, face recognition) and power efficiency.

### Face/Name Memory Storage and Reinforcement
- **Feasible Now**: Use a hybrid approach with both on-device storage and cloud sync. On-device storage for quick access and privacy reasons; cloud sync for persistent learning.
- **Assumptions Needing Evidence**: Scalability of memory storage, energy consumption, and user trust in the data transfer process.

### Confidence Representation
- **Feasible Now**: Implement a simple numeric score (e.g., 1-5) with a brief label (e.g., "Uncertain" or "Certain") along with a short reason. This minimizes UI complexity while providing useful feedback.
- **Assumptions Needing Evidence**: User perception and trust in the confidence indicator.

### Subtitles and One-Line Prompts
- **Feasible Now**: Design a system where subtitles are displayed prominently but briefly (e.g., 10 seconds), and one-line prompts appear discretely as needed. Avoid overwhelming the user with too much information at once.
- **Assumptions Needing Evidence**: User preference for prompt frequency and visibility.

### V1 Features for Daily-Use Value
- **Feasible Now**: Prioritize real-time subtitles in noisy environments, name recall during introductions, and contextual prompts that add value without overwhelming the user. Examples include reminding of a previous conversation or suggesting a response.
- **Assumptions Needing Evidence**: Initial user feedback on what features are most valuable.

## Core Attractors
### Real-Time Subtitle Assistance
- **Feasible Now**: Implement this feature with minimal latency to ensure it is useful in noisy environments. Current technology can handle basic speech-to-text conversion with decent accuracy.
- **Likely Waste of Time**: Attempting real-time translation without a reliable underlying language model.

### Personal Memory Support
- **Feasible Later**: Develop robust face and name recognition over time, but focus initially on simpler memory recall mechanisms that can be quickly validated.
- **Assumptions Needing Evidence**: User engagement with face/name recognition features.

### One-Line Contextual Prompts
- **Feasible Now**: Ensure these are concise and helpful. They should complement the user without causing distraction or annoyance.
- **Likely Waste of Time**: Over-complicating the UI/UX design for prompts, leading to a less usable product.

## Core Tensions
### Privacy vs Usefulness
- **Feasible Now**: Balance by allowing on-device processing while syncing essential data to the cloud. Provide clear privacy controls and user consent mechanisms.
- **Assumptions Needing Evidence**: User trust in handling personal information.

### Always-On Sensing vs Battery and Thermals
- **Feasible Later**: Optimize power usage through advanced hardware and software solutions. For now, focus on a balanced approach that minimizes continuous background processing.
- **Likely Waste of Time**: Attempting to run complex always-on sensors without adequate thermal management.

### Local Processing vs Cloud Intelligence
- **Feasible Now**: Use the cloud for heavy lifting while keeping local processing minimal but sufficient for core functionalities like real-time subtitles and basic context handling.
- **Assumptions Needing Evidence**: Energy efficiency of edge computing solutions compared to full cloud dependency.

## Drift Risks
### Gimmick vs Daily-Use Assistant
- **Feasible Now**: Ensure the core features are solid before expanding. Early user feedback can help gauge if the product feels like a gimmick.
- **Assumptions Needing Evidence**: User satisfaction and engagement metrics post-launch.

### Feature Sprawl
- **Feasible Now**: Prioritize the MVP with key functionalities while keeping an eye on potential expansion paths that align with core goals.
- **Assumptions Needing Evidence**: User needs beyond the initial set of features identified through beta testing.

## Reality-Check Rule
- **Continuously Surface Real-World Limitations**: Regularly assess and communicate hardware, battery, thermal, latency, privacy, and usability constraints to avoid optimizing directions that are not feasible.
- **Assumptions Needing Evidence**: Ensure all key assumptions are validated early in the development cycle.

## Next Steps
1. Conduct a user survey or focus group to gather initial feedback on feature prioritization.
2. Develop a prototype for V1 with minimal local processing and heavy reliance on cloud services.
3. Test battery consumption and thermal management strategies.
4. Validate privacy controls through user testing.
```

This markdown provides a structured approach to validating the core mission, addressing key assumptions, and ensuring that development remains focused on feasible goals while continuously assessing real-world constraints.
