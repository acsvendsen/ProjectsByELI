# Reality Check for SmartGlasses V1 Direction

## Core Mission and Constraints
### Mission
Create discreet assistive glasses that focus on live subtitles, face/name recall, conversation memory, and one-line support.

### Non-negotiables
- Frame-touch-only interaction in V1.
- Phone-first architecture with minimal local processing.
- Privacy and transparency are key.

### Core Attractors
- Real-time subtitle assistance.
- Personal memory support for names and conversations.
- Low-friction human experience.

### Core Tensions
- Privacy vs. usefulness.
- Always-on sensing vs. battery/thermal limits.
- Local processing vs. cloud intelligence.
- Rich memory vs. fast lookup.
- Discreet UX vs. visual clarity.

### Drift Risks
- Feature sprawl before core functionality is solid.
- Interaction complexity before the touch-first V1 is established.
- High-latency responses that break trust.
- Storing low-value information instead of relevant, weighted memories.

## Current Core Focus Areas

### Subtitle Placement and Confidence Display
#### Subtitle Placement: `More Prominent`
- **Feasible Now:** 
  - Given the current hardware constraints, more prominent subtitle placement can help with readability. However, it should avoid becoming too distracting.
  - Ensure subtitles are readable but do not overwhelm the wearer.

#### Confidence Display: `Label + Reason`
- **Feasible Now:** 
  - Providing both a label and a short reason for confidence helps build trust without overwhelming the user.
  - This can be implemented with minimal hardware impact since it relies on text display rather than complex rendering.

### Memory/Cache Policy
- **Assumptions Needing Evidence:**
  - How much face/name memory should be cached locally? 
  - What is the optimal balance between local caching and cloud dependency?

### Phone/Cloud Boundary
#### Phone First
- **Feasible Now:** 
  - Keep heavy processing on the phone to reduce battery drain and ensure reliability.
  - Use the cloud only for non-critical background tasks or when latency can be managed.

### Visual Hierarchy: `Subtitles Dominate`
- **Feasible Now:** 
  - Ensure subtitles are prioritized in the visual hierarchy without distracting from the main focus of conversation or activity.
  - Balance subtitle visibility with other UI elements to avoid cluttering the wearer's field of view.

## Reality Check Against Constraints

### Hardware and Battery
- **Subtitle Latency:**
  - Subtitles must be near-real-time to maintain trust. Current hardware should support this without causing significant battery drain.
  
- **Battery Draw:**
  - Keep subtitles and other functionalities optimized for minimal power usage. Avoid complex rendering or processing that could excessively drain the battery.

### Privacy
- **Memory Trust:**
  - Implement automatic new-person memory with context-based reinforcement. This can be done using best-effort within the constraints of local and phone processing.
  
- **Entity Linking Reliability:**
  - Ensure entity linking is reliable enough to provide useful information without overloading the system.

### User Experience
- **Low Friction Interaction:**
  - Frame-touch interaction should remain the primary method. Avoid adding unnecessary complexity until proven necessary.
  
- **Discreet UX:**
  - Prioritize a subtle and unobtrusive UI design that enhances rather than distracts from the wearer's experience.

### Real-Time Guidance
- **Subtitle Quality:**
  - Continuously update guidance to ensure subtitles are accurate, readable, and contextually relevant.
  
- **Memory Integrity:**
  - Ensure memory integrity through clear reinforcement rules. Automatic new-person memory should be reinforced over time but not at the cost of battery or thermal strain.

## Evolving Core Functionality

### Subtitle Feasibility
- **Real-time Subtitles:** 
  - Currently feasible with minimal hardware impact and acceptable battery draw.
  
- **Confidence Clarity:**
  - Label + reason format is a practical solution for providing confidence without overwhelming the user.

### Memory Trust
- **Automatic New-person Memory:**
  - Likely not a waste of time. Implementing automatic memory with reinforcement can significantly enhance utility while respecting privacy concerns.

### Phone/Cloud Balance
- **Phone First:** 
  - Optimal in V1 to reduce thermal and battery strain, but consider cloud for background tasks as needed.

## Next Steps

- Continue refining subtitle placement and confidence display based on usability testing.
- Define memory caching policies through further research and prototyping.
- Ensure all interactions remain touch-first until proven otherwise.
- Prioritize clear and unobtrusive UI design to maintain user trust and social acceptability.
- Surface early any contradictions or risks that may arise from the current direction.

By adhering to these guidelines, we can ensure the V1 development remains focused on delivering core functionality while addressing real-world constraints.
