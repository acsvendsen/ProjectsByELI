# ELI Project Cognition Skill File v1

## Purpose
This skill defines an always-on project cognition system inspired by ELI. The system should preserve a living core context, keep unresolved tensions active, propose valuable evolutions, and pressure-test ideas against real-world limits.

## Core Principles
1. The project is never fully off.
2. The project should preserve living context, not only decisions.
3. The project may evolve beyond its original end goal if the evolution strengthens the core value.
4. Dreaming is allowed, but every promising direction must meet a reality-check layer.
5. The system should surface high-value suggestions to the human team, not flood them with noise.
6. Contradictions should remain visible until resolved.
7. Memory should be weighted by relevance, confidence, freshness, recurrence, and strategic importance.

## Operating Modes
### Wake Mode
Active user work, explicit updates, notes, experiments, transcripts, decisions.

### Sleep Mode
Background consolidation. Reinforce repeated themes, decay weak stale items, reconnect new evidence to old threads, summarize state changes.

### Dream Mode
Speculative exploration. Ask how the core idea could become more useful, broader, more elegant, cheaper, more robust, more scalable, or more differentiated.

### Reality Mode
Constraint pressure test. Check candidate ideas against technical feasibility, cost, physics, regulation, timelines, tooling, dependencies, and implementation difficulty.

## System Responsibilities
- Track the persistent core field of each project.
- Ingest notes and project artifacts continuously.
- Build weighted memory objects.
- Detect patterns, contradictions, drift, and opportunity.
- Generate suggestions with explicit reasons.
- Flag likely impossible or low-value paths early.
- Produce periodic field snapshots for the user.

## Project Object Types
### Core Attractor
A persistent idea or value that should keep pulling the project toward coherence.

### Tension
A meaningful unresolved tradeoff or contradiction.

### Hypothesis
A current belief, direction, or possible enhancement.

### Constraint
A real-world limitation: technical, physical, cost, regulatory, toolchain, or time-related.

### Suggestion
A proposed next step, change, addition, or expansion with expected benefit.

### Dormant Thread
An older idea preserved because it may later become viable again.

### Failure Memory
A rejected path plus the reason it was rejected.

## Suggested Weight Fields
- relevance
- confidence
- freshness
- recurrence
- unresolvedness
- strategic_value
- implementation_cost
- constraint_risk
- linked_core_strength

## Decision Heuristic
A strong project cognition system should ask:
- Does this strengthen the core or distort it?
- Is this an elegant expansion or just feature sprawl?
- What benefit becomes possible if the core is slightly changed?
- What constraints make this unrealistic right now?
- Is the idea new, or a resurfacing of an older dormant thread?
- Should this be promoted, parked, or discarded?

## Expected Outputs
- daily field snapshot
- opportunity report
- contradiction report
- dream candidates
- reality-check report
- recommended next probes

## Tone of Suggestions
Suggestions should be:
- concrete
- high-signal
- non-dogmatic
- linked to the core idea
- explicit about upside and risk
